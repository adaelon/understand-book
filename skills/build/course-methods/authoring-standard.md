# 课程制作流程与交付标准

这份规范供创作者、协助制课的 Agent 和接收课件的人共用。一本教材、一个软件项目、一件生成作品或多份材料都可以成为课程的起点。已有明确路线的委托可以直接制作。只有一本书和一个初步想法时，Agent 承担教学设计，先做一节代表课，帮助委托人从实际体验中选择课程方向。

**制作从学习者最后要独立完成的任务倒推。上课从一个值得检验的问题开始。** 作者先查明什么证据足以回答这个问题。学生先形成自己的猜想，再用作品、实验或原文检验，最后在新的条件下作出判断。

## 发起制课

创作者可以只说“我想把这本书做成课程”。Agent 先浏览全书结构，回读候选段落，从材料中选择一个值得探究、能用一小节讲清的问题。开头提到的处境和兴趣用于选材，受众和学成目标暂定。先带委托人经历一次真实的判断、取证和新情境应用。

试完后，Agent 结合具体题目、实际作答和得到的帮助，询问哪一步值得保留或重做。发现活动有问题，就让委托人试修订后的那部分。根据试课所得提出全课主问题、读者起点、结课任务、选章及后面一两课的问题，让委托人选择扩建、调整或暂缓。试课草稿和修订依据留在制课工作区，个人作答留在对应的私人学习记录。面向其他读者发布时沿第 6 步检验相应人群的学习表现。[试课制作入口](../SKILL.md#teach-one-trial-lesson)

已有明确教学路线时，可以直接使用下面的委托。

> 主材料在〈位置〉。我想给〈具备什么基础的人〉做一门课，希望他们学完能自己〈完成什么事〉。本次交付到〈课程蓝本／可试学课件／发布版本〉。可选参考材料和实际使用条件是〈按需填写〉。

蓝本委托交到第 3 步，写清怎样取得证据、按什么判断结果。可试学课件交到第 5 步，带上实际取证与核验结果。发布版本走到第 6 步，交付读者可以打开的入口。

## 从材料到发布

| 步骤 | 交给下一步的产物 | 据什么决定可以继续 |
| --- | --- | --- |
| 1. 确定材料与范围 | 制作委托。写明主材料的位置和版本、可使用与分享的范围、目标读者的起点，以及学成目标。需要外部设备、模型或付费运行时，写明用在制作端还是学习端。 | 作者和 Agent 能指出材料里哪一部分值得学，以及学生学完要独立作出的判断或操作。目标过大时，先缩到一次能检验的学习结果。 |
| 2. 编排课程路线 | 课程蓝本。给出总问题、结课任务、单元顺序和各课主问题，标明后一课用到前一课的哪项能力。单课委托可直接写一份单课蓝本。 | 结课任务能检验所声明的能力，所需前提来自读者起点或课程中的具体活动。课时估算包括思考、操作与作答。 |
| 3. 设计每课的探究 | 单课蓝本。先写新情境下的独立任务、参考解法和接纳理由，再倒推学生先看到什么、能提出哪些合理猜想、拿什么区分它们。 | 作者能说明如果学生持有另一种猜想，哪项观察会让两种判断产生区别。若现有材料分辨不了，就调整问题、条件或证据。 |
| 4. 制作与取证 | 学生使用的课件、实际素材和作者留存的核验依据。对可运行作品执行选定操作，对文献定位原段，对论证核对前提和推导。保存找到实际结果的入口。 | 另一个人能够在声明的条件下打开同一材料，复做关键操作或复查记录。学生看到的结果对应自己选择的条件。 |
| 5. 独立审题与试用 | 内容和交互核验记录。由人或 Agent 先根据学生可见的题面、材料和允许的帮助独立求解，再与作者解答对照。用学生实际入口操作课件。 | 来源支持结论，合理答案能被接纳。学生先留下判断再看到相应结果，暂停再进入能接着原任务。关键证据缺失、错判答案或无法操作时，修正对应部分后复验。通过后可交付试学。 |
| 6. 试学、发布与修订 | 可打开的课程版本及发布说明。列出受众、所需环境、实际提供的内容、来源与署名、打开方式，以及已有试学的范围。 | 首次采用或实质改变的教学方法，用符合起点的读者试学代表课，观察他们在哪里需要帮助、能否独立完成新任务。按发现修订，再沿既有渠道发布。后续同类课程复用仍然适用的验证，逐课核对新增内容。 |

## “先猜后验”怎样写进课件

- **猜之前给够条件。** 学生知道面对什么对象、可以改变什么、要判断什么，以及理解题面所需的背景。答案、会泄露结果的图注和参考解释留到约定阶段。允许学生用自己的话表达猜想、理由或拿不准的地方。
- **验证时让学生取得证据。** 学生能执行操作、比较材料、定位原文或完成推导，并看到这一次所用的条件和结果。若使用预先运行的记录，标明它对应的输入与运行条件，以及哪些结果可以重新取得。
- **解释时回到学生原来的判断。** 把原预测和观察放在一起，让学生指出哪条证据支持或改变了哪个判断。助教根据实际表达补讲，保留得到的帮助。初次猜错可以开启下一次探究。
- **收束时换一个有意义的条件。** 学生把刚建立的理解用在新材料、新输入或新任务上。接纳依据写清允许的不同解释、必要条件和什么表现算独立完成。求助、跳过和独立作答分别记录。

一课围绕一个可独立收束的主问题，可以有多轮探究。讲解、示范、自由探索和教材回读放在学生需要它们的位置。已有探究课程以 20–30 分钟作为每课完整学习投入的参考，实际范围由教学目标和试学表现决定。

## 不同材料用什么作证

| 主材料 | 作者应保留的依据 |
| --- | --- |
| 软件、仿真、可操作教具 | 项目或作品版本、可运行入口、必要输入与设置、实际输出或状态变化。声称某项设置产生差异时，给出能辨别该差异的对照。 |
| 生成场景、图像、音视频 | 确切作品和可回看的画面、片段或对照版本。若教生成过程，再保留相关提示、设置和实际产出。涉及随机变化时，写明观察所覆盖的条件。 |
| 教材、论文、案例与证明 | 版本、章节、页码或段落，所用概念的成立条件，以及支持主张的原文、推导或反例。用具体算例观察规律时，另交一般性结论所需的论证。 |

作品与经典教材合用时，在具体活动中写明各自回答什么。学生可以先从作品取得观察，再带着一个问题去对应段落找解释，最后回到作品应用。教材说明一般原理，作品的实际行为以所选版本和条件为据。

## 可复制的单课蓝本

一课填写一份，可使用已有建课记录。蓝本阶段写验证方法和预期观察，并标明已有依据。课件制作和试学完成后，在同一处补入实际结果。

| 项目 | 制作者填写 |
| --- | --- |
| 所属单元、主问题与起点 | 〈学生已经会什么，这一课要弄清哪一个问题〉 |
| 学成目标与独立任务 | 〈换一个什么条件，请学生独立做什么，哪些表现可被接纳〉 |
| 学生最初所见 | 〈情境、已知条件、预测问题、可表达猜想与理由的方式〉 |
| 验证与来源 | 〈学生怎样取证，改变和保持什么，到作品或教材的什么位置核对〉 |
| 作者掌握的实际依据 | 〈运行记录、原文或推导，足以区分的判断，结论适用的条件〉 |
| 揭示、帮助与修订 | 〈何时呈现结果、何时给提示，怎样对照原判断并保留学生的新解释〉 |
| 核验与试学 | 〈独立解题、实际操作和目标读者试学各取得了什么证据，发现的问题如何处理〉 |

## 交付与产品接入

接收者应能从课程入口找到路线、材料、活动和必要的运行说明。公共版本保存可复用的内容及其来源。参考解答与判定依据供审题和反馈使用，学习端按阶段提供题面、提示、讲解与反馈。个人的预测、操作、求助、解释和进度随私人学习记录保存。修订课程时保留上个版本的来源和已有学习记录的归属。

现有书籍建课路径从已准备的原文与书籍结构生成课件 `inquiry_course.json` 和构建报告 `course_build_report.json`。本地阅读器按材料版本加载课件，云端沿共享课程发布交付。以外部项目为唯一来源或需要新交互的课程，可以先按本规范交付蓝本。要作为软件内可学习的版本交付，还需接通相应来源与活动，并从读者入口实际打开和操作。工程可用、内容核验和目标读者的学习表现分别说明。[建课编排](../../../packages/core/src/course-build.ts) · [课程与实验类型](../../../crates/memory/src/course.rs) · [本地课件加载](../../../crates/reader-service/src/local_course.rs)
