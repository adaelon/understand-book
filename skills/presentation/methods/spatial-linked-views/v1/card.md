# 三维结构与图解共用一个模型

`spatial-linked-views@1` · adopted · needs: `three`、`state`，含时间时再选 `continuous_scene`

## 要解决的理解障碍

读者能看到立体结构，却无法把空间位置、运动、公式和图表对应起来；改变一个参数后，不知道哪些表示应该一起变化。适用于有明确空间关系、参数模型和可验证结果的主题，例如齿轮、弹簧、杠杆、向量投影或光路。

## 表达配方

1. 建立一个带单位、定义域和边界的模型。一次 `derive(state)` 得到本帧全部结果，再供三维对象、二维图解和可读结果使用。
2. 用稳定对象身份连接表示：同一个部件在立体、图解、文字里保持颜色和名称。先让读者旋转结构，再在图解上直接操作同一变量。
3. 将观察与模型分开：相机只改变视角，拆解只改变部件的展示位置；拆解时暂停运动。参数变更重新计算，时间定位可重复、可后退。
4. 保存参数、周期整数、周期分数、相机和拆解比例。重开恢复到相同的暂停画面，静态导出保留实际三维像素。

## 适用边界

三维必须帮助辨认空间关系。纯数字变化、文字流程和没有空间意义的概念不因此升级为三维。弹性材料、碰撞、阻尼、接触应力等新解释目标必须另建相应模型，不能只换标签。公式、可读结论、来源与假设属于新主题，不从示例继承真实性。

## Agent 入口

`read_method` 按本方法确切版本读取卡片、完整 HTML、适配说明和元数据；`prepare` 选择技术需要；改写后 `write` 明确 `libraries:["three"]`、`asset_refs:[]` 和实际采用的 `method_refs:[{"method_id":"spatial-linked-views","revision":1}]`。读取结果要先在后续采样中被观察，才声明新的方法使用。按新模型核对后完成三个环境的 preview，再 deliver。
