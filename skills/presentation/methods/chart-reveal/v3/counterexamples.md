# 反例：参数齐全，数量关系仍要读者自己补

## 原页证据

用户提供的 CS336 资源核算截图：顶部是词嵌入、36 层注意力、36 层前馈、词表头四个流程框，框内混合 m、N_pair、m_out 和参数量。接着可选“8192 个输入 token”与“已有 8192 上下文，再补 1 个”；默认下方为 m=8192、N_pair=33,558,528、m_out=1，以及 113.8 TFLOPs、19.8 TFLOPs、1.2 GFLOPs、总计 133.6 TFLOPs 的表。

截图说明数值和流程都被列出了，但这个汇总画面没有同时画出 m 是哪些位置、N_pair 是哪些配对、m_out 为什么只取 1 个。

核对完整页面后发现，前一节已经有 query–key 配对格子、上下文 S／新输入 P／请求数 B 控件，以及“长方形加三角形”的解释；汇总表下也写明 m 从 8192 变成 1、N_pair 变成 8193、m_out 保持 1。因此，这不是“整页没有图、没有解释”的反例。具体障碍是汇总处又回到数字表：读者必须回忆前文图与符号，才能将这次切换和三笔计算关联起来。要改的是此处的联动与前后衔接，不是重复增加一张已有的配对图。

原始调用记录确认方法短目录可见，但具体方法读取为零。此例支持改进方法选用入口和表达示范，不能归因为旧模板失效。请求需要的是资源核算整体架构的心智模型；方法选择应以这个阅读目标为准。

## 问题怎样变成具体改法

原请求需要整体架构的心智模型，四个模块框与已有前文解释可以保留。在汇总处可以复用已有图形，让这次模式切换同时标出新投影对象、有效配对和词表输出位置，再把三种计数对应到各自的计算项；也可以让汇总表中的项目定位并高亮前文相应图示。

独立示范将这个联动缩成一个能数清的小模型：4 个输入位置；逐行 1、2、3、4 个有效配对；最后位置进入词表。切换后展示 4 个旧缓存位置仍在、1 个新位置产生投影、新 query 与 5 个 key 配对。再将同一规则代入 8192，保留原数表供核对。这个计数片段可以嵌入较长的架构讲解，不必替换整张演示页，也不代表原页面必须增加同样一套重复图。

这段示范采用自己的明确假设：已有缓存 N 个位置，再加入一个新位置，允许关注自身，因此新配对数是 N+1。不能在没有核实原文口径时，拿示范的 N+1 直接宣判原页 N 的含义错误。

如果问题是“哪部分占用了多少计算”，再增加同量纲分段图，把 1.2 GFLOPs 换为 0.0012 TFLOPs，单独标注小项。原截图 113.8 和 19.8 是显示后数值，不能据其四舍五入后的总和反推精确计算。对象计数示意与计算量图承担不同任务，不能用一个替代另一个。

## 看似修改、实际没有解决的问题

| 无效或不完整的改法 | 为什么没解决 | 应当改变什么 |
| --- | --- | --- |
| 换配色、圆角，继续原样排列参数 | 数字的对象和来源仍不在画面中 | 画出位置与配对，把同一对象贯穿图、符号和数值 |
| 再加三张大数字卡、提高字号 | 只是让结果更显眼，仍须回忆数字对应的对象 | 将已有对象图和当前汇总联动，必要时先给能逐个数清的小例子 |
| 把 m、N_pair、m_out、TFLOPs 放进同一个柱图 | 不同对象和单位的柱高比较没有统一含义 | 机制用对象图；同口径的计算组成先统一单位再比较 |
| 仅把公式收进折叠区 | 隐藏了核对材料，却没增加解释 | 第一屏增加关系图，精确公式与来源继续可查 |
| 删除所有数字和推导，改成一段简短结论 | 无法核验，也不适合深入学习任务 | 保留深层阅读路径，按理解顺序组织材料 |

## 不应套用这项修正的情况

用户已经理解计数机制、只想查询准确参数时，表格可以就是主画面；已有前文图时，先判断联动或定位能否解决问题，避免重复堆图。需要完整推导时，推导应完整展开。有效的审核意见要指出这张页面的具体理解断点、图上该增加或改变的对象及其作用；“不够直观”“建议增加图表”本身不足以指导修改。

完整对应修正版是 example/index.html。它展示同一类理解障碍的解法，不复刻原页全部内容，也不承担验证原 FLOPs 数值的职责。
