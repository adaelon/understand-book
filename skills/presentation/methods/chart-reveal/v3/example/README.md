# 运行与改写：先看见数量关系

直接打开 index.html 即可操作，无外部依赖。正式 Author 先读 card.md 与 counterexamples.md，随后读取完整 HTML、author.json 和本说明。把完整 HTML 作为 write.html；metadata 按新材料重写，声明实际读取过的 chart-reveal@3。正常执行 preview 与 deliver。

## 这个作品做了什么

首屏让读者看见计数对象及关系。橙色表示本次新增的位置或配对，灰色表示已有 KV 缓存，绿色表示 prefill 已呈现的有效配对。切换按钮改变实际工作范围，图、讲解、公式和原数表同时更新。默认 4 个位置可以逐格数清；8192 仅用于将相同规则代入较大数值，图上明确说明省略和非比例示意。

本例按页面任务组织阅读路径：输入位置 → 因果配对 → 最后位置的词表输出 → 精确核对。布局桌面将配对图放在右侧，与左侧的新投影和词表输出并列；窄屏按 01、02、03 依次显示。

## 改写时真正需要更换的部分

1. 先确定读者的问题。若不懂数值来源，选可枚举的小例子；若只比较已知数值，就用统一单位的基线图；若是查表任务，允许原数表优先。
2. 重建对象和计数规则：哪些对象新建、保留、重复、合并或只选最后一个？用真实图元表示它们，保持文字与图里的范围一致。不能直接替换标题、保留 token 的对象模型。
3. 明确小例与目标规模的连接。小例必须保留需要讲清的机制。若只是结构示意，直接注明非比例与省略，不用压到看不清的 8192 个格子充数。
4. 精确数值、公式、来源和假设仍保留。完整推导可以展开，也可以成为正文；解释深度取决于任务，不以固定时长或字数决定。
5. 不同量纲、不同口径不得一起按柱高比较。要比较计算组成，先把 GFLOPs 和 TFLOPs 换成同一单位，微小项单独标注；不能用对象计数直接冒充计算量或耗时。

## 计算、状态与恢复

derive 是唯一的模型入口，输入为 mode 和 positions，输出为新投影行数、有效因果配对数、词表输出行数。render 将同一结果写入对象图、算式、结论与表格。扩展公式时先改 derive，再改相应图形和可读说明。

状态还包括三个展开区的 open 值。页面初始化读取 window.presentation.initialState；registerStateReader 只返回当前标量、结论和计算状态，不改变页面。registerStateRestorer 从 saved.values.page 恢复后立即重画。交互结束调用 commitState，没有计时器、隐藏计算或自动播放。正式恢复与静态导出均通过 Reader 实际 iframe 验证。

## 适配后怎样验证

先用可以独立手算的小输入核对对象数、有效格子、图文范围；再检查实际规模和边界。不同处理模式、返回初始状态、展开区和保存重开必须保持相同结果。查看 320×420、640×240、960×720；控件可点击、数值不溢出，不能只看 HTML 源码。独立预期在 checks.md。

## 已知限制

这是独立教学模型，具体实现可能计算被 mask 的区域，也可能给所有位置做词表投影；移植前核实材料。候选在留出题上的生成收益需要另行实验，本作品自身可运行不等于迁移有效。
