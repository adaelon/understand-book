# 先看见数量关系，再核对参数

method_id: `chart-reveal` · revision: `3` · 状态：本地验证版本

## 要解决的理解障碍

参数、公式和表格都在，读者仍须自己猜每个数字在数什么、从哪里来、为什么变化。先判断页面任务：建立机制直觉、深入推导，还是已知口径下查表。只有第一种障碍需要把对象关系提前；查表页可以表格优先，长推导不必压成短视频。

## 先决定需要哪种图

- **不懂数量怎么来**：先画可数的对象、连接或分组。用一个能看清每个对象的小例子，把输入 → 计数规则 → 输出对齐；再代入真实规模。
- **知道数字意义，想比较大小**：固定单位、零基线和口径，使用柱图，再给差值与比例。不同量纲或不同对象的计数不可硬塞进一组柱高；需要此分支时通过 read_method 读取 `chart-reveal@2` 的完整 example/index.html，其正值、零值、负值作品继续适用。
- **想看组成或占比**：先核实分项互斥、穷尽、同单位，再用分段长度或组成图。小项单独标注，原数表保留；必要时读取 `part-whole@2`。
- **需要查数或验证推导**：保留原始表、公式、来源和条件，安排在机制图之后或独立查阅区。不是“参数越少越好”，而是先让读者知道参数指什么。

## 本例的表达配方

默认展示 4 个输入 token：4 个新投影位置、逐行 1+2+3+4=10 个因果配对、只对最后位置做 1 行词表投影。切换到“已有 4 个位置缓存，再处理 1 个新位置”，看到缓存保留、新投影只有 1 行、新 query 与 5 个 key 配对（含自身）、词表仍只投影 1 行。图、结论、原数表来自同一状态。

先看实际对象与连线，读者操作后立即看见哪里变化；不要求先记住 m、N_pair、m_out。缩小模型保留真实规则，教学数字明确标记；大规模视图显式省略中间对象，不冒充逐格或等比例显示。

## 边界与来源

这是解释因果计数的独立教学模型，不模拟完整 Transformer 的 FLOPs、延迟或硬件效率。假定已有有效 KV 缓存、单序列因果注意力、当前新位置可关注自身，并且仅最后位置进入词表投影。缓存使用、输出位置和 kernel 实际执行范围必须从新任务材料确定。

本候选从用户提供的 CS336 资源核算演示页反例提炼，具体页面证据与不确定边界见 counterexamples.md；示范不是原页实测结果，也不包含迁移实验的新题答案。
