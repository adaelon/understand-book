Saved page state contract:

state_contract maps scalar parameter names to semantic definitions, including units and valid domain. Preserve a definition only when old values retain exactly the same meaning and domain. Compatible saved page values with identical definitions and JSON types replace matching initial_state fields at write time; other fields keep new defaults. Inspect the effective initial_state in the write receipt and preview it. Initialize from the read-only window.presentation.initialState without mutating it.

Use one computed state for geometry, labels, native controls and state capture; keep graphical results described in visible DOM text. Register a synchronous window.presentation.registerStateReader(() => ({values: scalarParameters, visible_step: stringOrNull})) for custom parameters and button-driven steps. Numeric steps belong in values; visible_step is a string or null. The host captures actual DOM results and native controls. Call window.presentation.commitState() after completed custom actions, pause, dragend or asynchronous calculations, never on each input or animation frame. Native change and button clicks save automatically. There is no presentation.commit API.

Register window.presentation.registerStateRestorer(saved => { /* restore saved.values.page and saved.visible_step, then recompute */ }). It runs once after page initialization and native-control restoration when reopening this exact version. Restore data and recompute without replaying clicks, source navigation or other effects. It may return Promise<void> for asynchronous restoration. Do not independently restore early via presentation.restoredState as well as the registered restorer. Restore paused when playback exists. Saving and follow-up read the actual presented state without altering it.
