Saved page state contract:

This contract is available throughout local construction and review. Apply it when the page has changing parameters, selections or steps; a static page needs no state callbacks.

state_contract maps scalar parameter names to semantic definitions, including units and valid domain. Preserve a definition only when old values retain exactly the same meaning and domain. Compatible saved page values with identical definitions and JSON types replace matching initial_state fields at write time; other fields keep new defaults. Inspect the effective initial_state in the write receipt and preview it. Initialize from the read-only window.presentation.initialState without mutating it.

Use one computed state for geometry, labels, native controls and state capture; keep graphical results described in visible DOM text. Register a synchronous window.presentation.registerStateReader(() => ({values: scalarParameters, visible_step: stringOrNull, observation: {summary, state}})) for custom parameters and button-driven steps; add observation.rendered only when needed as described below. Numeric steps belong in values; visible_step is a string or null. The host captures actual DOM results and native controls. Call window.presentation.commitState() after completed custom actions, pause, dragend or asynchronous calculations, never on each input or animation frame. Native change and button clicks save automatically. There is no presentation.commit API.

observation is optional teaching semantics projected from that same computed state: summary is one readable sentence; state is a JSON object describing current parameters, objects, progress and phase in the lesson's terms. rendered is an optional JSON object containing the inputs and result actually displayed when an apply/run step can lag behind editing. Immediate-redraw pages omit rendered. Before any result exists, or when calculation fails or is cancelled, describe that phase and any still-visible old result honestly. Only a calculation that has become the displayed result updates rendered. Unknown quantities are null with an explanation in summary. The host's observed_result remains the actual visible DOM text alongside this projection.

Reading state is synchronous and read-only: do not apply pending inputs, restart playback, recompute or replay a demonstration to answer a snapshot request. Derive the observation afresh so parameter edits, programmatic updates, reset, asynchronous completion and meaningful timer changes all appear on the next read. A missing or failed reader leaves only the host's current controls and visible text; no earlier observation is substituted.

When input and display can differ, save both input and applied parameters and the completed semantic step in values (stored as values.page) and define them separately in state_contract. For example input_speed_b_m_s=2 and applied_speed_b_m_s=1 mean a pending 2 m/s input alongside a 10-second, 10-metre displayed result. Restore the old result from applied_speed_b_m_s while retaining input_speed_b_m_s for the next apply; observation is a projection, not another restoration store. An in-flight calculation must restore paused or awaiting application, not automatically complete.

Register window.presentation.registerStateRestorer(saved => { /* restore saved.values.page and saved.visible_step, then rebuild the displayed result from applied parameters */ }). It runs once after page initialization and native-control restoration when reopening this exact version. Restore data and rebuild without replaying clicks, source navigation or other effects. It may return Promise<void> for asynchronous restoration. Do not independently restore early via presentation.restoredState as well as the registered restorer. Restore paused when playback exists. Saving and follow-up read the actual presented state without altering it.

For teacher operations on the open version, declare action_contract in write/patch metadata. Supported entries are {kind:"set_parameters",parameters:["input_speed_b_m_s"]}, {kind:"invoke",action_id:"apply",label:"应用"}, and {kind:"highlight"|"reveal"|"annotate",region_id:"existing-region"}. Each parameter needs its existing state_contract definition, initial_state value and a native input/select/textarea marked data-presentation-parameter="input_speed_b_m_s". Invocation controls use data-presentation-action="apply". Regions use their existing id or data-teaching-region. Declare only actions the page implements; annotate reveals existing reviewed text.

Register window.presentation.registerActionHandler(async (action, {signal}) => { /* call the same functions as the controls; await completed rendering */ }). set_parameters can leave inputs awaiting application; invoke(apply) must wait until the result is actually displayed. Use the signal to stop pending asynchronous work on cancellation. highlight uses the host's region locator; reveal/annotate must update the page's restorable state before resolving. The host then captures and saves the exact result. Rehearse callbacks through preview.actions entries {kind:"interact",action:{kind:"invoke",action_id:"apply"}} as well as the original controls; preview checks the declarations against actual controls, regions, reader and handler. A failed callback or save has no applied receipt. Teacher operations never submit a learner answer; requestTeachingAction only opens the existing host form.

The live tool is presentation.interact: observe the currently open exact reference, then act with its saved_state_ref. Returned available_actions belong to that version. Changed human inputs produce a conflict with a new saved observation; natural playback alone does not invalidate the observation. A closed/reloaded page, ended run or uncertain connection requires another observe before any further action. Runtime operations preserve the content revision; edits to content, computations or undeclared actions use the authoring and review chain.

For continuous demonstrations, bind the visible result and explanation regions through teaching_binding.regions. Their state_fields describe changes to the displayed relationship: on an apply-based page use applied parameters, not pending inputs. After a successful teacher callback the host records visible region text for changed teaching fields; reveal/annotate record their declared teaching region. Highlight and un-applied input changes remain operation facts. Use the same callbacks as the learner controls, and leave them enabled when the teacher stops. Do not call reportTeachingHelp again inside a teacher callback: the host saves that action's before/after receipts and help together. Learner-triggered explicit help continues to use reportTeachingHelp.
