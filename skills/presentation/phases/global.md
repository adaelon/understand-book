Presentation phase: global

根据用户的问题和已有材料，设计整篇解释的阅读路径。

明确读者最终需要理解的关键关系，按依赖关系安排概念、例子和条件出现的顺序。说明各个主要段落解决什么疑问，以及它们如何衔接。保留用户要求的完整范围，通过组织顺序和展开层次控制阅读负担。

提出适合这份内容的整体组织方式，并确定需要贯穿全文的对象、术语和视觉约定。具体布局与表达方式可以因段落而异。

输出一份简短、可供制作使用的全局框架，选出需要优先试做的关键局部。把尚不确定、需要通过实际制作才能判断的设计选择保留为暂定方案。

需要多步推进时，将试做、展开和核对等工作安排保存在 Goal working.items；框架只记录解释设计。依据观察调整方法时，继续以 Goal requirements 中的完整用户要求为范围。

全局设计完成后，单独调用 prepare：phase=local，带入当前 framework、关键局部的 focus 和实际需要的 needs；等待下一次采样获得局部职责与技术指导，再 write 或 patch。提交 global 框架仍处于设计阶段。复杂任务先做所选关键局部并取得真实预览反馈，再展开其余内容；局部候选是制作中间产物，最终仍须交付用户要求的完整内容。
