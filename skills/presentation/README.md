# Presentation guidance assets

`SKILL.md` is the common explanation body (coach-handoff.v3). `phases/global.md`, `local.md` and `review.md` add the current responsibility. `engineering.md` keeps source, version, resource, actual-preview and delivery contracts. `capabilities.md` is the short directory. `references/` contains selected technical contracts. Authors read examples on demand.

Formal catalog revision 6 registers eleven methods in twelve versions. The first eight methods offer linked diagrams, direct manipulation and complete explanations. Both versions of the single-factor comparison remain registered. Spatial-linked-views pairs spatial mechanisms with diagrams. Compare-rules provides three ways to observe the same change of rule, and inspect-space offers an exploded assembly and a movable section. Each entry carries complete local source, Author metadata, adaptation notes and checks. The coach can name one scene file in its existing adaptation field. Ordinary prose and formulas remain available for derivations. [Method library](methods/README.md) · [Interactive gallery](methods/index.html) · Scene verification.

`crates/runtime/build.rs` reads the formal catalog by default and embeds every registered file. An isolated trial build sets `UNDERSTAND_BOOK_METHOD_CATALOG` to a repository-relative or absolute catalog path (the SE1 candidate uses `docs/performance/explanation-evolution/se1/candidate-catalog.json`). Cargo rebuilds when the selection, manifest or registered files change. The combination stays fixed for the binary's lifetime. Unset this build input for the formal combination.

Only an exposed Author tool adds the short method directory. `presentation.author` operation `read_method` requires the exact `method_id` and `revision`; omitted `file` reads `card.md`. The returned file list and entrypoint identify the example and adaptation guide. `offset` and `length` count Unicode characters. `offset`/`chunk_characters` describe returned text, `end_offset` is the requested range end, and `total_characters` is the file size. Budget truncation supplies `next_offset` and a continuation for the remaining requested range. Once that range is complete, start another explicit range to read further. Missing versions or files fail explicitly. [SE2 evidence and commands](https://github.com/adaelon/understand-book/blob/625b4405af3b011e87d4eb256f819c8075f88613/docs/performance/explanation-evolution/se2/README.md) record actual Provider-boundary inputs.

SE3 records directory exposure and exact observed file ranges after successful Provider sampling, separately from declared use. `write`/`patch` accept a complete `method_refs` list of `{method_id, revision, scope?}`. New references require a registered exact version observed in this run; inherited references point to their exact candidate or delivered version, including retired methods. A patch inherits when the list is omitted; supplying a list replaces it and `[]` clears it. Full writes must explicitly redeclare methods when the base has recorded uses. New writes without methods record `[]`; old payloads without records remain `null` on read. Candidates and delivered versions retain the declarations, observation snapshot and read/inheritance basis. The method directory is `se3.v1.catalog`; common guidance remains ex14.v4. [SE3 contract and evidence](https://github.com/adaelon/understand-book/blob/625b4405af3b011e87d4eb256f819c8075f88613/docs/performance/explanation-evolution/se3/README.md). Author metadata supplies the example's initial state, parameter definitions and content description; add HTML and actual method_refs after reading the selected unit.

Runtime compiles these assets into `agent_prompt::presentation` and uses `policy_modules_for_tools_with_presentation` to assemble actual instruction modules. A global context receives the directory without technical references. Local/review contexts receive only selected references and their dependencies, in stable order without duplicates. `continuous_scene` includes `state`; `manim` includes both. `konva` alone adds no timeline or saved state.

When the presentation coach recommends a registered method with scene alternatives, local construction and review also receive the technical references for that method. This makes the offline Three guide available when a spatial recommendation follows an initial two-dimensional proposal. The author's explicit prepare record is preserved. Library selection on the delivered version still follows the actual write request.

EX12.2 connects Resident sampling to this selector. First author-tool exposure uses global guidance. `prepare` replaces the run-local phase/framework/focus/needs and must be called alone; the next sampling projects the current framework/focus as task data and selects the matching guidance. Delivery and cancellation clear the record, and new runs do not restore it from history. Equivalent repeated prepares do not count as progress. Ordinary answers without the author tool load none of these assets. These assets do not grant preview or delivery eligibility.
