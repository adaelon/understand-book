## 1. 用户路径与交付目标

本机用户或自部署管理员进入模型设置，选择服务预设或自定义地址，配置凭据与模型，显式测试并设为默认；读者随后能完成带原文引用的问答、教学、练习反馈和连续追问。模型更换后，已有聊天、学习记录和材料引用保持可恢复，活动任务使用开始时已绑定的模型配置。

完整交付覆盖第 3 节的全部协议族及云端变体。各切片可独立验收，但只完成 OpenAI 兼容接口不能关闭本计划。协议支持、具体模型能力、真实服务验收分别记录；本方案不宣称按厂商数量计算的覆盖比例。

资料准备沿现有插件入口：插件连接外部 Harness，Harness 持有模型配置并执行语义任务，Build Engine 接纳候选并发布成果。阅读器的模型配置只作用于阅读、教学及相关后台任务。

## 3. 必须交付的协议范围

### 3.1 协议族

下表中“必验差异”在协议支持该能力的代表模型上验收；模型没有某能力时应呈现明确限制。所有行均为本计划完成条件。

| 协议 | 覆盖路径 | 必验差异 | 当前状态 |
|---|---|---|---|
| OpenAI Chat Completions | 官方及兼容端点 /chat/completions | SSE、工具参数增量及 tool_call_id、JSON 输出、流尾 usage、参数差异 | 本地回归、DeepSeek 兼容端点实测通过；OpenAI 官方未验收 |
| OpenAI Responses | 官方及明确支持的兼容端点 /responses | typed events、output items、call_id、reasoning items、结构化结果及恢复 | 本地回归、DeepSeek 兼容端点及课程回课实测通过；OpenAI 官方未验收 |
| Anthropic Messages | 官方及 Messages 兼容端点 /messages | system 分离、content blocks、tool_use / tool_result、thinking 与签名、缓存用量 | 通用适配本地回归、DeepSeek 兼容端点实测通过；Anthropic 官方未验收 |
| Gemini GenerateContent | generateContent / streamGenerateContent | contents / parts、functionCall / functionResponse、thoughtSignature、结束原因与 usageMetadata | 已实现，真实服务待验收 |
| Gemini Interactions | 官方 Interactions 接口 | steps、function_call / function_result、流式事件、interaction 续接与无状态历史 | 已实现，真实服务待验收 |
| Ollama Chat | 本机或用户部署的原生 /api/chat | NDJSON、免 Key、tools、结构化 format、模型能力与原生计数 | 已实现原生路径，实机待验收；兼容端点另归 Chat Completions |
| AWS Bedrock Converse | Converse / ConverseStream | content blocks、toolUse / toolResult、AWS EventStream、模型或推理配置 ID、用量与认证 | 已实现，真实服务待验收 |
| Cohere V2 Chat | 原生 /v2/chat | SSE 事件、工具调用、结构化结果适用组合、tokens 与 billed_units 区别 | 已实现，真实服务待验收 |
| DeepSeek Messages 扩展 | 项目现有 Messages 路由 | 真实路由能力探测、工具更新、推理块、续接、原用量与重试 | 扩展已隔离；本地回归和 DeepSeek 工具/结构化样本通过，见第8节 |

OpenAI 两套接口的数据和事件模型不同，必须分别适配。[Chat API](https://developers.openai.com/api/reference/resources/chat)、[Responses API](https://developers.openai.com/api/reference/typescript/resources/responses/methods/create)及[推理内容续接](https://developers.openai.com/api/docs/guides/reasoning)提供依据。Gemini 官方已推荐 Interactions，同时继续支持 GenerateContent，因此两者均列入范围。[Gemini Interactions](https://aistudio.google.com/docs/interactions-overview)

Cohere 的结构化输出与 tools / documents 组合存在接口约束，适配器需按任务分别请求，不能把所有能力简单组合发送；计费单位与实际 token 分开保存。[Cohere V2 Chat](https://docs.cohere.com/reference/chat)

### 3.2 云端部署与兼容服务

| 部署方式 | 交付内容 | 判定依据 |

## 4. 配置与运行合同

### 4.1 三类配置与持久化

- **模型服务连接**：稳定 service_id、显示名称、端点类型与地址、适用部署参数、认证方式及后端凭据。一个服务可供多个模型复用；具体协议使用该端点所支持的配置。
- **模型配置**：稳定 model_config_id、service_id、model_id、明确 api_protocol、能力、上下文窗口、输出上限与受支持生成参数。协议预设可给默认值，运行前必须解析为确切值；自定义模型可覆盖能力，界面标明人工配置与实测结果。
- **用途绑定**：一个默认模型，加可选的主 Agent、教学反馈及后台任务覆盖。沿原调用用途解析，后台压缩等需要原模型私有状态的任务保持原运行绑定。UI 初次只展示默认模型，高级用途按需展开。

扩展原设置结构并保持单一权威存储。已有桌面单连接和旧环境变量确定性转换为一个默认服务与模型，保留原 native / react 及已支持 DeepSeek 行为；成功保存新配置后采用新设置，旧文件保留原有失败恢复路径。显式新配置无效时返回错误，不能悄悄回退到旧环境中的另一服务。仅实现这条实际存在的升级路径。

保存前校验字段、引用和必需能力；持久化成功后热应用，失败继续使用原配置。读取接口仅返回“已配置凭据”及来源；空白密码输入表示保留，删除凭据是独立明确动作。本地无认证服务允许空凭据。云端凭据由所属后端的正式凭据链取得和刷新，前端不接收会话令牌。

连接/模型删除若被默认用途引用，须先选择替代；仍有活动或可恢复任务时保留其原配置或明确结束相关任务。持久历史保留模型来源。新增版本使用普通修订号及已有运行绑定，不另算配置指纹。

### 4.2 协议适配与能力

ModelAdapter 保持公共入口。按协议组织编解码，公共发送层承接超时、取消、重试、观测与 ModelSpendPort；SDK 内置重试须关闭或纳入同一真实发送账本，避免重试倍增。SDK 的异步/流式桥接服从现有宿主线程与取消生命周期。工具能力通用类型移出 DeepSeek 专用命名空间，专有工具更新仍由 DeepSeek 扩展持有。

请求模型表达文本、图像、工具调用、工具结果与协议私有块。支持图像的模型可消费项目实际提供的图片输入；文本模型遇到依赖图像的任务时在发送前说明缺少能力。能力配置分别表达工具、并行工具、JSON 对象、JSON Schema、图像、推理参数及续接方式，未知不冒充支持。公共工具合同继续由原注册表提供，特定协议的 schema 限制在适配边界处理，不能放宽业务参数校验。

纯结构化生成与 Agent 工具循环分别调用适合的协议接口。缺原生 JSON Schema 时可使用已声明的 JSON/文本结构化路径，并继续经过原解析与校验；解析失败保留失败状态。ReAct 只在显式配置且通过相应工具用例时使用；不在一次原生工具失败后自动换成文本模拟。

地址组装按协议和部署类型处理路径与版本参数，覆盖当前 run_admission 拒绝 query 的边界；额外参数不能覆盖冻结的模型、消息、工具、输出预算和认证。认证、限流、无模型、上下文不足、不支持参数、输出截断与连接中断映射到可处理的错误；错误提示指出应修改的配置项。

### 4.3 流式交付、历史与模型切换

SSE、NDJSON 与 AWS EventStream 由各自解析器消费，归一化为文本增量、完整工具调用、结束原因和用量。按协议的 index / id 组装并行调用，仅在参数完整且校验通过后交给原工具执行器。正常结束、需要工具、输出上限、安全拒绝和断流分别表达；已显示半句或不完整参数不能记成成功交付。文本流式、工具调用与流式工具调用分别记录能力；如 Bedrock 某模型支持工具但不支持流式工具，采用其声明支持的非流式调用并保持同一工具往返合同。

推理签名、加密 reasoning items、Messages blocks、Gemini thought signatures 等只由对应适配器解释和回放，归属为服务、协议、模型及原消息。服务端续接标识遵循同样归属。本地日志保存恢复所需内容，前端普通配置响应不包含这些私有数据。

新运行固定模型配置快照；默认模型修改只影响后续运行。恢复任务沿现有 ProviderBinding 检查，原绑定不可用时给出明确错误。显式切换模型时从已完成的本地历史投影到新协议，保留用户原话、已交付回答、来源和工具事实，清除不适用的私有续接数据；活动工具循环先完成或结束，不跨协议搬运未完成调用。

Responses / Interactions 的基础路径以显式无状态请求和本地历史恢复为基准；可选服务端续接须由对应配置启用并验证完整恢复，不把远端 ID 变成唯一历史。已有 DeepSeek 续接能力沿原合同回归。协议故障不触发跨服务或跨协议的隐式切换。

### 4.4 用量、预算与调用成本

所有真实发送沿 before_send / after_send 执行。单次流中的累计 usage 采用协议定义的合并方式，重试尝试之间才累计费用；推理 token 若为输出子集不再相加，缓存命中/写入按原含义保存。Cohere billed_units 等独立于上下文 token，扩展现有账本字段时保留原量纲。

本地自带 Key 场景可在费率未知时显示 token 和“费用未知”；受额度控制的多人部署必须有明确费率或沿原计费不可用状态停下，不能以新协议绕开准入。模型价格按部署配置维护，不在适配器写死。缺用量、取消后已发送请求、解析失败均留下原待核对或失败事实。

未配置模型时基础阅读继续可用。打开设置、保存、选择模型与读取已有历史不发生成请求；测试连接明确展示会发起小额请求。模型能力信息优先复用配置与目录，避免每轮额外探测。性能验证记录同一任务的请求次数、重试次数、首字时间、端到端时间和 token，先与现有路径比较，不预定无依据的加速比例。

## 5. 设置界面与管理入口

模型设置沿用当前阅读器视觉与中英文目录，以“模型服务 → 模型 → 默认用途”组织。首屏显示当前默认模型与可用状态；添加服务使用预设或自定义，云端参数、额外请求头和用途覆盖放入高级设置。避免让初次用户填写全部协议选项。

“保存”和“测试”分别操作。测试结果区分凭据/连接、文本生成、工具往返与结构化输出；一次文本测试成功只显示对应结果。测试草稿不会替换活动默认配置，应用成功才更新后续运行。失败保留输入，定位具体字段，提供可执行的处理提示。

桌面通过原 IPC 调用后端；本地网页/自部署管理员通过同一配置服务的受控 HTTP 入口操作，服务端权限沿既有身份与管理边界。自部署仍支持文件/环境方式启动，普通学习者看到当前可用模型及故障说明，不获得共享密钥编辑权限。

上述本地或单用户源码入口管理本机配置；多人管理员入口属于云端宿主，由云端扩展交付。前端共用模型配置组件与合同，服务级身份、权限和额度管理留在云端装配。

视觉与交互验收包含空配置、已有单连接升级、多模型列表、长模型名、无 Key 本地服务、无模型目录、测试失败、保存失败、切换时存在运行、重启恢复、中英文及窄视口。保留实际浏览器/WebView 操作和截图，构建与 DOM 断言不替代视觉证据。

### 7.2 真实服务、教学与性能

每个协议和每条云端路由选择一个实际支持目标能力的模型；记录服务、协议、模型 ID、部署/区域、配置来源与时间。一次成功只覆盖该组合。兼容接口至少使用官方及一个独立兼容实现；本地原生路径使用真实 Ollama 模型。

共同样本以 examples/quickstart/book.md 准备的原创资料为基础，实际完成“问题 → 阅读工具 → 原文 → 带来源的回答 → 追问”，并完成一条结构化教学/练习反馈；需要图像的适配用已有可定位图片样本。Responses、Messages 与 Gemini 的推理状态要覆盖工具往返和重载；云端路由使用真实认证和账本，不能用同形 HTTP fixture 替代。

依据原题、原文、真实学习者表达与已给帮助评价教学反馈；不把 JSON 合法视为教学正确。能力不同的模型明确支持范围，不因较弱模型失败修改所有协议的教学标准。课程流程复用 CONTRIBUTING 所指入口与已保留样本。

真实调用仅使用任务已有授权的凭据和预算；开始时按所测协议、样本、最大输出与重试范围估算调用量并记录预算，凭据或预算不足的组合保留未验证。测试 UI 的显式调用预算与完整发布采样分开。性能对照固定输入与模型配置，先保留现有 Chat/DeepSeek 基线；排查新增无用调用、重复传输或重复扣费，不把不同服务的网络快慢作为适配器性能结论。

实施证据沿 docs/evidence/model-providers-<日期>/<切片>/<协议>/ 保存原始结果，脱敏回归留在测试。文档状态按执行通过、语义通过、失败、未执行、待评价分别更新；发布报告注明适用端点和模型，已有失败不能由后来的成功覆盖。

- Bedrock 的 Converse 与 ConverseStream 分别承担非流式和流式推理，模型的工具/流式支持需逐项读取，不能把 AWS EventStream 当作 SSE。[Converse 指南](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html)
- Azure v1 有独立的服务地址、deployment 选择与凭据使用方式，不要求旧的日期 api-version；各模型支持范围仍按部署确认。[Azure API 生命周期](https://learn.microsoft.com/en-us/azure/foundry/openai/api-version-lifecycle)
- Azure 部署路由与 v1 的模型字段位置不同；Responses 支持取决于具体部署。[Foundry 端点说明](https://learn.microsoft.com/en-us/azure/ai-studio/ai-services/concepts/endpoints)
- Google Cloud Interactions 有项目与位置明确的端点及凭据合同，和 Developer API 分别验收。[Interactions 开发指南](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/interactions/developer-guide)
- Vertex Claude 使用 rawPredict / streamRawPredict 路由和对应请求版本字段，复用 Messages 内容合同。[Vertex Claude 调用指南](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/use-claude)
