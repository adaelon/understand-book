## 贯穿场景

取已有学习率示例的一维函数 $L(w)=(w-2)^2$，从 $w_0=0$ 做梯度下降。每次独立运行使用同一材料和新的隔离私人库，轮次间沿用同一聊天。将读者约定与资料中的公式分别记录，尤其用“先数值、后公式”识别首轮要求是否送达：仅从资料中也能推知记号 η。[学习率示例](../crates/runtime/src/testdata/ex11-learning2-goal.json)

| 回合 | 读者与系统做什么 | 评测端留下什么 |
|---|---|---|
| 第 1 轮 | 读者约定“讲义先给数值、再写公式，学习率全篇用 η。例子先取 0.1。等我明确说保存再写笔记。先讨论，等我说整理时再做一页窄屏讲义。” | 用户原话、初始笔记记录。约定放在问题开头，使六轮淘汰和单条文本裁剪可以区分。 |
| 第 2–6 轮 | 逐步讨论导数、更新方向和原文依据。第 4 轮只把示例值改为 0.01。 | 原始纠正、实际回读的材料和工具回执。记录中途哪条回答自然重提了规则。 |
| 第 7–8 轮 | 第 7 轮继续查证，第 8 轮只说“按之前的约定整理”。内置 Agent 的任务要求交付可在窄屏阅读的讲义页。 | 实际请求、讲义首屏、公式和来源，交付回执与重开后的笔记。期望先出现数值结果，首步为 0.04，记号为 η，笔记仍无新增。 |

最终请求不重复答案或约定。判定所用的推导、预期状态和故障标签只给评测端。ACP 的交接实验观察普通聊天请求；页面制作和预览经具备这些工具的 Resident 执行。

## 切片一 · 本机第七轮和第八轮送达了什么

使用隔离 Reader 和可记录 `session/prompt` 的受控 ACP 进程，复用现有子进程及换 Agent 验收入口。走普通阅读问答，受控的中间回复不复述首轮约定。取第七、八轮真正发给子进程的请求，并读回同一聊天的持久历史。再用相同前七轮重放一次，只在第八轮换 Agent。此片使用本机受控返回，模型费用为零。[协议夹具](../crates/reader-service/src/local_acp/tests.rs) · [Reader 与适配器验收脚本](../scripts/verify-local-agent-acp.py)

**完成判据。** 对照两份相邻请求，指出记号、顺序、保存条件和第四轮纠正分别出现在哪里。当前六轮装配预期第七轮带有首问，第八轮从第二轮开始；如果其他正式上下文仍带入原约定，标出来源并记为已送达。原话在库中、约定在请求中消失，即记录为 Reader 的交接缺口，并保留这对请求作修复回归。原话本身已丢失则先查会话保存。这个实验决定是否需要改变装配方式。

## 切片二 · 两次压缩再重开，核对任务事实

沿正式 Resident 回合、检查点安装和 Reader 私人存储走一遍同一场景。第一次让首轮约定进入压缩范围；第二次在第四轮纠正之后施加上下文压力，让纠正也进入可压缩历史。保存每次安装前后实际请求及其覆盖的回合，在第二次安装后关闭进程，以同一私人库和聊天重开，送入最后的整理请求。用安装回执确认发生了两次不同历史边界的替换；分别标记仍以原文保留、由任务状态重投影、或仅由摘要传递的事实。[压缩实现](../crates/runtime/src/compaction.rs) · [安装与重开测试](../crates/reader-service/src/tests/mod.rs) · [已有真实草稿样本](../crates/runtime/fixtures/compaction-20261016/README.md)

先用受控模型和较小测试窗口驱动安装、存储、重开。用已知的“笔记已经保存”坏稿验证评测能识别摘要与磁盘矛盾。再在已确定的模型预算内用真实模型生成草稿，保留压缩前原文、两份实际摘要、恢复请求及最终讲义。真实摘要采样单独记账。降低测试窗口只用于到达压缩边界，10 万 token 分档由切片三实测。

**完成判据。** 第一次安装后旧约定仍适用；纠正生效后以及重开后，讲义按 0.01 计算，原 0.1 只可作为历史值。全程未获保存授权，检查摘要中的动作表述、模型对用户的说法和实际笔记数。摘要失真、正确检查点未装入恢复请求、请求正确但讲义算错，分别指向摘要生成、Reader 恢复和模型交付。每处都用当时的请求或产物举证；尚未触发的压缩或未评阅的语义保留相应状态。

## 切片三 · 跨模型检验工具循环与规则遵循

从现有同聊天评测和 Provider 请求记录器扩展一个配对场景。选两款可在**同一 Reader 工具集**下执行、能承载长档且能报告单次输入的模型，记录具体模型、配置、程序版本和工作树差异。准备两份冻结历史，保留相同首问、纠正、末问、可用原文和起始副作用状态；长档扩展真实中间讨论与工具回执，避免增添解题提示或重复提醒。短档使用普通可完成该任务的历史。每次从对应隔离副本继续执行，之后让模型自己调用工具。[同聊天评测入口](../evals/semantic/agent-run.mjs) · [Provider 记录器](../evals/semantic/provider-recorder.mjs) · [既有模型对照范围](../evals/answer-quality/README.md)

首批为 **2 款模型 × 2 种历史长度 × 2 次独立运行，共 8 个任务**，交错运行长短档。以最终用户请求后的**首次主模型采样**为分档点，按该次 Provider 回执核对短档低于、长档高于 100,000 输入 token。此后每次采样另记实际输入和检查点事件。若投影后长档未到、窗口放不下或用量缺失，原样保留并标明条件。

运行前固定模型版本、可比的采样设置、输出额度与工具权限，记录协议必需的差异。每次从实际请求核对两款模型是否看得见同一组工具和要求。若配置导致一组独有某个工具，这一对只能说明该配置下的产品表现。按已有授权填写单任务调用上限、时间上限与整批费用上限，包含循环与修复调用。超时、预算截停和人工介入均留在原样本。

| 要判断的行为 | 如何取证 |
|---|---|
| 规则是否首次遵循 | 取首次可供交付的讲义，与用户最新约定和算式逐项核对；再看最终版本，标明哪项经反馈才改正。 |
| 工具循环是否有进展 | 对照工具调用前后新增的原文、有效引用、预览或写入回执。正常分页、换范围补证计进展；重复同一诊断且事实无变化记空转。虚称已读、已存或已交付单列。 |
| 门禁和自愈是否有效 | 逐次记录无资格的交付尝试是否被拦、具体诊断是否进入下一次请求、模型是否自行补齐并成功交付。对照真实窄屏预览和最终截图，看首步数值、公式能否读全。没有触发拒绝的样本计入首次遵循结果，自愈率只用实际收到可修正诊断的样本作分母。 |

**完成判据。** 每个条件列出实际样本数、首次通过数、空转与虚报、拦截与恢复、最终交付，以及用量、耗时和人工介入。缺少某种真实违规时，该门禁在本批的自然触发次数记零，已有故障夹具另列。短长两档的小样本用于找可复现的失败；同一差异独立复现且会改变工程选择时，再增加中间长度定位区间。

### Resident · 两次安装与进程重开

65,536 token 测试窗口下，第 3、6 轮分别覆盖 4、10 个历史来源，真实日志在序号 20、46 安装了两个不同检查点。关闭进程后从原库启动另一 Reader，第八轮实际请求包含第二个检查点。受控正例的回答先给出 0.04，再给使用 η 和 0.01 的公式；初始、第七轮和重开后均为零条笔记。另一次只向草稿注入“笔记已经保存”，结构校验照常接纳，重开后的请求与受控回答都带有该错误事实，实际笔记仍为零。这证明该语义错误可穿过现有校验并跨重启保留。[正例](evidence/long-conversation-fold-20261119/final-positive/verification.json) · [故障注入](evidence/long-conversation-fold-20261119/controlled-bad-2/verification.json)

**真实摘要。** 用 DeepSeek Flash 替换草稿生成。首次实验安装了第一份，随后三次均在 4,096 输出 token 处截断，只有一次安装。定向复验复用了同一批来源的首份合格草稿，把第二个边界的输出上限调至 8,192；实际输出 7,376 token 后通过校验，第二份检查点安装并在重开后被消费。两份草稿保住讲义顺序、η 和保存条件，第二份保住 0.01；第一份对 0.1 所属参数仍有疑问。部分要求也通过 Reader 的其他状态进入模型。此处真实采样验证摘要，最终文字讲义仍由受控端生成。两批共 5 次真实请求，输入合计 100,359、输出 21,870 token，按高峰费率计费用上界 ¥0.254254。[两批回执与语义核对](evidence/long-conversation-live-drafts-20261119/README.md) · [复跑入口](../scripts/long_conversation_live_drafts.py)
