# 视频讲解结构与检索（VI14）

## 合同与来源接纳

`VideoDiscourseItem` 复用 `discourse-index.ts` 的 mode、local_function、rhetorical_move 和关系语义。视频角色使用独立 `id`，保存 `vu_ids`、局部摘要及带支持角色的 `EvidenceTarget`；关系保存目标角色、类型、方向、置信度、理由及来源。纯画面角色可以独立存在。

Engine 为角色分配 `discourse:<batch>:<local_id>`。同一 VU 可关联多个角色，一个角色也可关联多个 VU；每个关联必须有该 VU 的实际交付图片。每条关系的来源必须包含两端角色使用的全部来源，联合端点的文本与图片都要保留。错误来源 ID、缺失端点、空理由、非法角色/关系及低于既有 0.5 阈值的关系在接纳处拒绝。

语义判断由执行器根据实际材料完成。接纳门检查结构与来源支持，原材料核对验证关系含义。时间接近本身不建立语义关系。

## 构建与累积发布

`prepareVideoDiscourse → VI13 有界材料冻结 → VI4 四工具交付原生图片/转写 → candidate → admitVideoDiscourseCandidate → discourse.json + PNG → VI9 累积发布 → Book::load → video.search → book.text / video.read_frames → 本轮观察与引用`。

准备沿用 VI13 的 60 秒、至多八图和传输预算。原材料冻结在 `.build/video-graph/<batch>/input.json`；讲解任务在 `.build/video-discourse/<batch>/input.json` 补充确切 VU 与图片映射。原生图像四工具执行器保留实际输入、候选、调用回执和运行成本。纯文本任务可在视觉索引形成前准备。

每个已接纳批次写入 `video-enrichments/<batch>/discourse.json`，覆盖以 `discourse` 能力独立登记。发布必须具备真实产物与帧依赖，Rust 读取门再次核对材料、输入发布、角色语义、两端来源以及 VU 对应的原代表帧。批次不可覆盖；恢复跳过已完成模型任务，贡献不变时复用发布。

## 实际检索与 Runtime

`video.search` 保留原视觉候选，新增 `discourse`：角色摘要直接匹配问题词语，再沿入边和出边各展开一跳。来源角色、目标角色、关系类型、理由和证据记录在 `via`；`matched_terms=null` 表示该候选完全由关系到达。

讲解候选附 `read_hints` 和 `text_reads`，分别连接 `video.read_frames` 与 `book.text`。视觉和讲解候选各自计数、分页，共用请求的 `limit` 和 `offset`；独立覆盖随讲解结果返回。`within` 限定可回读来源；显式 `analysis_id` 时仅采用该视觉分析选中 VU 关联的角色。空结果仍保留覆盖信息。

Runtime 的工具发现与请求说明包含讲解结构、解释、示例、反例和条件限定。工具结果直接进入负责回答的主模型上下文。讲解候选保持 `candidate_only`；实际帧输入成功的主模型请求后，才能经原有观察账本获得来源资格。

## 操作与复现

```powershell
node --import tsx skills/build/video-discourse.ts prepare <工作区> <批次ID> <选择JSON>
node --import tsx skills/build/video-discourse.ts run <工作区> <批次ID> <Codex可执行文件> [publish_book可执行文件 独立服务根]
node --import tsx evals/video/vi14-run.ts <Codex可执行文件>
node evals/video/vi14-verify.mjs
```

选择 JSON 为 `{ "vu_ids": [...], "segment_ids": [...] }`，两列表至少一项非空。原片继续使用 VI11 工作区与独立书库。验证器通过 `VI14_SEARCH_EXE`、`VI14_FRAME_EXE` 或 `CARGO_TARGET_DIR/debug/examples/` 定位读取入口。
