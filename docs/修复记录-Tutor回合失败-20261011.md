# Tutor 两次回合失败修复（2026-10-11）

## 故障证据

- “继续学习”：2026-10-11 08:38（香港时间）的第五次模型采样以 `length` 结束，8,000 输出 token 全为推理。输入从 26,743 增到 111,877 token；约 38,600 字符的完整 Tutor 内容被动态快照重复注入五次。
- “开始给我讲讲1.4吧”：08:41 回合生成了有效摘要，但 Runtime 报 `checkpoint uses 14593 estimated tokens versus 3783 before compaction`。旧口径把压缩前所有工具结果先改成回执，却把压缩后当前回合的原文正文计入，导致错误的大小比较。

原始证据保存在 `tmp/turn-failure-diagnosis-20261011/`。生产聊天记录未改写。

## 修复

1. `run_context_inner` 把完整 Tutor 指令和学习上下文存入 `agent.tutor_context`，使用已有 `TurnFrozen` 投影。每次采样及终答只追加当前状态与操作权限；暂停仍在下一次采样生效，旧动态快照继续保留。
2. `compact_with_adapter` 负责生成并校验候选，`maybe_auto_compact` 负责采用决策。压缩前后都用实际采样请求构建器计算预算，保持工具正文策略、上下文、工具列表和预留一致。候选缩小且物理可容纳即可安装，软阈值不再成为硬失败条件。有效但无收益的候选在原请求可容纳时跳过；两者都装不下则返回 `ACTIVE_CONTEXT_EXHAUSTED`。生成、来源校验及保存失败仍报 `COMPACTION_FAILED`。
3. 旧历史不足以抵消最小检查点固定开销时，确定性跳过生成；回合内记住既有来源边界，避免对相同历史反复生成。只在候选被采用后持久化和替换活动检查点。
4. CatalogMatch 的 DeepSeek Flash 普通 Agent 显式输出上限和上下文预留同时设为 32,768，输入软阈值保持约 84,000。演示页作者 131,072、压缩 65,536、显式配置及临时评估额度保持各自规则。
