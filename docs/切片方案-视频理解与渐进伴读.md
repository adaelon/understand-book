## 1. 交付目标与对齐依据

**FrozenIntent**：导入一份本地教学视频；全片带时间定位的英文忠实转写就绪后开放伴读；用户从当前画面、框选区域或时间范围发问，Agent 读取真实材料解释卡点，回答旁可预览来源，随后继续观看。整讲中文、全片视觉索引、共享知识图谱和讲解结构渐进补齐；支持原音频复核、人工及模型辅助转写校正。

**成功标准**：以 CS336 2026 P2 的实际本地文件完成导入、构建、观看、带来源问答、同源补齐、校正改版与历史回看；下文每刀都有可重跑的输入、产物和验收记录。最早的伴读闭环是中间里程碑，首版完成还包含后续全部已确认能力。

**TermMap**：以下领域词均已在 [CONTEXT.md](../CONTEXT.md) 定义并由 Grill 确认；术语表中的 `NEW，已确认设计` 表示相对旧产品新增，含义已经收敛。

| 术语 | 本方案沿用的定义与责任 |
| --- | --- |
| 忠实转写正文、双语对照 | 英文原意与顺序构成正文；中文依附确切英文版本 |
| 媒体定位、Visual Unit | 前者定位确定原视频，后者组织可修订的视觉事件 |
| 视觉索引、局部联合抽取、联合证据 | 索引找候选；联合抽取形成有来源知识；联合证据说明各模态的支持部分 |

## 3. 来源、现场与观察合同

以下是实施用最小合同，类型名与文件名为拟议名称；VI1 将其落实到现有 Rust 权威 schema、生成绑定与对应 TS 合同。字段通过用途确定，继续使用项目已有身份和版本机制。

```text
VideoSourceRef = { media_id, media_revision }
TranscriptRef  = { transcript_id, transcript_revision, video: VideoSourceRef }
VideoMaterial  = { book_id, video: VideoSourceRef, transcript: TranscriptRef }
MediaLocation  = { video: VideoSourceRef, start_ms, end_ms }
FrameLocation  = { video: VideoSourceRef, actual_pts_ms, width, height }
FrameRegion    = { frame: FrameLocation, rect_normalized: [x, y, width, height] }

TranscriptSegment = { segment_id, text, location: MediaLocation }
TranscriptMap     = segment_id ↔ 英文正文 LID/UTF-16 范围 ↔ MediaLocation
Translation       = { transcript: TranscriptRef, segment_id, zh_text }

QuestionContext = {
  draft_id, publication: PublishedBookRef, material: VideoMaterial,
  frame: FrameLocation, region?: FrameRegion, range?: MediaLocation
}
EvidenceTarget =
  Text { publication, transcript?, text_range }
  | Visual { publication, frames: FrameLocation[], regions: FrameRegion[] }
  | Audio { publication, location: MediaLocation, review_result_ref }
  | Joint { members: (Text | Visual | Audio)[], support_roles }
```

`media_id/media_revision` 识别导入后保留的确定原片，移动工作区保持身份。原视频或英文正文改版，沿材料更新入口产生新 `book_id` 和明确前版关系；同源译文、VU、索引及语义补齐保持 `book_id`，产生新 `publication_id`。正文文字相同不能证明两份原视频相同。

原视频、转写原始结果、规范正文、映射和派生产物保存在构建工作区中，以相对路径关联。导入外部文件的路径只记来源；后续播放、构建和恢复读取已导入材料。全片转写前允许从导入状态播放原片，Book 与可问答发布在正文及映射成立后生成。

准备态视频以 `VideoSourceRef` 登记媒体读取与已有访问授权，本地入口和服务器上已登记的准备态入口都可先播放。VI3 完成后关联首个 `PublishedBookRef`，沿原视频身份承接播放进度。已发布包保持只读；按需抽帧和音频切片使用现有纯内容派生缓存，带用户问题的复核结果沿该用户的运行与历史保存。

英文正文按自然语段进入现有 LID 基座，保留机器转写属性；同一段可关联多个识别片段。时间映射表达实际可用精度：只有句段级时间时，界面按句段定位；英文中的精确字符范围不能凭空提供逐词音频时刻。中文按英文段落关联，不改变英文 LID 身份。

裁剪位置按解码后原帧坐标归一化，界面缩放和播放器黑边只影响显示。抽帧结果返回实际 PTS；请求时刻与实际帧时刻分别保留。读取时间范围得到的有序帧，只证明已读取这些帧；持续过程需要继续取样或复核相应片段。

```text
提问现场 / 索引命中 / 图谱与讲解关系
    → 候选位置
    → 读取有界转写、真实帧、裁剪或短音频
    → 实际输入主模型 / 音频复核工具处理
    → 本轮 Observation
    → source.present
    → 原发布下的 SourceRef 与历史记录
```

索引卡片、OCR、译文和语义结果保留派生属性。纯画面证据无须虚构 LID；联合证据分别保留文本、画面或音频的依据。`source.present` 保留既有文本入口，并增加消费本轮媒体观察的类型分支。模型生成的说明、已有媒体文件路径或用户选中的范围本身，都不会被登记成已观察媒体。

视频帧通过现有图片请求通道交给负责回答的主模型；它和演示检查截图分别携带用途及来源。媒体观察记录关联实际成功处理的请求或工具结果，读失败时保持未观察。旧引用固定原发布、原媒体位置与必要快照，VU 拆分合并后照原位置打开。

## 4. 构建、能力覆盖与同源发布

```text
导入原片 ───────────────────────────────→ 原片可播放
   ├─ 音频准备 → 全片英文转写 → 忠实正文 + 时间映射 → 伴读可用
   │                              └─ 整讲中文分批生成
   └─ 变化候选 + 补充采样 → 真实帧 → VU / 视觉检索卡片
                                      │
            英文转写 + 有界真实帧 ──────┴→ 联合 / 单模态语义候选
                                           ├─ 共享知识图谱
                                           └─ 讲解结构
各阶段已接纳成果 → 累积发布快照 → 资源齐全的不可变发布 → 窗口间隙接入
```

转写服务承担语音识别与时间定位，允许按 VQ15 单独配置。视觉判断、翻译、联合抽取、讲解结构及模型辅助校正沿外部 Harness 执行；Build Engine 继续拥有任务、候选接纳、阶段状态、恢复和发布。读时 Agent 消费已发布材料及按需媒体工具。

| 能力 | 可用条件 | 覆盖的表达 |
| --- | --- | --- |
| 原片播放 | 已导入媒体可读取且播放器可解码 | 原片时长与播放状态 |
| 伴读问答 | 全片英文转写及时间映射完成、首个发布可读，读时图像通道可用 | 语言全片可检索；视觉尚未覆盖的范围单列 |
| 双语对照 | 对应英文段落的中文已接纳 | 已翻译段落及待处理、失败段落 |
| 视觉检索 | 对应范围的 VU、卡片、实际帧定位及必要资源共同可读 | 已处理区间及缺口 |
| 共享图谱 / 讲解结构 | 当前材料版本下的候选通过来源和结构接纳 | 各自覆盖范围及未处理范围 |
| 原音频复核 | 相应短片段可读取且复核工具可调用 | 实际处理范围、结果与仍有疑点的措辞 |

全片转写完成要求处理计划覆盖整片音轨、各块成功且时间映射连续可解释；静音可以没有文字但有已处理区间。失败片段不能作为静音跳过。低把握术语保留疑点，转写就绪不承诺每个词都已人工核对。

覆盖是已接纳材料区间的集合。处理完开头和结尾时，中间的缺口仍可见。准备中的候选与最终可消费成果分别表达；问答能够利用未建索引位置的按需真实观察。

同源新发布累积仍有效的已完成成果，按同一发布链前进。翻译与视觉任务先后完成时，后一次快照保留前一次仍有效的能力，旧批次到达不能使当前覆盖倒退。发布登记沿用已有清单、校验和原子边界；实际依赖未齐的批次继续留在构建态。

## 5. 提问期间的材料固定

```text
Watching
  ├─ 首次实际输入 / 明确选帧选区或时间范围 → DraftBound
  └─ 同源发布可用，窗口无草稿且无在途回答 → 接入并继续 Watching

DraftBound ─ 发送并接受 ─→ Queued / Running ─ 终态保存 ─→ Watching
     ├─ 手动继续播放：绑定现场保持原值
     ├─ 发送失败：保留草稿和绑定
     └─ 清空全部提问内容或取消草稿：释放绑定
```

首次实际输入暂停一次；单纯聚焦输入框不暂停。发送使用绑定时的 `QuestionContext`，接单后的在途状态包含准备、排队、运行和结果待保存。绑定由草稿移交 Run 时保持连续。显式选区或时间范围属于草稿内容，只有文字清空而选择仍在时继续保留绑定。

窗口与服务器共同参与该边界：界面持有正在编辑的草稿及播放状态；服务器持有草稿的材料绑定，并与该窗口接单、发布接入共用现有状态串行化入口。异步结果按草稿与现场身份应用；恢复窗口时先恢复仍存在的草稿/在途回合，再判断是否接入新材料。

```text
can_adopt(window, publication) =
  publication 已验收且依赖可读
  and 原视频身份、英文转写版本均相同
  and publication 位于当前同源发布之后
  and window 没有未发送草稿
  and window 没有在途回答

adopt_same_source → 保留播放位置、暂停/播放、倍速、聊天、滚动锚点
source_revision  → 提供新版入口，由用户主动使用
```

接入操作替换该窗口读取的发布及能力投影，保留观看现场。当前播放器的原片未变时保持媒体元素及播放状态；译文补齐按英文段落锚点更新。其他窗口按各自草稿与 Run 状态处理。回答及历史引用始终读取自己保存的发布。

## VI8b 起止时间范围提问

**依赖与边界**：VI5–VI7。时间选择可独立于框选使用；两者同时存在时分别保留关注点与过程范围。

## VI9 同源累积发布与保留现场的接入

**目标与产出**：实现第 4–5 节的累积发布和同源接入操作，将后台已完成片段按有意义的批次聚合后提供给正在观看的窗口。先用有真实依赖文件的两批成果夹具接通全链路，发布粒度与媒体复制体积一并记录。

## VI11 算法候选与视觉事件单元

**目标与产出**：建立全片候选扫描、补充取帧、视觉模型事件划分与来源接纳；发布含原片位置、代表帧、画面文字、变化线索及相关转写的 VU 和覆盖。

**验收**：VI0a 中代码微改与渐进画面能进入候选，并形成可回读的前后位置；讲者摄像头运动不会持续挤掉讲解区域的候选。重复画面可复用昂贵描述，每次出现仍保留独立时间和附近转写。模型划分越界或缺实际帧时不接纳；重划分后旧引用不变。

**依赖与边界**：VI4、VI9。采样间隔和变化阈值由同一标注样本上的遗漏与处理成本确定；正文中的每秒采样讨论不直接冻结为产品参数。

## VI12 视觉检索与问题驱动精读

**目标与产出**：让 Agent 根据画面文字、描述或已有 VU 查到候选位置，再通过 VI5 读取真实材料；返回当前索引覆盖和缺口。

**接点**：Core 视觉检索产物、`crates/read-tools/src/lib.rs`、`tool_registry.rs`、读时上下文选择。拟议 `video.search(query, within?) → candidates + coverage`。

**验收**：用固定问题集查找前文图示、只有画面出现的代码和重复画面的不同讲解位置；每个要求找到的样例至少召回一处有用原片候选，并保存随后实际读取的证据。索引尚未处理当前位置时仍可按当前帧提问；无支持答案的样例不由描述伪造证据。

**依赖与边界**：VI5、VI11。先验证画面文字/描述的检索路线；是否加入语义向量或直接图文检索，以未被现有路线满足的真实问题决定，并记录具体增益与成本。

## VI13 局部联合抽取与共享知识图谱

**目标与产出**：同一视频内，文本、视觉与联合抽取进入一套知识对象及关系；每个候选保留其支持来源，纯视觉内容能独立存在。

**接点**：`GraphNode` 及图谱贡献/接纳/合并合同、现有 Pass1/Pass2 和读时图谱召回，VI4 媒体输入。图谱节点身份与媒体来源采用类型化扩展。

**验收**：真实联合样例分别保存转写提供和画面提供的信息，完整关系可回读两者；纯视觉样例无需伪造文本锚点。两个同名但不同含义的候选不被自动合并；确认同一对象的语言和画面出现可共同召回。来源不成立的候选在接纳处退出，现有文本图谱回归继续通过。

**依赖与边界**：VI1、VI4、VI11、VI12。根据工作单元需要选择联合或单模态路径，一份视频内部形成共享图谱。

## VI14 讲解结构入库并参与检索

**目标与产出**：扩展 discourse 的媒体来源，保存图示解释、例子、反例、条件限定等关系，并用于候选召回或上下文选择。

**接点**：`discourse-index.ts`、对应 sidecar 构建/校验、读时检索与 Runtime 上下文；复用既有讲解角色和关系语义。

**验收**：固定原片问题及输入条件，比较启用/关闭讲解结构的定位结果；记录关系是否实际改变候选或减少找到所需原片的读取。至少一例能沿“解释/例子/限制条件”到达支持片段。多对多的 VU 与讲解角色保持来源，缺图像或文本支持的关系不能只凭时间接近成立。

**依赖与边界**：VI13。若产物没有参与实际检索或没有表现出预期用途，本刀继续修正消费链路。

## VI15 日常伴读的短原音频复核

**目标与产出**：将 VI0b 的音频能力接入读时工具，按疑点截取短原音频，与转写及相关画面复核讲者措辞；结果进入当前回答和对应音频来源。

**接点**：服务端音频处理/服务配置、Runtime 工具注册与观察账本、VI7 媒体来源。拟议 `video.review_audio(location, question) → reviewed_words + uncertainties + observation`。

**验收**：原音频确实进入复核工具；一处可听清的识别错误得到有定位的核对结果，一处不清晰内容保留疑点。用户可从回答旁回听对应片段；主模型引用的是复核工具结果及原音频范围。原有保存正文不会因这次提问而变化。

**依赖与边界**：VI0b、VI5、VI7。本刀完成日常问答路径，修订保存由 VI16/VI17 承接。

## VI16 人工编辑与模型校正草稿

**目标与产出**：材料维护方可以人工编辑转写，或主动请求外部 Harness 生成校正草稿；草稿列出修改前后、理由与原材料依据，支持整批或部分采纳。

**接点**：构建材料维护入口、VI4 执行器、VI15 音频复核及拟新增校正草稿界面/数据。草稿绑定输入转写版本及对应语段。

**验收**：真实疑点产生可检查的建议，拒绝的修改保持原文，部分采纳只进入选择的修改；草稿形成后人工再次编辑同一语段时，旧建议保留待处理状态，不能覆盖新内容。画面解释或补充知识保持独立依据，不被混写为讲者原话。

**依赖与边界**：VI4、VI15。本刀形成已采纳的新正文输入；发布版本与下游传播由下一刀完成。

## VI17 来源改版与派生成果更新

**目标与产出**：将采纳后的正文修订或显式替换原片接入材料更新流程，生成独立新 `book_id`，重算受影响的时间映射、译文、视觉关联、图谱及讲解成果，发布可主动切换的新版。

**接点**：现有工作区更新/新旧对应、BuildPlan/阶段恢复、发布书库、Reader 新版入口，VI1 来源身份和各视频产物输入依赖。

**验收**：修正一个实际术语后，对应中文与相关语义按新版输入更新；未变且完整输入等价的模型结果可复用。旧回答、笔记和聊天仍打开旧正文及原媒体；同源补齐机制不会把修订版自动切入其他窗口。新版构建失败时旧版继续可用；替换剪辑后的原片不会沿旧时间码假装定位成功。

**依赖与边界**：VI9、VI10、VI13、VI14、VI16。沿 ADR-0146 的实际输入和引用对应判定复用，来源更新与 VU 重划分分别处理。

## VI18 整讲、恢复与安装态验收

**目标与产出**：用选定 CS336 文件完成首版全链路，形成可复查报告、处理耗时/费用/体积记录及受支持环境说明；将媒体依赖、转写配置、构建资产和 Reader 接线纳入实际分发包。

**接点**：`evals/video/`，Core/Runtime/Server/Web 的定向回归，桌面安装资产，Linux 发布与现有资源路由，视频验收记录。

**验收**：第 7 节的真实场景与确定性行为均通过；整讲中文、视觉索引、共享图谱、讲解结构完成其声明覆盖。正式入口能从原片导入并恢复中断；实际安装环境能播放、构建和读取原媒体；Linux 两个窗口分别遵守草稿与原发布绑定。安装后缺少解码工具、配置或模型能力时给出实际缺项及恢复入口。

**依赖与边界**：VI0a–VI17。只对实际完成的宿主/平台组合声明支持，未通过的能力记录在报告的已知问题中。

## 7. 验收方法与结果归档

执行验证前，写明要检测的具体失败及失败后要修改的责任点。确定性合同交给测试判断，语义内容与听辨准确性对照原片核实；模型自评分不作为完成凭据。

| 场景 | 可观察的通过结果 | 失败后的处理 |
| --- | --- | --- |
| 无独立字幕的整讲 | 全片原声经过转写，完整处理覆盖及时间映射可见 | 回到 VI3 修分块、识别/对齐或恢复 |
| 当前代码/公式卡点 | 主模型收到真实图像，关键符号与引用画面一致 | 回到 VI5 修读取、分辨率或图像投影 |
| 08:12 输入、08:27 发送 | 固定 08:12 的帧、范围和材料 | 回到 VI6 修草稿至 Run 的绑定 |
| 框选 / 过程问题 | 原图坐标正确，前后帧有序且引用范围有依据 | 回到 VI8a/VI8b 修坐标/时序或按需读取 |
| 前文图示 / 重复画面 | 检索到实际有用的出现位置并读回原片 | 区分 VI11 候选遗漏与 VI12 检索失配 |
| 纯视觉 / 联合知识 | 支持结论的各来源可分别回看 | 回到 VI13 的输入、候选门或合并规则 |
| 图示解释 / 条件限制 | discourse 关系被实际用于找到材料 | 回到 VI14 的产物或消费路径 |
| 中文与索引交错补齐 | 空闲窗自动接入，忙窗保持，已具能力不倒退 | 回到 VI9/VI10 修快照组装或接入 |
| 音频疑点及无答案问题 | 实际复核并保留仍不确定之处 | 回到 VI15 或来源交付，不制造确定结论 |
| 校正、改版和历史回看 | 新版更新受影响成果，旧引用仍指原材料 | 回到 VI16/VI17 的采纳或版本传播 |
| 中断与恢复 | 已接纳成果保留，只恢复缺失阶段 | 修相应阶段的恢复和发布回执消费 |

新增测试按 `video-*` 文件或 `video_` 用例前缀组织，命名随实现固定；每刀只运行触达路径及必要相邻回归。现有入口可复用：Core 的 `source-manifest.test.ts`、`build-executor-mcp.test.ts`、`executor-transport.test.ts`；Runtime/Server 的来源、运行归属和发布测试；Web 的 `RightRail.test.ts`、`api.source-manifest.test.ts`，以及多人浏览器测试。类型/schema 变化运行对应生成及类型检查，完整安装验收集中在 VI18。

每份真实结果至少记录：原片与转写版本、实际发布、处理范围、宿主/模型/服务及配置、问题、已读取帧/音频/文本、回答及原来源、人工核对的具体差异。性能记录分为首次英文可问答耗时、整讲各能力完成耗时、问答取证耗时、媒体与产物体积、实际调用用量和可获得费用；未知用量保持未知。不同配置使用同一输入比较，并说明会据此改变哪个实现选择。

## 8. 已知限制与待实验收敛项

- VI0a 已建立实际 2026 P2 原片样例与媒体基线；原话/停顿待听核。没有整讲转写、视觉索引或带来源问答的完整验收。固定位置微改及返回画面由明确来源的补充教学夹具覆盖，详见[视频验收](验收-视频理解.md)。
- 首个转写服务、短音频复核方式、图像宿主支持和输入上限由 VI0b/VI0c 实测；媒体规格与分发依赖由 VI0a/VI2/VI18 确定。某条通路失败时保留该能力的未完成状态。
- 首版针对 PPT、板书、代码、论文和流程图等教学内容；高速动作或复杂连续操作需要另定观察能力。原片烧录字幕可能参与视觉观察，验收须区分转写、画面文字和人工核对来源。
- 全片索引、图谱和讲解结构提供检索基础；已处理范围与语义判断仍需通过真实问题检验。可用转写也允许存在待校正术语。
- 本方案交付视频卡点伴读。网站下载、跨视频知识网络、跨剪辑自动迁移引用和正式课程带学沿各自后续范围处理。
