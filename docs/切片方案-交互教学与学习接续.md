## 1. 目标与完成定义

学习者在同一个教具上尝试、提问、观看教师演示，再继续操作。教师知道页面当前实际展示了什么，知道自己已经给过什么帮助；下一次对话能带着此前作品、评价和仍未确认的关系继续，采用学习者此刻明确提出的支撑方式。

五项已接受方向及编号沿用源码索引：P1 语义现场、P2 连续演示、P3 支撑与判断、P4 证据接续、P5 记忆影响支撑与明确请求优先。全部完成须贯通以下实例：

> 学习者把小车 B 的速度从 1 m/s 改到 2 m/s，但尚未应用，图中仍是 10 秒走 10 米。他问“为什么没有变”。教师先说明当前输入与已显示结果的差别，在同一教具上完成应用，并保留共同时间下 A 走 10 米、B 走 20 米的对照。之后学习者说“速度翻倍，所以同一时间距离翻倍”。系统记录这句话发生在已看过演示的条件下。重开后教师可以沿用此作品讲新的关系；若学习者说“这次直接讲公式”，立即解释公式。

“图动了”“回答保存了”“模型输入出现摘要”各自只证明对应环节。完成闭环要同时看到正确现场、真实帮助归属、原表达回读，以及下一轮实际采用了相关依据。

## 3. 现场合同

### 3.1 一个快照包含两类观察

保留 `PresentationState.values`、`visible_step`、`observed_result`、`source_ref_ids`，增加可选 `observation`：

```ts
type PresentationObservation = {
  summary: string;
  state: Record<string, unknown>;
  rendered?: Record<string, unknown>;
};
type PresentationReaderResult = {
  values: Record<string, unknown>; // 沿用原页面可恢复参数
  visible_step: string | null;
  observation?: PresentationObservation;
};
```

`values.page` 继续承担可恢复参数；既有 `state_contract` 继续解释标量参数的含义、单位和定义域。`observation` 是从同一计算状态投影的教学语义；`observed_result` 仍由宿主读取实际可见 DOM。两者一起进入同一个 `PresentationFollowUp` 回执，不用页面自述替换宿主观察。

示例，尚未应用的新速度：

```json
{
  "summary": "B 的速度已设为 2 m/s；画面仍显示按 1 m/s 计算的 10 秒、10 米结果，等待应用。",
  "state": {"speed_b_m_s": 2, "time_s": 10, "phase": "awaiting_apply"},
  "rendered": {"speed_b_m_s": 1, "time_s": 10, "distance_a_m": 10, "distance_b_m": 10}
}
```

即时重绘页省略 `rendered`；有应用／计算步骤时，只有已成为实际显示结果的计算才能更新它。初次尚无结果、计算失败和已显示旧结果分别如实表达。页面读状态保持同步、只读，不能为回答观察请求自动应用参数或重播演示。

存在应用滞后时，可恢复参数必须同时保留待应用输入、最后已显示结果使用的输入以及已完成语义步骤。例如 `input_speed_b_m_s=2`、`applied_speed_b_m_s=1` 分别进入 `values.page` 与 `state_contract`；重开按 applied 值重建旧结果，并保留 input 值等待应用。`observation` 从这些状态投影，不能成为第二套恢复数据或在重开时把待应用值自动当作结果。

参数编辑、程序动作、重置、异步完成及有语义变化的计时更新，都应使下一次读取反映实际状态；持久保存仍沿已有 `commitState` 的完成动作粒度。动画逐帧变化不增加落盘或模型请求。

### 3.2 保存和追问继续使用原回执

```text
原页面计算状态
  → 同步 reader + 宿主可见文本
  → PresentationState（含 observation）
  → 现有 save_state
  → PresentationFollowUp
  → 本次追问的确切现场
```

页面重开仍先恢复参数，再从同一模型重建显示；恢复后的新快照可以说明“现在看到什么”，原追问继续引用原快照。缺少语义观察时保留宿主能看到的文本和控件，并明确所需关系尚无法读出。

依据：源码索引 O1–O3；本项目状态指导与快照合同。

## 4. 教师实时操作合同

### 4.1 观察与动作入口

新增 `presentation.interact`，与制作内容的 `presentation.author` 分工。它只有 `observe` 和 `act` 两种操作；工具定义、注册与示例沿既有单一工具合同维护方式生成。

```json
{
  "operation": "observe",
  "reference": {"presentation_id": "<确切已交付教具>", "revision": 1}
}
```

成功观察返回当前可操作的页面身份、`PresentationState`、保存回执、参数定义 `state_contract` 和 `available_actions`。清单由该内容版本声明，并与实际页面中的控件／区域对应。Agent 从该清单选择，不猜 CSS 选择器。

```json
{
  "operation": "act",
  "reference": {"presentation_id": "<同一教具>", "revision": 1},
  "based_on": "<observe 返回的 saved_state_ref>",
  "action": {"kind": "set_parameters", "values": {"input_speed_b_m_s": 2}}
}
```

首个动作集合如下；每个页面只声明自身确实支持的子集：

| 动作 | 参数与执行含义 |
| --- | --- |
| `set_parameters` | 修改页面声明可操作的参数，调用与原控件共用的更新函数；应用时机由页面语义决定 |
| `invoke` | 执行声明的 `action_id`，如 `apply`、`reset`、`next_step`；使用页面已有操作函数 |
| `highlight` | 定位并突出已存在的区域，复用 `locate-region` 的实际定位机制 |
| `reveal` | 揭示该版本声明的内容区域，并参与原页面状态保存／恢复 |
| `annotate` | 显示该版本已有并经过审阅的注释区域 |

作者合同在原 `write/patch` 内容元数据中新增 `action_contract`，与内容版本一同保存。例如：

```json
[
  {"kind": "set_parameters", "parameters": ["input_speed_b_m_s"]},
  {"kind": "invoke", "action_id": "apply", "label": "应用当前参数"},
  {"kind": "highlight", "region_id": "distance-comparison"},
  {"kind": "reveal", "region_id": "distance-relation"}
]
```

参数含义与范围引用原 `state_contract`；区域与调用动作分别绑定实际区域标识和页面操作入口。`set_parameters.values` 的键使用清单中实际声明的参数名。

页面通过新增 `window.presentation.registerActionHandler(async action => { ... })` 注册一个处理回调，复用自己的状态、控件处理和渲染函数。异步回调完成表示相应操作已经成为实际显示状态；例如 `set_parameters` 可以只完成输入更新，`invoke(apply)` 才等待计算显示。宿主在回调完成后统一采集、保存和回传。预览确认声明与实际控件／区域、handler 一致后才交付。

需要新增讲解文字时，仍经过既有内容制作、预览、审阅和交付；首版 `annotate` 不接受临时注入的自由文本。

`observe` 针对当前已打开页面；`act` 保留 `PresentationRef`，只推进运行状态。更改 HTML、来源、计算模型或未声明的控件属于内容修订。当前窗口未打开该教具时，返回具体不可用原因，由现有打开入口恢复后再操作。

### 4.2 真实完成回执

```text
Runtime 工具调用
  → ResidentStatePort 的实时交互端口
  → 活跃 Run 的定向页面命令
  → AgentPresentation → iframe 原处理函数
  → 浏览器完成该动作，采集 OM1 快照
  → 原 save_state 持久化
  → 命令结果回到本次工具调用
  → Agent 根据实际结果继续
```

宿主分配命令身份，绑定运行、当前阅读现场和确切教具版本；页面完成并保存后才返回 `applied`、新状态和回执。发出消息、经过固定延时或模型写出“已操作”均不构成完成。

网络端沿 `agent_stream`／现有运行订阅下发定向命令，结果通过既有工作区 action 路由返回；本地 Reader 沿本地运行观察和 presentation 路由完成同一合同。命令等待期间释放共享用户／工作区锁，回调可以正常写入结果。

关闭页面、切换现场、取消运行、断线恢复都是正常产品路径。待执行命令只对原页面绑定有效；重连不能从历史流重放已执行动作。基于旧观察而用户已编辑将被操作的参数时，返回当前观察让 Agent 重新判断；播放位置的自然推进按页面原操作语义处理，不能简单以“任意状态变化”拒绝所有动作。超时或取消不自动重试有副作用的动作，下一步先观察现场。

### 4.3 教师动作的证据归属

成功动作及前后快照进入教师交付／帮助记录。`reveal`、`annotate` 或实际完成的讲解演示沿现有帮助合同记录可见内容和回执，并供下一次真实学习者回应关联 `assistance_refs`。单纯定位或调整布局仍只是操作事实。

教师触发页面事件不能变成 `LearnerAction`；页面请求答题继续打开现有宿主表单，只有学习者实际提交才记录作答。教师演示、点击“继续”和页面结果正确，都不能单独支持学习者已独立掌握。

已声明且已审阅的操作在当前教学设计内执行；新增解释继续遵守现有教学审阅规则。动作失败时，回答依据失败后实际状态，不声称已经演示成功。

依据：源码索引 A1–A4；实际执行回执及帮助绑定为本项目设计。

## 5. 学习接续与支撑选择合同

### 5.1 接续视图的内容与权威

现有 `learner_context.learning_opportunity.continuity` 按当前目标、教学设计／焦点及已选入历史的相关引用构建；保留现有分页回读工具。已实现的核心字段如下：

```text
continuity:
  scope: 当前 learning_workspace_id、目标版本、来源版本、design_ref
  previous_work[]:
    action_ref / delivery_ref / saved_state_ref（存在什么就带什么）
    source_refs、fact_refs、evidence_refs、learner_quote_excerpt
    assistance_refs、assessment_ref、assessment_status
  open_questions: 来自当前设计的 open_question_refs 与相关依据
  teaching_implications[]: 原 evidence_ref、原 teaching_implication、适用范围
  read_more: 尚需回读的确切记录引用及现有工具入口
```

视图只组织已保存的作品、原话、评价和解释。服务端不从聊天关键词自动创造“误解”或“掌握”；有概念判断时，由 Agent 按原证据合同写入可修订解释。原记录可回读，截断片段注明截断。

最新作品与评价通过实际 `action_ref`／修订关系关联。旧作答的评价不能套到新作答；没有对应评价时表达“待评价”。已被 `supersedes` 或用户纠正替代的理解不继续作为当前结论。先前受助完成与独立完成继续分别表达。

选入的旧记录沿 ADR-0170 保留用户选择的提交前缀与原归属；跨书引用保留确切出版身份。当前工作区的新判断写入当前工作区，原历史不被改写。当前请求引用但投影未展开的记录通过 `workspace.records.read`、既有学习证据／trace 读取入口补齐。

教师先前发现了什么、审阅要求改了什么，仍从 `agent_working_state` 取得；不混入学习者能力判断。上下文重开或压缩后，从持久事实重建此视图，不依赖内存摘要存活。

### 5.2 如何影响下一次教学

已有事实：“用户看过速度对照演示后说‘同一时间距离翻倍’”。合适的接续含义是：“已有受助表达；若当前目标需要独立运用，可以在新数值下验证同一关系。”不能直接推成“用户已独立掌握比例关系”，也不能仅因未测过而推成“不会”。

Agent 在当前 TeachingDesign 的 `basis_refs`、`revision_reason` 与所选支撑中反映采用了哪条依据。关系不清时可以继续解释、换例子或提供操作框架；确实需要学习者做判断时才发出具体邀请。开放任务依据用户的理由与约束展开，封闭任务可以核对可检验结果。

优先次序固定为：当前明确请求 → 当前任务中的真实表达与已接受约束 → 相关历史证据中的教学含义 → 通用教学方法。这个顺序决定支撑，不改变原事实。

例如“这次直接讲公式”立即改变本轮交付，不要求用户再证明需要直接解释；“我想深入推导”不能被历史初学者推断压回基础问答。临时要求留在当前任务上下文；明确长期偏好仍走已有个人记忆入口和范围合同。

依据：源码索引 T1–T3、M1–M5、D1–D4；本项目 ADR-0164／0169／0170 和既有 `teaching_implication`。
