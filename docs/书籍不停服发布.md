# 书籍不停服发布

当前状态：2026-10-15 22:44 HKT 已部署到正式服务，release 为 `online-publication-20261015`，schema 14。Linux 实机 4 项测试和正式构建通过。部署证据见 [上线记录](performance/online-publication-20261015/README.md)。

命令行在线导入由正在运行的 Linux 阅读服务执行。上传和书籍准备不会重启服务；成功后，指定读者刷新书架即可看到新发布，已经打开的阅读现场和在途回答继续使用原发布。

## 使用

先把完整书籍输入上传至服务器的独立目录，并使服务账户 `understand-book` 可读。输入沿用 `publish_book import` 的现有完整包合同和 readiness 检查。不要改写已经发布的目录。

在服务器执行：

```bash
runuser -u understand-book -- \
  /opt/understand-book/releases/online-publication-20261015/target/release/publish_book \
  /opt/understand-book/data/multi-reader-to-tb-20261012 \
  online-import /opt/understand-book/acceptance/<本次上传目录> \
  --operation-id understandbook-20261015-v1 \
  --grant admin --grant adaelon
```

`--grant` 可重复，只授予列出的账号；没有全员授权或未来账号自动授权。正文内容或实际来源附件改变时，仍按既有约定使用新的 `book_id`。

每次新发布选择一个新的 `--operation-id`，使用英文字母、数字、连字符或下划线，最长 128 字符。SSH 中断或命令没有收到结果时，重跑**完全相同的命令与操作编号**。已完成的请求返回原发布清单，不重复导入，也不重新授予之后被撤销的权限。同一编号搭配不同目录或账号名单会返回冲突。

命令成功输出原生发布清单，其中 `reference` 是确切的书籍和发布身份。发布失败不改变当前默认版本，不会出现部分账号已授权的可见发布。原 `import`、`grant`、`revoke`、`default`、`grant-all` 离线命令保持原行为。

## 实现

服务在私人数据根创建 `publish.sock`，权限 0600，使用独立线程接收本机操作请求。服务始终持有 `ServiceWriter`；命令行通过本地 Unix socket 交付请求。文件复制、既有校验、目录封存使用发布线程的独立数据库连接，不持有读者的书库互斥锁。

完整目录准备好以后，在一个短事务里登记发布、更新默认版本、写入指定授权并记录操作结果。读者仍从现有书库接口查询元数据，内容缓存按确切发布身份区分，运行中引用不被切换。

schema 14 增加 `publication_operations`，只保存操作编号、请求字段和已发布引用，供断线重试读取。它与发布和授权在同一事务提交。

## 部署与限制

首次启用需要安装包含此功能的服务和维护工具，并重启一次；此后的书籍在线发布不用重启。schema 14 由服务启动时沿现有升级路径创建，保留发布前备份；旧 schema 13 程序不能直接打开升级后的数据根。

在线命令在 Linux 服务器本机运行，Windows 操作者通过 SSH 调用。目录需在收到结果前保持稳定。重复使用已完成的操作编号表示查询原结果，修改材料后发布新版必须换操作编号。

这次实现不推送刷新到已打开的书架；刷新书架后可见新发布。
