# 选择题、计算题与题内辅导

2026-11-07 · 首版题卡已接入阅读器。[最优化三题试用与实测记录](../examples/optimization-practice/README.md)

先让学生在阅读器里把一道题做完。学生可以直接答，也可以把还没想清楚的一步交给助教讨论。两条路共用同一道题，只有学生明确提交的答案进入判题。最优化教辅可以用这套能力交付原创题，现有「练一练」和「今日练习」也能使用。

## 一道题在学生面前怎样工作

| | 选择题 | 计算题 |
| --- | --- | --- |
| 看到题目 | 题干注明单选或多选，整行选项可点。选中后可以改，点「提交选项」才判。 | 题干写明要算什么、是否要求过程。用一个多行编辑区写思路和解答，接受普通文字、分行算式和 LaTeX，可预览公式。 |
| 中途有想法 | 每题都有「我的思路」输入框，可以只选答案，也可以写“我在 B 和 D 之间犹豫，因为……”，点「问这一步」。 | 在同一个编辑区点「问这一步」，可以引用其中一行，也可以发送当前整段。回复出现在题下，原稿继续可编辑。 |
| 正式交卷 | 只交所选选项。曾经讨论过的猜想保留在讨论里。 | 点「提交解答」才提交当前完整文本。学生可以先删掉猜想、补上理由。之前的讨论和助教的文字不会自动拼进答案。 |
| 交卷以后 | 显示本次选择和判断。选对但已经发出的理由有漏洞，可以继续讨论理由，保留原判。 | 反馈先指出成立的步骤和第一处影响结论的问题。可以「修改后再交」或「查看完整解答」，每次改答保留自己的版本。 |

「问这一步」就近显示在编辑区，主操作始终是提交。手机上沿同一列依次排题目、作答和题内往返，键盘打开后也能发出当前思路。未发出的文字随本设备的该账号、工作区和具体题目保存，切题再回来接着写。已发送的思路可以沿项目已有操作「留为我的想法」，由学生决定哪些值得存入个人笔记。

### 一个最优化样例

原创计算题：在 $x\geq 3$ 时，求 $(x-1)^2$ 的最小值与取得点，并说明理由。

学生在草稿中写“令导数等于零得 $x=1$，所以最小值是 0？”，点「问这一步」。助教可以回：“求导这一步找到了驻点。把 1 代回题目给的约束，会得到什么？”题目保持作答中，学生可以继续回复，也可以自己改稿。

同一题，另一位学生写“我算出了 3 和 4，但分不清哪个该填在最小值那里”。助教此时可以问：“你把哪个数代入了目标函数，又得到了哪个数？”这位学生已经找到边界，值得讨论的是取得点与函数值的区别。

如果学生最终提交“$x-1\geq 2$，所以 $(x-1)^2\geq 4$，在 $x=3$ 取到”，这份解答应判正确，直接证明和求导都可接受。只提交“4”时，可以肯定最小值，指出取得点和理由尚缺。对“$x=3$ 是最小值”的表述，可以请学生分别写出取得点和函数值。三个反馈针对不同的学生原话。

## DeepTutor 的参照

核对的是 HKUDS/DeepTutor v1.5.16 的 Quiz 源码。选择题点选后检查答案，书面题可输入文字或附图，提交后可以对照解析、请求 AI 评阅、重试。题卡的 Follow-up 入口在提交后出现，以具体题目为单位带入题干、学生答案以及已有评语。它的独立 Practice 页面还把已做题目用于错题回看和到期复习。[测验题卡](https://github.com/HKUDS/DeepTutor/blob/v1.5.16/web/components/quiz/QuizViewer.tsx) · [逐题追问的上下文](https://github.com/HKUDS/DeepTutor/blob/v1.5.16/web/context/QuizFollowupContext.tsx) · [官方 Practice 说明](https://docs.deeptutor.info/explore/practice/)

我们采用它的逐题上下文，把辅导入口提前到第一次提交之前，并内嵌在当前题下。这样，同一句“我觉得选 B”有明确含义：写下时是草稿，点击「问这一步」后是学生主动表达的思路，正式点选并提交后才是一次答案。

### 同一道题的两条操作路径

```text
问这一步 → 保存本次学生原话 → 按本题和这一步生成引导 → 在原题展示 → 学生继续写
提交解答 → 固定本次答案与已展示协助 → 按出题时的依据判题 → 返回反馈 → 改答或结束
```

- **辅导如何读学生的想法。** 能指出有效的一步，就先说具体是哪一步；发现推理跳跃，就请学生检验那一处；文字不足以判断时，只追问缺少的量或理由。服务端为本次辅导提供题面、学生选定发送的内容、同题已展示的信息，以及此时可以释放的教材依据或提示。根据原话选择引导位置，一次留给学生一个可以亲手完成的动作。已有「给我提示」继续按次序释放预备提示；学生直接要解析时走「查看完整解答」。
- **思路如何影响学习记录。** 发送的原话可用于本题接下来的引导。按现有规则，单纯澄清题意或指回题面，与提供解题结构、教材依据或关键步骤区别记录。提交时只计入此前已实际展示且属于协助的内容。改答和看过解答后的表现分开保留。即便助教曾明确说学生某一步做对，也不能据此替学生生成一次正式作答。
- **判题如何给反馈。** 多选沿现有规则区分选对、漏选和错选。计算题按各题实际需要设置要点，例如“写出可行条件”“取得点可行”“结论成立”，并给出允许的等价写法、近似要求。证据不足时保留“待确认”。首版提供可解释的分项判断；需给具体分数的题目，要先有明确配分。反馈按题目发布时的策略显示，错后还可改答的题先指出可修正之处，完整解答沿已有释放入口展示。
- **切题、恢复和失败。** 每次发问和交卷都携带原题 `delivery_ref` 与操作编号。迟到的回复回原题，重试取回同一次结果。评阅暂时失败时保留已交答案并标为待评，不消耗新的作答次数。未发送的草稿不调用模型，客观选项的对错由服务端直接计算；需要个别引导或开放题评阅时才使用模型。

## 实施顺序

前两步合起来是可试用的首版。教辅可以在题卡跑通后再接入。

1. **先在现有练习里答两种题。** 补齐公开作答格式、单多选控件和计算题编辑区，接通正式提交、分项评阅和改答。用一题多选验证漏选，用一道有两种正确做法的计算题验证等价解法，并从既有阅读练习和「今日练习」各走一次。
2. **把题下的思路接给助教。** 先完成“写一半就问、得到针对这一行的回复、继续原稿、最后交卷”。用同一道题的两种不同误解确认助教给出不同引导。再用切题、刷新和求助后改答确认讨论归属与协助记录；在手机上实际走一次输入和提交。
3. **接到最优化教辅。** 用少量原创题跑完按讲练习及后续回访。发布时连同来源、答案、评分依据和可逐步释放的提示一起准备；学生次日从已有「今日练习」进入同考点的另一题。整本教辅、限时组卷和手写照片评阅可按试用结果另排。

第一轮试用要观察的是：同一道题里，学生写出的具体想法能否改变助教的下一句引导；之后交卷，学生和系统能否分清哪一步是学生自己完成的。这是本方案的产品完成标准。

## 语音输入（已接入）

题目思路、计算题过程和普通聊天复用同一个录音组件。学生点「语音输入」，停止录音后检查、修改识别文字，再点「加入输入框」。文字追加到最新草稿末尾；口述的变量、数学符号和同音字由学生在预览或原编辑器中修正。后续「问这一步」「提交」「改答」沿用上述路径。

一次最多 90 秒。录音或检查识别文字时暂停该输入区的发送；取消、切换题目或切换阅读现场会关闭麦克风，迟到结果不能写入新草稿。连接失败可重试同一段录音，静音要求重录。服务端用本地中文/英文模型识别，原音频在本次请求结束后删除。具体配置与走查见[试用说明](../examples/optimization-practice/README.md#语音输入)。
