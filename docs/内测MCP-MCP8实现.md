## 实施范围

`UserPage → McpPanel → /admin/users/{user_id}/mcp`，写入沿 `OperationsProvider → OperationJournal → MCP4 API`。收款更正按 `entitlement_kind` 进入对应表单，MCP 更正绑定原收款与批次 revision；金额差额与次数差额分别输入。沿用现有管理员身份、人工收款与 schema 12。

## 账号管理入口

后台账号管理 → 账号详情 →「MCP 调用次数」。面板显示当月授予、已用与剩余免费次数，有效已购次数、免费恢复时间、下批到期时间，以及每个购买批次的条款、原金额、原次数、调整、已用、未用与当前可用次数。时间统一按香港时间显示，过期批次保留历史。

「登记 MCP 购包」输入正整数包数、付款时间、渠道、可选交易编号和备注，预览 `包数 × 10 元 / 包数 × 1000 次`；写入仅提交 MCP4 合同字段，由服务端确定价格与开通期限。「赠送当月次数」独立提交正整数次数及原因，不生成收款。

## 更正与回执

批次和混合收款明细均可进入「更正 MCP 收款 / 次数」。表单从原收款找到调用包及 revision，分别输入收款金额差额和次数差额，至少一项非零；保留已消费事实。界面提示最多可扣回的未用次数，最终并发消费及修订号校验由服务端决定。修订冲突后刷新查询，管理员核对后重新提交。

收款及收款追加更正显示模型使用额度或 MCP 调用包，并关联原额度期／批次／收款；模型收款继续使用原有金额与 micro-CNY 额度接口。账号管理操作表显示 MCP 购包、赠送和更正的中文名称。

三种 MCP 写入共用现有 `OperationJournal`。业务参数与操作号在发送前写入当前管理员的 sessionStorage；未知结果先查询原回执，未查到时保持原参数、原操作号重试。页面刷新后待核对操作继续保留，未完成前阻止新管理写入。成功回执展示提交参数、原购买条款、次数调整、消费和到期时间，赠送回执显示原操作所属月份；回执中的余额明确是操作完成时的快照，当前余额由查询刷新。

## 已知限制

- 账号 MCP 查询沿现有接口，只支持启用账号；停用账号会显示不可用并阻止购包／赠送，需先核对账号状态。
- 金额更正登记业务事实，不表示外部退款已经执行。
- Computer Use 保持用户此前停止状态，本片无实体浏览器视觉验收。真实 Agent、HTTPS 代理与发布沿 MCP9／MCP10。
