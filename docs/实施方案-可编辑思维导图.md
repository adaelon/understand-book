# 可编辑思维导图实施方案

日期：2026-10-28。状态：首版实现、真实浏览器与 Rust 六轮回放已通过，已于 20:28 随页面恢复、画板纠错和后台监控合并上线。当前结果与已发现问题见 [验收记录](https://github.com/adaelon/understand-book/blob/625b4405af3b011e87d4eb256f819c8075f88613/docs/performance/editable-mind-map-20261028/README.md)。

目标是在现有知识画板内完成“生成、人工整理、局部追问与改图、撤销、重开和带走成果”的闭环。以已上线的 `rust-board-teaching-20261028` 为行为基线，复用来源、讲解、讨论、笔记、演示和交付链路。现网包含主工作树尚未完整带齐的空间笔记改动；实施前建立包含现网功能的独立开发基线，保留其他任务的未提交工作。

## 1. 第一版交付

在当前画板加入“添加思维导图”，出现可输入的中心主题；也支持粘贴或导入 Markdown 标题、缩进列表。导图与自由卡片共用画板视口。用户可以直接编辑主题、增加同级或子主题、移动和复制整支、折叠、切换大纲、撤销重做，并请 AI 针对选中的分支解释或修改。

首版支持左右展开与向右树两种布局、基础主题样式、跨主题关联、桌面与手机核心编辑、Markdown 大纲导入导出和 PNG 导出。模板库、更多结构、SVG/PDF、Xmind 互通、只读分享及多人编辑安排在后续版本。第一版的结构、编辑、撤销与 AI 接入一起验收和发布。

## 2. 一份主题结构

- 主题继续是 `BoardItem`，沿用 `item_id`、`title` 和来源绑定；新增 `BoardTarget::Topic { children: Vec<item_id> }`。有序孩子列表是结构的唯一权威，父级与同级位置从它派生。
- `BoardDocument.mind_maps` 保存导图根和布局设置，例如 `map_id / root_item_id / layout_mode`。首版入口先服务一棵主导图及旁边的材料；不引入第二套画板、聊天或资料存储。
- 主题短标题使用 `BoardItem.title`，不再同时写入 `graphic.text` 和 `readable_content`。长讲解通过现有回答块、笔记、演示关联到主题；编辑主题标题不会改写原回答、原文或用户原话。
- 父子线由树生成；跨主题的条件、对比、因果等说明继续使用有稳定 ID 的 `BoardLink`，与层级结构分开。选择树边时使用子主题 ID，在所选修订中解析当时的父子端点。
- 折叠、焦点和当前选择属于 `BoardView`。移动结构、改标题、改样式属于内容修订；平移、缩放和折叠不会制造内容版本。
- 树校验覆盖实际要求：孩子存在、单一父级、不成环、同一主题不属于不同导图。旧画板缺少新增字段时读为空导图集合。

原文、回答、理解记录和演示保留既有归属。共享笔记正文仍通过笔记系统编辑，画板撤销不回退共享笔记内容。

## 3. 人工与 AI 共用编辑操作

增加基于预期画板修订的原子编辑入口，以操作批次修改结构。HTTP 请求使用 `board_revision`，避免与外层工作区传输使用的 `expected_revision` 混淆；存储层严格比较修订后提交整批操作。按钮、快捷键、大纲和 AI 都表达同一类意图：

| 操作 | 行为 |
| --- | --- |
| 创建导图、插入主题 | 指定父主题及同级插入位置；新主题获得稳定 ID |
| 修改主题 | 改标题或基础样式，沿用 ID 和原始来源 |
| 移动分支 | 修改原父级与目标父级的孩子顺序，后代整体跟随 |
| 复制分支 | 整支生成新 ID；复制内部关系，保留来源引用，不复制交付或学习事实 |
| 删除分支 | 连同失效关系、图文映射和路线目标清理，作为一个事务 |
| 更新关系与路线 | 按原 link/mapping/route/step 身份增改删，避免每次整理都追加重复关系 |
| 修改布局、移动整图 | 改布局设置或根锚点，其他主题几何由布局生成 |

删除与恢复复用已有目标清理逻辑；空间笔记投影关系继续由笔记接口维护。一次改名、一次拖动、一次批量操作分别是一项事务，不按键盘字符或拖动帧保存历史。

## 4. 确定性布局与交互

后端保存主题结构和布局参数；主题几何是派生结果。新增共享布局模块，Reader、候选预览和导出加载同一实现和字体规则。既有自由图元仍使用现有坐标。模型给出主题、关系和阅读顺序，普通主题编辑不接收模型猜测的坐标。

排布先取得实际文字尺寸，再计算子树范围和节点位置。一级分支的左右归属确定后保持，新增内容只推动受影响分支及必须让位的邻支。根锚点保持稳定，编辑时只让当前主题进入可见范围，不反复缩放到全图。

| 用户操作 | 系统反应 |
| --- | --- |
| 双击或 F2 | 编辑主题标题；Enter 完成、Shift+Enter 换行、Esc 取消；中文输入法确认不触发结构命令 |
| 非文字编辑状态下 Tab / Enter | 新建子主题 / 同级；中心主题 Enter 新建子主题 |
| 方向键 | 在父子与同级主题间移动选择；自由卡片保留原移动方式 |
| 拖普通主题 | 预览“成为某主题的子级”或“插入某同级之前/之后”，松手移动整支 |
| 拖根主题 | 移动整张导图；旁边自由卡片保持现有独立拖动 |
| Shift 点选或框选 | 批量复制、移动、删除、调整基础样式；父子同时选中按一支处理 |
| 折叠 | 显示隐藏主题数；搜索命中时展开祖先并定位 |
| 导图 / 大纲切换 | 修改同一棵树，保留当前主题和输入；大纲缩进与拖排序直接改变结构 |

普通父子线由结构决定，跨主题关系通过“建立关联”添加。第一版不支持导图内单个主题任意坐标偏移，以免自由位置和自动排布相互覆盖。空白处没有有效结构目标时，放下分支恢复原位置。

手机复用现有画板／讲解／讨论切换，增加可点击的新增、编辑、折叠、移动到和撤销入口；通过大纲选择父主题及位置，不要求用户精细拖放。支持双指缩放，进入双指操作时取消尚未提交的节点拖动。编辑面板适应软键盘，保留选中主题与草稿。

## 5. 撤销、保存与恢复

复用内容修订快照，为每次编辑记录操作者、动作摘要和撤销／重做关联。第一版按时间顺序撤销顶端事务；新的内容编辑清空重做栈。重新打开可以读取历史事务并恢复操作入口，不只保留当前页面内存中的栈。

撤销作为新修订反向恢复本次涉及的主题、关系、映射、路线和布局；不整份覆盖旧 `BoardDocument`。`deliveries`、原聊天、已发生的教学事实保留，重做使用原节点和解释块 ID。现有“回执在可见条目删除后继续存在”的合同可直接复用，避免重试重新生成已撤销内容。

一次完整 AI 改图批次是一项事务；撤销它不会撤销之前的人工作业。之后若又发生人工编辑，按时间顺序逐项撤销。生成途中取消只丢弃未提交候选，已交付部分继续保留；需要撤销当前仍在生成的批次时先停止该运行，再撤销已经提交的相应事务。

人工编辑即时显示，后台串行提交，保留未保存状态和可重试草稿。其他窗口改动时重新读取后再操作，旧修订不能覆盖新版本。快捷键处于文字编辑器内时使用文字自身的撤销行为，退出编辑后才使用画板事务撤销。

## 6. AI 局部编辑

输入框显示“针对：某主题及其子主题”。“解释这一项”允许只回答文字；“补一个例子”“展开这一支”“简化这一支”“重新组织这一支”才根据需要产生结构修改。复用刚上线的精确选择、最近两轮问答和表达教练，不另加每次手工操作都要经过模型的流程。

流程为：冻结目标范围与版本 → 内容规划 → 生成语义操作 → 公共编辑器准备候选 → 共享布局和实际预览 → 按既有教学状态执行必要审核 → 提交已经观察的候选。普通修改完成后直接应用并短暂标明新增／修改范围，提供“撤销”；不要求每轮先点击接受。

生成期间用户可以继续编辑。尚未提交的本地文字草稿也属于人工改动，不能被回包替换。

- 记录操作实际涉及的主题正文、父级孩子顺序、关系／路线原值和明确依赖，直接比较这些字段；自动布局坐标变化不当成语义冲突。若引用可编辑空间笔记，也检查其修订。
- 只有其他分支改变时，在当前修订上重放已有语义操作，保留正文和稳定 ID，形成新的候选修订，重新排布、校验并实际预览。候选内新内容的修订引用随新基线更新，历史来源引用保持原身份。复用内容与规划，不复用旧截图、待提交状态或旧教学审核授权。
- 同一主题、相关父级顺序或明确依赖被修改时，保留人工结果，把候选留为待处理修改，支持按当前内容重做。目标已删除时不重建旧对象。
- 正式提交仍检查当前版本；预览之后再次发生冲突，不能绕过检查覆盖。首版只承接明确无冲突的操作，不做任意字段自动合并。

“只补这一支”允许相邻分支为布局腾位置，但不能修改其正文、顺序、来源或身份；用户视角保持稳定。

## 7. 旧图与导出

旧画板继续按原模型打开。提供“将选中内容整理成思维导图”：根据内容、来源和用户意图准备主题树，展示重组预览后创建新导图，旧图保留。原连线可能表示条件、因果、对照或追问，不能仅凭箭头方向猜测父子关系。新主题引用原材料，原解释、用户原话和来源不被改写。

Markdown 导入导出覆盖主题文字与层级；跨主题关系、讲解路线和演示不宣称能通过普通大纲格式完整往返。PNG 使用相同渲染器按导图内容范围导出，不只截当前视口；大图提供选定分支导出，避免把全部内容压缩成不可读的小字。

## 8. 实施顺序与交付依据

| 内部切片 | 主要落点 | 完成时能验证的行为 |
| --- | --- | --- |
| 结构与事务 | `memory/boards` 的主题类型、编辑操作、修订与撤销；`server/board_api`；生成 Web 类型 | 关闭模型也能新增、改名、移动、删除与恢复整支；ID、来源、回执及联动关系保持正确 |
| 完整手工编辑 | 保留 `BoardWorkspace`、`BoardCanvas`；新增导图层、编辑控制器、布局模块和大纲组件 | 桌面、中文输入、手机都能完成整理；画布与大纲一致；刷新保留结构，保存失败保留草稿 |
| AI 原位修改 | 扩展 `runtime/board_author`、服务候选和提交，复用教练／预览／教学链路 | “没懂”可直接解释；补例子只改目标分支；非冲突改动承接后重新预览，同处改动不覆盖；AI 修改可撤销 |
| 真实使用与带走成果 | 旧图重组、Markdown、PNG、Rust 回放、较大章节及旧功能回归 | 从原材料生成到手工整理、追问、撤销、导出、重开形成完整闭环 |

首版规模目标按 500 个中文主题的章节导图设计；以真实章节为主要场景，另用可重复的较大样例测量编辑反馈、排布、首屏和保存重开。将本地编辑可见反馈约 100ms、500 主题重新排布约 200ms 作为工程目标，记录设备和实际耗时后再决定支持范围。1000 主题用于发现扩大规模的瓶颈，不据此提前承诺容量；不把模型等待混入编辑耗时。

Rust 验收沿原游客材料和追问，增加实际编辑过程：生成结构化导图 → 手动补只读／可写主题 → 移动权限分支 → 折叠和大纲定位 → “没懂”局部讲解 → 补例子时修改另一支 → AI 完成后撤销且保留人工改动 → 同一主题冲突处理 → 手机完成核心操作 → 导出与重开。代码例子实际编译运行，图与文字直接查看，保存结果由真实服务读取。

必要回归覆盖旁边的原文、回答、演示与共享笔记；删除分支及撤销后的关系和讲解路线；已交付部分的取消、重试及去重；历史画板重开和来源定位。发布前沿现有数据副本、Linux 预览及公网验证流程执行。教学内容质量和真人是否理解分别评价。
