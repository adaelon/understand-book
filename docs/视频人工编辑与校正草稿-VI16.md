# 视频人工编辑与模型校正草稿（VI16）

## 维护入口

构建维护命令 `video-correction` 提供人工编辑、主动生成草稿、查看差异、逐处或整批采纳/拒绝、导出正文输入。命令接入 `skills/build/automatic-build.ts`；也可直接运行 `skills/build/video-correction.ts`，省略下面的 `video-correction` 一级命令。

```powershell
node --import tsx skills/build/automatic-build.ts video-correction status WORKSPACE
node --import tsx skills/build/automatic-build.ts video-correction edit WORKSPACE EDIT_JSON
node --import tsx skills/build/automatic-build.ts video-correction prepare WORKSPACE DRAFT REQUEST_JSON [AUDIO_PROBE_EXE]
node --import tsx skills/build/automatic-build.ts video-correction run WORKSPACE DRAFT CODEX_EXE
node --import tsx skills/build/automatic-build.ts video-correction review WORKSPACE DRAFT
node --import tsx skills/build/automatic-build.ts video-correction inspect WORKSPACE DRAFT
node --import tsx skills/build/automatic-build.ts video-correction accept WORKSPACE DRAFT CHANGE_ID,CHANGE_ID
node --import tsx skills/build/automatic-build.ts video-correction reject WORKSPACE DRAFT all
node --import tsx skills/build/automatic-build.ts video-correction export WORKSPACE
```

`accept/reject` 可传 `all` 或逗号分隔的修改 ID。`review` 输出可读的修改前后、理由、依据、音频疑点和冲突；`inspect` 输出同一内容的 JSON。请求中的相对文件路径以命令当前目录为根，工作区内部文件保持相对关联。

人工编辑使用 `status` 中的当前文字和 `edit_revision`：

```json
{"segment_id":"segment-82","expected_revision":0,"before":"当前整段英文","after":"人工修订后的整段英文","reason":"回听后的定点纠错"}
```

草稿请求示例：

```json
{
  "segment_ids":["segment-82"],
  "vu_ids":["lecture-v1/vu-0001/1"],
  "question":"核对 denser 是否为识别错误；画面解释单列。",
  "audio_review_files":["已保存的VI15复核结果.json"]
}
```

`vu_ids` 可以为空。`audio_review_files` 接受 VI15 的 `AudioReview` 或包含 `review` 的 probe 结果；`audio_reviews` 接受同样结果的对象数组。需要新复核时传 `audio_requests:[{location,question}]` 与已构建的 `video_audio_probe` 路径。该程序调用 VI15 正式原音频处理函数，使用 `VIDEO_WHISPER_PYTHON` / `VIDEO_WHISPER_MODEL_DIR`；每段最多 30 秒。未提供音频复核时可以生成上下文建议，不能伪造听辨依据。

## 修订与采纳

工作区 `transcript_corrections.json` 原子保存当前修订文字、每段编辑序号、人工/草稿修改记录、待处理/已采纳/已拒绝建议及来源。`material.transcript` 固定原输入转写版本；`edit_revision` 只表达维护中的修改次序。

```text
已发布原转写 + 当前人工修订 + 选定真实帧/音频复核
  → 冻结草稿输入 → VI4 四工具 Harness → 候选接纳 → 待处理草稿
  → 用户选择修改 → 校验当前语段 → 更新修订存储 → 导出新版构建输入
```

每个建议包含原语段中的 UTF-16 位置、修改前后、理由、依据类型和实际交付来源 ID。候选门拒绝错版本、错原文/位置、重叠替换、未交付来源和仅凭画面改写口述。画面解释、补充知识和未消除疑点保存在独立注记中。音频工具原有疑点随来源保留，不依赖模型复述。

同一草稿的多个独立修改可分次采纳：Engine 从原输入与该草稿已采纳项目重建预期文字，再加入本次选择。人工编辑或另一草稿改变同段后，旧建议仍为 `pending`，显示当前文字和冲突原因。即使人工后来把文字改回，编辑序号也能识别中间变化。整批采纳时其他无冲突语段照常处理，返回 `conflicts` 明列未应用的修改。

拒绝只改变建议状态，重复采纳不会重复应用。新的人工编辑须同时匹配当前文字和编辑序号。草稿提交本身不改变任何转写；候选协议中的 `committed` 表示草稿已保存。

## 外部执行与恢复

草稿输入保存在 `.build/video-corrections/DRAFT/input.json`。材料准备复用 VI13 的有界来源选择与 VI4 原生图片传输，最多选择跨度 60 秒的材料，并遵循既有八张图片/传输预算。转写上下文、音频复核工具结果与图片分别交付；主模型没有直接接收音频。

`prepare` 固定当前语段文字及编辑序号，重复调用不更新输入；修改请求须使用新的草稿 ID。已完成的音频复核可在准备中断后继续使用。`run` 重用已保存草稿，模型运行中途人工编辑也不会改动其冻结输入。最后一批输入确认后才授予生成；候选错误沿现有 `retry_feedback` 返回 JSON 位置和具体原因，最多三次提交，错误候选不进入修订存储。最近一次拒绝保存在草稿目录中供维护排查。

## 导出与 VI17 接点

`export` 原子写入 `.build/video-corrections/accepted-input.json`，格式为 `video_transcript_revision_input.v1`：原材料身份、当前修订序号、全部英文 `canonical_text`、语段及原片时间、人工/采纳记录和已采纳建议的依据。只采纳的修改及人工编辑进入英文，注记独立保存。

VI17 应从当前修订存储重新导出，消费 `source_material` 和 `correction_revision`，生成新版 Book、重建字符映射并传播派生成果。修改后的文字沿用句段时间，不声称产生新的逐词时间。VI16 的原 `source.txt`、`base.json`、时间映射和发布链接保持原样。

## 验收入口

`node --import tsx evals/video/vi16-run.ts CODEX_EXE` 在 `evals/video/generated/vi16/workspace` 建立独立维护副本，使用 VI15 的 denser/sarcastic 复核、原片真实帧及新请求的 590–598 秒原音频，生产两组草稿。支持 `VI16_OUTPUT` / `VI16_AUDIO_EXE`；Whisper 与 FFmpeg 配置沿 VI15。

`node --import tsx evals/video/vi16-verify.ts` 在新的验收副本中执行部分采纳、拒绝、整批采纳及同段人工再编辑，核对正文、来源和原发布。真实模型的原始草稿保持待处理；验收动作不代表材料维护方的采纳决定。

## 已知限制

- 本刀提供构建维护命令和可读差异；Reader 内的编辑面板尚未提供。
- 正式草稿生产接入 Codex；DSH、Linux 和安装态沿既有待验范围。源码 MCP 变更需要重建 sidecar 才进入安装包。
- 音频词与时间是机器候选，人工完整逐字听核仍待完成。语义依据是否足够由维护方检查后采纳。
- 新版发布、译文/图谱/讲解更新属于 VI17；整讲生产与安装验收属于 VI18。
- 原片首轮未完成候选只留下通用接纳错误，具体原因无法追溯。当前实现保存具体拒绝原因并测试了反馈、重试上限与不落草稿行为。

## 原片结果与成本

2026-10-11，原发布 `01a125c2-840a-76d2-948c-0f427dd1ba88`，原媒体/转写版本均为 1。真实 Codex Harness 收到三张术语帧、两张疑点帧以及 VI15 工具复核结果，给出 `denser → tensor` 和 `beef float 16 → bfloat16` 两处待采纳建议，画面解释独立列出；`sarcastic` 保留疑点，未提交文字修改。

独立验收副本验证了整批采纳、全部拒绝、只采纳 tensor、人工先行修改后旧建议保持 pending，规范原文、时间映射及发布链接逐字节保持。原始模型草稿保持待处理。Core 六个定向套件共 57 项通过，类型检查与主构建命令入口通过；完成态使用不存在的执行器路径重跑仍返回 `reused:true`。

两次成功模型运行耗时 126.513、52.731 秒。连同一次未完成候选运行，共 239.476 秒；输入 386,878 tokens，其中缓存 297,216，输出 10,544。成功的术语运行包含宿主连接重试，耗时不代表稳定推理延迟。590–598 秒复核使用真实本地 Whisper，原始结果和耗时单列在音频凭据中；API 金额未提供。
