# 视频来源改版与派生更新（VI17）

## 维护入口

```powershell
node --import tsx skills/build/automatic-build.ts video-revision prepare OLD_WORKSPACE NEW_WORKSPACE [CORRECTIONS_WORKSPACE]
node --import tsx skills/build/automatic-build.ts video-revision replace OLD_WORKSPACE NEW_WORKSPACE NEW_MP4
node --import tsx skills/build/automatic-build.ts video-revision run NEW_WORKSPACE CODEX_EXE PUBLISHER SERVICE_ROOT
node --import tsx skills/build/automatic-build.ts video-revision status NEW_WORKSPACE
```

`prepare` 从指定校正工作区重新导出当前人工编辑与已采纳修改；省略第三个目录时读取原工作区的校正存储。校正必须绑定同一原材料。没有正文变化时不生成新版。`replace` 显式接收新 MP4，沿导入和全片转写流程产生新的媒体身份及时间映射。

新工作区使用独立 `book_id`，`video_source_manifest.previous_book_id` 指向原书。正文校正保留媒体身份，使用新的转写修订身份，重新组装正文、LID 跨度及每段字符范围，时间精度仍是句段。`transcript_revision.json` 保存新旧语段范围与等价/修订关系；`.build/video-revision/accepted-input.json` 保存本次采用的文字和采纳依据。

`video_revision.json` 保存进度、失败原因、前版发布及逐任务复用决定。前版任务输入、已接纳候选和必要图片在 `.build/video-revision/previous/` 内独立保存；恢复派生任务无需再次访问原构建目录。完成态重跑直接返回已有新版。改变采纳输入须新建工作区。

## 派生任务

```text
冻结已采纳正文 / 导入替换原片
  → 新正文与映射
  → 翻译任务、视觉任务
  → 新材料发布
  → 图谱任务 → 图谱发布
  → 讲解任务 → 完整阶段发布
```

沿用视频构建已有的分阶段计划、候选接纳、原子产物提交和发布回执。新工作区只组装本版有效贡献。失败保存当前阶段状态，重跑恢复缺失任务；旧版继续可用。

| 阶段 | 复用与重算依据 |
| --- | --- |
| 中文 | 比较目标语段及前后各两段的实际模型输入；原任务分界仍覆盖新输入且满足预算时继承，包括先前缩小的任务。只改上下文也重算。缺少原任务输入时重新生成。 |
| 视觉 | 同一原片可复用原扫描和真实帧。逐任务比较完整邻近转写；变化的上下文重新进入视觉执行器，事件与转写关联重新组装。已有的相同画面描述复用继续保留独立出现位置。 |
| 图谱 | 按新版 VU/实际帧选择重建有界输入，比较全部交付转写、图片字节、VU 和已有节点。未引用的上下文仍参与比较。候选重新经过来源接纳，绑定新版发布。 |
| 讲解 | 比较全部转写、图片及 VU/帧对应；重新生成来源、角色和关系。与图谱相互独立地判定。 |
| 替换原片 | 重新导入、转写及扫描；旧时间码不映射到新剪辑。按新媒体区间重建既有能力的任务。 |

复用限定于当前视频 v1 生产合同；抽取规则变化必须更新相应生产合同。比较采用实际字段和图片字节，不增加内容摘要。每条复用记录同时保留前版材料和原任务 ID。旧产物不改写。

视觉候选的来源或区间不合合同，会把具体问题返回外部执行器，最多三次提交；最后一次失败候选保留在对应视觉分析目录。文件或存储失败仍交给构建恢复处理。

## 发布与历史

新版沿现有发布书库入口登记，按普通 Book 由读者主动打开。它不属于原书的同源后继，VI9 间隙接入不会跨越 `book_id`。新发布的句段、译文、图谱与讲解来源共同绑定新版；原有笔记和聊天仍属于原 Book。

保存的媒体来源按其确切发布解析，跨 Book 回看只从当前用户自己的历史读取。网络端继续检查原发布授权；本地端从 `published/<book>/<publication>` 找到原包并核对身份。旧版被撤销或文件不可用时保留来源快照和不可用状态。

## 验收入口

`evals/video/vi17-run.ts CODEX_EXE PUBLISHER` 在独立 `generated/vi17/` 中复制正式材料及 VI16 部分采纳结果。VI11 材料的原中文任务保存在 VI10 工作区，验收按材料身份补入其真实任务输入/候选。脚本先为原转写补建实际 tensor 图谱与讲解任务，再运行新版传播。`vi17-verify.ts` 对比前后发布、720 段中文、实际输入、语义结果及 550 秒原帧像素，并验证完成态不再启动模型或发布。

定向回归覆盖上下文变化、字符长度变化、旧版不变、搬迁恢复、模型输入完整比较、来源重绑、显式剪辑替换、构建失败、跨版本旧回答/笔记/聊天、主动切换和撤销原发布权限。

## 原片结果

2026-10-11，独立新版 Book `5bfd5def-182f-4205-b574-0ca553e79450`，最终发布 `01a12865-798b-79d0-851c-bc9b43300afd`。`segment-82` 的 `denser` 改为 `tensor`，中文由保留 denser 疑点变为“比如试着构造一个 1e-8 的张量，结果实际上就是 0。”图谱和讲解均重新读取修订后的口述及实际帧，保存 float16 张量构造、下溢为零及动态范围限制的来源。

验收工作区的冻结计划复用 16 个翻译任务、9 个视觉任务、4 个图谱任务和 1 个讲解任务；重算 8 个翻译任务、1 个视觉任务及 tensor 的图谱/讲解。720 段中文完整，旧英文、映射和正式发布保持；550 秒前后发布的解码帧像素一致。完成态以不存在的模型/发布器路径重跑，通过且没有新发布。

Core 74 项、Server 视频 22 项及普通来源 5 项通过，共 101 项；另有一个浏览器宿主测试按设计忽略。Core 类型检查、主维护入口、Server 和发布器构建通过。验收使用服务协议验证主动切换与历史；本轮没有新增浏览器界面验收。

含两次原版语义准备、一次失败视觉尝试在内，8 次外部运行共 571.317 秒，输入 1,680,342 tokens（缓存 1,432,192），输出 45,950，API 金额未知。最终发布清单中的文件合计 256,093,943 字节；发布耗时本次未单独记录。

凭据：[原片新版](../evals/video/results/vi17-20261011/verification.json)、[定向测试](../evals/video/results/vi17-20261011/tests.json)。`vi17-replacement.ts` 另外裁出实际原片 547–555 秒，验证新媒体导入、真实 Whisper 转写及拒绝旧时间定位。

## 已知限制

- 原片验收使用 VI16 的独立采纳副本；原始两组模型校正草稿仍待维护方选择。
- 构建维护入口为源码命令。Reader 编辑面板、DSH、Linux、安装包依赖和整讲语义生产沿 VI18。
- 新版独立物化媒体。复用需要相应生产任务的完整输入和已接纳结果；缺失输入的成果不能以文字相同推断可复用。
- 替换剪辑不迁移旧引用或旧时间码；旧记录继续打开旧包。机器转写及复核不构成人工逐字真值。
