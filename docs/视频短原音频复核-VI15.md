# 视频短原音频复核（VI15）

## 入口与结果

`video.review_audio(location, question)` 从当前 Run 固定发布截取 1–30000 ms 原音频，使用 VI0b/VI3 的本地 Whisper 重新识别。返回复核文字、原片词时间估计、识别概率、疑点、对应保存英文、Provider 信息及可交付的音频目标。主模型结合这些结果与另行读取的画面回答问题。

```text
RunScope → 原发布/媒体范围校验 → FFmpeg 原声 PCM → 本地 Whisper
  → AudioReview → 当前 Run 的 Audio observation → source.present
  → 含复核结果的 SourceBinding → 回答旁原音频预览 → 历史原发布回听
```

Whisper 只接收原声与既有识别参数；问题、保存英文、字幕和画面文字不进入识别提示。复核结果与原英文同时返回，支持主模型比较差异。画面仍通过 `video.read_frames` 独立观察，联合引用分别保存支持来源。

`AudioReview` 保存复核 ID、Run、发布、处理范围、问题、文字与疑点；观察回执另关联实际工具调用 ID。成功且未取消后才登记音频观察，失败不授予来源资格。没有相交转写的纯音频成功结果也能立即调用 `source.present`。新回合清空音频观察和复核列表，历史回执不能授予新回合资格。

词时间从识别局部秒数映射回原片毫秒，允许模型实际返回的零时长词；越界响应拒绝。识别概率低于 0.5 的词单列回听位置；所有识别文字保持机器候选属性。空识别不等同于确认静音。

## 保存与预览

`MediaSource.audio_reviews` 随已存在的私人来源和会话历史保存，仅包含当前引用目标对应的复核。预览显示原音频范围、复核候选、疑点、保存英文及已有中文。原发布失去可用性时仍保留文字与疑点快照。

音频在独立播放器中按来源范围回听，关闭不会改变主播放器位置或倍速；“进入原视频位置”才跳转。复核不改写正文、时间映射或发布，不产生校正草稿。原声裁剪、适配器输入及临时原始识别响应在调用结束后清理；带问题的结果不进入共享缓存。

## 配置与重跑

服务端需要 FFmpeg、安装 faster-whisper 的 Python 和本地 `small.en` 模型：

```powershell
$env:VIDEO_WHISPER_PYTHON = '<Python 可执行文件>'
$env:VIDEO_WHISPER_MODEL_DIR = '<本地 small.en 模型目录>'
node evals/video/vi15-verify.mjs
node evals/video/vi15-browser.mjs
```

本工作区 `.worktree-local/environment.ps1` 已配置既有 Python 与模型。`FFMPEG` 可覆盖解码器路径；音频配置独立于读时聊天 Provider。未配置模型、缺解码器或识别失败时工具返回明确错误。解码与识别共用 120 秒上限，超时或运行取消会终止并回收子进程。

服务端嵌入既有 `packages/core/src/video-whisper.py`，不依赖启动目录寻找脚本。当前识别参数是英文、CPU int8、8 threads、beam 5、temperature 0、词时间、VAD 500 ms、关闭前窗文字提示。

原片验证器读取 VI11 工作区的最新正式发布。`VI15_AUDIO_EXE` / `VI15_SERVER_EXE` 可指定执行文件，默认使用 `CARGO_TARGET_DIR/debug/` 下的示例和服务。浏览器验证在 8794/5176 启动独立服务，结束后关闭；当前 8793/5175 不受影响。

## 已知限制

- `small.en` 会保留或新增识别错误，高概率也不证明正确；tensor 是新识别候选，尚非用户采纳的正文校正。完整逐字真值及精确词/停顿标注仍待核。
- 读时主模型获得音频工具结果，未直接接收音频；主模型语义回答、DSH、Linux 和安装态沿既有待办。当前 UI 闭环验证使用 HTTP 记录器，不作为回答质量验证。
- 每次复核重新加载本地模型。一次上限 30 秒，更长疑点分段读取；完整原始识别响应只在调用临时目录存在，历史保存有定位的词候选、概率、Provider 与疑点。
- VI16 负责人工/模型校正草稿及采纳，VI17 负责来源改版传播，VI18 负责全讲和安装态。
