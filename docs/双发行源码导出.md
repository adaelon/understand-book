# 双发行源码导出

`scripts/export-editions.mjs` 从当前唯一工作树生成两个可独立准备的源码目录。公共边界与各平台验收沿[双发行方案](切片方案-开源本地应用与云端服务双发行.md)；这个入口不发布安装包、不部署网站，也不创建远程仓库。

## 生成源码目录

完成当前公共与云端拆分、更新工作树锁文件后，在仓库根目录执行。导出仅需 Node.js、Git、Cargo 与现有 Cargo 离线缓存，不会安装依赖或编译产品：

```powershell
node scripts/export-editions.mjs --out ../understand-book-editions
```

输出目录必须不存在或为空。已有源码或失败输出保持原样，修正后使用新的目录。建议使用仓库外的相邻目录，便于确认构建没有借用当前工作树的依赖或 Git 状态。

| 输出 | 包含内容 | 默认入口 |
|---|---|---|
| `public/` | 公共 Rust 核心、共享 Reader、本地正式壳与 Debug、插件、格式资源和原创样本 | `pnpm build`、`cargo run -p reader-service --bin reader -- --reader-only .understand-book/quickstart-demo` |
| `cloud/` | 云 server、网站、Admin、原云客户端及同次导出的公共依赖源码 | `pnpm build`、`cargo build --locked -p server --bin server`；正式 Linux 发行沿 `scripts/linux/build-multi-reader.sh` |

公共依赖在云目录中保留原有 `crates/`、`packages/`、`skills/` 和资源布局，使 Rust 编译资源与 Node helper 的相对路径继续有效。云目录不链接原工作树；公共修复在原公共实现完成后重新导出，不在快照中维护另一份实现。

公共插件工具位于 `scripts/plugin/`，平台资源脚本位于 `scripts/desktop/`。公共根包保留 `build:book-mcp`、`test:maintenance-plugin`、`test:t7-executor-release` 和 `test:t7-codex-cli-release`；Book MCP 构建使用公共 `reader-service`，不要求云服务源码。

导出依据 Git 已登记文件与未被忽略的新源码，按脚本中的产品白名单选择。运行数据、个人环境配置、原始验收证据、构建产物和安装目录不进入源码快照。两份输出各自重写 workspace 成员清单；公共 package 不保留调用云包的构建命令。

公共文档使用明确白名单，保留工具契约、模型配置和公共代码实际使用的课程样本。公共工具参考去除远程 MCP 表面，完整 JSON 合同与页面同步裁剪；需要云宿主的 `docs:tools` 生成命令只留在云源码。各产品生成相对路径可访问的 README，公共贡献与结构说明、模型说明按本地范围投影，源工作树文档不被这一步覆盖。`materials/README.md` 保留资料下载、原始来源与权利说明；源码 MIT 许可和内置第三方许可保持原文件，不将下载的原书、录音或预构建数据打进源码。

示例仅带正式入门使用的 `examples/quickstart`、三维资源构建与方法说明使用的 `examples/gear-transmission`，以及公共练习测试编译依赖的 `examples/optimization-practice/questions.json`。完整讲义、历年试卷和其他学习材料通过原发布说明获取；导出的材料说明将原讲义源目录入口改为资料包说明。

公共维护 CLI 位于 `crates/maintenance-host`，依赖公共 `reader-service`。`.mcp.json` 和插件描述使用相对脚本入口，不包含机器专用 agent 配置。导出脚本仅在权威工作树使用，两个输出中的 `EDITION.md` 负责各自的编译说明。

## 版本与验证

每份输出的 `edition-source.json` 记录基线提交、源状态、导出时间、文件数量和经过装配变换的文件。源状态为 `working-tree` 时，该提交不包含所有导出的修改，不能当作已发布公共版本。文件固定在该快照内；远程仓库和公共版本确定后，再用明确提交或发布包替换此本地依赖交付方式。

导出在复制原锁文件后运行 `cargo metadata --offline --format-version 1 --filter-platform <当前原生目标>`，根据各产品成员整理 Cargo.lock，确认移出的宿主包已从锁文件消失，再以 `--locked` 重复离线解析。外部依赖的名称、版本与来源必须已存在于源锁文件，出现新解析则停止并保留输出，不在线更新版本。离线缓存不足时补齐原工作树的已锁依赖后使用新目录重试。

pnpm 锁文件只裁剪移出产品的 importer，保留原 registry packages 与 snapshots 全部内容。每个保留 importer 的 `link:` 目标必须属于同一发行目录的工作区包；缺少 importer 或仍指向被移出的包时停止。此步骤不运行依赖安装。

源码导出完成只表示复制、workspace 装配与离线 Cargo 清单解析完成，`validation` 初始为 `not_run`。独立安装与构建当前暂缓；恢复时，在两个输出目录分别执行以下命令，不能用原工作树的成功代替：

```powershell
# public 目录
pnpm install --frozen-lockfile
pnpm demo:prepare
pnpm build
cargo build --locked -p reader-service --bin reader

# cloud 目录
pnpm install --frozen-lockfile
pnpm build
cargo build --locked -p server --bin server
```

正式 Linux 构建继续使用原脚本的语义检索配置、Admin/Reader 静态资产校验与构建回执。

公共普通测试使用可随源码发布的样本。历史 HTTP 来源、BSR4 主题回放和 SR6 真实向量通过 `MCP_SOURCE_EVIDENCE`、`BSR4_EVIDENCE_DIR`、`SR6_RANKING_INPUT` 显式指定；未提供时对应历史回放显示跳过。SR6 普通测试以原创向量覆盖排名与发布判据，课程样本和 UTF-16 跨页来源样本随源码保留，不以复制私人验收目录补依赖。

每次独立验收的日志、源码目录与实际运行结果写回双发行实施记录。安装包、macOS 原生运行、生产数据副本升级和远程固定依赖分别需要自己的证据；导出脚本不会把它们标成通过。
