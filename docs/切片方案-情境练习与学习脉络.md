## 1. 目标与完成定义

用户在阅读、回看笔记、整理画板或操作教具时，偶尔遇到一个不点名的小问题，需要自己想起此前学过的关系并用出来；卡住时，提示一步步把他带回题目、情境结构、自己的笔记或原文；结束后系统诚实记录这次是独立完成还是得到了帮助，并据此安排之后的练习与教学。之后，跨书已讲关系连接成私人学习脉络，帮助找回措辞不同但结构相关的旧笔记。

**P1 实例（同一本书内，P1 / P1b 须走通）：**

> 用户读平均速度一章时写过笔记：“休息的时间不算，只看骑车的时间吧？”之后在这条笔记上点“练一练”。题面逐字引用这句原话，给出一段含十分钟休息的骑行，问整段行程该用哪些量。用户请求提示，得到“再看看题里那十分钟”（题内指向，不计协助），然后答对：系统记为独立支持，并随评估结果展示完整解答；回应回合只用一两句指出决定性的一步。若用户打开原文后才答对，则记为协助支持。若交付后核查判定这道题存疑，活动显示提示，本题结果不计入投影。

**全计划实例（需 P3 与 M1–M3）：**

> 用户在书 A 中学过“速度不变时，距离与时间成正比”，并写过笔记“时间翻倍距离也翻倍？”。几天后阅读书 B 关于匀速电机转数的段落（已开启阅读边注），边注出现：“电机转 30 秒转了 600 圈，转 90 秒呢？为什么？”题面不提速度或比例。用户卡住，先得到题内指向，再得到情境结构提示，仍卡住时打开自己的那条笔记后答出。系统记为协助支持，下次热身时换一个新情境再次调用该关系。

“题出现了”“答案保存了”“证据有记录”各自只证明对应环节；完成要求同时看到：未点名的题面、宿主检查与交付后核查、逐级提示、真实协助记录、以及之后选材实际采用了这条证据。

## 3. 数据合同

### 3.1 练习题：带 `practice` 的正式活动

不新建题目对象或存储；练习随既有私人学习记录归属与删除。

| 概念 | 实际承载 | 规则 |
| --- | --- | --- |
| 题目身份 | 选择 `move:{turn}:{move_id}`、交付 `delivery:{turn}:{move_id}` | 重试是新题（新的 `move_id`） |
| 入口 | `practice.entry`：P1 为 `note_revisit`、`warmup`；后续为 `reading_margin`、`board`、`presentation`、`exam_daily` | 必填 |
| 所练关系 | `move.target`（关系焦点与原文 LID 范围），可附 `move.object_ids`（教学图中的正式对象） | 焦点私有，不得出现在题面 |
| 方式与难度 | `practice.mode`：`recall` / `discriminate` / `compose`；P2 增加 `practice.distance` | 私有 |
| 题面 | `move.prompt` 与 `move.delivery_text` | 宿主粗查不得含目标标签（`named_target`） |
| 私有解答 | `move.explanation`（完整解答）与 `move.assessment`（冻结评分合同） | 本题结束前不公开 |
| 提示 | `practice.hints`：1–5 条，按种类顺序、每类至多一条 | 按请求逐条释放为 `HelpDelivered`，展示后记 `HelpDisplayed` |
| 回访笔记 | `practice.revisit_note`：确切 `NoteRef` | 仅用于 `note_revisit`；题面逐字引用原话 |
| 行为 | `actions` 必含 `submit`、`request_hint`、`reveal`、`skip`（P1b 起） | 同一交付至多一道练习题（P1b 起） |
| 核查结论 | 私有教学事实：通过 / 存疑 / 失败（P1b） | 追加，不改写原交付与证据 |

### 3.2 提示

`in_problem`（题内指向）→ `structure`（情境结构，P1b）→ `own_note`（自己的笔记，确切版本）→ `source`（原文 LID）→ `worked_step`（关键一步）。

- 只有 `in_problem` 不计协助；其余四类计协助，并按种类保留，供 P2 判断难度。`own_note` 首版一律计协助。
- 澄清题意在对话中回答，不是提示，不记录。
- 界面只显示“提示（还有 N 条）”，不显示等级编号；每类提示有自己的标签与“打开这条想法 / 打开原文”按钮。

### 3.3 证据

- 每次已评估的作答（`submit` / `revise`）由 `derive_assessed_evidence` 各写一条表现证据；`assistance_refs` 是作答时已展示且计协助的提示。
- 投影判定沿用既有规则：答对且无协助 → 独立支持；答对有协助 → 协助支持；改答后答对 → 修订后支持；部分对、答错分别计数。
- 跳过、查看解答本身不产生证据；查看解答之后的改答按协助计。
- **无正式对象的练习证据目前不进投影**：其证据 `object_id` 为空、身份为 `assessment:{action}:source`（`learning_evidence.rs:323–327`），`rebuild_learner_projection` 跳过无对象证据（`learning_evidence.rs:630`）。P2 选材须另行读取。
- 失误性质与所据关系冲突时的修复建议：P1 不记录，属 P2。
- 核查存疑（P1b）：投影重算时排除该交付产生的证据。

### 3.4 学习脉络（M1、M2）

| 概念 | 实际承载 | 规则 |
| --- | --- | --- |
| 开关 | 教学状态 `learning_map_enabled`，经 `/tutor/mutate` 的 `set_learning_map` 修改 | 默认关闭；按学习工作区；关闭时在同一事务中删除节点、出处、推理链与整理进度 |
| 节点 | `learning_map_nodes`：`node_id`、陈述 | 只追加；新节点身份由交付与抽取键决定，重试复用 |
| 出处 | `learning_map_sources`：`(source_id, source_revision, start_lid, end_lid)`、引文、`delivery_ref`、`turn_id`、`publication_id` | 引文须逐字出现在所引段落（宿主核对）；段落范围须是该交付的 `source_bindings` 之一 |
| 推理链 | `learning_map_chains`：前提集合 → 结论 | 链身份与前提顺序无关；合并后前提含结论的链丢弃 |
| 整理进度 | `learning_map_coverage` | 失败至多 3 次后不再重试，直到关闭再开启 |
| 触及 | 读取时派生，不存储 | 笔记在交付回合上写下（`turn_id` / `based_on_turn`），或锚点位于同一出版物的所引段落内；裸 LID 不触及 |
| 移除 | `learning_map_note_removals` | 用户决定，重建脉络后仍保留 |

## 4. 运行合同

### 4.1 出题

1. P1：Agent 依练习指导，从本轮已读材料与用户此前接触过的关系中选目标；尚无接触过的内容时说明并改为普通帮助。P2 起依选材规则。
2. 依入口构造情境：旧想法回访取笔记确切版本原话；阅读边注取当前阅读段落的真实内容；教具题取当前教具版本与状态。
3. 宿主确定性检查：合同完整、提示顺序与指向完整、所引 LID 本轮已读、所引笔记版本存在、公开文字不含目标标签、旧想法回访逐字引用、同一交付至多一题。
4. **出题前没有同步模型审阅**（ADR-0176 MA3）；作者须自行解题并排查捷径。
5. **交付后核查（P1b）**：交付成功后排入持久后台任务，前台不等待；只读题面、私有解答、评分合同、提示与冻结的评分来源；结论追加为私有教学事实。

### 4.2 作答与提示

- 提示通过活动按钮请求，每次一条。
- 作答以普通对话回合进入回应流程（`learner_context.responding_to_practice`，P1b）：答错时说明哪个结论不成立并指出第一个断点，不给出更正；不在对话中写提示正文、解答或所练关系。
- 跳过、查看解答或要求讲解即结束本题，之后按请求完整讲解。

### 4.3 结束与停顿

- 答对时宿主随评估结果释放完整解答（P1b）；回应回合用一两句指出决定性的一步，不重讲。
- 停顿：同一交付不出第二题；下一题只在用户继续时给出。
- 作答可用既有的“留为我的想法”保存为笔记。封闭题的作答文本是选项本身，开放题更适合回访与保存。

### 4.4 频率

- **阅读边注（P3）**：默认关闭。开启后，每次进入一个章节且连续阅读满 5 分钟（初值）后至多出现一题；同一天被忽略两次后当天不再出现。
- **热身（P3 自动提议；P1 仅为“练一练”目的入口）**：回到工作区时提议一次；最多连续 3 题，每题结束后用户选择继续才出下一题；可整体跳过。
- 以上为初值，按使用数据调整。

### P1：练习运行时与首批入口（本地完成）

- **产出**：练习合同与宿主检查；`request_hint` 按序释放并标注种类、笔记引用与原文 LID；冻结协助时排除题内指向；旧想法回访（笔记面板“练一练”，冻结确切版本）与“练一练”学习目的两个入口；练习卡片显示提示种类、剩余条数、“打开这条想法 / 打开原文”、“看解答”。
- **验证**：新增 Runtime 6 项、服务端 4 项、前端 1 项测试通过，前端类型检查通过。回归：Runtime 985 通过，3 项因仓库外真实书库缺失而失败；服务端 1203 通过、38 失败——22 项因本机缺少 ffmpeg、预览浏览器、matplotlib 或仓库外真实书库而失败（按错误信息逐项核对），1 项单独运行时通过（并行时序），其余 15 项断言失败在不含本改动的基线上同样失败；前端失败数与基线相同（48），通过数多出新增的 1 项。
- **未完成**（转 P1b）：没有真实模型验收；出题前没有任何模型审阅；作答回合不加载练习规则；未强制可跳过与一交付一题。

### P1b：练习闭环补齐（1–7 本地完成）

1. **回应回合规则**（本地完成）：新增 `practice-response` 模块；`learner_context.responding_to_practice` 在引用练习交付的回合给出公开练习视图；待完成活动摘要带 `practice`。
2. **必须可跳过**（已在本地）：练习的 `actions` 必含 `skip`。
3. **一交付一题**（已在本地）：同一交付集合中第二道练习题被宿主拒绝。
4. **情境结构提示**（本地完成）：`PracticeHintKind::Structure`，位于题内指向与自己的笔记之间；提示上限改为 5；计协助；界面标签使用本项目文案。
5. **答对后展示解答**（本地完成）：练习的答对作答随评估结果释放完整解答（记为已交付帮助，之后的改答按协助计）；界面显示解答并照常进入回应回合。
6. **交付后核查**（本地完成；本地与网络宿主的后台循环各运行一份）：练习交付后排入持久后台任务；独立模型核查解答与评分是否正确、有无捷径、是否超出材料、题面是否泄露、提示是否一次透露多步；结论追加为私有教学事实；存疑时活动显示提示、投影排除该交付的证据、回应回合不依据原评分断言对错；调用目的单独登记于运行标签与观测策略，计入额度。
7. **离线评测**（本地完成）：`tutor_explanation_review_rules.md` 补充练习说明——练习题不要求讲清所练关系，改查题面是否泄露。
8. **真实模型验收**（未做：需要模型密钥）：独立答对、借提示答对、答错后改答、跳过后转讲解、旧想法回访各至少一次，记录全部请求与用量；只证明机制，不证明学习效果。
- **验收**：作答回合加载回应规则且不泄露提示与解答；没有 `skip` 的练习被拒；一交付两题被拒；结构提示计协助；答对后看得到解答且之后的改答计协助；核查存疑的题显示提示且不计入投影；核查失败时证据照常计入；投影的独立 / 协助计数与实际提示一致。

### P2：选材与节奏（本地完成）

- **实际实现**：`practice.distance` 与 `level(mode, distance)`；宿主按同一来源的练习历史（LID 范围相交，无正式对象也可读）强制交错、两次未答对后换关系、按上次结果调整难度、重试换情境；失误性质以 `evidence`（`nature=hypothesis`）记录，与所据笔记冲突时附笔记引用并提出一次修复。

- **内容**：`practice.distance`（贴近原讲解 / 同一领域新情境 / 远迁移）；目标优先级（独立支持较少、被更多后续关系依赖、最久未被调用）；证据读取（正式对象读投影，无对象证据按同一来源版本的 LID 范围相交读取）；难度调整（见 ADR-0178 §6）；交错；换情境重试；失误性质以可修正的理解假设记录，所据关系冲突时附相关笔记版本提出修复建议。
- **验收**：连续练习中同一目标不连续出现；调高 / 保持 / 调低与实际提示种类一致且 `distance` 随之变化；同一目标连续两次未答对后换目标；重试情境与原题不同；无正式对象的材料也能读到此前的练习证据。

### P3：阅读边注与热身提议（本地完成）

- **实际实现**：`practice-pacing.ts` 管理边注开关（默认关闭）、阅读计时、忽略计数与热身提议，均为每台设备的本地便利设置；提议本身不调用模型，用户接受后才出题；`PracticeOffer.vue` 显示提议。

- **内容**：设置项（默认关闭）；边注触发与频率（§4.4）；回到工作区时的热身提议。
- **验收**：未开启时从不出现；开启后题目基于当前阅读段落的真实内容，所需关系来自此前所学；频率限制生效；热身逐题进行、可整体跳过。另行统计开启比例、忽略率与对阅读完成度的影响。

### P4：画板与教具（本地完成）

- **实际实现**：画板组装题以 `choice_set` 判定，选项为全部卡片、正确答案恰为前提卡片，卡片角色对用户隐藏；教具目标题须引用本轮已交付的演示版本，以开放评分标准判断用户提交的页面状态。“待定”项按快照加评分规则的方式决定。

- **前提**：既有规则“页面计算只是观察，不是评估”（`tutor.rs`）不变。以用户**提交**的画板或控件状态作为作答，按冻结合同评估；页面自身的计算结果仍只是观察。
- **待定**：画板组装用新的评分规则（结构比对），还是以提交快照配开放评分标准，在 P4 设计时决定。
- **验收**：画板题含干扰卡片，组装结果按私有解答的推理链判定；教具题以提交的状态判定，不依据用户的文字声明或页面自报的结果。

### P5：考试冲刺（本地完成）

- **实际实现**：考试冲刺面板“今日练习”按距考试天数决定当天题数（`examDailyCount`），以 `exam_daily` 入口逐题进行。

- **验收**：每日练习范围随考纲与日期修订变化；课程编排题沿既有来源出示；冲刺结束后证据保留。

### M0：召回评测集（工具就绪；标注待用户）

- **实际实现**：`evals/note-recall/`：纯函数评分（`core.mjs`，含测试）与运行脚本（`run.mjs`，调用本地 `POST /me/notes/search`）；`--structural` 时每个用例各跑两路与三路融合。用法见该目录 README。

- **协议**：用户从自己的学习记录中选 20–30 个真实教学回合（至少涉及两本书）；对每个回合，在完整笔记列表中标出全部相关笔记，标注时不看任何检索结果。计算 BM25、MiniLM 与两路融合的 recall@5 / recall@10；两路都漏掉的相关笔记构成目标集。评测数据留在用户私人存储，不进入仓库。
- **判定**：目标集为空或很小，则不做 M1–M3。

### M1：学习脉络构建（本地完成，默认关闭）

- **实际实现**：用户在练习设置中开启“整理我的学习脉络”后，本地与网络宿主的后台循环逐个整理已交付的讲解（练习题除外）：抽取调用只看交付正文与所引段落；宿主丢弃引文不在段落中的关系及依赖它的推理链；候选由同一来源相交的 LID 范围与陈述字面相近（只用于提名）产生；有候选时才调用身份判断，模型只能链接到所给候选，拿不准时保持新节点。两类调用分别登记为 `learning_map_extract` / `learning_map_identity`，网络宿主按读者后台任务计入额度。脉络不含任何理解状态字段，也不写入证据。
- **偏离 M0 先行的顺序**：M1 先于 M0 标注完成，因为 M0 的结构召回一路需要已建成的脉络才能评测；默认关闭，未通过评测前不影响任何既有功能。

- **内容**：从已交付教学正文抽取关系与推理链；只收录有原文出处、且与所引段落相符的关系；来源一律带 `(source_id, source_revision, LID)`；先由同一来源中的 LID 范围确定候选，跨书是否同一关系由模型依据陈述与原文判断，不按名称或 LID 合并（ADR-0169）；只追加、可整体重建。可选：删除可由其余推理链推出的冗余链（参考索引 L2）。
- **验收**：每个节点与推理链可回到交付回合与带版本的 LID；同一关系经两本书到达时能够合并，不同关系即使同名也不合并；删除后可完整重建；脉络中没有任何理解状态字段，也不转移证据。

### M2：笔记关联与结构召回（机制本地完成；评测待 M0 标注）

- **实际实现**：笔记操作 `learning_map_relationships`（某条想法触及的关系及其全部出处，标明为系统解释）、`learning_map_suggestions`（两条想法分别触及同一推理链的前提与结论、且尚无联系时提出，附两端陈述）、`learning_map_remove`（移除触及）；接受建议走既有的 `link`。搜索请求带 `structural: true`（可选 `turn_id`）时加入第三路：以该回合讲过的关系为焦点（无回合时取与提问最相近的至多 3 条陈述），沿推理链向前提回溯至多两步，按距离排序触及这些关系的想法，以 RRF 融合并在命中上标注 `structural_rank`。默认搜索与教学召回不带该标志，行为不变。
