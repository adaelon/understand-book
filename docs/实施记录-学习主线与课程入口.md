## 当前实现

- LE1：登录后默认课程首页；公共目标可直接接受，已有私人实例按 release/version 复用；开课失败保留实例、课、运行、聊天及材料目标。
- LE2：当前任务和本课目标固定显示；课程路线折叠；反馈区保留一个主要输入；完成卡区分课程进度与实际表现。
- LE3：讲解就地提供表达与应用题入口；普通应用题绑定原回答，持续闭卷明确说明收起资料；完成结果引用进入原课程 Coach，原课程接纳后再推进。
- LE4：阅读空态可直接“带我学这一部分”；私人选择记录保存原材料、课程与聊天引用；首页读取窄摘要；本机继续入口沿同一语义恢复。

## 集成时发现并修复

1. 首次没有聊天的用户无法保存课程接续。显式开课先建立原私人聊天，再交付课程；后续练习和恢复复用它。
2. [空闭卷结果解包](evidence/learning-entry-20261116/course-null-result/README.md)：合法 `result: null` 被错误替换为工作区 envelope，导致页面渲染异常。通用客户端改为按字段是否存在解包；没有增加播放器重挂或兼容层。
3. [手机课程前景](evidence/learning-entry-20261116/mobile-course-resumption/README.md)：已恢复原课程却被最后一次聊天前景切换遮住。课程接续现在显示当前课程任务，闭卷和对话显示相应原现场。
4. [返回首页的显示归属](evidence/learning-entry-20261116/course-home-visibility/README.md)：多根 App 使父级隐藏指令失效。恢复单根，闭卷沿原 Teleport 展示，隐藏阅读现场时同时收起弹层且保留原状态。

## 环境与复验入口

课程验收配置：`packages/web/playwright.learning-entry.config.ts`。先启动 `inquiry_course_browser_host`（`COURSE_BOOK_DIR=.understand-book/ai-infra-book-complete`），构建 web multi 后，用 4264 静态预览调用 4260 真实服务。宿主 4261 提供测试身份和停止入口；此配置没有模型。正式样本、命令、最终结果和历史失败范围见[浏览器验收记录](evidence/learning-entry-20261116/browser/README.md)。

开发态曾遇到修改期间 Vue HMR 的 `invalidateTypeCache` 错误，最终验收已改用静态构建。系统 C 盘在验收中耗尽；后续命令的 TEMP/TMP 指向项目 `.tmp/learning-entry-20261116/browser-temp` 或 `runtime-temp`。自动审批拒绝清理 C 盘的本轮临时测试目录，目录仍保留，未改动其他任务文件。

全局翻译目录检查还包含音频跟谱、额度套餐等既有修改的缺键；本轮学习入口及直接相关组件已补齐，不据此声称整个仓库全量检查通过。

工作树包含本轮之前的大量未提交修改；本轮沿现有工作树集成，不重置、不提交、不部署。
