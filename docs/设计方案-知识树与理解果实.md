# 知识树与理解果实

日期：2026-11-05。状态：产品方向已实现并完成本地验收；决策见 [ADR-0181](adr/0181-source-knowledge-tree-and-understanding-fruits.md)，进度与验收见[切片方案](切片方案-知识树与理解果实.md)。承接[想法笔记与理解路径](切片方案-想法笔记与理解路径.md)及苏格拉底问答。

## 方向

**决策：程序投影既有知识，私人理解按依据挂接。**

文字材料的知识树内容主体来自现有 Pass1 与 discourse，原文层级提供位置和顺序，BookStructure 补充已存在的章节说明与跨章主题。视频沿已有图谱、讲解结构及媒体位置组织，音乐沿既有曲式结构与音乐事件组织。树的生成不追加模型调用，不要求新的全书语义归并或完整教学素材构建。读者能在真实树状地图中看到当前位置，沿枝条浏览内容与来源，点击果实查看自己的理解与变化，并继续讨论。

## 公共知识的程序投影

- 可见树以书、章、节组织范围，直接展示 Pass1 概念、对象和论断。普通段落、公式和图片不单独成枝，LID 只保留为来源地址。
- 同一知识条目在同一节内只有一个入口，入口保留本节的各处原文依据；跨章节出现时保留各自入口。从枝条开始讨论同时携带知识身份与选中的位置。
- discourse 中有实际摘要的解释、例子和论证在独立分枝展开，复用原角色、关系和来源；只有角色标签、没有具体内容的记录不生成知识卡片。
- 节点引用包含资料及确切版本、产物类型和原条目身份。概念的不同出现位置可以有多个展示入口，共享知识引用；理解仍保留当时的来源范围。
- 父子结构表达浏览归属。支持、反驳、解释等语义联系保持原类型，选中内容后展示；同段相遇仅用于寻找候选。
- 程序用确切位置关联条目。某段存在多个概念或论断而没有明确归属时，保留同一内容组，避免凭名称或出现顺序发明从属关系。
- 标签使用已有内容。条目按原文顺序稳定排列，展开才显示局部内容；新理解不重新布局整棵树。

## 首屏与展开顺序

首屏先回答“我在哪、这里讲什么、可以从哪里开始”。标题使用当前章、节或音乐／视频范围的名称。已有章节摘要直接展示；没有章节摘要时，展示该范围按来源顺序的首条讲解摘要，并标为“开篇线索”。搜索收进工具栏。

有理解的范围优先显示“接着你的理解”，引用用户原话和现有下一步；没有理解时显示“从这里开始”，优先采用已整理的关键内容，否则采用原文顺序中的第一条论断。音乐沿既有事件顺序进入。按钮打开确切条目，具体条目页直接显示内容、来源和讨论入口。

范围内超过 6 个概念、对象、论断或关键内容时，先显示“要弄清的关系”“会用到的概念”导航分枝及既有解释分枝；分枝展示数量和实际内容预览。内容较少时直接展示知识条目。完整条目继续分页展开，原引用与来源不变。

初次打开跟随正在读／听／看的范围，显式知识引用优先；没有现场位置时恢复上次选择。进入之后，后台刷新保持所选枝条，“我在这里”才重新定位。导航后把标题带入视野，具体知识页无需穿过空树才能看到内容。

## 音乐与视频的接入方案

**决策：共用理解挂接，保留各媒介的内容与定位。**

| 材料 | 枝条的已有来源 | 理解保留的具体依据 |
| --- | --- | --- |
| 文字 | 原文层级、Pass1、discourse、已存在的 BookStructure | 原资料版本、知识条目、原文范围 |
| 视频 | 已有段落与视觉事件、共享图谱、video discourse 的讲解角色和关系 | 原视频版本、相关文字或画面、已读取的原声范围及联合依据 |
| 音乐 | MusicStructure 的曲式段落、MusicEvent 的事件、主题和声部角色及事件关系 | 确切录音与时间范围、谱本位置、事件与演奏出现身份 |

- 视频按现有时间段与讲解内容浏览。视觉事件与知识条目允许多对多；一个论断跨多个片段时保留各处来源，不能把同一帧或相邻时间内的内容都视为同一知识。
- 音乐以作品、已有曲式段落、音乐事件逐层展开。主题重复、变奏、声部交接等保留已有关系类型；相同主题或谱面小节的多次演奏保留各次出现，跨片段比较可关联两个以上事件。
- 音乐与视频理解继续使用 TeachingTarget 已有的 music_bindings、media_bindings，再增加知识条目与用户原话的关联。用户听感可保存为这次聆听表达；帮助条件与实际表现沿既有理解规则记录。
- 树与播放器互相定位。播放时只更新位置提示，手动展开的枝条与选中的理解保持稳定；果实可打开对应原文、画面、原声或谱面，并携带原问题现场继续讨论。
- 苏格拉底问题在 Agent 讲解或指定回听／回看片段完成后自然提出，持续播放时不因经过某个枝条自动打断。播放、暂停和选中仅记录交互，理解果实仍需实际表达依据。
- 缺少语义成果的范围先显示既有导航和内容覆盖状态。补齐成果后增加枝条；历史理解保留原版本与原位置，只有明确对应才能挂到更细的节点。跨材料理解保留各自来源，不按相同名称自动合并。

## 私人理解怎样挂接

复用 LearningEvidence、TeachingTarget、理解摘要和时间线。在理解观察中保存知识条目引用，并为各引用保留它所依据的用户表达片段；原话、帮助、来源与修订继续沿原事实保存。

1. 打开节点、提出问题或继续既有邀请时，向当前回合提供相关的真实知识条目与引用。阅读位置和当前问题提供候选范围。
2. 现有问答／后台理解整理在解释真实表达时，同时选出实际涉及的条目及相应原话片段。只补充这次已有调用的输入和输出，不新增全书分析或单独挂接调用。
3. 宿主检查引用属于当前材料版本、原话来自本次表达，并保存关联。选中过某节点、读过其原文或听过讲解不形成理解证据。
4. 同一知识关系及能力下的表达聚成一组果实，点击后查看每次表达和当时帮助。一条表达涉及多处时逐处保留归因，共用原事实。
5. 后来的新表达追加观察，准确旧观察留在历史。对系统解释的纠正沿已有修订机制更新当前视图。
6. 历史记录有明确对象对应时直接展示；仅有原文范围时先放在对应范围的理解记录中，保留进一步定位的空间，不自动分发给该范围内所有论断。

## 位置、果实与问答

- 当前位置是浏览／讨论焦点，用标记和路径显示。理解果实由已保存证据决定；未知位置保持没有理解记录，不赋予低能力判断。
- 点枝条查看知识内容、相关联系与原文；点果实进入现有理解详情、原话与时间线。
- “继续推敲”携带知识引用、当前理解依据和相关原讨论／演示现场。没有个人笔记的理解同样可继续。
- 主 Agent 直接承接最新用户表达。后台整理完成后更新果实；继续聊天不等待整理。现有后台失败状态应可见且可重试。
- 用户换话题时重新选择焦点；“继续”“谢谢”、单纯播放和操作不自动新增理解。多个果实不汇总为章节掌握分数。

## 实施顺序与完成场景

1. 公共投影与阅读入口：用已有真实文字、音乐和视频材料生成相应内容树，检验条目覆盖、来源跳转、重复出现及稳定位置。
2. 私人覆盖与直接引用：接入已有理解；验证同段多个论断时只关联实际表达涉及的内容，并保留帮助、纠正和时间线。
3. 双向接续与界面：聊天定位到枝条，果实回到原讨论，无笔记记录也可继续推敲；检查桌面与手机上的树形、文本、触控和展开行为。

完成场景为：用户在某条论断上表达理解，记录在正确枝条出现，查看果实时能读到原话及帮助；重新打开材料后位置与历史保留，从果实继续时 Agent 采用这条实际理解，而非重复开场。

音乐补充场景：用户比较同一主题的两次出现，理解关联两处实际事件，回听分别落到正确录音范围，重复小节不混淆。视频补充场景：用户结合讲者原话与画面解释一个关系，理解保留双方依据，回看能返回对应片段；后续播放不移动原提问位置。
