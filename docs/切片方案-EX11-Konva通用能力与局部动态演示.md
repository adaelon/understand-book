## 0. 意图、术语与交付范围

用户已认可 Konva 当前的排版与效果，并要求继续建设通用能力；随后确认借鉴 Ciechanowski 的局部演示方式，让 Manim 只承担一段过程，默认隐藏视频进度条，同时提高页面有效信息密度。这些反馈构成 EX11 的开发方向。EX10 原批次的技术失败与成本记录继续成立。

| 用语 | 本切片含义 |
| --- | --- |
| Konva 通用能力 | 正式工具能供给固定库；Agent 实际收到可复用指导，能跨主题制作并经真实预览修订；Reader 能恢复对应现场。 |
| 局部动态演示 | 正文中围绕一个关系、动作或变化过程展开的动态插图，沿用 [CONTEXT](../CONTEXT.md) 定义。 |
| Manim 短片段 | 固定模型、固定参数下预先渲染的一段过程；用户可播放、暂停、重播或定位到有意义的时刻。 |

| 通用制作指导 | Agent 能实际读到并用于新题目的方法和接口说明；指导针对对象、关系、操作和现场，不规定所有页面采用同一模板。 |

交付覆盖生产 Author、制作提示、预览、版本资源、Reader 与真实 Agent 生成。维持现有来源绑定、可见文字校验、不可变版本、显式现场保存和学习证据边界。EX11 的结果单独记账；EX2 v7 与 EX10 的停止状态保留。

## 1. 从观察到方案的逻辑链

在 [Mechanical Watch](https://ciechanow.ski/mechanical-watch/#balance) 中，局部时间滑块改变零件位置，邻近的一句话解释当前动作；在 [Gears](https://ciechanow.ski/gears/#disc) 中，圆弧与展开后的长度直接放在同图比较。实际查看的这两篇文章与 Moon 使用 Canvas，未发现 video 元素。借鉴对象是“正文中的可观察过程”和紧密的图文对应。

这给出三项设计判断：

1. **一个局部问题对应一个动态插图。** 连续拖动参数时采用实时图形；固定过程的变形、拆解、重组可以由 Manim 短片段承担。同页可组合两种表示。
2. **解释尽量发生在图形关系里。** 同轴比较、颜色对应、邻近标注、轨迹与局部强调，让读者直接看见差异。文字补充条件、含义和结论。
3. **控件围绕理解动作安排。** 用户要看一次变化，就提供播放/暂停和重播；用户要观察某个阶段，就增加阶段定位；用户要比较参数，就提供能真正重算的参数控件。

当前学习率 C 页已有较好的动态边界解释和可拖圆点，但图下空白、右侧读数/公式/说明/表格重复，以及过小的实际命中区域，会削弱这些优势。EX11 同时处理表示设计和实际操作。

## 3. 表示选择与页面组织

| 用户需要观察什么 | 优先表示 | 必要操作 |
| --- | --- | --- |
| 改参数后立即改变位置、轨迹、响应或结果 | Konva；简单形状仍可直接 SVG/Canvas | 连续改参、拖动、必要的时间控制。 |
| 一次固定的变形、拆解、重组、跨越或机制步骤 | Manim 局部短片段 | 播放/暂停、重播；有明确阶段时定位。 |
| 固定过程中的某个中间关系 | 可定位实时场景或可定位短片段 | 停在指定阶段，相关说明与画面同步。 |
| 对照、数值、定义或静态结构已经足够 | HTML、公式、表格或静态图 | 保留必要阅读操作。 |

方法指导要求 Agent 先决定本段要让读者看见什么，再选表示。即使安装了 Konva/Manim，普通短答仍直接完成。用户只需提出阅读问题；工具选择与技术名称留在制作过程里。

默认把一个局部演示组织为“引入问题的一小段正文 → 动态插图与就近控件 → 当前动作或关键关系的一句说明”。这是可调整的阅读顺序：并列比较适合并排，推导适合逐步展开，宽图可独占一行。

## 4. 正式 Konva 供给与制作合同

### 4.1 固定资源装配

在现有 `presentation.author.write` 新增可选 `libraries`，首版只接受 `konva`。省略时保持现有写入行为。工具将选择解析为固定的 Konva 10.7.0，并返回实际版本及逻辑路径。

```json
{
  "operation": "write",
  "title": "学习率与更新方向",
  "libraries": ["konva"],
  "html": "完整页面；业务脚本使用 Konva",
  "asset_refs": [],
  "readable_content": "当前关系、适用条件与必要结果"
}
```

该样例只展示新增字段；来源、初始现场、状态合同及修订版本继续沿用现有工具字段。

```text
Agent 原始 write 参数
  → 正式 Author 解析 libraries
  → 候选保存固定库 + 许可 + 短 script 逻辑引用 + 页面代码
  → preview / Reader 各自解析同一版本资源
  → 浏览器执行
```

库放在产品随包资源中，生产代码引用该位置；EX10 的冻结资源和证据目录保留原样。候选保存实际使用版本，已有页面重开不随宿主库升级而改变。库正文计入既有文本内容大小限制。

Author 在页面业务脚本执行前插入库引用。`read(index.html)` 返回可修改的页面与短引用；列目录返回库名、版本、许可和大小，读取宿主管理的库路径返回同类元数据。常规制作资料只含必要 API 用法。库正文不会通过工具回执或历史压缩进入模型消息。

`based_on` 修订显式声明该版本需要的 `libraries` 和 `asset_refs`；Author 重新装配所需资源，移除旧的托管引用，保持单次加载。调用参数、候选正文、浏览器最终文档各有清晰所有者；装配不修改 provider 返回的原始调用。

### 4.2 通用制作指导

指导分为“为什么这样表达”和“怎样正确使用接口”，内容进入实际 `presentation-method` 的加载路径。首版沿用短核心直接注入；若拆出参考文件，必须在同一刀提供 Resident 可用的读取/注入路径，并保留实际请求证明已读到。

| 能力 | 指导与可观察结果 |
| --- | --- |
| 排版 | 容器宽度驱动舞台尺寸；重排后对象和标签仍对应。正文、公式和原生控件采用 HTML；图形对象及其局部标签由 Konva 管理。 |
| 层次 | 对象、关系、强调有明确视觉层级；按实际更新需要使用 Layer/Group，稳定对象原地更新。 |
| 拖动 | 拖动屏幕坐标映射回领域参数；鼠标与触摸使用同一模型；真实命中区域至少 44px，可大于可见圆点。 |
| 动效 | 对象身份连续，动画有明确解释目的；改参后重算，回退后重建目标轨迹；零位移不残留箭头头部。 |
| 时间 | 领域步骤与视觉进度分开；暂停、回退、重复定位得到相同对象与结果。 |
| 现场 | 页面计算是单一事实来源；参数、状态读回、可见结果与 readable content 一致；操作完成使用 `presentation.commitState()`。 |

首轮指导使用少量彼此独立的 API 片段展示命中区域、坐标映射、尺寸变化和可定位渲染，避免提供一份让 Agent 逐题换标题的整页模板。指导修订依据实际生成错误。

## 5. 页面信息密度的具体要求

页面首先保证当前关键关系能被直接比较。密度改进按下列设计动作落实：

- **合并重复表达。** 同一组数值若已在图旁标注，正文解释它意味着什么；完整逐步表仅在读者需要逐项核对时展开。标题、说明、结论各承担不同作用。
- **把比较放在一起。** 可共用坐标、时间轴或图例的对象优先共享；颜色从对象延续到短说明。同屏能看到原因、变化和结果。
- **让控件靠近对象。** 参数输入、阶段选择和播放按钮邻近其控制的演示；简短控件保留清楚的名称、当前值和足够的触控区域。
- **按内容分配空间。** 图形使用能表达关系的区域，长说明回到正常正文流。窄屏按阅读顺序重排；短屏允许正常滚动，宿主输入区不覆盖演示控件。
- **保留有用留白。** 留白用于区分段落与关系；删除的是无解释作用的固定高度、重复容器和装饰。可读字号与触控尺寸不作为压缩手段。

`.comparison/.card/.callout` 改为可选。默认布局使用自然正文流和局部图；只有确有分组、并列对照或补充说明时才使用相应容器。共用 CSS 提供基础文字、间距和媒体适配，具体布局仍由 Agent 围绕问题设计。

学习率首个验收页应把同侧接近、交替接近与发散的轨迹组织成可直接比较的主体；当前 η、真实迭代步和必要结果靠近轨迹显示；公式与一句解释说明当前关系。完整历史表可另行展开。Agent 可以采用不同布局，只要比较关系和必要操作清楚。

密度验收保留同视口、同参数、同时间位置的前后截图，并说明哪些重复被合并、哪些关系现在可同时看见。发现问题时修改对应布局或指导；不以卡片数量、图形面积比例、页面总高度或模型自评分代替判断。

## 6. Manim 局部短片段的生产路径

### 6.1 渲染操作与反馈

新增 `presentation.author` 的 `render_animation` 操作。Agent 提供一个 `PresentationAnimation(Scene)` 类、JSON 数据、输出尺寸及可选语义定位点；宿主运行固定入口，数据作为 `data` 提供给场景代码。

```text
render_animation(
  code: Python source,
  data: JSON,
  size?: { width, height },
  cues?: [{ id, label, at_seconds }]
) -> {
  asset_ref, asset_path, poster_path,
  width, height, duration_seconds, fps, cues,
  preview_images
}
```

首版沿用 EX9a 已验证的 Manim 0.21.0/Cairo，省略尺寸时为 1280×720，采用 30fps、无音频 MP4。Agent 应按局部插图的实际形状指定画幅，正文不统一套 16:9 容器。片段长度以一个动作讲清楚为准，通常几秒到十余秒；实际时长由成品读取。背景、字体和配色由页面统一设计，Agent 对缩放嵌入后的可读性负责。

宿主使用单独的 Manim Python 路径，借鉴现有绘图依赖配置方式；运行于独立临时目录。首版执行超时设为 180 秒，依据 EX9a 高清渲染约 112 秒留出实际余量；不沿用 Matplotlib 的 20 秒。取消终止该次 Python/编码子进程并回收临时资源。失败返回精简诊断和可修订信息，资源尚未成功生成时不会返回可引用资产。

依赖缺失时返回明确不可用原因，部署说明写清 Python、Manim、编码器、字体及场景需要的 TeX；不在普通制作请求中临时安装依赖。该执行模式与当前受信任本机协作范围一致，临时目录不是代码沙箱。

渲染完成后确认媒体可解码，读取实际尺寸、时长与帧率，校验定位点在实际时长内，并提供首帧及能代表动作的少量真实帧。Agent 观察这些图像，再写入页面，继续使用浏览器预览验证页面内的真实播放器。代表帧不能替代最终页验收。

### 6.2 资源、保存与修订

当前 `content_files: BTreeMap<String, String>` 继续保存 HTML/JS/CSS、动画源代码与数据。为固定媒体增加专用字段，首版只服务本切片的动画：

```text
PresentationContent / PresentationView
  animation_assets: Map<asset_ref, {
    video_base64, poster_png_base64,
    width, height, duration_seconds, fps, cues
  }>

逻辑路径
  assets/<asset_ref>.mp4
  assets/<asset_ref>.png
  animations/<asset_ref>.py
  animations/<asset_ref>.json
```

新增字段反序列化默认空值，已有 SVG/Canvas 版本仍能打开。沿用 `.presentations` 的不可变候选/版本存储，媒体随所引用版本保存。首版使用现有 JSON 存储与浏览器 data URL，避免增加媒体服务；媒体字节与文本大小分别计量：文本维持 1 MiB，每段 MP4 最多 8 MiB、每版本全部动画及海报解码后合计最多 24 MiB。EX9a 的约 4.76 MB 成品提供当前量级参照，实际短片段用量在实现记录中保留。

`write(asset_refs)` 同时接受绘图和动画引用；HTML 使用渲染回执中的逻辑路径。每项资源必须来自当前制作调用或有权读取的 `based_on` 版本，并与保存页面的实际引用一致。`read` 返回媒体元数据、资产引用及可单独读取的场景源代码/数据，不返回二进制正文。修订只改变说明或布局时直接引用已有动画；改变其固定过程或参数时重新渲染并生成新资产。

preview 与 Reader 将版本内 MP4、海报分别装配为 data URL，在既有 CSP 上增加 `media-src data:`；脚本、字体、图片和连接规则按现有实际需要保持约束。视频编码与嵌入必须在真实 Reader 验证，不能从生成文件成功推定可播放。

### 6.3 短片段的使用边界

固定视频的时间定位只改变播放位置。要求 η、半径、力、速率等连续改参并立即重算时，由 Konva/浏览器承担；需要几个固定示例的对照时，可以保存几个明确标注条件的短片段。两者使用相同的领域说明，避免把视频进度显示成实时模型参数。

## 7. 播放、定位与现场一致性

### 7.1 用户操作

播放器默认隐藏原生 `controls`，使用 `playsinline`，显示一组紧凑的原生 HTML 按钮：播放/暂停、重播。确有解释意义时增加“分离/接触/推动”等语义阶段或局部时间滑块。隐藏系统进度条同时保留可发现的暂停、键盘操作和清楚的当前阶段。

默认静止在有意义的首帧，由用户启动。演示离开视口、页面隐藏或组件卸载时停止推进；返回视口保持暂停。单页多个演示各自有局部时间，播放一个时暂停其他正在播放的演示。操作完成后保存现场，不在每帧写入宿主。

### 7.2 领域时间与媒体时间

沿用 `presentationScene.seek({semantic_state, transition_progress})` 与 `snapshot()`。Konva 从参数和目标位置重画；视频由语义定位点把目标位置映射为媒体时刻，末端归入最终步骤与零进度。多个局部演示使用稳定 ID，当前演示由 `active_demo` 指定；preview 先通过已有点击动作选择演示，再进行定位。

```text
定位目标
  → 停止推进
  → 换算目标媒体时间
  → 等待 metadata，设置 currentTime
  → 等待 seek 完成且目标画面可观察
  → 更新阶段说明及现场
  → resolve seek；再截图 / 读结果 / 提交现场
```

已有 preview 会等待 seek 的 Promise；本刀补媒体就绪条件和真实帧验证。不能在设置 `currentTime` 后立即声称已显示目标画面。请求的逻辑位置与实际呈现帧分别记录，媒体误差按一帧时长核对；既有数学步骤/逻辑进度的精度要求保持原义。

### 7.3 保存、重开与追问

每个页面仍注册一个同步 state reader，返回已实际呈现的状态。多演示参数使用带演示 ID 的字段，保留各自参数、语义步骤和进度，以及 `active_demo`；字段进入现有状态合同。视频播放中缓存最后已呈现帧的时间与相应阶段，暂停或定位完成后更新现场和必要可见文字。

```text
registerStateRestorer:
  (savedState) -> void | Promise<void>

Reader 恢复:
  还原原生控件 → await 页面 restorer
  → 认证恢复后的公开内容 → 允许捕获/保存
```

同步页面继续按原方式恢复。媒体页面待解码定位完成再解除恢复状态；期间不把默认首帧存成用户的新现场。恢复失败沿既有错误路径显示失败，并允许重试。跨版本继承仍服从现有 `state_contract`，不会把旧片段的时刻强行套入已改变的过程。

同版重开恢复画面并保持暂停。显式保存和追问捕获同一次同步读到的参数、阶段、媒体位置和可见结果；不隐式改变当前播放状态。追问绑定保存回执与确切内容版本。媒体或 Canvas 内承担解释的关键含义同时以可读文字表达，纳入来源与观察合同。

## 9. 验证设计与失败后的动作

### 9.1 工程验证

每项验证解决一个具体失败。只对修改路径及其真实依赖运行对应检查；以下表格用于说明证据与修复方向。

| 具体失败 | 取得什么证据 | 出现时改什么 |
| --- | --- | --- |
| 库在预览可用但 Reader 缺失，或二次加载 | 同一正式候选的 preview/Reader 执行、based_on 修订与库版本读回 | 修两侧资源解析或托管引用装配。 |

| 定位返回但截图仍为旧帧 | 使用几何位置可区分的真实短片段，在起点/中间/终点、回退和重复定位后观察截图 | 修 await 条件；不能只修改状态字段使断言通过。 |
