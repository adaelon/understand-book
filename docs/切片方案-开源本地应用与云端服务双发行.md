# 切片方案：开源本地应用与云端服务双发行

日期：2026-11-17，更新于 2026-11-19。**公共 Reader 和两个宿主已拆分。各发行路径的交付与验收状态见第 9 节。** 产品决策见 [ADR-0187](adr/0187-open-source-desktop-and-cloud-editions.md)，模型协议范围与实测见[多协议模型接入方案](切片方案-多协议模型接入与配置.md)。

## 1. 用户路径与完成目标

**本地路径**：用户下载 Windows Setup 或 macOS DMG，经过正常安装后从桌面/开始菜单或 Applications 启动正式应用，在窗口内选择自己的资料或打开已有预构建材料、配置自有模型，完成阅读、带引用问答、教学和练习；关闭后能够恢复聊天、笔记、草稿和学习状态。基础阅读无需模型和网站账号；使用远程模型与外部研究时按所选服务联网。新材料的完整语义准备沿插件与外部 Harness 执行。

本地产品与发行采用用户认可的正式 Setup 体验。复用原正式桌面壳及安装链，把公共本地运行时装配进去；local-debug 提供已有本地功能的行为参考和回归入口。正式交付通过应用自身完成启动、资源定位、设置与恢复，用户无需运行 Start.cmd、手工打开 localhost 或维护解压目录中的资源文件。

**云端路径**：用户在网站登录，进入自己获授权的课程或资料，沿平台模型与套餐额度学习；换设备后恢复同一账号下的记录。既有云服务客户端继续作为网站的客户端交付，保持其登录和本机文件副本合同。

**开发与发行路径**：公开源码在没有私有仓库、个人资料与运营配置的环境中可以构建、运行本地应用和插件。云端仓库引用确定的公共核心版本，可独立构建和部署；公共能力修复只维护一份，两个产品分别发布。

完整完成须有本地两个操作系统、网站云端与仓库独立检出的实际证据。协议广度按 MP 计划独立验收；本计划的基础宿主验收可使用现有模型路径，联合宣布多协议双发行可用时须同时满足两份方案。

## 3. 产品与仓库组织

### 3.1 唯一归属与依赖方向

公共仓库保留：共同 Rust 学习核心、公共阅读服务、共享 Vue 阅读/课程/笔记/画板组件、公共合同与 i18n、本地宿主、Windows/macOS 发行、插件与构建引擎、开发样本及对应测试。原单用户源码启动路径继续可用。

云端扩展仓库保留：网站账号与套餐入口、云端宿主、授权与租户数据装配、服务额度及运营账本、邮件/订单/管理后台、云存储接线、部署与云服务客户端。公共课程的播放器和学习规则属于共享能力；平台课程目录的授权、服务配置与运营内容由云端持有。

依赖方向为本地宿主 → 公共核心、云端宿主 → 公共核心；公共核心不反向读取云端仓库的源码或配置。前端共享组件依赖公共合同，由宿主提供 API/身份展示/可用能力；原本共同的学习模型不因拆库复制。只在已有两个宿主确有不同实现的位置设接口，不引入通用插件容器。

目标包名和目录在 DF1/DF2 落实，例如将公共阅读服务从当前 server 提取成独立 crate，将共享 Reader 从当前 web 提取成独立 package；本方案中的职责名不是已存在包名。先在同一工作树完成拆分和验证，再迁入云端仓库，避免逐文件复制过程中形成两份权威实现。

### 3.2 跨仓依赖与版本

公共 Rust crates、前端包、工具合同和必要运行资产按同一公共发布版本提供。初期可固定引用公共 Git 版本或由该版本产出的包，记录准确提交与锁文件；无需为了拆分预先搭建包分发服务。云端正常构建不能依赖开发者电脑上的绝对路径，开发联调可显式使用本地公共源码。

每个发行物记录产品版本、公共核心版本、插件合同及数据格式要求；网站和本地版本号可独立推进。公共问题在公共核心修复，云端通过明确升级依赖接入。依赖升级在实际云端宿主验收后发布，不能自动跟随可变分支进入生产。

公共仓库的全新检出应只需公开依赖即可构建本地产品和插件；云端私有扩展独立检出后可获取其固定公共依赖并构建。源码包、二进制、课程/资料包各自按实际交付内容组织，运行数据、凭据和运营实例不进入源码与安装包。许可证沿仓库已有约定维护，拆库本身不重新定义已有公开代码的许可。

迁移时同步源码入口、构建脚本和文档链接；公共开发说明引用可访问的公共源码与合同，云端内部运行说明随扩展维护，不能让公共 Quick Start 依赖私有文档中的必需步骤。

## 4. 宿主与模型接入合同

### 4.1 共同运行时

教学、练习、来源引用、聊天与私人学习事实继续使用现有模型与状态规则。公共服务接收宿主已解析的材料访问范围和运行归属，再执行相同工具与教学流程。云端身份验证、资料授权和额度校验在原受信边界完成，本地宿主提供本机操作者范围；不同宿主身份不跨产品复用。

模型协议编解码、能力、工具消息、取消与实际用量观察属于公共核心；平台价格、套餐准入、预占与扣减属于云端实现。沿 ModelSpendPort 保留真实发送前后的生命周期；本地以自有 Key 运行时不查询平台套餐，仍记录已知用量，费用未知时保留未知。

沿 [ADR-0186](adr/0186-multi-protocol-reader-model-providers.md) 固定服务、协议、模型与运行配置。公共 API 返回必要模型状态，本地用户和云端管理员各自拥有配置操作权。公共生成逻辑不直接读取另一宿主的配置或环境变量。

### 4.2 与 MP 计划的衔接

DF1/DF2 确定公共服务、设置和前端装配接点，MP1 在这些接点实现模型配置与原单连接承接；两项工作合用一个配置合同与转换入口。MP2 及后续协议适配在公共 runtime 实现，云端模型管理界面和平台账本接线在云端宿主实现。

DF3/DF4 的本地产品化可先以现有 Chat/DeepSeek 路径验证安装与持久化。MP 的新协议合入后，按其既定样本补本地与云端代表性集成；九类协议及表列云端变体的完成条件全部保留。DF 不另列第二份协议支持表，MP 不再拥有宿主拆库和平台打包工作。

### 4.3 预构建插件与本机资源

本地阅读器展示材料就绪状态及原插件准备入口；插件已安装时沿原合同启动或交接，未安装或缺所需工具时显示具体准备方法。阅读已完成材料不要求运行 Harness。Build Engine 及语义执行器随插件/维护工具的原发行路径提供；阅读器必要的格式读取、OCR 或演示辅助资源由本地发行提供。

当前 Debug 包捆绑构建引擎是历史打包事实。实施时明确每项 helper 的真实调用方，把纯预构建资源移到插件包，同时保持原文件导入和基础层准备的可达路径；既用于阅读又用于构建的格式工具可以复用同一受管理资源。插件状态与应用状态分别报告，应用升级不自动安装或卸载外部 Harness。

## 5. 本地产品化与平台发行

Windows 复用的现有入口是 apps/desktop/src-tauri/tauri.conf.json 的 NSIS/currentUser 配置、windows/installer-hooks.nsh、icons 资源，以及 apps/desktop/scripts/export-installer.mjs 与 package:windows 发行链。当前发行校验要求云地址并排除 server/runtime，需保留云端配置并为本地产品建立对应的运行时、前端资源和发布校验；不能把现有云安装包直接记成本地完整应用的验收结果。

本地正式壳在 setup 阶段建立用户目录、解析书库与模型配置、启动公共本机服务并打开本机 WebView，在退出阶段保存并停止服务；IPC 注册与 capability 随实际本地命令更新。资源从 Tauri bundle 目录解析。旧正式本地壳的进程内服务结构见 [ADR-0068](adr/0068-windows-desktop-reader-and-codex-plugin-distribution.md)，当前功能行为沿 local-debug 的 main.rs 核对。

### 5.1 Windows 与 macOS 的共同体验

正式应用从系统用户数据目录启动，首次提供“打开资料”与“选择书库”，可直接阅读附带的原创样本；用户选择的书库保存为个人配置。模型设置沿 MP 计划。初始化、保存失败、缺少可选依赖或模型调用失败都保留输入与现有资料，提供对应处理动作。

使用现有 Reader 的排版、导航、课程与画板视觉体系，宿主入口采用本地书库/模型设置或云端账号/工作区。共享页面的布局与教学动作一致，系统文件对话框、快捷键和菜单按平台习惯适配。中英文、窄窗口、长资料名、加载/空态/失败状态均需实际查看和操作。

基本阅读、笔记与已有材料上的 AI 学习安装后可用；需额外 Python、模型或媒体工具的功能保留明确的按功能配置入口和状态，不要求用户配置所有工具后才能阅读。每项宣传为随包可用的能力必须在干净系统实测，不能依赖开发机器的 PATH 或资源目录。

普通使用从安装向导和应用图标开始，桌面窗口提供正式书库、模型设置、加载/错误反馈和恢复入口。运行不弹调试终端、不暴露开发目录或默认调试面板；基础阅读与已配置的 AI 学习不要求用户安装 Rust、Node 或 Bun。启动失败在应用可见界面说明原因并提供日志入口，用户通过界面配置的路径与模型设置在升级后保留。

安装器验证首次安装、创建快捷方式、安装后启动、同一本地产品升级、应用占用时的处理与卸载。安装/卸载 hook 只处理当前产品拥有的进程和安装资源；本地与云客户端的独立身份避免彼此终止或覆盖。用户书库、学习数据与独立安装的插件按原所有权保留。

本地产品的应用标识、安装目录、Setup 导出名和安装注册表键分别定义；当前云客户端已使用 app.understandbook.reader、UnderstandBookSetup.exe 与 HKCU/Software/UnderstandBook。插件或 helper 如读取安装位置，随所属产品更新发现规则，确保同时安装时解析到正确资源。

本地应用与云服务客户端采用不同应用标识、配置目录和更新渠道，分别识别“本地版”和“云服务客户端”。关闭窗口后按原保存规则处理草稿，退出本机服务和所属子进程；失败留可恢复状态。卸载与升级不清除用户书库和私人学习数据。

### 5.2 平台与资源矩阵

首轮发行目标为 Windows x64、macOS arm64 与 macOS x86_64，分别记录构建、安装、运行及功能证据。可选择分架构安装包；未验证的架构不列为已支持。

| 平台差异 | 需要实现与验证的内容 |
|---|---|
| 安装与身份 | Windows 安装包；macOS app/DMG、图标、bundle ID、签名与公证；各自首次启动、升级、卸载后的数据保留 |
| 资源定位 | 安装目录只读、用户目录可写；bundle 内资源、路径含空格、文件选择与应用从任意工作目录启动 |
| Native 依赖 | Node/Bun 的实际使用范围、Canvas、OCR worker/WASM/语言资源按目标 OS/架构准备，不能复用 Windows 二进制 |
| 系统行为 | 文件对话框、外链、快捷键、菜单、窗口关闭及后台停止；macOS 图形应用的环境与终端 PATH 差异 |
| 插件与 helper | 按平台发现真正安装的 Harness/插件与格式工具，保留手工指定路径；不把 codex.exe 或 Windows 应用目录当作跨平台合同 |
| 内容功能 | 文字/PDF/扫描 PDF、媒体、课程、画板和演示沿实际能力表逐项验证，缺少可选依赖时提示一致 |

macOS DMG 在 macOS 构建环境生成，并实际启动应用验证；发布签名与公证由发行配置完成。[Tauri DMG](https://v2.tauri.app/distribute/dmg/)、[macOS 签名与公证](https://v2.tauri.app/distribute/sign/macos/)。Windows 编译或 Web 测试不能代替 macOS 原生证据。

## 6. 现有数据与线上版本承接

### 6.1 旧本地 Debug → 本地正式应用

承接实际存在的包内 data、旧应用数据目录和 UNDERSTAND_BOOK_DEBUG_DATA_DIR。首次检测到旧目录时显示来源与拟承接的数据，用户选择后在旧进程关闭的条件下复制到新应用目录；目标已有记录时保留目标并要求选择独立目标或继续原配置，不做自动合并。

承接书库路径与材料身份、Provider 配置、本机依赖配置、memory 内笔记/会话/学习状态、private 产物以及 personal-note-drafts.json 内未提交草稿和放置进度。外部书库继续引用原位置；不将 debug-session.json 中的旧端口或 PID 作为新进程状态。模型配置转换复用 MP1。

先从副本启动并确认读取、恢复和保存，再记录承接完成；失败保留来源和现有目标，重试不重复导入同一批记录。已有云服务客户端的数据、登录与云副本不自动进入本地身份，两个应用可以并存。导入仅支持本项目真实旧格式与现有升级规则。

### 6.2 云端模块拆分与部署升级

新云宿主在生产数据的独立副本上验证账号/会话、资料授权、book/publication 身份、工作区与课程实例、run/chat/草稿/学习证据、画板与产物、套餐权益期、额度预占及待核对费用。沿原数据库迁移和持久化流程升级，不因代码搬迁重新创建用户、发布或学习实例。

发布按现有暂停接单/处理在途运行、备份、切换及恢复流程执行；持久任务保留真实终态或可恢复状态，用户不会因重启被重复扣费或重复创建课程任务。静态资源考虑已打开页面的原版本请求。回退需依据数据格式兼容性执行，不能只换旧二进制或用旧快照覆盖上线后新增记录。复用[整体发布记录](performance/all-pending-release-20261116/README.md)中的实际准备和副本启动方式。
