## 2 正文排版与阅读偏好

初始默认采用“书页宋体”，保留“清晰黑体”一键切换。中文字体候选为 Noto Serif SC / Noto Sans SC 或对应思源家族；RE1 确定实际资源、字重与字形覆盖，并记录来源、许可、版本及产物大小。字体随应用提供，正式页面不依赖第三方字体站点。

| 参数 | 中文正文起点 | 英文正文起点 | 调整规则 |
| --- | --- | --- | --- |
| 字号 | 19px | 18px | 用户可选 17–22px；界面显示实际选值 |
| 行高 | 1.85 | 1.70 | 可调 1.60–2.00，中文优先试 1.80–1.90 |
| 标准版心 | 约 36 个全角字宽 | 约 68 个拉丁字符宽 | 窄/标准/宽预设分别为 32/36/38 与 60/68/75；实际按字体测量并受容器限制 |
| 字距 | 0.015em | normal | 中文可调 0–0.04em；中英混排中的拉丁字串保持自然字距 |
| 段距 | 1.2em | 1.15em | 随正文字号变化，标题段距另定 |
| 章/节标题 | 32px / 24px 起 | 与正文字体配套 | 中文标题明确字体，窄屏允许自然缩小与换行 |
| 正文边距 | 桌面约 36–56px，手机约 20px | 同左 | 空间不足时先收敛辅助区域，保留可读字号 |

这些是版心上限与试读值，不要求窄屏仍容纳桌面字数。语言模式优先使用已有明确的文档语言，缺失或混排时允许用户选择中文/混排或英文排版；默认中文/混排。此选择与字体选择一起属于本设备偏好，不向正文插入空格、换行或零宽字符。CSS 的 `ch` 不能被当成汉字宽度。

界面字体保持清晰 sans。正文变量作用于 `.prose` 的文字、标题和对应的来源阅读内容；聊天/笔记文字使用适合辅助阅读的独立层级。代码使用等宽字体，数学沿 KaTeX 自身排版，PDF 文字层保留原属性。图片、宽表格、长代码继续使用既有展开或局部滚动能力。

拟议偏好形状：

```ts
type ReaderTypographyPreferences = {
  font: "serif" | "sans";
  languageMode: "cjk-mixed" | "latin";
  fontSizePx: number;
  lineHeight: number;
  cjkLetterSpacingEm: number;
  measure: "narrow" | "standard" | "wide";
};
```

“书页”“技术”“紧凑”是赋值预设，用户修改任一值后即按实际参数显示。预设不另存一份可能与实际值冲突的状态。字体与语言模式可分别选择；专注/对照继续使用既有 `DisplayPreference`，不混入排版对象。

偏好对象只保存显示参数；存储入口从 MU8 的当前用户上下文取得命名空间，不接受排版面板自行指定用户。设备侧偏好的读取、退出清理与现场切换接点按 [MU / RE 集成边界](#51-mu-与-re-的并行与集成边界)统一接入。

文字调整后仍需完整显示并可操作；[WCAG 文字间距说明](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)用于验证用户覆盖样式后是否裁切，不作为默认字距的规定。版心的语言区分参考 [W3C 视觉呈现说明](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html)。

## 3 正文批注与来源对应

默认正文显示已有高亮和轻量批注标记；同一落点有多条记录时展示数量，点击后按记录区分。标记使用现有已验证范围或正文放置位置，完整列表由 Notes 提供。临时定位强调与用户保存的 Highlight 在样式和生命周期上分开。

```text
正文标记 -> 锚定预览 -> 关闭 -> 原句
                    -> 编辑 -> 既有 noteEditor -> 原 memory 命令
                    -> 在笔记中查看 -> 既有 Notes 中的同一记录
                    -> 查看来源 -> 既有来源定位 + 阅读返回点
```

桌面优先在原句侧边可用空白中展开；窄屏使用可关闭的底部阅读面板，原句附近保留选中标记。首版只展开一个批注预览，显示来源摘要与对应标记。预览占覆盖层、不插入正文流；长内容在预览内滚动或进入 Notes，不能遮住关闭和编辑入口。

原句滚出当前可见区或被缓冲回收时收起只读预览；重新查看可通过正文标记或 Notes。编辑发生在既有编辑器，同一现场内预览收起不丢未保存编辑；退出、换用户及切换现场沿 MU8 的清理与生命周期合同。编辑/重锚导致 `mem_id` 改变后，按命令结果与最新记录刷新；不能把旧 ID 保留为另一份笔记身份。请求继续由 MU 的客户端绑定原用户与材料，旧现场的晚到结果不得更新新现场的标记、预览或编辑器。

选择相关操作使用紧凑工具条或固定可达入口，不在段落之间插入展开操作行。点击动作时先冻结选区；批注标记、预览、工具条与编辑控件均排除在正文选择及 Note 放置命中之外。鼠标、键盘、触屏都能打开、操作和关闭，关闭后将焦点交还仍然存在的触发入口。

既有 Note 来源失效、placement 表面不匹配时继续遵循原规则只在 Notes 展示，不借重新设计把记录投到相似段落。PDF 已有行内标记沿用原投影，RE3 不复制一套 PDF 标记。

## 4 读位连续性与动效

排版变化的恢复链路：

```text
捕获 MU 用户 / workspace / generation / 材料绑定 + 本地恢复代次
  -> 捕获 LID + 可验证段内位置 + 相对视口偏移
  -> 更新排版参数
  -> 等待本次字体与布局稳定
  -> 原 MU 上下文与本地恢复代次均仍有效时恢复同一位置
  -> 恢复可见位置采样
```

长段内读位需要规范正文的 UTF-16 位置或可确定还原的等价信息；短段可复用现有 LID 与 top。公式、图片和无法取得精确文本映射的对象保留可验证的对象/段落位置。沿既有 DOM/source map 和恢复 generation 实现，最终坐标允许一行以内的偏移。目标在缓冲外时沿现有加载路径恢复；字体到达后的补偿不得覆盖新的滚动、切书或显式导航。

MU 的 workspace generation 表示阅读现场是否仍有效，RE 的本地恢复代次用于取消被后续操作取代的重排任务，两者分别保留。材料绑定消费 MU3 的 PublishedBookRef；恢复不能只比较 `book_id + chat_id`。退出、换用户、workspace 替换或其 generation 变化时丢弃旧恢复与返回点；同一现场中的来源往返继续保存原消息上下文。字号或专注呈现变化本身不创建 workspace、不推进其 generation，也不重新执行登录或多窗口 bootstrap。

冻结引用不因重排重新推断范围。用户正在拖动原生选择或使用输入法时，延后会打断交互的布局过渡；后台字体就绪也遵守同一交互保护。显示调整只恢复原读位，不通过连续 `goto` 制造新的阅读意图。

| 动作 | 初始时长 | 过渡与反馈 |
| --- | --- | --- |
| 按钮/选择反馈 | 120ms，调优范围 100–140ms | 颜色与轻微按压反馈，业务动作立即响应 |
| 批注/来源预览 | 180ms，调优范围 160–220ms | 小幅位移与透明度，保留触发位置关系 |
| 目录/工作区展开 | 240ms，调优范围 220–280ms | 保持同一实例，稳定正文版心与读位 |
| 章节/标签切换 | 160–220ms | 当前标记连续移动，内容就绪后短过渡 |
| 来源到达强调 | 约 900ms | 目标短暂突出后回到原有高亮状态 |

同类操作共享缓动；入场快响应、平稳结束，退出可更短。原生滚动直接跟随输入；远距离来源定位沿既有目标落点执行，到达后强调目标。需要返回的来源入口先保存已有阅读返回点，返回恢复原区域、消息上下文与读位。

不逐帧改变正文字号/字距/版心来制造持续换行。面板过渡与最终排布衔接，正文最多进行必要的重排及锚点恢复。拖拽分栏直接跟手，结束时保持读位。浏览器的减少动态效果偏好下禁用位移、缩放和动画滚动，保留静态状态反馈；运行/加载状态仍有明确文字。

## 5.1 MU 与 RE 的并行与集成边界

本节记录与 [MU 切片方案](切片方案-Linux原生多人阅读与无Redis首版.md#82-与-re-阅读体验切片的并行边界)的交叉合同。MU 负责身份、私人状态、阅读现场与请求归属，RE 在这些边界内改善显示与交互。MU 的实施进度以 MU 方案为准；本节不另维护一份进度。

| 交叉点 | 涉及切片 | 冲突与约定 | 并行条件 |
| --- | --- | --- | --- |
| 正文字体与局部样式 | RE1 / MU 后续前端改动 | 字体静态资源与正文样式由 RE 实施，样式限于相应阅读表面；共用样式文件的同一片段依序合入 | RE1 可先行，不依赖 MU 全部完成 |
| 偏好存储与退出清理 | RE2 / MU4、MU8 | 采用“本设备＋当前用户”命名空间；MU 提供身份及清理入口，RE 提供参数与面板，账号切换时不继承上一用户的显示状态 | 参数与面板可独立准备；用户偏好集成等 MU 的身份及客户端入口可用 |
| 重排读位与来源返回 | RE2、RE4 / MU3、MU5、MU8 | 同时绑定用户、workspace、workspace generation、PublishedBookRef 与本地恢复代次；RE 补段内位置，MU 维护现场归属和检查点语义 | 捕获/恢复算法可先验证；完整链路与 MU8 在同一入口集成 |
| 批注、编辑与晚到结果 | RE3 / MU4、MU5、MU8 | RE 复用已有 Memory 命令与编辑器；MU 保持请求归属及响应过滤，切换后不把原用户/材料的结果画到新页面 | 标记与预览可先做组件验证；业务接入消费 MU 客户端 |

**共同文件的修改归属**：

| 接点 | 修改归属与交接 |
| --- | --- |
| `api.ts`；`App.vue` 的身份、请求和清理入口；Run 恢复模块 | MU 维护权威入口；RE 从入口消费当前用户、现场和材料，不另建身份或请求封装 |
| `App.vue`、`ReaderWorkspace.vue`、`useReadingContinuity.ts` 的共同生命周期 | 每次集成由同一个执行者合入相关片段；先保留 MU 的作用域与失效语义，再接 RE 的面板、锚点和过渡 |
| `ReaderPane.vue`、`NoteCard.vue`、`RightRail.vue`、正文样式及字体 | RE 负责显示、选择排除与按需预览；涉及 MU 请求、编辑器归属或清理的片段交给上述共同入口集成 |
| `reader-surface.ts`、PDF 与来源组件 | MU 负责用户命名空间、材料寻址及失效入口；RE 负责几何、工具层次和反馈，共同片段依序修改 |

开工时记录所接入的 MU 接口、当前切片和共享文件修改范围。同一片段不同时由两条线改写；独立目录若用于并行，必须带入所依赖的未提交 MU 成果，不能仅从旧 HEAD 开始后覆盖当前工作树。各自只更新本线的进度与交接记录，共同合同同步到两份方案。

**共同验收场景**：在纳入对应 RE 切片的候选版本上，复用 MU8 / MU10 用例补入以下操作；发生失败时修正其归属或恢复路径，不另建第二套上下文。

- A 调整字体并打开批注，退出后 B 在同一浏览器打开同一本书：读取 B 的偏好或默认值；A 的预览、编辑内容和晚到结果不出现。纳入 MU 的 T26。
- 同一用户两个窗口分别读 X / Y，在其中一个窗口调整排版并执行来源往返：另一个窗口不切书、不跳读位。显示偏好即使被另一窗口读取，也只能在各自现场恢复各自读位。
- 字体尚未加载完时切换 workspace、更新其 generation 或执行新导航：旧重排任务与旧返回点按各自失效条件取消，不能拉回旧位置。
- PDF 或来源仍在加载时切书或换用户：旧资源、标记和预览不附着到新现场；当前画布、文字层、选区与标注继续对齐。

上述场景随受影响切片验证；冻结同一候选版本后复用通过记录，后续只重跑被新增改动触及的场景。MU 原有发布检查仍按其方案执行。
