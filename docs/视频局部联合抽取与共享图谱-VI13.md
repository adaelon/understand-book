# 局部联合抽取与共享知识图谱（VI13）

## 合同与接纳

Rust `GraphNode` 新增可选 `GraphIdentity::VideoObject { meaning }` 和带支持角色的 `evidence`；`GraphEdge` 同样保留来源。来源复用 VI1 的 `EvidenceTarget`：文本固定转写范围，视觉固定实际 PTS，联合成员分别记录所支持的信息。旧文本 JSON 不需要新增字段，原 Pass1/Pass2 文本合同保持。

`prepareVideoGraph` 从一个实际发布选择 VU 和转写段，冻结至多 60 秒的材料、原生 PNG、当前图谱对象与输入发布。单个任务至多八图，遵循 VI4 图片及传输预算；文本、视觉和联合工作单元使用同一接纳入口。输入目录保存在 `.build/video-graph/<batch>/input.json`，恢复读取冻结字节。

模型提交局部节点 ID、对象含义、可选同对象确认，以及带角色的已交付段 ID/图片 ID。Engine 将这些 ID 转为真实来源；错输入、未交付来源、空角色、缺失关系端点和模态不符在写入前拒绝。`joint` 必须同时有语言和画面支持，纯视觉节点的 `occurrences=[]`、`source_lid=null`。

## §1 对象身份与来源

**决策**：视频对象独立定身份，显式确认才合并。

**否决**：
- 用名称生成视频对象 ID：同名变量在不同例子里会误合并。
- 以附近转写作为视觉锚点：无法表达纯视觉信息与各模态支持角色。

**命门**：新节点为 `video:<batch>:<local_id>`。`same_as` 必须引用输入中的已有对象，给出确认理由并提供本次来源；视频对象还须保持原含义和类型。已有 Pass1 文本对象可通过同一显式确认补入媒体来源，保留原 ID 和锚点。
**展开**：[视频方案 VI13](切片方案-视频理解与渐进伴读.md#vi13-局部联合抽取与共享知识图谱)、[联合证据术语](../CONTEXT.md#联合证据集合joint-evidence-set)。

`mergeAndGate` 对媒体来源先接纳再合并；纯视觉对象凭有效来源存活，重复对象和关系累积支持来源。没有来源校验入口的普通调用不会放行媒体候选。图谱仍是一套 `GraphNode/GraphEdge`，原文本路径继续通过回归。

## 执行、发布与读取

`已发布 VU / 转写 → 冻结有界输入 → executor.open → input.next（原生图片）→ generation.start → submit_candidate → 来源接纳 / mergeAndGate → VI9 不可变批次 → 累积发布 → Book::load → book.concept → book.text / video.read_frames → 观察 → source.present`。

四工具执行器沿 VI4 输入分块、最后一批确认、图片通道和候选传输。成功批次保存 `video-enrichments/<batch>/graph.json` 及实际 PNG；缺少依赖不能发布。已接纳批次不可覆盖，恢复跳过完成的模型任务；同源新发布累积其他生产者的贡献。

`Book::load` 校验材料、转写范围、输入发布、帧依赖和关系端点，将贡献并入普通图谱。`book.concept` 在原候选结构中增加 `video_graph`，包含对象含义、来源、相邻对象/关系及 `video.read_frames` 提示。名称与对象含义都可参与召回，同名候选分别返回。文字来源通过 `book.text` 回读；画面须经过 VI5 主模型成功请求才成为本轮观察。

输入发布保存在抽取来源中；同源 Run 的精读使用该 Run 固定发布，实际引用保存其观察发布。旧发布不被修改。检索和已接纳图谱支持本身不授予观察资格。

## 操作与复现

```powershell
node --import tsx skills/build/video-graph.ts prepare <工作区> <批次ID> <选择JSON>
node --import tsx skills/build/video-graph.ts run <工作区> <批次ID> <Codex可执行文件> [publish_book可执行文件 独立服务根]
```

选择 JSON 为 `{ "vu_ids": [...], "segment_ids": [...] }`；任一列表可空，两者不可同时空。语义工作单元由调用方按问题/材料选择。原片生产入口：`node --import tsx evals/video/vi13-run.ts <Codex可执行文件>`；回读验收入口：`node evals/video/vi13-verify.mjs`。

本机 Rust 构建使用 `D:\codex-build\understand-book-vi12`，debug=0、incremental=0，临时目录为同级 `understand-book-vi12-tmp`。验证器接受 `VI13_GRAPH_EXE`、`VI13_FRAME_EXE`，默认读取 `CARGO_TARGET_DIR/debug/examples/` 中的 `video_graph`、`video_frames_probe`。

## 验收与成本

2026-10-10，四个真实 Codex 工作单元分别处理 einsum 联合输入、bfloat16 纯画面、后续纯语言及补图确认，共 7 张原生图片交付。最终图谱 17 节点、17 关系；补图后显式确认 x、y、einsum、z 四个原有对象。矩阵与浮点例子的 x 保持不同身份，纯语言阶段的未确认对象也保持独立。

V04 的转写支持 hidden 求和规则，画面支持 `(3,4)`、`(4,3)`、输出标签和 3×3 全 4 结果。四段原英文通过 `book.text` 回读；图谱提示驱动五次 VI5 帧读取，实际 PTS 为 1196000、1210000、1211000、648000、652000 ms。每张 PNG 实际进入请求，并与构建来源解码后逐像素一致；检索阶段不创建观察。两个关键原图与支持角色一致。

新 publication `01a1259f-e01c-75c1-b3b8-1860a67888cf`，Book 仍为 `19ac880d-a788-43f4-9725-6c56f4980189`。复用 VI11 工作区和独立书库，输入 publication `01a12543-5248-76d0-9d6c-71a133a14357` 保持可读。规范正文、原 `base.json`、时间映射和 720 段中文逐字节保持，图谱通过贡献装载加入读取视图。

四次模型运行累计 286,960 ms；输入 528,194 tokens（缓存 414,208）、输出 15,393。模型使用 CLI 默认配置，金额未返回。本轮一次新发布物化 252,139,905 字节，用时 4,644 ms；重跑完成任务跳过模型，复用未变发布。凭据：[verification.json](../evals/video/results/vi13-20261010/verification.json)、[tests.json](../evals/video/results/vi13-20261010/tests.json)、[原材料核对](../evals/video/results/vi13-20261010/semantic-review.json)。

定向回归：Core 57，Rust Schema 54（含绑定导出）、Read-tools 12、Runtime 视频/注册/曝光 51、Book 工具合同 10、Server 发布 6，共 190 个不重复 runner 用例通过。Core 类型检查及服务/发布器/回读示例构建通过。

## 已知限制

- 图谱生产按指定工作单元推进；本轮覆盖 648–653 秒、1180–1238.46 秒。全讲生产与最终验收沿 VI18。
- 同对象确认由模型提出，确定性门检查身份、来源与结构；语义正确性仍需原材料核对。纯语言无法确认形状或对象身份时可以保留独立候选；后续工作单元可以显式复用已有对象，既有不同 ID 不会追溯自动合并。
- 本刀实现局部抽取。既有 Pass2 跨文本窗口链接器保留文本工作单元语义；视频讲解结构由 VI14 处理。
- 读时真模型、DSH、Linux 和安装态沿既有待办。构建验收使用真实 Codex 模型；读时 HTTP 记录器验证传输、来源和观察，不生成语义回答。安装态需要重建 sidecar。
