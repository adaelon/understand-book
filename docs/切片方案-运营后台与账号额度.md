## 2 身份与在线管理

管理员沿用现有账号登录。首版增加一个服务端管理员标记，以 `Principal` 对应用户的当前记录判定；首个管理员通过持有既有写锁的离线工具初始化。`GET /api/auth/me` 保留已有 `user_id`、`csrf_token` 与演示能力，新增布尔字段 `capabilities.admin`；每次管理请求仍读取服务端当前管理员身份。

网络 Reader 在服务端返回管理能力后显示“运营后台”，在新标签页打开 `/admin/`，保留原阅读标签页的现场与草稿。后台可直接访问，无需先打开材料；未登录时在后台登录页输入现有用户名和密码，调用现有登录接口。

管理请求路径固定为 `/api/admin/...`。管理员是操作人，路径中的读者是操作对象，两者不可互换。认证与现有写请求校验通过后，管理分支读取目标账号；普通 `/api/...` 的 owner、路径和现场过滤保持原合同。管理 API 不建立目标读者的阅读现场，不借用其登录 Cookie。

在线支持创建账号、改密、启停账号、撤销登录会话、授予和撤销已发布材料。创建与改密复用 Argon2 密码处理，密码不进入运营记录。材料管理只接收已登记的 `PublishedBookRef`。

停用时撤销登录会话并复用现有取消入口处理该读者的排队和活动运行；已发生费用继续核算，保存与恢复使用既有私人权威写入口。重新启用不恢复旧 Cookie，也不自动重跑任务。普通读者不能获得管理接口、费率配置或其他账号的费用明细。

## 3 额度与收款合同

金额使用整数保存：收款为人民币分；模型成本和额度为百万分之一人民币元（`micro_cny`），界面格式化显示。乘除采用明确的定点舍入规则：各计费项先累加，单次发送最终成本向上取整到 `micro_cny`；不用二进制浮点做余额运算。

一个账号同一时刻只有一个有效额度期，范围为 `[starts_at, expires_at)`，使用服务器时间判定。期内追加额度沿用本期；修改有效期是显式管理操作，显示修改后本期全部余额的到期时间。新一期独立记账，旧期未用额度不自动结转；确需补偿时人工赠送并注明原因。仍在核算的旧调用始终结算到原期。

最小数据合同如下，字段为拟实施名称：

```text
AllowancePeriod = { period_id, user_id, starts_at, expires_at, closed_at?, revision }
AllowanceAdjustment = { operation_id, period_id, delta_micro_cny, reason, receipt_id?, actor, created_at }
ManualReceipt = { receipt_id, operation_id, user_id, amount_fen, paid_at, external_ref?, note, actor }
ModelCallCharge = { call_id, logical_call_id, attempt, user_id, period_id, run_ref?, task_ref?,
                    purpose, model, rate_snapshot, state, reserved_micro_cny,
                    provider_usage?, provider_cost_micro_cny?, provider_cost_status,
                    account_debit_micro_cny?, evidence_kind, created_at, settled_at? }
available(period) = granted_and_adjusted - account_debits - active_or_pending_reservations
```

`run_ref` 关联现有 `turn_id`；读者触发的后台模型任务使用稳定 `task_ref`。费用记录只保存归属、计价与用量元数据，完整提问和答案继续归私人历史。

登记付款时，付款记录与本次授予额度在同一事务中成功或失败；赠送单独记录，不伪造付款。付款金额与额度金额分别输入，默认不做一比一换算。金额更正使用带原因的追加调整，保留原记录和关联；撤销收款登记表示账面更正，不声称已向用户完成外部退款。

每次管理提交使用稳定 `operation_id`；同身份、同操作号及同规范化业务参数重复提交返回原回执，参数不同返回冲突。直接比较保存的业务字段。界面超时后保留操作号，先取原回执再决定后续操作；重新点击不能重复加额度。有外部交易编号时，对该渠道的同一编号拒绝重复登记。

下调额度只能减少尚未被已结算和在途占用覆盖的部分。运营补偿和调用费用更正分别表达；费用记录已确认金额的修正要保留旧值、依据和差额，不能通过修改付款金额掩盖成本变化。

## 4 调用预占与结算

所有由该账号触发的托管模型发送都进入同一个费用入口：主对话的每轮采样、内部结构化判断、压缩、画像或教学相关后台请求、使用模型的呈现制作与图片观察。是否实际可达以 ADM4 的调用入口清单为准；每个可达入口须落实账号与触发任务归属。已有共享书籍的离线预构建属于运营准备成本，单独标识，不摊派给打开这本书的读者。

保留 `LimitedAdapter` 的公平并发、取消和材料授权。费用边界通过一个小的运行时端口接入实际发送处：Server 持有身份、数据库和预算，Runtime 在发送前请求许可并报告结束事实。Runtime 不依赖服务数据库，不自行从请求正文猜用户。已安装费用端口的多人请求不能绕过它直接发送。

```text
before_send(scope, logical_call_id, attempt, request_cost_input) -> reservation | SpendStop
after_send(call_id, provider_usage?, send_evidence, rate_snapshot) -> settlement | pending

调用获得模型槽
  -> 检查取消、账号与材料权限
  -> 按最终请求及适用费率计算预占
  -> 短事务：检查有效额度期、可用额；创建 reserved
  -> 短事务：标记 sent；提交成功后发送 HTTP
  -> 收集该次发送的用量快照
  -> 短事务：结算或保留 pending；释放可释放的预占
  -> 释放模型槽；继续既有工具调度与回答保存
```

费用持久化失败时，尚未发送的请求不发送；已经发送的请求保留已提交的占用并停止后续发送，由恢复流程核对。任何数据库事务或用户短锁都不跨越模型网络等待。运行中新增的费用状态与聊天历史使用关联身份，不要求跨存储长事务。

**费率与计价。** 首版由运营者配置已验证 Provider/模型的计费项及人民币折算，按适用时间选择费率版本；高峰与低谷等现网适用时段必须参与选择。调用发送时固定版本和折算依据，历史不随后续调价改变。原始费率币种、折算率、查询日期及官方来源随配置保留。官方计价入口：[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)。文档不固定当前售价。

按 Provider 合同归一化输入、缓存命中、输出等计费项。普通输入和缓存输入不能重复加；推理输出是当前 `ModelUsage.output_tokens` 的子集。仅有 total、缺少必要计价细分或不支持的计费项时，记录未知并待核算。只有该 Provider 明确规定的缺省零值才能归零。费用回执标记为供应商用量折算或人工账单核对，不能称为已核对的供应商最终扣款。

**预占估算。** 输入包含最终消息、工具描述和实际媒体计量，缓存按未命中成本预留，输出按本次实际输出上限预留。图片观察等路径必须采用该 Provider 对应的计量规则，不能把图片说明文字当图片成本。没有费率或没有可解释估价方式的调用在发送前返回配置原因。ADM4 记录估算与真实用量差异，ADM10 据此配置首批额度；不通过缩短本次输出上限来适配余额。

现有字符估计只适用于准入估算，不能证明严格费用上界。实际结算超出预占时完整记录差额，允许该期余额显示欠额并拒绝下一次发送，由运营者补充额度或核对；账面不能截断费用到预占值。产品提示表达“后续调用受额度限制”，不承诺供应商侧绝对零超额。

**每次发送与重试。** 现有一次自动网络重试的次数规则保留；每次重试使用新的 `call_id`，共享 `logical_call_id`，重新检查权限、取消及额度。前一次若明确未发送且未计费，可释放预占；若发送情况未知，则保留待核算占用。重试余额不足时停止重试并交付明确原因。最后一条有效 Usage 快照覆盖前面的累计帧，不能将这些帧相加，也不能把第二次发送的用量填到第一次。

**结算状态。**

```text
reserved -> sent -> settled
reserved -> released                       // 明确没有发送
sent -> released                           // 有可靠的未发送/未计费依据
sent -> pending -> settled | released       // 缺失必要用量或发送结果不明
```

`settled` 与 `released` 终态提交一次；迟到的同一完整回执返回原结果，冲突回执转人工核对。重复终态不得再次扣费。收到完整回执后即持久化结算，不等待整个 Agent Run 完成。调用返回错误但已有可用计费用量时仍结算，错误不能抹除已发生费用。

正常结算时账号扣减与本次折算成本相等。人工核对支持填写有依据的实际成本，或确认无需向该读者扣费并释放占用；后者只令账号扣减为零，若供应商成本仍未知，`provider_cost_status` 保持 pending，在运营待核对项中继续显示，不能写成供应商成本为零。人工操作保留操作者、原因、依据和时间。

## 5 停止恢复与读者体验

费用不足、额度过期、计价配置不全和费用存储不可用使用明确的受控原因。Runtime 的外层采样、内部判断、压缩与呈现路径识别这类停止，不把它当成模型可纠正的普通错误而反复采样。停止原因通过类型化状态传给宿主，不能靠自由文本包含某个词来判断。

读者看到“本期额度不足，本次已完成内容已保存”或对应真实原因，并能查看剩余额度、正在使用的预留和待核算金额。未保存时沿用已有 `TURN_UNSAVED` 等持久化状态，不能显示“已保存”。业务交付尚未完成的 Goal 保持未完成，额度停止不等于学习任务成功。

已产生的引用、笔记、演示与阅读位置按既有保存合同处理。费用不足和额度过期只阻止新的付费调用；账号和材料权限仍有效时，读者可打开历史、原文和已有成果。账号停用与材料撤权继续沿用原有授权限制。

补充额度后由读者点击继续，复用既有 Goal/聊天继续入口创建新的 Run 并取得新调用身份，依据当前保存状态推进。客户端不重发旧的已领取请求，服务也不自动恢复一次不明执行；已发生的工具效果不能为恢复费用状态而重放。

服务启动时先核对费用状态：

- 只有 `reserved` 且发送前持久标记尚未提交的记录可以按未发送释放。
- 遗留 `sent` 或不完整结算进入待核算；保留预占和原额度期。
- 已确认的费用保留，即使对应回答保存失败、聊天后来被删除或账号停用。
- 只读恢复状态不能触发供应商请求；晚到回执按原调用身份处理。

## 6 持久化与接口

沿用现有 `control.sqlite`，新增运营角色、额度期、授予/调整、人工收款、调用费用和管理操作回执。已有各模块继续持有同一 `ServiceWriter` 下的连接，余额检查和预占使用同一 SQLite 写事务。以账号、额度期、创建时间和调用身份建立直接查询所需索引。

`crates/server/src/admin_api.rs`、`admin_store.rs` 承接在线管理，`account_allowance.rs` 持有金额类型；数据结构由 `control_store.rs` 的既有版本升级安装。管理员标记加入已有用户记录；旧账号迁入后默认为普通读者，费用相关新表为空。

接口约定如下，均经过既有认证；金额字段注明单位。管理操作的目标账号置于明确路径段，权限由操作人的 Principal 判定。

| 接口 | 行为 |
| --- | --- |
| `GET /api/auth/me`（扩展已有接口） | 返回当前身份、CSRF 和 `capabilities.admin`；保留原有能力字段 |
| `GET /api/admin/users`、`GET /api/admin/users/{id}` | 账号列表、材料权限、当前额度和运营摘要 |
| `POST /api/admin/users` | 创建普通读者账号 |
| `POST /api/admin/users/{id}/password`、`.../status`、`.../revoke-sessions` | 改密、启停和撤销会话 |
| `POST /api/admin/users/{id}/book-grants`、`.../book-revocations` | 管理已发布材料权限 |
| `POST /api/admin/users/{id}/allowance-periods` | 建立有明确起止时间的一期额度 |
| `POST /api/admin/users/{id}/allowance-adjustments`、`.../allowance-validity` | 赠送/调整，以及显式修改有效期 |
| `POST /api/admin/users/{id}/receipts` | 同事务登记收款与额度授予 |
| `POST /api/admin/charges/{call_id}/reconcile` | 核算或更正未知费用，保留依据 |
| `GET /api/admin/operations/{operation_id}` | 查询管理提交的原回执 |
| `GET /api/admin/usage`、`GET /api/admin/charges` | 聚合成本和分页费用明细 |
| `GET /api/account/allowance`、`GET /api/account/usage` | 当前登录读者自己的额度和分页用量 |

用户入口不接受目标账号参数。管理写入使用操作号；额度期的编辑携带当前 revision，防止两个管理标签页覆盖对方修改；原操作重复返回回执优先于 revision 冲突。列表使用有界分页，默认 50 条，对首批读者足够。

**ADM2 已实现的请求合同。** 管理请求使用 `/api/admin/` 前缀；GET 账号列表和详情、已发布材料目录 `/api/admin/books` 接受 `limit=1..100`（默认 50）和 `offset>=0`（默认 0）。详情的 `book_grants` 为 `{items,total,limit,offset}`；列表为 `{users,total,limit,offset}`，材料目录为 `{books,total,limit,offset}`。账号投影为 `user_id/disabled/is_admin`，材料目录返回确切 `published_book_ref` 和 `is_default`，不暴露磁盘目录。ADM3 已在详情增加 current_allowance 与余额分列；运营汇总随 ADM9 实施。

```text
POST /api/admin/users
{"operation_id":"create-reader-001","user_id":"reader_001","password":"<12–1024 字节密码>"}
POST /api/admin/users/reader_001/password
{"operation_id":"password-reader-001","password":"<新密码>"}
POST /api/admin/users/reader_001/status
{"operation_id":"disable-reader-001","disabled":true}
POST /api/admin/users/reader_001/revoke-sessions
{"operation_id":"revoke-reader-001"}
POST /api/admin/users/reader_001/book-grants
{"operation_id":"grant-reader-001","published_book_ref":{"book_id":"book","publication_id":"publication"}}
```

`book-revocations` 使用与 `book-grants` 相同的字段。操作号为 1–128 字节 ASCII 字母、数字、`-` 或 `_`；写请求拒绝未知字段及查询参数，创建只能得到普通读者角色。成功返回 `{operation_id,actor,user_id,kind,parameters,created_at,ok}`；停用另有 `cancel_requested_runs`，表示已标记的任务数，不声称任务已经保存完成。`GET /api/admin/operations/{operation_id}` 只查询当前管理员提交的回执，找不到返回 404。

业务变更和 `admin_operations` 同事务提交；同操作人、操作号、目标、种类及规范化非凭证字段重复返回原回执，不同返回 `ADMIN_OPERATION_CONFLICT`（409）。创建和改密的密码不进入参数、回执或第二份凭证摘要；复用旧操作号只查询原成功事实，不再设置密码，提交新密码须使用新操作号。已有账号再次创建返回 `USER_ALREADY_EXISTS`（409），缺失目标或未登记发布返回 404。账号禁用后仍可管理其材料授权，实际阅读继续受账号启用状态限制。

停用事务同步撤销 Cookie、设置账号状态，并持久标记 `preparing/queued/claimed` 的取消请求；提交后通知活动 Run 的现有取消令牌。排队与重启恢复通过原 `end_pending`/JSONL 路径保存取消结果，保存失败保留既有 `unsaved` 状态。管理路径不加载目标读者私人状态或创建 ReaderWorkspace；重新启用不清除取消标记、不恢复 Cookie 或重跑任务。


**ADM3 已实现的额度/收款请求与 ADM4 发送合同**：见[实现合同](运营后台-ADM3-ADM4实现.md)，包括全部字段、错误码、分页、schema 6 升级、实际可达调用清单、费率配置与接入限制。

## 7 后台与读者界面

**应用与依赖边界。** `apps/admin` 是独立的 React + TypeScript + Vite 应用，复用 shadcn-admin 的导航、表格、表单、弹窗与主题，采用其 Tailwind CSS、shadcn/ui、TanStack Router / Query / Table。依赖在该 workspace 包内声明并进入仓库已有锁文件，Reader 的 Vue 与 CSS 保持独立。导入时裁掉无关示例页面、模拟用户与统计、模拟 Token 和 Clerk 登录集成；业务页面展示服务返回的事实。React 后台不导入 Vue 的 `network-context.ts`、`network-client.ts` 或 Reader 现场组件。

**登录与请求合同。** 后台建立小型独立请求模块，使用原生 `fetch` 调用同源 `/api/...`，沿用 Cookie、`credentials: same-origin`、`cache: no-store`、JSON 错误合同与写请求 `X-CSRF-Token`。登录字段沿用 `username/password`，成功后重新读取 `/api/auth/me`。Token 和管理员角色都来自现有服务。

```text
打开 /admin/... -> GET /api/auth/me
  -> 未登录：显示 /admin/login -> POST /api/auth/login -> 重新读取身份
  -> capabilities.admin = false：显示无管理权限与返回阅读入口
  -> capabilities.admin = true：加载管理路由及该身份的查询数据
管理写入 -> 既有 Cookie + CSRF + operation_id -> /api/admin/... -> 服务端授权与业务事务
```

身份响应只控制页面入口；服务端逐次执行管理授权。401 清除身份与管理缓存并显示登录；权限拒绝显示无权限；`CSRF_REJECTED` 刷新身份并提示重新确认操作，业务写入不自动重放。金额表单保留第 3 节的操作号与回执查询规则，TanStack 的写操作重试关闭。

后台沿用 Reader 的 `understand-book:authentication` 通知频道，在登录/退出后发送现有 `changed` 通知，接收通知及页面重新可见/聚焦时读取当前身份。身份、会话或管理能力变化时取消旧查询、清空相关缓存并丢弃旧响应，避免换账号后回填前一账号的数据。返回阅读复用现有 Reader 恢复入口；管理页面不创建或切换 ReaderWorkspace。个人额度请求仍由 Vue 的现有网络模块发起，随读者身份清理缓存。

**构建与站点路由合同。** 后台输出为 `apps/admin/dist`，Vite 资源基址为 `/admin/`，前端路由基路径为 `/admin`。开发代理沿用现有 `/api` 与后端约定；生产由现有 Nginx 提供两套静态资源，全部 API 仍交给 Rust 多人服务。

```text
packages/web/dist-multi/         <- Vue 网络 Reader 构建
packages/web/dist-multi/admin/   <- 随后复制 apps/admin/dist 的完整内容
/api/...                        -> 现有 Rust 多人服务 -> control.sqlite
```

多人构建脚本先生成 Reader，再构建并装配 Admin，全部产物成功后写现有构建收据，避免 Reader 清理输出目录时删除后台。Admin 的 CSS 与脚本只由后台 HTML 加载；桌面构建继续使用原有 Reader 入口。

| URL | 发布行为 |
| --- | --- |
| `/admin` | 跳转到 `/admin/` |
| `/admin/assets/...` | 从后台产物返回静态文件，缺失时返回 404 |
| `/admin/`、`/admin/login`、`/admin/users/{id}` 等页面 | 返回后台入口 HTML，支持直接访问与刷新 |
| `/api/admin/...`、`/api/auth/...` | 沿既有代理进入 Rust，保留 JSON 与认证状态码 |
| 现有 Reader 页面与 `/assets/...` | 沿用 Reader 的静态入口与资源 |

Nginx 的 `/admin/` 页面兜底固定到 `/admin/index.html`，缺失资源不能返回 HTML；两套资源按同一发布目录切换。后台 HTML 只包含界面代码，账号与费用数据经授权后的 API 加载。

**业务页面。** 首版后台为用户列表、用户详情和全站用量三个视图；前两个已由 ADM7b 接入，全站用量及活跃汇总已由 ADM9 接入。

| 视图 | 路径 | 内容与操作 |
| --- | --- | --- |
| 用户列表 | `/admin/users` | 账号、启停状态、有效期、可用额度、最近阅读/提问时间；创建账号与进入详情 |
| 用户详情 | `/admin/users/{id}` | 材料授权、赠送/追加额度、有效期、付款登记、费用与操作明细、改密及启停；处理待核算费用 |
| 全站用量 | `/admin/usage` | 今日及所选期间的已确认模型成本、账号扣减、在途预留、待核算占用及请求数、收款；按用户查看成本较高的任务 |

后台根路径进入用户列表。列表的搜索、筛选和分页参数交给管理 API；汇总金额由服务端提供，前端只做单位格式化。汇总尚未接入或缺少历史事实时显示对应缺失状态。收款表单并列显示“实际收款”和“授予 AI 使用额度”，提交后展示同一操作回执。赠送不要求填付款记录。费用核对显示调用时间、模型、计费项、估算来源、已有回执和处理结果；不展示完整聊天正文或服务端密钥。

**读者个人额度。** ADM8 在 `packages/web` 的 Vue 网络 Reader 中新增“使用额度”，显示“AI 使用额度（元）”、可用量、已用量、预留/待核算量和到期时间，并说明它与实际付款金额的关系。未知成本不能伪装成精确余额；表中“可用”已扣除尚未释放的未知请求预留，另显示占用的原因。费用不足时保留输入草稿并提供查看额度入口。

基础使用统计按真实事件定义：最近使用来自成功打开材料或提交有效提问；已完成任务来自保存成功且满足现有交付判定的 Run；回访指同一账号在不同本地自然日再次发生阅读或提问。日期展示与报表分日使用 Asia/Hong_Kong，底层保存 UTC。将这些最小运行元数据保存为可重建投影，不从 Token 数、登录次数或全部聊天正文推断学习成效。

## 9 迁入上线与验收

**旧数据接入。** 停接单、处理在途运行并按现有维护流程备份服务根。候选在副本上按既有 schema 顺序升级，再验证原账号、书库授权、私人历史和新表。选择现有或新建账号授予管理员身份，为现有参与模型调用的账号显式建立初始额度期；没有额度期的账号仍可登录和阅读，但不能发起托管付费模型请求。旧 Token 遥测保留，不追溯扣费，不伪造以前的收款和额度。

**费率与启用。** 费率配置仍属服务端运营配置，密钥沿用现有 Provider 配置。启动校验当前托管模型的费率和计量支持，错误时阅读服务可用、费用相关调用给出明确原因。首个管理员、默认材料、初始赠送额度、有效期及联系运营者的说明必须在发放账号前配置完成。

**双前端发布。** 沿用现有 Linux 构建脚本和 Nginx 模板，在同一最终 release 内生成 Rust、Vue Reader 与 React Admin 产物，并将 Admin 装配到 `packages/web/dist-multi/admin`。构建收据增加后台产物位置，发布前确认静态根与二进制指向同一 release，上游 MIT 声明随导入源码及发布包保留。候选环境按第 7 节验证 `/admin` 跳转、后台详情页刷新、资源 MIME/404、真实 Cookie/CSRF、API 状态码，以及 Reader 阅读与原有样式；再按既有流程验证并切换 Nginx 配置。

**回退。** 复用 [MU9 备份恢复](Linux多人阅读-MU9迁移恢复.md) 和 [现网运行说明](Linux多人阅读-现网运行说明.md)。新 schema 不交给旧二进制直接写入。尚未产生新业务时可恢复升级前快照；已发生新付款、用量或阅读写入后，先保存完整新库和私人状态，在维护状态处理前向修复或明确的数据接回，不能直接覆盖成旧余额。备份必须包含新费用事实、费率配置和未核算状态。
