# 对话理解与多人后台记忆

状态：2026-10-10，本地实现与定向验证完成；未部署。结果与扩展回归的已有问题见[验收记录](验收-对话理解与多人后台记忆.md)。

## 对齐确认

- FrozenIntent：在聊天起点展示学习目标入口，首个问题可直接成为起点；普通对话的理解分析不依赖手工创建教学会话；接通多人后台画像审核。
- TermMap：ProfileFact、ReviewJob、理解假设、会话学习意图沿用现有定义；TutorLoop 的主动教学仍受 TutorControl 控制，普通理解观察解除该门槛。
- RiskReceipt：用户在说明隐藏会话门槛及两条断链后明确回复“对，那开始改吧，把后台记忆也接通，改完先别上线”。后台分析沿用账号额度、私人数据归属与已有证据治理。
- ChangeType：边界调整；不增加新的画像或理解真相源。

## 实施步骤

1. [x] 多人后台 ReviewJob：在用户私有运行态领取持久任务，释放锁后经托管模型调用，回锁提交或记录失败；验收排队任务确实执行、失败可重试、账号隔离和费用路径。
2. [x] 普通对话理解：无主动教学会话时记录使用事实、提供受限理解分析上下文，允许有原文及事实依据的假设；验收 Tutor 关闭仍可记录理解，同时不能选择主动教学动作。
3. [x] 对话目标入口：空对话提示直接输入目标或问题，展示并允许管理已有学习目标，发送首问衔接教学；验收无需进入管理面板，关闭 Tutor 不被自动打开。
4. [x] 定向回归、前端类型检查、更新代码链路与架构；保留本地改动，不部署。

## 验证约束

每次测试针对明确失败：后台任务无人消费、持锁阻塞聊天、跨账号错误归属、开关关闭仍主动教学、首问未进入学习或重复发送、理解无事实依据。失败则修对应路径；不调用生产模型或修改生产数据。

## 实现接点

- `multi_user_host::start_with_access` 启动审核线程；`multi_user_review::remember_pending/tick` 跟踪新任务和重启积压，沿 `UserRegistry::load_for_review` 在容量内恢复用户。后台任务在用户卸载后仍留在恢复队列。
- `teaching::freeze_prepare/prepare_observation` 为普通对话提供观察上下文；`tutor.step` 允许带原文和对话事实的理解假设，主动教学仍检查会话状态。`LearningStore::append_evidence` 保留来源版本和表现证据的原活动边界。
- `ConversationLearningGoal` 在聊天中显示目标、调整目标及新目标入口；当前活动会话属于其他材料时，可直接为本书设定目标。`App::finishResidentRun` 刷新目标与理解界面。

## 已知限制

- 理解判断仍由当前对话模型按依据调用保存工具；没有另加每轮强制生成理解的后台模型。没有充分依据时可以不产生新记录。
- 本地测试使用临时数据和本机模型服务替身；尚未部署，也未调用生产模型或消费生产队列。
