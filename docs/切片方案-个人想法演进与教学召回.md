# 切片方案：个人想法演进与教学召回

日期：2026-10-30。对应 [ADR-0177](adr/0177-personal-notes-evolution-and-teaching-recall.md)。**PN1–PN6、服务端 MiniLM 与首页入口调整已于 11:50 HKT 合并上线；数据副本升级与公网验收通过。** 本文是后续实现、验收和进度更新的权威入口；[接入设计](设计方案-以个人想法为核心的笔记与学习.md)保留产品解释、场景和源码调查依据。

源码核对基点为 `bbf18a8c12bdf7b99ed402cc95195356f376d4e8` 的当前工作树，另有主 Agent、教学和画板等未提交修改。实施时按实际类型与符号定位，保留他人改动；本文引用的既有能力是工作树事实，不保证任意部署实例已经启用。ADR-0176 的上线状态沿其自身记录。

## 1. 目标、范围与交付边界

让用户在正在学习的地方随手留下真实想法，保存并回看其演进；当前问题能主动召回相关个人表达，主 Agent 据此改变支持；新的表达和修订又能参与以后学习。用户无需先建立资料、工作区或学习目标才能记录，也无需为了被召回而手工整理标签。

完整流程为：就地记录 → 可恢复草稿 → 稳定笔记与历次修订 → 讨论与针对性反馈 → 跨材料召回 → 新表达接续 → 个人联系与问题画板 → 用户自己的综合解释。各环节的保存、引用和失败后继续操作必须真实可用。

### 1.1 已确定的原则及其工程含义

| 原则 | 必须落实的行为 |
| --- | --- |
| 系统围绕人的想法 | 用户原话是个人表达的权威；资料、教学、笔记和画板围绕当前问题服务，当前明确请求优先 |
| 最低成本输出 | 正文可短、可疑问、可不完整；标题、分类、联系说明、材料及目标都不成为记录前置条件 |
| 就地表达、稍后整理 | 各入口复用同一编辑能力；收起、换资料与查看其他笔记保留草稿和原情境 |
| 同一想法多处使用 | 笔记身份稳定；阅读落点、画板位置和讨论引用分别持有引用，不能各自复制一份可编辑正文 |
| 看得见思想变化 | 保留每个已提交正文版本；可看原文、对照、打开相关讨论；恢复旧版追加新版本 |
| 需要时主动想起 | 普通提问自动触发有界个人召回，默认可跨该用户的材料；明确引用直接读取 |
| 召回影响教学 | 采用的笔记改变起点、例子、条件、练习或下一步，并留下对应版本引用 |
| 新表达改变后续接续 | 后续相关用户原话可在未改笔记时被读取；讨论、修订与系统理解判断保留不同身份 |
| 来源和事实可追溯 | 原话、原文摘录、AI 摘录及改写来源分开；查到、采纳或保存均不直接证明掌握 |
| 复用现有主线 | 同一 Resident/Goal、教练、LearningStore、私人存储和检索组件继续承担原职责 |

### 1.2 本轮决策范围

第一份教学可用增量为 PN1–PN3：记录、草稿、演进查看、带材料的通用笔记讨论、跨材料主动召回和教学采用全部接通。PN4 完成无材料讨论；PN5 完成自主联系；PN6 完成跨材料画板与综合表达。仅有输入框、搜索接口或字段不算完成。

现有决策已足够进入实现，没有待用户拍板的方向性事项。候选数量、分段预算与实际性能按本文初值和真实样例调优，属于工程验证，不再要求用户选择算法参数。若实现发现必须改变所有权、云端传输范围、额外付费服务或产品范围，再依据具体事实提出取舍。

新增语音/手写识别、未发送草稿跨设备同步、公共笔记发布、多人共同编辑、独立向量服务、全量自动知识图谱及专用作品导出不属于本计划。现有账号、材料权限、正式学生评估与部署流程继续生效。

## 3. 数据与所有权合同

### 3.1 个人笔记、版本与位置

下表是已经落实的逻辑合同，实际类型名称沿 Rust/生成 TypeScript 的现有方式确定。身份由宿主产生；调用方不通过指定用户目录或 owner 字段选择别人的数据。

| 对象 | 必要字段/关系 | 不变量 |
| --- | --- | --- |
| `PersonalNote` | note_id、created_at、current_revision、已保存修订 | 归当前用户存储；独立于材料和工作区存在；修改或移动不改变 note_id |
| `NoteRevision` | revision、saved_at、正文、可选标题、内容来源、保留摘录、明确资料引用；可选 change_note、based_on_turn、restored_from | 已提交版本不可覆盖；原话与素材分别保存；来源变化也属于内容变化 |
| `NoteRef` | note_id、可选 revision | 不带 revision 的日常引用解析当前版；运行接受、历史反馈和作品冻结确切版 |
| 记录情境 | 实际材料/发布、选区、章节、视频时刻、聊天回合或演示回执，可为空 | 说明产生在哪里；不凭情境推断观点来源或用户掌握 |
| 显示位置 | 宿主类型、位置数据、NoteRef | 正文批注与画板各管布局；移动不新增正文版，从宿主移除不删除笔记 |
| `NoteDraft` | draft_id、本人身份、可选 note_id/base_revision、正文、摘录、原情境、更新时间 | 当前设备持久保存；恢复后不改绑新材料；未提交内容不进入 AI 或搜索 |
| 讨论引用 | 原 session/turn、确切 NoteRef、真实回复目标 | 指明讨论哪一版；不等同正文修订或已经纠正 |
| `NoteLink` | link_id、两个 note_id、可选联系说明、建立时的确切版本 | 从两端可读；正文修订不丢联系；说明缺省时只表示用户建立了关联 |

同一应用内，同一笔记复用一份活动编辑草稿；跨浏览器页面或设备仍可能并发修改，通过 base_revision 处理，见 §4。草稿身份不要求工作区或材料。标题缺省时用首个非空句作显示摘要，不为记录一句话调用生成模型。

记录内容可以是纯摘录，但其身份是素材。既有作者未知记录保持中性身份。用户采用 AI 改写后保存新版本，并保留改写来源；系统不能把采用动作升级成独立掌握。

### 3.2 时间、修订和思想演进

首次成功保存形成初始版本；正式保存且正文、标题或内容来源发生变化时追加版本。相同内容的重复请求沿原操作回执处理；无内容变化的保存不增加历史。移动批注、拖动卡片、挂起草稿不新增正文版本。

每个版本保存当时完整可读内容，先用现有私人文档能力实现；版本差异按需从原文计算，不把差异补丁作为唯一正文。早期原话不由模型总结替代，版本更晚不表示观点更正确。

“思考过程”是修订、明确相关讨论和可选用户说明的组合视图。查看历史不会切换当前版。恢复 v2、当前为 v5 时，创建 v6，并记录 restored_from=v2；后续关系、显示位置和 v3–v5 的反馈保持。用户未改笔记但在讨论中补充了认识，则作为后续表达展示和读取。

恢复发生在未保存草稿上时，提供明确的“先保存当前修改，再恢复此版本”动作；第一步失败即停止。正常恢复也带 base_revision，防止另一个已打开页面的新保存被静默覆盖。版本对照与恢复不要求 AI 调用。

### 3.3 私人存储、索引与删除

正文与版本继续由 `MemoryStore → MemoryDocument` 唯一持有。新增 notes 与必要联系数据，沿原子提交、文档 revision 和错误返回工作；已有阅读行为、profile、LearningStore 等归属保持。

本机和账号云端仍是原有两个存储边界。正式 Windows 的 Agent 执行沿 ADR-0173；登录、自动召回或加入学习工作区都不自动上传本机笔记整库。用户主动向云端发起讨论时，仅沿该次发送范围提交所选表达及需要的上下文；云端持久化与本地整库迁入遵守原产品选择，不能偷偷形成两个可编辑权威。

派生索引放同一用户的私人根目录，不写 shared-cache/workspace-retrieval。索引键使用 note_id/revision 和片段位置；关联表达使用其已有表达/回合身份。删除笔记后，正文修订及其当前检索项、个人联系和旧导航映射退出笔记库；挂在宿主上的引用显示目标已删除。

旧对话、实际交付中已经保存的原话快照沿原历史保留，并标记笔记目标已删除；不能用这些历史快照重新制造当前笔记或让已删除笔记继续参加个人召回。画板不得为绕过删除而另存一份可编辑全文。删除笔记不声称同时删除所有旧聊天，聊天清理沿原功能。

### 3.4 旧记录接续

沿当前实际 schema 接续入口转换现存 note，生成稳定身份和初始修订，映射能够解析的 mem_id/note_replacements，保留材料、发布、选区、作者身份、原时间和摘录。重锚造成的旧身份继续导航到同一笔记；旧 id 无法确定当时正文版本时只能导航，不能伪装成历史版。

原记录接口中的笔记返回形状作为同一权威对象的投影。转换后所有保存/replace/reanchor 笔记分支写同一对象；不得同时维护一套 Record 正文和一套 PersonalNote 正文。非笔记 records、私人 profile/governance 等原数据保持。

转换成功后再发布新文档状态；写入失败继续保留原磁盘和内存状态。重开不重复生成初始版本。旧系统未保存的正文无法恢复。此处完成一次具体 schema 接续，不建立长期双写或泛化迁移平台。

## 4. 操作与失败合同

个人笔记命令放用户级入口，不要求当前 Book。路径命名沿现有路由风格；下表的操作及字段是必须落地的行为，服务端类型经既有 ts-rs 路径生成前端类型。

| 操作 | 关键输入 | 成功结果 |
| --- | --- | --- |
| create | 用户内容、可选标题/摘录/实际情境、原操作身份 | 稳定 note_id、初始 revision、真实保存时间；请求重试返回原结果 |
| read / list | note_id、可选 revision；列表范围与游标 | 当前或确切历史正文、来源和版本；列表有界，可读无材料笔记 |
| revise | note_id、base_revision、新内容、可选修改说明/讨论来源 | 追加修订或明确无变化；不更换 note_id |
| history / compare | note_id、版本范围/游标或两个确切 revision | 修订元数据与按需正文；对照不改变当前版 |
| restore | note_id、base_revision、目标历史 revision | 新修订及 restored_from，保留全部已有历史 |
| relocate / detach | 宿主实际位置、NoteRef | 改变该处显示位置/引用，不改变正文版本 |
| delete | note_id、原有用户操作上下文 | 删除笔记与当前索引关联；宿主引用显示已删除 |
| search | query、范围、limit | 有界候选、回读参数、实际词法/语义状态 |
| link / unlink | 两条笔记、可选联系说明及实际版本 | 双向可读的同一联系，移除不删除正文 |

正文为空且无保留摘录时不创建空笔记；有实际摘录的记录继续允许空用户正文。有效的无材料表达不能因缺 LID、书籍或目标被拒绝。

保存遇到过期 base_revision 时返回当前 revision 和可回读内容，保留客户端草稿。界面并置自己的修改和当前保存版，用户可继续整合，或明确选择将自己的内容基于已展示的新 revision 保存为新版本。不能静默覆盖，也不要求引入协同编辑算法。

| 失败点 | 必须发生的行为 |
| --- | --- |
| 笔记持久保存失败 | 草稿、来源和当前显示位置保留；其他位置仍显示最后成功版本；可重试 |
| 保存成功，讨论明确未接纳 | 显示“想法已保存，讨论未开始”；复用该版重试讨论，不创建第二条笔记 |
| 讨论接纳结果未知 | 沿既有操作身份/提交恢复核对本次请求；不重复发送新请求冒充重试 |
| 讨论开始后取消/失败 | 笔记已保存版本不回滚；对话沿现有停止和恢复语义 |
| 原材料不可用 | 笔记原话仍可读；来源入口准确显示不可用，不换成当前材料 |
| embedding 未就绪/不可用 | 保存、直接读取和词法查询继续；返回实际语义能力状态 |
| 目标已删除 | 返回明确不可用；保留其他对象与当前用户草稿，不按旧向量重建正文 |

## 5. 输入、草稿与演进界面

### 5.1 入口与共享编辑器

个人入口命名“我的想法”，与学习工作区在现有外层导航并列，主动作“记个想法”。置于 keyed Reader App 外，只依赖本人身份。阅读右栏继续展示当前材料相关笔记，提供“查看全部想法”；当前材料列表不得因个人全库检索而混入其他材料的阅读标注。

| 现场 | 入口与默认行为 | 自动保留的实际信息 |
| --- | --- | --- |
| 正文/PDF | 选区“记想法”；无选区也能记录 | 已选原文及确切位置，或仅实际阅读位置 |
| 对话 | 用户消息“留下这个想法”；助手内容保持摘录身份 | 原用户文字/来源消息、session/turn；不把助手话改标用户原话 |
| 视频 | 播放器旁“记想法” | 已确定的实际播放时刻/范围；普通记字无需额外截图或提交问题 |
| 演示 | 复用“记一下” | 既有确切演示版本和实际现场回执 |
| 我的想法 | 直接新建、搜索、继续草稿、打开历史 | 不要求材料、LID、工作区或学习目标 |
| 问题画板 | 从空白处创建或选择已有笔记，PN6 接通 | 本画板/所选对象情境和 NoteRef |

记录使用全局非模态便笺浮窗：桌面默认 400×360px，拖动顶部移动、拖动边缘或四角缩放；手机按可视区收敛，设备按账号记住用户调整的位置和大小。打开时阅读区尺寸和滚动位置保持不变，不添加背景遮罩，不捕获原内容的快捷键。入口直接聚焦正文，不等待笔记列表、讨论或模型；“我的想法”按需打开列表、历史和联系。来源摘录折叠展示，标题选填，收起和再次打开接续同一草稿。新记录保存成功收起并显示回执，修改已有版本仍留在详情。快捷键 Ctrl/Cmd+Shift+M 打开记录，窗内 Ctrl/Cmd+Enter 保存、Esc 收起。

新建全局想法默认保留能确认的当前阅读位置；输入区底部展示来源，可在没有预先选择原文/演示等确切来源的新草稿中改为“独立想法”。继续旧草稿时保留原来源。自动记录产生现场与放置到页面元素分开：来源随笔记保存；画布、对话和演示各自持有展示引用。跨宿主的统一放置交互见[产品方案 §4.1](设计方案-以个人想法为核心的笔记与学习.md#41-产生现场与展示位置2026-10-30-交互补充)。

2026-10-30 本地增补的实现与界面证据见[随手记浮窗](performance/personal-notes-20261030/floating/README.md)，此增补尚未发布到线上。

“先记下来”只持久保存；“与我推敲”先保存确切版本再进入讨论。带材料讨论在 PN3 接通，无材料讨论在 PN4 接通；开发增量不展示会失败的虚假按钮，不把独立笔记偷偷塞进最近一本书。

### 5.2 草稿状态

草稿使用设备持久存储，键由本人身份与 draft_id 构成。创建、输入、收起、切换资料、返回外层及打开另一笔记时保留原草稿。当前应用共享草稿状态；挂起后可从“继续上次想法”恢复。离开页面不是放弃，显式“放弃草稿”才清除对应草稿。

区分“草稿已保留在此设备”和“笔记已保存”。正式保存成功清除该次已提交草稿；保存中发生的新输入不能被旧请求回执清掉。账号切换显示对应本人草稿，网络个人保存使用现有账号数据。设备存储失败时不显示虚假的已保留状态，保留当前输入并提示保存。

普通收起和换材料不强制“保存/放弃/继续”模态选择；按现有交互安全返回原位置。Ctrl/Cmd+Enter 沿现有行为保存，中文输入法组合期间不触发；Esc 收起并归还焦点。移动端软键盘出现时正文、保存状态和主要动作仍可触达。

### 5.3 思考过程

笔记详情默认显示当前内容；“思考过程”按时间显示最初保存、各次修订和明确相关讨论。每项可看完整原文及当时摘录/来源，选择两版进行增删改对照。公式/代码保留原文差异和可读预览；变化不能只靠颜色表达。

历史视图明确标识版本，提供“查看当前想法”和“恢复为当前版本”。恢复遵守 §3.2；查看历史不污染当前编辑草稿。AI 变化概括是按需生成的解释，可回到对应原文，不替代时间线或自动宣称成长。

## 6. 召回算法与运行合同

### 6.1 查询范围与索引内容

个人召回默认查询当前用户在当前存储域的全部有效笔记，可过滤“当前材料”“当前学习空间使用过”“全部个人笔记”。使用过指实际 NoteRef 关系，不能仅因同一本书就判为同一学习目标。用户当前问题和明确指定内容优先于历史焦点。

默认索引当前修订，以及有明确关系的后续用户表达。关联表达保留原始回合/表达引用、时间和关联 NoteRef，不能改写为当前笔记正文。正文、素材摘录、简短记录情境分别标识，索引可借用情境找准短句，返回时保持作者身份。

旧版本保存在权威档案，按确切引用和笔记历史读取。第一版不承诺全部旧修订的全库语义搜索；“回顾这条笔记怎样变化”按身份读历史即可。“以前怎么想”若尚不知笔记身份，先查当前笔记/相关表达定位，找不到时如实说明搜索范围，不能声称旧内容不存在。

### 6.2 具体算法与初始预算

1. 明确 NoteRef 直接读取；UI 引用“当前版”在运行接纳时解析成确切 revision，后续编辑不改变这次输入。
2. 自动查询以本轮用户原请求为入口；当前明确引用、先前讨论和资料现场仍由各自上下文提供，不把长历史或旧目标拼成查询覆盖新问题。主 Agent 可以按尚缺的关系继续 notes.search，不另起查询规划模型。
3. 词法复用现有中文/英文词项处理和 BM25；向量复用 `Xenova/paraphrase-multilingual-MiniLM-L12-v2`、CPU q8、384 维、mean pooling/normalize 和余弦相似度。
4. 复用真实 tokenizer 与 `splitEmbeddingText`，每个输入在 128 token 能力内分段而非截掉尾部，简短情境计入同一预算。短笔记整体处理，长笔记保留每段原位置；不为每段调用生成模型补写原意。
5. 实际词法最多取 40 个候选、语义最多取 80 个候选（低于 0.3 的语义邻居不参与融合）；在最终数量截取前按 note_id 归并片段和关联表达，保留各来源。两路各自归并排名后以 RRF(k=60) 融合，默认最多提供 8 条笔记预览；明确指定的笔记单独保证读取，不争这个名额。
6. 前述数字是本轮验证后的实现值。候选不足可在既有输出预算内有界补取；上下文不足时整体裁剪候选及其读取参数，不能留下半截 NoteRef。不同材料同义/同名歧义、长笔记霸占候选等真实案例决定后续调整。
7. 候选带确切身份/修订、相关原话片段、作者、时间、情境、命中方式和下一步读取参数。RRF 排名不表示绝对相关、正确或掌握；没有有用候选时正常完成当前请求。

需要复用的是 BM25 的词项/评分逻辑、已有独立 embedding provider、分段、余弦和 RRF 公式。现有 Book Index、PublishedBookRef 候选、source.txt/base.json 读取与区间合并不能直接冒充个人笔记引擎；为这些既有组件增加小型笔记输入接点即可。

### 6.3 保存后增量更新与查询等待

笔记与修订原子持久成功后更新词法可查状态，并安排变化内容的向量计算。正文保存不等待 embedding；已有未变化向量复用，首次接续也按批构建。复用现有持久 worker，后台任务分批执行，查询不排在整个个人库重建之后；推理、文件扫描不持有用户存储锁。

索引当前有效版本由已保存笔记决定。每个任务发布结果前比对当前 note_id/revision；编辑后旧版退出当前搜索，删除后任务不能使其复活。此处处理的是异步更新支持后必然可达的先后关系，用已有身份和版本即可，不增加内容哈希。

查询返回语义 ready、partial/pending 或 unavailable 的实际状态与原因；部分就绪仅搜索有效的已建向量，词法覆盖当前已保存内容。模型缺失或失败沿现有可解释回退，不能标成完整混合检索成功。崩溃重开按当前修订与已有索引判断需要补建的内容，派生索引可重建。

### 6.4 自动入场与 Agent 按需读取

入场查询与 Agent 工具共用同一检索服务。给主 Agent 增加可发现的个人笔记读取能力，逻辑操作为 `search` 与 `read`：search 使用上述范围/预算；read 可读确切 revision、历史元数据、明确关联讨论和个人联系，分页取需要的部分。写用户笔记仍通过用户保存/采纳动作，不由自动召回顺带改写。

候选通过独立的 `personal_notes` 上下文片段与现有 grounded learner view 并列交付。沿 ContextFragmentLedger 去重和更新，同一已读版本不反复追加全文；不能只在 learner_context JSON 加字段却被现有 learner_view 白名单丢弃。

主 Agent 需要引用原话、比较新旧认识或改变教学时，读取对应版本和必要上下文。直接注入的完整、确切版本可登记为已读；搜索截短预览只作候选。个人笔记读取与书籍证据读取分别记账，笔记引用不能替代原材料证据授权。

教学焦点改变、候选不够或需要旧类比时，同一个主 Agent 可以补查。选中笔记的最新修订和明确后续修正按引用补读，不依赖它们再次挤进相似度 top-k。已有个人联系可有界查看一跳，并提供联系说明；没有说明的联系只作导航线索。

## 7. 笔记讨论、事实与教学采用

### 7.1 接纳和持久引用

“与我推敲”先保存，接纳输入时冻结 note_id/revision、当时正文、来源情境和当前请求，沿 FrozenTurn 进入同一运行。将确切 NoteRef 保存到现有回合领域记录/AgentChatTurn 的对应投影，不能只留在一次临时提示词。

后续用户明确回复该笔记讨论的回答时，保存实际 reply-to turn，并关联所讨论的 NoteRef。仅时间更晚、同聊天或语义相似不自动建立“修正”关系；讨论多个笔记时保存各自确切引用。新版本可以选择 based_on_turn，形成有据可查的修改背景。

当前新输入按现有 user_authored_text、UsageObserved、帮助冻结与表达提取进入真实事实链。拿旧笔记来讨论时，旧内容保留原时间，当前补充另记新表达；不因读取旧笔记就伪造一个今日作答。需形成理解解释时仍引用实际 fact_refs，NoteRef 另存，不能用 note_id 通过事实引用校验。

### 7.2 怎样改变教学

| 实际表达 | 可选择的具体教学动作 | 不能据此推断 |
| --- | --- | --- |
| 清楚区分过两个概念 | 从该区别继续解释当前应用及条件 | 保存过一次就永远掌握 |
| 猜测漏了关键条件 | 用针对该条件的反例或单变量演示 | 用户整体能力低或永远有此误解 |
| 自己提出类比 | 沿类比连接新内容并说明边界 | 类比在任何情境都成立 |
| 不同判断或待解问题 | 比较各自条件，接回新材料线索 | 新旧不同就一定是自相矛盾 |
| 后来明确修订或纠正 | 从更新后的表达选择下一步 | 所有较晚讨论都覆盖旧笔记 |

主 Agent 沿已有 TeachingDesign/TeachingMove 记录实际采用的 NoteRef，使用简短的已有教学说明表达它影响了什么。未实际采用的候选不登记为已使用；没有相关记忆时无需硬提“你以前说过”。检索日志、已读笔记和教学采用分开，复用现有运行/交付记录，不建独立评分平台。

主 Agent、后台教学教练、制作前表达教练沿 ADR-0176；正式学生评分沿原冻结合同。自动召回不增设笔记教师、逐轮重排 LLM 或审批模型，不把每次表达强制转成测验。当前用户直接讲解、深入、换题或停止的请求优先。

### 7.3 工作区与材料边界

个人笔记跨材料可用，不等于将其他工作区的聊天、目标和掌握统计自动导入。明确 NoteRef 关联的必要讨论可作为该笔记历史背景；当前工作区理解与统计继续根据该范围内的真实依据判断。ADR-0170 的整段历史选择带入规则继续有效。

笔记引用的书籍、视频和演示仍按原身份与访问范围读取。当前可读笔记不自动授予其原材料访问权，也不把原材料加进当前工作区。来源不可用时可讨论实际保存的个人表达，不能虚称已重读原书。

## 8. 无材料讨论、联系与画板

### 8.1 无材料讨论

PN4 增加真实个人笔记运行场景，区分共用运行职责与必须持有 Book 的职责。沿现有用户、聊天、Goal、取消恢复、模型调用和费用归属运行；不创建空白书、假 LID 或强制学习目标。

无材料时提供讨论、比较笔记、个人检索及正常回答；需要原材料的工具和正式 Tutor 能力按实际可用来源开放。以后选择材料时明确接入真实背景，旧讨论仍保留原范围。新表达保留在原聊天事实中，不制造材料掌握记录。

### 8.2 个人联系

用户选两条笔记即可建立联系，说明可以稍后补写。AI 建议必须给出具体联系理由和相关版本，用户采用或修改后才持久保存为个人联系。没有说明的关系不被推断成支持、反驳或纠正。

两个方向显示同一关系；删关系不删笔记，修改说明不新增笔记正文版。建立联系时保留双方版本；历史讨论使用当时实际引用的说明和内容，不因后续改说明而重写旧反馈。第一版通过详情列表完成浏览，不把图谱界面作为前置依赖。

### 8.3 画板与综合表达

工作区内的问题画板以 workspace/problem 归属，起始材料仅是背景，各条目保留自己的真实来源。列表、搜索、读取、导入、追问冻结和历史回读一起调整；旧材料入口继续可达。没有选择画板的个人笔记始终独立存在。

新增 Note 导入及目标类型。当前卡片按 note_id 解析最新内容，卡片的编辑进入同一共享笔记编辑器；画板局部说明仍由画板文本块持有。普通用户在其他位置编辑笔记后，当前画板读取同一新版，并显示更新。

**BoardContentRef.content_revision 是画板文档版本，不能代替 NoteRevision。** 导入/保存的画板快照保留当时 NoteRef；当前视图可解析最新，但选择内容进入讨论、交付作品或历史追问时，必须另外冻结实际看见的笔记 revision。历史画板显示其快照版本，历史讨论显示其输入版本，不拿今天的正文替换。

已有回答、演示、理解证据等不可改写快照保持原规则。画板线条可以引用个人联系，也可以仅说明本画板局部关系；排版连线不自动创建个人关系。移除卡片/删除画板不删除笔记或其他位置引用。

把围绕问题组织的笔记、条件、反例和联系整理为一份可编辑综合笔记：保留所用确切 NoteRef；AI 草稿明确来源，用户保存/采纳后成为其新笔记版本。先用现有编辑和讲解能力交付一页自己的解释；独立文件导出不在本范围。

### PN1a：稳定身份、版本与原子保存

**结果**：新建一条独立笔记，修改两次，重开仍读到三版；恢复首版得到第四版。位置变化不会产生新笔记。

**实现**：在 memory 的 note/document/store 内落 §3 的对象与不变量；提供 create/read/revise/history/compare/restore/delete 的存储操作；比较实际字段处理无变化，沿文档 revision 原子提交；完善删除与历史快照边界。对现有 v4 文档的具体升级号以实施时实际最高版本递增，不预写可能冲突的版本号。

**验证**：真实临时磁盘保存与重开；多次修订、重复保存、恢复、纯摘录、作者未知与来源变化；基础版本过期时双方内容仍在；写入失败不改变原持久状态。测一次代表性笔记/版本数量下的保存与重开，识别新增完整版本导致的全量写入成本。

**完成证据**：针对上述失败的 memory 测试与实际文档前后结果；没有功能入口前不声称用户已可用。

### PN1b：旧笔记接续与统一命令

**结果**：原材料笔记和新独立笔记都由同一权威对象保存，旧链接仍能打开现存内容。

**实现**：沿 RN1/schema 入口完成一次接续；更新 note_api、用户级路由、workspace_client 的笔记操作及现有 memory save/replace/reanchor 分支；把阅读标注保留为材料过滤投影；生成前端类型。原演示 receipt、原文选区及回答摘录校验保持。

**验证**：既有旧结构化记录、裸记录/作者未知、纯摘录、替换导航与多种来源样本；失败后重开原文档仍可用，再次重开不重复转换；读者只看到当前材料标注，个人列表能看到独立及跨材料笔记。两账号相同正文分别保存和读取，不串身份或命中数量。

**完成证据**：memory/server 定向回归、真实旧结构接续样本和生成类型检查；新旧接口均不能产生第二份可编辑正文。

### PN2a：个人入口与可恢复草稿

**结果**：没有资料和工作区也能写，收起、关闭、再打开继续原句并保存。

**实现**：在 NetworkApp/本地外壳稳定层增加“我的想法”与共享草稿模块；复用列表/编辑内容；设备持久存储按本人/draft_id 管理；实现草稿状态、挂起恢复、保存失败与同笔记多入口共享。不要直接复用要求 workspace_id 的聊天草稿 key。

**验证**：真实浏览器无材料创建、关闭重开、两个入口同一笔记编辑、保存失败重试、切换账号的草稿归属；保存中继续输入后，新输入仍可恢复。桌面和手机软键盘下操作输入与保存，检查焦点返回和状态可读。

**完成证据**：持久状态测试、前端类型检查和两种视口的真实操作记录/关键截图。

### PN2b：多现场输入

**结果**：用户从正在阅读、观看或讨论的位置留下想法，原情境随草稿保留。

**实现**：提取 NoteEditorPanel 编辑内核；接通 Reader/PDF、RightRail 用户消息、VideoReaderPane 与 AgentPresentation；用户文字与助手摘录分别处理。新增入口不强制标题、LID、截图或模型调用；恢复草稿使用原情境。

**验证**：视频某实际时刻写半句→收起→切书→恢复→保存；选区、PDF 位置和演示现场各做一条真实保存/重开；用户消息留为笔记保持作者身份；助手摘录仍可区分；窄屏、输入法组合和快捷保存正常。

**完成证据**：真实现场回读和界面结果；切换材料后的草稿不能被新材料覆盖来源。

### PN2c：版本与思考过程

**结果**：用户能读首版、比较两个版本、回看相关背景，并从旧版恢复继续写。

**实现**：在全局 PersonalNotes 实现当前/思考过程切换，原 NoteDetail 进入同一编辑空间；提供历史只读、原文差异、来源导航和恢复操作；历史讨论入口使用已有确切引用，PN3b 后加入新通用讨论。未保存草稿恢复按两步明确动作处理。

**验证**：新建→改两次→重开→对比首版/当前→恢复首版得到新版本；中间版本和已有关联仍可读；查看历史不改变当前草稿；先保存失败不会继续恢复。真实长中文、公式、代码、摘录在桌面/窄屏可读，不只靠红绿色差异。

**完成证据**：真实操作、版本回读和关键截图；不靠 AI 概括代替历史内容验证。

### PN3a：用户私有混合检索

**结果**：换材料也能找到相关想法；不同措辞可由语义路找到；刚保存或模型缺失时仍能精确/词法查询。

**实现**：落 §6 的私人索引与 search/read 服务；提取必要 BM25 小接口，复用独立 provider、分段、余弦、RRF 和持久 worker；按当前版本增量更新，删除与旧异步任务发布遵守当前状态；提供候选范围、分页回读和真实语义状态。

**验证**：中文/中英混写、相同术语不同主题、长笔记尾部相关段、短句带情境、同笔记多片段归并；更新后旧向量任务晚到、删除后任务晚到；新笔记语义未就绪时直接引用/关键词可读；模型缺失/失败不伪报 ready。实际模型验证分段与语义命中，替身只验证状态与控制流。

**完成证据**：候选及确切回读结果、索引更新记录、实际 embedding 结果；分离首次模型启动、首次建索引、热查询和单条变更成本。数据未改变时不重复 embedding 文档。

### PN3b：通用笔记讨论与版本关联

**结果**：在有材料的当前讨论中推敲普通笔记，旧反馈始终对应当时版本；用户补充能被后续读取。

**实现**：扩展 validate/input、FrozenTurn、TurnDomain/AgentChatTurn 与历史回读的通用 NoteRef；先保存再接纳，复用原提交恢复；区分当前新表达与引用旧内容，接既有表达提取、帮助条件和真实事件。新通用字段不混用演示专用 note_mem_id。

**验证**：保存成功/讨论失败/接纳未知三种状态；讨论运行时在另一处修订笔记，本轮仍读冻结版本；跨轮明确回复持有关联，同聊天无关回合不被挂为修正；旧笔记被查到不会产生新掌握事实；原演示追问继续工作。

**完成证据**：服务端与 Runtime 定向回归、真实持久回合、重开后版本/帮助读取及一次真实模型回应。

### PN3c：主动召回与教学采用

**结果**：用户仅提出当前问题，系统自行找到相关笔记，并据此选择具体讲法；新表达影响下一次接续。

**实现**：在原入场准备中调用有界个人检索，通过独立片段进入同一主 Agent；提供可发现 search/read 工具；沿 TeachingDesign/TeachingMove/交付保存实际采用的 NoteRef，保持 fact_refs 独立；按需读最新修订与明确相关后续表达，复用片段去重。

**验证**：原始模型输入确实收到候选且深读可达；候选不会被 learner_view 白名单吞掉；明确选中 A 不被相似 B 替换；没有相关笔记可正常回答；当前用户纠正优先；跨工作区笔记作为背景不自动增加当前掌握统计。教学焦点变化后的补查仍在同一主 Agent 循环。

**完成证据**：真实运行 trace 中的召回、读取、教学采用与交付版本；验证新增首答等待来自哪里，并确认未增加每轮查询规划/独立重排 LLM。

### PN3d：首份教学可用增量

**结果**：从就地记录到下一次主动想起的完整流程，在重开后仍成立。

**场景**：保存“参数不变，为什么表示会变化？”及实际背景；换另一材料，用户只问“同一个词在不同句子里的向量为什么不同”；主 Agent 召回该笔记并围绕参数/激活区别提供支持；用户表达新认识但先不改笔记；重开后再次提问，系统能读到明确相关的新表达；再保存新版、看演进和旧讨论。

**对照**：保持同一当前问题与可用资料，分别使用已清楚区分、遗漏条件、已有后续修正以及无关笔记的表达样例。人工查看实际回答是否相应改变起点/例子/下一步，是否过度假定用户理解。失败样例和用量一起保留；字段存在或替身通过不能证明教学有效。

**完成证据**：本地支持路径与账号网络路径的保存/重开工程验证；真实模型的检索和教学记录；桌面/窄屏完整操作；已有资料搜索、原笔记来源、正式学生评分等本轮实际受影响回归。通过后 PN1–PN3 才可记为第一份可用增量。

### PN4：无材料的个人笔记讨论

**结果**：没有打开任何材料，用户也能从一条笔记开始讨论、保存反馈、重开继续。

**实现**：调整 prepare_agent_chat、RunScope、PrivateBookContext 及 agent_run 相关职责，提供个人笔记场景；复用同一聊天/Goal/模型/取消恢复/计量，按实际材料上下文开放工具。连接“我的想法”中的讨论入口和版本引用卡；需要资料时由实际选择接入。

**验证**：无 Book/LID/学习目标的真实请求成功交付；不伪称读取书籍、不制造材料掌握；保存成功讨论失败仍可重试；运行取消、结果未知和重开沿原行为；加入真实材料后可读取并保留之前无材料讨论的历史。原 Reader 讨论和费用归属无回退。

**完成证据**：真实无材料多轮、持久回读、工具可用范围及费用/取消回归；独立入口的桌面和窄屏操作。

### PN5：个人浏览与有理由的联系

**结果**：从某条想法找到另一材料的笔记，连接、补说明、反向查看，并在讨论中使用。

**实现**：在已工作的个人 search/read 上完成列表/范围/游标和关系操作；详情双向关系、可选说明、AI 提议预览/采用/忽略；保存建立时双方确切版本。按需读取关系不改写笔记，不复制画板内部连线模型。

**验证**：跨材料双向打开同一关系；更新笔记后关系身份保留、当前正文唯一；旧关系依据可读；移除关系后双方笔记保留；无说明只作为关联，AI 未采用建议不进入个人已确认联系。

**完成证据**：存储/接口与实际浏览操作；一条关系被当前讨论有据使用。不以图谱动画或关系总数代替用户使用完成。

### PN6：问题画板、历史冻结与自己的解释

**结果**：同一笔记加入两个问题画板，在一处编辑后当前视图一致；历史讨论仍是原版；组织后能保存一份自己的综合解释。

**实现**：扩展 BoardImportSource/目标类型、工作区画板读列搜与追问范围；新增 Note 当前解析和确切历史引用；保留回答/演示等原快照；复用编辑器和导入成功后的选中定位。综合解释保存为新笔记/修订，引用用到的确切版本，标记 AI 草稿及用户采纳。

**验证**：两份材料切换打开同一工作区画板；外部编辑笔记后 board revision 未变，当前卡片显示新版，历史 BoardContentRef 与 NoteRef 仍能读旧版；同笔记两画板一致，局部说明仅作用本画板；移除卡片/删画板保留笔记；删笔记后当前卡片显示已删除且搜索不复活；综合解释重开仍可编辑并追溯版本。

**完成证据**：画板存储与 server/runtime 定向回归、真实浏览器桌面/窄屏操作和综合稿回读；原 Answer/Presentation/Understanding 导入与历史快照语义保持。

## 10. 验证、性能与完成记录

每次运行检查前，明确要捕获哪种失败以及失败后改哪个环节。优先使用已有 memory/server/runtime 测试、Core 实际 embedding 验证、Web 类型检查和浏览器流程；工具/接口变更时同步现有合同生成和公开示例。命令按实施时实际 package/Cargo 入口选取，不把尚未运行的命令预记为通过。

| 需要发现的失败 | 最小证据 | 失败后的处理 |
| --- | --- | --- |
| 原话、来源或版本丢失 | 真实保存/重开、旧结构接续、历史回读 | 修正权威保存/引用/原子提交，不加另一套备份正文 |
| 召回漏掉目标 | 检查 query、词法/语义各路候选和实际片段 | 按实际缺口修正情境、分词、分段或 embedding |
| 已召回却被挤出 | 查看归并前后候选及最终预算 | 修正片段归并/预算；仍不够时再评估重排 |
| 读到已解决的旧观点 | 精确版本与关联后续表达 | 修正当前索引、关联读取和教学解释，不能删除历史掩盖 |
| 召回未改变教学 | 同问题/资料下的真实表达对照与实际输出 | 修正主 Agent 的读取与教学选择，不以引用数量证明有效 |
| 界面能显示但操作失败 | 实际点击/键盘/窄屏操作 | 修正状态、焦点、布局与可恢复失败动作 |
| 新流程拖慢保存或首答 | 分阶段计时、冷/热路径与模型调用记录 | 定位全量写入、首次索引、worker 排队或多余模型调用 |

性能记录包含实际笔记数、版本数、长笔记规模与测试环境；指标包括输入可用、保存/重开、增量索引、热召回、自动召回增加的首答等待及模型调用。使用同一数据比较，冷启动、索引未就绪、热命中分别报告。现有资料搜索小样本结果仅供识别成本，不移作个人笔记承诺；不预设凭空提速比例或毫秒门槛。

沿原运行计量记录 embedding 实际输入/批次/缓存复用和主 Agent 用量。已有本地 embedding 无外部 API 费用，但仍有宿主计算成本；无材料讨论沿当前用户/Goal 的既有成本归属，不漏记或重复记账。

各切片完成时在本节状态表及既有代码链路/实施记录就近登记：实际改动、测试命令与结果、真实 UI 场景、真实模型证据、当前边界。素材和 trace 沿项目已有 performance 目录惯例保存；只保存能够复查判断的结果。必要检查通过且无新变更/具体疑点后停止扩测。
