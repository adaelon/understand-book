# 专注阅读双页与无感翻页切片方案

日期：2026-10-15。状态：FP0–FP6 本地交付完成；FP7 已实施修复，剩余联合性能验收按用户要求暂停，现有实现已于 2026-10-15 发布。决策入口：[ADR-0166](adr/0166-focus-reading-pagination-and-performance.md)。

## 0 已确认需求与边界

**FrozenIntent**：将专注阅读升级为真正分页的书页模式；宽窗口左右两页连续阅读，手机单页跟手翻页；目录、阅读设置、问答和笔记按需打开，返回时仍在原文位置。普通阅读保留连续滚动，现有来源、笔记、选区与逻辑工作区继续共用。

**确认记录**：用户先以“对”确认交互方向并提出“速度性能……必须无感”，随后以“可以，那先落 adr 和切片方案吧，一定强调性能要求”确认性能方案和本次文档交付。

**RiskReceipt**：已说明横向分页需要适配现有纵向读位、选择及标注几何；现有追加加载需要改为专注场景的有界准备；首次未缓存读取受网络影响。用户在上述说明后确认落档。

**ChangeType**：`[纯技术]`，扩展设备侧阅读呈现；显示书页不成为新的书籍或引用身份。

## 2 性能验收合同

下表为本工作线在 §5 固定可用环境中的通过门槛。FP1 固定运行环境、可测刷新率、材料、网络条件和测量方式；后续在同样条件下判断，不因某次失败临时改口径。

| 编号 | 场景与口径 | 通过门槛 |
| --- | --- | --- |
| P1 响应 | 翻页点击/按键，或有效横向拖动的输入时间戳，到第一帧实际页面位移；包含事件排队时间 | P95 ≤ 50ms；同时保留 P99、最大值及手势识别等待。动画总时长单独记录 |
| P2 连续帧 | 拖动和收尾动画期间的实际呈现帧；按浏览器实际运行刷新率计算预算 T | 60Hz 的 T 约 16.7ms，120Hz 约 8.3ms；缺失呈现帧比例 ≤ 1%；无本功能引入的 ≥ 50ms 主线程长任务 |
| P3 页面就绪 | 正常顺序阅读，每秒一次翻页、连续 200 次，包含跨章和反向；内容由正常预取取得 | 翻页时目标屏未就绪次数为 0；无空白页、正文闪现、晚到图片挤动或半个双页等待。首次冷打开单列 |
| P4 显示变化 | 当前正文、所选字体和可见图像已在本地就绪时，进入专注、字号调整、单双页切换到新首屏可读 | P95 ≤ 100ms；旧画面保持到新首屏就绪，原文锚点仍可见；完整邻页缓冲随后补齐 |
| P5 长时间资源 | 至少 500 次有效翻页及 20 分钟阅读；覆盖多章节、反向、字体变化及 PDF | 驻留页、DOM、原文/解析缓存、解码图片和画布始终满足冻结预算；同场景回返的稳态占用不随累计翻页持续增长 |
| P6 翻页期间工作 | 从输入到翻页结束的调用与渲染记录 | 不依赖网络/保存响应，不执行正文解析、重新分页或整流几何扫描；仅更新位移/透明度、必要页状态和一次读位确认 |

P1/P2/P6 必须在自动补页同时运行时测量。P3 不通过时，即使“只统计就绪页”的 P1 达标也不能交付。缓冲外快速连翻、冷跳转等记录完整等待和恢复，不丢弃失败样本。

覆盖式收尾动效以 160–220ms 为初始范围，距离较短时相应缩短；这个时长不属于响应延迟。连续输入允许接续或改向，不能等待整段动画完成才接收下一次操作。减少动态效果时直接完成切换，P1/P3/P5/P6 仍适用。

浏览器的排版、绘制和合成属于不同开销；位移与透明度有机会走合成路径，必须由记录证明，不能仅凭使用 `transform` 宣称达标。[浏览器渲染性能说明](https://web.dev/articles/rendering-performance)

## 3 交互与分页合同

**呈现规则**：宽窗口默认左右双页，左页读完接右页，一次翻页移动一屏；每页无法容纳舒适行宽时转为单页。断点按实际正文容器与字号推导，FP1 冻结最小页宽；手机默认单页。首末屏按剩余真实内容展示，末尾不复制上一页填满。

**操作规则**：PC 支持两侧按钮、左右方向键及 PageUp/PageDown；手机支持左右滑动和轻点页边，点中间呼出工具。链接、公式、笔记标记、表格横滚、PDF 放大后的页内平移、原生选择与输入优先处理。只有确认是翻页的手势才接管；书籍首尾的继续操作保持当前内容。

**分页规则**：以当前视口可用宽高、实际字体、字号、行距和版心排版。优先验证固定高度的原生多栏在局部窗口中的分页，按页边界记录原文起止位置；一次 LID 可以跨页，标题、行内公式、列表和段落的续接保持阅读顺序。[浏览器多栏行为](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Multicol_layout/Handling_overflow)

**宽高内容**：图片保持比例并预留确定尺寸；代码、表格和长公式保留原始文字与局部滚动/展开入口，超高内容能够继续读完。分页、横滚和展开的手势所有权分开。跨页续接需核对原文范围无遗漏、无重复，不能按截屏高度裁掉内容。

**原文连续性**：页边界保存现有材料身份、LID 和规范 UTF-16 范围，显示页码仅属于当前排版。进入/退出专注、字号/字体变化、旋转及来源往返围绕原文锚点恢复；图片与公式使用可验证的对象位置。工具关闭后回到同一页面和对象，聊天草稿及冻结引用沿现有现场保存。

**选择与标注**：保持可选的正文 DOM，复用来源映射；跨列片段用实际片段几何定位，不能把跨列元素的外接矩形当作一页。只有可见页参与命中、位置采样和标记展示，预取区不可被选中或聚焦。原生拖选期间暂停翻页与会破坏选区的重排；退出选择后恢复正常翻页。

**显示变化**：捕获原文位置 → 保留当前画面 → 准备新几何的当前屏 → 验证同一现场及最新请求 → 一次切换 → 补相邻页。工具栏临时呼出采用覆盖层，避免仅为显示按钮重新分页；手机视口变化合并处理，保护当前拖动。单双页切换复用同一阅读实例。

**状态归属**：预取调用既有只读内容接口，不调用有读位/已读副作用的翻页命令；页面确认后更新本地实际可见锚点。持久进度沿现有命令和异步已读合同同步，不能阻塞画面或把预取页算作已读。发起问 AI 时使用实际可见原文/冻结选区，不能落回预取窗口中心。显示变化不提交逻辑布局 revision。

章节与进度沿现有材料导航展示；局部页数在边界已知时显示。全书尚未分页时，不编造固定总页数，也不为展示总页数阻塞进入阅读。

## 4 准备链路与资源预算

```text
就绪页面准备：
  合并读取所需原文 → 复用或生成解析结果 → 准备字体/公式/图像尺寸与解码
  → 局部分页与来源映射 → 准备可见标注 → 同一现场下发布就绪页面

翻页：
  目标屏就绪 → 按输入更新局部位移 → 确认实际可见页与原文位置
             → 排程补页及必要状态同步
  目标屏未就绪 → 保留当前可读页 → 优先准备目标屏 → 就绪后切换并记录等待
```

“就绪”是实际目标内容已能按稳定几何显示。只拿到网络响应、HTML 字符串或 PDF 页对象均不算就绪。Markdown 的必要字体、公式排版、图像解码及标注几何必须齐备；PDF 的画布、文字层及已有标注投影须对应同一页面和倍率。图片提前 `decode()` 的具体作用见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode)。

**准备策略**：优先当前屏，再准备前后各一屏，剩余预算向阅读方向多准备一屏；可见页面稳定后补充。正常翻页触发补充而不重建所有页。每次准备只处理局部窗口，批次间让出主线程；长段排版可从已知来源边界接续，回收只发生在可确定的页/块边界。

**缓存策略**：原文与解析结果按现有材料版本、LID 及实际输入复用；几何结果还受字体和视口参数约束。正文不变时避免重复解析；标注改变只使涉及的页/片段失效。换材料、用户现场或来源版本时沿现有身份与取消机制清理旧任务。异步到达的数据不直接插入正在拖动的可见页。

**主线程策略**：指针事件只记录最新位移，绘制帧更新局部 `transform/opacity`；宽高、页距和阈值在手势开始前准备好。重排任务不与拖动争抢，准备批次避免读写 DOM 交错引发重复强制布局。纯解析确有可测瓶颈时再选择 Worker，DOM 排版仍使用主线程的小范围工作。

| 资源 | 初始预算与冻结责任 |
| --- | --- |
| Markdown 页面 DOM | 常驻当前屏、前后各一屏及一个准备屏，合计最多四屏；单页最多四页、双页最多八页，准备区计入总数 |
| 页面准备任务 | 同一阅读现场最多一个排版准备任务；合并下一目标与取消旧请求，补页让位于有效手势 |
| 正文/解析缓存、DOM 节点、解码图片 | FP1 已冻结正文 512KiB、解析载荷 2MiB、12,000 DOM 节点、8,000,000 解码图片名义像素；当前屏、邻屏与准备区合计，计数口径及依据见 [FP1](performance/focus-reading-fp1-20261014/README.md#冻结预算)；参数见 `reader-pagination-budget.ts` |
| PDF 专注驻留 | 前后各一屏加当前屏，桌面最多六页、手机最多三页；包括正在准备的画布，正常连续滚动沿现有策略 |
| PDF 画布像素 | 总量最多 12,000,000，沿现有像素预算；必须记录画布实际像素、栅格倍率及清晰度，像素数不等同于进程总内存 |
| 隐藏阅读区域 | 停止可见位置采样和非必要页面准备，保留有限现场；重新显示恢复有效几何后再采样 |

FP1 已冻结剩余资源上限与最小页宽（20em、页间距 32px），FP2 已完成分页器预算验证，FP3 接入上游读取与缓存。达到上限时先停止远处预取并回收远离当前屏的资源；单个必需内容无法在预算内完整呈现时，修正分块或既有展开路径并重新验证，不以裁切内容或静默突破上限交付。

## 5 测量与失败处置

**固定负载**：选一部真实长 Markdown/EPUB 导入书、一份包含长段/标题/中英混排的材料、一份公式/宽表格/代码/图片密集材料，以及原版 PDF。优先使用本仓库已有可读取材料，记录具体入口、版本、规模和涉及章节。补充夹具只承载明确行为用例；真实材料用于成本和连续阅读判断。

**固定环境**：正式 Web 构建的桌面 Chromium、可接入的 Windows Tauri/WebView2，以及 Chromium/WebKit 的移动视口与触摸模拟。记录实际系统、浏览器版本、可测刷新率、视口、DPR与电源模式；iPhone 13、Pixel 6a 保留为移动布局参考。桌面含 1440×900 与 1024 宽窗口，移动模拟覆盖竖屏、横屏、320 宽容器及 DPR 2/3。

FP1 固定可复现的本地基线、运行环境和工程预算；FP7 按同一可用环境完成正式入口联合验收。2026-10-14 验收范围已收敛为桌面运行时与浏览器模拟。可采集的性能指标继续执行原门槛，无法采集的物理呈现指标和实体手机差异列入 §8 的未验证范围。

**固定过程**：

1. 首次进入和首次跨章单独记录；随后使用正常预取进入稳定阅读。每组执行 200 次每秒一次的翻页，包含反向和跨章；再执行每秒四次的 40 次连续输入，核对接续、改向和没有长队列。
2. 正常就绪测试先使用本地/缓存资源，再使用固定 100ms RTT、10Mbps 下行条件；主动阻断网络时核对已准备页仍可翻，未准备页保留当前内容。不能在计时前人工预排整本书。
3. 单独覆盖冷字体、未缓存跳转、切换字号、窗口缩放、手机旋转、原生选区、笔记浮层及后台问答运行。冷路径记录完整等待，正常路径内的准备失败仍计入 P3。
4. 长阅读至少 20 分钟和 500 次有效翻页，在预热、100 次、500 次及返回同一章节后采集同类资源；检查保留的 DOM、缓存和图像是否落在预算内，以及远离当前页的对象是否仍被持有。

**记录口径**：使用生产构建，记录输入时间戳、页面 ready 时刻、实际呈现/合成帧及必要调用轨迹。`requestAnimationFrame` 回调间隔只用作调度诊断，不能单独证明页面已经显示；结合浏览器性能工具和必要录屏核对。P95/P99、掉帧、最长任务、就绪等待及资源峰值按设备/材料分别保存，不用跨设备平均值掩盖慢设备。

每项测量在运行前明确失败与处置：

| 具体失败 | 下一步动作 |
| --- | --- |
| 就绪页面响应超过 50ms | 查看输入队列和手势提交链，移除同步解析、几何读取或整树更新 |
| 响应及时但动画掉帧 | 区分布局、绘制、合成或解码成本，缩小参与节点与动画图层；修正后台准备调度 |
| 正常阅读目标页未就绪 | 分解读取/字体/解码/排版耗时，调整提前量与批次；优先去掉不影响显示的依赖 |
| 连续阅读资源增长 | 找出仍被持有的页面、解析结果或图像，修复回收；证明同场景往返的占用回到稳定范围 |
| 分页丢字、重字或笔记错位 | 回到分页/来源映射切片，先修连续性，再测对应性能；不得牺牲原文正确性换取通过 |
| PDF 下一跨页仅半屏就绪 | 修整屏预渲染调度与文字/标注层同步，核对总像素和清晰度 |

相同候选在同一负载的记录保留完整失败，修复后重跑受影响组；没有新改动或新问题时不重复扩大全量测量。性能结论必须来自候选实现，旧版连续滚动的记录只作为基线。

## 8 已知问题与限制

- FP0–FP6 已完成；分页内核、来源映射、就绪预取、公开交互、原文操作、持久读位及PDF均已落档。可用环境内的正式入口联合交付仍属FP7。
- FP1 的真实长链接首次同步阻塞已在 FP2 分页路径解决；FP5分页选择复用已准备的规范映射。可接入的 WebView2 及完整移动交互仍按所属切片和 FP7 验收。
- 行内公式额外换行、隐藏页显示引起的整页布局、迟到数学字体干扰已在FP4修复。FP3 历史61ms长任务样本仍无可靠归因并保留原样；FP4最终四组正常阅读及五组实际渲染记录均无阅读阶段≥50ms长任务。
- 实体 iPhone/Android、手机系统级选择手柄、实体触摸延迟和实际高刷表现属于未验证范围，不阻塞本期完成。桌面 Chromium/WebKit 模拟的结果不代表手机真实性能；无法采集的物理呈现指标保留未测。
- 冷材料、首次字体、远距离未缓存跳转和超出准备速度的连续快翻会暴露准备时间，须保留可读画面并记录等待；正常每秒一次翻页的预取未命中不在豁免范围。
- PDF 固定版面按原版页阅读；总像素预算、设备缩放和实际清晰度需共同验证。手机浏览器可能限制有效刷新率，实测按实际呈现频率报告。
- 原生选择手柄跨重排的限制沿 ADR-0131；冻结引用、已保存笔记和来源身份必须准确保留。现有普通阅读行为及后端命令含义以各自合同为准。
