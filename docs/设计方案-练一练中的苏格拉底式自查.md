# 「练一练」里的苏格拉底式自查

2026-11-04 · 设计提案，待实现。首版适用于文本阅读器里的选区、当前节或章。

**一道题占一张练习纸。题目留在原位，变化的是用户写在下面的想法。** 用户可以从一个不确定的猜测开始，问 Agent 为什么这么问，反驳它的理解，再回来修改最初的判断。在这张纸上，用户能亲眼看到自己保留了哪一步、改了哪一步，以及为什么。

## 一、用户怎样接着这道题聊

**直接落到题面。** 「做一道题」和「考考我」共用独立练习页。范围已知时，点击相应动作就显示当前题，页眉写明选区或章节。若用户从聊天里说“考考我刚才这段”，走同一路径。只有“刚才这段”有两个合理所指时才让他选。读完一章或提交一道普通练习，都由用户主动决定是否开启自查。普通单题作答前后都可以点「就这一步聊聊」，接着自己的式子或已展示的解答谈。

**题面下留一块始终可写的地方。** 第一次提示“写下你现在怎么想，猜测也可以”。第一次回应以后，同一处提示“接着写。你可以回答、反问，也可以改刚才的话”，主动作是「接着聊」。用户写“为什么？”和写一个算式一样自然，无须先给这句话分类。原题、已知条件和第一稿一直可回看。Agent 的回应排在它所承接的那句话旁边，像老师在草稿边写的批注。桌面用纸面留白区分原话和批注，手机把批注紧排在对应句子下面。

**随时拾起旧的一句。** 用户可以点自己或 Agent 的任何一笔「接着这句聊」，输入处只引用这一句。新回应接回来，先前的原话仍然保留。他可以说“我还是坚持这个判断”，也可以说“我想改的是第二步，第一步我还同意”。练习中始终只有一个输入框。普通聊天的消息列表收起，用户留在当前题的草稿上。

**把想法的变化还给用户。** 当用户真的改口，才临时并排呈现“我起初写的”和“我现在写的”两句原话。若变化的理由还不清楚，Agent 可以轻问一句“是哪一步让你改了主意？”用户也可以说“我并没有改，是你刚才理解错了”。这时撤回 Agent 的推断，按用户澄清的意思继续。用户没有改口时，就保留原判断和还没解开的疑问。

## 二、Agent 这一轮该说什么

每轮先读本题、用户指的是哪一句、这次实际说了什么，以及在此之前展示过哪些帮助。目标是找到当下值得弄清的一处区别。**如果用户问了一个问题，先给他一个实在的回应。只有下一个问题能分清两种合理解释时才追问。**

| 用户此刻在做什么 | Agent 的回应 |
| --- | --- |
| 给出结论，理由还不清楚 | 引用一个关键词或一步算式，请他说明这一步的含义。结果对错只说明本题要求中已经问到的部分。 |
| 反问 Agent，或质疑题目 | 先回答他问的那一件事。题意有歧义就澄清，质疑有道理就回材料核对。若回应已经给出解题线索，把它记为帮助。 |
| 修改自己的判断 | 保留两版，用他的话指出改动在哪里。若原因已说清楚，就承接这个发现，省去重复盘问。 |
| 说“你理解错了” | 收回先前归因，指出改读为哪句话。必要时只核对这个分歧。纠正 Agent 本身不构成一次错误作答。 |
| 说“不知道”，来回几轮都没有新线索 | 可以直接给一个经用户选择的提示、讲清当前这一步，或先停在疑问上。 |
| 已用一个例子或推导说清关系 | 收住主动追问。用户仍可以沿本题聊。若值得检验迁移，只提出“想换个情境再试吗？”，在用户选择后才另起一题。 |

首版对 Agent 主动发起的诊断问题设四问上限，含首问。达到上限就停下主动提问。用户发起的反问、纠正和澄清可以继续，不消耗这个额度。连续两次追问没有带来新信息时可以更早停。用户要求“直接讲”就给所需解释，之后仍能针对解释中的一句继续谈。实际展示的解答计为帮助。“到这里”为这次自查收尾。

## 三、一张纸上的实际对话

题面从头到尾是同一句。“去、回各 30 公里，去程时速 10 公里，回程 20 公里。全程平均时速是多少？”参考解答为全程 60 公里、用时 4.5 小时，平均时速 13⅓ 公里。下面是一种可能发生的对话。

| 谁写的 | 写在纸上的内容 |
| --- | --- |
| 用户 · 第一稿 | “我猜是 15。两段一样远，我觉得两个速度应该各占一半。” |
| Agent · 批在「各占一半」旁边 | “你说的‘一半’，是哪一个量的一半？” |
| 用户 · 反问 | “路程各一半。我不明白，算这趟的平均时速，为什么要看时间？” |
| Agent · 回应疑问 | “时速的单位是公里/小时。它问的是这趟路平均每小时走了多远。你愿意拿自己的 15 检验一下吗？” |
| 用户 · 修订 | “去程要 3 小时，回程只要 1.5 小时。我刚才把‘路程各一半’也用到了速度上。现在我会算 60 ÷ 4.5。” |
| Agent · 核对变化 | “路程各半仍然成立。你改的是用它来给两个速度各算一半。这样读你的话准确吗？” |
| 用户 · 澄清 | “对。我原来并没有觉得时间一样长，只是没想过两段用时为什么会影响平均值。” |
| Agent · 收住 | “明白了。你保留了对路程的判断，修正了把两个速度直接平均的做法。你刚才列的式子已经表达了这个区别。” |

到第五行，纸上就已经能看到第一稿与修订稿。用户无需等到看小结才发现自己改了什么。Agent 关于时速单位的解释记为已经提供的支撑。用户随后列出正确式子能支持“讨论后能解释并改用总路程与总时间”。无提示迁移仍待确认。

同样先写 15，若用户接着写“我用的是 60 ÷ 4.5 = 15”，Agent 应顺着他的式子请他复核除法。若他改为 13⅓，纸上保留“列式原本就对，修改的是计算结果”。在阅读论述性文本时也一样。用户若说“我同意作者的例子，但不接受他的结论”，就接着问例子究竟支持哪一步，允许用户保留与作者不同的、有依据的解释。

## 四、哪些内容可以成为理解判断

判断的单位是当前关系上的具体表现。复述一个主张、解释条件怎样导向结论、举出成立或失效的例子、在未点名方法的新情境里自行选用，分别支持不同的判断。用户给出反例或有效推导，可以直接采用。一条简短的式子已经说清的内容，无需再口述一遍。

题目、原话、原文出处、回答前已展示的帮助是判断依据。中性追问“这个一半指什么”给用户留下独立表达的空间。Agent 若指出“先分别算出两段用时”，已经给出关键一步。提示、直接解答、相关原文以及讨论中的实质讲解都按展示时点归属，适用帮助随同题后续推理保留。改答同时保留原尝试。用户的反问可以帮助 Agent 选下一句。判断能否解题，还要看用户自己给出的推理。

结束时，取用户自己已经展示的、讨论后能做到的和尚待确认的内容，写成两三句话。每句结论都能展开到原话。未知、存疑的题目、用户撤回或纠正的归因，只按仍然有效的证据呈现。用户没作答就结束，显示“这次还没有作答”。从小结点一句「接着聊」仍回到这道题；已经看过的解答继续算帮助。

## 六、怎样验收

1. **让用户在题中反问。** 输入第三节里的“为什么要看时间？”，应收到对这个疑问的回应。题面和第一稿都在，反问不会被评为答错，用户能从这一句接着写。
2. **让用户看到自己改了哪一步。** 从“两个速度各占一半”改到“只知道路程各占一半”。小结出现以前，两句用户原话已经可对照。再输入“我没有说时间相等”，检查 Agent 是否收回过度推断。若用户给的是正确列式加算术失误，就应走复核除法的另一条路径。
3. **让讨论在用户需要时继续。** 找回较早的一句接着聊，达到主动追问上限后继续反问，看完解答后针对其中一步提问。三处都留在本题。换情境只在用户接受后发生。
4. **核对教学记录和页面。** 分别走无提示修订、讲解后修订、提前结束、题目核查存疑。核对小结里的原话、先前帮助及判断范围。桌面和窄屏各走一次作答、返回阅读、找回原草稿和重试。正式评估用既有测试检查，追问是否真的接住用户则用真实 Agent 对话验收。
