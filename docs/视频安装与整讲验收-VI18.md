# 视频安装与整讲验收（VI18）

## 分发与依赖

Windows 分发包含 Reader、Build Engine、Book MCP、`publish-book.exe`、`video-audio-review.exe`，以及 `resources/video/` 中的 FFmpeg、FFprobe、原许可证、实际版本、Whisper 依赖清单与本说明。Whisper 适配脚本和语义执行器提示随 Build Engine 编译；运行不依赖仓库、Node 或 tsx。

`FFMPEG` / `FFPROBE` 可显式覆盖解码工具；未设置时使用程序旁的 `resources/video/bin`，源码与 Linux 入口再回落到 PATH。浏览器沿原媒体路由播放 MP4/H.264/AAC；按需帧和原音频由同一套工具读取。

安装 Python 3.11 后，在自选数据目录建立环境并下载本地模型：

```powershell
py -3.11 -m venv D:\UnderstandBook\whisper-venv
& D:\UnderstandBook\whisper-venv\Scripts\python.exe -m pip install -r "$install\resources\video\requirements-whisper.txt"
& D:\UnderstandBook\whisper-venv\Scripts\python.exe -c "from faster_whisper.utils import download_model; download_model('small.en', output_dir='D:/UnderstandBook/models/small.en', revision='d1d751a5f8271d482d14ca55d9e2deeebbae577f')"
$env:VIDEO_WHISPER_PYTHON = 'D:\UnderstandBook\whisper-venv\Scripts\python.exe'
$env:VIDEO_WHISPER_MODEL_DIR = 'D:\UnderstandBook\models\small.en'
& "$install\understand-book-build.exe" video-doctor --codex $codex
```

`$install` 是安装目录，`$codex` 是已登录的 Codex CLI 可执行文件。持久配置可将两项 `VIDEO_WHISPER_*` 写入用户环境后重新启动 Reader。桌面 Reader 也读取 `%LOCALAPPDATA%/UnderstandBook/.env`；从终端启动的维护命令需继承相同配置。

`video-doctor` 分别列出解码、Python/faster-whisper、模型文件及可选 Codex CLI 的实际缺项和恢复操作。CLI 版本检查表示程序可启动；账号和原生图片能力通过真实语义任务验收。读时模型继续沿 Reader Provider 设置配置。

## 正式命令与恢复

```powershell
& "$install\understand-book-build.exe" video-import D:\lectures\lecture.mp4 --workspace D:\books\lecture
& "$install\understand-book-build.exe" video-status --workspace D:\books\lecture
& "$install\understand-book-build.exe" video-resume --workspace D:\books\lecture
& "$install\understand-book-build.exe" video-transcribe --workspace D:\books\lecture
& "$install\publish-book.exe" D:\book-service import D:\books\lecture
```

复制完成后，恢复消费已导入的原媒体。转写保留每块识别响应，重跑恢复缺块；已完成态不再调用 Whisper。可通过 `--python` / `--model-dir` 为本次转写覆盖环境配置。

相同 Build Engine 提供 `video-translation`、`video-visual-units`、`video-graph`、`video-discourse`、`video-correction` 和 `video-revision`。`video-semantic-series run WORKSPACE graph|discourse JOBS_JSON CODEX_EXE` 将最多三个独立语义任务交给一个会话；JOBS_JSON 为包含 `batch_id` 和 `selection:{vu_ids,segment_ids}` 的数组。各单任务命令保留现有 `prepare/run/status` 或维护子命令与参数；源码形式是 `node --import tsx skills/build/automatic-build.ts <命令> ...`。校正请求中的原音频复核程序使用分发的 `video-audio-review.exe`。插件 `scripts/start-video.cmd` 从已安装目录或 `UNDERSTAND_BOOK_BUILD_EXE` 找到 Build Engine 并转发命令。

发布是不可变快照；英文正文/原片改版生成独立 Book，由读者主动打开。同源语义补齐沿窗口间隙接入，已有草稿、在途回答和历史来源继续固定原发布。

## 整讲生产与验证

首版采用原 CS336 77 分钟文件、原转写及已完成的 720 段中文。`evals/video/vi18-run.ts` 按四个独立工作区完成全讲，抽帧顺序执行，模型任务最多四个工作区并行；各阶段沿正式编译入口和已有候选接纳执行，主进程累积发布。图谱和讲解每次会话至多连续处理三个独立任务；每个任务仍在轮到它时冻结输入，经原候选门接纳后才推进，恢复跳过已接纳贡献。图谱与讲解的候选接纳错误返回具体反馈，同一输入最多三次候选尝试；仍失败则保留任务供恢复，文件或发布错误不会作为语义重试吞掉。`VI18_OUTPUT` 指定生产与书库目录，重跑复用已接纳批次。

`apps/desktop/scripts/smoke-video-release.mjs SIDECAR PUBLISHER ORIGINAL_MP4 OUTPUT_DIR` 从独立目录、仅系统 PATH 验证缺项诊断、原声转写、导入恢复、完成态恢复、不可变发布与原媒体字节。输出目录保存真实结果。

源码仓库的 `docs/验收-视频理解.md` 的 VI18 节记录最终结果和实际支持环境；工作进度见 `docs/VI18-实施状态.md`。

## 已知问题

- Python 环境与 small.en 模型由使用者配置；未配置时有实际缺项和恢复入口。
- Linux、DSH、读时真实 Provider 和完整逐字听核保留既有待验范围；双窗口采用确定性在途回答，验证发布绑定及现场保持。
- Windows 验收为独立分发目录中的 release Reader 与编译 Engine；NSIS 构建及发布门通过。原生安装升级和 Tauri WebView 未直接执行，现有安装未升级。
- 整讲视觉/图谱采用源码入口，讲解 383 项采用编译入口。编译入口的整讲视觉仍无完整通过凭据；早期长进程缺最终回执的原因未定。
- 语义人工核对覆盖两处原图及其图谱/讲解；整讲覆盖与来源校验不替代完整语义和逐字真值。原 VI16 草稿继续 pending。
