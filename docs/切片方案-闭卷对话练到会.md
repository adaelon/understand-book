# 切片方案：闭卷对话练到会

日期：2026-11-15。状态：**CB0–CB5 已交付；当前题面范围为文字、公式和表格。** 决策见 [ADR-0183](adr/0183-closed-book-dialogue-to-independent-performance.md)，当前实现与验证范围见[实施记录](实施记录-闭卷对话练到会.md)及验收证据。本方案定义普通教学与课程中的闭卷对话过程，复用现有教学、作答和理解记录。

## 1. 目标与完成定义

用户对已经讲过的概念或题目开启“练到会”，界面只显示当前问题或题目、本次对话和作答区。Agent 根据真实回答追问、补教，最后让用户在没有本次答案提示的条件下自行解释或完成任务。每个约定目标都有明确结束点，退出和恢复能回到原学习现场。

完整交付需在真实使用中贯通以下过程：

- 概念：讲解后开启 → 自己解释 → 针对缺口追问 → 达到已说明的目标 → 本轮完成。
- 题目：看过解法后开启 → 新条件或同目标变式 → 卡住求助 → 补讲 → 新的独立尝试 → 本轮完成。
- 中断：暂停、刷新或重启 → 恢复原目标、问题与草稿；查看资料后返回 → 保留查阅和受助条件，重新安排独立尝试。
- 课程：从当前课程目标进入 → 闭卷对话 → 保存实际表现 → 回到原课程位置，由课程原推进规则决定后续。

只新增开关、提示词、状态字段或静态页面均不足以完成一个切片。首个实现切片就要让一次概念练习经真实前后端走完，并验证历史讲解无法在闭卷现场回翻。

## 3. 用户行为与显示合同

### 3.1 开始和目标范围

入口放在当前教学控制及课程当前概念／题目附近，名称为“练到会”，说明闭卷、持续追问和可暂停。用户也可以在对话中明确要求开启。首次关闭，当前会话内的开启状态可恢复；开启本身不产生掌握记录。

入口优先采用用户正在学习的具体目标和已交付内容。已有目标清楚时直接展示目标并开始；找不到所指概念或题目时只澄清当前对象。目标写成可观察行为，例如“解释二分查找为何能排除一半，并判断降序数组时如何选择下一范围”。每个目标出题前确定需要观察的含义、条件或关键推理，接受合理的等价表达与解法。

目标已确定时，开启动作保存约定后立即请求首问，界面先进入闭卷的准备状态；失败时保留目标并提供重试。当前 `set_mode` 只修改设置，实施时需显式接上原请求发送链路；不能出现已开启但没有问题的静止页面。已存在适用的待答问题时恢复该问题，不重复生成。

模式在当前学习范围内持续生效。一个重点完成后显示结果并等待继续；用户选择下一重点时保留该约定，已完成部分无需重新验证。临时插问按其作用处理：帮助当前目标时记录补教并返回；明确改变目标时沿原目标切换流程保留旧进度。

### 3.2 闭卷视图

| 内容或入口 | 闭卷期间的行为 |
|---|---|
| 当前题目及必需条件 | 显示题干、数据、必需静态图和已有题型的作答控件；题面自身不能包含所问结论 |
| 当前尝试的交流 | 显示本次问题、用户已提交回答、草稿和 Agent 的必要反馈；等待用户回答时不叠加第二个待答任务 |
| 原文、笔记、课件、知识地图、演示和实验 | 收起，并从闭卷现场移除直接展开或切换入口 |
| 进入前的聊天及此前尝试 | 原记录保留，闭卷现场不提供向前加载、回翻或展开；当前尝试拥有独立的显示起点 |
| 提示、完整讲解和解答 | 通过当前对话按需交付并记录实际帮助；独立重试从新的显示起点开始，旧帮助不再可见 |
| 来源引用、历史消息链接和原有快捷入口 | 来源可以用普通文字标明；需要打开被收起内容时转为离开闭卷流程 |
| 学习操作 | 保留发送、请求提示、请求讲解、暂停与退出；不与课程原输入框并行出现两个待答入口 |

桌面和窄屏均采用单一学习区域：顶部简洁显示本轮目标和退出操作，中间为题目及必要对话，下方为作答区。继续使用现有字体、间距、配色和公式组件；长题干与长回答可阅读，窄屏键盘出现时仍能定位当前问题。闭卷期间不展示理解地图、评分仪表或无关侧栏。

进入前保存原阅读位置、课程阶段、实验参数和草稿。闭卷状态恢复必须先决定显示范围，再渲染正文和历史消息，避免刷新时先显示旧答案。原聊天记录由原会话持有，显示起点只控制本轮视图。

### 3.3 追问、求助和独立重试

| 实际输入或表现 | 下一步 |
|---|---|
| 用户说“懂了”或只报出结果 | 若目标仍缺具体依据，邀请用户说明相应含义或关键理由 |
| 回答部分成立 | 先准确回应已成立部分，只追问当前缺口；已经足够的回答直接收口 |
| 用不同措辞或另一种合理解法回答 | 按含义与推理判断，必要时澄清歧义，不要求复述固定句式 |
| 用户不知道、误解或连续卡在同一步 | 缩小问题、换例子或补讲所缺前提，再回到原目标 |
| 用户请求提示或完整讲解 | 实际给出所请求帮助；本尝试按受助处理，不因帮助很短或被隐藏而改记独立 |
| Agent 在反馈或引导性问句中给出了关键答案 | 同样记录帮助；后续复制或拼接这段回答不能作为本目标的独立完成依据 |
| 需要观察受助后的独立表现 | 生成同目标的新例子、条件变化或小变式，让用户作出前文尚未替其完成的判断 |
| 当前目标已有足够独立依据 | 给出具体完成反馈，结束本轮；不再提高标准或重复同一验证 |

补讲可以解释当前目标，但保持用户可见内容为对话或题目。确需可交互演示或资料阅读时，先离开闭卷现场。独立重试不得只把上一段提示折叠后再次索要同一答案，也不能借换题引入未经支持的新学习目标。

同一次尝试内，多轮追问可以共同揭示用户思路；若问题串已提供解题结构或关键关系，按实际帮助记录。最终独立尝试要求用户自行组织当前目标所需的解释或关键推理，不能只取最后一个短答案而忽略之前提供的脚手架。

### 3.4 暂停、退出与恢复

暂停保留目标、当前题目、原话、草稿、帮助事实及未完成事项，页面继续遮住资料并提供恢复按钮。关闭模式或查看资料时恢复原现场，不把该目标标记完成。刷新、断网重试与应用重启沿已有持久化和恢复路径处理；没有新帮助时可恢复同一题面和草稿。

离开闭卷去查阅后再次进入，保留此前答过和获得帮助的事实，为尚待验证的目标安排新的独立尝试。用户只暂停、未查阅资料时，不强制重新答已经完成的部分。应用只依据自身记录和用户明确表达的查阅情况解释帮助条件。

课程暂停或全局 Tutor 对对应通用会话的暂停会停止其闭卷主动推进。课程仍由自己的状态控制，不修改全局 Tutor 开关。模式关闭后，后续普通聊天沿原规则回应。

尝试保存确切聊天和问题引用。切换到其他历史聊天或新聊天时先离开当前闭卷现场，旧问题保留在原聊天，不阻塞另一聊天的普通请求。从原学习的恢复入口继续时定位原问题；明确要求在新聊天续学时引用旧事实并建立新的尝试，不改写旧邀请的归属。

## 4. 状态、事实与完成依据

### 4.1 所有权与最小持久内容

状态沿原私人学习存储保存，普通教学归 `TutorSession`，课程归 `CourseRun`。由原拥有者保存可选模式约定，并投影当前尝试；历史问答、帮助与判断继续使用现有事实引用。具体 Rust 类型及接口名字在 CB1 按原合同落定，前端类型沿现有生成路径同步。

| 内容 | 保存的含义及用途 |
|---|---|
| 显式约定 | 是否启用、归属目标及来源版本；用于后续回合采用正确规则 |
| 当前目标 | 用户接受的解释／解题能力、必要完成条件及所依据的已交付内容；用于限制追问范围 |
| 当前尝试 | 确切聊天、题目／邀请引用、上一尝试引用、独立作答或补教阶段、是否仍待回答；用于接续真实问题 |
| 显示范围 | 本次题目及对话显示起点；用于刷新恢复和隐藏此前讲解 |
| 实际帮助 | 本次交付的提示、补讲、解答及本应用可观察的资料查阅；用于解释回答条件 |
| 作答和判断 | 确切用户原话、所回应问题、帮助引用、成立与缺失的依据；用于反馈和完成判断 |
| 返回现场 | 原阅读／课程位置、草稿及既有现场引用；用于暂停和退出后接续 |

模式生命周期复用拥有者的暂停、结束与目标修订。尝试只需表达待答、受助后待独立重试、已独立完成或未完成离开等实际状态；不另建与聊天、教学事实竞争的消息存储。新的目标和来源版本按原绑定规则处理，旧表现仍指向当时任务。

### 4.2 每轮执行

```text
明确开启并绑定当前目标
  → 保存原现场，进入闭卷显示范围
  → 交付一个问题，等待用户实际回答
  → 按回答认可／追问／补教
      → 未提供答案支撑：继续当前尝试
      → 已提供支撑：保存帮助，转入新的独立尝试
  → 引用足够的独立回答，收束本轮
  → 展示完成反馈，恢复资料入口，等待继续
```

每次模型回合读取模式约定、当前目标与完成条件、已交付问题、确切回应、相关帮助和用户当前可见范围。Agent 可读原文及教师上下文，但不能假定用户此刻可以看到原文、侧栏或旧解答；必要题干信息应在本题提供。

教学判断采用原始表达和实际帮助，宿主核对引用属于当前目标与尝试、问题确已交付、当前回应确实存在。准备中的问题、失败交付、旧题的答对和空回答均不能完成新尝试。沿既有提交身份和交付边界处理重复发送、失败重试与暂停后的回包，不引入额外模型裁判回合。

### 4.3 表现与进度

概念复述、自行解释、受助完成和独立应用按实际任务区分。学习者反馈可写“你这次已经能自己解释为何保留这一半”或“你在提示后完成了推理，接下来用新条件试一次”。模式是否结束、某题是否正确、课程是否推进和后续理解判断分别由已有对象承担。

同一目标存在多项必需关系时，判断须说明哪些有原话依据、哪些仍缺；已足够就完成，不要求固定轮数、字数或连续正确次数。用户指出题目缺条件、合理反例或 Agent 判断错误时，先核对并修正题目／反馈，保留原表达，不将教师错误算成用户失败。

课程中取得的独立表现作为原课程判断的输入。已完整满足原题要求时沿原规则接纳，缺少原课程必需步骤时继续显示待完成；闭卷结果不得直接将整课改为完成。

### CB1：从讲过的概念到一次闭卷独立表达

在当前 Tutor 增加显式入口、模式保存和单一闭卷视图，目标来自已交付内容；开启后实际发出首问请求。让用户提交回答，Agent 能针对缺口追问，充分回答后引用依据收口；待答问题和显示起点在刷新后保持。首片包含最小暂停／退出、原现场恢复和求助事实保存；需要独立重试但该链路尚未完成时保留待验证状态，不宣告成功。

完成依据：一个真实概念在实际页面经前后端完成“开启—作答—追问—再答—完成”；能复现“懂了”未被计作完成、等价表达被接纳，以及回翻历史不能显示进入前讲解。CB1 未覆盖的补教重试与课程入口按待实施处理。

### CB2：补教后重新观察独立表现

贯通提示、完整讲解、引导中实际给出答案、同目标新题和新显示起点。接通既有题目与评估，针对本模式显式覆盖普通练习的回应停顿与提示交付规则。保存尝试间关系，判断读取本次回答之前实际提供过什么，充分回答后停止。

完成依据：真实概念和题目各走一次受助到独立的完整过程；同题照搬解答不通过独立判断，新情境的合理解法可通过；补教后不丢原目标，也不额外扩展考查内容。

### CB3：完整闭卷边界与中断接续

统一 Reader、来源预览、笔记、演示、知识地图、历史回看和受支持导航入口的行为，接通查看资料后离开、返回后的独立重试。覆盖草稿、刷新、应用重启、断网重试和窄屏；新题生成失败保留原尝试事实与可重试入口。

完成依据：实际操作所有涉及当前学习现场的资料入口，没有直接在闭卷视图展开旧讲解的路径；退出恢复原阅读位置和草稿；纯刷新不改变受助状态，查阅后不能续接为原题独立通过。桌面与窄屏均直接查看布局和完成一次作答。

### CB4：课程中的闭卷阶段

从当前课程概念或题目显式进入，归属同一 `CourseRun`。切换时保存活动、实验及草稿，闭卷期间只保留一个作答入口；题目必需条件转为固定题面。补讲先使用对话，需要原文或实验时返回原课程现场。退出、恢复和结果展示接续同一课程事实链。

完成依据：一门现有真实课程完成进入、求助、独立重试和返回；原实验与草稿保持，帮助沿原记录可追溯；闭卷成功只按原课程任务接纳，不绕过尚缺的课程步骤。原课程普通回看与自由答疑继续按原模式工作。

### CB5：真实内容、交互与交付记录

选项目现有真实材料中的一个概念、一道已讲过的题和一个课程任务，沿当前已配置模型执行。留存题面、关键问答、实际帮助、判断理由、暂停恢复与最终视图证据；对真实失败修正后复验对应路径。实现记录放在项目既有 `docs/evidence/` 或实施记录位置，并从本节链接。

完成依据：第 6 节相关行为在真实链路成立，资料隐藏和输入体验通过直接视觉验收，未通过场景明确保留。真实学习效果另由目标用户试用观察；未取得试用证据时不宣称已验证长期保持或学习效率。

## 6. 验证如何改变实现判断

每项验证在对应切片执行；以下为计划，尚未运行。

| 场景 | 要发现的具体失败 | 失败后修改位置 |
|---|---|---|
| 进入、刷新、向上翻、来源／笔记／演示入口及窄屏切换 | 已讲答案或其他材料仍可在闭卷现场看到，或恢复时短暂显示 | 原对话宿主的显示投影与 Reader 入口；同时核对后台返回的当前状态 |
| 用户只说“懂了”、抄答案或仅给结果 | 无所需解释依据就完成 | 主讲判断合同、当前尝试回应绑定与完成接纳 |
| 已充分的等价表达、合理不同解法 | 机械匹配或继续加码造成无法收口 | 当前目标的语义判断与结束规则 |
| 提示、补讲、带答案的追问后再答 | 忽略帮助，把受助推理最后一步记作独立 | 交付帮助事实、尝试关联和理解依据 |
| 隐藏旧答案后原题重答，与未被代答的新条件对照 | 仅因提示不可见就洗掉受助条件 | 新尝试选题和判断所读取的历史帮助 |
| 暂停／重启、提交失败后重试、查阅资料后返回 | 草稿丢失、重复题目、旧回包继续推进或查阅状态丢失 | 原生命周期、提交身份、返回现场与尝试投影 |
| 开启、切换历史聊天、在新聊天继续学习 | 开关打开却不出首问，或旧邀请被错误移入另一聊天 | 开启请求发送、尝试聊天绑定及恢复入口 |
| 课程目标练习通过与未完成课程步骤并存 | 新模式越过原课程推进要求 | CourseRun 绑定、表现回传及课程原判定 |
| 用户提出有效反例或指出缺条件 | 教师错误被记录为用户失败 | 题目修订、回应判断和证据修正 |
| 未开启模式的普通练习和课程 | 新分支改变了原提示、停顿、回看或推进行为 | 模式适用性与原路径分支 |

纯状态与引用错误使用既有单元／服务端测试；真实语义用代表性模型对话及确切原话判断；可见范围与交互使用实际浏览器。页面只有 DOM 断言或编译通过不足以证明闭卷体验成立。已有检查通过后，只因新改动、失败或未解决的具体疑点扩大验证。

进入、隐藏、切换、恢复和历史过滤由宿主完成，不额外请求模型；每次教学回应复用原运行链路。CB5 同时记录代表流程的回合数、等待与既有调用费用，识别重复生成或为状态切换新增的调用；若出现这些成本，修正重复路径后复验同一流程。

## 7. 已知限制

- 当前题面实现支持文字、公式与 Markdown 表格；配图与交互实验使用原学习现场。具体验证证据及真实学习效果的边界见[实施记录](实施记录-闭卷对话练到会.md)。
- 闭卷边界覆盖本应用的练习现场，外部自行查阅依赖可观察事实或用户说明；模式不是考试监考认证。
- 刚教后的独立解释、当次独立应用、延后检索与长期保持各有自己的证据范围。反馈与理解记录保留实际任务及帮助条件。
- 必需复杂演示或实时实验的学习先在原课程／教学现场完成；进入闭卷时只保留可完整表达任务的题面条件。无法这样表达的任务继续使用原活动，不强行套入本模式。
