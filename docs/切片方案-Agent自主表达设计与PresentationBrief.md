## 0. 目标、范围与证据基线

### 0.1 FrozenIntent

让用户以自然语言表达问题或困惑，Resident Agent 在当前书籍证据与阅读现场中，自主选择并制作有解释力的表示。Agent 可以先做小原型，再依据实际观察改变表示、案例或讲解顺序；不要求用户提前给出控件、布局、状态字段和测试步骤。

`PresentationBrief` 是待验证的可选增强，用来保存成品中不容易直接恢复、但会影响后续修改的设计意图。它伴随作品演化，不是前置施工图。自主表达能力的改进不以保存 Brief 为前提。体验方向是用户指定的 Ciechanowski 式可探索解释；本方案采用“让关键关系变得可见”的目标。

普通富排版、静态图文、交互讲解、教具和连续叙事均可使用。小原型只是制作策略，不是内容规模的永久上限。材料不足、普通短答、非数值文本、当前状态解释和纯布局修改，都不能被强制塞进同一教学流程。

本轮同时解决已反馈的两类体验问题：演示页正常点击与参数调整时保持画面、布局和焦点稳定；Agent 可按需调用 Python 制作专业静态图，再嵌入原演示内容。静态绘图与浏览器实时交互分别选用合适工具，图的制作质量与表示是否解释了问题分别判断。

### 0.2 本轮不做

不新增强制 `presentation.plan`、规划 Agent、Brief 数据库、通用 skill 市场、全学科模板枚举或新的学习状态判断。没有必要为了降低用户 prompt 压力，先建立一个更复杂的 Agent 编排系统。

沿用现有来源、页面隔离、Reader 权限、版本归属与正式教学边界。Python 与 Matplotlib 是制作宿主的明确依赖；交付页面继续自包含，不在浏览器联网加载库，不要求手机安装 Python。首版不接通用终端、任意安装依赖、Plotly 打包平台或每次拖动都重跑 Python 的交互服务。

## 1. 所有权与工作过程

### 1.1 最小所有权分工

| 所有者 | 本轮职责 | 不负责什么 |
| --- | --- | --- |
| 用户 | 表达目标、困惑、必要的个人约束，以及对结果的反馈 | 编写教学规格和页面实现要求 |
| Resident Agent | 选择表示、构造有标注的例子、编写候选、解释观察并改变设计 | 授予权限、伪造来源、自行认证学习效果 |
| Runtime | 按需加载 skill、绘图能力发现、预算与取消、结果投影及交付门槛 | 根据学科查表决定所有页面形状 |
| Server / 存储 | 确切版本与会话归属、执行绘图并保存版本资源、可选 Brief 与同候选上下文 | 自动重写设计目标或补造旧版 Brief |
| 浏览器与呈现宿主 | 连续渲染、局部公开内容校验、真实操作与现场保存 | 执行 Python、将页面自报结果视为独立证明 |
| 验收与研究 | 独立检查目标达成、正确性、用户负担和迁移表现 | 只用 Brief 自评替代实际观察 |

原文、用户原话、已保存现场与 Agent 的设计假设应有不同来源标记。当前阅读位置和选区沿用既有上下文；不要另建一份通用 `TeachingContext`。可以利用已有的可靠偏好，但不能因一句“没理解”就推断永久能力缺陷。

### 1.2 接入后的主路径

```text
当前问题 + 必要的原文/选区 + 既有版本/现场
  → Resident 决定是直接回答还是制作内容
  → 需要时按现有 tool.search 激活 presentation_authoring
  → 工具可见时加载短核心设计说明与制作合同
  → Agent 提出暂定表示，写第一版；ED3/ED4 沿用无 Brief 的现有合同
  → 需要静态图时调用 Python 绘图入口，观察图像后取得宿主资源引用
  → presentation.author.write(内容；仅 ED5 接入后可附 brief)
  → presentation.author.preview(candidate_id, actions, viewport)
  → 后续采样获得对应候选、环境与步骤的真实观察（包括失败及部分完成）
  → ED5 启用 Brief 时，一并取得该候选的可选设计数据
  → 检查代码与表达；必要时新 write 并再次 preview
  → 当前合同要求的环境全部完成且经过后续采样观察后，presentation.author.deliver(candidate_id)
  → 原内容版本保存、回答引用挂载和历史提交
  → Reader 中连续操作；变化内容经公开合同处理，保存状态不触发整页加载态
```

Brief 不单独触发一次模型请求、不增加用户审批、不增加每次必调的工具。在同次 `write` 中提交 Brief 与 HTML，不能证明模型实际思考的先后顺序；我们需要的是可回读的设计摘要和可用的反馈，不是记录或验收模型完整推理过程。

### 1.3 不同请求的参与方式

以下表格是生命周期说明，不作为逐条路由规则塞进 prompt。

| 用户请求 | 处理方式 |
| --- | --- |
| 简单定义或一句话解释 | 可以直接回答，不发现制作能力，不生成 Brief |
| “做一个让我能试的解释” | 结合当前材料选择表示；需要制作时生成可选 Brief |
| “这段讲直观一点” | Agent 判断静态、交互或换一种文字；不因关键词强制启动模拟器 |
| “解释现在的结果” | 使用绑定的确切版本与已保存状态；不默认新建或编辑页面 |
| “这个例子看不懂，换一种” | 读取实际对象；保留用户问题，允许更换方法、例子与 Brief |
| “只改字号、布局” | 保留解释意图、来源和有效状态；不重新检索或重做教学设计 |
| “把前一个版本改一下” | 读取并编辑明确旧版本，不默认换成最新版本 |
| “重试” | 复用仍有效的用户目标与持久引用；重新发现本轮能力，不复用失败运行的候选句柄 |

多个对象且现有上下文无法确定时，只澄清对象身份；原文不足以支撑结论时，只补必要证据或说明缺口。不要把本可由系统决定的技术细节变成用户必答问题。

## 2. 最小数据合同

### 2.1 新增类型

下列代码是 ED5 条件性试接时的目标形状；ED3/ED4 不新增此类型。

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
#[serde(deny_unknown_fields)]
pub struct PresentationBrief {
    pub aim: String,
    pub approach: String,
    #[serde(default)]
    pub checks: Vec<String>,
}

// 添加到私有 PresentationContent。
#[serde(default, skip_serializing_if = "Option::is_none")]
pub brief: Option<PresentationBrief>,

// 添加到 AuthorRequest::Write，并同步实际工具 schema。
#[serde(default)]
brief: Option<PresentationBrief>,
```

Brief 不含 `method_type`、`teaching_mode` 等封闭学科枚举，也不新增 `approved`、`verified` 或 `mastery` 字段。`checks` 是自然语言检查意图，不作为脚本、shell、选择器执行指令或自动执行权限；即使文本描述了某个操作，也不能直接执行。需要执行的动作仍由已有类型化 preview 合同提交。

### 2.2 字段语义与缺省

| 字段 | 含义 | 不是 |
| --- | --- | --- |
| `aim` | 这次希望使读者看清的关系或问题 | 用户已经掌握/不掌握什么的确定结论 |
| `approach` | 当前采用的表示和解释方法，可在观察后改变 | 不可修改的施工要求、完整推理过程 |
| `checks` | 检查表达是否成立的具体观察问题，可为空 | 检查结果、自动执行程序或通过凭据 |

Brief 应优先保留跨轮编辑需要的设计意图。例如第 5 节可记录：`aim` 为区分同侧接近、跨越最优点与距离增大；`approach` 为展示带符号的位置变化，因为仅看损失会丢失方向；`checks` 为损失下降速度相同的两例是否仍能看出不同运动。仅罗列“滑块、曲线、卡片”可从成品直接恢复，通常不值得重复保存。同轮目标对照的额外收益与跨轮保留意图的收益分别评估。

`brief` 缺失或为 `null` 均表示本候选未记录 Brief；不能仅因此拒绝制作、预览或交付。存在对象时，`aim` 与 `approach` 须为非空文本，`checks` 元素须为非空文本。字段格式错误仍返回正常的参数验证错误；“可选”不表示可接收任意形状。

为避免简报变成长上下文，ED5 可从以下工程预算起步：完整 Brief 序列化后不超过 4 KiB UTF-8，`checks` 最多六条。这是可通过测试调整的输入预算，不是每次都应填满的内容模板。工具 schema 与 Server 校验保持一致；schema 无法表达精确字节限制时，由 Server 返回明确实际错误，不静默截断意图。

### 2.3 写入、编辑与版本

ED5 接入后，`write` 总是提交本候选的完整可选 Brief，不另提供 Brief patch。采用单一缺省语义：**省略/`null` 均不自动继承旧 Brief**，避免换了表达方法却悄悄保留过时设计。

编辑 Agent 先读旧版，根据任务显式复制、重写或省略 Brief；用户不需要知道这些操作。纯布局编辑应保留解释意图，通常复制旧 Brief 即可；换例子、换模型、换表示时重新判断。旧版没有 Brief 时允许直接修改，也允许给新版本记录新的设计，不能回写旧版或声称恢复了原设计。

预览后需要改变表示时，提交新候选 C2；C1 不覆盖。二者的 Brief 各自对应自己的内容。编辑中 `based_on` 始终是所选的已交付版本，不把 C1 的临时 ID 填入 `based_on`。不为设计草图单独增加候选血缘图。

一个 Brief 即使文字不变，也不能作为新候选的预览凭据。Brief 有变化时同样走既有预览和交付；不增加特殊的“设计修改进展奖励”，不重置无进展计数或总预算。

### 2.4 与已有字段的关系

`readable_content` 描述实际公开内容，Brief 描述当前设计意图；二者不可互相替代。`assumptions` 仍承载自拟例子、简化模型与适用边界；`source_bindings` 仍由已有证据编译器产生；`state_contract` 与 `initial_state` 仍定义页面参数及兼容性。Brief 不复制这些权威数据。

如果 Brief 中提出的说法要进入公开页面，仍须通过原有来源与公开语义处理。不能通过把一个主张写进 `aim` 或 `checks`，使其自动成为已核实书源事实。

### 2.5 读取、公开投影与历史

`presentation.author.read` 在原版本元数据中返回可选 Brief；分段读代码时，模型上下文投影应避免无意义地重复多份设计数据。无需为了一个小字段扩展通用读取平台。

默认不将 Brief 加入公开 `PresentationView`，也不因为新增私有类型就手工修改前端生成类型。后续若设计公开展示，再通过权威 Rust 类型、既有生成流程和公开内容校验单独接入。

Provider 历史继续保留版本身份与精简回执，不保留整个 Brief 和 HTML 的多份副本。持久内容中的 Brief 不等于必须每轮回放的消息。旧历史和旧内容缺字段须兼容读取。

## 3. Skill 与上下文的接入方式

### 3.1 单一来源、按需加载

建议新增 `skills/presentation/SKILL.md` 作为核心表达方法资产，并由 `crates/runtime/src/agent_prompt.rs` 在 `presentation.author` 可见时装配为一个版本化 `InstructionModule`。这是拟新增路径，不是当前已经可发现的 skill。

第一轮可采用编译时嵌入，使 Windows/Tauri 与 Linux 二进制拿到同一份核心文本，不依赖部署机器存在仓库 skill 目录。仅放文件不会自动生效；须验证最终 Provider 请求确实含有该模块。若文件含 frontmatter，正文抽取方式须明确且有测试，不因解析格式不同产生两套实际指令。

核心 skill 负责表达设计；已有工具 schema 和最小协议说明负责调用合同；Server/宿主负责可确定性执行的限制。不要把旧制作指令全部复制一份到 skill 里。技能版本或内容标识应进入现有请求审计，便于还原评估条件。

平时沿用现有能力发现目录，用一句说明让 Agent 知道：当视觉比较、操作或过程展开有助于回答当前问题时，可以发现相应制作能力。完整设计说明只在工具可见后加载，不引入关键词强制激活规则。

发现与设计分别定位失败：没有发现所需能力时检查常驻能力描述与发现入口；发现后表示选错时调整按需表达说明；表示合理而实现失败时检查工具、宿主或必要辅助能力。不能将三类失败都归因于 skill 不够长。ED3 对照中的能力描述保持一致；若另需修改发现入口，作为单独变更复跑对应任务并记录，不能混称为核心说明收益。

### 3.2 第一轮核心正文提案

下面是可以用作 ED3 起点的短正文；不包含后文的测试题和验收标准。

```text
围绕读者当前的问题和已核实材料，选择能让关键关系变得可见的表达。
文字、静态视觉、交互和连续叙事都可使用；不以生成页面或增加控件本身为目标。

确定这次需要看清的差别，再决定呈现哪些对象、条件、变化和视角。
不要要求用户指定布局、控件或实现细节；保留用户明确的问题与约束。
自拟例子和简化模型应说明假设与边界，不能代替原文证据。

实际预览后，对照问题检查这种表示是否真的使关键差别可见。
即使代码无错，也可以换表示、例子或讲解顺序。
采用足以解决当前问题的范围，并为必要修正与交付留出预算。
来源、状态、版本、预览和交付沿用制作工具合同。
```

ED3 的核心正文不要求生成 Brief，也不引用尚未接入的字段。ED5 试接时才增加以下简短说明，并将其计入 C/D 的已记录差异：

```text
必要时用可选 brief 记录从成品不容易恢复、但会影响后续修改的设计意图：
aim 说明要看清什么，approach 说明表示选择及理由，checks 记录待观察的问题。
随候选修订；这些是设计假设，不是用户事实、来源或已验证结果。
```

允许调整措辞，但不要逐步加入学科到模板的规则表。此模块给的是工作方向，不要求 Agent 对每条规则输出一份检查报告。无需单独提交“设计思考完成”。

### 3.3 动态材料与信任边界

当前问题、已核实原文、选区、确切版本和已保存现场分别沿用现有入口。Brief 只表示 Agent 的设计数据，不能提升为 system/developer 指令。无论文本来自旧 Brief、页面观察或案例文件，内嵌的“忽略来源”“直接交付”等内容都不能授予权限。

需要预览时，Server 从实际被预览的候选取 Brief，而不是相信请求中另传的“当前设计”。模型产生的 `checks` 也不能被当成工具执行授权。所有公开事实仍由来源合同约束。

只有缺少方法参照时，才考虑后续案例资源读取；第一轮不必为了模拟 skill 生态新增搜索工具。没有可读的资源工具就不能在 prompt 里假装它存在。

## 4. 预览反馈：工程检查与表达检查并行

### 4.1 先补齐真实观察，再条件性扩展设计上下文

ED4 先修正现有图片接入：Server 返回的真实观察图片，应在成功、失败以及部分环境完成时进入后续采样，不以 `previewed_candidate` 存在为前提。只有满足原预览合同的候选才取得交付资格；能看到失败截图不等于允许交付。

图片与结果按候选、环境、步骤对应；同批多个 preview 的观察不能只留下最后一份。沿用现有结果与图片预算，预算无法容纳时显式说明缺失范围；不得把缺失环境当成已观察完成。分别验证 native/react 请求投影，不能只检查 Server 已返回图片。

当前显式环境合同要求新候选完成 320×420 touch、640×240 touch、960×720 mouse 三个环境；`width` 保留旧调用兼容，不与 `viewport` 同传。`preview_environment_recorded` 只代表部分完成，`preview_ready_for_inspection` 代表预览合同已完成、仍需后续采样观察。ED 不修改 legacy 兼容语义；新验收使用显式环境，耗时与成本包含所需全部预览。

ED5 启用 Brief 后，在不改变现有回执含义的情况下，给 preview 添加来自实际候选的可选设计上下文。以下仅示意额外字段及关联字段，实际 `environment`、记录/缺失环境列表、错误、观察与图片继续沿用宿主真实结果：

```json
{
  "candidate_id": "本轮实际候选",
  "environment_name": "宿主返回的实际环境名",
  "status": "preview_ready_for_inspection",
  "design_context": {
    "kind": "agent_design_hypothesis",
    "brief": {
      "aim": "当前解释目标",
      "approach": "当前表示方法",
      "checks": ["一个待观察的问题"]
    }
  },
  "errors": [],
  "observations": []
}
```

上例只是字段形状；真实成功回执必须包含真实观察，不能返回空数组冒充完成。失败或部分完成时沿用相应 status，也可返回同候选的设计数据。Brief 缺失时省略设计上下文即可。同次后续采样中，同一候选的 Brief 只需提供一次，并与各环境观察保持关联，不在每张截图或每个 DOM 步骤重复。

`AuthorResult.body` 已能携带结构化结果，ED5 不必为此新建顶层协议或强制审查工具。必须验证经过结果 envelope、预算截断、上下文压缩及 native/react 请求投影之后，设计上下文与相应截图仍能在同次后续采样中正确关联。出现截断应显式体现，不把部分结果当完整检查。

### 4.2 四种结果不可混淆

| 结果 | 由谁提供 | 可支持的结论 |
| --- | --- | --- |
| 浏览器运行、操作与 DOM/截图 | 实际预览宿主 | 页面在这些条件下实际呈现了什么 |
| 已知算例或不变量验证 | 独立于页面自报的测试 | 这些输入和范围内的计算符合预期 |
| 表达是否回应问题的判断 | Agent 与独立评审 | 当前表示是否暴露了需要解释的关系 |
| 用户解释或迁移表现 | 用户行为及相应评估 | 在明确任务和条件下观察到的理解表现 |

现有运行时门槛保留，不新增 `pedagogy_pass` 布尔自证。Agent 依据观察决定是否换方法，但最终产品评估仍需独立检查。不能因 checks 都写“通过”，或页面自报“验证成功”，就跳过真实操作和来源校验。

### 4.3 设计失败也是可以修正的失败

如果目标是解释位置来回变化，只有一个数值下降曲线可能不足以解释。此时应允许改表示，而不是把字体调大后宣称完成。修改后产生新候选、重新观察；旧候选的成功预览不能迁移到新版。

不是每个任务都必须先失败一次。Agent 第一次就选到合适表示时，可以直接交付；不能为证明“会探索”而强制列出三个方案、生成三个完整页面或反复重写。

预算不足时，保留已交付旧版；未完成的新候选不发布。可以诚实给出完成范围与仍有的缺口，不能通过修改 Brief 的目标、虚构观察或略过 `deliver` 制造成功。也不要增加无法提供新信息的复查循环。

### 4.4 状态与交互的现有边界

当前 preview 的状态保存回调与真实 Reader 并不等价，因此初轮仍必须进行实际保存、重开、追问与同版恢复测试。Brief 不是解决恢复 bug 的替代品。

当前支持 click/key；可用这些真实操作验证原生控件和按钮。未实现拖拽预览前，不能把程序直接改值称为“拖拽已测试”，也不能仅凭渲染截图承诺复杂触摸操作可用。后续新增动作见 ED9。

## 5. 一个用于验证表示选择的样例

本节是自拟测试材料与评审依据，不是生产 skill 的固定模板，也不得连同设计答案一起偷偷注入自然请求测试。

用户请求：**“学习率大一点，为什么会来回跳，甚至越来越远？让我能看出来。”**

为满足现有书内证据约束，测试书籍明确提供简化模型及适用范围：

\[
L(w)=(w-2)^2,\qquad w_{t+1}=w_t-2\eta(w_t-2).
\]

取同一个非最优初值，例如 \(w_0=0\)。记 \(e_t=w_t-2\)，则 \(e_{t+1}=(1-2\eta)e_t\)。这是独立可计算的测试关系，不依赖页面自己的“正确”标签。

| 学习率 | 误差变化 | 可用于核对的现象 |
| --- | --- | --- |
| 0.2 | 每步乘以 0.6 | 同侧接近最优点 |
| 0.8 | 每步乘以 −0.6 | 两侧交替接近最优点 |
| 1.1 | 每步乘以 −1.2 | 两侧交替且距离增大 |

前两种学习率的损失均每步乘以 0.36。因此，一个只有损失曲线的页面，即使计算完全正确，也不能仅凭这条曲线区分是否来回跳。

合格的设计可以采用参数位置、带符号误差、更新箭头、分步数字对照或其他有效表示；不要求固定控件或唯一布局。只要读者能够看出跨越最优点与距离变化，并明确知道临界值只属于该简化模型，就有可检查的表达依据。

把“只展示损失曲线”作为预置失败内容时，可验证 Agent 能否修改不合适的表达；这个用例属于针对性修复测试，不能冒充完全自然的首轮设计成功率。自然生成评估另行保留，允许一开始就设计正确。

至少再安排一个非数值材料：从测试原文中辨析“作者明确声称了什么”与“读者推测了什么”，或展示两种有证据的解释视角。验收不要求生成模拟器、因果按钮或虚构数值结果。

### 6.2 ED1：演示页点击稳定性修复

**输入**：第 0.3 节的 bridge/CSS 最小复现、实际 `AgentPresentation` 组件、来源拒绝与状态恢复回归。

**产出**：同一内容版本在普通点击、滑块及步骤切换时连续显示；首次加载、内容校验和现场保存各有独立状态，提示不改变演示区域位置。

**实施步骤**：

1. 先补会失败的浏览器用例：暂缓 observe 回执，点击后逐帧记录整页可见性、iframe 边界和焦点；再连续操作滑块。该用例必须检查等待期间，而非只等最终恢复可见。固定尺寸夹具单独覆盖首次出现保存提示时的布局变化。
2. 将首次加载与后续校验状态分开；“正在准备内容…”只用于首次加载。后续校验、保存和失败信息使用固定布局位置或不占文档流的提示；提示变化不触发 iframe 高度重新分配。
3. 将新公开内容的校验与整页渲染分开：保留已通过的内容及活控件，只暂缓尚未通过的新文字/来源发布。正常局部图形更新保持可见；需要阻断时保留受影响区域上一份已通过的展示，不能以全页空白代替。实现从现有 bridge 和编译器的真实拒绝用例出发，确定最小变化区域及接受/拒绝处理，不复制一套语义规则或新增通用渲染引擎。
4. 保持同版本 iframe 实例和 srcdoc 稳定；主题、保存回执和父组件更新不重载内容。检查容器测量是否被子内容反复影响，只修实际复现的尺寸反馈。
5. 现场快照只记录对应已接受观察的实际参数与结果；校验拒绝沿用明确失败语义，取消或换版本时旧回执不改变新现场。输入操作与保存仍沿用既有事件边界。

**公开合同**：不以删除隐藏 CSS、跳过校验或先显示后拒绝作为完成。新增无效来源和内部定位标识仍不能在用户可见帧中发布；不能仅根据字段名或数值外观认定内容无需校验。复杂 DOM 整体替换也必须覆盖，不能只修一种由测试指定的页面结构。

**主要位置**：`packages/web/src/components/AgentPresentation.vue`、`packages/web/src/presentation-bridge.js`、`packages/web/src/presentation.css`；需要调整公开校验衔接时核对 `crates/server/src/presentation_api.rs`，复用原判定。验证复用 `presentation-bridge.spec.ts`、`agent-presentation.spec.ts`、follow-up/recovery 用例和组件实例连续性用例。

**要发现的失败与处置**：等待回执时全页隐藏或提示造成位移 → 修渲染/布局；控件失焦或 iframe 重载 → 修实例与焦点生命周期；新来源/内部标识短暂可见 → 修局部发布边界，不能交付；快照与当前图形不一致 → 修观察与保存关联。

**完成判据**：固定尺寸场景连续点击、滑块操作及迟到回执期间无全页隐藏、无提示引起的 iframe 位移，load 次数不增加、焦点和滚动位置不被宿主打断。真实内容展开可产生预期布局变化。动态非法内容拒绝、来源跳转、保存、重开和现场追问仍通过。先在真实浏览器确认，再在发布涉及的 Windows/Tauri、Linux 与手机入口检查对应交互。

### 6.3 ED2：Python 静态绘图接入

**输入**：ED1 稳定宿主、当前 Resident 能力发现及制作链路，曲线/比较图和含中文、单位、图例的少量真实任务；采用前先保存同题现有浏览器绘图结果。

**产出**：Agent 能调用 Python + Matplotlib 制作静态图，收到图像和执行错误并修正；图随演示内容版本保存、展示和重开。首版必需格式为 SVG，PNG 仅在本轮任务确需栅格输出时补齐端到端 MIME/装配覆盖。

**已接入的最小工具合同**：

```text
presentation.author(operation="render_plot", code, data?, size?)
  → 图像预览 + asset_ref + MIME/尺寸 + 有界错误信息
presentation.author(operation="write", html, readable_content, asset_refs?, ...)
  → 宿主解析引用、装配版本资源 → 原候选
```

`render_plot` 位于既有 author 能力内；`size` 为像素宽高，`write.asset_refs` 指向本轮返回或基准版本列出的 SVG 图像引用。Python 依赖由制作宿主按 [固定版本清单](../scripts/presentation-plot-requirements.txt)安装，运行时不安装。

**实施步骤**：

1. 给制作宿主配置可复现的 Python/Matplotlib 环境，记录库版本和中文字体；Windows 与 Linux 分别验证，不依赖 Codex 本身的工具环境。首版使用无窗口绘图，沿用 Resident 的预算、取消与终态，限制单次运行时间、输出大小并回传执行错误；不在任务中自动安装包。
2. 工具接收绘图代码与必要数据，在本次制作的临时工作目录运行；Agent 可自由组织图形。提供统一的中文字体、字号、线宽、配色、边距与背景默认值，不把图表类型固化成学科模板。新入口服务绘图，输入不使用 shell 命令拼接。
3. 将实际输出图像投影到后续 native/react 模型请求，SVG 必要时由宿主渲染成观察用图片；保留绘图错误和真实图像的区别。图片预览用于 Agent 检查，不能只返回“文件生成成功”。
4. 宿主返回可用资源引用，`write` 接收引用并装配到自包含版本内容；模型不搬运图片编码，不将临时文件路径写进网页。预览与 Reader 使用相同的资源解析语义；图片资源按真实 MIME 处理，装配后按实际候选大小校验，不能通过引用绕过现有体积限制。
5. 图像字节随候选和已交付版本固定保存，重开显示不重跑 Python；取消的临时结果不替换已交付版本。确切版本 `read` 提供图像清单及按需可读的复绘代码/输入，编辑可复用原图或生成新图，旧版仍引用原资源。复用已有内容存储，不新增独立资产数据库。
6. 将关键图中文字、单位、图形含义、假设和来源写入可回读内容，沿原来源合同与真实图像观察核对；出图不授予事实或来源身份。页面缩窄、主题切换、重开及后续编辑均使用实际产物验收。

**交互边界**：实时滑块、动画和几何演示继续由浏览器 SVG/Canvas/JavaScript 更新，不在每个输入事件重启 Python 或替换整张静态图。确需重计算出新图时作为明确制作动作，完成后进入新候选预览。静态图会更规范不等于选对了表示；解释质量仍按第 5、7 节判断。

**主要位置**：两侧 `presentation_author.rs`、`presentation.rs`、Runtime 工具发现/图片投影、Server 绘图执行与存储装配、`presentation-document.ts` 及部署依赖入口。实施前确定原 author 边界内的具体文件，不建立平行制作系统。

**要发现的失败与处置**：实际宿主缺依赖/中文字体 → 修部署；图已生成但模型未看到 → 修结果投影；图片只存在临时目录或重开丢失 → 修版本资源；SVG/PNG 类型误判或预览与 Reader 不同 → 修装配；取消仍留执行进程 → 修生命周期；图更好看但计算或含义错误 → 修输入/表示，不能以绘图成功交付。

**完成判据**：至少一条真实 Resident 路径完成“绘图 → 观察 → 写入页面 → 原预览/交付 → 重开”；绘图错误可用于修正，取消可停止执行。已知数据点、坐标单位与中文标签正确，窄屏图例不裁切；换图生成新版本、旧版仍可见，现场追问可取得图的含义。相同任务下分别记录绘图实现质量、解释效果与新增成本，依赖发布范围对应实际验证的宿主；手机只显示已保存资源。

### 6.4 ED3：自然请求基线与短表达说明

**输入**：ED1/ED2 完成后的共同工程底座、既有普通/交互回答夹具，以及含普通短答、表示盲区和非数值材料的少量自然请求与稳定材料。记录修复与绘图能力均已包含，B/C 只比较短说明。

**先记录基线**：保存改动前模型、实际 prompt 模块、工具 schema、源材料版本、预算、耗时和全部原始结果。运行前记录本批要观察的差别及可接受成本范围。详细工程请求 A 沿用既有参考；先比较相同自然请求的 B/C，不先实现 Brief，也不新增实验平台或生产 feature flag。

**实现**：

- 新增第 3.2 节的短核心 skill 资产，通过现有 `policy_modules_for_tools` 按需注入，给予可追踪版本标识；不含 Brief 专用说明。
- 验证最终 Provider 请求实际加载该说明，普通回答不加载完整制作 skill。
- 在一个实际宿主运行第 7 节的小规模 B/C 对照，按能力未发现、表示选择错误、观察不可达和工程失败区分结果。发现入口若需修订，单独记录与验证。

**要发现的失败**：核心说明没进实际请求；普通短答加载长指令或无故制作；需要制作却未发现能力；表示仍不能揭示关键差别；短说明导致返工或成本增加。

**完成判据**：说明实际加载且不增加固定模型回合；B/C 原始结果、成本及失败原因可回读，能决定保留说明、调整发现入口或优先修复反馈。实验完成与表达效果改善分别报告；不把本阶段的观察缺口归因于没有 Brief。

**定向验证**：模块按需加载与实际请求投影；自然请求的可见产物及必要独立算例。新增用例只覆盖本次改动可能产生的具体失败，复用已有制作工程回归。

### 6.5 ED4：真实预览观察补齐

**输入**：ED3 基线、当前真实预览与图片投影；第 0.3 节已确认的失败/部分完成图片接入缺口。

**实现**：按第 4.1 节将观察图片投影与交付资格分开；失败、部分环境完成以及同批多个 preview 均保留可用的候选/环境/步骤关联。保持原交付门槛、预算和取消。仍由原 Agent 在后续采样选择修正或交付；本切片不新增 Brief 字段或 `review` 操作。

主要位置：`crates/server/src/presentation_author.rs`、`crates/runtime/src/orchestrator.rs`，以及当前实际负责结果/图片投影的模块。变更前按符号确认位置，不因本方案提及就创建平行实现。

**要发现的失败**：失败或部分完成的截图未到模型；同批只保留最后一份图片；候选/环境对应错误；预算截断被误认为完整观察；收到失败图片便取得交付资格；同批 preview/deliver 绕过后续采样。

**完成判据**：实际 native/react 请求包含可用的失败及部分完成观察，同批结果保持正确关联；原交付门槛有效。再针对第 5 节的预置表示缺陷，观察真实模型是否能基于反馈换出可分辨目标现象的表示，数值由独立检查核对。若仍失败，记录具体结果，不以修好了图片传输代替表达改善证据。

至少保留一条“页面无脚本错误，但表示不足”的修正记录，不能只用注入 JavaScript 异常证明表达设计能力。脚本化夹具测试与真实模型测试分别报告。

### 6.6 ED5：可选 Brief 最小试接与收益验证

**启动条件**：ED3/ED4 后仍有值得验证的设计意图用途，例如跨轮换表示时丢失原有解释目标，或预览后难以对照表示选择的理由。先记录具体假设及对应任务；工程参数错误、状态恢复故障和能力未发现不构成接入 Brief 的理由。

**实现**：在私有 `PresentationContent`、`AuthorRequest::Write` 与实际 schema 增加第 2 节可选字段；沿原候选、存储、确切版本 `read` 和 preview 回执接入。仅此时追加 Brief 专用短说明。编辑显式复制、更新或省略 Brief，历史仍保留精简引用。无需新增存储目录、公开字段、前端表单或独立版本系统。

主要位置：`crates/runtime/src/presentation.rs`、`crates/runtime/src/presentation_author.rs`、`crates/runtime/src/agent_prompt.rs`、`crates/server/src/presentation_author.rs` 及原存储和请求投影测试。`follow_up_context` 仅在具体任务证明需要时加入所选版本的简短 `aim`；默认继续以真实状态、可回读内容和假设为解释依据。

**要发现的失败**：旧 JSON 解码失败；无 Brief 被拒；字段未保存或串版；省略却自动继承旧设计；设计数据与截图不对应；Brief 被提升为指令或交付凭据；仅修改 Brief 重置预算；元数据增加而编辑与表达没有收益。

**完成判据**：带 Brief 与缺省的原链路均可读写，旧版本不变；以相同反馈修正底座做 C/D 对照，至少包含换表示及隔轮继续修改，分别报告同轮和跨轮收益。无可见收益时记录“Brief 增益未证明”，ED6 选择不生成/注入 Brief 的方案；若已有试验内容，继续兼容读取，不删除历史。通过实验并不自动构成发布决定。

### 6.7 ED6：连续使用与发布验收

**输入**：ED1/ED2 的实现与验收证据、ED3/ED4 的选定方案、ED5 的采用或跳过结论，以及运行前冻结的任务、独立判断依据和成本/退化界限。Brief 不是进入本切片的前提。

**实现**：复用现有工程回归与真实 Provider 入口，用选定方案验证解释当前现场、局部布局修改、换例子、旧版修改、失败重试和实际 Reader 重开。通过回答中的实际引用确认交付，检查来源、操作、兼容参数和原版本不变。保存首次运行和全部重试；宿主回归不重复扩成每组都要跑的模型实验。

主要候选位置：新增 `packages/web/playwright/agent-presentation-design-live.spec.ts`；私有运行证据；新增 `docs/performance/agent-presentation-design-<date>.md`。新增文件名均为候选，应遵守项目现有测试配置与付费验收入口。

**要发现的失败**：简报写得完整却没有解释目标；只在熟悉题目上成功；隐性依赖工程 prompt；所有请求都变成模拟器；高成本反复重写；页面自评与实际行为相反；恢复或来源退化。

**完成判据**：工程回归与实际 Reader 连续使用通过，所选方案满足预先记录的质量与成本条件。工程可用、自主表达改善、学习效果分别报告；实验执行完成但未达到质量条件时，保留既有方案或仅交付已有独立收益的部分，不宣称整体目标达成。

表达效果先在一个实际宿主判断；仅对选定发布方案，在 Windows/Tauri 与 Linux 实际入口复核相关集成。涉及手机发布时补 iPhone 的实际阅读/交互样例。预览中的 touch 环境与容器尺寸不能替代整个手机 Reader 或真实触摸手势验收。

### 6.8 ED7：按需表达案例（条件性后续）

**启动条件**：ED6 显示 Agent 缺少可迁移的表示方法，而不是参数错误、状态恢复或 Provider 故障。

建立少量原创案例，记录“问题为什么难看见、采用了何种表示、何种观察揭示关系、适用边界”。案例不写成完整成品菜单，不收集全学科目录；避免直接把当前评估题的答案加入资源。

候选目录为 `skills/presentation/references/`。优先复用已存在且适合的资源读取能力；若实际没有对应能力，再在原制作能力边界内添加一个最小按 ID 读取的接口并记录 schema。不能在 skill 中引用模型根本读不到的路径。

资源内容版本化、大小有界、按需取得。外站只作为方法参考；默认采用自拟案例，记录来源与使用条件，不默认抓取全文、复制整页或执行陌生脚本。使用案例不产生书源引用身份。

**完成判据**：实际模型请求证明仅在需要时取得相关资源；加入资源后用未覆盖题复验迁移表现，报告额外成本和潜在套模板现象。去掉资源仍可正常使用原制作流程。

### 6.9 ED8：受控绘图与状态辅助能力（条件性后续）

**启动条件**：重复绘图、控件、状态读取/恢复等工程劳动占据主要失败与成本，而不是问题目标不清。

ED2 的 Python 静态绘图已经单独安排；本切片只处理其后实际暴露的辅助能力缺口，不重复建设执行入口或重新要求 ED2 等待启动条件。

每次只解决一个被实测证实的重复问题，例如可靠的时间控制或状态恢复辅助件。允许自由 HTML/SVG/Canvas 组织，不提供不可脱离的页面框架，也不为所有问题生成统一仪表盘。

资源通过明确版本的受控打包或宿主接口提供，遵守现有自包含与无外部依赖边界。接口需要同版重开、编辑兼容、预览与 Reader 一致性测试；新增能力不可绕过来源、取消或学习状态规则。

**完成判据**：相同任务下相应工程失败减少，自由表达空间未被封闭；旧内容不受新资源版本影响。若不能证明收益，不继续建设通用图形平台。

### 6.10 ED9：真实操作与连续叙事扩展（条件性后续）

**启动条件**：重要任务需要当前 click/key 无法充分验证的操作，或多场景内容已有实际需求。

以一个真实目标扩展最小动作，例如有明确目标与有界轨迹的拖动，或确定性的时间推进。分别定义坐标/目标、输入方式、超时、取消、结果观察和资源清理；验证鼠标操作不能冒充触摸覆盖。不能用页面脚本直接设值替代用户动作验收。

连续叙事先复用同一内容对象及版本、现有场景状态与展开宿主；只有状态规模、资产或生命周期确实不足时，再修订相应合同。不预先建设跨文章教学图或多文档编辑系统。

**完成判据**：实际操作可复现目标现象，错误和取消可观察，相关平台上保存恢复可用；性能、触摸与可访问性范围如实记录。只支持了一个新动作，不能宣称支持所有复杂模拟器。

## 7. 验收矩阵与对照设计

### 7.1 最小任务集

所有任务提供正常使用中应有的原文、选区、版本或现场；“短请求”不等于故意不给必要材料。隐藏的是实现规格与评审答案，不是任务所需的来源。

| 任务 | 用户请求示例 | 独立检查重点 |
| --- | --- | --- |
| 连续交互 | “继续下一步。”、滑块连续调整 | 等待观察回执期间不整页隐藏、提示不推挤画面、焦点与实例连续 |
| 专业静态图 | “把这几组变化画出来，比较差别。” | 真实 Python 输出、中文/单位/图例、数值正确、窄屏与图像版本保存 |
| 简单解释 | “这句话是什么意思？” | 能否直接回答，不无故制作 |
| 首次交互 | “这里我不理解，能让我动手试一下吗？” | 是否围绕当前问题设计有意义的操作 |
| 表示盲区 | 第 5 节学习率问题 | 所选表示是否区分同损失、不同位置运动 |
| 非数值材料 | “哪些是原文说的，哪些只是我的推测？” | 不虚构模拟或因果；证据与解释边界清楚 |
| 当前现场 | “为什么现在会这样？” | 解释确切版本和保存状态，不默认重建 |
| 换表示/例子 | “这样还是看不懂，换一个简单例子。” | 保持问题，能调整方法而不只改措辞 |
| 局部布局 | “只把字号放大一点。” | 不重做教学设计、不换来源、不丢参数 |
| 旧版与重试 | “改前一个版本。”或“重试。” | 版本正确，失败句柄不跨运行，历史不覆盖 |

这不是生产路由枚举。允许一个任务存在多种好答案；评审不要求同样的组件、参数名或固定 DOM ID。

### 7.2 四组条件

| 条件 | 用户输入 | 系统差异 | 用途 |
| --- | --- | --- | --- |
| A | 既有详细工程请求 | 既有工程验收条件 | 作为制作能力参考，不与自然输入混算，不要求每阶段重跑 |
| B | 自然短请求 | 本批实验的共同工程底座，不加新设计说明或 Brief | 测量本批基线 |
| C | 与 B 相同 | B + 核心设计说明，不生成/注入 Brief | 分离设计说明的影响 |
| D | 与 C 相同 | C + 可选 Brief + 目标对照反馈 | 条件性检查 Brief 的额外收益 |

ED1 使用确定性浏览器回归确认稳定性；ED2 用相同材料比较现有浏览器绘图与 Python 绘图，输入、说明与预算保持可比，单独报告工具收益。ED3 在已完成 ED1/ED2、尚未增加短说明的共同底座比较 B/C，两组绘图能力相同。ED4 修正观察链路后，如需复验 B/C，两组都采用该修正；ED5 的 C/D 必须采用相同的 ED4 底座并重新取得 C 的结果，不能将 ED3 旧 C 与修复后的 D 直接比较。每批记录底座和实际文件状态，避免将稳定性、绘图或观察修复归因于说明或 Brief。

同批比较保持模型版本、采样配置、材料、非实验部分的工具能力、发现描述和总运行预算一致；Brief 带来的 schema、元数据与提示差异完整记录。优先使用独立会话，运行顺序交错或随机化；跨轮任务在各自独立会话中执行完整用户序列，避免组间污染。A 仅作工程参考，不解释成 Brief 的因果增益。

初轮先选少量有区分力的任务做 B/C，覆盖普通短答、表示盲区与非数值材料；ED5 才扩展 C/D，至少含换表示和隔轮继续修改。对选定的核心任务，建议每组至少三次独立运行；预算受限时提前缩小任务集或重复次数并说明，保留全部失败。小样本用于定位问题，不宣称统计显著或稳定达到某一质量水平。效果实验先用一个实际宿主；已有来源、恢复、取消等确定性回归按改动影响复用，其他平台只对选定方案验证集成。

### 7.3 评审与观察指标

**工程指标**：实际交付引用、候选与版本正确、源文绑定、关键操作结果、状态保存与恢复、取消与失败保护。

**交互稳定性指标**：从用户动作到校验回执之间的逐帧可见性、iframe 边界、load 次数、焦点及滚动位置；固定尺寸夹具区分提示引发的位移与内容展开的预期变化。只检查最终一帧不构成通过。

**绘图指标**：已知数据点与单位、中文与图例完整性、窄屏可读性、主题下的对比度、实际图像进入模型、版本资源与重开一致性。表示是否使关键关系可见，另按表达指标判断。

**表达指标**：是否回应用户实际问题；关键差别是否可观察；表示是否会制造误解；假设与来源是否区分；用量与复杂度是否与任务相称。独立评审先看用户请求和产物，尽量不看组别或 Brief，避免把漂亮的设计摘要当质量。

**用户负担指标**：首次目标达成情况；后续需要补充工程/设计指令的次数；完成任务所需的澄清和重试；用户因未说明按钮名、版式或状态字段而失败的情况。

**成本指标**：端到端等待、模型采样数、Provider 实报 token、生成代码规模、预览次数、返工原因和取消。统计包含当前合同要求的三个显式环境及修正后的重预览，不按一次 preview 估算交付成本。多轮累计 token 不直接等于单次用户典型费用；没有账单数据不推算费用结论。

Python 绘图另外记录执行等待、输出大小、绘图修正次数与依赖准备成本；不将每次交互保存计成一次绘图，不将部署安装时间混作每页典型等待。

**学习观察**：用户是否能解释变化、区分相似新例或说明适用条件。该项另行取得证据；页面运行成功、点击和停留不等于掌握。没有实际用户任务时写“尚未评估”，不从 Agent 自评推出学习效果。

### 7.4 不把测试答案藏进用户 prompt

工程夹具可以保留固定元素 ID 来测试宿主；自然生成测试不能要求用户输入 `id=recall`、`scene.values.page` 或具体控件名称。自然页面验收先检查实际可访问结构和用户可见结果，再独立核对目标，不能强行要求唯一布局。

已知算例、恒等关系和必要边界来自独立测试材料或检查器。Agent 自己给出的 `checks` 可帮助复查，但不能决定全部评审范围。把预置差表示交给 Agent 修复的测试与自然首次生成的测试分开报告。

### 7.5 发布判据

工程硬约束不得回归；按实际改动影响复用旧文件、确切版本、来源、恢复、取消和预算相关测试。每批比较前记录质量目标、成本与可接受退化界限；ED3 基线可以帮助确定后续判据，不能在看完该批处理组结果后改判据。ED6 发布依据是选定方案达到这些条件，而非完成了规定运行次数。

若 D 相对同底座 C 没有明确收益，记录“Brief 增益未证明”，选用 C 或停止生成/注入 Brief；已保存试验内容继续可读。若 C 也未表现出收益，保留原方案，按失败类别调整。ED4 的观察修复可按独立工程证据交付。工程通过、表达设计表现、学习效果三种状态分别公布，完成实验不等于达到产品目标。

## 8. 失败处理、上线与回退

| 风险或失败 | 处理方式 |
| --- | --- |
| 正常点击使整页隐藏或提示推动画面 | ED1 分离首次加载、局部校验与保存；检查等待期间的画面 |
| 取消整页隐藏后非法动态内容短暂出现 | 修局部发布边界，保留来源拒绝与可见性回归 |
| Python 依赖/字体缺失、执行失败或取消 | 返回真实原因并结束执行；不交付缺图候选 |
| 绘图引用失效或重开丢图 | 修版本资源保存及 MIME 装配；已交付页面不依赖临时路径 |
| Brief 变成长篇规则或每题套模板 | 缩短核心说明；保持开放文本与可选性；按独立任务评估而不是补分支 |
| Brief 与页面目标不一致 | 下一候选修正方法或内容；不修改用户原始目标来过关 |
| 设计文本携带伪指令或未证实事实 | 保持数据身份；不提升来源/权限；公开使用仍走既有校验 |
| 新字段破坏旧文件、旧历史 | 采用可选缺省，先跑旧 fixture；不批量回写原内容 |
| 加入设计上下文后挤占交付空间 | 限制字段和重复投影，保留既有预算和收尾机制 |
| 失败或部分环境完成的图片未到模型 | ED4 修正图片接入；交付资格仍由原合同判断 |
| 更好看的页面产生错误解释 | 独立算例与原文检查；明确模型范围，不以自评分兜底 |
| 页面能预览却不能恢复 | 在实际 Reader 重现；按状态合同修复，不继续增加用户 prompt |
| Provider、宿主或资源失败 | 按原因独立统计并保留失败；不把所有失败归为表达设计问题 |
| 候选取消或保存失败 | 保持旧交付引用和旧内容不变，按现有运行终态说明 |
| 新能力未在某个平台验证 | 限定发布范围，不扩大宣称 |

先在隔离书副本、私有历史与状态目录验证，不覆盖日常 Reader 数据。切换前记录实际二进制、Web 资源、skill 版本和源文件状态；不要仅记录 HEAD，因为本次基线可能包含未提交改动。

回退优先停用新的设计指令与 Brief 上下文注入，同时继续支持读取已保存的可选字段；停止生成 Brief 不应删除历史内容。新代码读取旧文件必须测试；旧二进制读取新文件不能自动保证，未经验证不直接回滚二进制覆盖日常数据。

## 10. 已知限制

- ED1/ED2 在 Windows 本机完成定向工程验收；Linux 实机、手机及安装包入口尚未验证。
- Python 绘图已接入；目标宿主仍需按依赖清单安装 Python/Matplotlib 和中文字体。同题各一次模型对照中浏览器版窄屏更易读，未观察到 Python 版的解释优势；成本/质量仍需后续任务观察。
- 当前预览状态回调仍为空实现，不能证明 Reader 保存与恢复；相关验收须经过实际 Reader。
- 失败和部分环境完成的图片投影缺口已由源码确认，修复与实际请求验证安排在 ED4。
- click/key 与显式 touch 环境不等于任意拖拽或真实 iPhone 手势已验证；发布范围对应实际覆盖。
- 现有工程验收与小规模自然请求实验均不能证明用户学习效果；Ciechanowski 式体验是产品方向，没有已达到同等制作水准的结论。
