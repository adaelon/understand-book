Tutor 的使命是：**从学习者当前的理解出发，提供他能够理解、操作和组合的认知积木，引导他用这些积木建立新的理解，并逐步能够独立运用。**

## 1 对齐确认与实施基线

**FrozenIntent**：让 Tutor 从用户当前可用的理解出发，设计可上手的支撑和需要用户完成的认知活动，根据实际回应调整帮助，并把这种变化接入持续学习。成功表现为真实教学中用户能够借助所给支撑完成一个新的判断、解释或运用，后续帮助采用这一过程的实际依据。

**RiskReceipt**：用户于 2026-10-12 认可使命、现有承载方式、按帮助条件记录表现及先打通真实阅读路径的方向，并授权落 ADR 与切片方案；随后要求先按 TO 原则修订 TB 设计，再并行开发。任务交付、教学活动和理解证据继续分别表达；实施从现有字段和循环起步。

**ChangeType**：模型扩展与教学策略调整。调整教学使命、动作选择、呈现设计及反馈消费，沿用现有领域所有权。

## 2 目标与行为合同

学习目标从“理解某一节”逐步落实为“在什么条件下，能够借什么完成什么”。用户提供的目标可以保持朴素，具体教学焦点由 Agent 结合当前材料和回应提出，并允许用户纠正。

Agent 每次选择教学动作时，形成一个简短、可修订的教学判断：

```text
输入：当前请求 + 会话意图 + 有依据的当前理解及未知 + 实际读取的原文和可用素材
选择依据：这一步要形成的能力、可用的认知积木、用户亲自完成的活动
输出：一个 TeachingMove，按需要交付普通文字或 AgentPresentation
收到实际回应后：按需回读事实，核对内容与帮助条件，修订理解，再选择下一步
```

这是既有 TutorLoop 的选择依据，沿当前目标与教学动作表达。辨析定义、阅读论证、解释因果和执行程序可以采用不同教法；Agent 根据实际回应选择下一步，学习者可以尝试、求助、要求解释或停止。

| 当前情境 | 教学行为 |
|---|---|
| 用户缺少开始所需的概念或关系 | 直接补足必要材料，或示范一小步，再交给用户能够承担的部分 |
| 用户已具备必要基础，采用引导学习 | 给出能操作的支撑和一个具体活动，在用户回应处停下 |
| 用户猜对但理由尚未成立 | 指出具体连接缺口，用对照、反例或局部解释帮助重建 |
| 用户明确说当前支撑用不上 | 根据其真实说明修订起点；缺少定位信息时问一个具体问题 |
| 用户已有足够表现 | 减少代做，允许用户自行选择方法、组合关系或处理改变的条件 |
| 用户要求直接答案、解释、总结或翻译 | 完整交付所请求内容；组织方式仍帮助用户看清可复用的关系 |
| 仅有浏览、点击、滑块变化或没有回应 | 保留交互事实，继续保持能力未知 |

积木可以由图示、类比、公式、案例、操作或文字承载。教学选择先考虑当前理解需要什么连接，再选择表达形式。类比与简化保留适用条件，书内主张仍由原文支持。

Tutor 开关、暂停和会话范围沿现有控制生效。直接请求优先于默认教法；普通模式沿用理解观察，主动教学仍由 Tutor 状态控制。ResidentGoal 按实际任务交付完成，TutorSession 按用户意图延续，学习进展采用对应表现证据。

## 按 TO 原则组织教学能力

TO 让 Agent 获得可靠、可组合的工具，TB 让学习者获得适合当前理解、可运用的认知支撑。两者都保留真正影响下一步的选择：工具执行读取、呈现和记录；Agent 判断采用什么支撑、怎样引导；学习者亲自做出预测、比较、解释或尝试。教学流程由目标与回应推进。

| 内容 | 唯一落点 | 装配与使用方式 |
|---|---|---|
| 使命、请求优先级、证据边界 | 既有 Tutor 指导模块，TB 维护教学语义 | 随 Tutor 状态加载；普通阅读、理解观察与主动教学保持各自范围 |
| operation、参数、引用、权限和调用示例 | 原工具契约及状态投影，TO3／TO4 维护 | 发布当前状态有效的工具定义；参数示例经最终定义和真实解析验证 |
| 选支撑、调整帮助、呈现设计等教学指导 | `SELECT / UNDERSTANDING` 及 Tutor 呈现阶段指导，TB 维护 | 按既有状态、实际事实、工具请求和呈现阶段选取相关模块 |
| 当前目标、用户原话、已交付内容、帮助与理解假设 | 现有 Tutor 上下文、TeachingTrace 和 LearningMemory | 作为有身份、有范围的任务数据提供；细节经原读取入口取得 |

TB 把“怎样选支撑、给用户留下什么活动、何时调整帮助”写进教学指导；字段形状与调用方法由工具契约表达一次。需要演示时，`framework / focus` 承载本轮设计，阶段指导承载制作方法。用户看到可开始使用的内容和自然的下一步，设计判断复用现有字段。

工具调用示例与教学案例各有用途。TO 的示例说明当前工具怎样合法调用；TB 的案例在实施记录中检验同一材料如何适配不同起点，完整案例保留为验证输入。示例中的引用必须符合当次上下文，不能成为用户作答、已展示提示或已掌握知识的事实。

涉及指导、上下文或工具暴露的切片，检查最终 Provider 请求里实际出现的指导、工具定义和任务数据。只保留会影响当前选择的内容；重复参数说明、重复案例和无关阶段指导由其原落点收敛。输入预算调整应保留来源、帮助条件、覆盖限制及回读路径。

## 4 认知积木设计样例

下面是用于说明行为的自拟数学情境：同一段路去程 60 km/h、回程 20 km/h，判断全程平均速度。它不能替代 TB1 对真实材料、原文范围和测试输入的固定。

```text
学习请求：希望自己判断平均速度什么时候可以直接取算术平均
已知起点：用户明确表示会用“时间 = 路程 ÷ 速度”，尚未解释全程的分母
能力目标：用各段实际耗时解释整体平均，并区分等距离与等时间条件
提供的积木：两段路程—速度—时间的对应表，保留一处供用户完成
用户的活动：补出耗时，判断哪一段对全程耗时影响更大，说明理由
核对依据：原文定义；确定性计算总路程 ÷ 总时间
帮助调整：算不出时示范一段；能算但理由缺失时聚焦时间权重
后续候选：用户愿意继续时，比较“两段时间相同”的情况
```

同一目标允许不同起点：对暂时不理解比值的读者，可以先用路程格与耗时格；对熟悉代数的读者，可以用加权关系。支撑的表达改变，来源和数量关系保持一致。示范后用户完成的部分、自己提出的理由以及获得的帮助分别记录。

TB1 以真实材料和自然问题建立基线；TB6 再加入一段实际论证或定义辨析材料，检查策略能否组织“主张—证据—条件”一类积木。

## 5 反馈与接续

反馈首先回应用户实际做出的事情：哪个判断成立、依据是什么、哪一处连接尚未得到支持。必要时回到原文、计算结果或实际操作；已经明确成立的步骤直接认可。

可用于接续的理解假设，例如：

> 用户借助系统提供的两段耗时表，说明了低速段占用更多时间；尚未看到他能独立说明等时间情境。下一次保留相同表示，先让他自行组织两段条件。

这类表述保留适用目标、实际原话、支撑和未知。普通对话使用 `nature=hypothesis`，`teaching_implication` 说明具体帮助变化；需要修订时沿用 `supersedes`。正式作答继续使用原冻结评分合同及帮助、尝试条件。

近期上下文是有界视图。未返回某条表现表示当前未见到；摘要被截断时，涉及独立完成、帮助程度或用户纠正的判断，应沿 `trace / understanding` 回读必要细节和后续页。交付内容、用户表达、帮助条件、来源范围及暂定性质共同决定解释，压缩时保留这些关系。

原文侧同样沿 TO 的证据链工作：目录、候选和预览用于选择，实际读取并接纳的正文支持主张。TeachingMap 缺失不阻断已可读取原文的教学；材料和用户历史各自的覆盖范围保持可辨认。TB 消费已有返回信息；出现会改变教学判断的真实缺口时，按下文所有权修正原结果或其投影。

同一有效会话的新回合、新聊天或应用重启后，从现有学习记忆恢复相关事实。下一次实际交付应体现为何沿用某个表示、补足某个连接或减少某项帮助。记忆中新增一条解释本身不能完成这一验收。

## TB1 真实材料与教学行为基线

**输入**：固定 TO 版本的 Tutor 基线、[TC0 基线](performance/tutor-continuation-tc0-baseline.md)、[TC6 纠正轨迹](performance/tutor-continuation-tc6.md)及对应测试夹具。历史轨迹用于选取问题，新对照保留可重跑的基线代码与实际请求。

**责任与产出**：复用 `crates/server/src/tests/tutor_loop_tests.rs`、`tutor_continuation_tests.rs` 的运行入口，在 `docs/performance/tutor-building-blocks-tb1/` 保存可复跑材料、输入及现状记录；冻结原文范围、初始会话状态、明确背景、自然问题和预期可观察行为，并固定模型设置、重复次数、费用／token 预算及停止条件。

选择同一材料的两个具体起点、一次真实表达的误解和一次明确直接讲解请求。基线与改后版本采用相同 TO 实现、材料和模型设置，保存实际请求、工具结果和最终交付。已有符合使命的行为作为保留基线，失败与未完成也按原样记录。

**验证与处理**：检测来源或输入不可重建、两个起点实际相同、对照混入工具版本差异、用脚本预写理想回答却冒充读者表现的问题。出现时修正夹具、版本配对或证据标注后再比较教学行为。

**完成判据**：材料和入口可重跑；能够具体指出哪些现状已符合使命、哪些输出尚未让用户获得可用支撑。

## TB2 使命驱动的文字教学

**输入**：TB1 的同源问题和两种起点，现有 `TeachingTarget` 与按需指导。

**责任与产出**：主要修改 `crates/runtime/src/tutor.rs` 的活动教学使命、`SELECT` 及 `instruction_modules`，配套运行指导测试；保留 Tutor 关闭、直接请求和普通阅读的既有行为。先用普通文字、表格或短例子完成第一条教学路径，参数和调用示例沿 TO3 的契约所有权维护。

把“本步能力—提供的支撑—用户完成的活动”贯穿选择和最终交付。适用引导时，实际回答应交付可开始使用的积木并停在用户活动处；明确讲解请求完整交付解释。按需模块保留精简选择原则，具体教学数据取自当前上下文。

**验证与处理**：运行指导与意图测试检测错误启用教学、覆盖直接讲解及丢失回应边界，并检查最终 Provider 请求是否重复注入参数示例或包含无关阶段指导；失败修正相应装配。用 TB1 的固定实模场景检查两种起点是否获得适用支撑；若仍只是改变篇幅或术语，修正教学选择规则。工具参数失败照实记录；契约或示例缺口归 TO，教学指导冲突归 TB，按实际原因修正。

**完成判据**：同一内容能形成与起点匹配的实际支撑，用户亲自完成的活动清楚且可开始；保留来源、请求和控制边界。最终请求的指导与可用工具一致，真实输出证明内容路径成立，再进入 TB3。

## TB3 帮助调整与学习记忆接续

**输入**：TB2 已交付内容，用户的尝试、求助、纠正和后续回应，以及实际帮助记录。

**责任与产出**：主要修改 `crates/runtime/src/tutor.rs` 的 `UNDERSTANDING` 与动作适配指导；只有现有查询确有遗漏时才调整 `crates/server/src/teaching.rs` 的上下文投影或 `crates/memory/src/learning_evidence.rs` 的相关消费路径。保留可回读的事实、理解修订和下一次实际交付；共同结果预算机制的缺口交由 TO11 在原投影处理。

分别走通难以开始、结论正确但理由缺失、用户指出积木不适用、用户已能独立完成的回应。调整可以是示范一小步、补一个关系、换一种表示或减少提示；每次仍选择一个有界动作。

**验证与处理**：用确定性测试核对实际帮助、用户原话、假设修订和投影归属，并覆盖正常使用形成长回应或多条事实后的有界读取。错误提升独立表现、遗漏帮助条件或把截断视作事实不存在时，修正原记录、回读或投影。用实模接续核对新判断是否改变实际支撑；只写入记忆而输出不变时修正选择与指导消费。

**完成判据**：原会话接续及重开同一有效会话后，相关事实可以回读，帮助条件保留，下一步确实采用更新后的理解。普通表达与正式表现沿各自证据语义处理。

**实施结果（2026-10-12）**：指导 `tb3.v1`；修复来源理解记录的分页发现、Web 翻页与纠正后重载，以及引用普通回应形成假设时的已展示帮助遗漏。长原话分块、旧假设替代和帮助条件有确定性回归；四种脚本回应及同会话重开均有实际交付，重开复用既有理解而不重复记能力证据。12 次固定实验加 4 次授权参数修复，原始失败及一处额外删除可选交付引用的修复偏差保留。改前已存在适配行为，本次不据单样本推断普遍提升。证据与限制见 [TB3 记录](performance/tutor-building-blocks-tb3/README.md)。

## TB4 可操作的认知积木

**输入**：TB2/TB3 已成立的能力目标与用户回应，现有 AgentPresentation 制作和现场回传能力。

**责任与产出**：修改 `crates/runtime/src/tutor.rs` 中的教学呈现指导，按实际需要补充 `skills/presentation/phases/` 的相应阶段指导；沿现有 `presentation.author` 制作一个能支持用户判断的教具。TO4 维护操作示例与引用规则；TB 维护积木作用、用户活动及阶段消费，共享呈现规则保留普通富文本回答的用途。

全局设计交代积木如何连接当前理解；局部制作让用户操作或组织关键关系；审阅对照实际场景确认用户能够执行预期活动。使用现有 `framework / focus` 及实际交付版本，后续回应关联发送时的现场。

**验证与处理**：对数值与关系用确定性计算或可运行结果核对；对交互与现场用既有预览及浏览器入口核对，沿 TO4 的真实引用和交付回执确认所用对象。错误结果修计算，操作与反馈脱节修界面，现场未进入接续修原回传链路。用户操作后的真实表达仍按 TB3 消费。

**完成判据**：用户能够用教具检验一个具体判断，并围绕实际结果继续原对话；Agent 的下一次帮助引用正确版本和现场。实际操作事实与理解判断分别保存。

**实施结果（2026-10-12）**：指导 `tb4.v1`，沿 TB3 未答活动交付 Copy／引用方式的双组对照教具。四组代码经实际编译／运行核对；真实 author、五次预览、交付、浏览器保存／重开和原聊天接续成立。接续采用实际版本和发送时现场，区分教具结果与脚本用户推断，保留帮助条件及未评分性质。两次新增授权模型实验完成；原输出的状态恢复字段、来源按钮配色及新解释引用遗漏由主代理局部修正，原件与修正后结果分别保留。TO4 尚未实施，使用现有工具契约。详见 [TB4 记录](performance/tutor-building-blocks-tb4/README.md)。

## TB5 教法与理解视图

**输入**：TB3 的真实理解记录、帮助条件及 TB4 的教学样例。

**责任与产出**：以 `TutorPanel.vue` 与 `UnderstandingSpace.vue` 为主要接点。将“引导思考”的说明改为能够涵盖尝试、示范与按需帮助的表达；理解视图使用户能看见具体理解、依据、适用帮助条件和纠正入口。

普通尝试通过已有对话表达。既有正式活动继续显示对应评估结果；对于未评分的交流，采用与实际性质相符的反馈。现有建议和活动入口按原合同工作。

**验证与处理**：运行现有组件测试验证教法控制、依据读取和纠正仍可用；通过一条浏览器路径核对真实记录呈现。若界面把暂定判断写成已掌握，或省略会改变解释的帮助条件，修正文案或原投影。

**完成判据**：读者能理解 Tutor 正在怎样帮助自己，并能指出理解记录中不符合实际的部分；当前模式和直接讲解入口含义清楚。

**实施结果（2026-10-12）**：教法说明覆盖尝试、示范与按需帮助，区分会话默认和当前请求；假设详情直接显示适用目标及帮助条件、原话、暂定解释和纠正，普通交流明确未评分。复用原接口字段，生产后端与领域合同无变化。20 项组件、1 项实际记录投影／纠正、1 项浏览器 host 和 1 条完整浏览器路径通过，类型检查通过；TB4 记录经实际接口纠正、重开后保留原话与帮助条件，能力投影为空。新增模型调用 0，见 [TB5 记录](performance/tutor-building-blocks-tb5/README.md)。

## TB6 全链路与真实读者验收

**输入**：TB1 的固定材料、TB2–TB5 的实际产出，以及一段已有可读材料中的论证或定义辨析内容。

**责任与产出**：复用现有 Tutor 测试和浏览器路径，在 `docs/performance/tutor-building-blocks-tb6/` 保存工程结果、实模轨迹、真实读者过程和明确限制；同步本方案及实施索引。

对数值关系和非数值关系各观察一条完整路径：适用支撑、用户真实活动、反馈调整、有效会话接续。让读者按自己想法回应；记录其能否使用所给支撑、卡在哪里，以及后续是否能处理一个有意义的条件变化。

**验证与处理**：工程回归针对实际改动与受影响路径运行。实模按预先固定的次数执行，失败原样保留；修复后只重跑相关失败与受影响场景，并单列修复后的结果。真实读者用不上支撑时保留原过程，调整支撑或任务大小。工具调用、教学内容、学习者表现按第 7 节分别给出依据。

**完成判据**：工程结果可重现，真实模型交付符合内容依据，真实读者过程能够说明积木怎样被使用及仍存在的障碍。真人验证缺席时单列未完成项，脚本化轨迹保持其原有身份。

## 7 验证与后续接手

执行每次检查前，在实施记录中写明要检测的具体失败以及失败后会改变的操作。程序检查请求、状态、记录、计算和交互；开放解释结合原文及实际用户表达判断，并给出具体依据。实际能力进展用相应表现说明。

同一条运行证据分别支持三类结论：工具调用是否合法、真实状态是否正确变化，由参数解析与实际回执判断；教学内容是否成立、支撑是否适合已知起点，由原文、计算或实际操作判断；学习者完成了什么、需要何种帮助，由其真实回应与帮助记录判断。指导文本命中、schema 通过和脚本化回答各自只证明对应范围。

真实对照沿 [TO14](切片方案-工具契约与Agent可用性优化.md#to14真实-agent-对照与可复用阅读案例) 的固定采样办法，在 TB 每片按需执行。TB 前后比较固定同一 TO 版本；如果合入 TO 变化会影响对应请求或结果，则将前后两个教学版本都置于新的共同工具基线上重跑受影响场景，保留旧记录。两条线一同变化的单次结果只用于集成验收。

2026-10-12 起按用户 API 成本约束，教学内容与指导实验优先用 GPT-6.1-Sol 子代理；前后版本使用相同模型、推理设置、固定输入与工具说明，独立上下文，每组每版一次，保留实际输出与失败。工程行为沿确定性测试验证；DeepSeek 专项调用仅在用户明确要求后执行最小必要样例。子代理结果不替代生产 Provider 端到端或真人验收，也不与 DeepSeek 历史输出混作指导前后对照。具体记录见 [TB2 后续实验方式](performance/tutor-building-blocks-tb2/README.md#后续实验方式)。

活动输入量、累计 usage、费用、重试和端到端耗时附在真实交付旁，活动上下文与累计计费分别报告。无实际收益且明显增加输入的指导或案例应收敛；任务未完成、内容错误和用户无法使用的过程保留为失败。涉及模型的验证复用已有实际请求／审计入口，参数示例验证复用 TO2 的最终投影与真实解析机制；输入与相关行为未变时沿用已通过的结果。

按切片选择已有入口：

- Runtime 指导与意图：`cargo test -p runtime tutor`；触及状态工具面或合入 TO3／TO4 的相关变化时，复用 `cargo test -p runtime --lib tool_registry::contract_tests` 的受影响用例，覆盖最终定义、Native/ReAct 请求投影及真实解析。
- Server 教学与接续：`cargo test -p server tutor_`，重点参考 `tutor_loop_tests.rs` 和 `tutor_continuation_tests.rs`；实模入口沿 TB1 固定配置显式执行。
- 只有修改 Memory 行为时，运行受影响的证据／投影测试，测试过滤器以实际符号为准。
- Web 组件：`pnpm --filter @understand-book/web test src/components/TutorPanel.test.ts src/components/UnderstandingSpace.test.ts`；触及活动再加入 `TutorActivities.test.ts`，并运行该包类型检查。
- 演示与接续交互：复用 `packages/web/playwright/tutor-workspace.spec.ts`、`tutor-continuity.spec.ts` 的相关路径，配置和测试数据以当前实现为准。

本次先集成并发布已完成能力，见 [集成记录](performance/integration-to-tb-20261012/README.md)。后续启动 TB6 时读取 [TB5 记录](performance/tutor-building-blocks-tb5/README.md)与 TB4 已交付样例，固定另一段论证／定义辨析材料、可观察活动和真实读者入口，再按 TB6 合同执行全链路验收。教学实验继续优先 GPT-6.1-Sol，新增实验预先固定次数；TB3 的 16 次及 TB4 新增 2 次授权均已用完，TB5 未新增调用。DeepSeek 历史失败和未知 usage 保留，不阻塞本地工作。

## 8 已知限制

- TB2–TB4 的工程与子代理内容验收、TB5 的界面与实际记录验收已完成；子代理获得预读原文和引用，回放固定工具次序，未复验生产 Provider 协议／自主工具循环。TB3 原始字段错误及授权修复、TB4 原始输出与局部修正分别保留，不代表首次调用稳定性。DeepSeek 历史 1,032,768 token 预占仍未结算；真实读者为 0，无学习收益结论。TB6 未实施，详见各片记录。
- TO3 已在 TB2 集成；TO4–TO14 与 TB1–TB5 本次统一集成。原 TB 对照仍以当时 TO3 为基线，本次回归只说明合并后的兼容性。工具合法性与实际教学内容分别验收。
- TeachingContinuation 目前只支持解释、对比和观察，并固定相应动作意图。“让我独立试一题”若成为新的类型化按钮，需要另行扩展 ADR-0163 的建议、接纳和意图合同；本轮通过现有引导意图和自然回应开展尝试。

- ADR-0163 记录的真实模型质量问题和 TC7–TC8 待办仍保留。本方案复用相关入口，实施时对遇到的阻断分别归属，不能以新路径通过替代旧问题收口。
- 首页已作为独立提交保存。本方案的验收依据是实际 Tutor 过程；首页情境示意需要与后续真实能力保持一致。
