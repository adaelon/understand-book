# 邮箱账号与一次性内测码切片方案

日期：2026-10-09。状态：**INV0–INV9 已完成并发布；注册、绑定及找回真实邮件验收通过，T15–T18 随同版上线，公网登录/阅读/后台复核通过。**

决策入口：[ADR-0159](adr/0159-email-accounts-and-single-use-beta-invites.md)。本方案面向现有 Linux 多人阅读服务，交付管理员手动分发内测码、读者自助邮箱注册和密码管理的完整流程。

## 0 对齐确认与实施状态

**FrozenIntent**：管理员生成随机内测码并手动发给受邀者；读者以邮箱、密码和一次性内测码注册，验证邮箱后获得账号，可自行登录、修改密码和找回密码。成功标准是受邀者独立完成注册及密码恢复，一码只能建成一个账号，老账号的阅读成果和额度连续保留。

**确认依据**：用户提出“不想所有人都可以注册”，要求随机内测码并手动发送；随后确认“一码一账号、验证后核销、长期有效可停用、材料与额度另行开通”，并要求落 ADR 和切片方案。邮箱验证及找回密码沿用本轮已确认的账号流程。

**RiskReceipt**：已说明邮箱需绑定稳定用户身份，以保留私人目录和额度归属；已说明注册资格与材料、模型额度分别开通。用户确认上述方案。具体接入采用本文件中的实现默认值，发信供应商及部署凭证留作上线配置。

**ChangeType**：`[模型扩展]`，扩展已有认证入口及管理员能力。

## 2 产品规则

| 行为 | 结果 |
| --- | --- |
| 管理员生成内测码 | 可单个或批量生成、复制并手动发送；首版单批 1–100 个 |
| 内测码格式 | 服务端安全随机生成 20 位大写字母和数字，展示为四组五位；避开 I、O、0、1；输入统一大小写并去除展示用横线及首尾空白 |
| 内测码有效范围 | 长期有效；未使用时可停用，停用后不恢复；需要重新邀请时生成新码 |
| 使用内测码 | 一个码最多成功注册一个账号；表单填写、发送验证邮件均不预占或核销 |
| 账号创建完成 | 普通读者、可登录、邮箱已验证；材料授权和模型额度由后台分别开通 |
| 登录、改密或找回密码 | 不要求内测码 |
| 老账号绑定邮箱 | 登录并验证当前密码后完成邮箱验证；保留原 user_id，不要求内测码 |
| 内测码列表 | 展示码、生成时间、生成管理员及未使用/已使用/已停用；已使用时展示对应账号与邮箱 |

邮箱统一去首尾空白、按大小写不敏感比较；注册、绑定、登录和恢复使用同一规则。不合并不同邮箱服务的加号别名或点号。密码沿用现有服务端长度和 Argon2 规则，前端提示与服务端一致。

## 3 持久化合同

数据仍由现有 ServiceWriter 和 ControlStore 管理。新增表与 users 邮箱列随现有 schema 升级提交；新建数据库和升级数据库得到相同结构。下列为最小业务字段，时间采用现有 Unix 秒约定。

```text
users += { email?: unique normalized email, email_verified_at?: timestamp }

invite_batches = { actor, operation_id, count, created_at }
beta_invites = { invite_id, code: unique, actor, operation_id,
                state: unused | used | disabled, created_at,
                used_by?: user_id, used_at?, disabled_at? }

registration_requests = { request_id, email, password_hash, invite_id,
                          verification_code, expires_at, failed_attempts,
                          completed_user_id? }
email_binding_requests = { request_id, owner_user_id, auth_epoch, email,
                           verification_code, expires_at, failed_attempts, used_at? }
password_reset_requests = { token, owner_user_id, auth_epoch, expires_at, used_at? }
```

内测码已使用状态与 used_by、used_at 一致，已停用状态与 disabled_at 一致；数据库唯一约束保证邮箱和内测码唯一。待完成注册不占用 users 的邮箱唯一值，账号完成事务决定最终归属。

INV1 结构：`users.email` 与 `email_verified_at` 同为空或同有值，空邮箱可存在于多个老账号；非空邮箱保存去首尾空白、小写化后的值。`registration_requests.password_hash`、`verification_code` 在未完成时必填，在 `completed_user_id` 有值时必须同时清空；绑定请求保留验证码和可空 `used_at`，重置请求保留令牌、账号、创建时的 `auth_epoch` 及可空 `used_at`。批次以管理员和操作号组成主键，内测码以复合外键关联批次，以外键关联使用账号。

内测码批次以 `(actor, operation_id)` 唯一。相同操作号和数量返回原批次，数量不同返回冲突；后台超时后查询原批次，避免一次点击生成两批码。此记录直接比较业务字段，并通过 beta_invites 关联还原原批次。

验证码、重置令牌和密码不进入普通操作回执或观测日志。密码只保存现有 Argon2 处理结果；验证码与随机令牌存于既有私有控制数据库，仅由对应流程读取。完成后的注册申请清除 password_hash 和 verification_code，只在原申请有效期内保留完成回执；其他已使用或过期请求可在下一次同类操作时清理。

## 4 注册与邮件流程

读者在注册页填写邮箱、密码和内测码；服务端确认基本格式、内测码可用、邮箱尚未绑定后创建待完成注册并发送邮箱验证码。验证码输入发生在注册页，验证完成后提示“注册成功，请登录”。

```text
提交邮箱、密码、内测码
  → 校验注册条件，持久化待完成注册
  → 在数据库事务外发送验证码
  → 读者输入验证码
  → 同一事务：
      校验申请存在且未过期
      若该申请已完成：返回原完成结果
      校验验证码正确、错误尝试未超限
      确认邮箱尚未绑定、内测码仍为 unused
      创建普通读者账号，写入已验证邮箱
      将内测码置为 used，关联新 user_id
      标记申请完成并清除临时凭据
  → 提交后返回注册完成；读者以邮箱和密码登录
```

若邮箱已绑定、内测码已使用或已停用，完成操作失败且不创建账号；建号或核销任一步骤写入失败，整个事务回滚。两份申请使用同一码时，只允许一份最终成功。重复提交已完成的同一申请只返回注册完成提示，不建立登录会话，也不创建第二个账号；最终分发按申请完成状态处理，无需重新检查已清除的验证码。

验证码默认 6 位数字、15 分钟有效、最多 5 次错误输入；同一邮箱的发送间隔至少 60 秒，服务全局每分钟最多发送 60 封事务邮件。重发沿用同一申请，替换验证码、重置有效期和错误计数；提交不同邮箱或密码创建新申请。重发也检查内测码仍可用。注册开始与完成使用现有服务风格的限流和错误响应。

发信接口使用一个实际事务邮件通道；供应商及 SDK/协议在 INV3 接入时按运营者可用配置确定。配置至少包含发件身份、凭证和发送端点。邮件发送设置有限超时，并在数据库锁外执行；明确失败时页面显示失败及重试入口，注册和内测码状态保持可恢复。超时结果不声称邮件一定未送达，用户可等候或重发，只有当前验证码有效。

邮件链接只使用部署配置中的可信站点 Origin。验证码邮件明确写出用途和有效期；找回邮件进入设置新密码页面。打开页面的 GET 请求仅展示表单，最终 POST 才执行密码变更和令牌使用。

## 5 登录老账号绑定与密码管理

登录沿用 `POST /api/auth/login` 的 `{ username, password }` 合同。username 可填邮箱或现有账号名：邮箱先解析到内部 user_id，再进入现有密码验证与会话创建。服务端返回真实 user_id，`/auth/me` 同时提供已验证邮箱或空值；前端可显示邮箱，私人状态和管理操作仍按 user_id 归属。

已存在的账号名登录继续可用，支持尚未绑定邮箱的老用户和现有管理员。新注册账号的内部 ID 由服务端生成并满足现有 ID 约束。后台账号搜索增加邮箱，返回邮箱与原 user_id，方便管理员对照收款、开通材料和额度。

| 操作 | 前提与完成语义 |
| --- | --- |
| 首次绑定邮箱 | 已登录、当前密码正确且账号尚未绑定邮箱；向目标邮箱发验证码。完成时再次确认 Principal、auth_epoch、邮箱唯一及账号仍未绑定，绑定到同一 user_id |
| 修改密码 | 已登录，提交当前密码和新密码；核对当前密码后，事务内确认账号及原凭据仍有效，再调用现有 write_password |
| 请求找回密码 | 填写邮箱；仅为已验证且启用的账号生成 30 分钟有效的一次性随机链接。页面统一显示“如该邮箱对应可用账号，将收到重置邮件” |
| 完成密码重置 | 提交链接令牌及新密码；同事务确认令牌、有效期、账号启用状态及 auth_epoch，写入密码并将令牌置为已使用 |
| 改密或重置成功 | 撤销该账号全部旧登录会话，清除当前 Cookie；Reader 和后台经现有身份同步清理旧视图，提示重新登录 |

绑定和重置请求记录创建时的 auth_epoch，使管理员改密、禁用或撤销会话后，旧请求不能继续改变账号。管理员现有改密仍走相同密码与会话机制。首次绑定邮箱不改变原密码、管理员身份、材料、额度和私人目录。

未绑定邮箱的老用户仍可在登录后改密；忘记密码时由现有管理员入口恢复，再完成邮箱绑定。新用户注册成功后书库为空时显示“账号已创建，等待管理员开通材料”，个人设置始终可访问。

## 6 HTTP 与界面接入

公开注册和恢复端点按下表在会话认证前精确分发，沿用 Site 的可信 Host/Origin 校验；已登录写操作沿用 Cookie、CSRF、Principal 和能力表；后台内测码操作沿用服务端管理员授权。

| 接口 | 输入摘要 | 成功结果 |

| POST /api/auth/register/resend | request_id | 更新验证码发送状态；失败时可重试 |

| POST /api/admin/invites/{invite_id}/disable | 无目标账号参数 | 未使用码停用；已停用再次请求返回原状态，已使用返回冲突 |

注册开始的发送失败响应保留已创建 request_id，供页面重试；发送失败不伪装成成功。密码找回对邮箱不存在保持统一提示，已知的全局邮件不可用返回统一的服务暂不可用；错误码不包含验证码或重置令牌。

Reader 页面包括登录、注册、填写验证码、忘记密码、设置新密码及个人账号设置。密码只留在表单内存，提交结束后清空；注册页只保存继续验证所需 request_id，不把密码或内测码持久保存在浏览器。邮件重置链接携带令牌进入正式站点，页面取得令牌后移除地址栏凭据，再提交最终 POST。

注册、忘记密码和重置页在未登录状态可直接打开；已登录用户打开恢复页时仍能完成指定恢复操作，成功后回到登录。正式网络 Reader 承担完整流程，Rust 内置壳同步登录语义并提供正式站点流程入口。后台提供内测码页面与邮箱展示，管理员的首次邮箱绑定和自助改密统一从 Reader 个人设置进入。

**INV3 实施结果（2026-10-09）**：[account_mail.rs](../crates/server/src/account_mail.rs) 使用单一 Resend HTTP `POST /emails` 通道，复用 `ureq`；配置合同依据 [Resend Send Email](https://resend.com/docs/api-reference/emails/send-email)。本地进程、项目 `.env` 和部署示例未发现发信配置，因此本片用本地真实 HTTP 接收器验收，生产发件域名及 API key 留给 INV9。

`multi_user_host::start` 在 `Site::new` 验证并规范化 HTTPS Origin 后加载 `UNDERSTAND_BOOK_MAIL_FROM`、`UNDERSTAND_BOOK_MAIL_API_KEY`；发送端点默认 `https://api.resend.com/emails`，`UNDERSTAND_BOOK_MAIL_TIMEOUT_SECONDS` 默认 10、范围 1–30。四项全空时邮件不可用且既有服务仍可启动；部分配置或无效值阻止启动，错误只含配置说明。发件身份使用已验证域名上的纯邮箱地址。本地协议接收器可用回环 IP 的 HTTP 地址。

调用顺序为 `mail.reserve(email) → 提交业务请求并释放数据库锁 → MailSend.verification / password_reset`。预留时统一邮箱大小写与首尾空白，保留加号别名和点号；注册、绑定与恢复共用同一实例的滚动 60 秒窗口，单邮箱一次、全局最多 60 次，失败与放弃发送也计入。预留对象不持有锁且发送方法消耗自身；邮件模块不持有控制库。网络不自动重试、不跟随重定向，DNS 等待也设上限。

验证码由系统安全随机源等概率产生 6 位数字；重置令牌为 32 个随机字节的 URL-safe Base64。共用有效期为验证码 15 分钟、重置 30 分钟，错误尝试上限为 5；请求的持久化、重发替换及校验消费由 INV4/INV6/INV7 接入。验证码邮件区分注册与绑定；重置链接固定为 `${Origin}/?account=reset-password#token=...`，INV8 读取后清除片段，最终 POST 才改密。

HTTP 2xx 表示供应商接受，拒绝为 `ACCOUNT_MAIL_REJECTED`，供应商限流为 `ACCOUNT_MAIL_PROVIDER_RATE_LIMITED`；超时为 `ACCOUNT_MAIL_TIMEOUT`，连接结果未知或 5xx 为 `ACCOUNT_MAIL_DELIVERY_UNKNOWN`。本地未配置和限流分别为 `ACCOUNT_MAIL_UNAVAILABLE` / `ACCOUNT_MAIL_RATE_LIMITED`。所有错误均为固定文案，不包含供应商响应体、密钥、验证码或重置令牌；超时保留“可能已发送”语义。业务端点应保留原申请供等待或重试。

**INV4 — 内测注册后端。** 输入：INV1–INV3。新增 account_registration.rs，接入 multi_user_host.rs 的 start/resend/complete 路由。产出：待完成注册、验证码重发、建号与核销的原子完成。完成判据：有效流程只建一号；未验证、发信失败、错误输入、过期、停用和重复邮箱均不消耗码；两份申请共用一码只成功一次；同一已完成请求重试不重复创建；写入故障回滚账号及码状态。

**INV4 实施结果（2026-10-09）**：[account_registration.rs](../crates/server/src/account_registration.rs) 的 `Registration::{start,resend,complete}` 经 `Authorization` 持有控制库连接和原有 `ServiceWriter`，由 Host 在会话认证前精确开放第 6 节三个 `/api/auth/register/...` POST 地址。三者沿用 Host/Origin 校验，严格解析请求字段，不接收指定 user_id；不带 `/api`、附加查询参数和未知注册子路径均不作为公开入口。

`start` 共用邮箱规范化和邀请码展示格式规则，锁外调用现有 Argon2 密码处理，再预留邮件额度；事务内复查邮箱和邀请码，清理过期申请并保存新申请。`resend` 在同一申请上复查状态，替换为不同于旧值的验证码、重置错误次数及有效期。两条路径均在提交与解锁后消费发送预留；保存失败不发送，发送失败保留已提交申请及响应中的 `request_id`、`expires_at`、`resend_after`。`resend_after` 为等待秒数（60），`expires_at` 为 Unix 秒。

`complete` 使用 immediate 事务：有效期内已完成则返回原 `{request_id, completed:true}`；未完成则校验最多 5 次错误输入、当前验证码、邮箱唯一和内测码 unused，然后依次创建普通账号、写已验证邮箱、核销码并清除申请中的密码处理结果和验证码。错误输入的次数单独提交，写入任一步失败则整个完成事务回滚。新内部身份为 `reader_<UUID>`，默认启用、非管理员，无登录会话、材料授权或额度。

验证码过期后开始新申请；未过期的重发更新为 15 分钟有效。已完成回执也只在原申请有效期内可重试，过期记录在下一次成功开始注册时清理。开始和完成各有每进程滚动 60 秒最多 60 次的请求预算，开始的 Argon2 同时只运行一份；邮件发送仍共用 INV3 的单邮箱和全局预算。

注册业务错误码：`INVITE_INVALID`（400）、`INVITE_UNAVAILABLE` / `ACCOUNT_EMAIL_IN_USE` / `REGISTRATION_EXPIRED`（409）、`REGISTRATION_NOT_FOUND`（404）、`REGISTRATION_CODE_INVALID`（400）、`REGISTRATION_ATTEMPTS_EXCEEDED` / `REGISTRATION_RATE_LIMITED`（429）；存储故障为 `REGISTRATION_STORAGE_UNAVAILABLE` 或沿用密码写入的 `AUTH_STORAGE_UNAVAILABLE`（503）。邮件错误沿用 INV3；成功和失败响应均不返回密码处理结果或验证码。邮箱登录由 INV5 完成，Reader 注册表单接续 INV8。

**INV5 — 邮箱登录与身份展示。** 输入：已验证邮箱数据与现有 AuthService。触达 auth.rs、multi_user_host.rs、NetworkApp.vue、network-context.ts、后台 lib/api.ts / lib/types.ts，以及内置登录壳。产出：邮箱和现有账号名登录，服务端真实 user_id，邮箱展示与后台邮箱搜索。完成判据：Reader、后台及内置壳的两种输入都定位同一账号；邮箱不进入私人目录或 owner 字段；旧管理员能继续登录，普通读者不能取得管理能力。

**INV5 实施结果（2026-10-09）**：`AuthService::login` 对含 `@` 的输入统一调用 `normalize_email`，查询已验证邮箱对应的 user_id；随后与旧账号名共用该 user_id 的尝试预算、Argon2 和会话创建。未知邮箱与错误密码返回原认证错误，停用账号不可登录。`dispatch` 从新会话解析 Principal，login/me 返回真实 user_id 和可空 email；角色仍由当前服务端账号决定。

Reader、React 后台及内置壳均以“邮箱或账号”接受输入，优先展示邮箱；Reader 偏好、工作区和管理操作继续以原 user_id 为键。后台列表/详情返回邮箱，搜索同时匹配账号名与邮箱，分页总数使用相同筛选条件。内置壳提示到正式阅读站点个人设置绑定；窄屏账号栏与邮箱允许换行。

**INV6 — 老账号首次绑定邮箱。** 输入：INV1、INV3、INV5。新增 account_email.rs，接入已登录能力和 Reader 个人设置中的邮箱绑定表单。产出：验证当前密码、邮箱验证码及首次绑定。完成判据：不需要内测码；错密码、已绑定邮箱、邮箱冲突和失效请求均不改账号；完成后原 user_id、材料、聊天、学习记录、管理员身份和额度仍可用，邮箱登录指向原账号。

**INV6 实施结果（2026-10-09）**：[account_email.rs](../crates/server/src/account_email.rs) 提供 `EmailBinding::{start,resend,complete}`，由 `Authorization` 持有同一 ServiceWriter 下的控制库连接。三个 `/api/account/email/...` POST 路由经过 Host/Origin、Cookie、CSRF 和能力表，不加载私人阅读现场；输入严格解析，主体只取 Principal。

`start` 在数据库锁外验证当前密码，复用认证的单密码计算槽和每账号/全局尝试限制；错误密码为 `CURRENT_PASSWORD_INVALID`（400），保留当前会话。随后 immediate 事务复查当前会话及 auth_epoch、账号尚未绑定、目标邮箱未占用，预留邮件额度并保存申请。新申请替换同一账号的旧申请，同时清理过期或已使用请求。申请保存成功并解锁后发送，失败响应保留 request_id、expires_at 和 resend_after，客户端可继续输入验证码或重发。

`resend` 检查申请归属、会话及 epoch、有效期和邮箱可用，受共享 60 秒邮件窗口限制；替换为不同验证码、重置 15 分钟有效期和错误次数。`complete` 在同一 immediate 事务检查归属和上述条件，最多允许 5 次错误；正确后仅更新原 users.email/email_verified_at，并写 used_at。有效期内且记录未清理时，当前账号可重试已完成申请取得原结果。写入失败整笔回滚；管理员改密、停用或撤销会话后的旧 epoch 申请不能被新登录会话完成。

绑定不修改密码、角色、auth_epoch、会话、材料授权、额度或私人目录。错误码包括 `ACCOUNT_EMAIL_ALREADY_BOUND` / `ACCOUNT_EMAIL_IN_USE` / `EMAIL_BINDING_EXPIRED`（409）、`EMAIL_BINDING_NOT_FOUND`（404）、`EMAIL_BINDING_CODE_INVALID`（400）、`EMAIL_BINDING_ATTEMPTS_EXCEEDED`（429）与 `EMAIL_BINDING_STORAGE_UNAVAILABLE`（503）；邮件错误沿用 INV3。

[AccountSettings.vue](../packages/web/src/components/AccountSettings.vue) 在书库、阅读页及附属窗口提供“个人设置”；书库为空也能绑定。表单处理错密码、发送失败、超时未知、重发冷却、验证码错误、过期重开和成功状态；密码提交即清空，不落浏览器存储。`networkFetch` 保留错误响应中的申请恢复字段。绑定成功只更新当前身份的 email，保留工作区、聊天草稿与身份 epoch；`profile-changed` 通知其他 Reader/后台刷新邮箱，既有登录/退出通知仍走原身份清理路径。注册及密码管理界面接续 INV7/INV8。

**INV7 — 自助密码管理。** 输入：INV1、INV3、INV5，现有 write_password 与 auth_epoch。新增 account_password.rs，接入改密、forgot/reset 路由。产出：当前密码改密和邮箱重置。完成判据：旧密码或无效令牌不能改密；一次性令牌使用、过期或 epoch 变化后失效；GET 不修改密码；改密和重置撤销所有旧 Cookie，旧密码失败、新密码成功；材料和额度保持原账号归属。

**INV8 — Reader 账号流程。** 输入：INV4–INV7 接口。在 NetworkApp.vue 内接入专门的账号视图组件及状态，补齐注册、验证码、找回密码、重置密码和个人设置。产出：移动端与桌面可完成全流程，书库为空时仍能管理账号，邮件深链接可直接打开。完成判据：页面真实操作覆盖注册失败重试、重发、注册成功登录、个人改密和邮件重置；跨标签页与后台在会话撤销后清理旧身份；密码不落浏览器持久存储。

**INV7 实施结果（2026-10-09）**：`AccountPassword::change` 在锁外验证当前密码并生成新凭据，再在 immediate 事务复查 Principal、auth_epoch 和已验证的原凭据，调用 `auth::write_password` 更新密码并撤销全部旧会话。`reset` 在密码计算前检查令牌，再在写事务复查一次性、期限、启用状态及 epoch；写密码、删会话和令牌 used_at 同次提交，任一步失败整体回滚。成功响应清除 Cookie，不创建新会话。

`forgot` 统一规范化邮箱，为每个合法地址预留共享发送预算；未知/未绑定/停用账号返回同一 accepted 提示而不发送，邮件未配置时统一不可用。可用账号保存 30 分钟随机令牌，新申请替换该账号旧令牌，清理过期/已使用记录，事务提交后发送。拒绝或超时保留已保存令牌，邮件可能送达；重试须等待共享 60 秒窗口。恢复与改密共用滚动每分钟 60 次入口预算，密码计算有单槽限制。公开路由精确匹配，GET 不修改账号；改密经过原 Cookie/Origin/CSRF 与能力表。

错误沿用当前密码、邮件和密码长度合同；新增 `PASSWORD_RESET_INVALID`（409，无效/过期/已使用/旧 epoch）、`PASSWORD_RATE_LIMITED`（429）、`PASSWORD_STORAGE_UNAVAILABLE`（503），密码写入故障沿用 `AUTH_STORAGE_UNAVAILABLE`。错误和成功正文不返回令牌、密码或验证码。

**INV9 — 候选部署与发布验收。** 输入：INV1–INV8、候选服务数据副本与实际发信配置。触达 Linux 发布配置、定向烟测和本方案验收记录。产出：数据库升级演练、真实收信证据、受邀者完整使用证据及发布记录。完成判据：第 8 节通过；真实邮箱能收到两类邮件并完成验证/重置；老用户原数据可用；管理员先授权材料和额度后，新账号才能使用对应能力。生产切换按届时明确的发布授权执行。

INV9 的具体输入、Resend 开通步骤、数据比对命令、候选验收和回退操作见[发布运行单](邮箱账号-INV9发布运行单.md)。

**INV8 实施结果（2026-10-09）**：`NetworkApp` 接入 `AccountAccess` 注册/验证码/找回/重置页，登录页提供入口，`?account=register|forgot-password|reset-password` 可直接打开。重置链接即使带有现存 Cookie 也优先展示账号页；取出 `#token` 后立即从地址栏移除，页面只在最终提交时 POST。注册失败保持可纠正表单；发信失败若返回 request_id 则保留验证码输入/重发/重新开始，过期禁止继续完成。找回统一提示并显示重发冷却；失效或缺失重置链接提供重新申请入口。

`AccountSettings → PasswordChange` 提供当前密码、新密码和确认密码，未绑定邮箱也可改密，密码长度提示与服务端 UTF-8 字节规则一致。密码提交即清空；注册内测码、申请和重置令牌仅在表单内存中，均不写浏览器存储。改密/重置成功清理身份、工作区及草稿，广播 `changed` 使其他 Reader 标签页与后台清理旧视图，返回登录提示使用新密码。空书库显示等待管理员开通材料，个人设置始终可用；内置登录壳补正式站点注册/找回入口。

## 8 验证范围与失败处置

测试优先使用临时真实 SQLite、实际 Host 路由和本地邮件协议接收器；浏览器测试的接口模拟只验证交互，不替代服务端账号与事务验收。

| 验证入口 | 检测的具体失败 | 失败后的动作 |
| --- | --- | --- |

## 9 已知限制与上线依赖

- Reader 注册/绑定申请保留在当前表单内存；关闭或刷新后重新开始。重置页面清除地址栏令牌后，刷新需重新打开邮件链接或重新申请。绑定与找回的新申请替换本账号旧申请。两端生产构建仍提示主包大于 500 kB，构建可通过。

- 旧 `mu4_real_host_login_cookie_rotation_csrf_logout_and_no_static_fallback` 和 `mu4_identity_origin_csrf_and_directory_injection_fail_before_side_effects` 回归在 `mu4_tests.rs:76` 的 `Fixture::seed_private` 初始化失败：`save_agent_history_path` 被当前事件写入合同以 `SESSION_EVENT_WRITE_REQUIRED` 拒绝，尚未运行到 Host 断言。该旧夹具需要另行适配事件写入方式；INV3 新增无私人历史夹具的真实 Host 测试覆盖启动、登录、Origin、CSRF 和注销。

- 内测码可由持有人转发，首版不绑定预定收件人；未使用码可由管理员停用。
- 邮箱绑定只覆盖老账号首次绑定；更换已绑定邮箱尚未纳入本方案。
- 生产发信通道为 Resend HTTP，发件身份及私有 key 已配置；真实注册、绑定和找回收信在 INV9 通过。
- 邮件通道不可用时，注册验证、邮箱绑定和找回密码暂不可完成；现有登录、已登录自助改密及管理员账号恢复仍可使用。发送和恢复入口限流沿用进程内方式，服务重启后窗口重新计数。
- 升级沿用现有数据库版本机制；候选部署先用数据副本演练并保留切换前备份。回退必须同时恢复匹配的二进制和数据库，不能让旧服务直接打开新 schema；接收新注册后如需回退，应先停写并保全新增账号及业务数据。
