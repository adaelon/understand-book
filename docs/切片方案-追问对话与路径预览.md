# 追问对话与路径预览切片方案

2026-11-18 · **切片 1–5 已接入阅读器。** 产品决定见 [ADR-0188](adr/0188-follow-up-conversations-and-path-preview.md)。第 5 节列出复验入口，第 6 节记录实际结果与待评价项。

## 1. 用同一个例子验收

读者正在读一项教学实验，问“多出来的 8 分，是软件带来的吗？”回答里有“对照组”和“随机分组”。他写了一半自己的猜想，想先弄懂这两个词。

1. 点“对照组”，预览看到已有问题“对照组也上课吗？”和实际回答的开头。已经看懂就收起，原问题、那半句猜想和书页都在原处。
2. 点「进入这条对话」后，读者接着问“能举个例子吗？”仍在同一条聊天。从这条回答里的“课时安排”另开，才在“对照组”下长出下一层。「回到原回答」逐层回到引出问题的那句话。
3. 回到开头，从“随机分组”准备另一问。在预览里把首问改为“抽签决定谁参加，还是决定谁用软件？”点「开始这条追问」后才发送。树中两条同级支线各有自己的问答。

## 2. 空间与交互

| 用户在做什么 | 路径放在哪里 | 用户仍能做什么 |
| --- | --- | --- |
| 边读边问 | 沿用原栏宽，自由阅读默认 384 px，课程问答至少 420 px。路径折在输入框上沿，有出处的词用铜色轻下划线。展开时，下部临时容纳树和预览，上部原回答独立滚动，让当前所引原句可见 | 书页和目录保持宽度与读位。关闭预览回到原输入，整棵树只需在探索时出现 |
| 专心聊天 | 复用 `RightRail.wideConversation`。进入宽屏全屏问答时，把树放在已有左侧「会话」区，目标、历史入口与右侧学习助手各留原位。宽度不足时沿用临时面板 | 中间始终显示活动聊天，点左侧另一行可以先看再决定。问答自己的演示工作区占用空间时保留演示与所属聊天的配对 |
| 用手机读或问 | 在问答输入框上方点「追问路径」，复用底部面板，树、预览、主按钮从上至下排列。收起后把焦点交回触发位置，进入聊天后由用户点输入框唤起键盘 | 在支线点「回到原回答」回到父聊天的原句。点「阅读」回到离开时的书页。切换阅读和问答后可以继续原支线 |

实点和「当前」标活动聊天，浅底标预览行，虚线空点和「待追问」标尚未发送的首问。第一次使用可从回答的划选菜单「另开追问」进入。已有聊天取最近一组可见问答的真实文字。若末问尚待回复，则显示该问题及实际状态。待追问来自读者的选区和首问草稿，已有建议带有明确出处时也可作为入口。预览所需内容都可从已交付文字或草稿得到。

## 3. 数据和操作约定

| 对象或操作 | 实施合同 |
| --- | --- |
| 父子关系 | 在子聊天的 `session.created` 事件上增加可选的追问来源。保存父聊天 ID、父回合 ID、已交付回答中所选文字的起止位置与确切摘文。父子属于同一读者，独立书库按书、学习工作区按工作区解析。材料与版本取父回合当时的绑定。无此字段的历史聊天自然成为根 |
| 原句定位 | 在正式回答的文本部件上保存两端的部件序号与源 Markdown 偏移，使用现有 DOM 映射的 UTF-16 半开区间，服务端按同一单位核对摘文。重复出现的同一词可以分别定位。来源按钮、演示与尚在流式生成的文字不作为段落选区。引用类型是助手回答，书中证据另外沿已有来源绑定核验 |
| 预览与进入 | 只读路径查询由当前根下的父子关系投影，返回节点标题、状态与所选节点的问答摘录。预览只更新界面的选中项，活动聊天、草稿、读位、运行数均不变。显式进入已有节点才走会话选择，不重发它的问题。待追问只占端侧草稿，取消后没有空聊天 |
| 开始与续聊 | 服务端在原范围解析出处，用这次提交的 `client_request_id` 关联子聊天创建及首轮准入。首轮冻结读者首问、原问题、所引解释及可用来源。后续走子聊天自己的顺序历史。同级对话、父聊天后续消息和父聊天的交付任务均留在原处。对历史上较早的已交付回答同样可以发起 |
| 失败与重试 | 父引用验证失败时留在原聊天并保留首问。子聊天已落盘、首问尚未准入时，能找回同一子聊天与待发送问题。准入结果未知时查原请求，已接受则接回原运行。一次提交的重试只得到一个子聊天和一个已接受的首轮。不同问题可以有意从同一句另开 |
| 返回与删除 | 原句可核对时滚到并短暂标出确切位置。文字经修订而失配时，落到父回合并说明原句位置已变化。父聊天已删除时，存活的子聊天保留自己的问答并作为可进入的起点，显示原回答已不可用。删除仍沿现有显式会话操作，后代不会随父聊天一起消失 |
| 草稿与阅读现场 | 在同一设备按读者、学习范围和聊天保存编辑现场，切换时取回该聊天的输入、已选引用及随草稿的既有选项。父聊天和各支线可以各留一份草稿。阅读返回点保管书页与课程表面的位置，打开地图、预览或进支线都保留进入前的读位 |

权威关系随子聊天日志保存，邻接关系由已有会话投影派生。同一个父日志不另写一份子节点列表。工作区内可切换资料，重开历史时按原来源和可见范围解析，当前打开的书不能替换旧提问的出处。[会话顺序日志](adr/0152-resident-linear-jsonl-session-log.md) · [学习工作区归属](adr/0170-goal-scoped-learning-workspaces-and-shared-releases.md)

## 4. 按用户路径交付

### 切片 1 · 在本地书里单独问一句，再回到原处

从已交付回答划选一个连续片段，编辑首问，发送，收到子聊天回复，再点「回到原回答」。第一片就贯通真实日志、读时运行和阅读问答栏。复用回答选区、顺序日志和原发送链，新增子聊天来源和跨聊天的首轮上下文解析。闭卷期间沿用当前尝试的可见范围。现有「这一步没跟上」继续在当前聊天工作。

**验收**　把同一词放在答案中两处，只圈第二处。在父框留半句草稿，进入支线再普通发送一次。父历史没有新增回合，子历史包含两轮，返回时命中第二处且草稿仍在。用真实临时日志目录关掉服务再重开，父子关系仍能解析。在子创建成功和首轮回执之间模拟中断，重试命中同一子聊天。旧的无来源 JSONL 能继续阅读。观察首轮实际输入，核对原问题与所选片段。若评价回答是否承接原意，另留获准真实模型的输入输出。

### 切片 2 · 在阅读分栏预览兄弟与下一层追问

依赖切片 1。把只读路径查询接到输入框上沿和回答词句，在右栏下部呈现同一棵树。先支持读者自己建立的路径和待发送首问。树上点选、显式进入、开始新追问分别处理。长树能滚动至选中的节点和进入按钮。

**验收**　搭出第 1 节的两条同级支线和一个孙节点。从“对照组”预览另一支，核对摘录来自那条聊天。多次预览、取消待追问时，断言活动会话 ID、日志回合数、模型准入次数不变，书页宽度与读位不动。直接查看分栏截图，所引原句在树上方可读。另删掉父聊天或让原回答修订，分别验证第 3 节的两种返回结果。

### 切片 3 · 换成全屏或手机，继续同一条支线

依赖切片 2。宽屏把路径面板移进左侧原会话区，小屏复用底部面板，预览节点、当前聊天、各自草稿共用同一状态。聊天附带的演示仍归原聊天。显式转入另一聊天时收起该演示，返回时能恢复原现场。

**验收**　在 1440 px 桌面由分栏切到全屏，再退出，比较书页读位和聊天 ID。在 1024–1279 px 的全屏或占用中的演示工作区检视临时面板。用 390 px 和 320 px 手机逐步操作「预览 → 进入 → 回到原回答 → 阅读 → 问答」。检查首问和主按钮可达、键盘与关闭后的焦点、无横向溢出，保留三种布局的真实页面截图。内测时请读者看看“随机分组”准备问什么，然后接着写原先的猜想，观察他能否分清正在聊哪条、下一步会回到哪儿。

### 切片 4 · 在云端重开自己的追问路径

依赖切片 2，可与切片 3 分开实施。云端宿主复用公共服务的来源、只读预览和创建合同，接入现有工作区选择、读者权限与运行准入。读者从本书历史重新进入已有支线，也可从学习工作区回到原聊天。预览不改变云端工作区的 `selected_chat`。

**验收**　用真实云端宿主与临时私人存储，在独立书库、两个含同一本书的工作区以及另一读者下核对树的可见范围。在同一工作区切换当前资料后查历史，原句仍指向原材料版本。模拟开始追问后网络回执丢失，再连接只回到同一个运行。子聊天的回复在读者返回父聊天后才到达时，只更新子聊天。重开与删除按同一归属验证，并用公共本地入口复验同一正常路径。

### 切片 5 · 在课程中旁问，再回到同一步

依赖切片 2、3，云端验收复用切片 4。读者在课程、原文或实验表面从右侧已交付回答另开讨论，实际求助绑定当前有效的 `CourseRun`、步骤和来源。切回原回答后仍在发问前的课程步骤或实验现场。沿用现有课程帮助和闭卷可见范围。[课程归属](adr/0182-book-structure-led-inquiry-courses.md) · [闭卷对话](adr/0183-closed-book-dialogue-to-independent-performance.md)

**验收**　在活动课程留下草稿后走完“预览 → 实际求助 → 回到原句”，核对预览没有帮助记录，实际求助有正确归属，课程步骤、完成状态和独立作答证据没有被导航推进。闭卷练习期间，树和预览必须服从本次尝试的可见回合，无法借另一聊天翻回已遮蔽解答。自第一次开放追问入口就沿用闭卷遮盖，至本片用实际课程往返验收。

### 一条真实模型首问

在隔离的本地 Reader 里放入一段虚构实验材料，预置父问答。读者从回答中第二处“随机分组”另开，问“抽签决定谁参加，还是决定谁用软件？”。DeepSeek Flash 查阅原文后，第一句就说明报名决定谁参加，抽签决定参加者中谁用软件。解释引用了实验原文第 1.1 段，假设的 100 人例子也标明为虚构。就这一个样例，原句承接与核心解释通过。两步说明、举例和总结重复了同一个区别，作为一次澄清偏长。[最终回答](evidence/follow-up-conversations-20261118/real-model-2026-11-18T10-12-15-054Z/run.json)

初稿把同一个反问写了两遍。阅读器要求修订，第一次验收时本地采样工具未识别当前修订指令，页面只交付了原文。修正请求分类后，回放这个样例已经取得的查书请求和回答，只补发原修订请求。最终写入子聊天的回答有一个苏格拉底问题和一个可定位的正文出处，父、子聊天各一轮。采样工具的 11 项测试通过。[首次不完整交付](evidence/follow-up-conversations-20261118/real-model-2026-11-18T10-08-52-721Z/run.json) · [采样工具回归](../evals/semantic/provider-recorder.test.mjs)

本次授权 1 个样例、上限 1 元。共 3 次计费模型请求，累计未命中输入 30,648 token、命中输入 27,520 token、输出 3,150 token。按请求发生时的非高峰人民币费率估算，合计 **0.0437984 元**。[语义与用量记录](evidence/follow-up-conversations-20261118/real-model-2026-11-18T10-12-15-054Z/semantic-review.json) · [DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
