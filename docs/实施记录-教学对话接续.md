# 教学对话的参与与向前探索

日期：2026-10-28。范围：当前工作树的主 Agent、Tutor、教学与表达教练、解释审核及其已有接续合同。

## 决策与实现

当前请求得到完整回应后，在值得继续的停靠点提供一个容易参与的入口。入口可以让用户表达当前理解，也可以从刚建立的关系出发，用一个变化、观察或猜想打开下一知识点。用户已经说清当前关系时，优先留下尚未解决的新关系，避免讲完下一课后再换数字复习。需要的对象、条件和含义应已可用，不要求用户猜陌生术语。

- `learner_starting_point.md → agent_prompt.rs`：共同原则覆盖普通问答、旧聊天和 Tutor 各状态；学习起点与讲解职责资产均升至 v2。普通聊天沿真实历史接续，不因此自动开启课程。
- `tutor.rs`：指导升至 `teaching-design.v21`。`participation=invite` 同时允许表达理解和探索新关系；仍经 `response_expectation → pending_response_invitation → responds_to` 交付与回应。新增受助表达示例进入现有真实 schema 和 Provider 投影测试；普通执行的直接讲解示例不夹带邀请，模型公开词表仍保持稳定。
- `tutor_continuation.rs`：未来帮助选项说明当前关系怎样连接新问题及其用途。表达邀请与未来帮助分别使用已有入口，避免同时给问题和菜单。新知识仍遵守当前设计、来源和目标范围，扩焦沿已有设计修订链路。
- `tutor_coach.rs` 与 `tutor_coach/presentation.rs`：教练根据真实回应安排后续，画板可用具体变化引出下一问。“不知道”提供小示范或提示；“继续”“直接讲”“跳过”与新问题按当前请求处理，不重复逼答。仅观察模式保持原权限。
- `tutor_explanation_review_rules.md`：升至 `explanation-delivery.v6`。完整当前答案可以留下下一问题，不要求提前讲完新知识；没有问句不构成失败。有强制作答门槛、必要信息缺失或冲突邀约时才针对具体问题修改。

现有理解记录继续区分用户原话、已经获得的帮助与可修订判断。复述已给解释支持局部的受助表达，不变成独立运用或掌握证明。没有新增数据库状态、UI 关卡或生产模型调用。

## 真实对话案例

以下为配置模型 `deepseek-v4-flash` 的公开原文节选。第二轮保留实际第一轮回答，测试用户分支在读过该回答后编写；不把这些模拟回应称为真实读者学习结果。

### 已经说清当前关系，打开下一关系

第一轮问题是“递归是什么？书里只说函数调用自己。我完全不懂。”模型用倒计时说明每次调用和终止条件，并邀请预测 `countdown(2)`。测试用户回答：

> 依次是2、1、发射。因为每次调用的n比前一次少1，到了0就直接停止。

最终规则下，模型先回应这两个具体关系，然后提出：

> 再试一个小变化。下面这个函数在**递归调用之后**又加了一句打印：

```python
def f(n):
    if n == 0:
        return
    print(n)
    f(n - 1)
    print(n)
```

> 如果调用 `f(2)`，你猜会依次打印什么？提示：想一想外层调用在 `f(n - 1)` 那里“暂停”之后，等里面做完会发生什么。

这次改变了观察对象：从递归如何停止，进入暂停的外层怎样继续执行。模型没有先给出新问题的结果。实际执行该段公开代码已确认问题有确定结果，记录在 `tmp/dialogue-next-step-20261028/invitation-code-result.json`。

同一历史在第一候选下，会先讲完整个求和函数，再让用户把 `total(3)` 换成 `total(4)` 练习。两份输出都保留：初次为 `runs/followup_recursion_correct.response.json`，最终为 `runs/followup_recursion_correct_final.response.json`。这是同一历史上的一次定向比较，不代表稳定成功率。

### 接受下一步，就兑现它

平均速度例子讲完后，模型提出等时间与等路程的区别。测试用户说：

> 继续讲前一半路程快、后一半路程慢的情况吧。

模型沿用 120 公里，明确假设前后各 60 公里分别以 90、30 公里/小时行驶，算出总时间 2 小时 40 分钟、平均速度 45 公里/小时，并说明：

> 同样是 90 和 30 两个速度，**“各走一半路程”得到 45，“各走一半时间”得到 60**。区别就在于：每种速度持续了多久。

这是对既有承诺的实际展开，没有重新要求用户选择下一方向。完整原文为 `runs/followup_speed_continue.response.json`。

### 用户选择的边界

- 用户说“不知道，我还是没看懂为什么外面的调用要等里面的”，模型转用普通函数调用的泡茶/烧水例子解释等待与返回，再联系递归。
- 用户说“这个我先不猜了，你直接带我看执行过程吧”，模型直接展开 `countdown(2)` 的执行过程，没有要求先答题。
- 用户说“先不做这道题了，我想知道它和循环有什么区别”，模型回答新问题，没有继续追问旧邀请。
- 用户明确要求“只告诉我结果，不要继续讲，也不要提问”，最终规则下只回答“60 公里/小时。”

## 验证与证据

模型输入由 Rust 生产请求构建器导出，原始系统指令、请求、公开回答、用量和失败均保留在 `tmp/dialogue-next-step-20261028/`。第一候选为 `final/`；最终规则为 `revised/final/`。最终对话比较显式替换系统指令，保持实际公开历史和测试用户回答相同。运行脚本支持显式 `--system-file`，不会悄悄覆盖早期请求。

共 10 次模型调用，合计 47,467 tokens：第一候选的两个起步和六个第二轮分支；最终规则的一个同历史定向比较和一个明确结束边界。全部返回完整公开回答和用量，无网络重试；文本回答不要求 JSON。没有再进行提示词循环试验。

92 项不同自动回归通过，覆盖主请求装配、教练请求及纠错、Tutor 状态和接续、邀请交付、原生画板、工具示例/Provider 投影、解释审核投影及请求预算。初次发现普通邀请示例过滤影响模型词表稳定，已修复其原生画板回退条件；新增示例与当前工作树的工具示例总数断言同步更新，77 个公开工具示例均通过真实结构与 Provider 投影校验。早期失败日志保留，最终按测试名称去重且以最后结果为准，见 `tmp/dialogue-next-step-20261028/regression-summary.json`。另有一项需指定录制目录的教练回放保持忽略，生产提示导出成功。

## 限制

此次真实语义试验使用普通聊天的生产指令；主动 Tutor、教练及画板链路由自动请求/交付回归覆盖，不等同于完整 Reader 多轮运行或真实用户学习效果。

第一候选仍有两个相关问题：平均速度首轮串了两个问题，递归答对后先讲下一课再换数练习。最终规则明确单个回应任务和先打开未解关系，并只针对后者完成一次同历史复测；未宣称所有首轮都已稳定改善。

第一候选还出现较长的解释、把普通同步函数调用概括成“任何函数调用”的过宽表述，以及直接讲解样例中的“一刻钟前”等无依据措辞。此次未逐项重测或认定这些生成质量问题已消除。更换数字的练习在有实际需要时仍可使用，不要求每一轮都引入新知识。

本轮未修改界面或部署，也未将这些样例认定为事实准确性全面通过。
