## 修复结果

- `video.read_frames` 未说明 `start_ms <= sampling[i] < end_ms`；采样数量、排序、时间范围共用一条报错。实际问答两次采到了区间结束时间。
- 帧读取的 IO/解码失败也标记为 `invalid_input`，容易引导无效参数重试。
- 共享媒体范围和框选校验仅报告 `location` / `region`，没有指出约束和输入值。
- `video.review_audio` 写作 0–30 秒，实际范围为 1–30000 毫秒；问题文本与范围错误混合，并归类为 `unavailable`。
- `video.search` 的查询和 limit 错误混合；未知 analysis_id 未给出可用的恢复方式；可选范围、默认分页和后续读取参数说明不足。
- `source.present` 的媒体参数缺少直接复制实际帧/音频目标、帧与区域合计上限的说明。

以上缺口已修复。三个视频工具共享原始毫秒时间范围的声明，发布五个可解析、可分派的调用示例。保留既有错误码；由调用者修正的参数错误标记为 `invalid_input`，文件、索引和解码不可用标记为 `unavailable`。

原始失败现在返回：

```text
sampling[6]=20000 ms is outside [start_ms=10000, end_ms=20000) ms.
end_ms is exclusive: require start_ms <= sampling[i] < end_ms.
Remove this sample or choose a time inside the range.
```

扩展回归还发现视频图谱与讲解结构两个加载器直接反序列化带标签的媒体证据，在 Server 的 `serde_json/arbitrary_precision` 配置下拒绝合法小数帧时间。两处沿用项目已有的 `JSON Value → typed value` 解析方式，保持原始小数时间与媒体引用。

## 二次实际问答复现及补修

重启后的 `turn_f581e0ae9701d5d8` 使用新程序。实际只发出两次取帧调用：先把 `video/start_ms/end_ms` 错放在顶层，缺少 `location`；修正结构后又把 20000 放入 `[12000,20000)` 的采样列表。两次均在解码前失败。最终回答将前一轮的两次失败一起算入本轮，不能作为本轮工具调用证据。

原有无进展守卫在两个无进展批次后禁用工具，只为文本定位与 Tutor 参数纠正提供一次恢复；视频工具尚未接入。冻结帧上下文也只给位置和自然语言指导，模型仍需自行组装范围和采样参数。

补修沿用现有机制：

- 冻结帧上下文提供完整 `frame_read_hint`，精确保留时间和框选，结束时间限制在视频时长内；没有框选时省略 `region`。有当前帧时直接暴露 `video.read_frames`。
- 三个视频工具的 `invalid_input` / `validation` 错误可使用已有的一次恢复机会。相同参数仍被重复调用守卫拒绝，修正后继续错误会结束；资源不可用不会获得参数纠正机会。
- 新增“漏字段 → 结束点错误 → 修正成功”的完整 Runtime 链路测试，同时覆盖修正仍失败、重复参数和资源不可用。扩展首轮请求测试，验证提示参数通过实际工具 schema；补真实视频末帧、有/无裁剪的读取测试。

已用同一份原视频及框选重放合法读取，返回 `actual_pts_ms=15466.6875` 和 1754×1015 PNG。旧诊断程序的图片请求使用 2048 输出 token 上限，当前模型因推理输出达到上限而结束；随后使用当前源码构建的完整 Resident 链路和原配置验证实际问答。

第一次完整重放进一步发现：模型精确复制 `frame_read_hint`，但 `serde_json::from_str::<ReadFrames>` 将合法框选宽度 `0.9135416666666667` 解析成 `0.9135416666666668`，使 `x + width > 1`。模型改读全帧后完成了回答，识别出 Delphi Scaling Suite Results；本次运行实际提交一组五张图片并接纳观察，但没有成功保留原框选。已用原始参数建立失败回归，确认为 JSON 浮点解析误差。共享媒体契约的 serde_json 启用 `float_roundtrip`，保持调用参数精度和既有几何边界。
