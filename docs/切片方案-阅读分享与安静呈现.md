# 阅读分享与安静呈现：实施切片

日期：2026-10-10 修订。状态：设计已接受；RS0 文档已落档，RN1–RN4、RS1–RS8 待实施。决策入口：[ADR-0160](adr/0160-reading-share-images-and-calm-surfaces.md)。

交付顺序：演示笔记保存与返回 → 统一记录、编辑与回看 → 笔记／摘录分享 → 本次阅读回顾 → 书架接续 → 回答与图解分享、理解空间。RN1–RN2 形成首个演示笔记闭环，RN1–RN4 完成笔记升级交付；随后 RS1–RS3 完成图片分享首版。后续新功能方向列于 §7，尚未排期。

## 1.1 笔记内容与关联

一条新笔记分别表达以下内容；这是领域合同，RN1 将它映射到现有 `Record` 与服务接口的笔记专属字段：

```text
阅读笔记
  自己的文字：用户明确填写或编辑的正文，可含 Markdown／公式
  保留片段：可选的原文摘录或助手摘录，保留其内容身份
  主要关联：原文选区 | 已交付回答 | 已保存演示现场 | 既有正文放置
  正文标记：存在确切选区或显式放置时才显示
```

首版每条笔记有一个主要关联，至少包含自己的文字或明确保留的摘录。只有演示关联、没有文字的操作不形成笔记。原文入口沿 `SelectionContext` 取得摘录与精确范围；回答入口保存选定片段、原 `session_id + turn_id` 和该回合的实际来源绑定；演示入口保存 `PresentationFollowUp` 所指的确切版本与现场。网络材料保留原发布引用，本地材料沿现有书籍绑定。用户填写的正文与保留片段分区编辑和展示。

原文选区与正文放置沿既有定位规则；回答和演示笔记的保存不再要求选择正文落点。读者另行选择“放到正文”时，沿原放置流程增加或移动显示位置，笔记关联保持原对象，放置位置只说明“显示在这里”。新关联仅从用户明确选择的已交付内容或成功保存的现场建立。

内容编辑、重锚和保留操作继承原关联及保留片段，使用原子命令返回的记录身份；失败时旧记录保持。同样文字关联不同演示版本或状态时分别保存，重复提交同次记录沿现有 `CREATED | EXISTING` 语义处理，身份比较纳入实际关联。演示版本和参数不会因编辑文字而更新；记录另一个现场时新建笔记。

笔记继续存入原私人 memory。RN1 沿现有 MemoryDocument 版本机制从当前 v3 升级到 v4，并保留已支持的旧格式读取／升级链路；核对旧记录正文、标识、选区、放置、来源、时间和其他私人记忆均保持。旧记录以原正文和已有结构字段读取，作者未知时使用“阅读笔记”，新内容身份只记录新入口确切发生的操作。`>` 本身不决定作者、来源或记录类型。

## 1.2 演示留存与返回

```text
演示页“记一下”
  → 取得并保存点击时的版本与现场，得到不可变回执
  → 打开绑定该回执的笔记编辑草稿
  → 写下自己的想法
  → 保存笔记及确切关联
  → 笔记列表重新打开
  → “打开演示”定位同一版本；“回到记录时”显式恢复记录现场
```

现场在点击“记一下”时固定。之后继续调整演示不改变这条草稿的关联；关联卡显示演示名称、当时步骤和结果摘要。初次记录失败时保留已输入文字并提供重试，完整保存成功才显示“已保存”。编辑已有笔记继续使用原关联。

版本、现场、内容文件、图像／动画等必要资源继续保存在原私人演示存储，笔记保存其确切引用。保存时校验所选版本已经交付且现场回执属于该版本，读取时由服务端从当前用户的已存笔记解析关联。聊天删除后仍能读取该版本、现场、文字说明、来源绑定和必要资源；仅绕开对已删除聊天的存在性依赖，材料访问与私人对象归属仍沿既有合同。来源显示其原材料与发布。

编辑笔记继承保留关系；删除笔记解除自身关联。原聊天、另一条笔记仍在引用同一对象时继续保留；既有对象清理依据仍有效的聊天与笔记引用处理。当前已有的文件资源存储与读取协议继续负责资源，笔记正文不嵌入整份演示文件。

打开笔记只显示文字与关联卡，不改动当前演示；两个显式返回动作复用原宿主和恢复协议。笔记来源的打开与恢复可独立于原聊天执行，不自动重建已删除的聊天。若读者从返回的演示继续追问，消息归当前明确选择的对话，携带服务端从笔记取得的原版本与现场关联；原聊天仍存在时可另行跳回该聊天。版本更新不替换笔记已记录的版本。

## 1.3 编辑与回看

桌面采用轻量侧面编辑，阅读正文或演示保持可见；手机使用可收起的单栏编辑区，输入与保存操作随可用视口重排。主要输入是“记下你的想法”，关联卡只读，预览按需展开。原文、回答、演示、Markdown 批注、PDF 批注及 Notes 主列表共用同一编辑草稿与操作语义。

| 动作 | 草稿与现场行为 |
| --- | --- |
| 点击外侧、收起编辑区 | 收起并保留草稿，通过“继续编辑”返回 |
| 翻页、调整演示、同材料切换聊天 | 草稿仍属于创建时的材料与关联，不随当前画面改写 |
| 编辑已有笔记并保存 | 仅提交明确编辑的文字，关联、保留片段与原读位保持 |
| 新建另一条或切换材料／发布 | 有未保存内容时提供保存、放弃、继续编辑；保存失败则留在原草稿 |
| 用户明确放弃 | 清除当前草稿，已保存笔记保持 |
| 退出或换用户 | 沿身份清理入口清除旧私人内存；主动退出前处理未保存内容 |
| 页面刷新／关闭 | 通过宿主可用的未保存提示提醒，首版草稿驻留当前页面 |

保存动作使用草稿固定的关联和当前有效授权，不能用保存时碰巧选中的聊天或演示替换它。延迟返回的现场读取或保存结果沿原作用域过滤；换用户后不会重新显示旧草稿。输入法组合输入期间不触发快捷保存。

笔记列表默认显示当前材料的最近记录，按原 `generated_at` 首次保存时间倒序排列，另提供原文顺序查看。搜索覆盖自己的文字、已保留片段和可读取的关联标题；原文、回答、演示和高亮可按类型筛选。列表以短预览、可读来源名称和保存时间支持扫描，完整内容在详情区阅读，预览本身保持静态。高亮仍有独立身份和原编辑动作。

笔记详情先显示自己的文字，再显示保留片段及关联卡；来源、删除、正文放置等次要操作按需展开。原文笔记提供查看原文，回答笔记提供原回合入口，演示笔记提供同版本定位与记录现场恢复。来源往返、回顾打开笔记以及关闭编辑后返回沿现有阅读连续性机制。

## 2 页面融入与视觉规则

统一气质是暖纸色、稳定的内容重心、按关系分组的间距和少量手写点缀。既有主操作延续珊瑚色；分享预览允许选用奶油蓝。正文与操作文字使用足够深的颜色。

| 表面 | 内容组织 | 交互重点 |
| --- | --- | --- |
| 分享图 | 小标题／一个主要内容块／来源与补充感想 | 主要内容占中心，短内容允许宽松留白 |
| 本次阅读回顾 | 一个当前关注条目＋四类事实 | 选中条目突出，其他记录继续容易浏览 |
| 书架 | 顶部一个接续区域＋原材料网格 | 继续阅读是接续区的主要动作，找书仍保持效率 |
| 笔记编辑 | 自己的文字、紧凑关联卡、按需预览 | 阅读背景可见，收起可续写，保存反馈明确 |
| 笔记列表与详情 | 短预览／保存时间／可读关联；详情先显示自己的文字 | 搜索、最近记录、原文顺序及显式返回现场，分享靠近所选内容 |
| 演示／图解 | 主要图面、短说明、来源与相关操作 | 大画面保持可读，实际图例、数值和参数完整 |
| 理解空间 | 当前概念、实际原话、当前解释、依据 | 保留原有纠正和事实查看入口 |

界面初始间距：同组 8–16px，区块 24–48px；封面式大图圆角 24–32px，紧凑操作保持既有尺寸。它们是首轮视觉参数，依据真实内容调整。长文、列表和控件左对齐；短标题和封面可居中。手写字只作少量装饰，状态、来源与操作标签保持清晰字体。

窄屏按可用区域重排，手机减少外围留白。装饰、面板和字体变化沿 [ADR-0148](adr/0148-reader-typography-annotations-and-motion.md) 保护读位、原生选区和减少动态效果偏好。聊天继续沿[阅读助手空间调整](design/reading-assistant-space-20261009.md)保持正文主位。

## 3 分享流程与内容归属

首批内容来自读者明确选取的一条笔记或一段可引用原文。两种排版分别为“摘录卡”和“理解卡”：前者突出原文，后者突出选定笔记及读者在草稿中补写的感想；理解卡的版式名称不赋予内容掌握程度或作者身份。新笔记允许分别选取自己的文字与保留片段，预览沿其内容身份显示；演示笔记可先分享文字与关联说明，实际图面由 RS7 接入。

```text
笔记／高亮／原文选区的分享入口
  → 沿当前身份、材料和原对象读取所选内容及来源
  → 固定本次所选正文，建立页面内分享草稿
  → 调整标题、感想、两种排版及配色
  → 按实际字体排版，预览全部页面
  → 下载当前页或依次保存多张 PNG
  → 关闭后回到原阅读位置与入口
```

草稿准备、预览和导出都是用户动作。草稿中的标题和新增感想可编辑，所选原文／已保存正文为只读；更换选段回到选材步骤。预览中的修改只影响本次分享表达。首版草稿和生成图片驻留当前页面，关闭或刷新后结束；导出失败保留草稿供重试。

| 内容 | 显示身份 | 来源处理 |
| --- | --- | --- |
| 已通过既有引用规则的原文选区 | 原文摘录 | 保留原书名及可解析章节／页码，沿冻结选区取得正文 |
| 新笔记中用户明确填写的文字 | 我的笔记 | 沿已存笔记关联解析原文、回答或演示现场 |
| 笔记中保留的原文／助手片段 | 原文摘录／助手解释 | 使用片段已保存的真实来源绑定，与用户文字分区 |
| 旧笔记或作者未知的正文 | 阅读笔记 | 沿已有记录解析可用来源与关联，保持原正文 |
| 读者在草稿补写的一句话 | 我的感想 | 与原文和笔记正文分开呈现 |
| 后续接入的已交付回答 | 助手解释 | 使用该回合已绑定的来源，保持原材料和版本 |
| 后续接入的回顾条目 | 阅读回顾 | 保留原聊天及记录截点，内容按用户选择输出 |
| 后续接入的图解 | 图解与说明 | 使用确切演示版本、可见状态及其来源 |

当前 `MemoryRecord` 的 `source_session_id` 本身不证明作者。RN1–RN4 记录的新内容身份供分享读取；旧笔记按已有事实使用“阅读笔记”。没有来源的笔记可以分享，原文出处不填造。来源目前不可用但已有确切出处记录时保留该记录并标明状态；重新读取失败不能换成当前书的出处。书名优先取真实材料元数据，缺失时用已有材料名称；图片标题的编辑不改写书目来源。

宿主复用已有用户、材料发布和现场绑定。换用户、退出、切换材料或聊天后清理原分享草稿及待下载结果；迟到的来源读取仍由既有请求作用域过滤。同一现场内用户继续翻页不会改写已经选定的分享内容。派生图片只包含用户在预览中看到并选择的内容，内部用户标识、文件路径、协议字段和未选择的对话保留在原系统。

本期流程沿原读取接口运行，由浏览器本地排版导出；既有阅读记忆、教学和会话存储继续拥有原始内容。分享动作本身不启动模型任务。

## 4 版面与导出合同

首批两种排版均采用固定浅色纸面，保证分享图片在不同设备上外观一致；预览工具栏跟随应用显示模式。默认沿现有暖纸与珊瑚色，奶油蓝为另一个配色选项；正文深色、来源可读，手写点缀不承载事实。输出先采用 1080×1440 的竖版 PNG；RS7 为图解增加 1440×1080 横版。预览按比例缩放，分页按输出尺寸计算。

两种排版都包含标题、已选内容、内容身份、必要来源、可选感想和克制的产品署名。原文和说明保持原字符与顺序。实现以同一份排版结果驱动预览与输出，避免分别维护两套换行规则。

```text
当前分享草稿 + 实际就绪字体／内容资源
  → 排版与分页结果
  → 预览每一页
  → 按同一结果输出 PNG
```

正文优先使用项目已分发的中文字体，控制标题与正文层级；1080px 宽竖图初始正文字号为 40–48px，辅助来源不小于 28px。长内容按段落、列表项、完整公式或表格行等实际内容块分页，超长段落按文字行续页，续页带标题、页序和出处。完整输出保留所选文字，不静默省略；过宽表格、过高公式等无法完整放入单页的对象提示用户缩小选材，不能裁切后下载。

首片先完成短篇文字笔记；RS2 扩展既有 Markdown、公式、代码和表格的可导出范围，并提供长内容分图。无法导出的内容在预览前给出具体原因及重新选材入口。图片资源复用现有已解析材料资源；封面不是首版文字分享的必需项。未知或加载失败的内嵌内容不得用空白冒充成功输出。

PNG 渲染方案在 RS1 用真实中文字体和两张最小版面确定；如需增加库，只引入经本项目浏览器样本验证的单一导出依赖。RS7 的演示导出另沿其现有隔离和资源协议接入。具体库及实际支持范围写回本节，验收看下载文件的真实内容。

浏览器提供明确下载动作；移动端需要预览／保存图片时沿实际浏览器能力提示。多图允许逐张保存，批量保存作为便利入口，不能成为唯一出口。桌面包沿已有本地文件保存能力处理；若要扩展桌面命令，仅负责写入这次已生成的图片字节。

**完成判据**：页面与图片只表达当前聊天指定截点内的事实；刷新可以显示新事实，已经打开的分享草稿仍保持原选择，重新选材后才采用新内容。已有来源、成果和跨发布跳转继续工作。

**验证与失败处理**：覆盖空回顾、多条目、原对象不可用、刷新和跨发布往返。若图片范围漂移则修所选回顾数据的绑定；若状态把“已回答”写成“已懂”，修展示映射。打开、刷新与导出均不增加学习事实或模型调用。

## RS5 书架与阅读接续卡

**输入**：授权书架、封面、当前主窗口原有可恢复现场及其持久读位／聊天选择。现有书架列表只有材料与封面，接续摘要需要在本片接入。

**产出**：书架顶部增加一个接续区域，显示实际材料、已保存位置、可取得的上次问题或明确待继续项，主动作是“继续阅读”；其余材料继续使用紧凑网格。

**接点**：`NetworkApp.vue`、`BookCover.vue`、`network-client.ts` 和现有 workspace 恢复入口；接口不足时在原授权读取边界补只读摘要，由既有持久状态派生。

**完成判据**：目标是当前主窗口已有的明确可恢复现场，不从书架排序猜“最近”。点击后进入正确材料、发布、聊天和读位；仅显示卡片不执行阅读跳转。没有记录时显示正常选书入口；没有问题时只展示读位。无权访问的材料沿既有状态处理。

**验证与失败处理**：覆盖刷新后恢复、同书多个发布、另一窗口阅读不同材料、无记录和授权变化。错误恢复修原现场绑定；缺少摘要数据先补原只读投影，不能另存一份读位或伪造问题。

## RS6 已交付回答分享

**输入**：RS3、单条已交付回答的可见内容及原回合绑定来源。

**产出**：回答菜单提供生成理解卡，读者选择所需文字并编辑标题／感想；助手解释和读者新增内容分别显示。

**接点**：`RightRail.vue`、`App.vue`、`AgentAnswerView`、既有来源解析和分享面板。

**完成判据**：图片仅含选中回答，来源指向该回合的实际材料；流式运行内容不作为已交付版本导出。所选片段保留适用条件和关联来源，复杂图解进入 RS7 对应入口。

**验证与失败处理**：覆盖带多个来源、无来源、历史回答、跨材料来源和未完成回答。若正文与来源来自不同回合则修绑定；不可独立理解的选段在预览中允许扩大选择，保留明确的内容范围。

## RS7 图解静态分享与专注呈现

**输入**：RS6、现有 Presentation 内容版本、当前或已保存状态、说明与来源、RN 保留的笔记现场，以及实际 SVG／Canvas／DOM 图解样本。

**产出**：演示工具栏增加“导出当前图解”，使用横版或竖版预览；演示笔记提供“分享记录时的图解”，从其已保存版本与现场取图。静态画面配必要参数、步骤、结果说明与来源，演示外壳使用宽松主图布局。

**接点**：`AgentPresentation.vue`、`PresentationSceneCard.vue`、现有演示通信与资源读取、分享面板；原 iframe 隔离维持。具体输出接口沿原消息协议扩展，只负责本次静态输出。

**完成判据**：工具栏导出对应用户选取的当前版本与状态，改变参数后图片和说明同步；笔记导出对应记录时的版本与现场，原聊天删除后仍使用 RN 保留对象。下载过程不重置正在看的演示或重新运行模型。不能静态输出的具体内容给出原因，不能下载空图或初始状态冒充当前结果。

**验证与失败处理**：在项目实际使用的 SVG、Canvas、公式／DOM 图解上分别验证输出，覆盖资源未就绪及保存状态恢复。图面与参数不一致时修状态绑定；资源失败时明确处理，支持范围按验证过的实际渲染路径记录。

## RS8 理解空间的单项阅读

**输入**：现有理解空间的当前解释、用户原话、实际活动表现及修订依据。

**产出**：概念列表保持可扫描；打开一个概念后突出当前解释、真实原话和相关依据，保留纠正与历史入口。

**接点**：`UnderstandingSpace.vue` 与局部样式；沿现有理解投影和纠正命令。

**完成判据**：暂定理解、独立作答、帮助后作答和历史修订仍可区分；未知保持未知。版面调整后，依据、纠正和历史翻阅可完整操作，长内容在手机上可读。

**验证与失败处理**：用已有理解记录测试多种证据类型和纠正操作；若层级简化掩盖证据性质，修内容结构与标签。此片只调整呈现，不产生新的能力判定。

## 6 验证与记录规则

每片在运行检查前写明具体要发现的失败及对应修正动作。纯版式参数以真实内容对照评审；内容转换、来源绑定、分页完整性、下载产物和原现场连续性用确定性检查。测试覆盖受影响链路，通过后仅在新变更或未解决问题触及时重跑。

RN 测试沿现有 memory、server 笔记／演示和 Web 组件／Playwright 入口增加；覆盖关联身份、旧记录升级、草稿保留、删除聊天后的演示读取及真实恢复。分享测试优先放在 `packages/web/src/reading-share.test.ts`、分享组件测试及相关 Playwright 用例中；这些名称是拟议接点，随实际代码固定。测试内容选取本项目支持的真实材料形状，不以断言装饰间距或重复实现逻辑代替行为验证。

每片完成更新本方案状态及 `docs/代码链路.md`，记录实际通过范围；结构或主要数据流发生变化时更新 `docs/架构.md`。笔记升级关闭条件是 RN1–RN4 的存储、记录、回看及留存验收完成；分享首版关闭条件是其后 RS1–RS3 的实际下载与来源／连续性验收完成。当前仅设计落档，所有实现状态以切片表及实际验收为准。

## 7 后续功能方向

以下方向沿本方案记录，排期时再确定新增状态与完整交互。它们不阻塞 RN1–RN4 和 RS1–RS8。

| 方向 | 用户行为与复用基础 | 开始实施时需要确定的内容 | 验收重点 |
| --- | --- | --- | --- |
| 停读时留下接续意图 | 在接续卡基础上，读者明确写一句“下次想看什么”，关联原读位或笔记 | 显式保存内容在现有私人记忆中的归属及再次编辑入口 | 下次进入时能回到当时材料和真实意图，写入与撤回可理解 |
| 我的理解前后对照 | 用户选择两次真实笔记／作答，并附上促成改变的原文或例子 | 两条记录及证据身份的选取、用户说明和对照版式 | 保留原话与帮助条件，由用户表达变化；图片与原记录一致 |
| 回看一个问题 | 从已有问题、笔记或教学活动中选择一项，先思考，再展开旧回答和原文 | 普通回看与正式教学活动的入口、来源失效和反馈职责 | 普通查看不增加能力成绩；正式作答沿已有教学合同记录 |

## 8 已知限制与范围

- 当前新笔记仍受选区／正文放置准入约束，演示读取仍依赖原聊天；RN1–RN4 尚未实现，当前保存回执本身不能兑现删除聊天后返回。材料授权撤销或原材料不可用时沿现有不可用状态，自己的笔记文字保持。
- 旧演示未必支持恢复自定义参数和步骤；RN2 按原恢复合同显示实际可恢复范围，并以完整支持恢复的真实演示验收。笔记打开与恢复不增加学习成绩，记录和分享不触发模型任务，显式追问沿原对话运行。
- 笔记编辑草稿首版保存在当前页面；收起可续写，刷新、进程退出或身份失效后的恢复不作持久保证。宿主支持时提供未保存提示。分享草稿保持原页面内生命周期，与笔记编辑草稿分别处理。
- 首版回看范围为当前材料，搜索复用已读取记录；跨材料主题合集、多人协作编辑和跨设备草稿另行定义。原文与演示的精确引用范围继续由原合同决定。
- 当前前端尚无本方案的通用图片分享入口；导出库、复杂内容支持和各平台文件保存行为须经 RS1–RS3 实测后记录。
- 部分旧笔记缺少确切作者和完整来源信息，其混排正文完整保留并使用中性身份；新入口记录明确的内容身份。已导出的静态文件不会随原记录后续修改而更新。
- 超出可读版面的对象需要缩小选材，长文本则分图；预览必须让用户看到全部实际输出及不可导出的原因。
- 交互教具的静态图只能表达一个明确状态，连续变化和交互操作继续在原演示中查看。
- 分享首期交付为本地图片保存；公开链接及其访问范围、跨设备分享草稿和跨聊天主题合集留待独立需求。
- 本期沿现有材料与访问规则运行，正文排版、PDF 文字层、学习判定及运营页面继续遵守各自合同。
