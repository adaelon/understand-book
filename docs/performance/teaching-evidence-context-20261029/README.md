## 变更

### 完整补证后统一修订

`tutor.rs` 的修订指导与 `orchestrator.rs` 的实际退回回执，现在要求先明确每个缺证项的完整关系，再选读取范围。章序涉及成员及先后，比较涉及双方与成立条件，案例涉及措施、结果及连接；单一搜索命中不能代替整个关系的原文。

已有合法首尾时直接通过 `book.text` 的 `lid/end_lid` 连续读取，独立位置使用现有 `book.text_batch`。缺边界时才使用 context 的真实邻接/next_calls 或检索，禁止猜编号。读取所需 continuation 后再统一修订，证据已支持原句则保留正文，允许 `edits:[]`。

事实与综合审核的 `required_change` 同时明确尚缺关系及已有定位下可执行的完整补查方向。四字段 finding 合同、稳定问题编号、实际来源引用校验、全文事实审核、独立解释审核均保持。当前源码规则版本为 `teaching-design.v28`、`text-facts.v10`、`explanation-delivery.v10`、`teaching-delivery.v36`。最后一次完整回放使用解释规则 v9；随后 v10 修正输出示例并作定向验证。各轮数据仍对应各自冻结的 binary，不追溯套用新规则。

首组回放暴露两个真实缺口，第二版同时修正：

- 首次退回回执的完整 JSON 为 10,793 / 11,167 字节，超过 `MemoryReceipt` 的 4 KiB 模型正文限额。实际发送时只剩 `semantic_budget_exceeded`，完整 `review_feedback` 被省略。普通文本修订现把未解问题全集、最新问题处置和补证指导放入已有 `agent.teaching_revision` 私有上下文，工具回执只提供短错误与草稿引用。意见只携带一份，重复的 findings 和 draft_ref 不再复制。每次保留草稿都从审核历史重建，参数、前置校验或审核调用失败不会清掉尚未解决的意见；成功接纳沿既有路径清理。
- 解释审核先前会按宽泛问题的最低充分性接受缩水稿。现在同一请求的修订须保留首稿已有且相关的解释作用，投影附两份实际正文的中立差异，同一次解释审核明确给出 `revision_comparison`。首稿与当前稿引文分别验证；实际丢失关系进入已有 unresolved/revise 流程。允许纠错、准确等价替换及删除无关内容，首次审核与视觉综合审核不新增比较合同。

这两项修正不增加模型审核阶段，不提高全局工具预算，也不新增补证工具或自报通关状态。原始完整审核记录仍沿原路径保存。

这是对读取行为的具体指导，不能单靠提示词宣布语义覆盖已被程序保证。真实回放需要证明模型确实读全所需关系，并避免第一次补证后再次缺证。

### 合并同次采样前的重复 system 快照

`deepseek_messages.rs:flush_updates` 中，同一次 assistant 采样前积压的完整 system 文本快照只保留最后一份。后者已包含全部有效上下文；全部工具添加、移除保持原顺序和位置关系。跨 assistant 边界已经生效的历史快照、原生续接、签名、工具调用和结果均保持，leading-only 路径不变。

依据是模型能力中 `in-history` 的完整替换语义：[DeepSeek 官方模型能力文档](https://api-docs.deepseek.com/api/list-models/)。处理范围仅为同次采样前尚未消费的快照，未进行历史摘要或删除来源。

使用上一轮 candidate-04 首个真实作者请求做离线比较，system 正文 UTF-8 字节从 1,157,864 减至 938,926，减少 218,938（18.91%）；历史纯文本快照 11 → 8。逐项比较各 assistant 边界及尾部的有效 system、全部非文本快照消息、leading system 和其他设置均相同。该比较直接证明发送正文减少，token、缓存和耗时以真实 Provider 结果另测。
