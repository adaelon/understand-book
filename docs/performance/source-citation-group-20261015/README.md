# 来源引用成组提交试验

## 意图与范围

用户在上一轮批量读取报告后确认“可以，那继续实验吧”。本片保留 `book.text_batch`，仅调整已有 `source.present` 的引用规划指导，验证成组提交、复用已有引用、局部修正失败是否减少模型往返与实际 token。引用仍须匹配本轮已观察原文；不改变来源验证、工具输入合同或 Provider 的并行参数，不部署。

来源引用、本轮证据账本、Agent 请求计划均沿 CONTEXT 既有定义；成组只是多个独立调用的组织方式，变更类型为纯技术。前轮已经说明 token 收益不稳定，用户同意继续以实验结果判断。

### §1.1 引用规划指导

**决策**：先验证现有引用工具的成组使用指导。

**否决**：
- 新增批量引用工具：现有 Runtime 已能处理同轮多个独立引用，先隔离提示对调用行为的影响。
- 全局开启并行调用：会改变其他工具的采样策略，超出本片因果对照。

**命门**：完整保留来源覆盖和错误拒绝，不能用减少引用来代替省调用。
**何时回头**：真实 Provider 不采用成组调用，或重复对照显示总 token 未改善。

## 实施步骤与状态

1. 构建当前工作区基线（含上一轮批量读取及此前已有改动），保存独立可执行文件。
2. 只修改来源交付指导，运行相关引用/请求组装测试；构建候选。
3. 同一三题每版两次，共十二次真实产品调用，按基线→候选→候选→基线顺序运行。隔离每题 Reader 与私人状态，保存用量、引用轮次、失败、答案和来源解析；不重跑挑结果。

当前：十二次真实对照已完成，未重试或补跑。候选曾将来源交付指导由 v10 升至 v11，增加一条先规划完整引用集合、同轮提交独立引用、复用成功引用并局部修正失败的指导。45 项相关 Runtime 测试及基线/候选服务构建通过。首次测试仅因另一处既有版本断言仍为 v10 失败，实验期间同步为 v11 后全部通过，引用行为未修改。

实验结束后已撤回本轮新增指导及版本断言，`agent_prompt.rs` 与冻结基线逐字一致，恢复后的服务构建通过，保留上一轮 `book.text_batch`。候选可执行文件和完整提示快照保存在 `tmp/source-citation-group-trial-20261015/`，本报告保留增补原文；没有生产发布。

候选的唯一运行行为改动是给 `SOURCE_DELIVERY` 增加以下指导，工具输入、验证与采样并行参数均沿基线：

> Once observed evidence covers the request, plan the complete set of supporting quotes for the intended answer before the first source.present call. Submit independent quote calls together in one sampling, then wait for their results before using source markers. Reuse successful source_ref_ids; if one quote fails, correct only that quote instead of resubmitting successful ones. Preserve all necessary premises and qualifications; fewer calls must not mean missing support.

## 判据与测量

- 编译及相关测试检测指导是否进入实际请求、同轮多个引用是否仍通过独立来源验证、错误是否会污染其余引用；失败时先修实现，不开始候选模型测量。
- 真实结果核对核心回答事实与每个最终来源；用供应商报告的输入/输出/缓存/总 token、模型活动和引用所在模型轮次比较，缺失用量保持未知。
- 不把工具调用条数、请求体字节或缓存命中 token 的变化直接当成费用变化。

## 结果

相同三题的两次实际总 token 如下。未删除异常路径或失败交付，没有追加模型重跑。全部问题消息一致，所有调用的输入/输出/总 token 均完整返回；推理 token 已计入输出，缓存命中已计入输入。

| 问题 | 基线第一次 / 第二次 | 候选第一次 / 第二次 | 基线均值 → 候选均值 |
| --- | ---: | ---: | ---: |
| AlphaGPT 奖励与因子次数 N | 45,764 / 251,936 | 42,891 / 57,033 | 148,850 → 49,962 |
| 标签熵与相对排序损失 | 103,591 / 87,691† | 169,935 / 135,928 | 95,641 → 152,931.5 |
| 过拟合与数据隔离 | 80,899 / 67,499 | 67,038 / 69,693 | 74,199 → 68,365.5 |

† 基线第二次该题有最终引用交付失败，见已知问题；实际用量保留，但不能作为等质量低成本样本。

| 合计指标（每版六次） | 基线 | 候选 |
| --- | ---: | ---: |
| 总 token | 637,380 | 542,518 |
| 输入 / 输出 token | 599,584 / 37,796 | 504,068 / 38,450 |
| 缓存命中输入 token | 520,064 | 417,024 |
| 模型活动数 | 33 | 30 |

| 已交付且解析有效的来源 | 17 | 26 |

基线六次中五次已能在一轮提交引用，候选六次均一轮。候选减少了一轮引用提交和一次引用拒绝，但不是把六次低效串行调用全部转成批量。

| 模型阶段 | 基线活动数 / 总 token | 候选活动数 / 总 token |
| --- | ---: | ---: |
| 首次提交引用之前 | 19 / 330,773 | 18 / 270,565 |
| 首次提交引用至最终交付 | 14 / 306,607 | 12 / 271,953 |

各阶段的输入、输出和缓存明细均保存在 [comparison.json](results/comparison.json)，其和与整次实际用量一致。阶段统计描述观察结果，不单独证明提示的因果收益。

合计总 token 表面下降约 14.9%，但第一题基线第二次从已知两处继续展开邻近原文、搜索多个关键词、补读公式并混合一次 Tutor 操作，首次引用前就用去 176,334 token；同一题基线第一次仅 12,137。这条自主路径波动主导了总量差异，不能归因于引用成组。第二题候选两次总量都高于基线两次；候选第一次引用前做了六次外层采样和一次嵌套 query，随后才在一轮提交七个引用。

**判断**：成组指导能够影响引用组织，但当前证据不足以支持稳定净节省；本轮新增指导已撤回，不继续叠加提示。下一项值得单独验证的是已有证据足够时停止扩展阅读与搜索，并先修复明确的引用格式交付漏报。

## 已知问题与限制

原生请求仍设置 `parallel_tool_calls=false`，而前轮当前供应商已实际返回过同轮多个调用。本片只验证当前供应商的实测行为，不证明其他供应商会遵循成组指导。每版每题两次仍是小样本。

本轮明确发现一处既有引用交付问题：`baseline-r2/cross-02` 成功注册三条来源，但最终采用单层 `[source:source_ref_…]`，`answer_view.sources` 为空，回答仍被标记 `incomplete=false`。因此该次消耗保留为实际结果，引用交付标为失败，不作为等质量低成本样本。本片未修改该交付路径。

后续已单独修复此问题，并将修复纳入下一轮两组共同基线；见 [引用交付修复与充分证据停止检索试验](../evidence-stop-20261015/README.md#引用修复)。本轮原始失败记录仍保留。

十二次回答的指定核心事实均正确；这不等于整篇回答无误。`candidate-r2/cross-02` 的额外解释称目标熵与可恢复信息已到“同量级”，却同时给出约 1 bit 与 0.0011 bit，另有分子/分母措辞混淆。基线第一组第一题也有把“比如”的样本外例子表述为排他要求的边界问题。详见 [人工核对](results/manual-review.json)，不把这些问题因果归给本轮提示。
