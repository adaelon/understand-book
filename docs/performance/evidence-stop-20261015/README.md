# 引用交付修复与充分证据停止检索试验

## 范围与接续

用户明确授权：先修复引用交付失败却未报错，再继续实验“证据足够时停止扩展检索”。来源引用、本轮证据账本、Agent 请求计划沿 CONTEXT 的既有定义；本片不引入新的领域概念。

两个切片分别验收：

1. 复现已注册来源使用单层 `[source:source_ref_…]` 后没有可点击引用、仍被标记完成的问题。沿现有绑定后格式规范化和交付校验修复，未知/损坏引用仍需修复或报告失败，保留字面代码/链接等排除规则。
2. 修复通过后冻结含修复的基线，只调整证据充足时停止扩展的指导，与相同三题每版两次的候选比较。两版都包含引用修复及既有批量读取，避免混入修复效应。不部署。

### §1.1 引用格式交付

**决策**：复用已绑定来源的格式规范化与交付闸。

**否决**：
- 把注册成功直接当作引用交付成功：最终回答必须确实包含可点击来源。
- 仅增加模型提示：已出现的格式变体应由确定性代码处理。

**命门**：不得把未知 ID 绑定到任意来源，也不得静默吞掉无效引用。

### §1.2 证据充足时完成回答

**决策**：范围限定为用户已给原文位置的具体问题。读到的原文覆盖全部所问及必要条件后回答并引用；缺失前提、指代、未读完的正文或可能改变结论的冲突仍需继续读取。穷尽请求按要求完成覆盖。

**否决**：硬性工具次数上限会截断必要检索；把额外背景与推导当作每次都必须完成的范围会继续扩大任务。

**命门**：保留原文的示例、条件与适用范围，不能靠删除这些限定制造省量。

## 判据

修复测试须证明：已绑定的单层标记得到真实来源、重复与混用保持正确、未知/损坏标记触发现有错误路径、字面示例与链接不被误当来源。随后运行相关交付、流式预览及历史保存测试。

实验保留全部用量、调用阶段、最终引用与事实核对，不删离群值、不重跑挑结果。节省必须来自不再需要的查询/阅读，不得跳过问题要求的前提、条件、完整范围或尚未读取的正文。

## 引用修复

上一轮 `baseline-r2/cross-02` 成功注册了三处来源，但模型正文输出单层 `[source:source_ref_…]`。编译器此前只识别标准双层 `[[source:…]]`，其余标记被视为普通文字，最终来源列表清空且 `incomplete=false`。

现在，明确用作句末引用的单层 `source:` 标记先归一为标准语法，再经过既有来源校验。已登记 ID 直接成为可点击引用，不增加模型调用；未知或损坏 ID 进入既有一次修复流程，修复后仍失败则交付失败提示并标记未完成。代码、引用文字、转义和 Markdown 链接沿现有字面规则处理。

新回归使用实际失败记录中的三组 ID 与对应句式，并验证混用、相邻合组、重复去重及未使用来源清理。演示正文与流式预览使用相同路径；流式测试按 1、2、7、999 字符分块检查。

验证记录位于 `tmp/evidence-stop-trial-20261015/`：

- `source-marker-tests.log`：修复后 41 项相关测试通过，包含随后补入的相邻混用回归。
- `prompt-tests.log`：5 项实际提示装配与版本测试通过。

## 实验方法

基线与候选均包含上述引用修复及已保留的 `book.text_batch`。候选仅增加：用户已给原文位置的具体问题，在读到的证据覆盖每个问题及必要条件后完成回答；不为追加背景、例子或额外推导扩大检索。未覆盖的具体缺口及用户要求穷尽的范围继续读取。

沿原三题，每版每题两次，固定 A1→B1→B2→A2；每个问题新建独立 Reader 与记忆目录。只记录真实产品调用，不调用付费评委，不重跑或挑选结果。

| 问题 | 需要保留的事实与限定 |
| --- | --- |
| cross-01 | 奖励段举样本外通缩夏普率、Rank IC 为例；不可把例子改成唯一硬性要求。因子库不能重置尝试数 N，并解释两者联系。 |
| cross-02 | 打标压低 H(Y)；指增损失应对齐相对排序或组合表现，并连接这两个判断。 |
| exact-02 | 防过拟合总纲要求评判数据从未参与搜索，不能仅回答为两份数据不同。 |

给定位置是否读齐，以模型下一轮实际收到的工具正文为准，不以调用参数或被截短的 trace 摘要代替。初次读取同轮发出的额外定位与读到正文后继续扩展分别统计。总量及引用前阶段均使用 Provider 返回的 input/output/cache/total；reasoning 是 output 的子集，cache 是 input 的子集，缺字段保留为空。

最终回答另核对核心事实、必要限定与真实来源交付；这个核对不等于证明两版整体回答质量相同。每题保留两次原始值、均值及范围，复杂题与单段题分开报告。

## 限制

首组 A1 的读取回执观测没有识别 Provider 将 `book.text`／`book.text_batch` 映射为 `book_text`／`book_text_batch` 的名称，因此该组无法从回执确认读齐时刻；此字段保留未知。原始 token、调用轨迹、最终答案及来源验证均正常保存。观测修正从 B1 首次请求生效，不改变请求或响应、不补跑 A1；涉及读齐时刻的比较按有效观测数报告。

每题每版仅两次，不能据此推出总体稳定节省率。缓存状态和自主回答路径可能不同；所有实测值保留，不以请求体字节替代 token，也不把未知字段当作零。

总量观察降幅为 **25.0%**，首次引用前降幅为 **13.6%**。总差额的 **78.9%** 出现在首次提交引用起的阶段；这个阶段包含引用提交、可能的补读、Tutor 操作和最终输出，不能把阶段差额全部归因于停止检索。

缓存也发生变化：候选未命中 input 反而增加 8,481（约 10.6%）。因此总 token 降幅不等于费用降幅，本轮没有按价格推算费用。两道复杂题合计 527,411 → 372,668 token，单段题合计 149,361 → 134,742 token；全部数值包含两个样本，没有剔除高用量路径。

核心事实均覆盖，但整体回答存在原文限定、额外推断和可读性问题。具体例子及每次判定见 [人工核对](results/manual-review.json)，每题两次值、范围、缓存与阶段明细见 [完整比较](results/comparison.json)。

## 最终决策

**保留引用交付修复，撤回本轮停止扩展指导。** 候选第一题的短路径并非基线不能做到，第二题两次仍扩大检索，第三题两次行为不同。现有数据不足以把 25.0% 总量下降归为稳定停止检索收益，因此不继续叠加此提示。

基线第二组的标签熵题在第 6、7、8 轮分别成功提交 7、1、1 条来源，九次全部成功，零拒绝、无 repair 模型；三轮是继续添加来源，不是重试。它使首次引用起的阶段用去 155,957 token，是总量差额的重要组成。

本轮未提交或部署。固定样本结束后只汇总已有产物，未继续调用模型。接续时先读本页、[完整比较](results/comparison.json)与[独立实验结论](results/conclusion.json)；不要重新运行已完成阶段或将候选提示当作当前生效版本。
