# 视频播放修复、实测与发布（2026-10-21）

云端已发布 `video-playback-20261021`，Windows 安装程序已更新为 **0.3.5**，本机安装及重开成功。原课程现在按播放片段取数据，先显示播放器和封面，再加载字幕与学习状态。课程标题使用书库中的正式名称。

## 根因与修复

真实故障视频是《CS336 第 2 讲：PyTorch 与资源核算》，时长约 77 分 21 秒，1920×1080、H.264/AAC，原文件 225,917,024 字节。旧 MP4 已做 faststart，但文件头的全片索引 `moov` 仍有 **5,861,907 字节**；首帧前须经过这一大段数据。旧完整阅读页还串行等待约 459 KB 的视频上下文，播放器才挂载。公网传输慢会放大这些等待；原媒体流又占用同步 HTTP 工作线程，四路慢传输可阻塞普通请求。原始调查见 [启动基线](../video-startup-20261021/README.md)。

本次按三个层面修复：

1. `server::video_playback` 从原文件无重编码生成 HLS VOD：一个 `index.m3u8` 与一个支持字节范围的 fMP4。浏览器只读取当前位置需要的片段。派生文件按现有不可变材料身份复用，不修改原视频；来源定位、截图和问答继续绑定原文件。发布成功后准备播放缓存，维护命令可为已有材料准备缓存。
2. `PublishedLibrary::video_playback` 和 `/video_playback` 返回轻量播放信息及现有课程封面；实测响应 961 字节。`App.vue` 先挂载播放器，字幕和草稿异步加载；字幕未就绪前不提交依赖字幕的问答。`NetworkApp.vue` 在选中视频时并行预载播放模块，避免工作区创建完成后才开始下载模块。
3. HLS 请求先经原授权链，再用 `X-Accel-Redirect` 交给 nginx 发送。Rust 工作线程不再随媒体下载长时间占用。内部 nginx 地址不能从公网直接读取，未授权用户不能读取播放清单。

播放器使用 hls.js 1.7.3 的 MSE 路径，并保留原有播放位置和倍速。缓冲限制为约 15 秒，最大 30 秒/6 MB，后向保留 30 秒。封面、加载状态及重试入口可见；重试或退出会释放旧播放器。浏览器缺少 MSE 时再尝试原生 HLS；不支持时使用原媒体入口。

### nginx 与媒体目录

派生缓存实际路径：`<data>/shared-cache/video-playback/<book_id>/`。服务配置 `UNDERSTAND_BOOK_MEDIA_ACCEL_ROOT=<data>/shared-cache/video-playback`。nginx 的内部 `/_private_media/` 映射到独立只读挂载 `/opt/understand-book/media/`，使用 `sendfile`，播放清单 gzip，响应 `Cache-Control: no-store`。

只读挂载单元为 `opt-understand\x2dbook-media.mount`，已启用并排在 nginx 之前启动。私有数据根仍为 0700。需要独立挂载，是因为控制存储打开时会重新设置私有根权限；直接给 nginx 增加上级目录遍历 ACL 会在服务重启后失效。真实重启后，挂载、授权读取和范围响应已验证。

已有视频可以使用同版程序执行：

```bash
reader_maintenance prepare-video-playback <service-root> <book-directory>
```

成功发布后的缓存生成失败只记录警告，原文件仍能读取；排查日志并修复媒体问题后，再执行准备命令。缓存是播放派生物，原视频仍为权威来源。

## 已知问题与测量边界

- 公网首帧仍为数十秒量级，公网传输与工作区创建还有明显等待。此次已移除全片大索引、字幕串行阻塞和媒体占用业务线程的问题；没有把单次结果表述为固定时延或“秒开”。
- 限速结果来自真实文件的首播和指定跳转字节区间，未在该实验中播放完整 77 分钟。全片包比较验证时间映射，真实浏览器验证首播、2400/4600 秒跳转及恢复。限速实验中的跳转部分取消了限速，不能当作公网跳转耗时。
- 发布修复验证了这条实际 H.264/AAC 视频路径；其他格式不能直接套用其性能数据。派生缓存增加约一份媒体存储；冷生成在发布/维护时发生，已有缓存直接复用。
- Edge 虽声明支持原生 HLS，实测原生路径仍导致大范围读取与首帧超时，故优先 MSE。早期 FFmpeg 默认改变视频时间基，已显式沿用原时间基并完成全片复核。
- 发布过程中发现一次网页构建未设置多用户变量，已恢复原正常入口后重新构建、完整候选验证再发布。失败记录保留为 `published-entry-mode-failure.json`；最终公网 Edge 和资源一致性以最终报告为准。
- 验收脚本曾先退出登录再关闭页面，导致页面离开时无法释放测试阅读现场。脚本已改为先释放现场再注销，仅清理本次测试账号自己的现场；首次 WebView2 工作区创建 503 的记录保留，未扩大线上容量限制。后续诊断时该错误已不再出现，不能从现有回执确认其确切错误码。
