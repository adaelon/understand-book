## 先把你会的东西对齐

```rust
let foo = Foo(0);
```

跟你写 `let x = 5;` 是同一件事：**把一个值绑定到一个名字上**。区别只在右边那个值的种类——这里不是整数，而是一个自己定义的类型（例子里 `struct Foo(u32);`，就是「装着一个 u32 的 Foo」）。

## `&foo` 造出来的不是那个值，而是「指向那个值的引用」

原文定义：`&` 是 Rust 的**借用运算符**，「在表达式中的 place 前写 `&` 可创建共享借用」，而「借用让代码在不取得所有权的情况下临时访问值」。

所以这一行：

```rust
let bar = &foo;
```

- 没有把 `Foo` 值搬到 `bar` 名下
- 也没有复制一份
- 而是造出一个**引用**，让 `bar` 指向 `foo` 已经绑定的那个值

原文把类型直接说了出来：**「bar 的类型是 &Foo，也就是引用类型」**。对照一下：

| 名字 | 类型 | 是什么 |
|---|---|---|
| `foo` | `Foo` | 值本身 |
| `bar` | `&Foo` | 指向那个值的引用 |

## 所以两行 println 为什么都能过

```rust
println!("Foo is {:?}", foo);   // 用 foo 本身
println!("Bar is {:?}", bar);   // 顺着引用看同一个值
```

第二行是**通过引用去看那个值**，看到的还是同一个 `Foo(0)`。

关键是：**`foo` 的值根本没被拿走。** 借用的定义就是「不取得所有权地临时访问」——`bar` 只是借看了一下，值的归属没有变，所以 `foo` 自己照样能用。

⚠️ 这里要跟你的整数直觉分开记：`let a = 5; let b = a;` 之后两个名字都能用，是因为整数被**复制**了一份；而 `foo` 这个例子两个都能用，原因完全不同——值从头到尾就还在 `foo` 手里。（这段整数对照是我拿你已有的经验打的比方，不是原文的说法。）

顺带一条限制，原文也写明了：「由于这是不可变引用，我们不能通过 `bar` 修改 `Foo` 中的值」——`bar` 只能读，不能改。

## 轮到你判断：去掉 `&`

把第二行改成：

```rust
let bar = foo;   // 去掉了 &
```

原文在讲这个例子时，把「这一次，程序可以编译」归因于这一行的写法：**「这一次，程序可以编译，因为 main 中的第二行变成了：`let bar = &foo;`」**——也就是说，能不能编译，原文是挂在这行的 `&` 上的。（我读到的这段没有写出报错信息本身。）

那么请判断：去掉 `&` 之后会怎样？

- **A.** 还是能编译，两行都照常打印，结果和改之前一样
- **B.** 编译不过，因为这一行不再借用 `foo`
- **C.** 能编译，但 `foo` 那一行会在运行时出错

回复 **A / B / C** 就行，并说一下你为什么这么选——你怎么想的比选对更重要。（想先要提示就说「提示」，想跳过就说「跳过」。）

> 说明：上面关于借用、类型和「不能通过 bar 修改」的解释，都来自原文 1.1「借用」这一节读到的内容；去掉 `&` 时的具体编译器报错文本，这一段没有给出，所以那部分要靠你自己的判断。
