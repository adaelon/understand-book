原文这一段正好把你卡住的那一步拆开了，我们从这一行本身看起。

**一、`&foo` 拿到的是“借用”，不是那个 Foo 值**

原文先把借用的定位讲清楚：借用让代码在不取得所有权的情况下临时访问值；它不是绕过或放宽所有权规则，而是所有权模型本身的一部分。借用表达式会创建引用——在表达式中的 place 前写 `&` 创建共享借用，写 `&mut` 创建可变借用 。

这句话直接回答你的问题：`&` 不是“取地址绕过移动”，而是所有权模型里另一条合法路径——拿到的是一种访问权限，不拿走值。所以原文里 `bar` 的类型是 `&Foo`，也就是引用类型 。

**二、`let bar = &foo;` 这一行到底发生了什么**

原文的例子是：

```rust
// borrowing_basics.rs
#[derive(Debug)]
struct Foo(u32);
fn main() {
    let foo = Foo(0);
    let bar = &foo;
    println!("Foo is {:?}", foo);
    println!("Bar is {:?}", bar);
}
```

原文接着说：这一次程序可以编译，因为 main 中的第二行变成了 `let bar = &foo;`；并明确“我们借用了 foo，并把借用赋给 bar”，`bar` 的类型是 `&Foo` 。

把它对上你已经知道的东西：这次赋给 `bar` 的**不是那个 `Foo` 值**，而是“指向 foo 的值的引用”这个值。既然 `Foo` 值没有被搬走，`foo` 仍然是它的所有者，之后打印 `foo` 完全合法；`bar` 只是一个解引用后能看到同一处的 `&Foo`，所以打印 `bar` 也合法——这一行里根本不存在“谁把值交给谁”的转移，只是一个临时访问许可。

所以 `&Foo` 与 `Foo` 在赋值处的区别，可以压缩成一句话：**加 `&` 改变的是“被赋过去的是什么值”（是引用值，还是 `Foo` 值本身），而不是你原来的变量名是否还可用；`Foo` 值一旦被赋值搬走，旧绑定就失效，而引用被赋过去时值还在原地。**

**三、两个附带条件**

1. 原文特别强调：由于这是不可变引用，我们不能通过 `bar` 修改 `Foo` 中的值 。“能用”与“能改”是两件不同的事。
2. 原文说“这一次，程序可以编译”，是在与“前面所有权一节中的例子”对照；那段被引用的所有权示例的代码，并没有出现在我读到的这一段原文里 。所以下面的预测题需要你自己推。
