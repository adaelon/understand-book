## 改动与调用链

- `runtime::tutor::review_delivery`：输出上限从 4096 提高到 32768，与当前外层模型请求的额度一致；上下文计算同步预留该额度。
- `runtime::orchestrator::run_context`：审视调用失败保留底层分类和原因，记为 `TEACHING_REVIEW_FAILED`。同一正文允许重试一次；调用失败本身不要求改写正文。内容审视要求修改时仍须修改后通过。
- `presentation.author patch`：省略教学绑定时读取并继承实际候选/版本的绑定，在校验当前设计与焦点后修改；为新候选保留绑定以供交付。原先宿主允许继承而外层拒绝，导致布局修正被误判为设计未就绪。
- `ProgressPhaseGuard`：页面制作的范围、参数错误进入现有的单次修正机会。重复失败仍停止；收尾返回最后的真实错误。
- `runtime::response_message_content`：截断和缺正文保留完成原因及 token 数，不把整份含私有推理的响应拼入错误。
- 页面保存后的回执在教学流程中明确要求以真实页面引用调用 `tutor.step select`，完成正文审视；提前收尾的修正提示也指向这一步。避免旧回执的“直接结束”与实际交付门禁冲突。
- 历史源码压缩不再向调用参数注入工具不接受的 `saved_source`；读取入口放入现有的结果续接信息，明确旧调用是省略源码的历史摘要。审视要求修订页面时，保留完整意见并给出被审视版本的 `index.html` 精确读取请求。
- 页面工具参数错误保留原始原因，并一次提供当前操作允许的字段与定位要求；读取操作混入写入字段时，模型能在既有的单次纠正机会中修改完整请求。参数校验本身不放宽。
- `agent-run-state.ts:agentFailureMessage` → `App.vue`：普通界面区分“演示页制作未完成”和“演示页已生成，但回答检查未完成”。历史记录按原有活动与工具记录解释；原始错误数据不改写。
- 同批前端：过期聊天查询不能覆盖新聊天状态或弹出旧错误；待确认操作保留原操作身份；移除用户提示中的内部分类、编号和“现场”等用语。

## 已知限制

提高单次上限允许模型在复杂审视中消耗更多输出 token，并不预先消耗全部额度。两次实际请求和确定性回归只能证明这些场景；模型内容仍须经过原有审视，不能保证任意未来请求一次完成。

第一次最终验收中，缺少动作的用户原话引用是在正文审视后被拒绝，补齐后额外进行了一次审视；当前动作接纳顺序会产生这类额外调用，本次没有调整该顺序。
