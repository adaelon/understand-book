# 连续卡住时的局部教学支撑

用户要求先上线现有教学闭环，再用 gpt-6.1-sol 多轮模拟连续卡住、只能表达零碎理解的读者，依据实际效果继续修复系统。初次上线于 2026-10-17 08:36 HKT 完成，见 [发布记录](deployment-initial/README.md)。之后才启动本次基线对话。

## 基线实际表现

[基线六轮对话](live-01/conversation.md) 通过真实服务器 ModelAdapter、原文工具和教学持久化运行，教师与学习者均为隔离的 gpt-6.1-sol。第一轮用户仍是原有的 BookStructure 困惑；之后每轮由学习者只读可见答复产生输入，主线程原样转交。

首轮同时展开章节与主题分支、M/A/C 包含关系、最终并集、反事实和四种“没出现”的区别。用户接住“乙没进主干但主题仍能选”，随后连续卡在最终清单与删除、accepted 与 macro、主干与最终、主题是否补回章节、候选记录与原文这几处。

后续回答能够澄清具体关系，没有每轮追问，也没有把章节结构选择等同于原文删除。六轮全部选择 support，未产生普通邀请或交互演示页。首轮正文 992 字符，后续为 614、703、593、546、499 字符；字符数量仅描述实际输出，未用作教学阈值。完整运行 28 次模型请求，六轮 HTTP 200。

## 实现

`organizing_model` 保留总体方向，`target` 与 `focus_block_refs` 表示现在要建立的关系。指导和工具示例据此区分整体结构与当前支撑，不把一个完整课题塞进单个关系积木，也不要求每轮覆盖所有相关定义与情况。

服务端的 `learner_context.current_target` 优先保留当前设计版本最新实际交付的局部目标。未交付选择不能改变它；新版设计尚无交付时采用新版目标；显式引用历史交付仍沿用原交付目标。`select` 省略目标时，同设计且本次关系在最近交付关系范围内，继承该交付目标，其他情况采用当前设计目标。显式目标始终优先。

`TeachingDesign::validate_focus` 使当前焦点成为实际工作范围。动作必须在焦点内，邀请必须在本动作关系内；演示 prepare/write/patch 的绑定必须在当前焦点内，区域必须在本页关系内。需要改变范围时可以修订设计，完整解释也可以选择较宽焦点。没有字数、积木数量、卡住次数或固定教学顺序限制。

已有的 `open_question_refs` 和 `return_to` 现在组成 `learning_opportunity.return_context`：原问题表达、原邀请、当时冻结的帮助及原演示场景。新补讲另在当前交付视图，不回写原问题获得帮助的条件。只有实际保存的返回链接才产生该视图；它不判断用户已经准备好，也不会自动推进教学。

涉及的生产文件为 `crates/runtime/src/tutor.rs`、`crates/runtime/src/orchestrator.rs`、`crates/memory/src/teaching_design.rs`、`crates/server/src/teaching.rs` 和 `crates/server/src/teaching/design.rs`。开始前快照位于 `baseline/`，其他工作树改动保留。

## 改后的实际对话

[改后六轮对话](live-02/conversation.md) 使用全新的 gpt-6.1-sol 教师与学习者。与基线使用相同原文和首条困惑；后续输入各自由学习者产生，不复制基线轨迹。36 次模型请求，六轮 HTTP 200，正常完成。以下结论依据实际内容，选择字段只记录模型当时的判断。

| 轮次 | 用户实际卡点 | 教师实际回应 |
|---|---|---|
| 1 | 把候选、章节与主题看作连续删减 | 用乙说明候选保留与两路选取；正文 523 字符，减少了集合符号和情况表，但仍提前加入 accepted 未选及最终未选的情况。 |
| 2 | 把 accepted 误读为系统留下的全部候选 | 把范围缩到“这一章采用”，并排展示候选目录与本章名单，说明下面少乙不会删去上面的乙。 |
| 3 | accepted 有乙、macro 无乙，到底算用还是没用 | 区分“本章采用”和“承担主干角色”，复用同一乙，不重新讲全部分支。 |
| 4 | 已被章节采用，仍担心没有 macro/主题认可就不能进最终 | 只沿 accepted → 最终清单解释这一条贡献，不把主干身份当作最终收录条件。 |
| 5 | 换成只有主题采用，又担心乙没有章节位置 | 增加主题 → 最终清单这一条来源，说明它可以被主题线引用，不必先有章节 accepted 身份。 |
| 6 | 自己接回最初的乙，同时明确仍需盯着一个点 | 180 字符确认本例连接，未称整体掌握，未追加新概念或任务。 |

学习者最后原话包括：“这样我能接上最开始那个例子了：主干没有乙，主题还是能从候选目录找到它，再让它进最后的清单。我现在还得盯着乙一个点才理得清。”这支持在既有帮助下形成了本例连接，不能当作独立应用或迁移证据。

实际选择为 support、support、support、conclude、conclude、conclude。后两次新问题仍获得所需帮助；conclude 在这里表示完成当前问题，不代表学习者已掌握整个结构。没有强制提问流程，本组也没有主动邀请，因而不把它当作主动引出新尝试的额外成功证据。原有邀请能力的前一组四轮记录保留在 [上一阶段](../teaching-initiative-20261017/implementation.md)。

独立 gpt-6.1-sol 审阅者只读原文和实际对话。[基线审阅](live-01/content-review.md) 认为后续具体澄清成立，但缺少小步应用机会，额外引入原文对象造成新的混淆；[改后审阅](live-02/content-review.md) 确认逐步收窄和第六轮收束成立，未发现实质原文错误，仍指出首轮反事实偏早。用户在同一乙例子中整合复述，而未完成新情境迁移，是验证边界，不是已经观察到的错误。

## 验证边界

本次是本地真实应用链路中的模型模拟，不是生产网站真人对话，也不是长期保持或跨情境迁移证据。两次后续输入独立生成，不能把差异归为受控统计收益。字段约束能保持已选择的范围，不能自动判断自然语言积木是否足够小，因此实际内容另行审阅。首轮负担有所减轻，但提前引入 accepted 反事实仍带来下一轮困惑，不能宣称首轮范围控制已完全解决。两组均未生成交互演示页，页面绑定与原场景返回只有本轮代码回归证据。
