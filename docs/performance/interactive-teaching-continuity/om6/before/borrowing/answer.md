先看这段代码（来自原文 1.1 的借用示例）：

```rust
#[derive(Debug)]
struct Foo(u32);

fn main() {
    let foo = Foo(0);
    let bar = &foo;
    println!("Foo is {:?}", foo);
    println!("Bar is {:?}", bar);
}
```

第 5 行 `let foo = Foo(0);`：`foo` 拥有一个 `Foo` 值，`foo` 是这个值的所有者。

第 6 行 `let bar = &foo;`：`&` 是借用运算符，它在 `foo` 前面创建一个对 `foo` 的不可变借用，并把借用赋给 `bar`。`bar` 的类型是 `&Foo`，即引用类型。这一步只创建引用，`foo` 仍然是所有者，值没有被搬走。

第 7 行 `println!("{:?}", foo);`：这里直接写 `foo`，读取的是 `foo` 本身持有的值。`{:?}` 要求把值格式化输出，格式化只读取值，不取走所有权。所以这一行结束后 `foo` 依然有效。

第 8 行 `println!("{:?}", bar);`：这里写的是 `bar`，`bar` 是 `&Foo`。格式化输出会先顺着这个引用找到它指向的 `foo` 的值，再读取该值。读取同样不移动所有权，`foo` 仍然有效。

所以两个 `println!` 都能读到值：第 7 行直接读 `foo`，第 8 行通过 `bar` 这个引用间接读 `foo`；两条路径都只读取，都不移动所有权。原文对此的说明是：程序可以编译，因为第二行变成了 `let bar = &foo;`，`bar` 的类型是 `&Foo`，并且由于这是不可变引用，不能通过 `bar` 修改 `Foo` 中的值。

现在把第 6 行的 `&foo` 改成 `foo`：

```rust
    let bar = foo;
```

这一行把 `foo` 持有的值移动进 `bar`。移动之后，`bar` 成为该值的所有者，`foo` 不再持有值，也就不能再被使用。

于是第 7 行 `println!("{:?}", foo);` 会编译报错：它要读取的 `foo` 已经在第 6 行被移动走了。第 8 行 `println!("{:?}", bar);` 本身没有问题，因为 `bar` 现在拥有这个值。

把两段对照起来看：`&foo` 让 `bar` 只借用 `foo` 的值，`foo` 保留所有权，两次打印都合法；`foo` 让 `bar` 拿走所有权，`foo` 失效，之后再用 `foo` 的那一行就报错。
