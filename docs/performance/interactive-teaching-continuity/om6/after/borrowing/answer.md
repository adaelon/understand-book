先看这段代码：

```rust
#[derive(Debug)]
struct Foo(u32);
fn main() {
    let foo = Foo(0);
    let bar = &foo;
    println!("Foo is {:?}", foo);
    println!("Bar is {:?}", bar);
}
```

逐行看：

1. `let foo = Foo(0);` 创建一个 `Foo` 值，并把它的所有权交给变量 `foo`。此后 `foo` 是这个值的所有者。

2. `let bar = &foo;` 中，`&` 是借用运算符。它在 `foo` 前创建一个共享借用，也就是一个不可变引用，并把该引用赋给 `bar`。因此 `bar` 的类型是 `&Foo`：它指向 `foo` 拥有的那个值，但自己不拥有它。这一步只创建引用，不复制也不移动 `Foo` 值，所以所有权仍留在 `foo`。

3. `println!("Foo is {:?}", foo);` 读取 `foo` 拥有的值来打印。读取不转移所有权，`foo` 打印后仍是所有者。

4. `println!("Bar is {:?}", bar);` 通过 `bar` 这个 `&Foo` 读取同一个值来打印。共享借用允许读取，所以这一步也能拿到值。

两个 `println!` 都能读到值，原因在于：`&foo` 只借出访问权，没有把值从 `foo` 移走；`foo` 和 `bar` 访问的是同一个 `Foo` 值，一个通过所有者，一个通过共享引用，而读取都不改变所有权。原文也指出，正因为这是不可变引用，我们不能通过 `bar` 修改 `Foo` 中的值。

如果把 `let bar = &foo;` 改成 `let bar = foo;`，情况就变了：

- 这一行把 `Foo` 值从 `foo` 移动进 `bar`，`bar` 的类型变成 `Foo`，`bar` 成为新的所有者。
- 移动之后 `foo` 不再拥有该值，也不能再被读取。因此后面那句 `println!("Foo is {:?}", foo);` 会编译报错，因为 `foo` 的值已经被移走。
- 只打印 `bar` 的那一句仍然正常，因为值现在归 `bar` 所有。

所以关键差别在 `&`：有 `&` 时创建共享借用，所有权留在 `foo`，两处都能读；去掉 `&` 时发生所有权移动，`foo` 失去值，只有 `bar` 还能读。
