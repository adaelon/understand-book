# EX11.6–EX11.7：回合收尾与跨题生成

日期：2026-09-28。基线 `c2ff3e1`，沿用 EX11.1–5 与当前工作树。EX11.6 工程修复完成；EX11.7 前三批失败保留，输出预算修复通过，方法 ex11.v8 将在 batch4 验证。

## EX11.6 根因与修复

EX10 第三批 C 的第 10 个工具循环已成功 `deliver`。之后第 11、12 次请求仍给出终答，但目标含一个 `reader_action` 要求，其描述实际是生成页面内的拖动、播放、暂停、回退与现场恢复。Runtime 对这个类别检查宿主 Reader effect；本轮该值为零。因此 `objective_gap` 在页面交付后仍成立，两次终答均不能完成目标，第 12 次返回 `TURN_LIMIT_EXCEEDED`。

没有缺失的页面保存动作，也不是收尾采样没得到机会。原始证据在 `ex10-svg-konva/batch3/runs/C1/response-09.json`（deliver）、`request-10.json`（完整目标与已交付事实）、`response-10.json`、`response-11.json`、`outcome.json`。目标原文提取为 `crates/runtime/src/testdata/ex11-c1-goal.json`。

修复 `goal.update` 的实际 Provider schema：`content` 包括页面交互与解释正确性，`presentation_delivery` 检查真正交付页面，`reader_action` 指用户要求的宿主阅读器操作。缺口回执现在指出这条边界，并要求按既有 refine/revise 规则修正误分类或执行真实动作。请求的交互功能仍保留在 requirement 描述中。回合上限、完整性判断及 Server 持久化规则保持原有语义。

`ex11_c1_goal_contract_and_completion_replay` 首先因实际 schema 缺少分类说明而失败，修复后通过：原记录误分类且无 Reader effect 仍不完整；正确分类且页面已交付，在普通终答和上限后的终答均完成；缺少页面仍不完整。Runtime 目标相关 8 项及 G4 4 项通过；Server `goal_completion_requires_a_mounted_delivery_owned_by_the_goal` 通过，仍拒绝草稿、仅预览、未挂载版本、别的目标版本与不完整回合。

这项修复向模型明确验证类别，不把错误分类静默改成成功。真实模型遵循情况由 EX11.7 的请求和目标记录验证。

## EX11.7 batch1 结果与修正

首个学习率页用了原生 Canvas。四次有效 write、一次缺少 operation 的调用失败、12 次 preview 调用后交付；总计 12 次模型请求、1,177,011 tokens、471.631 秒，最终回合 `incomplete=false / warning=null`，持久目标为 completed。方法实际加载为 ex11.v6。后续六个输入未启动，详见 [批次判定](ex11-local-demonstrations/ex11.7/batch1/verdict.json)。

三视口下，支持的六个非零 η 共 108 组数值全部通过；真实图形坐标与独立递推一致，轴外点有明确的边缘三角提示。鼠标/触摸拖动、回退、整数步骤保存、重开与追问通过。以下问题使该页未通过完整合同：

- 实际计时器在推进步骤、按钮显示暂停，`snapshot().playing` 始终返回 false；正式 Reader 三视口均复现。
- η=0 不在控件范围内，无法检验静止边界。
- η=0.5 一步到达后，后续零更新仍绘制箭头头部；绘制调用与截图一致。
- 运动只逐个揭示静态整数步骤，忽略分数定位，也没有相应的保存现场。

模型自行修正了初稿“切线低于曲线就表示过冲”的错误文字，最终页不再存在该项；没有把初稿错误追加到最终失败清单。Canvas 检查初版把正确的轴外提示记作点缺失，汇总按实际可见范围纠正；η=0 数值差异归范围缺失。Reader 夹具两次早期失败分别为在播放断言处停止、空白序列差异误报，诊断保留。最终 Reader 检查完成了保存/重开/追问，仍因实际播放状态错误而失败。

制作方法更新 ex11.v7，将实际状态与连续运动合同放到开头，明确 snapshot 读真实播放状态、非零分数定位与回退重现、可保存分数现场、静止边界及 Canvas/SVG 零箭头。方法加载测试通过；[batch2](ex11-local-demonstrations/ex11.7/batch2/frozen.json) 使用相同输入，重新冻结源码并独立记账。

## EX11.7 batch2 输出中断与修复

ex11.v7 的第一题在第二次模型请求返回 `Provider unfinished response: length`，共 278.303 秒，没有返回候选页。实际请求没有设置 `max_tokens`。唯一完整响应报告 6,665 tokens；失败请求未返回用量，批次总用量未知，不能以 6,665 代替。见 [错误判定](ex11-local-demonstrations/ex11.7/batch2/verdict.json)。

DeepSeek 文档说明未指定时使用服务商默认输出上限，且允许显式设置更大的值。正式 Flash 页面制作请求现设 `max_tokens=131072`，同步增加 output reserve，并平移压缩高水位以保持约 84K 的输入压缩阈值。范围限于目录匹配的 Flash 且暴露 `presentation.author` 的正式请求；普通短答、其他模型、显式 profile override 保持原行为。[官方请求参数](https://api-docs.deepseek.com/api/create-chat-completion/)

测试先复现缺少输出上限，再验证 Native/ReAct 实际请求体、剩余上下文空间、压缩阈值及适用范围，连同既有实验输出上限测试通过。服务商返回的 `length` 没有报告具体耗用量，因此“默认单次输出预算不足”是基于请求与返回的诊断，不能声称已经量得确切截断 token 数。配置仍使用原 `deepseek-v4-flash` 别名；官方文档将别名映射到当前 Flash 服务，冻结记录不声称模型权重不可变。[官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)

## EX11.7 batch3 结果与修正

显式 128K 输出预算后，首题返回完整页面并正常交付收尾：12 请求、1,159,212 tokens、521.683 秒。四次 write、九次 preview、两次 deliver 调用全部保留。首次候选携带 plot 引用且预览通过；模型修订时遗漏该引用，后续预览失败，最终交付的是首个有效候选。见 [批次判定](ex11-local-demonstrations/ex11.7/batch3/verdict.json)。

三视口共 378 个独立数值、实际 SVG 坐标、分数位置、零位移箭头样本全部通过。真实 Reader 的鼠标/触摸拖动、播放/暂停、回退、分数现场保存/重开与追问也全部通过。没有复现原 EX10 C 的目标误分类收尾问题。

最终稿仍有实质错误：切线旁写 `Δw=-2ηL′(w)`，正确式应为 `-ηL′(w)`；在分数进度处，它还把移动点的导数与本步起点的更新量混用。η 有滑杆，但页面没有读者可直接使用的分数位置滑杆。长推导位于第一幅图之前，三种情况的主对照与控件之间又隔了一幅图。故数值计算和 Reader 工程通过，不等于解释合同通过。

方法改为 ex11.v8：先做紧邻控件的最小比较与可见位置滑杆，再补推导；明确离散更新与插值的不同含义，并要求逐项代入核对辅助说明；每次 write 携带全部使用的 plot/animation 引用。该批失败不补算成功，后续用新冻结批次。

## EX11.7 修订触发的历史压缩失败

batch4/learning-1/revision-1 在读取原版本的第 5 次请求后触发压缩，严格解码报 `missing field item_id`，120.370 秒后返回 `COMPACTION_FAILED`，未生成修订页。五个聊天请求报告 405,856 tokens；旧记录器没有保存结构化压缩调用的返回和用量，实际总用量未知。原始 history 与调用前副本逐字节相同，首稿未被改写。

EX11 记录器新增结构化调用的请求、原始返回文本、解析结果、错误及累计 usage 快照；成本汇总加入修订子目录和该类用量，缺失项继续明确为未知。该工程修复要求新的源码冻结；先在新批次的 diagnostics 目录复跑旧稿修订，再开始其六个独立生成样本。

## EX11.7 batch5 压缩后收尾失败

诊断续接 batch4 的原稿和相同反馈，排除在六个独立样本外。结构化压缩生成已通过严格解码；随后 Agent 完成一次 write、三次 preview 和一次 deliver，但回合最终落盘返回 `INTERNAL_ERROR: checkpoint source IDs are duplicated or stale`。12 个聊天请求 1,056,389 tokens，结构化压缩 11,172 tokens，合计 1,067,561，334.963 秒。候选与版本仍在诊断存储中；本次不能算作完整交付。

根因是中途压缩保存了原工具历史，回合结束时 Author/工具发现历史清理改写了这些消息，收尾仍携带旧压缩检查点。`finalize_agent_turn` 现在在最终消息不再保留已保存消息前缀时丢弃派生检查点，再原子保存最终历史；只追加消息的回合保留检查点。没有修改持久化格式或放宽读取时的来源校验。回归覆盖正常追加、Author 清理、工具发现清理、失败截断及磁盘重开；先复现同一 stale 错误，再验证修复。

## EX11.7 batch7 数值定位点解析

机制与系统题分别在 109.481 秒、91.667 秒后未完成，报告 66,629 与 85,022 tokens。检查原始请求发现 `at_seconds` 是合法的 0.6、1.1、4.3 等 JSON 数字，原错误不能归为模型传入对象。`AuthorRequest` 的 internally tagged enum 在 workspace 启用 serde_json arbitrary_precision 后，把缓冲数字作为内部映射交给 f64 解码；之前测试只走 `from_value`，未覆盖实际 Provider 的 `from_str` 路径。

`AnimationCue.at_seconds` 现在先按 JSON Value 解码再转换为 f64，保留数字类型与既有范围校验。新增实际 JSON 文本测试红→绿，覆盖整数/小数定位点并仍拒绝字符串、对象、null。相同错误在 batch6 的第一次机制渲染中也存在，该项归因已更正；其后页面/调用错误仍保留。

EX11 专用诊断夹具另修正正文范围：共用单元夹具在唯一 0..100 叶节点后附加未归属尾巴，模型自然调用全文搜索时产生 SEARCH_SOURCE_INVALID。现在 EX11 使用完整覆盖的 100 字符占位叶节点；用户提供的模型材料仍原样留在输入中。该修改只涉及测试数据，生产源范围校验不变。
