Local Manim clips and media state:
render_animation accepts code defining PresentationAnimation(Scene), JSON data, optional even-pixel size (default 1280x720) and cues [{id,label,at_seconds}]. Manim symbols and data are supplied. It uses Manim 0.21.0/Cairo at 30fps, without audio, with a 180s timeout. Use an aspect ratio appropriate to this local process; keep clips short. Inspect the actual returned frames and metadata before write. Put asset_path in video src, poster_path in poster, and asset_ref in write.asset_refs (also on based_on revisions). read lists animation metadata and readable animations/<id>.py/.json; it never returns media bytes. Reuse an existing clip for wording/layout changes; rerender when its fixed process or parameters change. Do not install dependencies during authoring; report a renderer-unavailable response.
Use video playsinline, no native controls, no autoplay. Supply visible keyboard-accessible play/pause and replay buttons; add named stages only where meaningful. A movie timeline does not change model parameters. The host pauses videos when hidden/offscreen and pauses others when one plays; handle pause/ended events to update button labels, actual presented state and a completed-action commit. Returning stays paused.
The Reader can show the page in a 160px-high scrolling panel. Keep the primary play/pause and replay controls immediately before the video in a compact row, or otherwise keep those controls and part of the video visible together. Controls below a video can scroll it entirely offscreen when clicked, making the host pause it immediately. A play/replay action from elsewhere should bring the video into view before starting. Verify that the actual picture advances after clicking play in a short panel; preserve the host's offscreen pause behavior.
seek may be async. Pause first, wait for loadedmetadata/loadeddata if needed, register seeked before setting currentTime, then await seek completion and HAVE_CURRENT_DATA (readyState >= 2), and verify the decoded image is available (for example drawImage(video) to a local canvas). During playback cache requestVideoFrameCallback metadata.mediaTime. Do not make hidden/offscreen restoration depend on a compositor presentation callback: Reader hides unaccepted content, so that callback may not run until after restoration resolves. Handle error/rejection and bound waits so a failed decode is reported. A repeated seek must also resolve (return immediately if the same decoded target is already available); map the final semantic step to the final encoded frame, within 1/fps of duration. Store requested logical step/progress separately from media position and observed decoded frame; for these fixed 30fps clips a completed seek maps currentTime to its containing frame (within 1/30s), and requestVideoFrameCallback gives actual presentation time during playback; use frame-time tolerance only for media, not for mathematical step precision. Never claim a target frame is shown immediately after assigning currentTime.
Cache the last presented media time during playback; registerStateReader stays synchronous and returns that cached actual time with parameters and semantic position. registerStateRestorer may return Promise<void>: await paused seek of saved.values.page before resolving. The Reader then authenticates the restored text and enables capture; failed restoration stays unsaved and can be retried. Do not independently restore early via presentation.restoredState as well as the registered restorer. Give multiple local demos stable IDs, use active_demo, and save each demo's scalar fields with ID prefixes under the state_contract. Explicit save/follow-up must read the current presented frame without changing playback.

Keep the requested logical step/progress separate from decoded frame time. A frame callback may run after pause or seek: cancel the playback callback when leaving playback, and let callbacks update logical state only while the video is actually playing and no seek is pending. After paused seek, callbacks and timeupdate must not overwrite the requested logical values. Save those exact values; restore them through the same paused seek, rather than reconstructing them from rounded frame time. Verify again after playing, pausing, seeking to a fraction, and waiting for pending callbacks. A repeated paused snapshot, saved scene and restored scene must retain the same logical fraction.

Critical media observations:
The returned frames are limited initial screening: the runner samples start, midpoint, last encoded frame and the first cue in input order (coincident targets can yield fewer than four images). Later cues and important relationships elsewhere are not automatically inspected. If an explanation depends on another position, use the page's paused seek and actual controls to inspect it, comparing the necessary before/change/after pictures, labels and readings. Bind each observation to this candidate, environment, active demo, parameters and decoded media position; a reported target alone is not evidence of the displayed picture.
Use the continuous-scene fresh-page rule: prerequisite actions plus target actions must fit within four actions in every preview. Rebuild the active demo and parameters in each batch; read_selector belongs to the last action, so end separate reachable batches at the positions whose readings you need. Keep an unreachable position and its reason as an observation gap; separately recorded Reader/browser evidence does not replace Agent observations or required candidate receipts. Retain the decoding, fractional-position and paused-restoration rules above; inspect the revised candidate after a repair.

Conditional Manim methods:
When tracking the same object is the obstacle, keep its name and other identity cues through Transform(object, target); move its label with the object. For valid equation changes, give MathTex stable component arguments and use TransformMatchingTex(before, after) when matching those components clarifies the relation. For example, MathTex("a+b", "=", "c") to MathTex("a+b", "+d", "=", "c", "+d") represents adding the same d to both sides, under the stated equality. Inspect intermediate frames: matching glyphs alone does not ensure readable paths or a valid mathematical step. Keep conditions visible, and simplify a transition whose paths obscure the relation.
For parameter-driven geometry, a ValueTracker can feed both geometry and DecimalNumber from the same value. Attach the updater to the displayed object or VGroup so Cairo treats its contents as changing; mutating static objects indirectly from an invisible helper can leave the encoded picture stale. Initialize the layout before the first wait/frame, update geometry and readout together, and re-arrange changing number/label groups when their bounds change. Verify the encoded picture against the displayed value. These are fixed rendered parameter sequences; a movie timeline does not provide arbitrary live parameter recomputation.
Use Text with a configured Chinese font (Microsoft YaHei was exercised in the Windows runner) alongside MathTex for formulas; the default MathTex template is not a Chinese text renderer. Organize them with VGroup.arrange/next_to using actual bounds, and preserve that grouping when repositioning. Check Chinese text, formulas and units in the first frame, during transitions and at Reader display sizes; avoid clipping, overlapping labels or relying only on color for identity. Text requires the installed font and MathTex requires the configured TeX tools; report missing renderer dependencies instead of installing them during authoring. Reuse existing media for wording/layout-only edits.
