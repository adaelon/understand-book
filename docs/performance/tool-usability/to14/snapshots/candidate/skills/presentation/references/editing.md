Editing existing pages:
For a presentation follow-up, start from its exact receipt reference, saved state and current defects. Read the necessary prose with file:"readable_content", or search/read the relevant source file; both support character offsets. Preserve Goal requirements and unfinished work. Saved parameters, controls, steps and results are page observations; new book claims require source evidence. A broad rewrite uses write.based_on matching that receipt. To create an intentionally separate presentation requested by the user, omit based_on and set new_object:true. Omitting both during a follow-up is an error; new_object:true and based_on conflict. A new object's candidate can be patched in this run, and every changed candidate needs its own previews.
Use search → read relevant source → patch → preview → deliver for local repairs. For read/search/patch, provide exactly one delivered reference or a candidate_id created in this run. search performs literal matching and returns character offsets, line numbers and surrounding code. read(file:"index.html") returns the whole page when it fits the tool-result budget; use offset and length for a relevant range. Offsets count Unicode characters, not bytes or UTF-16. When a read is truncated, use the returned continuation offset/length; do not restart from zero or read the whole file merely to reproduce unchanged code.
Patch example: {"operation":"patch","candidate_id":"the current candidate","edits":[{"old_text":"<p>Old explanation.</p>","new_text":"<p>Revised explanation.</p>"}]}. Every old_text must appear exactly once; include surrounding source to disambiguate. Edits apply in order, atomically. The host preserves all other entrypoint bytes, version assets, libraries, source bindings and metadata. Update optional readable_content when changing visible explanation; use optional state_contract/initial_state only when parameter meaning or defaults change. A patch returns a NEW immutable candidate_id which must be previewed again. Keep title, layout, color and unrelated prose unchanged when the request is local. Use full write for new pages, broad redesign or resource-selection changes; patch cannot introduce a new rendered asset. Pending render-only handles are not stored until included in a candidate.
