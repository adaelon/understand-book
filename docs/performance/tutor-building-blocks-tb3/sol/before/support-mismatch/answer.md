明白，你已经说明不再认为有两份 `Foo`。我们换成逐行代码和类型对照。

先读这两行：

```rust
let foo = Foo(0);
let bar = &foo;
```

第一行把 `Foo(0)` 绑定给 `foo`。第二行先计算右侧 `&foo`，得到对这个值的不可变引用，再把引用绑定给 `bar`。借用不取得原值的所有权。[[source:source_ref_b7cdf804a5f27a0d]][[source:source_ref_9af277d1d3d785d4]]

| 变量 | 类型 | 此时保存什么 |
|---|---|---|
| `foo` | `Foo` | 原来的 `Foo(0)`，仍由它拥有 |
| `bar` | `&Foo` | 对该值的不可变引用，可读取，不能通过它修改原值 |

这个对照对应原例的两行绑定和正文对 `bar` 类型的说明。[[source:source_ref_e2f1f69dfb7b32e3]][[source:source_ref_9af277d1d3d785d4]]

补充一条用于读后面代码的 Rust 规则：本例 `println!` 中的 `{:?}` 做 Debug 格式化时，只借用参数来读取，不把参数中的值取走，也不修改它。共享借用允许这种读取；所以判断一行是否还能使用某个变量，要看它的值或引用是否仍有效，以及这一行要读取还是修改。

现在请你用自己的话解释原例这两行为什么都能使用：

```rust
println!("Foo is {:?}", foo);
println!("Bar is {:?}", bar);
```

按代码顺序说：创建 `bar` 后，`foo` 的所有权发生了什么？第一行打印会不会取走它的值？第二行的 `bar` 又凭什么能读到那个值？把这几处连接成你的解释即可。
