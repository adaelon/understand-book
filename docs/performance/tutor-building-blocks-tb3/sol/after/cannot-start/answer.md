我们把判断缩成一条连接：**打印需要读取那个变量；先看赋值以后，这个变量还能不能读取值。**

原文的 `&foo` 创建共享引用，`foo` 仍拥有值，`bar` 借来读取；所以原文里的 `foo` 没有因为这次赋值失去读取资格。[[source:source_ref_b7cdf804a5f27a0d]] [[source:source_ref_9af277d1d3d785d4]]

先示范一个小例子。假设 `Parcel` 是能用 `{:?}` 显示、但没有 `Copy` 能力的类型：

```rust
let a = Parcel(0);
let b = a;
println!("{:?}", a);
```

这里补充两条 Rust 规则：没有 `Copy` 能力的值直接赋给另一个变量，会转移所有权，原变量不能再读取那个值；`println!` 的这种显示虽然只是借用，也必须先能合法读取变量。

我这样连起来：`let b = a` 把值交给 `b` → `a` 不能再读取值 → 打印要求读取 `a` → 这一条打印不能通过编译。换成打印 `b`，则可以读取，因为 `b` 接到了值。

现在只留同样大小的一步。原文的 `Foo` 只派生了 `Debug`，没有 `Copy` 能力。[[source:source_ref_4c3de5a75d5bc2f7]] 把原文第二行的 `&` 去掉：

```rust
let foo = Foo(0);
let bar = foo;
println!("Foo is {:?}", foo); // 只判断这一行
```

请补完一句：**“赋值后值由 ___ 拥有，所以第一条打印中的 `foo` ___（能／不能）读取这个值。”** 先不用判断第二条打印或整个程序。
