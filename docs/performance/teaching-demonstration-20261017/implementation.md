# 演示作为当前教学表示的闭环

目标：用户只表达困惑和局部理解时，教师能选择是否使用演示、使什么关系可观察，并把实际操作现场与用户自己的解释接回后续帮助。沿用已有教学设计、页面制作、不可变现场回执和内容接纳，不规定每轮使用页面或提问。

## 实际断点

- 普通教学自动提供 tutor.step，但 presentation.author 为延迟发现；完整演示指导又要等该工具可见，教学设计本身没有表示选择。
- 接纳调用只有聊天正文，没有所引用页面的实际内容与作者预览。曾保存但未通过接纳的页面可能随最终答案一并附出。
- 生产 bridge 已发送 teaching-help 与 region-located，宿主入口却拒收这两种已有消息，后面的帮助登记分支不可达。
- 支持型演示没有邀请时，已展示帮助不冻结到后续普通表达。历史教学投影只留文字，不能默认重获表达发生时的原始场景。

## 实现切片

1. 当前设计选择 representation：文字说明为何足以建立连接；演示说明为何需要以及使什么关系可观察。页面选择在下一采样激活现有制作工作流；老设计仍可读取，当前使用时补上选择。
2. 既有交付接纳读取精确引用页的可读内容、初态、教学绑定和实际作者预览。最终教学附件由接纳后的动作集合决定，保留页版本不会自动成为交付。
3. 修复前端已有消息协议；真正显示的页面帮助才登记。无邀请的支持页同样冻结已显示帮助。
4. 教学帮助与表达投影保留精确场景回执、原页版本、控件值和渲染结果。场景与原话并列，渲染、点击和未编辑预填均不自动成为理解证据。
5. 真实操作暴露了作者页错误恢复自定义状态，而制作预览原先未执行 restorer。保持完整场景 API，在预览完成操作后重新打开同一候选，恢复并回读自定义值和可见步骤；实际不一致通过已有 preview_failed 退回制作。不能把新开页正常显示当成保存状态可恢复。
6. 多轮页面制作使历史达到压缩条件，暴露跨轮复用工具编号被全历史去重错误拒绝。沿项目既有轮内唯一约定移除这层错误去重，来源身份仍由各消息的 source_item_id 区分；当前工具结果只投影本轮，避免同编号覆盖以前轮次。旧调用和原始失败记录保持。
7. 制作与多尺寸预览还暴露每次采样都追加完整运行状态造成的容量问题。沿既有上下文账本，仅在实际压力下退役已被新版本替代的运行状态与阶段指导，重新组成当前完整活动指导；用户原话、真实工具证据及冻结场景不变。正常低压路径仍保留既有缓存行为。

## 验证如何改变决定

前端回归先出现4项失败，修复后20项通过：真实message入口能够保存当前现场、登记帮助、等待确认再回执。后续测试检测主动曝光、选页但无页交付、被退回页泄漏、无邀请帮助遗漏、现场版本错接和未来帮助回填；若失败，先修这些执行路径，不进入语义验收。

多轮实验沿用真实服务器工具、持久化和内容接纳，由隔离6.1 sol提供教师与用户响应。用户只看实际回答和真实渲染/操作结果，不读源码、私有设计或教学步骤。页面操作由用户代理选择，父代理仅执行其选择；真实bridge快照经实际state.save和follow-up入口回到下一轮。对话与页面内容另行独立审阅，不能以生成页、保存状态或字段出现作为闭环完成。
