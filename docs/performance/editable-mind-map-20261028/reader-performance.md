# 500 主题 Reader 实测

2026-10-28 在实际本地 Reader、真实服务和 Edge 中完成。Windows 10.0.19044，AMD Ryzen 7 5800H（16 逻辑处理器），Edge 156.0.4314.42，1600 × 1000，像素比 1。运行目录为 `tmp/editable-mind-map-20261028/performance-01`；目录内保留冻结的服务二进制、Web 构建、存储、原始测量与截图。

500 个不同短标签取自本机 Rust 书源，从“Rust 入门”起提取；没有找到结束标题，因此不声称仅来自一个章节。固定五叉层级用于规模测量，不代表模型整理的教学提纲。数据通过正式原子编辑接口保存，再打开完整 Reader，未用独立布局页替代页面测试。

| 测量 | 样本 | 中位数 | 最大值 |
| --- | --- | ---: | ---: |
| 输入事件到两帧后的编辑器内容 | 40.1、25.0、20.2、26.7、24.7 ms | 25.0 ms | 40.1 ms |
| Enter 提交到两帧后的新主题标题 | 160.8、80.8、63.1、91.5、86.1 ms | 86.1 ms | 160.8 ms |
| Enter 到服务读取确认新标题 | 605.3、489.0、561.8、525.8、504.8 ms | 525.8 ms | 605.3 ms |
| 拖动指针到下一帧相机变化 | 10 次 | 21.8 ms | 24.2 ms |

首次导航到 500 个主题全部挂载、字体就绪并等待两帧为 **4841.9 ms**；关闭页面后重开为 **4876.3 ms**。重开后确认 500 个身份、每个主题的孩子顺序和五次改名后的标题全部保留。初始 500 操作保存批次为 231.7 ms。页面没有捕获到运行时异常。

这些测量区分了输入、可见标题变化和服务保存。首次提交 160.8 ms 超过计划中的 100 ms 本地反馈目标，后四次为 63.1–91.5 ms；当前结果不支持“所有编辑反馈都小于 100 ms”。首屏约 4.8 秒也应保留为可改善的真实成本。样本量小，仅反映这台机器上的本次运行。

直接查看了三张原测量截图。100% 下初始视口和重开视口只展示可读根主题与延伸出屏幕的连线，它们用于根标题编辑和保存测量，**不是全图可读性证据**。

随后使用同一已保存数据追加真实导航验证，没有重跑或覆盖测量：点击“显示全部内容”，再切到大纲，折叠其他分支，仅保留 11 个可见主题、3 层结构。回到导图后适应画布为 92.4%，主题文字完整、连接清楚，折叠按钮显示隐藏主题数量；内容修订仍为 7。截图 `500-topics-readable-three-levels.png` 已直接检查，证明折叠后可以在正常阅读尺寸查看局部层级。

初次测量发现“显示全部内容”受 25% 缩放下限约束，这棵完整 500 主题树仍有内容在视口上下方。原目录的 `500-topics-fit-overview.png` 保留此失败现象。

修复后，把原有隔离数据复制到 `navigation-02`，使用新的冻结 Web 构建补做导航验证，不重跑性能样本。此次全图缩放为 2.14%，浏览器逐一检查 500 个主题的四个边界，全部位于画布内。这个缩放只提供形状概览；在大纲搜索一个主题并定位、切回导图后，缩放恢复到 100%，所选主题与附近文字可读。再次折叠到 11 个主题、3 层，适应画布为 92.4%，内容修订仍为 7。三张新截图均直接查看，导航未再发现问题。
