## 实现行为

笔记正文和版本保留用户实际保存的表达。“相关理解”说明已经展示的能力、具体卡点、尚待确认之处，并标出原笔记版本及帮助条件。“思考过程”串起确切版本、明确相关讨论、实际活动、系统判断和用户纠正；只有修订原本带有讨论来路时才显示因果链接。关联依据使用用户真实表达，保存、复制或采纳正确文字本身不产生能力证据。

笔记与理解总览共享同一当前解释。关系按原学习范围和材料版本保留身份；一条笔记可以关联多个关系，同一关系也能带回多个笔记版本。继续推敲/练习携带原范围、原关系、确切版本及 evidence_ref。独立且无材料的想法先显示真实修订和讨论。

纠正追加撤回记录，旧原话和旧判断保留。存疑活动的表现及依赖它的观察退出当前摘要。开放题以明确逐项映射区分概念和计算；只有部分标准提供局部映射时，整题结果留在原评分记录，不覆盖已明确的局部判断。

## 真实模型判断

通过 `crates/runtime/examples/note_understanding_eval.rs` 调用产品同一 `execute_coach`，使用本机配置的 `deepseek-v4-flash`。全部使用确定的平均速度材料与人工构造表达，没有发送真实个人笔记。

最终 `model-accepted/` 保留冻结输入、模型公开 JSON 输出、解析后的结果、耗时和输入字节数。六个场景全部成功接纳，共 7 次模型调用；“数值正确但理由错误”使用既有一次合同修正流程后接纳，其余五例一次完成。每例 5.57–12.88 秒，模型输入主体 1477–1738 UTF-8 字节，公共指令与 schema 为 25245 字节；修正调用单独记录。此处记录字节和实际调用数，没有把字节换算成未采集的 token 使用量。

| 场景 | 最终观察 |
| --- | --- |
| 只是提问 | demonstrated 与 difficulties 都为空，仅记录尚未确认的关系 |
| 理由正确 | 保留停车计入总时间及速度变化的因果关系，具体计算仍待确认 |
| 数值正确、理由错误 | 保留所给数值，同时指出“只算运动时间”与结果冲突 |
| 概念正确、算术错误 | 保留时间范围与单位换算，卡点归于除法计算 |
| 提示后完成 | 标出此前帮助，保留待验证的独立应用 |
| 修正原想法 | 更新同一关系、保留旧笔记第 1 版引用，不将受助修正说成独立掌握 |

先前 `model/` 与 `model-revised/` 记录了求证被扩大成卡点、把核验材料混作先前帮助，以及 JSON reason/focus_ref 位置不稳定的问题。修正了冻结输入的时间边界、知识关系字段说明和笔记来路要求；`model-diagnostic/`、`model-final/` 和最终验收目录保留完整过程。能力字段继续允许项目已支持的中文表述，没有强制替换为固定枚举。
