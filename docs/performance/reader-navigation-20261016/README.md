# Reader 目录跳转与专注阅读（2026-10-16）

## 行为与实现

- 普通目录跳转使用客户端当前版本直接提交；只有服务端明确拒绝旧 revision 时才刷新并重试一次。现场 generation 变化、网络中断、保存失败均不自动重放。
- 未缓存的目标正文随已确认的跳转窗口返回，消除关键路径上的单独正文读取；最近正文缓存最多 100 个叶节点、512 KiB UTF-16 文本。切换材料重新创建缓存，正文不截断。
- 连续点击只保留尚未发出的最后一个目录请求；其他写操作仍构成顺序边界。在途请求保留版本确认，但旧结果不能覆盖新页面。
- 专注模式显示目标页不等待旧读位保存；保存仍串行，只有当前导航的确认回包可更新视口。发问前继续等待最新读位保存。
- 滚动补载携带导航和材料上下文；跳转后旧补载不能把上一章段落拼入新窗口。
- 专注阅读纸面和周围留白为白色，移除右上角贴边的“菜单”。目录、阅读设置、问答、笔记和退出专注仍使用底部阅读工具。

主要代码：`packages/web/src/network-client.ts`、`App.vue`、`reader-window-text.ts`、`components/LeftRail.vue`、`components/TopBar.vue`、`style.css`，以及 `crates/server/src/lib.rs` / `workspace_registry.rs`。

## 测量方法

正式域名 `https://understandbook.top`，书籍 `ai-agent-engineering`，publication `01a0f58a-2aea-7742-a392-296745511508`，2646 个叶节点、292 个章/节节点；目标目录交替为 `1.4.9.13` 与 `1.8.14`，每次 6 个样本。使用独立工作区，结束后 detach 和登出，无模型调用。

浏览器测试使用独立 Chromium 会话、1440×900 视口和本机既有代理。计时从实际目录 click 事件开始，到目标原文进入可见区域并等待两次 animation frame；首次样本单列，后 5 次取中位数。脚本为 `packages/web/playwright/reader-navigation-live.spec.ts`，通过 `READER_NAV_LIVE_OUTPUT` 显式启用；凭据由 `READER_NAV_CREDENTIALS` 外部提供，不写入结果。

HTTP 测量脚本为 `tmp/reader-navigation-20261016/measure.py`。`--paired` 在同一网络时段交替运行原来的三请求链路、携带正文的一次提交、复用正文的一次提交；逐段对照 UTF-16 原文，只有正确结果纳入完成样本。

## 验证

- 前端 4 组单元测试共 37 项通过：单次提交、显式版本冲突重试、generation 改变、网络失败不重放、连续点击合并、其他写操作的顺序，以及正文缓存/边界。
- 服务端测试 `mu5_directory_navigation_returns_exact_confirmed_window_and_preserves_cas` 通过：窗口与读位一致、正文逐段相等、书尾夹取、旧 revision 拒绝且不改读位、跨用户隔离。
- 浏览器 3 个场景通过：冷跳转与缓存返回、700ms 旧跳转回包、1800ms 旧读位保存期间连续跳章和刷新恢复、900ms 旧滚动补载。桌面与390px手机验证白底、底部工具、退出专注。
- TypeScript 检查、正式多人前端构建、Linux release 的5个程序构建通过。

旧滚动补载在修复前复现：跳到第三章后，第一章第9段被迟到的补载插入；加入导航上下文判断后同一测试通过。最初专注浏览器测试的夹具把 `/profile/memory` 返回为空对象，触发组件渲染错误；按现有接口补齐夹具后完成验证。没有把这项夹具错误算作生产缺陷。

浏览器计时包含目标正文渲染，不包含登录、初次下载应用文件或旁栏后续内容。HTTP 计时仅表示请求链路。样本量较小，不作为全体用户或不同网络条件的延迟保证。

首次跳转和网络长尾仍可能超过数秒；本次没有把首次样本或长尾隐去。当前证据证明串行往返减少和所测场景的中位数改善，不证明所有网络下的最坏延迟已经消除。
