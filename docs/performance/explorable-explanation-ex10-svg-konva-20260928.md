## 实施与批次身份

固定任务为一维二次损失学习率解释：同一用户请求、ed3.v1、共享交互合同、deepseek-v4-flash / native / temperature=0。B 使用原生 SVG，C 使用 Konva 10.7.0。两组有各自最小 API 示例，任务答案不进入制作资料。共同说明 2,225 字节，B API 1,756 字节，C API 2,082 字节。独立答案单独保存。

Konva 库为 192,898 字节，附 MIT 许可证。先行点线场景通过真实 author 写入、三视口 preview，以及 Reader 鼠标/触摸拖动、保存、同版重开和追问。该工程场景不计入生成成功率。初次测试生命周期缺少最终回答提交，以及示例 ResizeObserver 循环，均在冻结前修正；原失败记录保留在 [preflight](ex10-svg-konva/preflight/)。

第一批于 9 月 27 日 23:03 冻结，顺序执行 B1、C1 后停止。B1 已交付但存在质量错误。C1 的测试 adapter 把装配后的库源码写回模型返回的工具调用，导致 Runtime 后续历史包含库源码。模型随后误以为自己粘贴了库，又改写一次，最终触发 `ACTIVE_CONTEXT_EXHAUSTED`：输入估算 130,642 tokens，加 12,000 预留，超过现有容量。该失败属于实验装配位置错误。

已将固定标记替换移至 **test-only Author Write 内部、候选校验和保存之前**。模型返回的工具调用保持原样，保存的候选包含实际库源码。回归测试用固定模型响应走真实 adapter，再将其 write 送入真实 author：断言返回参数不变、候选等于完整装配结果、普通测试不启用装配。两项回归通过，见 [日志](ex10-svg-konva/assembly-boundary-test.log)。生产 CSP、1 MiB 限制和 ed3.v1 保持原值。

第二批于 9 月 28 日 09:08 冻结。资料逐字沿用第一批，装配修复与源文件快照另存 [batch2/frozen.json](ex10-svg-konva/batch2/frozen.json)。B1 第三次模型请求返回 `Provider unfinished response: length`，状态 502；没有生成 write，也没有交付页。按合同 §6 停止该批，C1 及后续样本未运行。请求 `output_token_limit=null`，没有设置实验输出上限；此处也未以累计 tokens 或墙钟作为拒绝条件。截断请求的实际用量未返回，保留为未知。

独立计算覆盖 η=0、0.2、0.5、0.8、1、1.1、1.2，k=0…5。B 用闭式独立核对，C 用递推核对其闭式实现；几何读取实际 SVG 图元或 Konva 对象，不只检查模型自报状态。依据见 B 的 [independent-check](ex10-svg-konva/runs/B1/independent-check.json)、[Reader 记录](ex10-svg-konva/runs/B1/reader-check.json)，C 的 [independent-check](ex10-svg-konva/runs/C1/independent-check.json)、[Reader 记录](ex10-svg-konva/runs/C1/reader-check.json)。

解释有两处明确错误。B 页面把梯度方向说成始终指向最小值；本题指向最小值的是负梯度。B 最终回答把 η=0 纳入“幅度缩小、单调靠近”，实际保持 w=0。C 在 η=0.5 的动态解释中，一边写一步到达，一边写乘数为负、每步换边；实际乘数为零。这些错误足以否决对应原稿，少写代码不能抵消它们。

C 在 Reader 640×240 展开态中，回退按钮被宿主 header / 追问表单遮挡，真实 click 超时，见 [原始失败日志](ex10-svg-konva/runs/C1/reader-run.log)。这是受支持短屏入口下的实际操作问题，不能归因为 Canvas 绘制本身。原候选的独立三视口几何核对通过，也不能替代 Reader 短屏操作验收。

前两批总已知用量 **1,293,955 tokens，另有一次截断请求用量未知**。Provider 未暴露输入/输出拆分，未以字节估算冒充实际输入 tokens。各次响应、时间和 [cost-summary.json](ex10-svg-konva/cost-summary.json) 可追溯全部成本。第一批 C 包含错误装配进入历史的额外输入，不能把 B/C 总量差异解释为库的净收益；第二批未获得修复后的有效 C 样本。

B 首次 write 在 272.001 秒，候选被接收，但第一次 seek preview 因 semantic_state 类型错误失败，第二稿修正后才取得成功预览；第三稿调整标签。首份成功动作预览回执在第 5 号请求中可见，对应开始时间 332.027 秒。真实拖动验收发生在生成之后，因此“首次实际拖动可用时间”未单独测量。C 首次 write 在 215.081 秒，但正式会话未走到 preview；诊断页事后可操作不能倒填为正式交互交付时间。

固定库装配时间第一批 C 两次分别为 907、932 微秒，最终增加 192,891 字节（完整脚本减去标记）。资料整理、下载、测试开发和诊断的总人工墙钟未单独计时，不计入模型生成耗时。两组实际请求均没有显式 `max_tokens` 上限；8,000 是 Runtime 输出预留，容量检查额外包含安全余量，不能把预留误写成模型输出额度。

五秒 Reader 观察中，B 为 230 个帧间隔、帧间隔 P95 33.4 ms、观察回调 P95 4.4 ms、1 次保存和 185 次 observe；C 为 228 个帧间隔、33.4 ms、4.1 ms、6 次保存和 169 次 observe。仅这两次桌面诊断不能证明绘图库性能优劣。C 五秒后自然播放结束，测试再次点击播放使其重新开始，因此该记录中的 `paused.playing=true` 不能当作暂停缺陷或暂停成功证据。另行在独立原稿预览中验证两页真实拖动、播放 200 ms 后中途暂停，2/2 通过且无脚本错误，见 [viewer-check](ex10-svg-konva/viewer-check.json)；这不补算 Reader 短屏通过。

## 采用结论与后续入口

**保留当前 SVG 路径，不将 Konva 设为默认能力，也不进入有限产品接入。** 工程先行证明固定 Konva 可以在现有自包含、安全和状态合同内工作；它没有证明 Agent 交付质量更好。正式样本不足、已有原稿存在必要质量错误，未满足 C 连续三次通过并体现重复改善的采用条件。

EX10 的实验代码、全部实际样本、失败原因、原始页面、成本和可操作入口已经交付；达到约定停止条件即结束本刀。下一独立切片应先处理 Provider 截断的可观测性/续行能力与 Reader 短屏遮挡，再决定是否建立新的冻结对照。已经停止的批次不改提示补抽，不将诊断候选提升为成功样本。EX2 v7 继续停止，生产仍为 ed3.v1，未进入 EX7。

## 已知限制与用户反馈

- 尚未取得用户实际操作这两个页面后的反馈；仅有用户此前明确要求实时拖动交互，及本轮“token 不是问题”的成本约束澄清。未评价真实学习收益。
- C 是未交付的原始候选，可能仍会在会话内修订；其诊断错误只能说明当前候选不通过，不能预测完成后的表现。
- B 的保存重开测试显式调用提交入口，故不掩盖原稿漏用 `commitState` 的缺陷。C Reader 短屏完整流程和修复后真实 Provider 的 C 生成仍缺证。
- 第二批截断响应没有完整响应体和用量；现有适配器遇到非正常结束即返回错误。没有将缺失字段当作零成本。
