## 可以怎样使用

1. 在资料库或阅读界面打开右下角“记个想法”，直接写半句话也可以保存。标题、材料、目标都可留空。收起或刷新页面后，从草稿继续。
2. 阅读选区、原回答、视频时刻和演示现场的记录入口进入同一个编辑器。正文与保留素材分开；记录情境固定在当时的资料版本，之后切换材料不会改掉来源。
3. 保存修改会追加一版。“思考过程”可以阅读旧版、比较版本、回看相关讨论；从旧版继续写会创建新版本。来源区可以返回实际材料位置，查看综合稿的来源想法与形成表述的讨论。
4. “一起推敲”开启个人讨论，无须先打开材料。讨论可收起、重开、继续和停止。用户原话可以留为想法，助手回答先进入标明来源的 AI 草稿，由用户修改保存。已打开资料时，可以把确切讨论带到该资料中继续。
5. 普通学习提问会尝试找回相关个人表达。真正被教学采用的想法会出现在回答旁；明确点击“围绕这些想法补充”后，新表达才关联到这些想法。结束关联后，后续闲聊不再自动记成该想法的变化。
6. “联系”可搜索另一条想法、建立双向联系和修改说明，也可请 Agent 建议。建议在用户采用前不成为个人联系。画板可引用这些想法；“整理成我的解释”生成可写的综合稿，“请 Agent 起草”先形成讨论与候选稿。

## 召回的实际方案

词法复用 BM25，按稳定笔记身份归并片段；多字中文查询不以单个汉字共同出现作为相关依据，并排除常见连接词的二元词项。语义复用服务器内的 `Xenova/paraphrase-multilingual-MiniLM-L12-v2`，CPU q8、384 维、真实 tokenizer、128 token 分段。资料和个人笔记各用自己的所有权与索引入口。

词法取 40 个候选，语义取 80 个候选，语义低于 0.3 的邻居不进入融合；用 RRF(k=60) 归并，普通自动入场最多 8 条，显式引用另行读取。候选是待判断的个人表达，最终是否采用由主 Agent 根据当前问题决定。联系是显式关系，不能冒充语义相似或已掌握。

索引以 `note_id + revision + expression_count` 判断变化，不为正文额外计算哈希。已保存正文立即可读，向量按批补齐；旧任务不能恢复已删除或已改版的索引。真实返回 ready/partial/unavailable 与原因。向量推理、缓存读取在用户锁外执行，返回时再次按权威当前版本筛除已变更、已删除的候选。

`notes.read` 的正文、摘录、相关表达、联系说明使用 Unicode 字符分页，默认 3000、最多 4000 字符；附带最多 4 条后续表达、8 条联系预览和续读参数。历史一页 10 个版本头；读历史头或联系头不会自动算成已读正文。主 Agent 可继续按确切版本和区间回读。

## 真实模型验证

测试资料、问题和用户表达都是本次构造的学习样例。模型为实际配置的 `deepseek-v4-flash`，没有用固定回复代替这一组教学效果检查。[完整对照结果](real-model-comparison.json)保留问题、原话、后续表达、回答、读取与采用版本。

| 已有表达 | 实际行为 | 执行阶段耗时 |
| --- | --- | --- |
| 误以为推理中的向量变化意味着重新训练权重 | 真实读取 notes.read，从初始嵌入、固定参数与变化激活的区别解释 | 75.3 s |
| 已经区分参数和激活 | 真实读取 notes.read，承接已有区分，再展开注意力如何使用上下文 | 132.1 s |
| 旧笔记仍错误，但明确关联的后续表达已纠正 | 读取旧版及更晚原话，从已经纠正后的理解开始，继续解释 q/k/v | 72.1 s |
| 无关的烹饪笔记 | 修正词法噪声后重跑，未读取或采用无关笔记，回答当前问题 | 约 110 s |

首次无关样例曾被牵强用作类比；结果文件保留该失败样例及修正说明。重跑依据最终回答和 TeachingDesign/Move 的实际引用判断，不能只以搜索命中率判断教学正确。

[无材料真实讨论](real-personal-discussion.json)：实际 RunScope 没有 Book，用户明确引用“多读几遍就说明理解了，但解释给别人听就卡住”。接纳路径放入确切笔记版本，真实模型一轮调用约 11.7 s，围绕熟悉感、主动解释与关系生成给出反馈，没有生成材料掌握事实。

四组初始运行共 30 次模型请求，无关样例复验 9 次，无材料讨论 1 次；这包括正常教学/工具循环，不存在额外查询规划或专用重排模型。计时是测试记录的 Agent 执行阶段总耗时，不是网络首 token 延迟，也不等于语义检索新增等待。

## 检索和存储成本

[真实 MiniLM 测量](real-retrieval.json)使用 100 与 1000 条中文笔记，包含一个目标位于长笔记尾部的样例。每组 5 个改写问题的目标均在前 3 名；两组各只更新 1 条笔记，均只重算 1 个片段。

| 规模 | 首次加载并完成全部索引 | 已就绪语义查询 | 重开缓存 |
| --- | --- | --- | --- |
| 100 条 | 3.585 s | 5.4–10.6 ms | 100 条命中，文档 embedding token 为 0；模型重开约 1.17 s |
| 1000 条 | 45.497 s | 20.2–35.6 ms | 1000 条命中，文档 embedding token 为 0；模型重开约 5.40 s |

冷加载数字是“模型加载并等待整批建完”的测量，不是保存必须等待的时长。产品中的保存不等待整批索引，查询可先使用词法和已经建好的有效向量。上述查询数字是语义引擎调用，不包括 HTTP、UI、主 Agent 生成和 Rust 合并开销。

[真实磁盘保存测量](storage-cost.json)：1000 条笔记、3001 个已保存版本，每版约 360 中文字符；私人文档 6,210,230 字节，追加一次修订约 290.3 ms，重开约 136.6 ms。环境为本机 Windows/debug，使用真正的保存与重开路径。当前文档仍采用原子全量保存，没有引入第二套笔记数据库。

## 使用条件与已知限制

- 已发布版本为 `personal-notes-20261030`。MemoryDocument 升级为 schema 5，控制库升级为 schema 22；上线后不能直接用 schema 21 的旧程序打开现有数据，恢复边界见发布记录。
- 在线服务默认使用 `/opt/understand-book/models/local-embedding.json`，由运营方随部署统一安装、检查和预热。读者无须下载 MiniLM、配置环境或提供 embedding 密钥。模型文件跨 release 复用，私人索引按账号隔离；运行时故障真实返回 partial/unavailable，词法查找、明确引用与保存仍可使用。
- 未发送草稿保存在当前设备并按账号分开；不会同步到其他设备。已经存在但旧系统没有保存的历史正文无法补回，旧作者未知时保留 unknown。
- 语义召回不能保证找到全部联系；当前索引面向当前版和明确关联的后续表达，历史版本通过确切引用回读，不做全库旧版语义搜索。
- 当前样例验证工程闭环和模型会使用个人表达，不代表已测得真人学习收益。没有测量“相同完整问题关闭/开启召回”的端到端首 token 差值；报告分别给出实际语义耗时与 Agent 总执行阶段耗时。
