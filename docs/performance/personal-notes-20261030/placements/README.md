# 随手记的产生现场与展示位置

日期：2026-10-30。状态：15:16 HKT 已随 `all-pending-20261030` 上线，见[合并发布记录](../../all-pending-release-20261030/README.md)。接续[浮窗实现](../floating/README.md)，本阶段接通统一「放到…」、原句下展示、画布元素关联和演示页关联。

## 交付行为

浮窗继续支持拖动、八方向缩放、收起、设备草稿与快捷键，打开时不改变原阅读区的尺寸、滚动位置或组件实例。

全局入口默认只保存想法，并冻结打开时可确认的产生现场；也可选择独立想法。从消息、画布或演示的「在这里记想法」进入，默认放到该位置。选择来源、选择展示位置与修改正文分别处理，后续切换页面不会把旧草稿改绑到新页面。

| 展示位置 | 当前行为 |
| --- | --- |
| 画布 | 放独立想法卡片，或放在选中元素旁并连接；同一画布重试使用已有卡片，卡片与连线一次保存。 |
| 对话 | 选择一句话后记想法，显示在原句所在段落下；记录该文字在消息中的出现次数，区分相同句子。不选文字时放在消息下面。 |
| 演示 | 选择时保存演示状态。能识别页面的演示按页面显示；其他演示按保存的状态显示。「其他演示页的想法」可恢复相应页面和状态。 |

一条想法可出现在多个位置，各处解析同一 NoteID 的当前正文。想法详情列出展示位置，可返回或移除；移除位置保留正文、历史与产生现场。历史画布保持原有的版本冻结规则。

正文先保存、放置随后失败时，草稿记录已经确认的笔记身份。重新打开后只重试放置，不重复新建想法或追加修订；也可改选位置或改为只保存。

## 代码与存储

- `note-placements.ts` 注册当前可用宿主、执行统一放置，并按账号和会话共享附件读取，避免每条消息各发一次请求。已被画布、来源窗口或讨论层覆盖的宿主仍保留实例，但不提供默认现场和放置选项。
- `PersonalNotes.vue` 提供「放到…」、默认来源快照、位置列表、返回与移除。`personal-notes.ts` 保留已确认正文和未完成放置的设备草稿。
- `MessageThoughts.vue` 在原句所属段落后挂载 `AttachedThought.vue`。附件内容不参与原回答选区的来源偏移计算。
- `BoardWorkspace.vue`、`AgentPresentation.vue` 提供当前元素、页面或状态；`ApplicationShell.vue`、`NetworkApp.vue`、`App.vue` 接续对应阅读空间、会话与画布。
- `MemoryDocument` 升到 schema 6。`note_attachments` 存消息和演示的展示引用，`NoteContext.origin / board_id / board_item_id` 保存产生现场；旧 v5 缺省字段按空引用升级。
- `personal_note_api.rs` 校验所属会话和保存的演示回执；演示页面从实际保存状态确定。`board_api.rs → BoardStore::place_personal_note` 沿画布原存储一次写入卡片和可选连线，不放宽普通布局更新的合同。
- `notes.read` 输出消息和演示的 `display_locations`，画布位置通过用户自己的画布反向查询；展示引用不复制笔记正文。

## 检查中修正的问题

首次服务端画布测试发现普通布局更新会拒绝新增连线。改为独立的原子放置操作，沿原锁与快照保存，不改变普通更新规则；随后真实存储测试通过。

浏览器合并检查首次出现 4 条原浮窗场景失败：旧测试接口没有返回新增附件查询的 `items` 字段。补齐该测试数据后，4 个尺寸场景全部通过。另修正演示测试接口路径及状态恢复数据，使测试使用实际保存和恢复协议。选区测试发现原算法会保留段落前换行，最终用添加附件前后的原始选区结果做等价比较，确认附件不污染文本或偏移。

保留后台消息、再覆盖真实画布组件的新增浏览器测试确认：旧消息会错误抢占默认现场，并出现在位置菜单。修正宿主的前景可见性判断后，该场景及其他 5 个放置场景通过。独立草稿主动选择「关联当前位置」的新增组件测试还确认了演示快照遗漏；补齐确切状态捕获后，来源切换保持正文且不自动增加展示位置，相关 9 项测试通过。

## 已知限制

窗口是应用内浮窗，展示位置通过明确的「放到…」或就地记录选择。演示想法位于宿主页面下方，关联页面或状态；尚无演示内部任意图形、像素位置的摆放。原句引用无法重新定位时，保留引文并显示在消息下方。

浏览器验证使用实际组件与模拟接口，真实服务端存储另行测试；本阶段没有重跑正式部署的完整模型链路。手机使用浏览器视口、触屏与键盘模拟，未用实体手机。草稿和窗口位置留在当前设备。根工作树包含其他原有改动，发布时须基于实际线上版本集成；本轮未提交、推送或部署。
