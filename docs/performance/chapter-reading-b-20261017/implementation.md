## 表达与实际帮助的关联

现有 `LearningEvidence` 和教学事件已经保存原话、来源、设计及关系引用，以及输入时冻结的 `support_delivery_refs` 和 `assistance_refs`。本轮在 `learning_opportunity.delivered_support` 补上 `responding_to_expressions`：它读取该次真实交付所回应的原始表达，与实际帮助正文、帮助后的 `learner_expressions` 并列提供给教师和交付接纳者。

前后表达共用同一投影方法，各自保留事实引用、原话预览、当时的正文帮助、显示过的提示、邀请、页面现场和理解解释。纯点击不成为读者表达；长原话可以按原事实引用分段读回。未真正交付的选择不进入帮助记录；后加提示不会改写先前输入的帮助条件。换焦点与数据库重开后，这些关联仍可恢复。

`responding_to_expressions` 表示这份帮助回应了什么，不能自动当作正式前测。普通帮助正文通过原话事实的 `support_delivery_refs` 指向实际 `MessageDelivered`；`assistance_refs` 记录显示过的额外帮助。因此后者为空也不能宣称独立表现。

实现接点：[design.rs](../../../crates/server/src/teaching/design.rs)。沿用现有存储与 `nature=hypothesis`，理解判断保持可修订、未评分。

## 理解判断如何改变后续教学

Resident 在支持实际解释或困惑时，将对应事实写入 `responds_to.fact_refs`，包括没有前一份邀请的首次表达。理解更新沿用实际 `design_ref / block_refs`，把这次表达连接到处理中的关系。

后来的表达出现新的连接时，为这次表达追加假设。先前对原话成立的解释继续作为历史起点；`supersedes` 用于纠正原解释本身无依据的推断。采用历史解释前，需要结合后来表达及其帮助条件判断它是否仍描述当前情况。

局部进展的解释要明确：先前怎样连接，实际帮助已提供什么，后来又作出了什么判断。复述已交付结论只能支持复述或在该帮助下使用；没有可比的早先表达时，只描述当前表现。换问题后按新关系取证。下一步根据实际需要补较小连接、改变支撑、修订问题或结束局部工作。

现有交付接纳同时检查进展表述与下一步是否得到原话和实际帮助支持；仍使用原有一次接纳调用。指导版本更新为 `teaching-design.v8`、`teaching-delivery.v5`。

实现接点：[tutor.rs](../../../crates/runtime/src/tutor.rs)。当前学习工作视图继续沿既有运行链进入下一次采样和内容接纳。

## 真实章节验证

按[实验协议](protocol.md)使用项目书第六章完整原文，沿生产工具、设计接纳、理解记录和交付执行。教师、独立内容接纳者和隔离模拟读者均使用 gpt-6.1-sol。教师只读真实产品请求；模拟读者只读公开交付。首条困惑及卡住、换方向、结束等情境由实验安排，具体后续表达依据实际帮助生成。

每轮的 `input-context` 保存输入前冻结上下文，`learning-trace` 从正式存储导出完整事件及学习证据。原始请求、模型响应和实际答复保存在 `conversation/`。实验侧变式与判断依据保存于 [held-out-tasks.json](held-out-tasks.json)，教师事先不可见。

前三轮形成了以下可复核关联：

| 时点 | 原话或实际帮助 | 保存的判断与后续行为 |
| --- | --- | --- |
| 原先解释 | “一条材料没进导览，后面应该就找不到它了。” | `opening-route-loss` 记录这一具体混淆，绑定 `route-retention` 关系；首份交付用同一条缓存失效条件对照导览未展示与材料仍保留 |
| 得到首份帮助后仍有断点 | 能复述两者不同，但追问“留着它为什么就有机会再找到它” | `retention-to-return-gap` 明确记录在帮助下复述、未证明独立迁移；后续支持补出保留目录、当前问题触发搜索、预览入口、取得完整材料 |
| 实验侧未提供变式 | 旧路线丁、己，新路线丁、戊、己；模拟读者判断仅凭新增戊不能证明新发现或重读原文，并提出查旧目录与实际取内容过程 | `route-change-application` 追加为新假设，绑定 `retrieval-return` 设计关系，记录已得到的帮助及局部应用边界；公开反馈确认这个例子中的连接后收束 |

首三份答复分别见[原先解释与第一份帮助](conversation/answer-01.md)、[补上找回机制](conversation/answer-02.md)、[对新判断的局部反馈](conversation/answer-03.md)。前两份实际公开讲解没有给出“路线新增项能否证明新发现”的判断；题面由实验侧提供，隔离模拟读者独立形成所提交的理由。这里观察的是在所列帮助之后处理未代答条件的行为，不是题面自发产生，也不代表无帮助掌握。

五条理解假设均保持 `nature=hypothesis`、`status=unassessed` 和 `supersedes=null`，准确的原先解释继续存在。第二条假设通过原话事实、输入时的首份帮助和随后引用该解释的教学动作连接到对应关系；第三条还直接绑定设计和关系。

第四轮读者明确改问“候选接受”与“用于主题”的关系，并要求完整直讲、不出题。教师修订设计焦点后，实际交付区分了旧接受成果、本轮完整材料交付和主题关系的新判断，以缓存失效条件说明适用边界。条件、交付记录和主题接纳规则与第六章原文相符，补充例子明确标为构造。[完整答复](conversation/answer-04.md)没有普通表达邀请。

第五轮读者准确复述刚才的解释及缓存例子，同时明确说没有拿另一条候选独立判断，并要求结束。`closing-assisted-restatement` 保存了“在这些帮助下跟随解释，独立迁移未确认”的判断。[结束答复](conversation/answer-05.md)采用同样边界，没有添加问题、练习或后续菜单。第三轮的新条件判断与第五轮对已给结论的复述，得到了不同的理解解释。

五轮均返回 200，分别保存一份真实教学交付；局部工作实际选择为 support、support、conclude、conclude、conclude。完整讲解请求可以直接完成并收束，并不需要强制先出题。工程回归同时保留了普通邀请的承接与结束路径。

[live-results.json](live-results.json)汇总原话、输入时帮助引用、设计关系、解释及实际交付。`summarize.mjs` 从正式记录回读，检查所有事实引用可解析、冻结帮助发生在对应输入之前，以及最终交付确实对应获得接纳的同一份已保存选择。五条证据及五份交付均通过这次回读；内容判断另以实际原文与公开对话核对。

| 用户轮次 | 产品链模型请求数 | 本地该轮墙钟 | 实际工作 |

完成的五轮共 45 个产品链模型请求，其中 Resident 34 次、structured 11 次。structured 包含 8 次交付接纳、1 次读者记忆意图提取和 2 次查询计划处理；8 次内容接纳均接受，不等同于 8 份公开交付。隔离模拟读者另外生成 4 条回应。完整 harness 墙钟为 1603.42 秒，包含轮间模拟读者生成与协调等待。

第二轮一次修改复用了已保存的动作身份，被服务端拒绝，改用新身份后交付。第五轮先后因沿用过大的未完整读取目标、遗漏必填 participation 被拒绝，随后提交符合当前取证范围及合同的选择完成收束。这些失败与重试全部保留，最终正文与实际接纳且保存的版本一致。

## 验证边界

最初一次首轮尝试在第 8 个模型响应因文件 JSON 格式错误失败，未交付正文，原样保存在 [conversation-transport-failure](conversation-transport-failure/turn-01.json)。执行者改为对象序列化后，从相同起点重跑成功。该失败额外发生 8 次模型请求、耗时 165.81 秒，另计于上面的成功对话之外。

首条混淆、卡住与换方向等分支是实验安排，变式题面也由实验提供；具体后续原话由只看到公开帮助的隔离模型生成。这些结果描述了生产链如何承接模拟表达与帮助条件，真人理解收益仍由切片 C 的形成性观察及后续对照判断。

模型文件通道没有 provider token 回报；主机估算值保存在结果文件中，不能用于计算真实费用。墙钟包含文件传输、执行者轮询和协调等待，不作为线上直接 API 延迟。本轮以无 BookStructure sidecar 的完整章节原文路径完成，页面帮助与普通邀请分支由工程回归覆盖。
