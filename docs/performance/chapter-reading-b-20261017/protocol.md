# 切片 B 真实多轮章阅读协议

本轮复用[切片 A 来源与模型文件通道](../chapter-reading-a-20261017/protocol.md)，沿当前生产 prepare、execute_prepared、工具、独立内容接纳、持久化和最终交付运行。材料继续使用 A 的完整第六章 fixture，规范章 LID 为 `1`；没有 BookStructure 或教学地图。教师和内容接纳者均为独立 gpt-6.1-sol，接纳者只处理 `kind=structured_completion` 的真实请求。

运行要回答的具体问题是：暂时卡住是否改变实际支持；表达能否关联到此前实际帮助和同一 design/block；明确换问题是否修订焦点；局部充分或明确结束是否得到局部收束。若出现来源错误、把未提供前提当作已会、答非所问、代答或帮助时间错配，保留原轨迹，修改对应机制并只重跑受影响路径。HTTP 200 和接纳通过不能独立证明这些内容判断。

## 输入产生与隔离

只预先写首问。每次真实 answer-NN.md / page-NN.html 保存后，由 fresh-context 的独立 gpt-6.1-sol 模拟读者依据实际可见交付写下一条表达，协调者原样提交。reader/reader-turn-NN.json 及 input-NN.json 的 `reader_provenance` 记录所看见的交付文件、当时已给的提示、输入产生方式和选择该表达的理由。顶层使用 `request` 包裹实际聊天请求，实验元数据不成为用户原话。协调者负责指定卡住、换问题和结束等情境，具体原话由隔离模拟读者形成。

读者模拟只以真实可见正文及页面为条件，不读取设计、内部工具响应、理解推断或内容审阅结论。后续原话不能预写成无论帮助是什么都会给出的标准答案。模拟器的表达是场景行为材料，不是真人学习证据。若某条故意呈现混淆或切换方向，明确记录这是实验安排，不能声称模型自主产生了该变化。

教师只取得 harness request-NNNN.json 中的实际 instructions/input/tools/tool_choice、图片等，不读本协议、模拟器指令、质量结论或实验侧任务。独立接纳者只读真实 CompletionRequest 的 system/user/schema。实验侧未提供变式的题面和判断要点另留在协调者侧，禁止塞进教师上下文；若先前交付已经给出同一判断，记录为已提示，不能算未代答应用。

## 紧凑的适应性序列

1. 首问表达“导览缩短意味着材料消失”的当前困惑，请求带读第六章。
2. 读真实首答后，呈现仍卡住的具体位置。沿实际用词指出尚不能连接的地方，不给教师指定工具或支撑答案。观察是否继续同一关系并换一种可用帮助。
3. 看过真实补充帮助后，若足以理解当前关系，给出有理由的同关系表达；若仍不充分，继续如实求助。实验侧可以在此观察一个此前未提供的变式，记录读者作答时实际拥有的帮助。该变式不通过教师来发题。结果单独报告，不注入产品为教师预设的正确回答。
4. 在已能陈述保存与选择的区别后，以真实原话转向“搜到以后凭什么采用”的问题，观察设计焦点与实际来源、帮助是否相应改变。没有此前表现的新关系只报告当前表现。
5. 依据新问题实际获得的帮助表达局部结论或剩余疑问，并明确当前想结束；观察教师是否回应这个局部结果，避免把有限表现扩大成整章掌握。需要完整讲解分支时，在尚未结束的实际问题上请求直接讲解，并按交付覆盖范围判断。

序列是要覆盖的场景，不是规定轮数。证据不足就记录不足；不通过重复同义回答制造进展。最多沿现有 harness 的 12 次用户输入，提前结束写下一条 `{"stop":true}`。

## 运行与留档

运行前清除旧的 `TEACHING_LIVE_STATE`、`TEACHING_LIVE_START_TURN`。将 `TEACHING_LIVE_BOOK_DIR` 指向 A 的 fixture，将 `TEACHING_LIVE_OUTPUT` 指向本目录下新建的 conversation 子目录，`TEACHING_LIVE_SOURCE_BASIS` 标明完整第六章来源。沿 A 的 opt-in 测试运行，编译由协调者串行安排。教师及接纳者按 A 的原子文件响应规则分别服务各自请求。

现有 turn-NN.json 保存实际交付、历史 turn、冻结 tutor、累计调用数和耗时；answer、page 保存实际可见内容。新增 input-context-NN.json 在 execute 之前保存原样输入、实际提交请求、turn_ref 与冻结 tutor，防止后来的帮助污染输入现场。learning-trace-NN.json 从正式存储分页读回该 TutorSession 的全部 teaching events 及该来源的 evidence（保留被后续修订的记录），能沿原话 fact → support_delivery_refs → design_ref/block_refs → evidence → 后续设计和动作复核。新导出只是读取既有记录，不产生理解事实。

内容报告逐次指出原话、实际帮助、设计块和判断怎样影响下一步，并单列未代答变式是否真的没有提前给出关键判断。保持模拟读者结果与真人理解收益分开。模型文件通道没有 provider token 回报；累计模型调用、实际 elapsed_ms 和可用的服务器估算如实列出，缺失实际 token 不填零。

一次首轮尝试在第八个普通模型响应因 JSON 格式错误停止，未产生公开答复或内容接纳。原样保存在 `conversation-transport-failure/`；传输执行者改用对象序列化后，在 `conversation/` 从相同起点重跑。模型调用与失败另行计入成本，不能算作教学通过。当前实际结果见[实现与验证记录](implementation.md)。
