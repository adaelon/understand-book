## 运行前冻结（2026-09-27）

v4 实测显示：即使拿到了正确的页面和表格，最终回答仍会在另写逐步解释时混淆相邻步。v5 将具体递推数列、逐步读数及算术示例集中在页面的同一可执行计算结果；readable_content 与最终摘要解释公式、边界和定性关系。用户明确请求具体数值时，再逐字引用带参数、步数、精度的已观察结果。这样仍交付数值演示，同时消除本题里独立手写的第二套数列。完整根因和 v4 失败见 [v4 记录](explorable-explanation-ex2-v4-20260927.md)。

- C 仅加载 `explorable-explanation-ex2-skill-v5.md`；B 为生产 ed3.v1。当前 EX6 共同底座、模型、采样参数、输入、质量门槛不变，tokens/墙钟继续只记录。
- 复用同底座 v4-B1，先运行 v5-C1；通过后 B2/C2/B3/C3。三次 C 通过才运行其他三题 B/C。任何 C 数值/内容错误或未交付，停止该候选并保留全部失败。v4 的失败不混入 v5 的三次分母。
- 页面数值继续按 EX0 独立闭式核对 η=0.2/0.8/1.1、边界0.5/1和实际新增参数、多步读数；页面如有绘图标签、表格、计算解释也检查。readable_content 和最终文字仍逐条检查，有任何具体计算值就加入逐字引文清单，不能因为候选要求少写数值就跳过。
- 三视口、交付、方向/幅度区别与相对 B/ED3 的具体表示收益继续作为质量条件。普通短答无固定附加回合；非数值题不虚构因果、不制作无意义动画。
- 生产 ed3.v1 保持到质量 Gate 成立。核对工具和命令沿用 v4，独立答案与校验材料不注入自然请求。

## 结果

C1 交付，12 次模型请求，828,394 tokens，355.521 秒。首三次是书内查找，仍计入成本。readable_content 不再抄写递推数列，最终回答引用的 η=1、t=6/7 和 η=0.75、t=6 读数正确，并确实出现在预览中。

但页面提供 η=0 的滑块端点，`regimeOf` 按 `abs(λ)==1` 把 λ=+1 归为“方向每步翻转、等幅来回跳”。真实浏览器将 η 设为 0 后，w3=0.00 正确，结论却仍是来回跳。`v5-browser-cases.json` 与对应 `-result.json` 保存红测。末步初稿的 k/k+1 标签错误已由模型在修订中改正，不计作最终未解决项。

v5 因受支持输入的内容错误未通过，停止 C2/C3 及其他题，生产保持 ed3.v1。原始结果保存在 `ex2-windows/v5-C1-learning-rate/`。下一候选保留单一计算来源，补齐实际可操作边界与静止状态的观察要求。
