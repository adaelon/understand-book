# 固定首稿的局部修订与证据问题承接

2026-10-29。本轮继续验证《失败的逻辑》的「这本书讲的是什么啊」，从上一轮 candidate-03 保存的同一份首稿开始，比较首次退回之后的修订过程。上一轮独立生成各自首稿的测量和失败样本仍保留在 [此前报告](../teaching-revision-20261029/README.md)。

## 实现

普通文字稿新增 `tutor.step revise`：宿主提供当前 `draft_ref` 和每段原文的编号，作者提交 `edits`，每项用 `field`、`paragraph`、`new_text` 指明原稿中需要替换的完整段落。`field` 仅允许正文 `delivery_text` 和已有邀请语 `public_prompt`；段落编号从 1 开始，由宿主提供，无须作者复抄旧文或自行计数。所有目标均从同一原稿定位，再从后向前应用，前项增删段落不会改变本批其他目标。重复目标或越界使整批不生效，错误明确指出具体项。未涉及的正文、参与方式、设计引用、来源目标和 `finish` 设置原样保留。

补读证据已足以支持原稿时，允许 `edits:[]` 原稿重审。补丁恢复为完整的原始 `select` 请求后，再经过现有参数校验、设计与来源检查，以及完整正文审核。事实通过后仍须经过独立解释审核；没有以差异检查替代全文审核。原生画板、演示页及局部画板交付继续使用各自的编辑机制，不获得普通文字补丁引用。

未解决证据和解释问题由宿主分配固定 `issue_ref`。后续审核必须用 `issue_updates` 逐一说明 `resolved` 或 `unresolved` 及其理由；漏项、重复、未知引用进入原有审核格式修复。作者修改或补读本身不能关闭问题。任何仍未解决的项继续阻止接纳，不因审查员同时写了 `accept` 而消失。新发现独立保存，旧项不因数组顺序变化而换号。

事实与解释审核分别承接自己的问题；事实退回而跳过解释审核时，旧解释问题仍保留。如果本轮由文字切换到包含页面或图像的综合审核，综合审核承接两条分支的未解决问题。问题状态限于当前回答运行，完整审核记录持久保存，未新建全局任务服务。

完整待修稿继续通过私有动态上下文提供：`editable_paragraphs` 保存各字段每段的编号和原文，`preserved_select_fields` 保存其余完整参数，正文不重复输出两遍。公开工具参数只保留修改位置，删除替换文字；审核反馈仍可为指出具体问题而引用正文。成功接纳、成功换设计、outside 或暂停后清除当前修订引用。旧引用不能修改新版本。

独立解释审核收到宿主保留的首次退回原稿 `revision_reference.text`，对照当前稿是否仍完成原有的案例、研究方法、因果连接、必要条件和组织路线。原稿仅供比较解释作用，不充当事实依据、已交付帮助或当前正文引文。事实审核仍使用当前正文与实际证据，不能让旧稿代替事实核实。

## 固定输入与计时口径

- 使用 `evals/semantic/teaching-patch-replay.mjs`，从真实正式运行入口、隔离会话和隔离记忆目录恢复记录的工具前缀。前缀中的书源读取和设计操作仍实际执行。
- 两组首稿均为 1,193 个字符，初始实际已读证据均为 19 段，确认偏好与首个事实审核的 4 条退回意见直接相等。没有重生成首稿，也没有给候选增加人工补充答案。
- 首次退回是同一份保存的审核结果；其后作者及全部接纳审核使用真实 `deepseek-v4-flash` Provider。计时从首次真实修订作者请求开始，到最终可交付答案完成；固定前缀耗时和模拟审核不计入。
- 基线是本轮修改前冻结的 `server-baseline.exe`，即上一轮最终 v3；原文匹配版是 `server-candidate.exe`，最终段落编号版是 `server-candidate-v2.exe`。两组相邻串行运行，期间不编译或运行负载测试。
- 自动 coach/profile 在两组均固定为 unavailable，以保持记录中的无 coach 修订上下文；此控制及所有失败均在实验记录中说明。
- 正文实际变化轮次、只补证重审、完整 select、局部 revise、错误、审核调用分别记录。段落原样保留仅说明改动范围，不能替代内容深度和正确性的判断。
- 这是同一案例的修订延迟对照，不是完整新问答延迟，也不是线上平均值或分位数。常驻服务尚未替换。

## 质量参照

首稿中城市降速案例、完整章节路线和系统相互关联的论述都有原书依据。首轮审核对此提出的是当时已读证据不足；不能仅靠删除这些内容把审核变快。比较最终稿时，核对城市案例的局部目标与系统反作用、摩洛模拟与简单因果被忽略的反差、复杂度与忧虑的自我强化、思维节省与副作用及时间延迟的联系、章节对决策过程的分解。

书前科维的评价被首稿称为「推荐序」，需要修正归属。「井打得太密」在这里可以理解为打井过多，不因这一口语近义表达判定整答错误；若强调空间分布致因才需另外证据。全文审核和最终人工内容复核仍需留意新引入的普遍化或因果排除推论。

## 首版实测暴露的问题

最初的原文匹配版使用 `old_text` 精确定位，复测后已取消这个未发布的接口，没有保留兼容分支。正式实测使用同一输入，顺序为 baseline-02 → candidate-02 → candidate-03 → baseline-03。

| 运行 | 修订耗时 | 真实模型调用 | 实际改正文 | 新增退回或错误 | 原样保留首稿段落 |
|---|---:|---:|---:|---|---:|
| baseline-02 | 79.670 秒 | 5 | 1 轮完整提交 | 无 | 4/15 |
| candidate-02 | 75.274 秒 | 5 | 1 轮、5 处原文替换 | 无；内容深度复核未通过 | 11/15 |
| candidate-03 | 42.796 秒后失败 | 5 | 0 轮，2 次替换均拒绝 | 两次原文定位失败，最终回答不完整 | 无新审核稿 |
| baseline-03 | 167.531 秒 | 7 | 2 轮完整提交 | 新增一条事实错误后再次修订 | 7/15 |

candidate-02 少 4.397 秒（约 5.5%），调用数和改稿轮次相同，不能据此宣称稳定提速。它虽然保留了更多段落，仍将正确的完整章节路线缩成只剩两章，系统关联的显式解释也减弱；不满足保留首稿深度的要求。4 条问题均确实进入复审并逐项关闭，这也说明清空问题列表本身不能证明深度保住。

candidate-03 两次都在第 6 项定位失败：作者引用末句少了一个「的」，前 5 项虽能匹配，整批仍按原子规则拒绝。第二次重复同一错误引用。问题不是原子性失效，而是让模型复抄长原文作为定位键不可靠，因此改为宿主段落编号，并让错误直接指明具体位置。

baseline-03 的第一次全稿重写把原稿「用计算机模拟」改成「而不是事后评论历史」，引入原稿没有的排除性错误，事实审核据书中历史案例退回。这是无关改写增加返工的直接实例。

另有 baseline-01 在首个真实请求遭遇 HTTP 400：实验夹具遗漏了原生续接信息。已从保存的原始会话恢复原生块并按 UTF-8 字节直接核对正文相等，签名不变；未生成替代推理文本。该失败单列保留，不算产品回退，也不纳入性能比较。

## 最终段落编号版实测

最终冻结版本按 baseline-04 → candidate-04 相邻运行，仍从同一份首稿、19 段已读证据、4 条首次退回意见开始。运行前的准备检查和两次正式运行均通过直接相等核对。

| 指标 | 修改前 baseline-04 | 段落编号版 candidate-04 |
|---|---:|---:|
| 首次退回后的修订总耗时 | 161.037 秒 | 118.471 秒 |
| 首个可交付答案 | 160.670 秒 | 118.058 秒 |
| 真实模型调用 | 8（作者 5、事实 2、解释 1） | 9（作者 6、事实 2、解释 1） |
| 实际正文修订 | 2 轮整稿提交 | 2 轮段落修改 |
| 固定首次退回后的再次事实退回 | 1 次 | 1 次 |
| 参数或位置错误 | 0 | 0 |
| 最终字符数 | 1,072 | 1,240 |
| 首稿原样保留段落 | 2/15 | 11/15 |
| 事实审核等待 | 107.987 秒 | 68.179 秒 |

候选第一次只替换第 2、10、12、14 段，正文从 1,193 变为 1,233 字符。第二次只替换第 12 段，变为 1,240 字符，上一版 14/15 段完全不变。两次均未重新提交整份 `select`，没有发生原文抄写或位置匹配失败。

4 条首次退回意见全部进入问题账本。第一次修订后，事实审核明确关闭其中 3 条，目录项 `factual:1:1` 继续为 `unresolved`；作者随后补读 1.107–1.113，修改第 12 段。第二次审核在同一问题编号上确认解决，最终 `open_issues=[]`。没有通过删除章节路线结束补证。

本对耗时减少 42.566 秒（26.4%），但改稿轮次未减少，真实模型调用增加 1 次，时间差主要来自事实审核等待。结论是局部修改和未解问题承接已在真实调用中生效，当前这对耗时较低；尚未证明稳定提速或调用成本降低。旧基线三次有效样本本身为 79.670、167.531、161.037 秒，也说明不能把单对差异直接作为稳定收益。

用量按唯一模型活动的最终记录求和，未发现流式累计值重复相加。基线共 1,726,634 token（缓存输入 1,285,376，未缓存输入 414,257，输出 27,001）；候选共 2,221,044 token（缓存输入 1,724,288，未缓存输入 478,103，输出 18,653）。总量包含多次请求重复携带的输入，不能当生成字数或未缓存计费量。首次真实作者请求的存档已约 1.36 MB／1.39 MB，13 条历史 system 消息约 103 万／106 万字符；历史上下文体积是后续性能工作的具体线索。本轮未修改该历史输入机制，也未核对 Provider 账单。

## 最终内容判断

独立内容复核以冻结首稿和原书为参照，判断 candidate-04 保留了核心解释深度：城市降速的局部成功与整体反作用、计算机模拟的研究方法、摩洛案例中简单因果仍被忽视的反差、复杂度和忧虑强化失败决策的反馈、思维节省与副作用及长期影响的连接均仍在。完整七章路线得到补证，保住了目标、信息和模型、时间序列、规划的组织方式。

baseline-04 是可用概述，但把章节路线缩成第六和第七章，系统关联的显式连接也有所减弱。首稿原样段落比例仅用于定位改动范围；以上判断来自实际解释内容与原书对照，不以字数或段落比例代替质量判断。

自动通过的 candidate-04 在城市案例中新增了「新开的大商城」，原书只说明附近城郊有商城，没有提供开业时间。这是轻微的无来源修饰，不影响核心因果，但仍记录为自动事实审核漏检；不能宣布自动内容零错误。原始答卷保持不变，另存一份仅删除「新开」两字的阅读稿；人工修正不计入模型成绩或测量耗时。

## 复现与代码入口

从仓库根目录执行下列命令；输出目录必须是尚不存在的新目录。模型、原始会话和来源数据来自保存的 seed，本地凭据沿原 Provider 配置读取，不写入报告。

```powershell
node evals/semantic/teaching-patch-replay.mjs --server tmp/teaching-patch-20261029/server-candidate-v2.exe --out tmp/teaching-patch-20261029/prepare-new --label candidate --prepare-only
node evals/semantic/teaching-patch-replay.mjs --server tmp/teaching-patch-20261029/server-baseline.exe --out tmp/teaching-patch-20261029/baseline-new --label baseline
node evals/semantic/teaching-patch-replay.mjs --server tmp/teaching-patch-20261029/server-candidate-v2.exe --out tmp/teaching-patch-20261029/candidate-new --label candidate
```

- `crates/runtime/src/teaching_revision.rs`：原稿引用、宿主段落编号、同版原子修改与完整请求恢复。
- `crates/runtime/src/teaching_review_issues.rs`：稳定问题编号、分支承接与审核关闭。
- `crates/runtime/src/orchestrator.rs`：修订操作进入原选择链路，保存首个被退回的真实原稿，绑定完整审核与生命周期。
- `crates/runtime/src/tutor_review_input.rs` 和审核规则：事实与解释各自输入投影，原稿只供解释作用比较。
- `crates/runtime/src/teaching_patch_tests.rs`、工具合同测试及以上模块单测：真实运行循环、完整字段保留、补证与未解问题测试。
