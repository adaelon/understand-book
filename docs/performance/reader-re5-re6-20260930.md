# RE5–RE6 专注阅读、伴读层次与 PDF 表面

日期：2026-09-30。基线为实时工作树，HEAD `5e10516`，保留既有 RE1–RE4、MU8 及其他未提交成果。合同：[ADR-0148](../adr/0148-reader-typography-annotations-and-motion.md)、[RE 方案](../切片方案-阅读体验排版批注与动效.md)。本次实现未提交。

## 实现

RE5 在桌面顶部、窄屏顶部及横屏紧凑导航提供专注阅读。进入时保存原设备呈现、前景和目录开合，明确切到正文；退出恢复原选择。专注期间仍可打开目录、问答、笔记及辅助标签。目录长标题允许换行，当前章节带 `aria-current`；目录、伴读标签和工具采用暖灰背景、珊瑚色状态与统一边线。目录展开将键盘焦点交给搜索，Escape 关闭并返回目录入口。

`ReaderWorkspace.toggleFocus` 只改变原显示投影，Reader、RightRail 和演示 iframe 保持实例。完整 `workspaceContextKey` 变化时清理临时专注返回状态；正式 slot、布局提议和 revision 继续由原控制面持有。显示切换前 App 保存 LID、来源字符与视口偏移；连续显示切换复用同一锚点，用户交互、新导航或现场改变后重新捕获，避免窄栏往返时行首变化累积成读位漂移。

RE6 将 PDF 适宽按钮与 75%–250% 的倍率选择分开，倍率相对于适宽。增大工具触控区域，协调页边、页间距、背景和纸页阴影，批注和翻译采用同一配色。阅读表面选择使用独立工具行，避免覆盖 PDF 标题和工具，并说明正文字体设置用于重排正文。

切出 PDF 时，App 保存原来源身份、页内位置、水平位置与倍率；切回后由 `PdfReaderPane.initialReadingAnchor` 在原版加载完成时恢复。现场变化清理缓存，新导航或用户交互取消初始恢复。文档加载代次与页面渲染代次分开，容器变化只使几何失效，切源与卸载仍使旧文档失效。PDF.js 画布和文字层继续使用原缩放路径，选区、标注与来源映射保持原规则。

## 修正与已知限制

- 修正了 1024px 窄栏专注往返的来源字符漂移、WebKit 目录按钮不自动聚焦导致 Escape 丢失，以及容器变化取消未完成 PDF 加载的问题。加载/渲染代次分离有新增延迟加载组件测试。
- 更新过期测试接点：移动选择读取真实文本后代、阅读按钮使用精确名称，PDF 提问夹具监听当前 `/agent/runs`。双栏 PDF.js 的正文与公式合并在行 span 中，矩形断言使用实际行。
- 日志保留调试期失败。最终 WebKit 合组中两项 PDF 首次加载在并行构建期间超时，停止构建后同版本独立重跑 2/2 通过，未扩大超时或降低页内恢复断言。表格按最终通过记录计数。
- Windows Tauri 安装包、真实 Linux Nginx/TLS、实体 iPhone、真实长书及复杂图表长期试读仍归 RE7/MU10–MU11。Windows 上的 WebKit 和短 PDF 夹具不替代这些验收。
- 保留现有 Vite 大 chunk 和 happy-dom/KaTeX quirks 提示。本次未部署现网、迁移生产资料或调用付费模型。
