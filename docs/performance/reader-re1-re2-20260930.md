# RE1–RE2 正文排版与阅读设置

日期：2026-09-30。基线：实时工作树，HEAD `5e10516`；沿现有 MU8 的 `NetworkApp → App → ReaderPane` 集成。

## 实现

RE1 的正文采用本地分发 Noto Serif SC，清晰黑体采用 Noto Sans SC。正文默认 19px、1.85 行高、36em 版心和 1.2em 段距；窄屏保留字号、两侧各 20px。章/节标题使用同一家族的 600 字重。中文字符使用透明样式 span 控制字距，原文字符不变；拉丁字串保持自然间距，代码沿等宽字体，数学沿 KaTeX。来源预览消费同一排版变量，工具和 PDF 原版文字层不使用正文样式。

RE2 从顶部“阅读设置”进入原生模态面板；手机从页面菜单进入。书页、技术、紧凑预设直接赋值，字体、语言排版、字号、行高、中文字距、版心显示实际参数。英文模式从 18px / 1.70 起步。当前 manifest 没有可消费的明确文档语言字段，默认中文/混排，读者可在面板切换。

`network-context.readerPreferenceOwner` 提供网络用户或与 Server `LOCAL_USER_ID` 相同的本地 `local` 身份。`useReaderTypography` 将显示参数保存到当前用户的本设备 localStorage；换用户时同步清除旧内存状态、错误和面板。存储失败仍应用设置，并显示“未能在本设备记住”。不会写 Memory、布局命令或重建 workspace。

`ReaderPane.captureScrollAnchor` 在视线探针附近保存 LID、规范正文 UTF-16 字符范围、原字符和视口偏移。`reader-text-anchor` 使用原有 DOM/source map 双向映射；重排和来源返回均可恢复段内位置，代码/图片/公式保留段落锚点。原生选择与冻结引用不因排版重新推断。

重排复用 `createReadingContinuity` 的恢复代次，同时核对完整 `workspaceContextKey`（MU 用户生命周期、workspace、generation、PublishedBookRef、书与会话）。所选字体加载就绪后才应用新正文排版；拖选或 composition 期间延后。滚轮、按键、拖动、实际滚动、显式定位、切场景和卸载取消旧恢复。字号和版心不逐帧动画。

## 字体来源与分发

| 字体 | 固定包版本 / 上游元数据 | 可变字重 | Vite 产物 |
| --- | --- | --- | --- |
| Noto Serif SC | `@fontsource-variable/noto-serif-sc@5.3.0` / Google Fonts v35，2026-01-07 | 200–900；正文 400、标题 600 | 100 个 WOFF2 分片，6,025,576 字节 |
| Noto Sans SC | `@fontsource-variable/noto-sans-sc@5.3.0` / Google Fonts v40，2026-01-07 | 100–900；正文 400、标题 600 | 98 个 WOFF2 分片，4,507,216 字节 |

来源：[Noto Serif SC](https://fontsource.org/fonts/noto-serif-sc/about)、[Noto Sans SC](https://fontsource.org/fonts/noto-sans-sc/about)。两者为 SIL OFL 1.1，完整许可随应用放在 `public/fonts/`。Fontsource CSS 携带完整发布子集的 unicode-range：简体中文、拉丁、扩展拉丁、越南文与西里尔文；保留发布包全部分片，不按当前书籍裁剪字形。emoji 继续使用系统 emoji 字体。构建总计增加约 10.04 MiB 字体资源，浏览器只请求当前文字需要的分片。

[实际字形证据](reader-re1-re2/rendered-fonts.json) 来自 Chromium `CSS.getPlatformFontsForNode`：两种正文均使用 `isCustomFont: true` 的 Noto SC，代码为 Consolas，emoji 为 Segoe UI Emoji。变量字体内部名称中的 ExtraLight / Thin 是字体内部名称，CSS 使用的实际字重为 400 / 600。

## 已知问题与限制

- 本片完成实现与本地浏览器集成验收；Windows Tauri 打包入口、真实 Linux Nginx/TLS、实体 iPhone 和真实长时间阅读舒适度尚待 RE7/MU10–MU11。Windows 上 Playwright WebKit 不是 iPhone 验收。
- 本次使用已有短材料夹具与固定混排长段；真实长篇书籍的长期试读仍需用户验收。字体字形覆盖遵循所选 SC 字体发布范围，不承诺所有罕用汉字或其他文字。
- 生产资源约增加 10.04 MiB；现有 Vite 大 chunk 提示与 happy-dom 的 KaTeX quirks 提示保留。设备间不自动同步显示偏好。
- 初轮新增测试修正了 happy-dom 环境声明、存储异常注入对象及 select 的可访问名称；首轮 MU 测试误读未复制完的新构建，等待构建复制完成后两引擎通过。
- RE3–RE7 未在本片实现；正文笔记卡仍沿原有呈现。未部署或重启现网。
