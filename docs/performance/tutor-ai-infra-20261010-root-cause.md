## 结论

吞吐低的主要原因是动作粒度与控制路径成本不匹配：每次搜索翻页、单对象 inspect、单段 read 都成为一个独立生成任务；每次回读又重建教学任务并回放已有动作。三分支整轮合并进一步降低名额利用率。全量上下文随每个微动作重复持久化，导致磁盘持续增长，并最终在冻结下一个任务时再次 ENOSPC。

另外存在一次已完成命令未被主控及时取走的 73 分钟停顿。这一停顿独立于引擎实际执行时间，现有记录不能确定其宿主或网络层原因。

## 原因与代码依据

### 1. 搜索分页成为昂贵的独立任务

`agents/formal-objects-extractor.md:19` 要求每次 invocation 只提交一个动作；同文件要求广泛搜索、跟随 next_offset。实际运行未带 prepared retrieval，进入 `teaching-object-alignment.ts:189` 的旧关键词路径：空白分词、任一词命中整个对象 JSON 即入选，按原顺序每页 6 条，未按相关度排序。

最新轮次三个分支的 23 个已写动作中，21 个为 search、1 个 read、1 个 inspect。查询实例分别可命中 262、245（随后改写查询缩到 36）、101 个对象，对应 44、41（6）、17 页。分页 offset 递增，没有发现同 query+offset 重复提交；本问题是翻页成本与召回范围过大，不能误称为无限重复同一页。

上一完整轮次三个对象分别用了 6、11、12 个动作，共 29 个动作才完成 3 次 resolve。全窗口 search 占 56/83，约 67.5%。本窗口不是被耗尽后的补读路径主导。

### 2. 每次回读重建并回放累积状态

`teaching-build.ts:311` 每次从 fragment 回执建立 newObjectAlignment；`routeParallelAlignment` 从 batch=0、step=0 重走历史。`accepted`（126 行）读回执、校验后再次调用 advanceObjectAlignment；`makeTask`（153 行）重新渲染与构造 descriptor；`stageState`（169 行）再逐项调用 accepted。`build-orchestrator.ts:3032` 的教学任务局部读取也进入该路由。

因此确认一个新动作并非轻量增量查询，成本随既有动作数量增长。64 次回读累计约 206.6 分钟，单次中位数 190 秒，是已有真实命令记录，不是估计的模型耗时。未做新的 CPU profile，不能把全部 206.6 分钟进一步归到某一个内部函数。

### 3. 三路上限没有形成持续三路吞吐

`routeParallelAlignment` 选择 3 个 focus；任一分支 pending 时，在 254 行返回，直到全部完成才合并并进入下一批。上一轮快分支在 14:47:52 写入 resolve，慢分支到 15:56:44 才结束，快分支约 69 分钟无法推进新 focus。

此外，当前 Build skill 要求回读期间晚到的终止通知在新派发前再次经 refill 消费。记录中有 26 次连续回读之间没有新 spawn，后一次命令执行累计 78.7 分钟。它们保障现行归属协议正确，但把生命周期记账再次绑定到了昂贵的语义路由。应在引擎内降低该路径成本，不能简单在 root 跳过通知或复用终止执行器。

### 4. 全量上下文重复落盘并耗尽空间

`makeTask` 把完整 source、structure 和 alignment 放进每个任务；`freezeTeachingTask`（84 行）同时保存不可变 task 与 current writer context；`acceptTeachingCandidate`（456 行）又把整个 next alignment 连同 accepted_action 存入回执。

## 修复优先级

1. 先恢复可持续的磁盘余量，并消除每动作重复保存全书 source / 全量 ledger 的写放大；复用现有版本与依赖身份，保留不可变证据和必要的当前状态，不删除接纳回执来掩盖问题。
2. 将教学路由变成基于已接纳进度的增量推进。常态只消费新增动作；恢复时从已保存且可验证的进度接续。把生命周期名额更新与昂贵的全历史回放解耦，避免同批晚到通知导致又做一遍重建。
3. 调整对象对齐的工作粒度，使 search / inspect / read 能在一次持续的对象处理过程内推进；或先批量提供有界候选和必要展开材料，减少每 6 条候选启动一次完整任务。保留语义判断和原文依据要求。
4. 让已完成分支尽早合并并补入新的独立 focus，继续沿用实际依赖冲突判定；减少整轮屏障。检索按意义、别名与相关度提供候选，广泛查证仍可继续，不靠武断截断条数换取完成。

优先验证同一段真实工作能否避免反复全量回放、同等语义决策所需派发数能否下降、每动作新增字节是否摆脱全书大小。当前日志已经足够说明重试和只提高并发上限不能解决主要问题；无需再跑整书构建来重复证明。
