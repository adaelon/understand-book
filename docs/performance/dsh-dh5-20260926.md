## 实现合同

- `ub_build_prepare_and_confirm` 接受 `max_parallel=1..3`，默认 1。准备与读取新用 V2，计划投影显示准确并发，invocation 保存该上限；旧 V1 保持封闭字段。
- `live` 以 dispatch slot 为索引，结合随机 launch 身份和原 handoff 对照；同 slot 的旧 terminal 不能删除 replacement。每个新 child 使用专用 preset、四工具、独占 stdio。
- Engine 返回的重复 active dispatch 被识别为当前 owned slot。任意 child 完成并清理后推进 Engine，消费已到达的其他终态后补位。一次调用按 handoff 启动数预留余量，到限额后等待所有 owned child 收尾。
- 原生 spawn 没有空闲配额 API；取实测三并发上限，扣除实际 Agent 注册表和插件在途创建占用，再与计划上限和本调用余量取交集。控制结果标明 `agent_registry_conservative`。
- `dsh_build_controller.v1` 在既有 Engine registry 内保存前台 controller 的 PID/启动身份。活动 PID 或无法证明死亡时拒绝另一个 controller；旧 controller 的 release 不能删除 replacement。同一插件实例重叠调用返回 `build_already_running`。
- 不同 invocation 的接手核对当前工作区实际 lease 与原 invocation 的 dispatch 所有权。外部 owner 仍持有 lease 时返回 `WAIT/active_lease`，不发行新 child；原 owner 完成后可复用接纳成果。
- `dsh_executor_observation.v1` 保存 launch、slot、handoff、真实 MCP 调用次数、最后操作、原 Engine 诊断和观察到的回执；缺失调用证据为 null。记录不含正文、candidate、模型 final 或任意异常文字。
- 只有已记录的连接准备零调用失败和精确 open 拒绝进入既有 bootstrap 恢复。运行时、上下文/模型漂移、连接未知、候选 retry 和取消保持分类。Engine 已提交后 child 崩溃同时保留 committed 与 runtime 事实。
- NEEDS_USER 到达后停止补位，收尾所有 child、上报所有观察，再重读当前请求。取消/卸载取消全部 owned 工作并等候清理；一项 cleanup 失败不跳过兄弟 child。

## 本轮发现与修复

1. 原 DSH invocation 固定单并发。三执行器红测先失败，现支持 1–3 并保留确认上限。
2. 原 bootstrap 恢复只接受公共 V4。DSH V5 复用同一恢复规则，新 ref 保持同一 slot，不制造语义失败。
3. 用户边界需要显式停止补位并收尾；测试在收尾期间多次修改计划，最终返回最新 request。
4. 已收到 committed 后模型崩溃仍需保留宿主故障。现在观察同时保留 DONE 回执和 runtime 结果，Engine 继续复用成果。
5. 新 invocation 原可重放外部 owner 的活动 dispatch。新增测试在 Codex lease 活动时得到 SPAWN（红）；修复后返回 WAIT，原 owner 提交后 DSH 从下一阶段继续。修复限定 DSH 接手入口，旧 Codex 协议保持。

跨宿主夹具最初使用空 nodes，实际被既有质量门拒绝；夹具改为有证据的有效 claim 后验收，质量门未修改。红测日志保留。

## 故障矩阵对应

- T18：提交落盘后丢响应；继续原 invocation 后不再生成 Pass1。
- T19：两/三并发均在最慢 child 完成前补位。
- T20：旧 launch 无法调用/释放同 slot 新 child；旧 controller release 无法移除 replacement。
- T21/T35：边界期间收尾并保存所有观察，随后重读漂移的请求。旧答案拒绝由既有 driver 回归覆盖。
- T22：三 child 的取消、卸载及清理失败隔离；实际 Agent 与独占 MCP 进程清理。
- T23/T27：活跃 PID 保持阻塞；可证明已退出的 PID 可恢复；同 invocation 排他；跨 invocation 活动 lease 不重放。
- T24：停止旧 Codex 工作后用新 DSH invocation 接手，Pass1 产物复用、旧 handoff 字节保持。
- 其余已有确定性合同与负例沿用 DH1–DH4 的证据，并以本轮受影响回归核对。T30 的正式安装包验证属于 DH6。

## 已知限制

- DH0 仍缺人类“要求修改”一次真实操作。计划全文显示通过组合仍为官方包加本地 SidebarRight 修复。
- DH6 的可分发安装包、脱离源码运行、真实模型完整标准计划、Desktop 整体重启与升级/回滚未验收。此轮不宣布首版正式支持。
- 模型与材料均为合成确定性夹具，真实模型质量和吞吐不在本轮证据内。单 claim 的 Pass2 开启样例没有跨段配对，Engine 关闭无任务阶段。
- 正文和 candidate 可能保存在宿主 child 日志；父上下文隔离不等于宿主日志不落盘。CLI/自定义 composition 的全局压缩策略仍需单独验证。
