# 2026-10-24 局部追问与理解历程

## 目标与基线

局部追问按实际所需工作作答和审核，后台指导与理解观察不阻塞当前回答或下一轮。用户原表达及时保存；有信息的理解表达可靠生成可修正观察，保留输入前实际帮助。我的理解显示原表达时间及同一关系的变化历史，更正旧解读与后来新理解分开。补回原 AI Infra 会话中遗漏的 prefill/decode 复述。

正式基线为 `output-budget-20261024`。同材料连续两轮：首轮 180.50 秒，第二轮 330.69 秒；第二轮前置教练等待约 29 秒，9 次主模型约 126 秒、3 次审核约 175 秒。原始证据在 [上一轮验收](../output-budget-20261024/README.md)。本次修改前工作区源快照在 `tmp/followup-understanding-release-20261024/before`，不将有未提交修改的 Git HEAD 当作完整部署身份。

## 实现边界

- 不增加单独的复杂度分类模型或按字数/关键词分类。当前原话、实际拟答、所需证据与操作决定处理范围；需要补读或深入处理时继续执行。
- 当前回答经过事实、来源与问题覆盖审核；缩小无关材料和附加输出，审核自身格式错误在审核内部修复。合理输出额度与费用约束保持。
- 后台任务独立于前台开跑条件，有限并发并保留费用控制。观察使用冻结的原话、表达前帮助和实际原文；已记录事实复用，无法解释的保留待处理。
- 时间线按表达发生顺序，后台晚写入不冒充新表达。历史事实保留，当前有效解释与更正状态可辨；模型只取当前问题相关的关键历史。

## 验收

必要回归覆盖非阻塞调度、理解补记和去重、异步乱序、更正与新观察、局部审核及安全终止。实际页面检查手机与桌面时间线、分页与返回原会话。真实验收沿用原两问，比较耗时和模型往返，同时检查答案、来源、理解原话/帮助及后台结算。部署前验证候选与生产数据兼容，备份后切换；发布后确认网站和回填结果。

## 实现结果

- 首次正常采样直接决定局部作答、补读或更多工作；已接受目标的位置可授权重新读取，但不会冒充本轮已读证据。纯文字使用 `text-delivery.v1` 审核，保留当前请求、拟答、原话、帮助和实际原文；本次新页面/媒体继续完整审核。审核格式错误内部修正一次，`select.finish=true` 只在已审且当前请求全部操作完成后直接交付。
- HTTP 运行不等待指导生成，采用已就绪且适用的指导；前后台模型并发分开，后台单槽且新请求让位于前台等待者。后台在原有持久任务中逐条返回 recorded / existing / no_new_information，不把回答当作学习者表现。
- 新的 `support_delivery_refs` 保存普通讲解/补救交付，保留原类型；正式活动帮助仍使用 `assistance_refs`。真实反馈沿原 assessment 引用读取，显式跨聊天引用按已冻结原事实验证。历史观察与后续指导的有效性分别处理。
- `observe-understanding` 维护入口只排队历史观察，正常后台按同一校验链处理；显式 `--retry-failed` 恢复 Failed/Interrupted，保存原尝试和费用，重复 Ready 请求不新增调用。
- 理解总览按原表达时间排序，同一可靠关系的历史从早到晚展示。更正旧误读与后来新表达分开；模型获得有限相关历史及时间。打开的理解页每 10 秒检查新记录水位，离开或浏览器转后台时取消，不替换正在编辑的详情。
