# 已知原文位置批量读取试验

## 范围与判据

用户在 dsh-ops 调研后确认“可以的，你试试吧”。本片为 Resident 增加一次读取多个已知原文区间的能力，比较读取轮次和真实模型用量；不修改 MCP / REST 的单段合同，不开启全局并行调度，不部署。

术语沿用 CONTEXT 中的 LID、本轮证据账本、历史 Tool 回执和 Agent 请求计划。批量只是多个既有读取的组织方式，不引入新的证据类型。每个区间仍须通过当前轮定位授权；只将输出预算后实际送给模型的原文入账。

1. 保存当前源码构建的基线服务，增加 `book.text_batch(ranges: TextInput[1..8])`，按首次顺序去除完全相同的请求。
2. 逐项复用原文读取、投影、证据验证；预算不足时输出可执行续读，验证非连续区间、长首段、重复文字、零预算和未定位端点。
3. 用隔离本地服务运行相同已知位置问题，保留供应商 usage、模型活动、工具活动和来源解析结果；结果中区分受控路径与自然模型选择。

### §1.1 批量读取入口

**决策**：在 Resident 增加有界批量原文工具。

**否决**：
- 全局开启并行工具：改变写操作入口且部分模型不支持。
- 扩大共享单段输入：会牵连 MCP 记次、来源包装及 REST 标量路由。

**命门**：先投影再入账，遗漏内容保留续读位置。

## 受控调用对照

固定三段相同正文、三个可解析引用与相同答复行为，只改变读取组织方式。结果来自 [controlled.json](controlled.json)，请求体字节是请求序列化大小，不是供应商 token。

| 读取组织 | 模型采样次数 | 所有请求体字节之和 | 有效引用 |
| --- | ---: | ---: | ---: |
| 三次单段、每轮读一段 | 5 | 169,115 | 3 |
| 同一轮发出三个单段请求 | 3 | 98,543 | 3 |
| 同一轮一个批量请求 | 3 | 97,179 | 3 |

批量相对逐轮读取少两轮；相对已经合并在同一采样的单段请求，轮次相同，请求体减少约 1.4%。该对照在同一候选 Runtime 中执行，用来分离调用组织的影响；不包含真实模型的工具选择、分词、缓存与额外推理变化。

## 真实模型对照方法

`evals/semantic/book-text-batch-trial.mjs` 对修改前、修改后的独立服务分别运行 `cross-01`、`cross-02`、`exact-02`，每题每版一次，共六题。均使用当前配置的 `deepseek-v4-flash`、同一 `quantification-essence` 书籍来源、相同问题和已知 LID 提示，不强制选择批量工具，不重跑挑选结果，不使用付费评分模型。

供应商用量从保存的模型活动读取；推理 token 已包含在输出内，缓存命中 token 已包含在输入内，均不重复相加。缺失字段保持未知，同时提供已报告用量下界。引文逐条沿正式来源解析核对；回答核心事实由人工阅读保存答案和规范引文判断。原始记录位于 [results](results/)，检查说明位于 [manual-review.json](results/manual-review.json)。

## 真实模型结果与判断

| 问题 | 原版总 token | 批量版总 token | 变化 | 模型活动数（原→新） | 时间（原→新） |
| --- | ---: | ---: | --- | --- | --- |
| AlphaGPT 奖励与因子次数 N | 未知；已报告至少 95,556 | 43,201 | 不计算缺失总量的降幅 | 7 → 3 | 72.1s → 14.5s |
| 标签熵与相对排序损失 | 131,364 | 187,503 | **+42.7%** | 7 → 8 | 80.9s → 66.6s |
| 过拟合与数据隔离 | 64,779 | 63,481 | −2.0% | 4 → 4 | 19.4s → 22.4s |

第一题首轮自主选择批量读取，没有像原版一样再做额外 `book.query`；两项核心事实都得到正确支持。第二题也选择批量读取，工具调用从 20 次降到 15 次，但随后拆为多轮补交引用，一次改写公式被 `SOURCE_NOT_OBSERVED` 拒绝，最终模型活动和总输入增加。第三题首轮单读，后续自主扩展至三个邻近位置时用了批量，因此不是完全不使用批量的控制组。

三题候选核心事实均正确，最终来源分别为 2/2、10/10、2/2 可解析且引文匹配。原版对应为 4/4、10/10、2/2；第二题原版开头有一句“同一个分子的两种写法”与后文分母解释冲突，原回答和人工记录均保留。

| 问题 | 候选输入 token | 候选输出 token | 候选缓存命中输入 | 首轮输入增加 |
| --- | ---: | ---: | ---: | ---: |
| AlphaGPT 与 N | 41,282 | 1,919 | 16,256 | 413 |
| 标签熵与排序 | 176,654 | 10,849 | 160,384 | 413 |
| 过拟合隔离 | 60,209 | 3,272 | 49,664 | 409 |

完整原版/候选用量、缓存和工具记录见 [comparison.json](results/comparison.json)。新增工具与指导使这三次首轮输入增加 409–413 token。收益必须来自减少后续模型往返或重复读取，不能仅靠减少工具调用条数推断。

**判断**：有界批量读取能够保持来源证据正确，且逐轮读取场景确有收益；本次自然工具选择的对照未证明整体 token 稳定下降。实现和复现材料保留为本地试验，本片不作生产发布。后续更值得单独验证的是多个来源引用一次提交、避免反复补引文与多余取证，而不是继续扩大批量上限。

## 已知限制

- 每题每版只有一个样本，缓存状态和模型自主路径不同，不能当作普遍节省比例；token 总量也不等于费用或响应时长。
- 原版第一题有一次嵌套模型服务错误且缺少该调用的 usage，全量未知；已报告的下界没有被当作完整总量。
- 本地历史未持久化观测端补写的 `accepted_evidence_count`，该字段保持未知。引用解析证明最终引用有效，不能替代缺失的账本观测指标；账本行为由相关运行时测试验证。
- 既有工作区包含其他未提交改动；基线与候选由同一当前工作区在本片编辑前后构建，本次未提交、未部署。
