# 第三轮两稿盲审与审核驱动修订

后续第一轮的“回答自足”规则对照、作者修订和页面实测见 [第一轮自足规则验证](q1-self-contained-review.md)。实验组修正了三处局部问题，但仍未补齐目标机制。

2026-10-18。本次冻结 `teaching-delivery.v12` 与 `plain-explanation.v1`，使用实际配置的 `deepseek-v4-flash`，服务返回的模型名为 `deepseek-flash`。原稿被要求修改，上一轮改写稿获得接受；主模型仅依据原稿的实际审核反馈修改一次，复审接受了修改稿。

这次闭环修正了开场表达，但没有解决此前关注的依据与层次问题。修改稿仍从“已有字段被截取”推到了“与原文的差别主要在短和字段选择”；初审和复审都没有将这一步推论列为缺陷。以下先记录模型实际输出，再说明实验结束后的判断。后者没有进入任何模型请求。

## 冻结与隔离

- 审核 system 逐字等于生产审核规则原文、两个换行和共享写作规约原文；调用中途没有改规则。冻结文件见 [review-system.md](../../../tmp/tutor-three-turn-20261018/blind-q3-review/review-system.md)。
- 两次初审分别使用独立上下文，仅 `proposed_delivery.text` 不同。保留同一份真实当前问题、上一条粒度／LID 问题、冻结用户输入、四段已读原文及引用映射。
- 旧教师回答、页面、设计、审核、纠错记录和工作状态没有进入初审。来源身份和文本沿用原记录，没有加入新来源或标准答案。
- 原稿与改写稿正文逐字保留，包括各自的引用标记情况。随机编号只用于本地文件管理，候选来源映射不发送给模型。两份实际请求在去掉正文后直接比较相等。
- 每份稿件最多初审一次；有效 `revise` 才触发作者一次及复审一次。`accept` 不安排修订。本次没有重试或重采样。

审核、作者都沿用原请求的参数：`temperature=0`、`max_tokens=32768`、JSON 输出、流式响应。作者 system 使用冻结的共享写作规约和通用修订任务，未加入本题答案或人工诊断。

原稿初审指出第一句的“更像投影，不是改写”用标签对立开场，替换了用户所问的比较，且未先定义“投影”。它仍认为用户所问关系已得到回答，并未要求补查已有字段怎样从原文形成。

给主模型的反馈来自运行时对实际审核结果的归一处理，原样使用生产前缀加 `normalized_review.revision`，没有人工转述。反馈中的具体要求是：

> 删去“更像 X，不是 Y”的标签对立开场；先用具体操作说明进入向量计算的是准备阶段从含义／条件／别名（或章节问题／概览）中选出的短文本，再说明“投影”指这段用于向量计算的短文本。若保留“不是改写”，应放在截取前缀的操作之后，由该操作支持，而不是作为开场定性。

完整反馈保存在 [作者实际请求](../../../tmp/tutor-three-turn-20261018/blind-q3-review/case-e5d9ddfe-author-request.json)。作者保留问题、来源和当前草稿，只增加上述真实反馈；没有拿到另一份候选稿。

主模型将开头改为：

> 对。进入 embedding 的是准备阶段从候选的「含义／条件／别名」或章节的「问题／概览」中选出的短文本，整章正文没有直接进入这段向量输入。

随后定义“投影”为这段用于向量计算的短文本。原有来源标记得到保留。完整正文见 [审核驱动的修改稿](../../../tmp/tutor-three-turn-20261018/blind-q3-review/case-e5d9ddfe-author-answer.md)。

复审收到相同规则、相同事实来源、实际修改稿，以及这一个案例真实的上次意见和修改前后正文。它认为标签对立已经删除、术语已经定义，并接受修改稿。[原稿初审](../../../tmp/tutor-three-turn-20261018/blind-q3-review/case-e5d9ddfe-response.json)、[改写稿初审](../../../tmp/tutor-three-turn-20261018/blind-q3-review/case-ffd7f16c-response.json)、[修改稿复审](../../../tmp/tutor-three-turn-20261018/blind-q3-review/case-e5d9ddfe-r2-response.json) 均保存了完整公开输出。

## 仍未解决的具体问题

审核驱动的修改稿保留了这段话：

> 按这段说明，操作是把已有字段截取前若干码点；来源没有说它会换一种说法重写字段内容，它与原文的差别主要在「短」和「只留指定字段」。

所给四段来源说明了检索视图使用哪些已有字段、候选投影如何截取字段前缀、完整字段如何保留，以及准备结果如何复用。它们没有说明这些字段怎样由原文形成。因此，“截取已有字段”只能解释字段到向量输入的这一步，不能支持随后对向量输入与原文全部差别的概括。

初审给出的修订方向允许将“不是改写”移到截取操作之后，未要求核对这个比较的层次。主模型按这一方向修改后保留了上述概括，复审又予以接受。这是本次实际发生的漏检，不能用最终 `accept` 宣布核心问题已解决。

已经得到的证据是：冻结规则在这一对稿件上能区分开场表达，实际反馈能促成对应修正。尚未得到的证据是：审核能够独立发现必要依据的缺口，并驱动主模型补齐或撤回缺乏依据的结论。后续需要改进的是审核对“所引来源究竟支持哪一步推论”的判断；本次按冻结协议结束，没有继续改规则或再给模型补充诊断。

## 已知限制

这是正文与审核反馈的受控模型实验。作者使用同一实际配置模型、共享规约和生产归一反馈，没有运行完整主教师工具循环，也没有新增来源查询、写入应用记忆、重放演示页或重启服务。程序验证保证输出合同、引文出处与规则接入，不能证明语义正确。

本次只测试第三轮的两份既有稿件，各调用一次；不能据此估计稳定检出率，也不能推断第一轮、第二轮或其他问题已经修复。上一轮改写稿沿用其原始引用缺失和中英文术语混用，初审未提出这些事项；本次没有据此把它改成应用内成品。
