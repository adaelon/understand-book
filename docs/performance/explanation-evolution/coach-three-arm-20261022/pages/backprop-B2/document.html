一个中间量被用两次，反向传播怎么不漏算？

u = x·y 被两个地方用到：一次进入 v = u + x，一次直接进入 L = v² + 3u。下面用 x = 2、y = 3 把前向值算出来，再从 L 出发往回走，看两份贡献在哪汇合、为什么相加，以及漏掉一份会差多少。

先给结论：u 被用了两次，就会收到两份贡献——一份沿 v 回来（2v·1），一份从 L 的 3u 项直接回来（3）。两份在 u 处相加，得到的一个和才继续传回 x 和 y。x 同样被用了两次（进 u、直接进 v），也同样收到两份。漏掉任何一份，输入梯度就会少一项，而这一项还会被后面的局部导数放大。

先把这个小模型摆清楚

四个量、三条运算，全部是实数：

  • 中间量u = x·y
  • 中间量v = u + x
  • 输出L = v² + 3u

u 出现两次：一次在 v 里，一次在 L 的 3u 项里。x 也出现两次：一次进入 u，一次直接加进 v。这两处“被用两次”，就是后面要分辨的全部来源。

术语约定：图上节点里是前向数值；边上写的是这条边自己的局部导数（把这条边单独拿出来看的变化率）；节点上方或下方的 ∂L/∂· 是最终对 L 的导数（把所有路径加起来的结果）。后面把 ∂L/∂u 简写成 gu，读法不变。

前向：一步一步算出数值

每次只用已经算好的量，顺序就是箭头指的方向。

u 只在第 1 行算了一次。后面第 2、3 行都直接用这个 u 的数值，没有重算——这正是“同一个中间量被用两次”的具体含义。

反向：从 L 出发，逆着箭头走

反向要按逆拓扑序走：一个量的梯度，得等所有用到它的地方的贡献都到齐，才能定下来继续往回传。所以顺序是 L → v → u（两份到齐）→ x、y。

每条边只做两件事

第一，读出这条边自己的局部导数；第二，把上游传来的梯度乘上它，得到这条边送给目标节点的一份贡献。节点把自己收到的所有贡献加起来，得到自己的梯度。

注意区分两处 ∂L/∂u：边上的 ∂L/∂u = 3 是“只经过 3u 这一条边”的偏导；节点上的 ∂L/∂u = 16 + 3 才是“所有路径加起来”的总导数。汇合就是把后者凑齐的动作。

为什么回来的两份要相加

单链是连乘。一旦一个量被两个地方用到，从 L 到同一个输入就有好几条路径；每条路径各自连乘，再把终点相同的结果相加。相加了才等于“总共变化多快”。

用一次小扰动看两条渠道

把 u 增加 Δu，其他都不动。L 会从两条渠道同时变化：v² 这一项因为 v 跟着变大，3u 这一项直接变大。

三行都满足：合计 = ∂L/∂u · Δu + Δu²。最后那一项随 Δu 变小得更快，所以“导数”取的是每单位变化的一阶部分；两条渠道的一阶变化率相加，正好就是 ∂L/∂u。

三句话收住

顺序。一个量的梯度，要等所有用到它的地方的贡献都到齐才能定下来，这就是反向按逆拓扑序走的原因。

相加。收到几份贡献就加几次；加完之后，继续往回传的只是这一个和，不再分成几份。

漏算。漏一份就是漏一条路径，而且这一项会被后面的局部导数放大，所以错的会一路传到输入，不只是中间量上的数变小。

默认例子对一遍：u 处 16 + 3 = 19，x 处 57 + 16 = 73，y 处 38。展开求导得到同样的 73 和 38。
