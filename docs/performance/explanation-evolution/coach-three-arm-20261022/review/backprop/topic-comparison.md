# 共享节点反向传播：五页匿名比较

这五页中，没有一页在数学解释、阅读路径、实际交互和移动适配上都明确全面领先。**Oak 对本题核心难点——共享节点如何汇总、相消与零贡献如何理解——解释得最稳；Birch 的逐步操作和窄屏阅读路径更顺手；Maple 对“一阶变化率为什么相加”的精确扰动展示最具体。**它们各有明确的优点和仍会影响理解的问题。

Pine 和 Cedar 也完整覆盖了默认例子，并提供了正确的计算。Pine 的两张账本便于直接看贡献来源；Cedar 的可切换漏算实验很有用。但两页都存在会改变读者数学理解的解释错误，Cedar 还有明确的回传箭头方向问题。因此，我不会把它们的完整解释当作当前最可靠的选择。

这是对初次交付页面的用户视角观察，未进行真实学习者测试，不推断学习增益。计划中的另一个位置没有页面交付，未参与评估和比较。

## 共同的事实基础

五页都通过真实 Reader iframe 阅读和操作，均检查了完整默认阅读路径、前后步及改输入后的状态、960×720、320×420、640×240 三种窗口。Pine、Cedar、Birch、Oak、Maple 各完成以下六组输入：

| 输入 x, y | 前向 u, v, L | 梯度 g_v, g_u, g_x, g_y |
|---|---|---|
| 2, 3 | 6, 8, 82 | 16, 19, 73, 38 |
| -1, 2 | -2, -3, 3 | -6, -3, -12, 3 |
| 2, -1 | -2, 0, -6 | 0, 3, -3, 6 |
| 0, 2 | 0, 0, 0 | 0, 3, 6, 0 |
| 0, 0 | 0, 0, 0 | 0, 3, 0, 0 |
| 1, -2.5 | -2.5, -1.5, -5.25 | -3, 0, -3, 0 |

**30 组指定终态的核心数值全部正确，五页的独立求导结果也都吻合。**另对 Birch 补测 x=2、y=-2.5，专门核对其负号解释，数值仍正确。各页差异主要落在如何解释这些数、如何呈现当前步骤，以及读者怎样在页面中找到对应证据。

## 数学解释：Oak 更稳，Maple 的扰动展示有独特价值

**Oak 最清楚地连接了两种层次：完整路径与节点收到的直接贡献。**它列出 x 的三条完整路径和 y 的两条完整路径，再将经过 u 的路径重新分组。这解释了为什么 u 先收 3 和 16，x 后收 57 和 16，既没有漏算，也没有把同一路算两次。账本明确区分“还没收到”“暂记，还差一笔”“到齐”，能直接回答用户最初的顺序疑问。

Oak 对特殊输入也给出了正确含义。相消时，它明确写出 g_u=3+2v=0，解释 x→u、y→u 的贡献因为传入梯度为 0 而消失，并保留 x→v 的 -3；v=0 时，它承认某些漏算在当次数值上不会暴露。这些是本题的关键区别。其不足是路径重组正文仍混入未标明的默认 19、73，以及结尾又把“漏算一定得到错数”说得过于绝对。详细账本和条件解释比这些残留句子可靠。

**Maple 的强项是把“为什么相加”变成可核对的小扰动计算。**它同时列出经 v 的精确变化、经 3u 的变化、总变化、一阶项和 Δu² 余项。相消状态下，表中一阶项为 0，而总变化仍有平方余项。这比单纯列出导数之和更直接地解释了局部变化率。它还逐项展开多项式求导，并列出完整路径再重组，证据充分。

Maple 的问题也正好落在零与状态解释上：全零输入下出现“∂L/∂x=0，不是0”；漏算对照的零差值正确，旁边却仍概括所有输入梯度都错。说明总导数的段落固定写 16+3，未随当前输入改变。它的计算展示很好，但不能将所有配套文字直接视为正确解释。

**Birch 的主线明确，负数概括不可靠。**它展示共享 u、x 的直达路径、局部导数和回传乘积，并逐步记录当前已算出的内容。默认例子和相消数值都能读通。但它说 y 为负时 u 支路给 x 的贡献也为负；实测 x=2、y=-2.5 时，传入 g_u=-3 与局部导数 -2.5 相乘得到 +7.5，直接反驳这句话。其漏算段“一定变小”也不适用于负贡献或零贡献。

**Pine 的两张账本是清楚的，局部导数与整体敏感度的概括有错误。**u 账本和 x 账本分别列来源、乘法和合计，配合微小增量解释，默认读起来相当直接。但“局部导数为负意味着 L 减小”不成立；负号还要与传入梯度相乘。v=0 时，漏算卡又声称两种漏算值都与正确值不同，实际上遗漏零直达贡献后数值相同。这会干扰用户理解零贡献的含义。

**Cedar 的解释材料完整，但核心表述与图形存在冲突。**它先把三类数字分清，后面还有正确的漏算切换和逐项展开；然而“正确”模式的说明把 u 的总梯度 19 也分配给 x→v，照文字计算会得到 76，而图和表给出正确的 73。它还把贡献符号和零值完全归因于局部导数，忽略传入梯度。

Cedar 的回传图示是另一处独立问题：它把虚线明说成回传边，却在计算 v 梯度时画 v→L、在 u 汇合时画 u→L 和 u→v。Maple 保留前向箭头并明确要求读者逆着箭头走，这种表示本身可以成立；Cedar 对虚线的说明使同方向箭头成为信息流误导，不能只当作画图风格差异。

## 阅读路径：完整静态阅读与逐步操作有不同取舍

五页都提供了不操作也能读完整默认例子的材料，没有哪页只能靠一张符号图理解。

Pine 的图、当前步卡和两张账本组织紧凑，读者容易从当前解释转到贡献分解。正文后面又完整讲一遍依赖、相加和独立核对，内容有所重复，但这并不妨碍默认例子成立。

Cedar 先解释术语，再进入工作台，最后展开完整推导与自检，顺序清楚。图下面分列前向值、局部导数和累计结果，适合逐类查看；其问题主要是内容正确性，而不是缺少可读路径。

Birch 把当前步说明、当前已算记录和结果放得较近。它还明确说明初始处在全部算完的状态、重放怎样开始、改输入会保留当前步。对希望边操作边看发生了什么的读者，这条路径更容易跟上。

Oak 的全文讲解最像一段完整推导：十三步逐条讲，再给账本、路径和展开式。完整读一遍时顺序清楚；按步操作时却需要来回滚动。实际点击到第 9 步，在 960×720 视口里，u 汇合的正文位置仍在视口下方约 1900 像素，账本约 2294 像素；320×420 下更远。它能改变状态，但控制面板附近只显示步骤名称，无法同时读到该步算术。

Maple 的当前步解释紧邻前后步按钮，主要计算区又各自标当前输入，便于核对。它的表格多，全文阅读更细；这些表格承担了不同工作：前向代入、反向贡献、扰动余项、完整路径、漏算和独立展开，不能仅因篇幅长就视为重复。重放的便利性稍弱：要回起点需连续按上一步，复位按钮回到默认完整结果。

## 交互：核心状态都能更新，差别在解释与状态是否一致

五页都能调整 x、y，前后步也能操作。没有观察到核心数值停留在旧输入的情况。特殊输入下的问题主要是说明文字不成立，或夹杂默认值，不能归因于计算没有重算。

- **Birch** 的当前记录和部分贡献标记让步骤状态最容易追踪。较轻的问题是第 10 步已算出 y 收到 38，节点和结果栏仍显示 ?，下一步才显示最终值。
- **Pine** 有明确的未到齐状态，但第 12 步文字提前说两个输入梯度都齐了，图中 y 仍为 ?；早期核对卡也把尚未显示在图中的最终值称为“图上”结果。
- **Oak** 的部分账本与到齐状态清楚，步骤滑杆便于跳转；操作和解释位置分离是其主要交互成本。
- **Cedar** 可分别漏掉 u 的两种贡献；**Maple** 可切换漏掉 3u，并把正确值、漏算值和差值并列。这两种实验的实际数值都正确，且能展示局部误差怎样传到输入。Cedar 的错误总梯度说明、Maple 的全零说明则与正确对照值冲突。

## 移动适配：Birch 最直接，Maple 的保留图形方案可用

**Birch 的 320×420 阅读最直接。**它用注明方向的边列表替代宽图，保留每条边的局部导数、回传值和最终梯度，正文与步骤记录正常换行。它牺牲了同时看到完整拓扑的视觉概览，但没有牺牲具体计算的可读性。

**Maple 保留了图，并提供明确的横向滑动提示。**实际从左侧移动到右侧后，v、L 都可查看；详细表格变成带字段名的卡片，信息没有挤成难辨的小列。它需要横向查看图，纵向卡片也较长，但操作路径明确。

**Oak 的图比较简单，节点值和短局部因子仍可辨，账本和步骤卡能够竖向阅读。**它在窄屏上的主要负担仍是控制面板与当前解释的长距离分离，而非控件被遮挡。

**Pine 和 Cedar 都把图整体缩小，导数标签偏小。**Pine 的账本与正文仍可读，长公式能横向滚动；Cedar 的展开对照表还有左列表达式被挤成每行少数字符的问题。两页都能操作，但图上区分节点值、局部导数与总梯度需要更多费力辨认。

在 640×240 下，五页的步进按钮均可到达、可点击，没有发现固定层遮住按钮的阻断。

## 选择判断

如果任务是**先读一份最能准确解释共享节点、汇合时机、相消与漏算例外的完整内容**，我会优先选择 Oak，同时把其未更新的默认数字和结尾概括视为待修正文。

如果任务是**主要在手机上逐步操作，持续看清当前算到了哪里**，Birch 的呈现方式更合适；它的负数解释和数学显示仍需修正，不能因为交互顺畅就略过这些错误。

如果任务是**特别想弄懂“两路变化为何相加”与一阶近似的含义**，Maple 的精确扰动表和逐项展开最有参考价值，但全零状态文案和默认数字残留影响了完整解释的一致性。

这形成明确取舍，尚不足以认定某一页全面更好。Pine 的简洁账本、Cedar 的双分支漏算实验也有可取之处；它们当前的关键解释错误使其不适合直接承担最可靠主讲页面的角色。
