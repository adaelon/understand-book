# river 匿名教学页独立评审

评审先独立检查 river，最后才与此前独立检查的 stone 比较。证据仅来自 blind/alarm/river 的截图、可见正文/控件记录，以及 index.html 在真实 allow-scripts iframe 中的渲染。实际以960×720、320×720阅读、滚动、点击按钮和调整滑块；未读取页面源码、项目源码、runs、其他评审或分组映射。页面未被修改。

river 已具备不操作也能读完的讲解，动态四格与概率计算成立，零报警也没有误写成0%。开头用两个解释卡片分别确定“缺陷件”与“报警件”的分母，随后把全批四格、全批条带和报警内部条带联系起来，主线明确。正文仍有一处明确的倍数错误，以及一处承诺存在但实际没有的预设入口。

**成立的表达与交互**

- 第一节只比较两个共享95件分子的比例，没有把误报率的495件混入。卡片分别写“分母：有缺陷的100件”和“分母：报警的590件”，再展示95÷100与95÷590。句子、群体、分式三者对应，适合百分比入门者。
- 静态分母表还单独列出缺陷率、检出率、漏检率、误报率、报警可信度。动态四格在行头、列合计再次注明所对应的分母，读者可把同一个95在两种分母之间追踪。
- 图中先用一条表示10000件全批的四类份额，再用另一条专门表示590件报警的内部构成。默认报警条约16.1%绿色、83.9%红色，与“95件正确报警、495件误报”的紧邻文字一致。两条分别标明集合，归一化后的宽度变化有解释。
- 缺陷率下降的正文给出95变19、495变499、590变518、16.1%变3.7%，并保持d/f固定；它准确把可信度下降归因于报警构成变化。提高d与降低f也分别列出漏检和误报变化。
- p=0时，模型滑块仍保留d=95%，但“缺陷件中报警的比例”卡片显示“—，本批无从核对”；报警可信度则依据是否有误报显示0%或无定义。这比只展示一个“0”更能避免空集合与有定义的0%混淆。
- 参数可以直接用滑块独立改动。预设会切换整组基准值：例如先点f降到1%，再点d提到99%，实际为p1/d99/f5。此处上方写“换成下面几组参数核对”，下方也列出按顺序切换各组时的194、594等结果，因此有整组情景的语境，不把它当成计算错误。给按钮补齐整组p/d/f会更直接。

**具体问题**

1. **第七节的“两百多倍”是明确的数量错误。** 原句：“‘误报率5%’的分母是无缺陷的9900件，算出来是495件误报。要问‘报警里有多少是误报’，分母换成590件报警件，答案是495÷590≈83.9%。两个5%之间隔着两百多倍的件数差距和完全不同的人群。”前面比较的实际是5%与83.9%，而且描述的是同一批495件；不存在两百多倍的件数差距。即使按标题把“报警里5%”当作另一个假设，其数量是590×5%=29.5件，495/29.5约16.8倍；若指下一段漏检5件与误报495件，则是99倍。这个倍数没有成立的对应对象，应删除或重写为准确的分母区别。证据：960-text-ratio-error.png保留了完整第七节及邻近段落。

2. **第八节说0%与100%两种情况可用两组预设直接调出，实际没有100%的预设。** 该段先讲p=0、f>0得到0%，再讲f=0且p/d>0得到100%，紧接着说“页面上两组预设按钮可以直接把这两种情形调出来看”。实际可见的六个按钮为初始值、缺陷率降到0.2%、误报率降到1%、检出率提到99%、一件都不报警、全部是误报；其中“一件都不报警”得到的是无定义，不能当作100%。通过滑块把默认f降为0确实正确显示100%，因此问题是入口说明与实际控件不符。将该句改为正确的滑块操作说明即可，不必为了文字承诺扩大功能。证据：960-text-ratio-error.png、初始DOM按钮清单和behavior-cases.json的all-alerts-correct。

**显示限制与实际阅读路径**

960宽度下两个比例卡片并排，全批条带、两种比例与报警内部条带相距较近，视线能从四格合计下移到报警的重新分组。没有一整屏的大画布隔断两种分母。证据：960-default-graph.png。

320宽度下解释卡片改成纵向，两张卡都保留完整分母、语言解释和分式，不必横移才能看到关键分母。比例卡与报警条也仍能完整阅读；无报警的长解释会自然加高，并未被裁切。证据：320-two-fractions.png、320-proportions.png、320-no-alert.png。页面整体宽度为320，没有整体横向溢出。

表格则通过压窄单元格、断行来适配。默认总计10000被断成“1000”与“0”两行；低p情景的9490.5被断成“9490.”与“5”。这些都是数字内部断行，增加逐项算账时的辨认负担。下方图例能完整写9490.5，数字本身也未改变，但核心四格不宜要求初学者重新拼接小数。可给数字保留不换行、调整列宽或在窄屏改用完整四格卡片。证据：320-four-cells.png、320-fractional-cells.png。分母汇总表全列可见，部分名称和说明断行多，仍能读出对应关系。

正常滑块刻度p0.1%、d95%、f0.5%产生49.95、9940.05、59.45，页面显示50、9940、59.5，且分式写9.5÷59.5。显示的16.0%与精确期望一致，因此这里只认定有限显示精度且未说明近似；不认定算式或分母选择错误。如果想让读者直接拿四格核算，可保留本控件能产生的两位小数，或明确数量展示的近似规则。证据：960-small-decimals.png。

完整故事可以不操作读完。读者的默认推导路径是：先看到100与590作为两个分母的结论，经过比率汇总和交互区，第三节才看到10000如何一步步得到这两个数。它可读，但入门者需要暂时接受590的来源，之后再回到前面核对；把第三节默认计算更早接到首组卡片后面，会令第一次阅读更连贯。

**验证边界**

“数字、图、文字一致”基于可观察的数值与条带变化，没有读取实现，也没有宣称内部数据来源。比例条视觉宽度只作常规可视核对，没有像素级计量。未执行线上或付费操作。

**与stone的具体比较（完成river独立判断后）**

river把两个条件概率放进各自完整的解释卡片，320下也保留分母与分式；stone开头直接给出16.1%的默认答案，接着先算四格再交互，数字来源的叙事顺序更顺。river用短条带接连表达全批与报警子集，视觉联系比stone的大面积浅灰方格更紧；stone额外列出多档p和多档d/f对照表，读者不操作也能横向看趋势。

两页的核心动态算术与无报警处理均成立。stone有“三行分子都是95件”的身份错误；river避免了这个错误，却在第七节引入没有依据的“两百多倍”。river的0%/100%预设入口说明另有不符。两页都有有限小数精度展示；river的整组预设语境比stone明确，但其按钮也会重置未在名称中列出的参数。

窄屏上，stone采用表内横向滚动，核心分母首次藏在右侧；river让表格全列留在视窗中，却拆开了10000与9490.5等数字。river前置的解释卡片减少了对拥挤表格的依赖，stone较宽的横向表格则在滚动后保留了数字整体。两者需要处理的阅读断点不同，不宜只凭页面长度或是否首屏出现图来判断。
