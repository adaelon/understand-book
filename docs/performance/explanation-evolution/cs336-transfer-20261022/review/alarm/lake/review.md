# lake 匿名教学页独立评审

本次先独立阅读lake，再进行关键状态操作，最后仅凭此前已完成的观察作简短比较。证据限于blind/alarm/lake的可见正文/控件记录、截图和index.html真实allow-scripts iframe。实际检查960×720与320×720，未读源码、runs、其他评审或分组映射，未改页面或其他协作者文件。

四格数量与报警可信度的主计算正确，低基率小数和两种无报警状态也正确。页面以四格的列与行解释不同分母，这条阅读主线有效，手机布局完整。但是正文中的百分数符号、部分固定标签、空缺陷集合的检出率结果，以及“只把”按钮的行为存在直接矛盾，影响了把交互当作教学核对工具的可靠性。

**独立预期与关键实际状态**

四格依次为正确报警、漏检、误报、正确放行。

|---|---|---|---|
| 1/95/5 | 95 / 5 / 495 / 9405 | 590；16.1017% | 正确，显示16.1% |
| 0.1/95/5 | 9.5 / 0.5 / 499.5 / 9490.5 | 509；1.8664% | 正确，显示1.87% |
| 1/95/1 | 95 / 5 / 99 / 9801 | 194；48.9691% | 正确，显示49% |

| 0/95/0 | 0 / 0 / 0 / 10000 | 0；未定义 | 正确，显示0÷0未定义 |
| 1/0/0 | 0 / 100 / 0 / 9900 | 0；未定义 | 正确，漏检100保留 |
| 0/95/5 | 0 / 0 / 500 / 9500 | 500；0% | 主矩阵及可信度正确 |

behavior-cases.json保存了各状态的完整可见正文与输入值，包括错误发生时的文字，不能把此表的“主计算正确”等同于整页文字正确。

**有效的表达**

初始表把“有缺陷/无缺陷”设为列、“报警/不报警”设为行，并直接把d、f、可信度的分母标到列头和行头。随后解释“前两行沿列数、可信度横着数”，让分母转换有一个可追踪的位置。三个比率默认时的95÷100、495÷9900、95÷590均正确。

全批分段和报警子集分段分别标出总数，图例同时写件数。默认的95/495与16.1%/83.9%能对应；低p时半件期望被保留；无报警时报警条为空，显示“随手拿不到一件报了警的零件”，说明这个条件集合不存在，表达贴近入门者。

第七节明确说提高d会让正确报警与全部报警同步增加，降低f只减少误报，避免把提高d说成只影响分子。它还按当前参数计算各改一个百分点的局部变化；默认d增加1个百分点多1件正确报警，f减少1个百分点少99件误报，具体而且可核算。p=0/f=0时局部计算也显示0→0、未定义→未定义，并说明f已无下降空间。

**直接可复现的问题**

1. **p=0时，检出率表把0÷0的“结果”列成95%。** 点“没有缺陷也不误报”或“没有缺陷但仍误报5%”，第二节第一行显示“检出率d；算式0÷0；结果95%”。该节还写“右边的分数就是每个比例的出处”。在无报警状态，同一张表的可信度行则正确把0÷0写为未定义。模型设定的d可以继续保持95%，但不能把它写成这批0÷0所得的结果；应区分“检测器参数95%”与“本批没有缺陷件，无法从本批数量计算检出比例”。证据：960-p0-rate-denominators.png；behavior-cases.json的p0-f0、p0-f5。

2. **按钮明确写“只把”，实际覆盖其他参数。** 点“缺陷更少的批次”后为p0.1/d95/f5；再点“只把误报降到1%”，p被恢复为1%，变成p1/d95/f1。若真只改f，应保留p0.1，得到正确报警9.5、误报99.9、报警109.4、可信度约8.68%；实际展示的是95、99、194和49%。继续点“只把检出率拉满”，f又从1%恢复5%。若只改d，预期p1/d100/f1应为199件报警、可信度约50.25%；实际p1/d100/f5为595件、16.8%，甚至会给人“提高检出率使可信度降低”的错误因果印象。建议真正只修改指定参数，或去掉“只把”，清楚标为整组基准情景。证据：960-only-button-before.png、960-only-button-after.png及对应状态输出。

3. **误报率说明中的5%固定不变，参与计算的数字却随当前f变化。** 点“只把误报降到1%”后，第四节仍显示“误报率5%：99÷9900”，而该分式是1%；同卡片底部又正确写“1%之所以这么小”。在无报警预设f0时还会变成“误报率5%：0÷10000”。这不是静态默认例子，因为其中的99、9900、194、51%等均为当前状态数据。应让文字中的率同步更新，或把整段明确冻结为完整的默认例子。证据：960-f1-text-mismatch.png、320-no-alert.png。

4. **p=0、f=5%的静态例子把报警数写成495，正确值是500。** 第八节明确写“如果p是0%但f还是5%……报警会来495件……分母495”。10000件此时全为无缺陷件，10000×5%=500。点击对应预设后，同一节开头正确显示“当前有500件报警”，几行后仍说495，出现页面内部直接矛盾。把这段的495改成500即可；0%与未定义的概念区分本身正确。证据：960-500-versus-495.png。

5. **首次教算法时，p与d/f使用了不一致的百分数约定。** 当前值写p=1%、d=95%、f=5%，但公式是“有缺陷件=10000÷100×p=100件”，下一行却直接写“正确报警=有缺陷件×d=95件”。若p按所写的1%代入，前式得到1件；若把p当作百分数前的数字1，d与f同样按数字95、5代入又不成立。应统一以比例代入（10000×p，p=1%），或每个率都按百分数值除100，最好直接展示10000×1%=100、100×95%=95等明确数值替换。主矩阵算对，问题在教给读者的书面算法可能引出100倍错误。证据：提供的960-first.png、320-four-cells-and-formulas.png。

**实际阅读与交互路径**

默认故事按“四格→三个分母→全批条→报警子集条→控制参数→解释基率变化和两种改进→零报警”展开，完整内容不依赖操作。960宽度下行列标记清晰，比例图的标题和图例足够具体。

320宽度的三张表均宽292px，全部列留在视窗内，无整页横向溢出；默认10000、低p的9490.5等主要数量完整，不需横向寻找分母，也未把长数字拆成两行。比例表中的分式和说明允许合理折行，数值仍可辨认。两条图及图例也能顺序读完。证据：320-four-cells-and-formulas.png、320-low-p-four-cells.png、320-denominators.png、320-alert-graph.png。

控件放在主要四格和图的下方，操作后的主要反馈发生在上方。读者点按钮后需要回滚才能再次看到第一张四格与主要可信度图，控件附近没有并列的当前可信度读数。第七节的当前参数局部比较在控件下方，是另一种反馈，但不替代主要结果的直接可见性。这是交互阅读路径的摩擦，不是要求全篇或所有控件挤进一屏。证据：320-controls.png、提供的960初始DOM各节位置。

**验证边界**

只根据公开控件和可见结果判断，没有检查实现。已覆盖默认、低基率小数、降低f、提高d、两种无报警、全误报与连续按钮操作。未为显示舍入额外扩展检查，也未进行线上操作或模型调用。

**与此前页面的简短整体比较**

lake的行列方向解释最具体：它把每个率的分母直接接到四格的行头/列头，并解释横向与纵向如何换分母；320下表格也比stone的隐藏右侧列、river和dune的数字内部断行更好读。它把控制区放在图表之后，需要回滚看效果；前几页把控件与其下方结果集中得更明显。

四页关键四格和报警可信度主计算均成立，无报警主结果均能正确区别未定义和0%。各自的正文问题不同：stone说三行分子同为95，river引入无依据的两百多倍，dune把人群至少9倍用于过宽的误报多数推论；lake则在更大范围动态更新正文时留下5%固定标签和0÷0得95%的分母矛盾，另有495/500与百分数记号错误。

这些页面的预设都会切换基准参数，river附近有“换成几组参数”的明确语境；dune“减半”容易被理解为当前值操作；lake的“只把”更明确承诺单参数改变，实测又覆盖其他参数，因此这处行为与文案的冲突尤其直接。比较不依赖组别，也不把页面长短或图是否出现在首屏当作质量结论。
