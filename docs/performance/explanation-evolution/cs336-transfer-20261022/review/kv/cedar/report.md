## 确认发现

### P2 — “T 压到上限”会把可容纳配置推成超量，且无法输入所有合法整数长度

复现：初始参数 → 加一条序列（B=5、T=8192、s=2）→ T 压到上限。

预期：T=floor(196608/(5×2))=19660，KV=12,884,377,600 字节，总需求比 24 GiB 少 524,288 字节，应可容纳。用户应能选择任务约定的 0..32768 整数长度。

实际：T 变为 19712；KV=12,918,456,320 字节，总占用 24.031 GiB，提示“装不下：差 0.031 GiB”，但同屏仍写“T 上限 19660 token”。再按此按钮仍是 19712。键盘 Home 后 ArrowRight 从 0 到 128，控件没有数字输入途径，无法到 1、19660 或 19661。因而用户不能用页面自身按钮落在其计算的安全上限，也不能观察只多一个 token 的容量边界。

证据：nondivisible-controls.png、nondivisible-result.png、mobile-controls.png、mobile-result.png；observations.json 中 B5-nondivisible-cap、B5-cap-second、mobile-nondivisible-cap。宽屏重复两次，窄屏重复一次；Home→ArrowRight 重复两次均到 128。置信度高。范围：非 128 倍数的合法 T，特别是不能被步长表达的容量上限；B=4,s=2 的整除上限正常。

### P2 — 正文把“每层全部头”的 2048 个元素说成“每层每头”

复现：阅读第五节“长度翻倍时，哪些量翻倍？”第二段。

预期：每个 token、每层、每个缓存头，K 与 V 合计 2×128=256 个元素；8 个头合计 2048。头维度应与前文乘法解释一致。

实际可见原文：“不翻倍的是权重 10 GiB、其他开销 2 GiB、每个 token 的 131 072 字节、每层每头的 2048 个元素。”它把所有 8 个头的总数当作每个头，错了 8 倍，直接混淆目标读者需要理解的数组维度。前文第二节及交互计算使用的是正确总数，不抵消这里的错误陈述。

证据：head-elements-prose.png；visible-lesson.txt。首次完整正文读取与稍后截图均确认同一句；置信度高，属于静态讲解错误，未观察到它改变计算器数值。

### P3 — 容量图说明把 24 GiB 红线右侧说成剩余空间，与图中溢出区相反

复现：阅读默认容量图下说明；再点击“最挤的一组”。

预期：默认未使用的 8 GiB 在已用部分之后、24 GiB 红线之前；最大溢出时红线右侧代表超出容量的 116 GiB。

实际说明始终写：“红色竖线是 24 GiB 上限，线右侧的浅色空白是还没用到的余量。”默认图中红线在最右端，浅色空白在它左侧；最大配置中红线右侧是橙色斜纹溢出区，却继续沿用这句说明。图形、图例和数值本身能正确区分余量与溢出，但这句读图指引指反了方向，给新读者相互冲突的解释。

证据：冻结截图 960-scroll-3.png（默认）；maximum-graph.png（最大溢出）；observations.json 的 default 与 maximum-overflow。两种状态均确认；置信度高，范围是容量图的说明文字。

## 已验证且正确

独立推算：每 token 元素数=32×8×128×2=65536；KV 字节=B×T×65536×s；固定12 GiB；容量约束 B×T×s≤196608。

- 默认 (4,8192,2)：KV 4 GiB，总16 GiB，余8 GiB，单序列1 GiB，每 token 131072字节，上限24576。
- 加一条 (5,8192,2)：KV5 GiB、总17 GiB，增量1 GiB。
- 默认 T 翻倍：(4,16384,2) KV8 GiB、总20 GiB，固定项不翻倍。
- s=1 与 s=4 切换：缓存按比例变，权重10 GiB与其他2 GiB保持固定。
- T=0：缓存0、总12 GiB、余12 GiB；单序列增量0。
- (4,24576,2)：KV12 GiB、总24 GiB，明确“恰好装满，算装得下”。
- (16,32768,4)：KV128 GiB、总140 GiB、超116 GiB；图中斜纹区与数值一致；T上限3072。
- (1,32768,1)：KV2 GiB、总14 GiB、余10 GiB，正确说明显存可196608但控件长度上限32768先到。
- 最大值时继续点加一条/长度翻倍，控件保持B=16、T=32768。
- 刷新回到默认4/8192/2；无持久化要求，因此没有将重置判为缺陷。
- 完整正文能连续阅读；960与320宽度截图及实测中未见横向溢出，320页面 scrollWidth=clientWidth=320，表格、按钮和结果卡能换行阅读。文章较长本身不构成问题。
