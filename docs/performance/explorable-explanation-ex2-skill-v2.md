---

Presentation method (ex2.v2, explorable-explanation):
Choose the smallest explanation that makes the reader's missing relationship visible. Before authoring, decide within the current turn: Obstacle — what difference, mechanism, or boundary is not yet understood? Objects — which things must keep their identity across views or time? Change — which comparison, transformation, or sequence would reveal the relationship? Interaction — which reader action would test understanding, if any? Do not add a page, animation, or control when prose or a static visual answers the question.

Select zero or more explanation moves for the obstacle, not a fixed layout: object-continuity keeps an entity recognizable; progressive-reveal limits simultaneous information; transform shows A becoming B; compare-in-motion distinguishes similar endpoints with different paths; parameter-sweep varies one input; trace-ghost retains meaningful prior states; invariant-highlight marks what stays fixed; viewpoint-change changes representation or coordinate system; counterexample exposes a false generalization; prediction-reveal asks before showing the result; decompose-recompose separates parts then reconnects them; concrete-to-abstract moves from a specific case to a rule. Combine only moves that help the current question. Use Understand Book's existing visual language; these method names are not user-facing labels.

Make one primary view for the target relationship, adding a second view or table only when it reveals a different necessary fact. Avoid galleries of examples, duplicate charts, and long prose that repeat the same mechanism. Keep the page compact enough to inspect and revise within the authoring budget. Design formulas and controls for narrow touch screens before the first preview so the required three viewports can be checked without avoidable rewrites.

For continuous change, keep object identity stable and distinguish real semantic steps from visual interpolation. Make pause, replay, parameter changes, saved state, and visible results agree when the page needs them. If the same point can be shown with a table, static comparison, or discrete steps, use that simpler form. Preserve the user's question and verified source material; label assumptions and the scope of simplified examples.

After real preview, check whether the chosen representation exposes the intended difference, whether numbers and text agree, and whether all required viewports remain usable. Revise the representation when a correct-running page still hides the relationship. Follow the authoring tool's source, state, version, preview, and delivery contract.
