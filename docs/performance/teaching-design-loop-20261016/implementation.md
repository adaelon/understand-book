2026-10-16，用户批准实现。工作树已有大量其他改动；本次开始前的相关文件保存于 `baseline/`，用于区别本次增量。

2026-10-17 后续：已补充正常默认模式下、不由用户安排教学步骤的多轮验证，并修复同轮理解证据不能及时刷新当前模型视图的问题。新结果、七轮逐字对话、独立语义审阅和本轮回归见[自主教学验证与理解视图修复](autonomous-evaluation.md)。下文保留原 `sol-live-03` 阶段的结果；两组实验不合并为同一次运行。

## 已实现的闭环

沿用 Resident 与私人教学事件：保存并消费教学设计、最终动作集合、普通表达邀请、输入时的帮助条件、基于用户原话的反馈关联。演示页复用同一邀请与现场收据，用区域关联说明正在观察的关系。没有新增固定课程阶段或掌握分数。

1. **先形成可消费的设计。** `TeachingDesign` 保存当前要建立的关系、认知积木、积木间连接、原文依据、正在处理的问题与返回位置。`tutor.step(design)` 接受后，设计必须进入下一次模型请求，才允许选择教学动作或制作演示。设计可以沿用，也可以根据用户表达修订；不规定讲解、提问、演示的顺序。
2. **把普通表达接回主会话。** `response_expectation` 提供自然的邀请，`responds_to` 关联真实用户表达和原邀请。用户可以说理解、求助、请求完整讲解或暂缓。正文已包含邀请时只显示一次，观察实际邀请段落的曝光。
3. **按实际交付推进。** 运行结果持久化最终选定的动作集合；只选择过、被替换掉、运行中断的内容不会打开邀请或关闭旧问题。教学设计与最终呈现分开保存。
4. **根据原话修订判断。** 私人学习证据保留用户表达、输入发生时已看到的帮助、涉及的积木及修订关系。界面按钮文案、未修改的演示预填文字不算用户解释；修改过预填文字仍保留辅助来源。针对性反馈关联被回应的事实，允许撤回已被新表达推翻的旧判断。
5. **演示作为同一段教学的观察现场。** 页面绑定同一个设计和积木，区域声明可观察关系与状态字段。实际页面快照随表达保存，区域定位不改变实验参数。页面与聊天共享邀请；页面不可用时仍能在聊天接续。显示提示或完整解释时，页面等待帮助展示记录保存，再允许后续表达沿用这份帮助条件。

主要实现位置：`crates/memory/src/teaching_design.rs`、`crates/server/src/teaching/design.rs`、`crates/server/src/teaching/page_help.rs`、`crates/runtime/src/tutor.rs`、`crates/runtime/src/tutor_continuation.rs`、`packages/web/src/components/TutorActivities.vue`、`packages/web/src/presentation-bridge.js`。

## 方法原则如何落到系统中

参考文章中的驱动问题、认知连接、主动表达、具体进展和学习接续，分别落到设计的目标与问题依据、积木关系、普通表达邀请、基于原话的判断更新、保存的返回位置。反馈关注用户哪条连接需要修正，解释提供搭建这条连接的材料。系统支持先示范、直接讲清或暂缓，不把每一轮都做成测验。

## 验证方式

- `teaching_design_live_tests.rs` 提供文件传输的 ModelAdapter：每次模型调用把真实运行请求交给 gpt-6.1-sol 子代理，返回它自主选择的工具调用或回答；工具、来源检查、事件与最终交付均走实际应用循环。没有固定工具序列，也没有预先注入工具读取结果。
- 多轮场景先用文字检查误解纠正、部分正确的承接、直接讲解与跨轮接续，再观察生成演示页中的同一关系。原始请求、回答、工具结果和页面保存在本目录的独立运行目录，不覆盖以往 TB 验证材料。
- 对页面的验证会使用生成的真实页面内容和生产版 document/bridge，在 Chromium 中操作控件，保存真实快照，再经实际服务器保存接口生成后续对话的现场收据。反馈必须能解释这份操作后的画面。

## 七轮实际结果

`sol-live-03` 完整完成七轮、44 次模型请求。一个 gpt-6.1-sol 子代理承担实际教师生成，另一个同模型子代理独立审阅实际用户表达、回答和页面，没有用工具调用成功代替教学判断。

| 情境 | 实际生成行为 |
|---|---|
| 用户被多个名词绕晕 | 以一份材料库、两种选材用途组织关系，配同一甲乙丙例子 |
| 把章节采用误当成主题采用的前置许可 | 保留正确的材料库/主干关系，只修“本章采用清单=全局可用清单”的错误连接 |
| 用户重新表述正确 | 引用用户的新例子确认局部正确，修订旧误解判断，没有强制追问 |
| 请求可操作演示 | 同一卡片显示保留、章节采用、主题采用、最终收录，只切换当前组合 |
| 操作后误认为最终收录会回写章节采用 | 对照真实保存的 A={甲}、T={乙}、最终{甲乙}，解释汇总不会改写上游决定 |
| 明确要求直接讲解 | 从乙卡三行标记提供具体判断入口，没有再出题 |
| 新聊天回忆 | 引用之前的用户原话，解释缩写，区分受助后的正确表达与尚未证实的独立使用能力 |

可阅读证据：[完整对话](conversation.md)、[独立内容审阅](semantic-review.md)、[实际操作截图](sol-live-03/browser-04.png)、[浏览器操作记录](sol-live-03/browser-04.json)。原始请求、模型响应、持久化回合与收据保存在 `sol-live-03/`。

## 验证中修复的问题

- 接受设计后，冻结的 Tutor 事实被动态片段重复投递；改为回合冻结的初始上下文与单独的设计更新。
- 长理解记录使设计接受回执超过 4 KiB，通用预算投影会截断 `design_ref`，导致下一次采样拿正确时机却拿到错误引用。`tool_result.rs` 现在为设计接受生成小回执，保留完整引用；完整设计、理解上下文与原始工具记录仍保留在各自原有位置。TB4 的真实接续回归暴露了此问题，七轮模型也曾通过下一采样的完整设计自行恢复。
- 已经接受设计目标后，动作省略重复的 `target` 被错误拒绝；省略时沿用当前已接受目标，显式提供时仍校验。
- 正文与活动组件重复显示同一句普通邀请；前端识别实际承载邀请的正文段落，保留一处问句和表达入口，并以该段落的可见性记录展示。
- 返回演示现场的 `return_to.scene_ref` 只有字符串类型，模型把收据内的 `saved_state_ref` 当作教学事实引用；现在字段说明和错误信息明确引用类别，并要求该事实确实携带 `presentation_follow_up` 或 `scene`。复用已有教学事实即可读取原现场，无需再造场景存储。
- 长会话触发压缩时，验证适配器没有辅助模型通道；补齐真实结构化模型请求通道，保留失败运行记录，重新执行完整情境。这是验证适配器修正，不是生产压缩实现的变更。

## 验证边界

这组验证使用脚本化的、能区分理解差异的用户表达，模型由 gpt-6.1-sol 子代理提供。它验证实际生成行为与应用闭环；不能当作真人长期学习效果或线上默认模型表现的证明。本次为本地实现，未部署到线上。

第四轮回答保留了一处外层文件传输导致的字面换行字符；第六轮经历了场景引用参数遭拒后继续完成的过程。后续澄清场景引用合同并补定向回归，未将原始七轮记录替换成事后修订答案。本次七轮未触发辅助上下文压缩，因此不宣称验证了该通道的完整模型行为。
