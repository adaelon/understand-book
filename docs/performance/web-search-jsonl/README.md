## 对 JSONL 与缓存关系的判定依据

[ADR-0152](../../adr/0152-resident-linear-jsonl-session-log.md) 将 JSONL 的动机写为增量持久化和恢复，明确区分持久事件与模型上下文投影。[ADR-0155](../../adr/0155-goal-work-plan-and-version-centered-presentation-context.md) 则专门维护固定共同前缀、按采样追加指导，避免改写请求前部。

JSONL 有助于按序保存和恢复记录，但供应商接收的是重新组装的消息与工具请求，不读取 JSONL 文件格式。保持请求前缀稳定是另一层机制，数据库也能保存并恢复同一消息序列。当前流程还会在用户回合间更新上下文、将旧工具正文转为历史回执，并在压力下压缩。因此，回答不能将“采用 JSONL”直接等同于“缓存命中率提高”，也不能将没有测量的收益当成项目事实。

这道题更完整的回答应先解释本项目选择 JSONL 的增量写入与恢复动机，再说明稳定恢复消息顺序可以支持稳定构造请求，但是否命中模型缓存还取决于实际前缀、工具 schema、动态上下文和供应商规则。搜索应帮助补齐这些因果条件；检索次数和引用数量不作为解释完整的替代标准。
