name: presentation-method
description: Choose and revise a useful explanation format for the reader's current question.
---

Presentation method (ex2.v5, explorable-explanation):
Choose the smallest explanation that makes the reader's missing relationship visible. Before authoring, decide within the current turn: Obstacle — what difference, mechanism, or boundary is not yet understood? Objects — which things must keep their identity across views or time? Change — which comparison, transformation, or sequence would reveal the relationship? Interaction — which reader action would test understanding, if any? Do not add a page, animation, or control when prose or a static visual answers the question.

Select zero or more explanation moves for the obstacle, not a fixed layout: object-continuity keeps an entity recognizable; progressive-reveal limits simultaneous information; transform shows A becoming B; compare-in-motion distinguishes similar endpoints with different paths; parameter-sweep varies one input; trace-ghost retains meaningful prior states; invariant-highlight marks what stays fixed; viewpoint-change changes representation or coordinate system; counterexample exposes a false generalization; prediction-reveal asks before showing the result; decompose-recompose separates parts then reconnects them; concrete-to-abstract moves from a specific case to a rule. Combine only moves that help the current question. Where two quantities can have the same magnitude but different direction or path, put that pair on a common scale to separate the two effects. Use Understand Book's existing visual language; these method names are not user-facing labels.

For continuous change, keep object identity stable and distinguish real semantic steps from visual interpolation. Make pause, replay, parameter changes, saved state, and visible results agree when the page needs them. If the same point can be shown with a table, static comparison, or discrete steps, use that simpler form. Preserve the user's question and verified source material; label assumptions and the scope of simplified examples.

Give computed results one executable source. Generate the visual, numeric readouts, sequences and any step-by-step arithmetic explanations from that same calculation in the page; label parameters and current/next step indices. Use real preview to inspect these values and their relationship. Keep derived numeric sequences and worked arithmetic in this executable content. In static readable_content and the final summary, explain the rule, its boundaries and the qualitative relationship, and direct the reader to the computed readout instead of manually duplicating its numbers. Fixed model constants and analytically derived boundary values can appear in prose. If the user explicitly requests a numeric answer in text, copy the exact labelled result actually observed in preview, preserving its step, sign and displayed precision; inspect any additional case before quoting it.

After real preview, check whether the chosen representation exposes the intended difference and whether all required viewports remain usable. Revise the representation when a correct-running page still hides the relationship. Follow the authoring tool's source, state, version, preview, and delivery contract.
