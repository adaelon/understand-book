## 《借用》这一章的重点

**一句话定位**：借用是在不取得所有权的前提下临时访问一个值，它按所有权模型自身的规则运作，值的所有者与释放责任都不变。

### 1. 两种借用，对应两种引用类型

- 在值或 place 前写 `&`：产生共享（不可变）借用，引用类型写作 `&T`。示例里 `let bar = &foo;` 让 `bar` 的类型成为 `&Foo`，并且不能通过 `bar` 修改 `Foo` 内部的值。
- 写 `&mut`：产生可变借用，可以借它修改值。

注意：`&` 是 Rust 的借用运算符。该运算符不保证所引用的值在引用存活期间始终有效；这一点与 C 里单纯取地址不同，所以它并不等同于 C 的取地址。

### 2. 可变借用要求所有者本身是可变绑定

写成 `let a = String::from("Owned string"); let a_ref = &mut a;` 会编译报错。原因在于：`a` 是不可变绑定，编译器不允许对不可变绑定所拥有的值取得可变访问权限。把声明改成 `let mut a = ...` 才能通过。

这里还顺带澄清了一个常见误读：`&mut a` 并不会把 `a` 移动进 `a_ref`，整个过程只是借用。

### 3. 借用者能改，但不能释放

`a_ref` 是 `a` 所拥有值的可变引用，可以往字符串里 push 字符，却没有释放那块堆内存的权力，因为它不是所有者。反过来说，一旦所有者 `a` 先被释放，这次借用就失去依托、随之失效。

这一条是后面「引用不能比被引用对象活得更久」的直观来源。

### 4. 排他性，以及现代编译器改用「实际活跃范围」判断

书中那个加入 `println!("{}", a)` 的例子，在旧编译器上报错，正是可变借用排他性的体现。而在采用非词法生命周期（NLL）的现代 Rust 中，`a_ref` 最后一次使用是 `push`，借用在那里就结束了，所以那段代码现在能编译。

判断标准因此要改一处：不看「是否写在同一对花括号里」，看「借用是否仍然活跃」。如果在 `println!` 之后再使用 `a_ref`，可变借用就必须跨过对 `a` 的共享访问，编译器依然会拒绝。准确的表述是：可变借用仍然活跃时，不能再创建指向同一数据的其他借用。

### 5. 本章末尾引出的三条正式规则

本章最后一句说明「下面明确列出 Rust 中的借用规则」，这几条规则紧接在下一节。

1. **有效期**：引用的生命周期不能长于它所引用的对象，否则对象析构后引用悬垂；安全 Rust 的借用检查会阻止这种引用被当作可用引用保留下来。
2. **可变引用排他**：存在可变引用时，在它仍然活跃的期间，不允许再有指向该值的其他引用，无论可变还是不可变。
3. **共享引用可多**：没有活跃的可变借用时，可以有任意数量的共享引用指向同一值，各自仍须满足有效期。

分析这些规则的是编译器的一个组件，也就是借用检查器。

### 读这一章时可以抓住的主线

把三个例子串起来看，就是一条递进的因果链：先证明借用不转移所有权（`bar = &foo` 能编译），再说明可变借用需要所有者可变，然后展示借用者对值的权利边界（能改不能释放），最后落到排他性这一条会把「同一作用域」收紧为「借用实际活跃的范围」。后面讲生命周期、方法接收者（`&self` / `&mut self` / `self`）时，都会反复回到这条主线。
