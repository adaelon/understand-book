## 主要问题及建议

### 三个快捷入口在这本书上无法开始

12:49:36 HKT 只读核对线上当前 `board-visual-math-20261028`：Rust publication `01a0f58a-4df3-7822-8f5d-f712568fd50a` 有 `source.txt` 和 `base.json`，没有 `book_structure.json`。见 [线上回执](production-readiness.json)。因此本地入口禁用不是仅由本地副本过旧造成的。

`crates/server/src/tutor_api.rs:253` 将缺失结构归为 `preparing`；`packages/web/src/components/LearningPurposeEntry.vue:27` 原样显示“BookStructure 缺失、无法读取或属于其他来源”，`:49` 禁用三项。页面没有说明是否有实际准备任务、何时能用，也没有在该入口可执行的恢复动作。

优先完成 Rust 材料的结构准备并发布，让三个已承诺的入口真正可用。未完成时使用用户能理解的事实提示和可用操作；只有实际有准备任务时才显示“准备中”。缺失材料与后台正在处理应区分，不应仅以等待文案代替。

### 概览后的下一步承诺没有兑现

`packages/web/src/components/RightRail.vue:1504` 在 Tutor 关闭时显示“开启连续教学”，未同时检查该材料是否 ready。本次点击后只是开启开关，随即显示不可继续状态。见 [点击后画面](continue-learning-blocked.jpg)。

应让回答后的动作和入口使用一致的可用条件。结构未就绪时继续提供当前可用的普通追问，例如解释刚才的具体例子；不要把开启全局开关描述为本书马上能够继续教学。

### 概览存在两处实质概念问题

原答见 [answer.md](answer.md)，未作修订。

1. “该运算符不保证所引用的值在引用存活期间始终有效”把原文意思说反。其引用 127.2 说 Rust 借用不能等同于 C 中不带有效性约束的取地址；128.3 明确安全 Rust 会阻止悬垂引用作为可用引用保留。Rust [官方书](https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html) 同样明确引用的有效性保证。这是有引用但引用不支持答句，并与答案后文有效期规则相矛盾。
2. “可变借用者没有释放那块堆内存的权力”继承并强化了原文 127.14 的不准确概括。同一例子里 `a_ref: &mut String` 可通过 `*a_ref = String::new()` 替换并析构旧字符串；见 [官方赋值语义](https://doc.rust-lang.org/reference/expressions/operator-expr.html#assignment-expressions) 和 [`mem::take`](https://doc.rust-lang.org/std/mem/fn.take.html)。准确边界是借用本身不转移所有权、引用结束不自动析构被借用值，不能概括为绝对不能通过可变引用释放旧值。

第一处需要改善生成内容与原文的语义一致性；第二处还需要修正书籍正文，不能只改回答提示。其余主要例子和 NLL 说明有来源支持。回答围绕借用主题展开，未发现无关主题扩展。

## 首次点击的节奏

本次后端活动记录覆盖约 40.9 秒，最终回答所在模型请求约在 36.3 秒首次产出文本。中途有查阅原文的工作进度；不把进度文本计作用户已收到讲解。7 次模型调用、13 项工具操作（含一次读取被拒后恢复），累计 240963 个模型报告 token，包含重复上下文与缓存输入，并非新增内容量或实际账单。见 [metrics.json](metrics.json)。

答案有一句话定位、五组重点和一段学习主线，内容相关、层次清楚。作为“先了解重点”的第一步，1500 多字符和约 41 秒的等待仍偏重。建议先给读者能立即接住的关系概览和一个具体例子，再提供可点击的深入方向；这里是体验判断，不以硬字数限制替代教学质量判断。

四种目的的定位可以保留：概览看重点关系、读懂从一个关系推进、复习从当前范围的短回忆／应用开始、探索给少量有原文依据的问题候选。后三项当前不可达，尚无本次生成质量的结论。
