## 实现

正式 `App → PdfReaderPane → PdfFocusReader → FocusPageTurn` 使用同一 PDF 文档、来源映射及批注投影。宽窗口默认双页，窄窗口单页，菜单可选单页；原版页按整页适配，放大后优先页内平移。专注工具提供目录、PDF／重排正文切换、问答、笔记和退出，浮层不改变书页尺寸。退出或切换阅读表面沿原页、页内比例、横向位置与倍率恢复。

当前屏与前后屏是唯一驻留窗口。双页必须两张画布、两套文字及批注全部完成才发布。候选画布也占预算，桌面最多六页、手机最多三页，实际 backing pixels 总量不超过 12,000,000；进入与退出同时持有的连续模式画布也计入。画布按原版 96dpi × 设备像素比例栅格化，每页不超过总额度的六分之一。正文文字在原版坐标布局，显示尺寸用统一比例转换，因此缩放、窗口变化和单双页组合可直接转移已准备的原版页，不重复生成文字层。

只有规范当前屏的文字参与原生选择。预览文字用 `content-visibility:hidden` 隔离，预览标注保持 inert；动画期间由透明输入遮层阻止文字拖选，避免对数千文字节点反复改变继承的 inert／pointer-events。已有原生选区阻止翻页；鼠标拖选、笔记落点和放大平移优先。

PDF.js canvas continuation、文字流及发布共享暂停条件。交互开始会取消已排队但未完成的候选画布，防止 PDF.js 已安排的 RAF 在新手势内继续绘制；恢复时重新准备该候选。未完成画布不进入浏览器绘制，文字布局分任务完成，收尾后的后台补页等待当前画面绘制。后台与隐藏状态停止准备，卸载释放画布、文字任务和 PDF 页代理的重资源。

`PdfReaderPane` 的可交互页映射只指向当前屏，选择、高亮和笔记继续使用原 PDF 坐标及现有 selection.resolve／ranges.project。当前页锚点通过预先排序的来源位置索引查找；App 即时更新阅读上下文，已有 paper profile 的 viewport 保存异步执行，迟到保存回执不倒退正在阅读的页。

## 验收入口

实际运行环境：Windows 10 build 19044，Chromium 149.0.7827.55（headless），桌面1440×900、移动390×844，旋转844×390；主要时间线DPR 1，另有DPR 2/3资源与选择场景。Tracing刷新周期16.666ms。收口时系统活动电源方案为“野兽模式”。

`vite.focus-pdf.config.ts` 构建正式 App，`playwright.focus-pdf.config.ts` 串行运行公开按钮、键盘、鼠标和 CDP 触摸，默认端口 4194。使用 FP1 的真实 Kimi K3 原版 PDF（1,790,685 字节）及原始映射；七页双栏／大图样本用于精确选择与投影几何。真实 HTTP Range 回执支持本地与固定 100ms RTT、10Mbps 条件。

```powershell
pnpm --dir packages/web run build
pnpm --dir packages/web exec vue-tsc --noEmit -p playwright/tsconfig.focus-pdf.json
pnpm --dir packages/web exec vite build --config vite.focus-pdf.config.ts
pnpm --dir packages/web exec playwright test --config playwright.focus-pdf.config.ts --reporter=line
python packages/web/playwright/fixtures/summarize-focus-pdf.py --check
```

P1 比较 Chrome filmstrip 中读区实际像素，P2 使用 DrawFrame／DroppedFrame 及实测刷新周期；RAF 变化仅保留为诊断。P3 每组 200 次、每秒一次，并含反向，共桌面／手机 × 本地／弱网四组。P4 每个设备各 20 次缩放、20 次单双页或旋转、20 次热进入；测新首屏可读、旧画面与页锚点。P5 至少 20 分钟、601 次有效翻页，含缩放和反向，最终返回起点核对持有资源。P6 检查从输入到收尾的五项工作计数：准备屏、画布启动、文字层启动、文字流分块和批注渲染。

最终统计与验收状态以 `results/summary.json` 为准；`--check` 要求五组帧记录、四组正常阅读、两组显示变化及长读记录全部存在且满足门槛。

## 发现与修复

- 最初每次显示变化重绘整屏，P4 超过 200ms。复用原版页后，第一轮 120 次显示变化各组 P95 为 13.3–49.9ms。
- 每次确认视口扫描完整来源映射造成约 14.6ms 同步工作；改为一次排序后按位置二分查找。
- 翻页前后切换继承的 inert 与 pointer-events 导致整套透明文字样式重算。当前文字几何保持不变，预览文字不参与选择，标注和输入单独处理。
- 候选画布参与绘制、PDF.js 绘制与文字布局挤在同一帧，出现 50–65ms 长任务。候选绘制隐藏、文字分任务、收尾后再恢复准备，消除了这条叠加路径。
- 所有设备都使用每页两百万像素时，DPR 1 下合成耗时达到约 16–25ms，帧指标失败。按设备像素比例使用原版栅格，保留高分屏预算，修复后的桌面记录 P95 35.158ms、缺失帧 0%、无阅读长任务；最终完整界面复验另存最终结果。
- 手机触摸曾被内层滚动容器取消；适页与放大状态现在分别声明触摸滚动归属。缓冲未就绪时反向到首屏会取消旧目标；恢复数值相同的几何不再误删就绪邻屏。
- 反向拖动的最初一段位移只露出与当前屏相同的空白边距，首次可见变化落到第二次触摸移动；窄屏的页边阴影现在随真实位移进入读区，使起始拖动也有可见的页面边缘。宽屏不使用该阴影，避免额外合成开销；原桌面弱网2.26%缺失率修复后为0.905%。
- PDF 专注页沿正文模式收起上下导航栏；阅读工具承担两种表面切换。切入正文显式准备专注屏，正文卸载时撤销其活动范围，避免返回 PDF 后提问仍带入旧正文引文。

原失败保存在 `first-trace` 至 `twelfth-trace`、`first-touch`、`first-display`／`second-display`、`summary-*.log` 和对应浏览器日志。中间尝试保留原始证据，最终实现与最终指标为交付依据。

## 限制

- 当前证据为 Windows Chromium 桌面、移动视口及触摸模拟；实体手机、系统选择手柄、高刷新率和物理显示延迟未测。WebView2／WebKit 联合验收归 FP7。
- 资源数字是该阅读实例持有的页、画布实际像素、DOM 与准备任务，不是浏览器总堆或 GPU 总内存。放大保持同一原版位图；实际栅格倍率在画布记录和截图中保留。
- 网络与批注写入使用生产 App 的接口回执夹具；精确七页样本的 resolve／project 回执验证前端选择与投影，不作为新后端对齐正确性的证据。冷读取与缓冲外快速连续操作可等待，当前已就绪画面保留；正常节奏的未就绪仍计入失败。
