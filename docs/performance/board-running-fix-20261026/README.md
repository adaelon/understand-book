# 新画板运行反馈与图解检查修复

用户在 AI Infra 的新空白画板上请求整理上下文状态。画板为空，右侧只显示静止的“正在运行”，底部却显示此前画板的完成提示。

## 原因与修改

后台确实在运行，904.66 秒后以 incomplete 结束，记录了 32 次模型请求，没有原生图解提交。见[故障轮次摘要](incident-summary.json)。原生画板候选已经完成预览，但教学选择的检查输入只有文字和 HTML 演示，没有当前原生图解。检查因此要求提供画板保存回执，而保存本身又要求先通过检查，形成反复修订。范围之外的讲解仍受既有教学焦点约束，本次没有取消这些约束。

- Runtime 保留当前成功预览的观察与截图，并在教学选择时从宿主重读候选，核对当前版本、作者已观察状态及完整讲解文字。
- 图解以 `proposed_board` 送入包含视觉证据的检查，明确它是待保存候选；已提交内容仍由 `committed_deliveries` 表示。引用可来自实际保留的卡片正文与预览公开文字，不含来源快照或隐藏资料。审阅后再改图需要重新检查。
- `App` 和讨论合并逻辑传递现有活动记录；右侧复用工作步骤组件并展示当前阶段。终态历史替换过期的运行中活动。
- `BoardDiscussion` 的加载图标补齐自身旋转样式；父组件的 scoped 样式原本无法覆盖它。
- 切换画板清除旧完成通知及刷新失败状态；处理完成回执前先核对画板归属，旧请求晚到也不会污染新画板。

## 验证

新增前端场景在修复前复现旧通知残留、工作步骤缺失和阶段始终为“正在运行”；修复后相关 52 项通过，多人构建及类型检查通过。

原生卡片文字作为检查引文的用例在修复前失败；修复后 Runtime 画板筛选 15 项通过，教学循环 57 项通过（2 项已有忽略），检查投影 11 项通过。各筛选含交叠，不相加作为独立总数。使用受控宿主和模型的完整运行循环验证“预览回执及图片进入作者采样 → 教学选择收到同一图解及截图 → 检查后交付”的传递顺序；该用例不启动真实浏览器或模型。另覆盖文字不一致、候选替换、旧画板版本和检查后改图不能交付。

浏览器使用真实 `BoardWorkspace`、`BoardDiscussion` 和活动组件，API/运行记录为模拟数据。已操作从完成画板切到新空画板，再切到运行中讨论；旧完成提示消失，当前步骤可见，连续两次读取加载图标的实际变换不同。此证据不等同于重新运行用户的模型请求。
