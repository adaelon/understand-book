## 首轮发现及处置

1. 否定请求“不要制作交互页面”被现有目标启发式误标为 `PresentationDelivery`。真实采样的运行状态仍要求交付页面，直接讲题和来源问答最后进入了收尾路径。原始请求保留了这个真实用户表达，没有为了通过实验而改写它。
2. 首轮样例讲义有正文，但结构与知识图为空；中文问题触发了中文词的字面检索，没有命中英文原文。实际采样只曝光当前书工具和工具发现，未出现跨资料指导或工作区资料目录，模型没有继续读取视频。原回答要求用户重新贴材料，来源目标没有完成。
3. 直接讲题把“同一时间窗口支持两条不同陈述”当成“窗口一定过宽”的判断依据。两条陈述可能同时为真，这不能判断窗口是否合适。整段视频可能仍包含支持陈述的证据，但不如明确指出相关时段便于定位；不得把“不够精确”写成“不支持”。

以上原始失败保留。虽然日期和范围在正文中的行为已满足，四例都被错误页面要求标成了未完整交付，因此修复后以相同四个原始请求追加一轮新目录，验证完整交付。不会用追加采样覆盖首轮失败。

## 复现

[执行脚本](../../../../scripts/cloud-exam-model-eval.mjs)读取本机已有配置，不打印或保存凭证。需要先完成 server 的统一编译，并确保 4200/4201 没有其他验收宿主。脚本把测试程序复制到工作区 `target/cloud-exam-tmp/run-*` 独立目录运行，并将子进程 `TEMP/TMP` 指向同一目录，避免 Windows 锁住后续构建目标及系统盘临时空间不足，正常结束后只清理本次创建的目录。

```powershell
node scripts/cloud-exam-model-eval.mjs --test-bin target/debug/deps/server-<当前构建标识>.exe --out docs/performance/cloud-learning-20261020/costs/new-run
```

有新失败时可以用 `--only direct-question,text-video-sources` 等参数选择相应案例，并指定新的输出目录；第二轮因四例均受页面误判影响而全部复验，第三至六轮仅执行 `--only direct-question`。既有 `run.json` 不覆盖；六轮的运行程序副本均已清理，第五轮的后台最终结算缺口如上保留。案例的用量以“该案例执行期间开始的请求”为口径，后台请求如有交叠会保留目的分类，总量以所有实际记录为准。当前脚本保留真实 SSE、审阅原稿与结论、管理员账本及账号视图，区分主任务的嵌套审阅与账号级后台任务。
