# 理解记录、教学设计与审阅共用真实交互

日期：2026-10-18。决策见 [ADR-0164 §11](../../adr/0164-tutor-mission-and-cognitive-building-blocks.md#11-理解判断的共同依据)。

## 问题与行为

用户要求 Agent 紧接实际表达讲解。此前理解记录、设计和审阅各自持有理解摘要，设计可以写出“刚从演示理解了……”或从一个用途问题推断用户持有某种误解。交付审阅虽已执行，仍可能沿用这个前提。

现在，新理解记录的事实依据须为真实用户表达；设计采用理解记录时展开其原始表达；最终交付审阅也使用同一份宿主生成的原话和帮助记录。讲过、展示过、点过，只说明交互和帮助条件。

理解未知时正常讲解。先把当前问题所需的概念、对象和连接讲清楚，不把建立理解假设、让用户作答或证明掌握作为讲解前提。只有实际表达支持某种理解判断时才采用它。准确的确认可以直接肯定，省略的细节仍待确认；设计不能自行补出一个更强的错误观点再纠正用户。

## 数据与执行路径

- `memory::LearningStore::learner_expression_fact` 统一验证原事件的来源、版本、会话与实际表达。新 Hypothesis 的每条 `fact_ref` 都经过它；`learner_quote` 必须来自被引用原话。交付、显示、点击和未修改预填不能混入事实依据。
- `understanding_basis` 将当前未被替代的理解记录解析到原表达。相同来源版本的理解可跨会话复用，原事实按其原会话验证。Performance 的帮助引用仍保留在历史记录中，采用理解时通过其原 action 解析表达。用户主动纠正的原文独立保留。
- `server::teaching::grounding` 生成 `learner_grounding`：`expressions` 为原话，`interpretations` 为可修正解释，`delivered_support` 为表达时已有的帮助。它是现有记录的派生视图，不新增账本。用户纠正使用 `kind=learner_correction` 和 `evidence_ref`，不会伪装成教学事件的 `fact_ref`。
- 初次准备、普通观察、动态学习者视图、设计采用与 select 预检共用这一路径。相关原话与实际帮助正文完整传递，保留每次输入冻结的帮助引用；之后才交付的帮助不会反过来改变较早表达的条件。比较帮助前后变化时，也带入该帮助原本回应的表达。
- 预检汇总最终明确保留的动作和当前动作，重新验证被采用的理解引用。已被替换的候选不进入最终依据，已失效的理解不能借保留动作继续采用。
- 模型的学习者视图不再同时携带无原话的聚合状态和裸理解摘要。原存储与用户查看入口仍保留。
- 原有交付审阅同时检查设计、参与理由、正文和页面，接受时返回它所依赖的理解断言及原话引用。运行时逐条核对引用和原文，再允许保存选择；交付引用、空依据、虚构引文和缺少声明字段会被拒绝。普通讲解可返回空断言数组。
- 审阅引用只用于本次接受判断，不回写为新的理解记录。主模型提供的同名依据字段会在预检前移除，审阅采用宿主实际解析的结果。

历史记录保持原样。不能追溯到真实表达的旧依据不会被新设计或动作采用；旧设计仍可读取、修改，用户可以继续请求讲解。用户纠正混合了帮助引用的旧假设时，新记录只保留原表达引用，旧记录不重写。

## 验证

每组检查对应一个具体失败：

| 范围 | 需要发现的失败及处理 |
| --- | --- |
| Memory | 帮助被写成理解依据、引文不属于原话、错误会话或旧理解被重新采用；出现时修复共同解析与写入边界。 |
| Server | 未知状态阻止讲解，原话/输入时帮助丢失，用户纠正不能被引用，保留动作漏掉原依据；出现时修复派生视图及选择路径。 |
| Runtime | 审阅用交付或虚构引文放行、普通讲解被强制要求诊断、旧摘要仍成为第二份用户画像；出现时修复审阅接受和模型视图。 |
| 语义回放 | 正确确认被纠错、用途提问被诊断为误解、展示被当作掌握，或正常解释被要求先测试；出现时修订审阅行为并保留具体案例。 |

本地 Memory 的 `learning_evidence::tests` 8 项通过，`teaching::tests` 2 项通过。Runtime 的 `teaching_` 和 `tutor` 过滤集合 61 项通过。

Server 的 `teaching_design_tests` 和 `tutor_` 过滤集合 145 项通过，19 项已有真实模型或浏览器宿主测试保持忽略。默认测试可执行文件正被另一任务使用，采用 `cargo rustc -p server --lib --profile test -- -C extra-filename=-tutor-grounding` 生成独立测试程序，复用现有依赖，未终止另一任务。

旧回放 fixture 已接入当前设计步骤，按原话解析本次理解依据，缓存本轮来源回执，并交付原冻结正文。历史样本文件保持原样；旧混合引用记录的读取测试直接恢复历史存储行，再验证新纠正使用实际表达、原历史记录不变。成功回放报告写入临时目录，避免测试覆盖历史报告。

本地可复验命令：

```powershell
cargo test -p memory --lib learning_evidence::tests
cargo test -p memory --lib teaching::tests
cargo test -p runtime --lib -- teaching_ tutor
cargo rustc -p server --lib --profile test -- -C extra-filename=-tutor-grounding
& target/debug/deps/server-tutor-grounding.exe teaching_design_tests tutor_
```

六种语义回放由独立 Codex Agent 按当时实际审阅指令执行，未提供预期判定；输入和输出保存在本目录。逐条对照后六种判定均符合预期，接受的断言引用也都匹配输入原文：

| 案例 | 结果 |
| --- | --- |
| 用户问 Embedding 用在哪里，直接说明用途和过程 | 接受，无需理解断言 |
| 用户准确确认中间产物，却被评价为“只对一半” | 修改 |
| 用户明确认为最高相似度必然证明结论，针对其原话纠正 | 接受，附原话 |
| 从用途问题编出“相似度等于证据”的设计前提 | 修改 |
| 准确肯定用户提出的中间产物关系 | 接受，附原话 |
| 设计凭演示已展示宣称用户已掌握，再据此推进 | 修改 |

回放文件：[输入与当时审阅指令](semantic-review-input.json)、[独立判定](semantic-review-output.json)、[预期](semantic-review-expectations.json)。用户纠正的类型化引用和保留动作处理另由代码测试覆盖。

## 已知限制

引用存在且逐字匹配，并不能证明它在语义上支持断言，也不能保证审阅者完整找出了所有隐含假设。这两项仍由审阅模型判断。此次六例使用独立 Codex Agent，没有测量线上 `deepseek-v4-flash` 的通过率，也没有完成网站真实模型端到端回归。

本轮修改停留在工作区，未部署到网站。六例结果和本地合同测试证明了相应路径，不能据此宣称所有解释质量问题已经解决。
