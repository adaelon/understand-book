# 已接纳帮助与学习者推理的交付闭环

本轮目标：修复首轮跨入尚未需要的条件，以及连续讲解代替学习者推理的问题。实际完成判据是：零碎理解的学习者得到必要帮助后，教师能留出尚未被讲解解决的小步；卡住时补足更小的连接；不把邀请变成每轮流程。

基线保存在 `baseline/`；上一轮内容证据见 `../teaching-stuck-20261017/live-02/`。该轮首答提前解释 accepted 的反事实，后续六轮中没有真实邀请。该失败记录保持原样。

## 实现切片

1. `TeachingMove.delivery_text` 是待接纳的实际教学正文。服务器从持久化的明确选择集合组装私有 `delivery_draft`；runtime 在下一采样提供它，最终交付消费这份正文及普通邀请。自由终答不再扩写支撑或代答预留推理。模型可重新 select 修改正文。
2. support 同时记录当前补给的连接、可选的未完成小推理。它们通过真实交付因果链进入私有工作视图；选过但没交付的内容不算帮助，也不自动成为问题。
3. 普通表达冻结实际收到的支持，跨焦点保留帮助与表达的关联。原设计与关系身份保持不变；conclude 不生成学习表现，也不删除已有支持事实。
4. 提示模块说明上述真实接口，消除把任意困惑问句理解成“完整代答”的歧义。没有按轮数、字数或支持次数强制邀请。

## 验证如何改变决定

- 交付路径回归检测自由终答泄漏、旧稿沿用、预算终答绕过及私有工作状态公开：失败则修交付链，不进入行为实验。
- 证据路径回归检测后来的帮助回填到早先表达、换焦点丢支撑、未交付选择冒充帮助：失败则修事实绑定。
- 新鲜 6.1 sol 多轮实验检测首轮是否仍把后续条件一起讲完、必要帮助后是否仍包办全部判断、卡住时是否反复要求同一步：失败则保留记录、定位机制并迭代。
- 对话内容由独立 6.1 sol 审阅，依据原始材料和实际可见正文，不用字段成功代替教学效果。

## 第一次真实实验后的修订

`live-01/` 保留首个候选的两轮实际交付与下一条学习者表达。首轮 431 字仍带入未 accepted 的反事实；第二轮 536 字完整展开甲乙丙。学习者随后又卡在额外引入的 accepted 条件。已接纳正文的交付约束生效，但不足以约束选择本身的跨度，不能据此发布。

增加选择接纳前的私有内容判断：用独立结构化模型请求读取实际用户表达、冻结帮助、当前设计和本次完整正文，判断是否存在可定位的跨度或代答问题。accept 才调用服务器持久化 select；revise 返回具体意见，走现有工具修正循环。判断不以字数、问题次数或固定步骤为条件，也不对已有源证据重复逐条验真。明确保留的早期选择按实际顺序一起送审，避免只审局部而漏掉组合后的扩张。

审视调用使用现有 provider、取消、用途和消耗记录，计入模型回合与 token 预算；无有效结论不能接纳。代价是每次新 select 多一次模型判断，发生修订会增加调用。最终正文仍消费通过接纳的内容。

`live-02/` 的四轮、26 次模型请求中，实际行为为 support、support、invite、conclude。第三轮先提供最终汇合规则，再留下新点丁的判断；用户用 accepted 路径给出正确判断及理由，第四轮明确反馈并结束邀请，未追加新问题。这支持一次受帮助的应用。首轮仍添加了未 accepted 的变化，四次审视均 accept；独立内容审阅见 `live-02/opening-content-review.md`，确认额外跨度可避免，不能把本组作为首轮问题已解决的证据。

将审视准则修订为 `teaching-delivery.v2`：明确老师读到的来源不等于用户已有起点；找到具体案例已经回答当前困惑的位置，之后增加变化条件必须由当前需求、表达或所邀请的小尝试支撑。

`review-regression/` 把 live-02 第一轮的真实失败稿及完整判断上下文原样送入新审视路径，由隔离 6.1 sol 产生实际结论。结果为 revise：具体的乙仍在 C、未进 macro 却可被主题选用，已经回答当前疑问；随后改变 accepted 的条件要求尚未建立的新区别，应删去额外分支。真实调用 1 次，测试通过；这证明已知失败现在能够触发修订，不代表所有跨度问题均能检出。

最终候选完成 `live-03/`、`live-04/` 两组多轮会话。每组教师和学习者均为新鲜隔离的 6.1 sol；接纳执行者独立消费实际 review packet。学习者只看实际交付正文，后续输入逐字转发，不提供教学步骤。

## 最终对话证据

`live-03/` 自然完成 3 轮、20 次模型请求。首轮围绕乙保留在 C 但未进主干；用户主动提出未 accepted 的变化后，第二轮才补足该区别，并留下丁缺少主题证据的新判断。用户给出判断与理由，第三轮针对性反馈并收束。没有为了原计划轮数要求模拟用户继续装作困惑。

`live-04/` 使用更难同时处理多个关系的新鲜学习者，自然完成 4 轮、29 次模型请求。首份准备稿又提前扩展未 accepted 分支，真实接纳判断退回，修订后才交付。用户随后依次混淆 accepted 与主干、candidate 与 accepted 对主题的作用；教师分别收窄为两身份对照，以及“从哪里找/凭什么选”，再留下小丙的新判断。用户说出“这一章收下小丙，也没说明它跟这个主题有什么关系，还是得有主题那边的证据”，第四轮针对这个理由反馈，不再提问。

两组实际路径分别为补帮助—邀请—反馈收束，以及补帮助—补帮助—邀请—反馈收束。首轮没有靠字数上限删减，也没有按支持轮数自动要求用户作答。四轮组的运行中退回表明内容接纳机制实际改变了发布结果；被退回的稿件未交付给学习者。

独立 6.1 sol 内容审阅只读原始来源与实际可见对话，两份均未发现实质教学内容问题：

- [三轮实际对话](live-03/conversation.md) / [独立审阅](live-03/independent-content-review.md)
- [四轮实际对话](live-04/conversation.md) / [独立审阅](live-04/independent-content-review.md)

这些证据支持即时区分及一次紧贴讲解的应用，不能支持真人学习效果、长期保持或复杂迁移。四轮组直接检验了 accepted 不足以保证主题选入，不能独立证明用户已会应用 accepted 不是必要条件这一另一方向；不为补满覆盖而强行延长已自然结束的教学。两组未产生演示页，只有文字关系图和对照表，故本次不形成演示页面交互的新验收结论。

## 最终验证与发布

runtime 完整串行测试 629 passed / 8 ignored；server 设计测试 14 passed / 1 ignored；server tutor 测试 115 passed / 19 ignored，显式排除既有历史 TB2 录制回放（其输入缺当前设计合同）。真实 v2 审视回归通过，本地测试程序与 Linux 五程序均成功构建。Linux 最终构建 5 分 53 秒、exit 0；六个生产文件在工作区、最终冻结快照与远端候选逐字节一致。

部署使用 `frozen-source-final`，前两份行为未接纳候选的证据仍保留。最终版本于 2026-10-17 11:10:14 HKT 上线，server、演示 worker 配置与 Nginx 均切换到 `teaching-handoff-20261017`。本机与公网书库授权、manifest、正文、演示能力和项目资源验收通过；完整数据备份与旧版回滚程序保留。清理已确认非运行的旧编译中间物后，可用空间 918,482,944 bytes。详见 [部署记录](deployment/README.md)。

## 局限与代价

接纳判断仍是模型判断，不能保证每次都发现跨度或代答问题。每次准备新选择增加一次模型请求，修订则增加后续调用；这些调用纳入现有预算与取消链。这里增加的是准备、接纳、真实交付和证据绑定的执行约束，教学方向仍由实际表达决定，不是固定问答流程。
