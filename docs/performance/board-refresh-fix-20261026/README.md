# 刷新后工作区加载失败

2026-10-26 22:30 上线后，用户刷新浏览器，出现 `The operation could not be completed`，学习工作区显示为 00。账号仍有 2 个学习工作区和 28 个聊天记录；数据没有被删除。

## 原因与恢复

上一轮为避免未完成的回复自动成为画板成果，在 `board_delivery::deliverable` 中加入了 `outcome.incomplete` 判断。历史事件读取也调用同一函数，导致旧版已经保存的 4 条未完成回复回执不能重放。整个用户历史加载因此返回 `AGENT_HISTORY_LOAD_FAILED`，阻断书库、聊天和阅读恢复；登录与学习工作区元数据本身仍能读取。

`NetworkApp.vue` 的 `catalog()` 依次读取书库、视频和学习工作区。书库请求因用户历史加载失败而中断，工作区列表尚未读取，页面便显示初始空列表的 00；不是后台工作区数量变成零。

22:45:11 HKT 将服务恢复到 `board-running-20261026`，PID 221414，维护 7.52 秒。没有回滚数据库、删除卡片、覆盖聊天或更改账号密码。页面资源与 Windows 0.3.8 安装包保持原样。

这次故障来自发布代码，上一轮以新建账号为主的预检遗漏了旧画板回执恢复场景。

## 修复

新画板内容仍由 `deliverable` 判断，未完成回复只保留在讨论中。历史事件改用 `has_completed_answer` 校验已经记录的回复和回执，不再用新内容的准入规则否定既有记录。回执所属画板、原聊天、原轮次和重复链接校验保持有效。

修改范围为两个生产文件及一个测试文件，没有数据迁移，也不改写旧记录。之前的上下文容量修复保留在候选版本中。
