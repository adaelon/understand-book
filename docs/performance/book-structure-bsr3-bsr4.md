# BSR3–BSR4 结构检索与主题工作集

日期：2026-10-01。设计为 [ADR-0151](../adr/0151-book-structure-global-outline-and-semantic-retrieval.md)。BSR3–BSR4 已完成 Core 合同、真实本地检索和独立 Codex subagent 主题对照。两组均形成 4 个主题、8 条有双端依据的阅读依赖，原文核对发现的遗漏已定点修订并完整重放。C 未证明整体成本收益，默认保持 `lexical_only`。正式 Engine 接入为 BSR5。

## 实现

`book-structure-retrieval.ts` 以可用的章节问题、章卡概述和候选含义、条件、已有别名形成短投影。正文、完整词法字段、候选引用和证据位置保持可达；不把显示章号、路径和构建身份混入 embedding。投影的既有内容摘要仅用于复用未变向量。

SR 的准备依赖、缓存缺项估计、排序均使用实际消费者的投影版本。T5A 继续使用原缓存，BookStructure 使用 `.build/semantic-retrieval/book-structure/cache.json`。准备前用真实 adapter tokenizer 检查所有投影；超限明确失败，不静默截断。搜索翻页与 inspect/read 复用当前准备；语义缺准备不会退化为空结果。

`book-structure-themes.ts` 先从全部章卡和候选索引形成有限主题目录，每个问题对应一个工作集。任务携带紧凑全局目录，按需搜索与展开；每个阶段说明新增条件与判断变化。阅读依赖分别保存前置概念、后文应用、双端证据和理由。程序检查引用与交付，语义是否成立由真实内容对照验收。

目录收敛只有一次有界修改／合并；合并保留成员和已接纳依赖，未解决项保持 incomplete。原文审阅发现具体遗漏时，`reopenStructureTheme` 只重开对应主题，携带原结果和问题、保留其他主题与原额度；修订后直接恢复已收敛状态，不重扫目录。物化将主题显式成员补为重点并保留章节已选内容、宏观路线和来源；主题成员本身不产生依赖。

## 实验合同

用户选择独立 Codex subagent + 已安装本地 MiniLM。规划者及 B/C 生成者均不继承父聊天，只读取本阶段 prompt/input，不读取旧成品、验收答案、代码或另一组输出。规划者生成同一份 4 主题目录，B/C 分别完成主题和目录收敛。

材料复用唯一真实基线 `E:/allwork/download/agent/lifebook/.understand-book/ai-infra-book-complete`。重读 14 张已接纳章卡和 BSR0 固定主题涉及的完整片段贡献，共 202 候选；提供 212 处原文展开位置。没有按答案过滤同贡献的其他候选。两组候选、prompt、证据合同、初始问题、输入及输出预算一致，B 为改进词法、C 为同一词法加真实 MiniLM；每个主题从相同问题查询开始。

本轮独立上限为每组 80 个语义动作、每步输入估算 20,000／输出估算 6,500 tokens；本地 embedding 600 documents／80 queries／160 calls，失败和重试占额度。Provider 为本机 multilingual MiniLM q8 CPU，禁用远端下载，实际 tokenizer 上限 128。未沿用 SR6 余量，未调用外部生成 API。

## 真实内容验收

共享规划生成四组：状态复用的容量／转移／恢复、工作负载与器件瓶颈、并行划分与通信、期限与任务容量成本。两组覆盖全部 12 个正文章节；最终各 25 个主题发展阶段，B 显式选入 60 个不同重点，C 选入 64 个。这里只物化局部主题报告，章级选择和主题合并的正式全书发布留 BSR5。

固定状态主题同时保留六组比较：模型中 KV 表示、推理前缀共享与容量、跨阶段载荷转移、可恢复推理状态、训练 checkpoint、Agent 轮次提交。生成物区别模型头共享与请求前缀共享、分页分配与去重、内存可读与恢复一致性；没有把共同讨论“状态”变为训练 checkpoint 是 Agent 提交前置的错误依赖。

首轮 B 43／C 44 次提交均通过交付校验，但原文核对发现两组都没有明确连接分页映射与共享容量，传输量化联系也不完整。保留 [初始对照](book-structure-bsr4-20261001/initial-comparison.json)，用同一份[原文审阅问题](book-structure-bsr4-20261001/source-review-issue.txt)定点重开固定主题；反馈给原文范围和缺口，不提供算例答案。每组增加一次读取、一次修订，仍计入原 80 次额度。其余三个主题逐项完全不变。

最终结果补齐逻辑块到物理块的映射、16 请求共享 6,144 token 前缀的容量关系：共享 864 MiB 加每请求私有后缀 324 MiB，总计 6,048 MiB（约 5.91 GiB），落入 12 GiB 预算；也明确 144 KiB/token × 8,192 token = 1.125 GiB，经 25 GB/s 链路约需 48.3 ms，另有 5 μs 启动，以及双端驻留、完成标记与释放次序。对应原文 `10.10.2.4`、`10.10.3.17`、`11.8.3.14` 与相邻完整段落，修订记录在两组 session 和 before-revision 快照中。

其余主题已逐项读实际阶段、摘要和依赖，并对关键判断核对原文：Roofline 的瓶颈条件、融合时中间量 444→620 MiB、Softmax 全局最大值、专家热点、通信重叠、AF/PD 约 393/48.3 ms、训练不同卡数工期、Agent 副本与期限、重试期限边界，以及机房网络固定时间。各组 8 条依赖都有前置材料和后文应用；共同边包括注意力→推理、存储层级→表示及矩阵执行、并行→通信/训练、排队期限→服务/Agent。状态组最后一条 B 选择表示宽度→转移载荷，C 选择前缀连续性→跨阶段恢复，均有实际来源支撑。来源映射只是定位，内容判断以上述原文阅读为准。

- 原文抽样中部分范围从句中开始；新增候选展开保留 canonical span。验收核对实际支持的完整命题，不将索引位置当成已交付内容。
