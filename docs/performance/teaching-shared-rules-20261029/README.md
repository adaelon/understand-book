# 主讲与审核共享教学标准

2026-10-29。用户要求保留回答深度和审核标准，让主 agent 提前知道教学与验收规则，并继续用《失败的逻辑》的同一首稿验证。规则共享和当前反馈去重已实现，最终候选的解释深度与事实质量通过独立复核。与同稿基线相比，最终样本调用从 10 次降至 9 次，总输入减少 23.02%；但耗时从 181.053 增至 225.061 秒，正文修改从 1 次变成 2 次。**本轮未实现耗时与修订次数改善。** 第一候选的事实漏检和全部失败原样保留；完整计量见 [comparison.json](comparison.json)。

## 已确认的根因与实现

主 agent 以前已有通用教学指导，但完整关系补证等具体要求集中在提交或退回后；作者和审核各自维护同类规则。上一轮真实作者请求里，旧的删除或泛化建议同时出现在 `open_issues`、聚合修订说明及历史纠错记录，和后来补充的保深要求并存。

- 新增 `teaching_quality_contract.md`，从首次取材前注入主讲，事实、解释、综合审核直接引用同一文件。覆盖完整关系证据、来源标题归属、原稿相关深度、批量补证和可执行反馈；分支职责、来源隔离和审核输出协议各自保留。
- `review_feedback` 保留完整当前 `open_issues` 与局部修改操作指导，删除重复聚合 `revision` 和顶层 `request_resolution`。每项未解决问题使用当前完整修法，替换过时行动；问题编号、尚未解决的证据和原始诊断保留。
- 新请求缺口与仍未解决的旧请求缺口一同保存在稳定请求问题中。事实退回、跳过解释分支、参数失败或审核调用失败均不能清空旧问题，只有实际规范化审核可以关闭。
- 历史纠错向模型投影 `review_ref`、回合、规则及状态，不重复历史行动正文；完整审核、后续修改和原始记录仍持久化，可经 `tutor.step trace` 获取。

没有增加模型阶段、工具预算、功能开关或问题状态协议。仍使用实际来源和全文审核，保留同首稿深度对照及局部段落修改。

## 已知限制

共享标准和当前反馈确实送达、能追溯且没有重复旧行动，不保证模型每次完整遵守。第二候选的首次审核仍出现“只保留已读章节”建议，也仍漏掉既有条件错误，直到复审才检出。此类不当建议与漏检均保留为真实失败证据。当前没有新增模型阶段或用关键词过滤审核意见，也没有针对本书章名、位置或交通案例写特例。

本轮是固定文本首稿的修订验证，不覆盖新首稿生成、图片制作、演示页面制作或跨模型稳定性；单次样本不能证明稳定的提速幅度。所有修改为本地源码交付，未替换线上服务。
