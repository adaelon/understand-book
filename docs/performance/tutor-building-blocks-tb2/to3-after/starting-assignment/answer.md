## 先给结论

`let bar = &foo;` 里的 `&` 让 bar 只是**借用（指向）** foo 的那个值，而不是把值从 foo 手里拿走。值还留在 foo 那儿，所以 `foo` 能打印；bar 指向的是同一个值，所以 `bar` 也能打印。两行 `println!` 都能过，程序就编得过。

## 用你熟悉的东西搭积木

1. **名字贴着值。** 你已经在做的：`let foo = Foo(0);` 就是给一个 Foo 值（里面装着 0）贴上名字 `foo`。这和 `let x = 5;` 是同一件事，只是"值"从一个整数换成了一个结构体。

2. **`&` 不搬值，它造的是"引用"。** 原文把借用定位为：让代码"在不取得所有权的情况下临时访问值"，它不是绕开所有权规则，而是所有权模型本身的一部分 。在值前面写 `&` 就得到一个**不可变借用**，对应的类型写作 `&T` 。

3. **所以 bar 拿到的是引用，不是值。** 原文说："我们借用了 foo，并把借用赋给 bar。bar 的类型是 &Foo，也就是引用类型"，并且因为是不可变引用，不能通过 bar 修改里面的值 。这就是你没见过的 `&Foo`：它就是"指向 Foo 的不可变引用"这个类型名。

一句话图景：**一个值，两条能到达它的路**——拥有者 `foo`，借用者 `bar`。两条路都能读，所以两行 `println!` 都能打印。

顺带把术语说破：**"所有权"**就是"这个值归谁、谁有权把它交给别人"。借用就是"我不接手，只临时用一下"。

## 那这里为什么非写 `&` 不可（补充规则）

原文这一段只提到"前面所有权一节"，没有把那一节的细节带过来，所以下面这条是我补给你的规则：

你从整数来，会觉得奇怪——`let b = a;` 之后 a、b 都在，从来不需要 `&`。原因是**整数是复制的**：赋值会复印一份，两边各自独立。
但 `Foo` 不是整数，是结构体。对这类值，普通赋值 `let bar = foo;` 不是复制，而是**移动**：值从 foo 搬进 bar，foo 被搬空，之后就不能再用。`&` 的作用正好是"别搬，改成借"，于是 foo 还能用。原文也说"这一次，程序可以编译" ——"这一次"暗示了之前那版（没有 `&`）是过不了的。
