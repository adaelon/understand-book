把这段代码摊开看：

```rust
#[derive(Debug)]
struct Foo(u32);

fn main() {
    let foo = Foo(0);
    let bar = &foo;
    println!("Foo is {:?}", foo);
    println!("Bar is {:?}", bar);
}
```

**1. `&foo` 做了什么**

`&` 是 Rust 的借用运算符：在表达式里有位置的值（place）前写 `&`，就产生一个共享（不可变）借用，也就是一个引用；写 `&mut` 才是可变借用。借用的意义是"不取得所有权就临时访问值"——它不是绕过或放宽所有权规则，而属于所有权模型本身。也正因为 `&` 带着有效性约束，它不能简单等同于 C 里不带约束的取地址。

**2. `foo` 和 `bar` 分别是什么**

- `foo` 是变量，类型就是 `Foo`，它持有 `Foo(0)` 这个值本身，**所有权在它手里**。
- `bar` 是变量，类型是 `&Foo`，是一个引用类型；它**借用** foo，自己不拥有那个 `Foo` 值。原文的措辞是："我们借用了 foo，并把借用赋给 bar。bar 的类型是 &Foo，也就是引用类型。"

也就是同一个值同时有了两个入口：所有者 `foo`，以及指向它的引用 `bar`。

**3. 为什么两个都能打印**

区别全在第二行写的是 `let bar = &foo;` 而不是 `let bar = foo;`。因为是借用，foo 的所有权没有被交出去，foo 仍然是那个值的所有者；bar 则是指向同一值的引用。两者都处于可用状态，所以两行 `println!` 都合法。书里对这一点只说了一句："这一次，程序可以编译，因为 main 中的第二行变成了……"这里的"这一次"是相对"前面所有权一节中的例子"而说的对照。

**4. 去掉 `&` 会怎样**

去掉 `&`，第二行就是 `let bar = foo;`。这不再是借用，而是把值**移动**给 bar。`Foo` 只派生了 `Debug`、内部是 `u32`，并不是 `Copy` 类型，所以这次赋值按移动处理：所有权转到 bar 手里，foo 随即失去使用资格（正是你已经掌握的那条规则）。于是 `println!("Foo is {:?}", foo)` 这一行会编译失败，而 `println!("Bar is {:?}", bar)` 仍然合法。

这里的取舍可以这样记：**`=` 右边写不带 `&` 的变量名是"交出所有权"，写成 `&foo` 是"只交出访问权"。**

证据边界说明一下："去掉 `&` 后第一处打印报错"是把书里"这一次，程序可以编译"这句对照（意味着原先的写法通不过）与你已知的移动规则接起来推出的结论；那段"前面所有权一节中的例子"没有随这段文字一起附给我，我没有直接读到它的原文。

**5. 能不能通过 `bar` 修改 `Foo`**

不能。bar 的类型是 `&Foo`，即不可变引用／共享借用，书里明确写着："由于这是不可变引用，我们不能通过 bar 修改 Foo 中的值。"

要经由引用修改，需要的是可变借用 `&mut foo`（原文也提到写 `&mut` 可创建可变借用）。此外还有本段文字未展开的补充条件：变量绑定本身要写成 `let mut foo = Foo(0);`，并且在可变借用有效期间不能同时存在指向 foo 的共享借用。

**一句话总括**：这段代码用一次共享借用，把"移动导致旧变量失效"换成了"所有者和引用并存、而且都能读"；而选了 `&` 而不是 `&mut`，也同时决定了对 bar 只能读、不能写。
