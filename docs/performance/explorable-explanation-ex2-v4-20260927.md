# EX2 v4：递推数值修复

## 运行前冻结（2026-09-27）

候选为 `explorable-explanation-ex2-skill-v4.md`。v3 的“同一计算并检查”没有使实际观察成为文字数值的依据：v1 C3 在 `response-05.json` 的 write 首次引入错误数列，`response-06.json` 保留它，最终进入 readable view；v3 C1 的页面采用正确的 `series(eta)`，错误的 η=0.6 第 4 步首次出现在交付后的 `response-06.json` 最终回答。两者都不是宿主改写或递推公式错误。

v4 只替换数值制作段：页面同一计算结果生成图形与可见数值；用已有 preview 查看将被引用的参数、步数和结果；初稿可读说明先讲规则，核对后才引用具体迭代值；最终回答不另算未观察的新数列。没有增加工具、固定题目的答案或新 Runtime 校验层。

- 共同底座：HEAD `c2ff3e1` 加当前工作树，含已完成 EX6 的 seek 和候选修订说明。此前 EX2 B 仅作历史参照；本批重新运行 B。
- B：生产 `ed3.v1`；C：只在已加载的 presentation method 中替换为 v4。生产保持 ed3.v1，质量 Gate 通过后再决定启用。模型仍为 `.env` 的 `deepseek-v4-flash`、temperature=0、默认每次输出 8,000 tokens；全部输入逐字沿用 EX0。
- 学习率顺序 B1/C1/B2/C2/B3/C3，各自独立会话；全部三次 C 正确且有具体表示收益后，其他三题各跑 B/C 一次。任何 C 内容/数值错误或未交付立即停止本候选，保留失败，不替补样本。
- tokens、墙钟仅实录，沿用用户已接受超限的决定。Provider 错误、未交付、三视口失败和内容错误仍失败。普通短答应直接答，无固定额外回合；非数值题不得虚构因果或制作无意义动画。
- 数值核对：独立闭式 `w_k=2-2(1-2η)^k`、`e_k=-2(1-2η)^k`、`L_k=4(1-2η)^(2k)`。按原文末位精度判定四舍五入。对旧两处错误先做确定性复现；对新产物枚举页面可见读数、readable content 和最终文字的具体算例，保留文字出处与机器核对结果。浏览器运行覆盖 η=0.2/0.8/1.1 及产物实际引用的新参数，多步与边界；不能用仅存在公式替代运行核对。
- 表示收益：明确比较 B/ED3 缺少的关系，例如等幅而方向不同的同尺度比较或步长与距离的同标尺关系；交付页面存在本身不算收益。学习效果尚未评估。

## 结果

B1 交付，7 次模型请求，405,273 tokens，238.133 秒；页面在 7 个学习率的 84 个位置/误差读数通过独立闭式核对，可读说明两组数列共 10 个值正确。C1 交付，5 次模型请求，332,745 tokens，272.108 秒；但最终回答写“现在 w=−5.683……所以下一站跑到 −13 附近”。η=1.2 的 w4=−5.6832，下一站 w5=+12.75648，w6 才是 −13.059072。页面及最终回答后面的表格正确，前面的解释把相邻步骤混淆。

候选 v4 质量失败，按冻结条件停止，未运行 C2/C3 和其他题。生产继续 ed3.v1。错误在模型 `response-04.json` 原文及 `outcome.json.answer` 中，不是宿主转换；首稿 readable_content 也已直接写具体数列，模型没有执行要求的“先观察、再引用”工作顺序。

确定性证据：`node docs/performance/ex2-numeric-check.mjs docs/performance/ex2-windows/historical-numeric-claims.json` 对历史两处错误返回非零；`v4-numeric-claims.json` 中 B1 十个值通过、C1 的下一站失败。浏览器核对用 `ex2-browser-numeric-check.mjs`，历史页面两处读数正确（v3 页面实际保留两位小数，显示 2.00），B1 的 84 个读数通过。核对清单由人工从原文标注参数、步数、量和逐字引文，程序负责闭式计算与精度判定；它不是自动理解任意散文的通用审查器。

原始运行：`ex2-windows/v4-B1-learning-rate/`、`v4-C1-learning-rate/`。同底座 B1 可供后续候选对照；v4 C1 不计入其他候选的稳定性分母。
