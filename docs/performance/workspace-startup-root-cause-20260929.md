# 工作区启动等待根因与修复 — 2026-09-29

## 结论

启动把聊天历史、全书目录标题和画像加载全部串入正文显示的前置链路。聊天历史接口为当前书的所有历史提问生成来源标签，重复执行完整的来源解析；解析期间持有服务端共享 AppState 锁。历史越多，启动和其他并发请求承受的等待越大。

本机真实书籍 `ai-agent-engineering` 有 2,938 个节点、292 个目录项；当前书历史有 33 个聊天、89 条提问，其中 21 条带引用，共 84 个引用范围。当前活动聊天只有 4 条提问。

## 实测

使用书籍和用户历史副本。正式安装版为 `E:/allwork/Understand Book/UnderstandBook.exe`（2026-09-20）；调试服务为 `target/debug/server.exe`（2026-09-27），配合 2026-09-28 的本地前端产物。

| --- | ---: | --- |
| 正式安装版 WebView2 首次加载 | 808.6 ms | Resource Timing：请求发出于页面时间 980.8 ms，响应于 1789.4 ms 完成 |
| 正式安装版直接复查接口 | 801.9 ms | 199,183 字节响应 |

正式版在页面时间 1,811.8 ms 发出 `reader_ready` 用途事件；其前置画像请求在 1,807.1 ms 完成。该时间描述页面初始化，不等于进程启动至首帧的总时间。

原始历史对照中，历史请求发出 100 ms 后并发调用 `/api/desktop/status`，状态接口仍等待 7,468.4 / 6,928.7 ms。去掉提问标签输入后，状态请求仅 1.9 ms。说明历史计算会占住其他 API 所需的锁。

对照只改变临时副本，未更改用户聊天。减少历史响应约 19%（201,045 → 162,408 字节）时耗时降到约 0.19 秒；保留全部聊天并移除标签输入时降到约 0.024 秒，瓶颈集中于来源标签计算。

## 修复前代码链路

1. `packages/web/src/App.vue:init` 在 `appSurface = loading` 后依次等待工作台状态、manifest、资源清单、来源身份、PDF 数据、全部目录标题、阅读位置、视口、论文投影、聊天历史和画像，最后才设置 `appSurface = reader`。已有正文也不会提前挂载。
2. `crates/server/src/lib.rs:agent_history_response` 构造当前会话详情，并对当前书所有历史会话调用 `session_summary`。摘要包含所有历史提问的来源标签。
3. `agent_location_label` 调用 `Book::resolve_source`，最后仅取 `source.label`。完整解析包含叶节点收集和排序、位置表构造、证据文本/摘要、祖先标题、引用预览及周围上下文。
4. `crates/read-tools/src/lib.rs:source_heading_path` 对每个祖先调用 `source_node_text`，将祖先整个 span 从 UTF-16 解码，再由 `markdown_heading` 只取首个非空行。本书根章节覆盖全书，单次标题提取也会解码大段正文。
5. `session_summary` 对带引用的提问先经 `question_source_label → question_quote_view` 生成标签，再单独调用 `question_quote_view` 生成引用视图。`verified_question_evidence` 对逐渐增长的范围逐个调用完整解析，重复计算进一步增加。
6. `crates/server/src/host.rs` 的普通请求在获取共享 `AppState` 锁后调用 `route`；历史投影期间不释放该锁。

## 目录的额外开销

`App.vue:loadOutlineTitles` 为每个目录项调用一次 `/book/text`，等待全部完成后继续初始化。`Book::text` 返回该节点整个 span；前端才从全文中取标题。

本书 292 个目录项对应 292 个请求，标题所请求的原文合计 3,810,281 字节；书本原文只有 1,024,134 字节。祖先与子章节内容重复传输。本机调试测量该批请求约占 525 ms。远端访问时，这些请求还需承担连接队列、网络往返和传输成本。

## 修复方案

- 正文达到可读条件就显示阅读区；聊天历史、画像和目录标题分别加载，不阻塞整页。
- 来源标签采用轻量的标签/标题投影。保留必要的引用合法性判断，把完整预览与上下文组装留给实际打开来源的路径；同一提问的引用视图只生成一次。
- manifest 或一个批量目录接口直接返回标题；标题提取只读所需行，避免请求章节全文。
- 消除历史接口的重复重活后，再依据实测决定是否需要缩短其他共享锁持有区间。

## 修复结果

已完成三个改动：

- `Book::source_label` 与完整来源预览复用同一段证据范围校验，只投影标签，不生成摘要、预览和周围上下文；祖先标题只解码首个非空行。历史摘要中的同一引用视图只计算一次。
- `ManifestNode.title` 随现有 manifest 批量返回目录项首行，前端沿用原来的标题格式处理。当前章标题也复用该数据，不再单独请求章节全文。
- `App.vue` 在正文视口就绪后显示阅读区，历史、画像和论文投影随后独立加载。历史有明确的加载、失败与重试状态；加载期间保留输入草稿，待会话恢复后开放发送与新建对话。切书/卸载会丢弃过时的启动历史结果。Reader 布局按书标识，首次恢复聊天不清除已有选区、不重放布局焦点。
