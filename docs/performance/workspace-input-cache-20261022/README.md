# 工作区连续讲解：输入缓存对照

本轮已实现并完成真实请求测量。固定教学状态切换序列的连续追问输入费用下降 47.49%；完整纯文字讲解链的输入费用与追问首字没有改善，且内容仍有一项科学条件缺口。以下将缓存隔离结果、真实交付与质量限制分别报告。

## 改动与约束

本轮减少教学状态变化引起的工具定义重写。`presentation.author` 保持完整操作定义，当前采样允许的操作进入追加式状态消息；Runtime 在发起采样前冻结相同限制，并在执行时独立检查。未接受演示设计时仍仅允许 read/search，同批提交设计不能提前授权后续操作。

`tutor.step` 中依赖待评估响应、学习者表达是否存在的示例移入当前 learner view。操作定义、必填字段、交互意图限制和 active/observing/reference 权限保持原样。实际来源读取、来源展示门槛、检索结果与讲解正文均未缩减。

## Q1：实际交付发现后的修正

实际付费请求暴露了已接受稿件用同一 `move_id` 改写的浪费：模型完成新的内容审视后，存储才拒绝改写旧事实。现在 Server 的既有 select 预检复用完整事件的不可改写判断，付费审视前即可拒绝冲突；最终事务仍做相同检查。原样重试保持原事实与时间，真正修订使用新 ID，并从待交付集合移除被替代的选择。

审视规则 `teaching-delivery.v24` 明确：会改变关键主张真假、因果方向或必要前提的修订，应作为必须修订的发现；一般润色仍可选。来源引用继续遵守既有可选展示政策，不增加强制引用门槛，不删减原文证据。

5 项 select 服务端回归均通过，包含真实 Runtime → Server 路径：原稿、同 ID 改稿、新 ID 改稿三次选择只产生两次内容审视，最终交付新稿，旧事实不变。日志见 [`server-quality-tests.log`](server-quality-tests.log)。缓存隔离对照两臂共同使用 Q1 指导；完整交付则比较原始 baseline 与最终 Q1 整体改动。精确边界见 [`quality-q1-method.json`](quality-q1-method.json)。

首字以实际公开 `answer.patch` 为准，包含准备、教练和内容审视，不是首个工具参数，也不包含浏览器绘制或音频播放。正文已经核对文件、持久化、交付和最终公开 patch 一致；最后一条自由正文未被选入的改写不替代实际交付稿。原始数据见 [`live-delivery-candidate-q1/complete.json`](live-delivery-candidate-q1/complete.json)、[`delivery-q1-analysis.json`](delivery-q1-analysis.json)，完整质量证据见 [`quality-q1-review.md`](quality-q1-review.md)。

## 对照方法

- 原始修改前 Runtime 源码位于 `baseline/runtime-src`。测量使用同一当前树的两个隔离 Runtime 副本，baseline 仅还原本轮相关函数；同期其他修改在两组保持相同。构造方式见 `capture-method.json`，相关有效源码位于两组 `effective-src`。
- 两份实际 Book 测试材料分别讲过拟合、正则化。经过生产正文读取、结果投影和来源引用登记，再由 `build_sample_request` 及 Native/ReAct 投影生成请求。
- 普通文字讲解和 active Tutor 各包含四问：概念解释、训练/验证数值比较、L2 算例、过强正则化与参数选择。每次追问重建 Run 内上下文账本，只保留原始对话历史。
- 每场景两次重复，AB/BA 顺序；每组与每次重复使用独立前导标记。真实请求保留完整输出，不把新输出写入下一份固定输入。不执行回包中的工具调用。
- 从直接流式 HTTP 响应记录首个非空文本、思考、工具调用的时间。无文本时首文本时间为 null，不能把首工具参数时间算成用户可见首字。
- 费用来自供应商实际 usage 与当次请求适用的价格快照。输入命中、输入未命中、输出分别计价；价格文件按时间区间选择，不使用测试用准入费率。

## 工具稳定性与证据保留

在同一 active Tutor 权限下，连续四问原有的 3 次工具定义变化降为 **0 次**，仍是 20 个工具。Native 工具定义由 91,092 / 109,996 / 91,719 / 109,926 字节变为固定 **109,373 字节**。这些是紧凑 UTF-8 JSON 的字节数，不是 tokens。

两篇当前原文、完整用户问题、固定历史和来源展示结果逐字保留；两组使用相同的真实读取结果与已发布 source refs。Tutor 状态、实际权限变化仍按现有合同处理。没有为了提高命中而省掉正文、证据或解释依据。

Native 的本地 JSON 共同前缀未变长；供应商如何排列 Native 工具定义是内部实现，因此最终以 usage 为准。ReAct 的工具定义位于第一条 system 消息，本轮消除了这条消息随设计及事实引用变化而重写。跨 Run 的历史回执投影仍会截断可复用前缀，本轮未改变该行为。

## 讲解行为与验证

首次候选的缓存收益已经出现，但两次文字公式追问都转去重新设计 presentation，旧版则直接给出讲稿。候选还出现一次来源 revision 错配。该候选没有按质量要求验收。

最终版本把提示明确限定为 `presentation.author` 的操作限制：当前要求文字讲解时继续已接受的文字设计，历史视觉请求不覆盖当前请求；只有当前需求确实需要演示制作时才修改设计。复测中，两版的四个文字请求均返回 `select` 完整讲稿；候选的两次公式追问恢复直接文字解释。算例 0.05/0.09 → 0.15/0.10、训练目标与验证表现的区别、验证选参与测试集边界均保留，没有插入测验或宣称学习者已掌握。所有新讲稿引用均来自实际读取的两篇材料。要求演示的另外四个请求仍只是第一跳准备操作，未计为已交付页面或完整解释。

最终候选 **15 项相关 Runtime 测试通过**：请求录制/工具稳定性 2 项、教学演示与同批授权边界 7 项、Native/ReAct 前缀 2 项、指导切换 2 项、Tutor 示例与权限 2 项。完整结果在 [`scoped-tests-v2.log`](scoped-tests-v2.log)。测量脚本的 7 项本地测试覆盖流式计时、工具增量、usage/分项费用、价格区间、调用上限与禁止隐式重试。

缓存 v2 的 Runtime 全量：**780 passed、0 failed、11 ignored**，详见 [`runtime-final-tests-verified.log`](runtime-final-tests-verified.log)。运行在与当前生产代码一致的隔离 Runtime 副本，静态 fixture 路径按隔离目录补齐。此前确认的六处陈旧测试预期已按当前公共契约修正：证据政策版本、并行新增 `agent.progress` 的工具列表、Web routing card 和 ranked search 样例数量。新增授权边界测试也改为检查真实工具回包，避免误读最终化后已清除的瞬时状态。并行的 progress 公共修正同样同步到两组隔离代码，未纳入缓存差异。

## 限制

这是同一固定对话输入的生产请求构造与真实供应商对照。表中费用和 tokens 是这些主采样的用量，不含实际完整教学循环中的额外审视、工具执行与最终提交调用。来源材料和教学状态是明确声明的测试输入，新输出没有作为下一问历史。这一固定输入实验没有执行真实服务器 RAG、自主工具循环或页面交付。额外交付补测已覆盖默认 Native 配置、真实教学循环与学习事件持久化，但仍是单材料临时 Book；没有验证工作区 RAG、视频、页面制作、浏览器渲染、音频或长期学习效果。

普通控制组的模型输出存在坐标方向颠倒、把 lambda 与训练进程的曲线混淆、把示意 U 形说成必然、过度推断噪声/方差等真实问题。两版普通请求完全相同，这些不是本轮输入变化造成的已证实回归，但质量不能宣称全通过。本轮已修正直接由候选提示引出的多余设计行为，其余既有生成质量问题保留记录。

小样本与网络/供应商负载不足以证明稳定的延迟改善。公共教学答案首字已按实际 `answer.patch` 边界测量，首次更快而追问更慢；不得以首工具时间代替该结果。费用是依据官方价格重算的供应商用量成本，不是对账单。
