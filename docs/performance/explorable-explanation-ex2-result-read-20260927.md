# EX2：读取页面计算结果

## 已确认范围与实施顺序

用户确认将“公式→页面程序→指定参数/步的实际结果→模型解释”作为数值修法。沿用现有 preview、页面状态 reader 和场景定位；不实现通用公式解释器。本轮生产改动是结果读取链路，EX2 实验 skill 的完整自然请求 Gate 仍独立记录。

1. **结果读取**：`preview(read_selector="#result", actions=[...])` 在最后一个动作之后读取唯一可见结果区域；同次浏览器取值中捕获文字、页面 state reader、原生控件值与可用的场景位置。返回绑定 candidate、environment、动作序号。无 selector 时行为不变。
2. **完整投影**：选择性读取返回紧凑的结果与问题信息；保留参数、步骤、数值和精度，不能对这条结果逐字段截断。超出预算时整条结果不返回，并明确要求缩小读取范围。Server 继续执行原来源/语义/布局验证，截图仍交给模型。
3. **使用验收**：用历史 v4 的当前步/下一步读数做浏览器与模型输入回归；验证后使用真实模型读取程序结果并作答，记录准确值与实际调用证据。模型试验前冻结输入、次数和停止条件。

## 验证将检测的具体失败

- 参数能反序列化但未传入浏览器：实际最终区域没有正确数值或步骤，修复传参链路。
- 状态 reader 仍为空回调、读到初始参数或读错动作时刻：改参数后捕获仍是旧参数，修复同步捕获。
- 选择器缺失/多匹配/隐藏、过大结果：不能给出看似成功的结果，返回明确读取错误。
- 通用预算压缩截断结果，或在更小预算下保留半条结果：修复专用投影，参数与值必须整体保留或整体拒绝。
- 原 click/key/seek 或三视口失效：修复新增路径导致的回归。

## 真实模型诊断：运行前冻结

只跑 1 次定向能力诊断 `selected_result_real_model_reads_and_explains`，使用现有 Provider 与 ed3.v1。请求模型自行写小页面，从 η=1.2、k=4 点击一次，用 `read_selector` 读取当前/下一步，再在最终文字逐项解释 η、k、w，三视口后交付。完整输入固定在测试源码，运行保存 input.json；请求不含预期数值。

通过要求：实际工具调用使用新参数；后续模型请求收到完整 reading；独立闭式解核对页面与最终文字的数值和步号；成功交付。错误或未交付即保留结果并停止，不补抽样。该诊断验证新链路可用，不能替代 EX2 自然输入的三次 C 与跨题 B/C Gate。原始证据目录 `ex2-windows/result-read-D1/`。

## 诊断结果

一次运行通过：`deepseek-v4-flash`，8 次模型请求，290,566 tokens，138.122 秒，已交付。最终回答明确给出 η=1.2、k=5、w5=12.756480，下一步 k=6、w6=-13.059072；同时正确引用 k=4 的默认状态与各步误差。

首次候选有页面 bug：公式处遗漏 `etaFixed` 元素，render 中断，按钮已令 state reader 返回 k=5，但结果文字仍为 k=4。`request-03.json` 同时包含失败状态、异常、reading.text 与 page_state；模型在 `response-03.json` 明确识别状态/读数错位，下一轮重写候选。修订候选通过三视口，`request-06.json` 收到完整且 `truncated=false` 的 reading，随后 deliver，`response-07.json` 形成最终回答。没有修改模型生成代码或原始记录。

这次观察证明新结果对象既可作为数值引用来源，也暴露“页面状态已变、显示未更新”的真实缺陷；读取本身不证明页面计算正确，数值仍由独立闭式核对。
