# 附录 F 章节与面试问题对照

面试准备可以从一条完整请求开始：读者提出什么要求，系统取得哪些事实，谁执行动作，结果保存到哪里。下表帮助你在追问出现时回到对应章节。每行的回答主线来自正文，条件变化题则要求重新判断原假设是否仍成立。

## 把多章知识组织成一次回答

准备AI Agent方向时，可沿第9—13章串起一次请求，再用第17章解释制作与版本，最后用第21、23章回答效果怎样判断。关键是说清模型在每次采样前实际知道什么，哪一步由程序决定，哪一步仍需要语义判断。

准备后端架构方向时，可由第3章的归属进入第16、18、19章：问题如何被接纳，模型等待时谁能修改状态，结果怎样回到原聊天，保存不明时怎样恢复。再用第20章说明这些权威如何部署到真实目录和进程。

构建方向可以从第4章的一段原文走到第8章发布，再用第23章的交接与候选失败说明恢复。检索与评测方向则连接第6、21、22章，保留不同消费者和不同实验的分母。

练习时先讲清一个当前机制，再选择一条真实失败解释它为何重要，最后改变一个条件。源码选读见[附录B](B-源码阅读路线.md)，结果依据见[附录E](E-运行验证与实验入口.md)。历史成功、固定响应通过、源码推导与教学假设沿用正文标记，不将它们拼成一项新的实测成果。
