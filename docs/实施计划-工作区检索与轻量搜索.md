# 工作区检索与轻量搜索

2026-10-22。状态：代码实现与本地定向验证完成，尚未生产部署。

## 决策与范围

工作区提供词法与本地多语言向量混合召回；普通单篇优先直接读取，未知位置用轻量相关性搜索。现有字面出现查询保持原合同。复用现有本地 embedding provider，不采用 DeepTutor 代码。

新增 `book.search` 返回单篇词法相关候选；`library.search` 仅搜索当前运行冻结且仍获授权的工作区资料。候选不是证据，必须沿原文读取、本轮证据账本和来源引用交付。来源、发布与 LID 继续使用既有身份。

本轮不改变导入和正式 Tutor 准入，不实现语音或新的快讲界面。索引不要求语义预构建；本地模型缺失时明确报告语义检索不可用并保留词法搜索。

## 实施

1. read-tools：有界正文窗口、中英文词项与 BM25，懒索引内存纳入书库预算。
2. Core：复用已安装多语言 MiniLM，按真实 tokenizer 分段、发布版本缓存及常驻 JSONL 查询。
3. Runtime/Server：工作区混合召回、授权与成员过滤、完整下一步读取调用、发现与结果预算。
4. 工具合同：Resident/MCP/REST 同一单篇输入与结果，生成文档保持一致。

## 实际调用

| 场景 | 路径 |
| --- | --- |
| 已选中的文章段落 | 直接 `book.text`，沿现有解释与引用链交付 |
| 单篇文章中未知位置的相关内容 | `book.search`，中英文词法排序，不启动向量模型 |
| 精确词句、出现次数或前后一次 | 原 `book.search_text` |
| 工作区多份资料中的相关解释 | `library.search`，BM25 与向量候选按排名融合，再 `library.read operation=text` |
| 视频中的相关讲解 | 检索已保存转写，原文读取后复用现有时间来源；需要画面或原声时沿现有媒体工具读取 |

工作区检索首次遇到某个发布时按需创建向量索引，后续复用；不要求先做全书知识图谱、教学资产或语义预构建。新工具本身也不改变现有上传准备流程和正式 Tutor 准入。模型、分段版本、发布版本或来源版本不匹配时重建派生索引。

## 模型配置

服务进程设置 `UNDERSTAND_BOOK_EMBEDDING_CONFIG` 为现有本地模型配置 JSON 的路径；必要时用 `UNDERSTAND_BOOK_NODE` 指定 Node。配置示例已经加入根 `.env.example` 和 Linux Reader 环境模板。配置形状沿用现有 provider：

```json
{"version":"local_embedding_config.v1","runtime_dir":"/path/to/runtime","model_dir":"/path/to/model"}
```

修改模型配置后重启服务。模型常驻于查询子进程，派生向量保存在服务数据根目录的 `shared-cache/workspace-retrieval`，不写入不可变发布。配置缺失、模型不可用或嵌入失败时，返回 `retrieval.semantic.status=unavailable` 与原因，仍提供可用的词法结果。成功时为 `ready`，同时报告本次真实 tokenizer 输入量、嵌入段数与缓存复用量。

本地 embedding 没有外部 API 请求费用，用量保留在检索结果中；本轮不新增一份聊天计费。

## 验证目的

- 原文字面查询不能被相关性搜索改变：复用原 search_text 测试。
- 相关结果不能串资料、越过章节或读错 UTF-16 位置：用可执行 next_calls 回读验证。
- 搜索候选不能直接成为引用：走真实搜索、读取与 source.present 链。
- 工作区成员冻结、撤权和版本必须保持：复用跨资料测试加入搜索路径。
- 语义检索须真实找回中英文异词同义内容：使用已安装模型与原创样例，并分别记录首次索引和缓存查询。
- 模型缺失和输出预算不足要保留诚实状态与可执行结果，不能伪装混合检索成功。

## 结果

- Core 的 7 项定向测试及类型检查通过：真实 tokenizer 分段、长查询、UTF-16 位置、索引身份失效、缓存复用、失败恢复。
- Book 工具合同 13 项测试通过，相关性搜索输入与原字面出现查询保持独立。
- read-tools 的 8 项检索测试通过；普通词法查找合同另行保留回归覆盖。
- 原创跨语言样本：中文口语问题找回英文过拟合解释第一名（0.561）；英文问题找回中文正则化解释第一名（0.699）。真实 JSONL 常驻进程首次启动并索引首份 3 段资料约 3.025 秒；热查询 14.7 ms。已加载模型加入第二份 3 段资料约 58.2 ms，第二范围热查询 23.6 ms。
- 真实长输入：7,995 UTF-16 单位的源叶完整分为 16 段，最大 126 tokens；928 UTF-16 单位的查询完整分为 5 段，最大 123 tokens；末尾相关解释被排在第一，绝对范围为 7859..7995。
- 词法成本样本：4000 段、425,780 UTF-16 单位，Windows debug 构建首次索引与查询 679 ms；稀有词热查询中位 147 µs，4000 候选常用词热查询中位 11.313 ms。结构 payload 约 3.54 MB，准入估计约 8.36 MB。
- 服务端 `search` 筛选 24 项测试全部通过，包括 REST/MCP 参数与结果一致性、工作区成员与撤权、版本保持、锁外推理、候选回读，以及原有字面查询回归。
- 显式配置本机模型后，Rust → JSONL → 真实模型 → Rust 的桥接测试通过；第二次调用复用三个既有向量，不再嵌入文档。
- 工具参考已从实际注册表重新生成，文档生成器 7 项测试通过；新增结果类型的两项 TypeScript 导出通过。
- Runtime 的候选裁剪、来源隔离和闭合输出 schema 测试通过；工具发现、可见性与上下文预算的 42 项定向回归全部通过。公开示例执行与能力映射各 1 项测试通过。

新增相关性搜索保留独立工具名额，原有书籍结构能力仍可发现和调用；模型工具 schema 字节预算继续有效。候选结果按整条命中及其读取参数一起裁剪，不把残缺定位交给 Agent。

## 已知边界

上述性能来自本机原创小样本，不能外推为整本教材或完整工作区的响应承诺；首次为整个所选范围建索引仍与资料量有关。视频检索对象为已有转写，不对未读取画面或原声作内容断言。相关性排序不保证穷尽所有语义相关段落，搜索预览不能直接作为引用。当前没有更改运行中服务的模型配置或执行生产部署。
