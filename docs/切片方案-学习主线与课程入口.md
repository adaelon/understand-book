# 切片方案：学习主线与课程入口

日期：2026-11-16。状态：**LE0 文档完成；LE1–LE4 已实现并通过定向工程验证；LE5 真实模型样本未通过，首次使用者待验收。** 决策见 [ADR-0184](adr/0184-task-led-learning-entry-and-continuity.md)。本方案复用已有课程、统一问答和闭卷练习，定义入口、课内任务、反馈回课与下次接续的调整；第 5 节记录各切片的实际状态和证据。

## 1. 目标与首条交付路径

首次使用者能够找到一门实际可学的课，接受已展示目标并直接开始；学习中知道当前要做什么，表达后获得具体反馈；离开后能回到同一任务。使用自己材料的人可以从当前内容直接请求讲解，再选择表达或练习。

首条交付路径使用已有正式课件和私人课程实例：

```text
学习首页 / 课程入口
  → 看懂目标并开始第一课
  → 完成当前讲解、阅读或探究活动
  → 表达或应用；需要时显式进入闭卷练习
  → 反馈、补教与适用的独立尝试
  → 由原课程接纳表现，显示下一任务
  → 暂停离开
  → 首页继续同一任务、问题和已保存现场
```

首个样本优先使用项目已有《深入理解 AI Infra》资源下界课程，其多轮活动、实验、解释和最终任务可覆盖主路径；以实施环境中实际可访问的发布版本为准。自带材料路径使用已准备的文本材料。课程题面、揭示顺序和独立表现要求沿原合同。

交付时，页面流程、后台状态和真实教学回应须在同一学习范围贯通。以首次使用者无需旁人指路即可开始、知道当前任务并在返回后继续作为体验完成依据；具体模型反馈还需由原话与来源支持。

## 3. 用户行为与界面合同

### 3.1 学习首页与开课

学习首页以一个明确的主行动组织首屏，按实际状态呈现：

| 用户当前状态 | 首屏主要内容与动作 |
|---|---|
| 有未完成课程、练习或补学 | 当前目标、上次停在哪里、这次要做什么；“继续回答”“继续本课”或“继续练习” |
| 没有未完成任务，有可用课程 | 可直接开始的课程卡；目标、建议基础、已有预计时长和“开始第一课” |
| 有自己的材料，尚未开始学习任务 | 所选材料与“带我学这一部分”；同时保留直接提问和阅读 |
| 没有可用课程或材料 | 真实空态与“添加自己的资料”，沿现有流程确认目标和准备材料 |

“课程”成为稳定的一级入口，课程列表展示已有可用内容；用户可以查看路线和选择另一课。公开课程目标在开课按钮附近可见，点击即接受所展示目标，用户可就地修改。考试日期、范围与日程在选择备考时展开。创建或取得原私人实例后直接进入所选课的实际第一项任务；已有进度提供继续及明确的重新开始操作。

仅包含材料或公共路线的共享发布保留其资料用途。课程不可用时展示实际原因和可执行的下一步。宣传首页的体验入口连接真实课程；需要登录时保存所选课程，完成登录后接回原选择。

示例文案用于说明信息层级，实际标题、目标与时长取自课件：

> 判断任务受算力还是带宽限制  
> 通过讲解、实验和独立判断，理解该优先升级什么。  
> 开始第一课 · 查看课程路线

### 3.2 课内当前任务

课程顶部保留主问题和当前轮次，主要学习区域说明本段目标及当前动作。阶段名可按真实活动显示为“先猜一猜”“观察或取证”“我来解释”“应用一下”；主按钮绑定原课程动作。当前轮已有独立任务时直接使用，阅读、实验和反馈按原顺序交付。

完整课沿原 20–30 分钟编排及实际内容调整，在已有轮次提供暂停点。用户始终能看清这次要说明、判断或完成什么，课程路线作为次级导航。先猜后验课程保持预测在结果揭示之前；材料中的推导、条件与最终应用目标保持连贯。

普通学习现场按任务提供原文、实验和答疑；作答区域突出当前唯一待答任务。右侧插问用于求助和讨论，返回继续原任务。闭卷期间由现有专用视图提供作答，退出时恢复课内输入与现场。补学显示正在补什么及“回到原问题”。

### 3.3 讲解后的表达、练习与闭卷约定

入口位于相关讲解或当前任务附近，名称与点击后的行为一致：

| 动作 | 开始行为与结束方式 |
|---|---|
| 带我学这一部分 | 采用当前选区、章节或已选材料范围，沿统一问答请求一个可开始的重点；先交付讲解或探索任务 |
| 我来解释一下 | 从已讲目标进入表达；持续闭卷形式在动作附近展示“收起资料，按回答追问或补讲，可随时暂停”，点击后沿“练到会”保存约定并交付首问 |
| 给我一道应用题 | 沿现有普通练习合同提出当前目标的新情境题，等待回答并反馈；用户可进一步选择“练到会” |
| 练到会 | 显式接受当前有限目标内的闭卷持续练习，按 ADR-0183 保存帮助、独立尝试与结束依据 |
| 这一步没跟上 | 根据所指内容直接补讲，或进入原课程的短补学支路，再回到原任务 |

表达邀请只在有已交付内容或明确任务时出现；目标采用确切讲解、课内活动与材料范围。缺少会影响选题的对象时澄清该对象。已有待答问题时恢复原问题；尚未交付问题时实际请求首问，失败保留目标并允许重试。

“练到会”从学习记录分类移到学习动作，知识树、理解和历史仍提供回顾入口。桌面、窄栏及手机使用相同动作含义。用户可直接提问、请求完整讲解和暂停；当前明确请求沿原统一问答及闭卷选择处理。

### 3.4 反馈、回课与结束

反馈用本次真实原话说明已经成立的部分、需要补充的具体关系以及下一步。用户表达充分时收束；存在缺口时针对缺口提问或补讲，实际帮助保留在记录中。补教后的独立尝试沿 ADR-0183 使用尚未被代答的判断。教师判断有误或题目缺条件时先修正问题与反馈。

闭卷结果回到进入时的课程任务，按下列合同处理：

| 结果与原任务的关系 | 回课行为 |
|---|---|
| 证据完整满足原任务的既定要求和帮助条件 | 原课程判断链接纳引用，显示“本段已完成”及原规则允许的下一动作；已接纳的同一要求直接复用 |
| 当前目标已完成，原课程另有观察、解释或新情境要求 | 明确说明已经做到什么、尚需完成哪一步，定位该步骤 |
| 暂停、退出、求助后仍待独立验证 | 保留未完成状态，返回原位置或继续当前尝试 |
| 结果与进入任务的目标或版本不匹配 | 保留结果的原归属，回到原课程实际待完成任务 |

接纳使用原 CourseRun 的任务、评估与帮助事实，提交成功后才更新页面进度；失败时保留已交付结果并可重试。实现阶段需接通“闭卷结果引用 → 原任务判断 → 原课程动作”的具体路径，当前闭卷结束事件本身仍只说明该模式内目标的结果。

结束卡分别显示“完成了哪一段”和“本次能够独立解释／在帮助下完成了什么”。有依据时给出一项可继续的任务，并提供“今天先到这里”；学习进度、当次表现和以后复习中的表现沿各自事实更新。

### 3.5 首页接续与失败恢复

当前任务指原课程、闭卷尝试或具体对话学习请求的读取投影。首页按用户最近明确开始或继续的未完成任务呈现主卡，其他任务可切换。后台反馈整理、课程目录浏览和查看历史均不改变这次选择。已完成或明确跳过的任务转入结果／回顾入口；没有未完成任务时可恢复上次阅读或开始新课。

普通对话以已交付的待答问题或用户明确选择的下一步确定未完成状态；其余对话归入最近学习，点击后恢复原聊天与已交付内容。

点击继续定位原工作区、材料版本、课程运行或聊天，再恢复活动、题目和已保存草稿。课程内有闭卷或补学时先恢复该子过程；暂停中的任务由明确继续动作恢复。页面加载与普通导航只读取状态，已交付的问题直接恢复；确需下一问时沿原用户动作请求。

接口读取失败时保留选择并提供重试；已归档、材料不可用或原任务不可继续时明确说明原因，允许恢复归档或选择其他实际可用内容。用户不会因打开另一材料而丢失原接续引用。

云端任务按原账号与私人工作区接续，本机任务按本机原归属恢复。未提交草稿沿已有设备与尝试存储范围保存；其他设备恢复任务及已提交事实，草稿可用性按原能力展示。

### 3.6 视觉与用语

沿现有暖色阅读风格、字体和组件层级设计。首页突出当前任务与可开始课程；课内突出目标、实际学习内容和主动作；反馈紧邻所回应的表达。桌面保留按需阅读与答疑，手机让当前问题、输入和主要按钮在软键盘出现后仍可定位。

对外动作采用“开始第一课”“继续回答”“我来解释一下”等学习语言；设置保存偏好，记录提供回顾。新增文案同步 `packages/i18n/src/en.json`，英文模式的请求语言和原始资料显示沿现有规则。

## 4. 状态与执行边界

| 内容 | 原所有者与本次职责 |
|---|---|
| 公开课程、目标、建议基础和时长 | 原课程与 WorkspaceRelease；目录读取实际发布及可用状态 |
| 接受目标与私人实例 | 原 LearningWorkspace 和共享实例 API；开课动作接受可见目标，复用已有操作回执 |
| 当前课、轮次、阶段与原任务结果 | 原 CourseRun；首页及结束卡读取它已接纳的状态 |
| 闭卷目标、问题、帮助和尝试 | 原 ClosedBookPractice、teaching_trace 与其课程／对话绑定；恢复和回课引用原事实 |
| 用户原话与具体反馈 | 原聊天、课程表达和 LearningEvidence；反馈接纳与摘要保留引用 |
| 首页最近选择 | 沿既有私人接续存储保存目标引用及用户开始／继续的时间，内容从原记录读取 |

首页投影只需携带目标标签、当前动作、原范围与目标引用、状态及必要恢复位置；优先从已有持久记录读取，缺少首页选择信息时补最小接续引用。列表按当前展示范围读取摘要，完整题面、聊天和课件在进入任务时加载。

开课、课程推进和闭卷操作沿各自现有提交与重试机制。创建实例成功而开课失败时保留该实例和所选课，重试接续未完成步骤。完成反馈及任务位置以服务端接纳结果为准，页面通过已有身份和版本读取恢复。

课程浏览、首页摘要、显示切换和恢复已交付内容由宿主处理；新的解释、首问、答疑和反馈沿现有模型执行与计量路径。实施时观察完整学习段的回合、等待与调用量，去掉导航引起的重复生成。

## 5. 切片顺序与完成依据

各实现切片包含本身涉及的服务端、界面、中文／英文文案和定向验证，交付一条可实际操作的路径。桌面与手机的关键操作在对应切片验收。

| 切片 | 可交付结果 | 依赖 | 状态 |
|---|---|---|---|
| LE0 | 决策、行为合同与既有文档衔接 | 本次确认 | 文档完成 |
| LE1 | 从首页发现一门现成课程，开始、暂停后继续同一课内任务 | LE0 | 已实现；真实服务开课、失败重试、刷新与原任务接续通过 |
| LE2 | 课内当前目标、阶段主动作、具体反馈与下一步清楚可见 | LE1 | 已实现；组件验证及实际预测—实验—解释入口通过，完整教学质量随 LE5 验收 |
| LE3 | 从讲解进入表达／练习，闭卷结果回到原课程判断并继续 | LE2 | 已实现，存储与协议验证通过，真实模型回课尚未通过 |
| LE4 | 自带材料的直接学习入口，以及课程、闭卷、补学、对话的统一接续 | LE1、LE3 | 已实现；原范围恢复、取消重试、闭卷三视口及真实课程接续通过，学习效果随 LE5 验收 |
| LE5 | 代表课程真实模型与首次使用者验证，记录实际完成范围 | LE1–LE4 | 已执行一个模型样本，未通过；首次使用者待验收 |

实际测试、浏览器截图、模型原话与已发现问题集中记录于[实施记录](实施记录-学习主线与课程入口.md)。

### LE1：课程发现、开课与第一次接续

调整学习首页、课程导航和 SharedWorkspaceCatalog 的入口；展示可用课程目标，点击开始即接受或使用用户修改的目标，建立／取得私人实例并进入所选课。已有课程按原进度继续；实现同一课内任务的首页摘要与明确恢复。空目录、自带资料入口、课程不可用与开课失败使用实际状态提示。

完成依据：无私人工作区的用户可从首页开始一门真实课程；学习一段并暂停后，重新打开页面能够继续原活动；多资料工作区不会恢复到第一份无关材料。开始过程失败后的重试沿原实例接续。主路径在桌面、手机和两种界面语言下可操作，课程浏览和已交付活动恢复不产生模型调用。

### LE2：当前任务与反馈后的下一步

在同一课程播放器中突出主问题、当前段目标和阶段动作，利用原轮次与暂停能力形成可收束的学习段。统一课内作答、活动内反馈、补学返回和结束卡的指向；原文与实验保持相应教学用途，结果按原揭示顺序出现。

完成依据：真实课程完成预测／阅读／实验、解释、反馈与下一段接续，用户在每个阶段都能指明当前要做什么。充分表达直接被承接，求助得到针对性支持；已有反馈准确区分进度、受助表现与独立表现。暂停、刷新和回看不改变当前轮的草稿、参数及待答身份。

### LE3：表达、应用与闭卷结果回课

把“我来解释一下”“给我一道应用题”和“练到会”接到已交付讲解或任务附近，移出记录分类。普通应用题沿练习合同；持续表达练习按可见说明显式开启闭卷，沿原状态交付首问、补教和独立尝试。实现结果引用进入原课程判断及回课动作。

完成依据：一项概念解释和一项应用任务经真实前后端完成进入、求助、独立重试、结束与回课。已满足的同一课程要求经原规则接纳后直接继续；另有迁移或观察要求时准确定位剩余任务。闭卷通过本身不会跳过原课程要求。普通提问和普通应用题保持原结束方式。

### LE4：自带材料与跨入口接续

阅读空态提供“带我学这一部分”，利用当前选区、章节和已有 LearningPurpose 规则沿统一问答发起明确请求；讲解后复用 LE3 动作。将首页接续扩展到同课的闭卷、补学和实际对话目标，恢复原问题、帮助与可用草稿，并统一网络与本机受支持入口的操作含义。

完成依据：没有现成课程的文本材料也能完成讲解、表达与反馈；在课程、闭卷和补学中分别离开后，首页继续恢复到原来的子过程。普通对话接回原聊天与已交付内容。云端重开／换设备恢复已提交事实，本机重启恢复本机任务；后台整理和历史浏览不替换用户最近开始的任务。失败重试保留实际归属。

### LE5：真实首次使用与教学质量

复用前四片已通过的工程证据，用同一正式课件和当前配置模型完成一轮完整学习，并请符合课程起点的首次使用者实际操作。记录其选择入口、理解当前任务、作答、使用反馈和离开后接续的过程；发现迷路、重复作答或无效追问时修正对应环节。

真实模型记录题面、原话、帮助、反馈、原任务接纳、回合等待和既有调用费用。核对反馈是否承接已说清部分、是否针对真实缺口、补讲是否正确，以及充分回答后能否结束。首次使用者或模型条件尚不可得时保留待验收状态；实际完成范围和问题记录到现有证据目录并从本节链接。

## 6. 验证安排

以下是实施时的定向验证安排；当前已执行范围和结果见实施记录。每项用于定位会改变下一步修法的具体失败。

| 场景 | 要发现的失败 | 失败后的处理 |
|---|---|---|
| 新用户从首页选择已有课程并开始；开课请求失败后重试 | 仍被送回创建／资料页、丢失所选课或重复建立实例 | 调整目标接受、原实例回执和课程导航衔接 |
| 多资料、多课程间开始／暂停，再从首页继续 | 打开第一份资料、错误课或过时任务 | 修正当前任务选择及原运行／聊天引用 |
| 当前轮预测、实验、解释、反馈与回看 | 提前揭示结果、多个待答主入口或阶段指向不清 | 调整播放器的状态投影、主动作与回看显示 |
| 概念解释、提示后作答、变式独立尝试 | 把受助回答当成独立、忽略等价表达或答对后继续加码 | 修正本次目标、实际帮助与语义反馈接纳 |
| 闭卷完成后回课；原课另有迁移要求 | 已满足要求被重复询问，或直接越过剩余课程要求 | 修正证据回传与原任务判断／推进路径 |
| 闭卷／补学中暂停、刷新、回到首页再继续 | 丢问题、草稿、参数或原任务返回点 | 修正原恢复引用、显示状态与局部草稿恢复 |
| 自带材料的讲解与普通提问 | 无课程无法开始，或普通问答被强制转成持续练习 | 调整内容范围与统一问答的入口映射 |
| 桌面、窄栏、手机软键盘及英文长文案 | 主要动作难找、输入被遮挡或布局溢出 | 修改相应组件的布局、文案和焦点行为 |
| 页面加载、课程浏览、已交付内容恢复与一次完整学习 | 导航重复生成问题，或无效追问增加等待与费用 | 复用已交付状态，修正请求触发和追问目的 |

纯状态、操作归属和课程接纳使用原单元／服务端测试；多组件恢复与交互使用真实浏览器和实际服务，模拟服务的验证单独标明。真实语义以原材料、问题、用户原话及帮助事实判断。视觉验收直接查看桌面和手机关键页面，采用现有 1366/1440 与 390/320 宽度中符合修改范围的场景；相关检查通过后，仅对新改动、失败或仍未解决的具体疑点复验。

首次使用观察重点是用户能否自主开始、知道当前任务、利用反馈并回来继续。教学反馈的正确性与闭卷收口另按上述具体表现判断；实施不预设未经实测的点击率、时长收益或学习提升数值。
