# ADR-0171 全量 Agent 成本与固定百分比额度

日期：2026-10-18。状态：已接受；Q1–Q5固定基准、成本归属、外部构建预算/回执、百分比界面及任务汇总已实现，W2/W3运行来源、B1运营父预算与B2逐次模型计量已接入统一账本；执行验证状态统一见[切片方案](../切片方案-目标工作区与统一Agent额度.md)。行为合同见[设计方案](../设计方案-目标工作区与统一Agent额度.md)。

## §1 成本覆盖与承担方

**决策**：全量执行记成本，按实际承担方归集。
**否决**：只统计最终回答；会遗漏压缩、后台记忆、重试和预构建。复用公共成果时重复分录整次构建费用；会扭曲实际成本。
**命门**：用户服务使用账号额度，公共准备归平台；外部执行器需提供预算准入与可核算回执，未知和估计保留各自状态。实际成本、账号扣减和付款沿 ADR-0156 分账。

## §2 百分比基准

**决策（2026-11-08 修订）**：后台填成本预算，读者看本期剩余比例。

**否决**：把内部固定标准的倍数称作“剩余额度”；加购后显示超过100%会使用户误解。让运营为每个账号手填版本号和换算值，会造成重复配置与冲突。

**命门**：余额概览的100%为本期累计净授予预算，剩余先扣除实际消耗及在途、待核算占用；补充后重算比例，不改金额。历史明细和已经确认的任务上限仍按原期固定标准；界面明确区分历史计量与当前剩余比例。新套餐与独立赠送预算由系统生成内部换算标识，初次授额为100%；不同商品可配置不同成本预算，不再要求统一目录分母。旧商品、已售权益、精确整数结算与真实收款事实保留。

后台操作分为套餐开通/续费、补充本期预算、全局商品配置；独立赠送在一个事务中建期并授额。加购只增加当前期预算，新期不结转旧余额。实现与验证见 2026-11-08 记录。

## §3 额度与任务预算

**决策**：前台、后台与构建遵守同一费用准入。
**命门**：父任务预算约束后续发送且不额外扣账；个人构建最终用户扣减以确认上限封顶，完整成本照实记录，超出部分归平台。每次发送预占与结算，停止保留结果；未发送释放，未知留待核算，补额度后显式继续，重启不重发已完成调用。

## §4 外部执行的结算层级

**决策**：一次执行固定一个结算层级。
**否决**：执行总额与内部调用都扣账；会重复计算同一成本。
**命门**：受信执行器沿管理员入口提交预算、逐次准入和费用回执；整次执行重试与内部传输重试各有实际发送身份。并行准入与结算分别在同一账本事务完成，待核算仍占用预算，部分用量只留估计证据。提高上限需同一任务的新确认与当前版本，原确认及费用保留；人工核算也遵守上限，免扣后的迟到回执只补真实成本。当前不可约束预算的外部执行器只用于平台准备，个人付费准入要求完整计量和预算能力。

## §5 运营构建的共享父预算

**决策**：B1运营任务的多个资料构建绑定同一个平台父预算，调用沿原Q3账本准入与结算，Q5按同一任务汇总。
**命门**：计划准备和已有成果复用不启动模型；首次确认保存原构建创建身份，提额保留新预算确认而不重新创建已存在的构建。部分费用保留待核算占用，完成成果导入、发布及用户使用不重复生成构建费用。平台任务的预算限制后续准入，供应商实际费用仍按完整依据记录。

## §6 个人准备的逐次模型计量

**决策**：个人书籍准备使用DSH的`provider_calls_v1`，真实`llm/stream`边界逐次准入和提交用量，服务端按冻结费率结算；任务固定发起账号与工作区，用户确认百分比上限和额度期。
**否决**：将原粗粒度部分回执标为完整个人计费，或同时计算执行总额与内部调用；前者缺费用依据，后者重复扣账。
**命门**：输入、缓存读取、缓存写入和输出按实际供应商合同归一；缺用量仍待核算，传输重试各有调用身份。额度期变化须明确继续确认，迟到回执及历史百分比仍用原期；本地持久回执重传不重发模型。个人视频本地转写不产生模型扣减，原CLI完整语义预构建继续归平台。

本 ADR 扩展 ADR-0156 的运营任务归属及用户呈现，沿用其额度期、分账、恢复与人工收款。远程 Book MCP 次数合同仍由 ADR-0162 持有，边界见设计方案 §10。
