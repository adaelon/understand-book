# ADR-0177 个人想法演进与教学召回

日期：2026-10-30。状态：**已接受；PN1–PN6、服务端 MiniLM 与首页入口调整已于 11:50 HKT 合并上线。** 用户已确认以个人想法为核心、低成本表达、灵活使用、需要时主动召回并影响教学，以及保留想法演进。本文确定架构决策与边界；接口、切片顺序、完成判据和实施状态以[切片方案](../切片方案-个人想法演进与教学召回.md)为权威；场景解释、现状与源码依据见[原设计方案](../设计方案-以个人想法为核心的笔记与学习.md)。

## 背景与目标

现有私人笔记已经保留用户正文、资料或助手摘录、确切材料关联及演示现场，但对象身份仍附着在 `Record.mem_id` 和必填材料上。正文编辑或重锚改变身份，`note_replacements` 解决旧入口导航，未保留完整正文修订。笔记在阅读器中能够保存和找回，普通笔记召回仍主要依赖 Agent 主动调用且限定当前材料。

系统另有原始用户表达、帮助条件、理解假设和学习接续能力。它们能够指导主 Agent，却不能代替可编辑的个人笔记，也不能据笔记存在、保存次数或检索排名认定用户掌握了内容。用户要求把自己的想法作为学习的持续起点：想法可以粗略、位置灵活，后续讨论会修正想法，以后需要时系统能找回并接着教。

本决策建立一条完整路径：**就地表达 → 保存稳定笔记与修订 → 当前问题主动召回 → 主 Agent 据此选择支持 → 新表达与旧想法接续**。第一份可用交付必须走通这条路径；跨材料召回属于核心交付，不推迟到高级整理或画板之后。

## 决策

### 1. 个人笔记归用户，内容与使用位置分离

**决策：同一想法以稳定个人笔记持续存在。**

在现有 `MemoryStore → MemoryDocument` 私人存储内建立 `PersonalNote`，使用稳定 `note_id`，不依赖当前书籍、出版物、学习工作区或目标才能创建。笔记内容由这一个对象持有；不在阅读器、聊天、画板和理解空间分别维护可编辑正文。

| 对象 | 职责 | 必须保持的边界 |
| --- | --- | --- |
| `PersonalNote` | 笔记身份、创建时间、当前修订及其修订集合 | 内容编辑、切换材料、移动展示位置不改变身份 |
| `NoteRevision` | 一次正式保存的正文、可选标题、内容来源、保存时间及明确引用 | 保存后不可覆盖；原话可以完整回读 |
| 记录情境 | 当时已确定的材料、选区、位置、回合、视频时刻或演示回执 | 可缺省；发生位置不能直接证明观点来源或理解程度 |
| `NoteRef` | 笔记身份与可选修订号 | 当前笔记导航可解析最新版本；历史讨论、反馈和已交付作品冻结确切版本 |
| `NoteLink` | 两条笔记的联系、可选联系说明及建立时所据修订 | 联系归用户，不因画板关闭或移除卡片而消失；缺省说明仅表示关联 |
| 设备草稿 | 正在输入的正文、原情境、编辑对象和基础修订 | 用于恢复未提交表达，不是已保存笔记版本或教学输入 |

材料、工作区和画板均可引用同一笔记。正文批注、PDF 放置和画板卡片位置由各自宿主持有；移除一处引用只移除该处使用，删除笔记使用明确的笔记操作。删除原对象及其派生索引后，当前列表和召回不再提供该笔记；已保存会话或交付中的原话快照仍按原历史保留，其引用目标可标为已删除。保留版本历史不构成删除后的搜索入口。不同位置编辑同一笔记时，保存携带基础修订，以便保留本地文字并让用户处理已变化的版本，不能静默覆盖另一处修改。

笔记继续使用现有本地用户或网络账号的私人目录和原子提交。个人笔记不进入共享出版物或公共发布缓存，也不因增加该对象自动上传本机数据。正式 Windows 产品继续沿 ADR-0173 的云端 Agent 边界；登录和自动召回不使本机与云端私人存储互通。用户主动发起讨论时，可沿既有发送范围提交所选笔记和相应上下文；这不授权上传本机整库或自动转移原材料。笔记等学习成果沿 ADR-0173 保留学习记录归属，保存不受原材料上传空间套餐限制。这里不增加独立思想数据库、通用同步平台或第二套事务系统。

### 2. 正式保存追加修订，演进视图直接读取原记录

**决策：保留每个已保存阶段及其真实变化背景。**

用户完成一次正文、标题或内容来源有变化的正式保存，追加不可覆盖的 `NoteRevision` 并更新当前修订。重复保存相同内容、草稿自动保存和仅移动位置不产生正文修订。创建或修订的网络重试沿操作身份及回执去重，不依赖正文相同推断是否为同一次用户操作。

日常打开显示当前内容；“思考过程”组合首次保存、后续修订及明确关联的讨论。用户能读任一版本完整原文、对照任意两版增删改、回到当时实际存在的来源，并从旧版继续编辑。演进视图由修订与讨论组成，不再建立一份可独立修改的思想历史正文。

恢复旧版本追加新修订并保存恢复来源，例如 `v5 → 恢复 v2 → v6`；`v3–v5` 与各自反馈保留。既有讨论仍读取讨论时的版本，可另外跳转到当前笔记。版本较新只表示表达较晚，不能直接标成更正确、已掌握或理解进步。

用户可选填写“为什么改”，也可在确切讨论入口保存新认识并附上来源回合；这些都不是保存前置要求。仅处于同一聊天、时间较晚或语义相近，不足以断言某次讨论促成了这次修改。AI 应请求概括变化时，结果作为系统解释展示并回到所据原文，不取代历史内容或补写不存在的心理过程。

用户只在讨论中改变说法而未编辑笔记时，相关表达留在原讨论与事实记录，演进视图显示为“后续讨论”。只有用户保存或采纳后，才形成笔记的新正文修订。召回会同时考虑确切相关的后续表达，不要求用户为获得正确接续而重复整理笔记。

### 3. 表达入口就地出现，整理与模型响应不阻塞记录

**决策：先接住表达，再按需要讨论与整理。**

复用一份正文编辑能力，在阅读选区、正文、视频、演示、用户消息、画板和独立个人入口嵌入合适容器。没有选区、标题、标签、材料或学习目标时仍可记录。情境取自实际已知信息；用户只记文字时，不要求额外截图、暂停视频或启动模型。

“先记下来”只保存；“与我推敲”先保存确切版本，再提交讨论。讨论启动失败不撤销已保存笔记，用户可直接重试讨论。已发送的用户消息可以留下为笔记，助手摘录保留自己的来源；未发送的草稿不会自动进入 AI 上下文。

草稿控制置于可切换材料的 Reader 页面之外，按用户或本地身份与草稿身份持久保存到当前设备。收起、切书、刷新或重开后恢复原文字、原记录情境及基础修订，不能把新页面的材料覆盖到旧草稿。聊天、视频提问与正式活动输入继续按自身语义保存，通过实际的“留下为笔记”操作接入。

创建、保存、移动、查看历史、手工连接和回读已知笔记均不依赖生成模型。没有标题时可用正文首句显示摘要；不为记录入口增加标题生成调用或强制卡片整理流程。

### 4. 用户原话、保留素材与系统解释分别承担责任

**决策：每种表达保留真实内容身份与来源。**

沿用 RN1 的分离原则：用户明确填写的正文、原文摘录、助手摘录和已知的 AI 改写来源分别保存和展示。纯摘录仍可保存、检索和使用；既没有正文也没有保留片段的空记录不创建。用户采纳 AI 改写会形成新的笔记版本并保留已知来源，采纳动作不证明独立理解。

旧内容作者不明时保持中性身份，不用文本样式、相似度或升级过程猜测作者。笔记内容本身是私人历史数据，包含的指令、引用和猜测不改变当前运行的指令优先级。笔记被检索、打开、保存或加入画板均不自动生成掌握事实。

### 5. 采用双路检索与明确关系读取，自动候选后由主 Agent 深入

**决策：BM25 与现有多语言向量召回，RRF 融合排名。**

复用现有关键词检索、`Xenova/paraphrase-multilingual-MiniLM-L12-v2` 宿主 CPU q8 embedding 和余弦搜索，以 RRF（现有 `k=60`）融合两路排名。首版沿当前模型的 384 维与 128 token 输入能力，不新增独立向量服务、每轮查询规划模型或独立重排模型。在线服务的 MiniLM 由服务运营方随部署统一安装、检查和预热，普通读者不安装模型、不配置环境变量或额外密钥；“本地”描述服务器内 CPU 推理。部署复用同一模型，私人索引仍按用户隔离。服务器内运行 embedding 不改变正式 Windows 的云端 Agent 交付边界，也不意味着云端能读取本机私人库。具体候选预算沿现有上下文预算和切片方案管理。

检索与教学按以下职责接通：

1. **索引带情境的表达。** 短笔记整体索引；长笔记按段落和实际模型 token 上限切分，每段保留原文位置并附简短真实情境。用户正文与保留摘录区分身份，明确相关的后续用户表达保留自己的事实或讨论引用。草稿不进入索引。
2. **以当前问题触发。** 用户开始或继续一轮请求时，用当前请求、必要的相邻对话、实际选区与已确定教学焦点形成短查询。保留原请求，旧焦点不能覆盖用户切换的话题。用户明确指定的笔记直接按身份读取，不受相似度候选预算淘汰。
3. **合并到笔记再交付。** 各路片段按笔记或明确关联表达归并，避免长笔记或多个版本挤满候选。默认搜索当前修订；历史回顾另行读取。RRF 合并相关性名次，不把关键词分数与向量分数直接相加，不把任何分数解释成正确性或掌握程度。
4. **补齐明确关系。** 候选携带身份、修订、原话片段、内容来源、时间、记录情境和全文入口。选中后按确切引用读取当前修订、所讨论历史修订和相关后续表达；当前版本及明确修正关系不能被普通相似度排序挤掉。已有笔记联系可有界查看一跳，并提供已有联系说明；没有说明的联系只作导航线索。
5. **由同一主 Agent 判断用途。** 主 Agent 需要精确引用、判断理解或选择例子时读取足够原文；教学焦点变化或候选不适用时按需补查。没有适用笔记时正常完成当前请求，不为显示记忆而牵强使用。

个人索引使用现有用户私人存储根，是可重建的派生数据。按 `note_id + revision` 及关联表达的确切身份更新变化记录，不能复用资料检索的共享缓存归属或整本出版物失效策略。正式保存原文立即完成，向量计算在宿主现有执行路径中锁外进行；计算失败或尚未完成时，已保存内容仍可直接读取并通过可用的关键词与关系查询找到。向量更新不得让旧任务结果冒充新修订，候选回读以权威笔记当前状态为准。

这里查询当前用户在当前存储域内的跨材料个人笔记；阅读标注列表继续按原材料过滤。跨材料笔记召回不自动获取原材料权限，也不自动把另一工作区完整聊天、学习目标或掌握统计带入当前工作区。必要的已保存片段和精确关联讨论作为历史背景提供，原材料读取及工作区历史选择继续遵守 ADR-0169/0170。

### 6. 召回必须改变教学，并保留实际使用关系

**决策：以具体表达调整支持，以真实事件形成理解依据。**

相关笔记沿现有上下文片段与原始学习依据交给主 Agent；使用已有片段账本避免反复追加同一版本全文。主 Agent 沿现有 `TeachingDesign / TeachingMove` 选择起点、例子、条件、任务或下一步，并保留实际采用的确切 `NoteRef`。仅提到“你以前写过”不构成教学使用完成。

| 个人表达提供的信息 | 可以改变的教学选择 |
| --- | --- |
| 已经清楚表达一个区分 | 从适用条件或新应用继续，减少重复铺垫 |
| 猜测缺少关键前提 | 选择检验该前提的反例或单变量演示 |
| 用户自己的类比 | 沿用熟悉关系，并说明当前适用边界 |
| 相互不同的观点 | 并置各自条件，让用户比较、保留或修订 |
| 未解决的问题 | 用当前材料的新线索接续 |
| 较新的明确修订或纠正 | 调整后续支持，历史猜测仅作回顾依据 |

笔记引用与现有 `fact_refs / interpretation_refs` 分别表达。用户刚写下当前理解并提交讨论时，沿真实表达事件记录正文、修订和输入时帮助条件，并扩展涉及事件提取、冻结、回读与投影的路径；不能把 `note_id` 放入原有事实引用字段。拿旧笔记讨论时，旧正文保留原时间及可知帮助，当前补充另记新的表达，不能重新标成今天产生的理解事实。

讨论针对某一笔记时，保存确切版本引用；后续确实围绕该笔记的表达保留关系。语义相似、同聊天或更晚发生只构成候选线索，不自动建立“纠正、推翻或已解决”关系。当前明确请求、用户纠正和明确修订优先，历史解释不能覆盖用户现在要求的讲解方式。

`UnderstandingSpace` 继续展示可修正的系统理解解释、依据与原笔记入口；个人笔记保留正文编辑权威。正式活动评价继续依据冻结活动和真实作答，普通记笔记、阅读反馈及开放讨论不强制插入测验。

### 7. 同一主 Agent 承担讨论，无材料场景真实调整运行范围

**决策：复用主 Agent 循环，增加有真实归属的个人讨论。**

有材料的笔记讨论先进入现有 `validate_agent_input / run_admission / FrozenTurn`，冻结确切版本、当时正文、记录情境和当前请求。沿 ADR-0176 使用同一 Resident、Goal 工作计划、工具和交付循环；教学教练提供已就绪指导，表达教练按既有制作职责工作。保存笔记不启动后台模型，不增加笔记教师、查询规划者或默认成稿审批。

独立笔记保存和找回不依赖 Book。独立讨论则需要真实调整当前 `prepare_agent_chat`、`RunScope`、`PrivateBookContext` 等对 Book 的依赖，以当前用户、聊天和所选笔记建立运行范围，复用原模型授权、额度、费用、取消、持久对话及恢复路径。不能只增加前端按钮或伪造空书、LID、出版物及教学会话。

无材料运行可以讨论、比较笔记并保留反馈；需要原材料时按确切来源和实际权限读取。只有存在符合原合同的目标与材料上下文时才提供相应正式 Tutor 能力。普通个人讨论不自行建立长期学习目标，不改变已有工作区方向，也不制造材料掌握记录。

### 8. 个人联系跨位置存在，画板组织具体问题

**决策：笔记联系独立保存，画板引用内容与联系。**

`NoteLink` 保存两端身份、可选联系说明及建立时的相关修订，支持从两端查看。用户选定两条笔记即可先连接，稍后再补说明，不要求先选关系类型；没有说明的联系只作导航线索，不能据此认定支持、反驳或纠正。AI 提议须给出具体理由及相关版本，经用户采用或修改后保存。修改联系说明不追加笔记正文修订；历史讨论保留当时实际引用的说明和内容。联系在离开画板后仍可用于找回与思考。

画板新增笔记引用类型；创建条目时保留所展示修订，当前编辑画板可解析最新内容并标明变化，历史讨论与已交付作品继续读当时版本。`BoardContentRef.content_revision` 当前表示画板修订，外部修改笔记不会改变该修订；因此选中、交付及历史追问还须冻结实际解析出的确切 `NoteRef`，不能仅凭画板版本重建当时内容。动态最新视图不改变历史快照。卡片编辑进入同一笔记编辑器，移除卡片不删除个人笔记。既有回答、演示和 Drawing 的不可改写交付快照继续保留，不通过放松所有条目规则实现可编辑笔记。

画板局部线条说明当前问题中的关系，不自动进入个人联系网络；它可以引用已存在的 `NoteLink`。工作区内问题画板按工作区与问题组织，条目各自保留来源；跨材料接入必须覆盖列表、打开、导入、追问冻结与运行回读。书架原画板入口继续可用，用户记录想法不要求先建画板。

围绕一个问题整理成综合笔记或说明时，结果可继续编辑并引用采用的笔记版本，区分 AI 草稿与用户修改。综合表达产生的新认识仍回到同一笔记模型，不再增加一份独立知识正文权威。

### 9. 旧笔记做有限接续，按现存资料保留历史

**决策：原存储内升级接续，旧内容身份不补造。**

沿已有 schema 升级入口，把现存笔记转为稳定对象和初始修订，原放置转为引用；当前 `mem_id` 与可解析的 `note_replacements` 导航到同一笔记。转换与持久化沿原子提交完成；非笔记记录、画像、审核、理解和治理状态保留既有归属。

既有 `memory/save / replace / reanchor` 的笔记分支接入同一权威操作，原调用者需要的记录形状只作读取投影，不双写两份正文。稳定身份接管正文编辑和位置变化；这部分调整 RN1 的内容寻址笔记编辑约定，保留其内容来源、确切关联、原子保存及旧入口接续原则。

接续只使用实际已有的正文、时间、作者和来源。旧替换曾覆盖但未保存的正文无法恢复；旧导航可到现存笔记，不能宣称找回从未保存的旧版。已交付反馈中存在的原话快照继续按原身份保存，不反推生成虚构的笔记修订。

## 实际取舍与影响

| 考虑过的方案 | 本次选择与原因 |
| --- | --- |
| 继续以单材料记录和替换导航承载全部笔记 | 稳定个人笔记及追加修订能够同时支撑多处使用、历史反馈和演进；代价是需要改变保存及引用链路 |
| 为每个使用位置复制一份可编辑内容 | 各位置引用同一对象，避免用户修改后产生多个不同的权威版本 |
| 每轮只等 Agent 自己想到去搜索笔记 | 宿主先自动提供有界候选，主 Agent 按需深入，让未被用户点名的旧想法也能参与教学 |
| 只使用关键词或只使用向量 | 双路检索分别覆盖准确术语与不同措辞，RRF 复用现有实现；笔记版本与讨论关系通过明确引用补齐 |
| 把整库笔记、全文历史或自动知识图谱交给模型 | 有界候选与按需原文读取控制等待和上下文占用，保留用户联系理由，不依赖自动全图抽取 |
| 只提供当前版，或把每次键入当成永久版本 | 正式保存形成修订，草稿负责恢复；能回看实际表达，又不让时间线被输入过程淹没 |
| 自动把后来语句认定为修正并改写笔记 | 保留确切讨论关系，正文修订来自用户保存或采纳，避免系统替用户确定观点 |

追加修订会增加现有 `memory.json` 的存储与全量提交成本；首版在实际记录和代表性修订量上测量保存、重开与内存，再决定是否需要局部存储调整，不因预想规模引入新数据库。个人索引按记录更新，保存不等待 embedding；冷启动和热召回分别测量，模型与宿主开销分别计量。

自动召回会占用每轮首答时间和上下文，因此候选数量、原文长度与补读围绕教学需要受限。语义检索未就绪时保留可用召回并如实标记能力，不能把关键词回退说成已验证语义效果。仅一次检索命中也不证明教学质量，必须分别查看检索候选与实际采用。

## 验收与回看条件

首份可用增量以“留下想法—主动找回—改变教学—接续新表达”验证。工程判据和实施顺序见[切片方案](../切片方案-个人想法演进与教学召回.md)；以下条件决定本 ADR 是否被正确落实。

1. **表达可恢复。** 写到一半收起、换材料或重开后，原文字与情境仍在；保存不依赖生成模型。
2. **历史可追溯。** 首次保存、连续修改、任意两版对照、历史讨论回读及恢复旧版均保留原文；两处编辑不静默覆盖，旧反馈不会指向新正文。
3. **需要时能找回。** 用户未点选笔记，当前问题仍能找到另一材料中措辞不同的相关想法；无关内容不会仅因候选靠前而被强行采用。
4. **教学确实变化。** 对同一问题与资料，分别给出清楚区分、缺失条件及已修订的真实表达样例，用真实模型观察讲解起点、例子、条件或下一步如何变化。字段存在和替身通过不能替代这项证据。
5. **更新能接续。** 用户后续明确修订或纠正后，重开仍能接着新表达继续；原猜测可以回看，不再被当作用户现在必然持有的观点。
6. **范围与成本真实。** 无材料讨论有实际运行和费用归属，跨材料画板全链路可用；记录保存、热查找、冷/热召回和首答增加的等待均有代表性测量。

当真实中文或中英混写样例漏召回，先定位查询情境、分段、分词或 embedding 是否遗漏；目标已在候选但排不到预算内时，再评估是否需要独立重排。若个人库规模使现有余弦扫描或 `memory.json` 提交影响交互，依据相同内容与环境的测量调整索引或存储。若目标已被正确找回但教学没有合理变化，先修正主 Agent 的读取、依据组织和支撑选择，不以增加另一层审核代替定位。

达到上述工程和场景证据只能说明对应路径可用，真人长期学习收益仍需实际使用资料。失败样例与实际开销保留在原验收记录，不通过删除失败样例或降低教学标准完成切片。

## 实施记录（2026-10-30）

个人笔记由 `MemoryDocument.notes` 持有，旧 `Record` 仅为阅读批注投影；修改正文追加修订，显示位置独立变化。`NoteRef` 同时服务讨论、联系和画板。全局 `ApplicationShell` 中的编辑器保留设备草稿；来源、历史比较、恢复和相关讨论可以直接打开。

实际候选预算调整为词法 40、语义 80、RRF(k=60)、自动入场最多 8 条，语义相似度低于 0.3 不进入融合。真实对照暴露的无关中文单字命中已修正；原失败及复验结果保留于报告。显式引用在接纳时冻结，自动候选必须经实际读取后才可计入教学采用。只有用户明确围绕该次采用继续表达，才追加相关原话，原笔记仍由用户决定何时修订。

无材料场景使用 `RunScope.book=None`，沿原运行接纳、Goal、日志、取消与计量接续。个人讨论带入资料时使用确切 `personal_chat_ref`，实际资料仍独立执行授权与来源核验。当前画板解析最新笔记；历史画板和实际反馈保存版本引用，综合稿使用 source_refs 与 based_on_turn 保留来路。

[工程、真实模型、性能和界面证据](../performance/personal-notes-20261030/README.md)区分了 Probe 浏览器场景、真实 DeepSeek 教学对照和真实 MiniLM 检索。语义模型是否可用取决于现有宿主配置；未配置时词法与明确引用可用，语义状态如实返回 unavailable。

## 浮窗与放置续作（2026-10-30，本地）

随手记改为可拖动、缩放的非模态浮窗。全局记录默认只保存并冻结产生现场；就地记录默认关联明确位置。统一「放到…」接通画布卡片及元素连线、对话原句所属段落下、演示页面或保存状态，各处仍引用同一 NoteID。产生现场、展示引用与正文修订分开；移除展示不删除正文，部分成功的设备草稿只重试放置。MemoryDocument 本地版本为 6，新增 `note_attachments`，画布保持原生个人想法卡片，控制库不变。实现、测试与限制见[放置验收](../performance/personal-notes-20261030/placements/README.md)；本段增补未部署，不改变前述线上 schema 5 的历史记录。
