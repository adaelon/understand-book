日期：2026-10-22。状态：工程实现已落地；首批内容、完整四轮教学与响应速度尚未通过验收。用户已确认精选作品与录音、预构建、交响乐的乐器与声部区分，以及参考视频中的跟谱动画；范围与依赖见[切片方案](../切片方案-音乐预构建与交互伴听.md)，实际结果及剩余工作见[验收记录](../验收-音乐伴听.md)。

## §1 产品范围与首批样本

2026-11-12 补充：音乐读取增加仅供发现的材料目录、多词事件检索和按完整来源分页；保留原始记谱信息，已有出版物可从其原始 MusicXML 补读。谱面默认选择及合成示范排除明确隐藏且静音的对象，动机分析使用可核对的音程、时值与前后段落证据。实现与本地验证见[修复记录](../performance/music-answer-quality-20261111/repair-20261112.md)，回答质量评测尚未重跑。

**决策**：精选录音与乐谱，提供可交互的音乐伴听。
首批目标为舒伯特《音乐瞬间》第3首的整曲体验，以及贝多芬第九交响曲选段的多声部与主题传递；选段保留真实乐章位置和必要的整体导航。用户提供的《看见舒伯特｜音乐瞬间第3首》视频作为谱面移动、彩色标记与光晕的视觉参照。
**权衡**：精选材料允许校准对齐与关键解释，增加逐作品准备成本，换取可靠的首批学习体验。具体谱本、录音、变更说明与使用依据随素材和发布保存。

## §2 预构建产物与教学分工

**决策**：构建有来源的音乐事件与整体联系。
音乐事件回答“发生什么、依据在哪、怎样帮助听见”，连接局部片段与主题的跨片段重复、变化和传递；事件允许重叠。作品结构、具体录音的演奏观察、可选听辨素材分别保存，作品与谱本理解可在更换录音时复用，演奏对齐及观察绑定具体录音。
**命门**：谱面事实、实际音频分析或人工听核、参考资料与解释性观点各保留来源；读取预构建描述本身不表示读时模型已经听过原声。跨片段关系保留两端依据。构建产出可回听片段和概念入口，教学措辞与用户理解依据来自实际互动。
继承 [ADR-0174](0174-teaching-coach-and-participation-planning.md) 的教练与 Resident 分工：教练规划参与及节奏，Resident 根据当前用户输入取证、准备材料并交付；播放器执行连续呈现。教学资产接续 [ADR-0158](0158-book-structure-ready-tutor-and-optional-teaching-assets.md) 的可选构建边界。

## §3 乐器、声部与音乐作用

**决策**：分别表达乐器、谱面声部和片段角色。
乐器与乐器组回答声音来源，谱面声部定位实际演奏内容，角色记录某个片段中的主题、伴奏、低音、节奏推动等作用。一个声部可同时承担多个作用，角色随片段变化，主题身份可跨声部延续。钢琴同一乐器内的多个 voice 可分别承担旋律与伴奏，谱表不另造乐器身份；交响乐事件记录参与者及其呼应、共同演奏、支撑和交接关系。
**命门**：谱面中的参与不能直接推定该声部在录音里清晰可闻。展示可按乐器或角色聚焦，同一视图有明确图例与名称；初学者视图逐步展开当前相关声部。谱面合成示范保留其派生身份。

## §4 稳定来源、演奏出现与对齐精度

**决策**：固定来源位置，允许修订分析和对齐。
音乐来源引用沿确切资料发布，谱面位置固定谱本及对象，录音位置固定原媒体时间区间；音乐事件、结构解释和对齐可修订。继承 [ADR-0145](0145-video-media-locations-and-revisable-visual-units.md)，已交付引用与学习记录仍返回原依据。
**命门**：同一谱面对象可对应反复演奏中的多次出现；录音时间映射按实际演奏顺序保存这些出现。小节／乐句定位与逐音符对齐分别表达覆盖与精度，局部缺口可见。真实录音使用独立对齐，乐谱生成播放的时间不能替代演奏时间。
结构化谱面优先使用 MusicXML，服务端使用 Verovio 生成带对象标识的 SVG；只有扫描谱时，精选片段可标注区域并补录必要的结构化内容。对象标识连接时间与显示，坐标属于具体排版。精确参考动画必须有相应音符对齐依据。

## §5 播放驱动的谱面动画

**决策**：以播放器时钟驱动高亮、光点和跟谱。
预构建提供谱面对象、演奏映射与声部／角色标注；客户端根据当前播放时间绘制高亮、光点、短淡出和谱行平滑跟随。暂停、跳转、倍速、循环与反复重新计算当前状态，多声部及和弦同时呈现，延音线按实际起音关系表达。光点与谱面共用坐标变换，重排后重新定位对象。
**命门**：用户手动查看其他谱位时暂离自动跟随，保留返回播放位置的入口。Agent 选择关注对象、对照片段及教学动作，客户端执行并返回实际播放结果；播放过程不逐帧调用模型。按音符高亮与按乐句导航分别消费其已具备的精度。

## §6 构建、发布与运行时接入

**决策**：音乐接入现有构建、资料和教学体系。
新增音乐材料、谱面定位、演奏映射及语义产物的必要合同，沿既有 Build Engine 接纳、恢复与发布；读时通过 PublishedLibrary、LearningWorkspace、来源观察、教学及私人理解机制消费。共享发布沿 [ADR-0170](0170-goal-scoped-learning-workspaces-and-shared-releases.md)，费用沿 [ADR-0171](0171-all-agent-cost-accounting-and-percentage-allowance.md)，服务端执行沿 [ADR-0173](0173-cloud-learning-subscriptions-and-exam-sprints.md)。纯音乐来源独立表达，转写只用于实际存在的语音内容。
**权衡**：复用控制面及来源责任，在音乐合同中补足时间与谱面语义；逐作品可保留人工校准及听核记录。现有语音复核、视频转写和 PDF 展示能力作为各自现有能力复用，音乐听觉分析由真实样本验证后的执行路径承担。

## §7 实施落点（2026-10-22）

`base-schema::music` 是合同权威，生成 TypeScript 类型；`music_source_manifest.v1` 在一个成果中保存作品、确切谱本与录音、来源权利、谱对象、演奏出现、对齐覆盖、事件、结构和合成示范。`voice_ids` 与 `focused_voices` 表达同一乐器内的声部作用和选择，明确填写的 `theme_id` 保留跨声部及事件的主题身份，事件的 `occurrence_ids` 绑定可随校准修订的播放范围。`MusicQuestionContext` 固定提问时的原声范围、谱面位置和关注对象，`MusicSourceTarget` 固定已读取的发布来源；同资料更新允许重排和语义修订，发布器核对原录音、原谱字节及既有谱对象语义。

`music-import / music-score / music-alignment` 接入原 Build Engine 的 `music_prebuild` 发布事务、持久状态与局部校准，作品导读明确保存为编选文字。Verovio 6.3.0 在服务端生成 SVG；Engine 旁的 `resources/music/` 分发可替换的 ESM/WASM 文件、对应源码、许可和替换说明，谱面附带 Leipzig 字体的 OFL 与署名。实际安装入口见 [DSH 插件说明](../../packages/dsh-plugin/README.md)。

`LocalApp → MusicCalibrationPane → 本地构建工作台 → Engine music-calibrate` 提供图形校准。编选者在真实原声和谱面之间复听，按演奏出现调整小节边界与音符时间，保存修改原因、依据和实际接纳精度；保存沿既有成果事务，重建重放历史。未发布本机材料直接校准，已发布版本保持不可变。

运营构建沿原任务、预算、暂停／恢复与成果接纳流程，成果进入 `PublishedLibrary` 和学习工作区；确定性的本地谱面构建与精选标注接纳不产生模型调用费用，读时模型与后台教练沿既有费用归属结算。公开导入要求录音、谱本各有来源与许可记录，保存编选时的分发标记。运营者决定是否发布。

`MusicReaderPane` 以真实播放器时间驱动跟谱，按已接纳的覆盖显示小节或逐音动画；乐器与 voice 聚焦、循环、倍速、手动浏览后的恢复跟随及谱面合成示范接入同一现场。`music.read / music.interact → source.present → TeachingTarget.music_bindings` 连接有界来源读取、离散播放动作、实际浏览器回执与私人理解。教练继续使用 ADR-0174 的原后台任务，具体实现和验证入口见[架构](../架构.md#精选音乐预构建与交互伴听2026-10-22)及[验收记录](../验收-音乐伴听.md)。

原录音与合成示范分别保持时钟及播放状态；恢复原声会退出示范，示范中提问会暂停双方并明确定位原声片段。需要边听边提示时，动作选择本轮已读事件的 `listen_for`，客户端实际显示后开始播放，回执确认显示与播放结果。动态教学正文继续经过原有准备、审阅和交付；编选提示补足播放开始前的听觉关注。

## 已知限制与后续范围

2026-10-23 谱面事实补全：`MusicScoreMark` 保存调号原编码、拍号、文字指示、节拍器标记和 MusicXML 播放参数，固定原小节／拍位并复用音符／休止来源锚点。`MusicWork.tonality` 独立保存经谱本或参考来源核对的作品调性及解释。`music.read` 的谱面分页返回对应声明及先前小节延续的上下文，引用保留事实快照和声明出处。舒伯特的 F 小调与原文件 `mode=major` 编码分别保存，处理依据见[音乐样本说明](../../evals/music/README.md)。谱面事实不依赖录音对齐的接纳状态；`sound tempo` 不代表录音实测速度。

- 舒伯特原录音已产生 900 条逐音对齐候选和 78 个小节演奏出现候选，覆盖仍为 `pending`。尚未通过全曲逐音符听核，播放器不将候选当作已校准跟谱；参考视频的完整逐音效果仍是验收目标。
- 贝九样本围绕真实第四乐章第 93–164 小节和 1923 年 Albert Coates 演奏，保留完整乐章录音时间。已构建 72 小节、6 个实际参与声部、17 页谱面及三个主题交接事件，录音映射仍为候选；当前现代转录与修复版录音及所带谱面标注列为 `local_only`，记录了编选时尚未确认公开分发权。
- 当前预构建使用精选标注、真实音频特征候选及明确标注的谱面合成示范，尚未接入读时音乐音频模型。真实音乐精度、学习效果与完整端到端验收仍待完成，按[验收记录](../验收-音乐伴听.md)分别报告。
- 首批覆盖精选短曲与交响乐选段。个人任意录音上传、通用扫描谱识别、完整贝九深度构建、全乐团自动分轨和外界实时演奏跟随留作后续范围。示例视频仅作为体验参照，产品分发素材的使用依据分别确认。
- MusicXML 4.0 采用 W3C FSA；Verovio 采用 LGPLv3，允许商业及闭源产品合规使用。首选服务端预构建并保留清晰署名；将库交付到浏览器或桌面时，按实际版本落实许可文本、对应源码及适用的替换／重新链接要求。格式与工具许可、谱本与录音使用权分别记录。依据：[MusicXML](https://www.w3.org/2021/06/musicxml40/)、[Verovio 官方许可说明](https://book.verovio.org/introduction/licensing.html)、[LGPLv3 正文](https://raw.githubusercontent.com/rism-digital/verovio/develop/COPYING.LESSER)。

**何时回头**：样本证明当前自动分析或对齐不足以支撑已声明的效果时，调整该阶段方法、校准量和能力覆盖；素材取得成本或逐作品准备成本改变首批范围时，再提交具体取舍。保持精选伴听、来源可回看、教学按用户实际反应调整的产品目标。
