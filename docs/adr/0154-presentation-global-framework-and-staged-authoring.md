# ADR-0154 演示页全局框架与分阶段制作

状态：设计已接受，2026-10-02；EX12.0–EX12.4 已完成；最终原生修正与内容验收见 [EX13.6](../performance/presentation-context-ex13/ex13-6/README.md)；EX12.5 待实施。实施合同见[切片方案](../切片方案-演示页全局框架与分阶段制作.md)。

后续已接受 [ADR-0155](0155-goal-work-plan-and-version-centered-presentation-context.md) 与 [EX13](../切片方案-EX13-Goal工作计划与演示修订上下文.md)：Goal 负责工作进度，框架保留解释设计职责，阶段指导改为稳定前缀后的追加式组装。EX13.0–EX13.6 已完成，EX12.4 最终原生验收通过；下一片为 EX12.5 Reader 连续使用。

承接 [ADR-0133](0133-agent-led-explorable-explanations-and-evolving-presentation-brief.md) 与 [ADR-0139](0139-explorable-explanation.md)。保留 Agent 的表达选择权及既有来源、版本、现场、预览和交付合同；调整复杂解释的制作组织与指导加载方式。

## 背景

图形、实时交互和局部动画能力增长后，演示页仍可能同时堆放术语、图形、参数、读数、公式和练习，使读者难以辨认当前重点。用户提供的《信任的进化》截图显示，不同局部可以采用故事、局部高亮、选择预测、并列过程图等不同表达，同时保持对象身份、图文对应和明确的当前任务。清晰程度不能从元素数量或固定布局推导。

当前 `presentation-method` 已有按问题选择表示的原则，但 `ex11.v11` 又包含统一的开场比较顺序、具体 seek 位置及完整 Konva/Manim 工程细节；`policy_modules_for_tools` 在制作工具可见时整段注入。需要把共同原则、当前阶段职责与实际使用能力的技术合同分开，并让局部制作接收到全篇理解路径。

## §1 复杂解释的制作顺序

**决策**：先定全局理解路径，再试做关键局部并展开。

**否决**：
- 只列章节标题后逐项填充：没有表达各段解决的问题及前后依赖。
- 先完成所有页面再检查设计：表示问题会扩散到整篇内容。
- 所有请求一律走完整规划：短答与小修补承担不必要的工作。

**命门**：全局框架保留用户要求的完整范围；试做用于暴露表达问题，不能成为缩减交付内容的理由。
**展开**：[工作过程与交接](../切片方案-演示页全局框架与分阶段制作.md#工作过程与交接)。

## §2 共同解释原则

**决策**：各阶段共享同一份解释原则，职责分别加载。

**否决**：
- 用两份阶段 prompt 替换共同原则：会丢失图形、交互和真实观察要求。
- 在多份提示中复制改写共同原则：易产生冲突和措辞漂移。
- 按场景穷举模板：内容与读者问题的组合没有有限模板边界。

**命门**：文字、图形、例子、对照和交互由解释需要选择；图形与交互要求以实际使用它们为条件。
**展开**：[共同指导正文](../切片方案-演示页全局框架与分阶段制作.md#共同指导正文)。

## §3 全局框架与局部职责

**决策**：以简短全局框架约束局部目的和衔接。

**否决**：
- 将框架做成组件清单或固定线框图：提前锁死表示，却未解决理解顺序。
- 局部只收到一个标题：容易重复前提、遗漏条件或改变对象含义。
- 每个局部必须独立成页：人为拆散需要共同观察的关系。

**命门**：局部保留整体目标、当前作用、必要材料、相邻承接与对象约定；布局和表示可调整，前提或顺序有问题时更新全局框架。
**展开**：[全局框架的最小内容](../切片方案-演示页全局框架与分阶段制作.md#全局框架的最小内容)。

## §4 实际提示与阶段状态

**决策**：同一 Agent 按当前阶段组装实际模型请求。

**否决**：
- 只拆 Markdown 文件而仍全量注入：模型实际收到的指导没有改变。
- 默认增加规划、制作和评审 Agent：当前分工可在原循环内完成。
- 用新增持久规划资源承载阶段：本轮交接尚不需要独立生命周期。

**命门**：运行时携带当前阶段和简短框架，模型负责设计判断；阶段切换在后续采样生效，不新增用户确认步骤，也不授予交付资格。
**展开**：[提示组装与运行时接入](../切片方案-演示页全局框架与分阶段制作.md#提示组装与运行时接入)。

## §5 能力说明与工程合同

**决策**：技术细节按所用能力加载，工程合同持续生效。

**否决**：
- 全局设计时加载所有绘图与媒体细节：实现惯例容易抢占表达选择。
- 将单题修复升级为通用页面要求：会强迫无关内容使用同一表示。
- 为减少提示而删除状态或来源约束：会损坏已有内容与现场能力。

**命门**：来源、确切版本和真实预览保持共同约束；动画定位、图形库和媒体恢复细节随相关能力加载，具体算例留在对应验证中。
**展开**：[技术指导的归位](../切片方案-演示页全局框架与分阶段制作.md#技术指导的归位)。

## §6 局部反馈与整篇串读

**决策**：以真实画面和操作修订局部及全局组织。

**否决**：
- 局部代码通过便拼接交付：整篇仍可能重复、跳跃或对象含义不一致。
- 只观察长页首屏：无法发现后续段落与衔接问题。
- 将预览完成解释为读者理解：没有相应用户表现证据。

**命门**：关键局部先验证表示，整篇按实际阅读顺序观察；反馈指向具体对象、文字、位置、顺序或操作，并能说明修改理由。
**展开**：[观察与修订](../切片方案-演示页全局框架与分阶段制作.md#观察与修订)。

## §7 验证与采用

**决策**：用自然请求和具体产物判断改进效果。

**否决**：
- 把美观评分、控件数量或框架完整度当成质量证明：无法回答哪里更易理解。
- 把预览能力修复算成提示收益：不能隔离变更影响。
- 为证明通用性先枚举全部场景：有限实验只能支持已覆盖的解释关系。

**命门**：同底座对照覆盖长篇机制解释、预测后观察及静态关系解释；记录实际理解障碍、修订、完整交付与制作消耗，失败后修改对应路径。
**何时回头**：框架只增加复述与调用，或跨段仍失去联系时，先调整交接信息与阶段粒度。
**展开**：[EX12 实施切片](../切片方案-演示页全局框架与分阶段制作.md#ex12-实施切片)。

## 对既有决策的修订

ADR-0139 §3 的“无须独立模型回合”不再约束复杂演示的阶段交接：复杂任务可以在同一 Resident 循环内通过不同采样完成全局与局部工作。简单解释继续直接完成。

ADR-0139 §10 的“只有跨轮修改才考虑 Brief”不适用于本轮全局到局部的交接摘要。本 ADR 接受运行内框架的具体用途；ADR-0133 的持久 `PresentationBrief` 仍为独立条件性工作，本轮不增加其存储字段。运行内框架不会成为第二份用户目标，也不会修改正式 Tutor 路线或 BookStructure。
