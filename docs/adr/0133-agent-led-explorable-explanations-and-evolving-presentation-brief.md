# ADR-0133 Agent 自主表达设计与可演化的 PresentationBrief

状态：设计方向已接受，2026-09-18；2026-09-25 增补点击稳定性与 Python 绘图。ED1/ED2 已实现并经 Windows 本机定向验收；ED3 的短说明已接入并完成同底座自然请求对照，但表示盲区样本超出预设成本界限，收益未获证实。ED4 的图片投影和门槛已实现，真实模型看到预置差表示截图后提出修订；新候选的两个触屏视口未通过预览，脚本化历史的 Provider 协议问题阻断后续交付，见 [ED3–ED4 记录](../performance/agent-presentation-ed3-ed4-20260925.md)。ED5–ED9 未实施，Brief 为条件性实验；Linux/手机待验。ED1/ED2 验收见 [ED1–ED2](../performance/agent-presentation-ed1-ed2-20260925.md)。

本 ADR 细化 [ADR-0130](0130-agent-rich-presentation-and-read-time-authoring.md)，复用 RP1–RP7 的制作、运行与交付机制；RP8 仍是正式教学接入。实施合同见[切片方案](../切片方案-Agent自主表达设计与PresentationBrief.md)。

## 背景

用户希望只表达当前问题和困惑，由 Agent 选择能使关键关系可见、可操作的表示，并依据实际观察修改方法。Ciechanowski 式可探索解释是体验方向。现有 RP 已有制作、预览、后续采样和交付闭环；详细工程验收请求包含布局、控件、参数名及恢复字段，能够证明给定设计后的实现能力，尚不能证明自然短请求下的自主设计表现。

现有专用说明在 `presentation.author` 可见后才加载，主要约束制作协议。2026-09-24 工作树核对还发现：Server 为真实观察生成图片，但 Runtime 只在 `previewed_candidate` 存在时接入，失败或部分环境完成的图片未沿此路径送入后续采样。表达指导、能力发现与观察反馈需要分别判断，不能把所有缺口归因于没有 Brief。

2026-09-25 用户反馈点击抖动、闪屏及图表质量一般。实际 bridge/CSS 的最小浏览器复现确认：点击更新数字后，等待 accepted 时整个 body 被隐藏，回执到达后恢复；组件也会在后续校验时重新插入首次加载提示。现有 author 无 Python 入口，图表主要由生成的网页代码制作。稳定性修复和 Python 静态绘图纳入本轮，先于 Brief 试接；原 ED1–ED7 顺延为 ED3–ED9。

## §1 表达方法的所有权

**决策**：Agent 围绕当前问题自主选择与修订表达方法。

**否决**：
- 学科到页面模板的固定映射：限制对实际困惑的回应。
- 遇到“没理解”就强制制作：可能增加负担而未解决问题。
- 用控件、动画或卡片数量判断质量：不能说明关键关系已可见。

**命门**：普通文字、静态视觉、交互及连续叙事均可使用；保留用户的问题与约束，必要澄清针对对象和含义，不要求用户提供工程规格。
**何时回头**：实际任务需要稳定的专门合同，再独立设计。
**展开**：[方案第 1 节](../切片方案-Agent自主表达设计与PresentationBrief.md#1-所有权与工作过程)。

## §2 先验证说明，再条件性试接 Brief

**决策**：先验证短表达说明，Brief 按具体用途试接。

**否决**：
- 完成 Brief 存储和连续编辑后才判断必要性：过早支付实现成本。
- 将观察链路修复计为 Brief 收益：混淆变更影响。
- 为对照新建实验平台或生产开关：现有验收入口足够。

**命门**：ED1 修交互、ED2 接绘图，ED3 在同底座做 B/C，ED4 修模型观察，ED5 按用途做同底座 C/D；ED6 可发布不含 Brief 的方案。每批预先记录质量和成本条件，绘图收益另行比较。
**何时回头**：无可见收益时保留原方案或已有独立收益的部分；完成实验不等于产品目标达成。
**展开**：[方案第 6、7 节](../切片方案-Agent自主表达设计与PresentationBrief.md#6-实施切片)。

## §3 Brief 的用途与归属

**决策**：Brief 可选保存影响后续修改的设计意图。

**否决**：
- 把页面组件清单再抄一遍：成品已能表达这些信息。
- 独立规划 Agent、数据库、版本或必调工具：现有内容生命周期足够。
- 将 Brief 视为事实、用户能力或验证结果：它只是设计假设。

**命门**：保留开放的 `aim`、`approach`、可空 `checks`；重点记录成品不易恢复的目标及表示选择理由，随候选/版本保存；同轮对照与跨轮编辑收益分别评估。
**何时回头**：只有多个实际执行者需要共享设计状态时，再考虑独立规划资源。
**展开**：[方案第 2 节](../切片方案-Agent自主表达设计与PresentationBrief.md#2-最小数据合同)。

## §4 发现入口与按需说明

**决策**：能力目录提示用途，表达说明按需加载。

**否决**：
- 只放 skill 文件而不接入请求：Resident 无法使用。
- 常驻完整设计说明或按关键词强制制作：增加上下文与误触发。
- 在多处复制完整协议：容易发生漂移。

**命门**：未发现能力时检查目录和发现入口；表示选错时调整短说明；实现失败时修工具或宿主。ED3 说明不含 Brief 字段，ED5 试接时才追加对应说明并记录差异。
**何时回头**：真实任务暴露方法参照或重复工程劳动缺口，再增加按需案例与辅助能力。
**展开**：[方案第 3 节](../切片方案-Agent自主表达设计与PresentationBrief.md#3-skill-与上下文的接入方式)。

## §5 观察反馈与交付资格

**决策**：真实观察独立投影，交付沿用原有门槛。

**否决**：
- 只有候选完成合同才向模型提供图片：失败或部分完成也需要观察。
- 同批仅保留最后一份图片：会丢失候选或环境的反馈。
- 收到失败截图就允许交付：观察不等于通过合同。

**命门**：ED4 补齐失败、部分完成及同批多预览的图片投影，绑定候选/环境/步骤；沿用结果预算并显式说明截断。ED5 的可选设计数据来自实际候选，同次采样不按每张图重复。
**何时回头**：现有结果与图片投影不能承载实际任务时，再调整对应能力。
**展开**：[方案第 4 节](../切片方案-Agent自主表达设计与PresentationBrief.md#4-预览反馈工程检查与表达检查并行)。

## §6 原制作链路与版本语义

**决策**：Brief 复用原内容链路与确切版本语义。

**否决**：
- Brief 缺失即拒绝制作或交付：破坏可选性。
- 编辑时静默继承旧 Brief：可能保留过时方法。
- Brief 改动重置预算或作为预览凭据：没有新增观察依据。

**命门**：ED5 才增加 `write(..., brief?)`、保存、确切版本 read 和预览上下文；省略/null 均不继承。修订产生新候选，`based_on` 指已交付版本，历史仅保留精简引用；私有 Brief 不直接进入公开视图。
**何时回头**：有明确的公开设计说明需求时，再单独设计公开投影。
**展开**：[方案第 2、4 节](../切片方案-Agent自主表达设计与PresentationBrief.md#2-最小数据合同)。

## §7 表达判断与独立验证

**决策**：表达效果依赖实际产物与独立观察。

**否决**：
- 页面无错误或 Brief 完整即算解释成功：未检验关键差别是否可见。
- `checks` 自动执行或自报通过即授予交付资格：设计假设没有执行或认证权限。
- 点击、停留或 Agent 自评推导掌握：缺少用户理解证据。

**命门**：保留已知算例、来源检查与非数值任务；首次生成和预置缺陷修复分开报告，C/D 包含换表示及隔轮修改。工程可用、表达改善、用户学习效果分别记录。
**何时回头**：相应领域出现独立可复现验证器时，再增加有明确范围的自动检查。
**展开**：[方案第 5、7 节](../切片方案-Agent自主表达设计与PresentationBrief.md#5-一个用于验证表示选择的样例)。

## §8 验收与后续能力

**决策**：先做小规模效果对照，再验选定方案的集成。

**否决**：
- 每组都重跑完整平台矩阵：增加成本而未隔离表达收益。
- 先建全学科案例、图形或多 Agent 平台：没有实际缺口依据。
- 模型实验通过就宣布所有设备可用：发布范围缺少集成证据。

**命门**：单宿主先比较，工程回归按影响复用，选定方案再做 Windows/Tauri、Linux 及发布涉及的真实 iPhone 验收；ED7–ED9 各由实际任务触发。
**何时回头**：重要任务超出现有操作或内容生命周期能力时，再扩展最小合同。
**展开**：[方案第 6、7 节](../切片方案-Agent自主表达设计与PresentationBrief.md#6-实施切片)。

## §9 演示页连续交互

**决策**：局部校验保留已通过画面，提示不改变布局。

**否决**：
- 每次 observe 隐藏整页并重启加载提示：正常点击也会闪屏与位移。
- 直接删除隐藏样式或先显示再拒绝：破坏现有动态公开合同。
- 只等最终一帧恢复可见就验收：遗漏用户操作期间的缺陷。

**命门**：ED1 区分首次加载、变化校验与保存；待校验区域保留已接受展示，活控件与同版 iframe 连续。延迟回执、连续操作、非法动态文字/来源及实际现场保存均须验证。
**何时回头**：复杂内容替换使局部发布无法维持公开合同或现场一致性时，先收敛最小实现，不扩大为通用渲染平台。
**展开**：[方案 ED1](../切片方案-Agent自主表达设计与PresentationBrief.md#6-实施切片)。

## §10 Python 静态绘图与版本资源

**决策**：按需用 Python 制作静态图并随内容版本保存。

**否决**：
- 提示 Agent 使用不存在的 Python 工具：没有实际执行与观察链路。
- 每次滑块输入都重启 Python 换图：破坏即时交互体验。
- 模型搬运图片编码或引用临时路径：增加上下文并破坏重开。

**命门**：ED2 在原 author 能力内接 Matplotlib 出图及真实图像反馈，SVG 为首版必需格式；宿主管理资源和取消，复用版本存储，预览与 Reader 装配一致。浏览器实时交互继续使用 SVG/Canvas/JavaScript。
**何时回头**：真实任务需要 PNG、复杂交互库或更多辅助能力时，分别补齐格式/打包/生命周期合同，专业排版不能代替解释效果验证。
**展开**：[方案 ED2](../切片方案-Agent自主表达设计与PresentationBrief.md#6-实施切片)。

## 后果与已知限制

稳定性、Python 静态绘图、短说明与反馈修复可独立交付，均不以 Brief 为前提。Python/Matplotlib 与中文字体是制作宿主的新依赖，需要 Windows/Linux 分别部署验证；交付网页保持自包含，手机不执行 Python。Brief 若被采用，会增加元数据与上下文成本，停止生成或注入后仍保留已保存内容的读取能力。

当前工具支持显式 `viewport { width, height, input }`，新制作要求 320×420 touch、640×240 touch、960×720 mouse 三个环境；旧 `width` 仍有兼容语义。部分环境完成与可交付状态分别表达，成本统计包含全部要求的预览。touch 环境不等于真实手机手势已经验收。

预览中的状态保存/恢复回调仍为空实现，必须在实际 Reader 验证保存与重开。点击整页隐藏已有最小复现，完整 Reader 的位移和修复尚待验收；Python 绘图收益未验证。此次仅改文档，未修改运行时或更新部署；没有达到参考网站制作水准或改善用户学习效果的结论。
