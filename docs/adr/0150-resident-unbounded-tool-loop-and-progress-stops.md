# ADR-0150 Resident 持续执行与无进展停止

状态：已接受并实施，2026-09-30。
修订：ADR-0026 的默认轮数硬闸、ADR-0091 §7 的轮数停止、ADR-0132 §1/§3 的默认预算提示与十二轮上限、ADR-0136 §5 的十二轮上限。

## §1 外层循环生命周期

**决策**：外层默认不限轮数，按任务进展持续执行。
**否决**：
- 固定十二轮或改成更大的常数：采样次数不能证明任务完成或无法推进。
- 仅依靠上下文容量结束：压缩不能识别重复空转，也不能代替用户停止。
**命门**：任务完成即交付；上下文压力沿 ADR-0091 压缩后继续；取消、实际无进展、压缩失败及不可恢复错误保留未完成状态。累计 usage 仍作遥测。已有显式有限调用配置保留，默认不设上限，不新增用户开关；实验明确设置的成本预算继续生效。
**何时回头**：真实运行证明默认长任务需要用户指定的费用或时间预算时，单独定义预算入口。

## §2 交付缺口与无进展

**决策**：未交付的文字终答纳入现有无进展判断。
**否决**：
- 只删除轮数条件：交付缺口分支会重复采样，绕过工具无进展停止。
- 把文字声明或调用次数计作进展：无法证明证据、操作或交付发生变化。
**命门**：缺少页面或阅读操作时，文字终答按现有连续无进展规则处理，允许纠正后执行工具；实际工具进展重置停滞状态。持续缺口返回 incomplete 与 AGENT_NO_PROGRESS；实际交付核验、教学动作约束及旧历史停止原因保持原合同。默认提示只表达目标与交付缺口，显式有限调用才显示剩余轮数；收尾说明实际停止原因。
**展开**：[运行实现](../../crates/runtime/src/orchestrator.rs)、[上下文预算](../../crates/runtime/src/auto_compaction.rs)、[Resident Goal](0136-resident-goal-lifecycle-and-delivery-completion.md)。

## §3 多人服务模型调用与用量

**决策**：2026-10-01 删除多人服务的 `model_calls_per_turn`、`tokens_per_turn` 配置与停机逻辑，累计 usage 只作遥测。
**否决**：把 64 次 / 120000 Token 改成更大的常数，或按剩余累计预算压低下一次输出额度：重复输入与缓存命中仍被计入累计值，不能据此判断任务是否完成或无法推进。
**命门**：所有可达模型目的继续共用公平并发、取消和授权检查；每次 Provider 调用记录实际 usage，未知项保留 null、重复累计帧只取最后一帧。单次请求的显式输出上限及模型默认输出预留保持；历史失败记录保留原错误，已保存回答和私人效果不重放。
**展开**：[多人运行接口](../Linux多人阅读-MU6运行接口.md)、[服务模型适配器](../../crates/server/src/service_limits.rs)。

- 2026-10-01 多人服务累计预算删除：Linux release 下先用三项回归复现旧的 Token 停机、调用次数停机和输出额度挤压；修改后 MU6 相关 36 项全部通过，包含累计 240002 Token 后完成回合并保存笔记、历史用量读取、取消、并发、保存恢复及 SSE。
- `OuterConfig` 默认不设上限；循环提示、交付缺口重试、真实停止原因及服务端夹具已同步。当前链路见[架构](../架构.md)，变更索引见[代码链路](../代码链路.md)。
- `cargo test -p runtime --lib --target-dir .tmp-rust -- --test-threads=4 --quiet`：416 通过、3 跳过；包含压缩、取消、显式有限调用及新增五项持续执行回归。
- 新增回归验证 16 次采样完成、重复文字不虚报交付、定位与导航进展可恢复执行、工具停滞说明真实原因、文字与工具共享无进展计数。
- `cargo test -p server --lib agent_run_tests --target-dir .tmp-rust -- --test-threads=4 --quiet`：25 通过；覆盖任务保存与续接、取消、失败恢复、流式响应及超过 60 秒的响应完成。
