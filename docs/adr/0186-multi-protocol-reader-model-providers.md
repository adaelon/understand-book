# ADR-0186 阅读与教学的多协议模型接入

日期：2026-11-17。状态：**已接受；2026-11-18 实现及本地定向验证完成，真实覆盖与未验收项见切片方案。** 用户确认开源版应支持主流模型 API 协议，资料预构建继续通过插件和外部 Harness 运行。实施范围、协议覆盖及验收见[切片方案](../切片方案-多协议模型接入与配置.md)。

**决策：沿现有运行时统一多协议模型接入。** 阅读问答、教学、练习反馈及相关后台生成共用模型服务配置和协议适配；复用 ModelAdapter、请求计划、工具执行、引用校验、取消、重试与用量账本。插件预构建的模型配置、调用和执行器生命周期继续归外部 Harness，Build Engine 继续管理计划、候选接纳、恢复与发布，沿 [ADR-0138](0138-multi-harness-prebuild-and-deepseek-harness-adapter.md) 执行。

## 配置与职责

配置分为可复用的**模型服务连接**、**模型配置**和**用途绑定**。服务连接持有端点与凭据；模型配置引用服务，明确实际 API 协议、模型 ID、能力与生成参数；用途绑定为主 Agent、教学及后台任务选择模型，未覆盖的用途继承默认模型。首次设置只需配置一个服务和一个默认模型。

API 协议、云端部署方式与工具调用策略分别表达。native / react 沿用为工具调用策略；厂商品牌属于预设配置。OpenAI Chat Completions 与 Responses、Anthropic Messages、Gemini GenerateContent 与 Interactions、Ollama Chat、Bedrock Converse、Cohere V2 Chat，以及已有 DeepSeek Messages 均纳入本次完整交付范围。Azure 与 Vertex 的正式端点和认证变体同步交付。协议细分和逐项状态以切片方案为唯一清单，不以厂商卡片数量或文本连通代替覆盖。

协议适配器负责消息与内容块投影、地址和认证、流式事件、工具调用与结果配对、结构化响应、结束原因和用量归一化。业务运行时继续拥有工具注册、执行授权、教学语义、来源与学习状态。协议接入不改变题目判断或引用规则；图像等输入按确切模型能力映射，所需能力不可用时明确提示。

服务于本机的配置归本机操作者；自部署服务的共享配置归部署管理员，使用现有管理权限。云端普通学习者继续消费已授权服务。凭据只在所属后端使用，前端读取配置只返回凭据是否存在；具体存储沿原宿主约定。保存配置保持纯配置操作，连接测试由用户显式触发。

产品归属由 [ADR-0187](0187-open-source-desktop-and-cloud-editions.md)明确：协议、能力与共同调用合同进入公共学习核心；Windows／macOS 本地宿主提供用户配置，云端宿主提供管理员配置与平台额度实现。两类宿主使用同一模型配置合同，代码拆分和平台发行沿双发行方案执行，本 ADR 的协议覆盖范围继续有效。

## 运行与恢复合同

沿 [ADR-0091](0091-model-aware-agent-request-tool-exposure-and-active-context-budget.md)，运行开始时固定所选服务、协议、模型、能力和配置版本；修改默认项影响后续运行。原任务恢复使用已绑定配置，不可用时返回现有可诊断的绑定错误。删除仍被用途或可恢复任务使用的连接时，先提供改绑用途、保留旧配置或结束原任务的明确操作。

推理内容块、签名、Responses items 等协议私有续接状态随原消息保存，并绑定确切服务、协议和模型。相同协议按官方合同回放；新回合显式换服务或协议时由本地规范化历史重新投影，旧私有状态不发送给新服务，未完成的工具调用必须先沿原运行恢复或结束。服务端 conversation / response / interaction ID 只作为适配器续接能力，本地历史与恢复事实继续由项目持有。

每次实际发送仍通过既有用量准入与结算；错误、取消、重试和缺失用量保留真实状态。缓存、推理、总量与计费单位按协议定义映射，不能重复累加或把未知填成零。多人收费部署仍要求可用费率与原额度授权，本地自带 Key 路径按实际可得信息展示用量。

## 取舍与既有决策

- **选择项目内的协议适配器。** 现有 Rust 运行时已经承担工具、证据、流式交付与账本。复用公共发送生命周期，让每种协议实现自己的编解码；云端认证与事件流可用适合的官方 SDK。
- **OpenAI 兼容是覆盖路径之一。** 仅统一成 Chat Completions 会丢失其他原生协议的内容块、工具结果和续接语义；指定协议失败时报告原因，不静默换协议或服务。
- **外部网关作为用户可选端点。** 不要求部署额外网关才能使用原生协议，也不建立新的通用网关服务。兼容厂商以实际端点和模型验收记录为准。

本决策扩展 [ADR-0070](0070-desktop-provider-settings-and-hot-reload.md) 的单连接设置和热应用，保留保存不自动调用模型、凭据不回传、写入失败继续使用旧配置的约定；扩展 ADR-0091 的能力与请求投影，保留工具和上下文预算所有权。当前实现与目标能力之间的差距、真实服务验证缺口集中记录在切片方案的状态部分。

当新增服务无法由现有协议或明确的端点变体表达时，依据它的实际请求与响应增加适配器；只有部署规模证明独立模型网关有必要时，重新评估进程边界。
