## 背景与已确认范围

目标是让小范围受邀读者在同一台 Linux 服务器上独立阅读、提问和积累学习记录。首版采用一个 Rust 主服务，共享管理员发布的书库，按用户隔离私人数据，按阅读窗口隔离现场。读时 Agent 继续复用现有运行核心，预构建仍在现有插件 / Harness 流程完成。

**首版不引入 Redis、外部消息队列、微服务拆分或强制 PostgreSQL 迁移。** 使用服务级 SQLite、现有个人持久存储，以及进程内有界缓存和调度。以后是否引入 Redis，由跨后端协调、分布式 Worker 或实测共享缓存需求触发，不以“已有多用户”作为理由。

不包含实时共读、共享聊天、协作编辑、开放注册、读者自主预构建、团队租户模型、自带模型密钥、跨服务器高可用，以及桌面本地数据与服务器的双向实时同步。不同设备登录同一个服务器账号可继续读取自己的持久数据，但不自动同步当前视口。

设计基线中的 Host 创建一个 `AppState` 和一个 `RunCoordinator`，切书会替换宿主唯一的 Book、Reader 和 messages；单纯添加账号或把这些对象搬入 Redis，不会解决归属问题。依据：`crates/server/src/lib.rs:91–124,2811–2878`；`crates/server/src/host.rs:1262–1287`；`crates/server/src/agent_run.rs:401–465`。

## §1 共享基座、私人空间与窗口现场

**决策**：宿主状态按服务、用户、现场和运行分层。

**否决**：所有账号共享一份 `AppState`；每窗口独立加载同路径 Memory 后整体写回；把登录会话、聊天会话、Tutor 会话和阅读窗口统称为 session。

**命门**：

- 服务级持有已发布书库、权限目录、共享纯内容缓存、调度器和运维配置。
- `UserRuntime` 持有一个用户的 Memory、Learning、AgentHistory、私人演示 / 成果及画像缓存的权威写入口。
- `ReaderWorkspace` 持有一个独立阅读现场的 Book 绑定、Reader、当前选中聊天、现场 generation 和恢复检查点。它不是构建工作区，也不是团队空间。
- `Run` 固定归属用户、原聊天、原现场和已发布材料；模型等待在锁外，私人修改只经权威入口提交。

同一用户的两个窗口可阅读不同材料，共享长期笔记与学习记录，但不互相切书、滚动或恢复演示滑块。现场常驻数与全部存活 Book 引用共同受预算约束；闲置现场保存检查点后释放内存，恢复时按原绑定加载。聊天与教学目标由用户持久拥有，不随现场回收而删除。

**何时回头**：明确需要多人共同操作同一现场时，新增共读领域及授权；不得重新共享私人 Reader 来模拟协作。

## §2 身份是宿主边界，不是模型参数

**决策**：多人 HTTP 入口先认证，再按每个对象检查授权，最后构造受限业务上下文。

**否决**：信任客户端 `user_id` 或任意代理身份头；用难猜 ID 代替授权；只保护 JSON 路由而漏掉 SSE、PDF、图片、下载和私人演示。

**命门**：使用 HTTPS、应用级登录和可撤销的服务器端会话。首版管理员创建账号，不依赖邮件服务。会话 Cookie 使用 Secure、HttpOnly 和适当 SameSite；写操作验证 CSRF 和可信来源，密码采用维护中的 Argon2id 实现。认证、对象归属和书库授权分别判定。[S1][S2][S3][S4]

所有 Host 旁路、旧路由别名及资源请求进入同一权限入口。普通读者不能提交服务器目录，不能调用预构建、Provider 设置、原始诊断和管理接口。多人模式下缺失身份立即拒绝，不回退成默认本地读者。

桌面 / 本地单用户兼容适配器可以注入固定本地身份，但仅在显式本地模式内生效；不能作为 Linux 多人入口的匿名兜底。服务进程具备读写多个用户目录的操作系统权限，不等于应用用户彼此可读；本方案不声称可对服务器管理员提供密码学隔离。

**何时回头**：需要组织身份、SSO 或公开注册时扩展认证适配，不改变对象级授权。

## §3 书库只消费不可变发布包

**决策**：现场与引用固定到不可变的书库发布对象。

**否决**：浏览器传绝对 `dir`；按进程“当前书”定位 PDF；原地同步正在使用的正文 / 图谱 / 映射；从同名文件推断内容版本关系。

**命门**：继承 ADR-0146：搬迁不改变 `book_id`，内容或实际来源附件改版形成独立新 `book_id`。发布登记生成稳定 `publication_id`，关联不可变目录、完整清单和既有 readiness；`PublishedBookRef = { book_id, publication_id }` 固定该次成果。清单保留既有 `source_fingerprint` 及各能力版本，来源校验沿原合同执行。

预构建发布逻辑与各能力 readiness 不重写。Linux 增加“私有暂存 → 校验完整包 → 原子登记供读时使用”的交付边界。普通阅读、语义能力、正式学习分别消费既有就绪条件。新包登记本身不替换在途 Run 或活动窗口；视频同源补齐另按下述接入约定推进。

**视频补齐扩展（2026-10-02，已确认设计、待实现）**：同一原视频、同一英文转写版本下，已验收的新发布在该窗口无未发送提问草稿且无在途回答时自动接入，保留播放位置、播放状态、倍速、聊天和滚动锚点。开始输入后固定该轮材料与提问现场，历史引用继续持有原发布。已完成片段可先交付，所需媒体、映射和索引依赖共同可读；原视频或英文转写改版仍由用户主动使用新版。采用保留现场的接入路径，普通材料切换与现有实现边界保持原义。依据：[视频 Grill VQ36](../grill-video.md#vq36-同源补齐成果自动接入2026-10-02)。

运行账户只读发布包；注册表、纯内容派生缓存和私人数据移到各自可写目录。已有读时写入必须逐项迁出或禁用，不能靠 UI 隐藏宣称书库只读。旧引用继续指向旧材料，材料不可用时明确报告，禁止跳到最新版本冒充原证据。

**何时回头**：需要远端对象存储或更细发布粒度时调整读取实现，不改历史证据归属。

## §4 不用 Redis，但接单必须可恢复

**决策**：服务元数据入 SQLite，私人业务沿用原存储。

**否决**：把所有活跃状态写 Redis；已返回接受却只放内存队列；新增一套替代 AgentHistory、ResidentGoal、Learning 或预构建任务状态的业务真相。

**命门**：接单记录复用既有 `turn_id`，拥有请求幂等、归属、排队、领取和容量占位。规范化请求与冻结输入保存在用户 Pending Turn 中，幂等比较直接读取这些字段；最终回答仍由 AgentHistory 提交，教学事实仍在 `learning.db`。接单准备使用稳定 ID 和冻结载荷跨存储提交；恢复读取已有教学回执，不重新计算回应次数或教学绑定。

只有接单、完整 Pending Turn 及本请求必要的教学准备回执持久化，且状态成为 `queued` 后，才能返回 202。同用户同键同内容返回同一 `turn_id`；同键不同内容返回冲突。准备中的同键请求等待原准备完成或返回准备中状态，不重复提交。数据库满、私人存储失败或队列容量不足时不能伪装为已接受。

SQLite 使用本机文件系统、短事务和有界连接 / 忙等待；服务主写进程独占运行根目录。WAL 支持读写并行但仍是单写者，不能以共享网络目录代替分布式数据库。[S5] JSON 快照保持每用户统一提交，不因引入 SQLite 就全量重写个人数据模型。

**何时回头**：实测数据库写争用或多后端部署需要时评估 PostgreSQL；跨进程协调 / 广播需要时评估 Redis。两者不是互相替代的决策。

## §5 Run 固定归属，Reader 读写检查现场代次

**决策**：运行固定原归属，现场读写受代次约束。

**否决**：用服务器全局 busy 阻止所有用户；按任务结束时的当前书保存答案；克隆整份用户状态后写回；取消一个 Run 顺带取消其他读者。

**命门**：`RunScope` 绑定 `user_id / workspace_id / workspace_generation / chat_session_id / turn_id / published_book_ref / provider_binding`，并持有提问时必要的现场快照。用户和资源权限由宿主建立；私人写入口与现场读写端口分开。

同代次内保留实时 Reader 与用户操作优先规则；切书、换聊天或接管使 generation 更新。旧 Run 的实时 Reader 读取返回现场失效，导航、布局和演示恢复返回未应用；回答可依据原材料和冻结现场继续提交到原聊天，私人笔记仍按原材料授权提交。

不同用户可并发；同一聊天最多一个待执行 / 活动 Run，每现场最多一个可变 Reader Run。多人模式删除聊天与接单 / 领取共用占位边界，存在 preparing、queued、claimed 或未保存结果时返回忙；处理完运行后才可删除，引用该聊天的现场清除选择并更新 generation。

按用户公平调度，分别限制模型、预览、绘图与动画资源，旁路调用计入相同资源限制。采用并发 / 排队上限及实际 usage 记录；单轮累计 Token 与模型调用次数不触发停机，持续执行规则见 [ADR-0150 §3](0150-resident-unbounded-tool-loop-and-progress-stops.md#3-多人服务模型调用与用量)。锁、事务和网络等待分离，继续复用现有 HTTP 和 Agent 核心。

**何时回头**：确需同一聊天分叉并行，或同一现场多人控制时，另行定义冲突与合并语义。

## §6 恢复观察不等于恢复执行

**决策**：历史决定交付，仅恢复输入可重建的未领取回合。

**否决**：重连再次 POST 问题；逐 token 持久化；根据内存队列为空认定没有待处理任务；依赖 Redis Pub/Sub 保证回放。

**命门**：本进程内重连使用同一 Run 的快照和序号；重启后按接单、原聊天及必要教学回执对账。只有未领取且输入完整可重建的 queued 回合可重新调度；依赖已丢失待确认操作的回合结束为需要重新确认。待确认敏感候选保持原有临时存储边界，仅保留必要的非敏感操作身份。

已领取、已经开始或执行情况不明的回合标为中断 / 待核对，不自动重放。最终历史已提交时只修复索引。用户实例持有待确认操作时暂不回收；操作到期明确失效后再回收，后续确认不能转而消费其他操作。

未保存故障、运行结束和任务目标完成继续分开。旧 `/agent/chat` 等待同一接单核心，不绕过幂等和资源限制。未来 Redis Pub/Sub 仅可用作通知，它是至多一次投递，不是断线恢复真相源。[S6]

**何时回头**：明确需要跨进程续执行时，先定义工具幂等、检查点和副作用确认，不能仅换队列实现。

## §7 Tutor、演示与多设备连续性

**决策**：保留一个用户的全局 Tutor 控制和单一当前教学会话；消息、演示与教学行为保持原有明确关联。

**否决**：每窗口新建同一个人的掌握度；在另一窗口关闭 Tutor 后，旧 Run 继续推进原教学；演示附属页为了隔离而另起聊天；设备滚动直接覆盖另一个活动窗口。

**命门**：`learning.db` 从用户级私人根解析。Tutor 修改沿既有 `operation_id / expected_revision` 提交，旧运行提交教学行为时核验确切教学会话与控制代次。默认显示偏好可按用户 + 设备 + 来源保存，当前现场按窗口保存；恢复检查点采用服务端 revision，不用客户端时间决定谁覆盖谁。

新独立标签页得到新现场；刷新可恢复原现场，发生连接归属冲突则分叉或显式接管，不能悄悄共享可变 Reader。演示附属视图通过已有宿主关系显式关联原现场。退出登录清理用户范围缓存、观察连接和待发送草稿，不把上一个账号的现场暴露给下一个账号。

**何时回头**：需要并行课程或离线同步时另定产品语义，不在本次改造中隐含支持。

## §8 模型生成代码在受限执行层运行

**决策**：多人服务中的 Python、动画与浏览器预览只可通过已验收的隔离执行器运行；未具备时对应能力默认禁用。

**否决**：把临时目录、普通子进程或超时当作沙箱；把主服务 API Key、其他用户目录或容器管理 socket 交给生成代码；让模型决定挂载和启动参数。

**命门**：当前绘图会执行生成的 Python，且通过普通 `Command` 启动；`Command` 默认继承父环境，因此需要显式环境白名单与操作系统级隔离，而不能只修改提示词。依据：`crates/server/src/presentation_plot.rs:46–58,89–122`；[S7]。

执行器仅接收本任务允许的内容副本和受限输出目录；无生产凭据、无用户数据根、默认无网络、非特权身份，限制内存 / CPU / 进程数 / 输出大小 / 时间并清理进程树。容器、命名空间、权限和资源限制需要组合与实测；使用容器并不自动免除隔离验证。[S8]

浏览器内嵌演示继续用受限 frame、CSP 和宿主消息合同，不把认证令牌传给演示页，不让生成 HTML 与宿主共享凭据权限。多用户鉴权与生成代码隔离必须分别验收。

**何时回头**：确需联网检索或更高权限计算时，增加明确受限的能力代理，不放开整个执行环境。

## §9 迁移、回滚与上线门槛

**决策**：旧数据迁入指定账号，新旧实例使用独立数据根。

**否决**：复制旧数据给全部新账号；通过全局字符串替换修改来源；复制正在写入的 SQLite 主文件却忽略 WAL；多人开始写入后无检查地切回旧二进制。

**命门**：迁移前停写并备份，保留原目录和数据版本；逐项映射 Memory、History、Learning、Presentation、私人目标成果及阅读位置。SQLite 使用一致性备份方式，文件和数据库间通过停写形成同一恢复点。[S5][S9] 迁移按操作 ID、目标状态和映射记录续接；原始引用与已发生事实不重写。写入者锁约束遵守该协议的服务与工具，旧二进制通过独立根和停写切换隔离。

对外开放至少通过账号越权、资源越权、同用户多窗口、幂等接单、崩溃窗口、书籍换版、Tutor 冲突、受限执行或确定性禁用、Windows / Book MCP 回归与真实 HTTPS / SSE 验收。性能阈值须在基线切片冻结，不能把有限样例通过解释为无限用户容量。

**何时回头**：上线后的恢复目标或数据保留要求变化时调整运维政策，不绕开数据兼容检查。

## 结果与代价

该设计保留现有 Rust / TypeScript / Vue / Tauri、Agent 核心、个人学习模型和预构建流程；主要改动集中在宿主归属、请求边界、私人存储注入和调度恢复。收益是避免多人互相覆盖上下文，也避免为了早期并发直接引入分布式运维。

代价是需要较大范围审计 `AppState` 的隐式使用，处理服务 SQLite、私人 JSON 与教学存储的准备 / 恢复，补齐资源接口和模型旁路，并对生成代码执行设置真实边界。MU1 和 MU6 作为实施阶段，分别拆成三项与四项独立验收的小切片，具体输入、产出与完成判据见切片方案。

## 已知限制

首版保留单机故障域和每用户文档写入的容量限制；常驻现场及全部 Book 引用纳入容量验收。Provider usage 缺失时记录未知；按用户累计金额 / Token 硬额度及消费对账待明确需求后独立设计。已领取回合和依赖已丢失临时操作的回合需要用户重新发起或确认。
