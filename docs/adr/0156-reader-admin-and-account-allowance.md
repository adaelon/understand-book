# ADR-0156 运营后台与账号使用额度

状态：设计已接受，2026-10-08；ADM0–ADM10 已完成并于2026-10-08上线，实际费用差额见[ADM10运行单](../运营后台-ADM10发布运行单.md)；后台见 [ADM7 合同](../运营后台-ADM7实现.md)，读者额度见 [ADM8 合同](../运营后台-ADM8实现.md)，汇总与回访见 [ADM9 合同](../运营后台-ADM9实现.md)。

面向首批几十位受邀读者，服务端统一提供模型调用，运营者在线管理账号、登记微信人工收款并授予使用额度。实施合同与源码依据见[切片方案](../切片方案-运营后台与账号额度.md)。

2026-10-09 账号入口扩展：[ADR-0159](0159-email-accounts-and-single-use-beta-invites.md) 增加内测码邀请、邮箱注册和自助密码管理，已接受设计、待实现；材料授权、人工收款和使用额度继续沿用本 ADR。

## §1 运营入口

**决策**：在现有多人服务内提供轻量运营后台。
**否决**：
- 独立管理服务与第二套账号：增加部署和身份同步成本。
- 在线请求启动离线管理程序：与现有服务写锁冲突。
- 仅隐藏管理按钮：普通读者仍能直接调用接口。
**命门**：管理命令经现有登录、服务端管理员身份和写请求校验，复用同一 ServiceWriter 与 ControlStore；首个管理员由本机离线工具授予。
**何时回头**：出现明确的多人运营职责分工时，再细分管理权限。
**展开**：[身份与在线管理](../切片方案-运营后台与账号额度.md#2-身份与在线管理)。

## §2 收款、额度与成本

**决策**：人工收款、使用额度与调用成本分账。
**否决**：
- 收到多少元就允许花多少模型成本：无法表达服务定价与赠送。
- 首版接自动支付和订阅：首批人工处理尚能覆盖。
- 将模型 Token 总量作为余额：不同计费项的单价不同。
**命门**：收款登记和对应额度授予同事务提交；赠送与更正独立记原因，原记录保留；使用额度以人民币模型成本口径表达，不作为用户现金余额。
**何时回头**：人工核对和开通订单成为实际运营瓶颈时，接入支付渠道。
**展开**：[额度与收款合同](../切片方案-运营后台与账号额度.md#3-额度与收款合同)。

## §3 额度期与所有权

**决策**：每账号在一个时刻使用一个额度期。
**否决**：
- 按聊天或设备分别给额度：同一读者可重复消耗。
- 自动滚入下期或无限续期：改变授予时说明的有效范围。
- 改价后重算旧账：历史消耗无法复核。
**命门**：调用固定账号、额度期与费率版本；追加只改变指定期的授予量；过期和停用不删除私人阅读成果。
**展开**：[额度与收款合同](../切片方案-运营后台与账号额度.md#3-额度与收款合同)。

## §4 模型请求准入

**决策**：每次实际发送前预占额度，返回后结算。
**否决**：
- 只在用户点击发送时扣一次：漏掉内部推理、压缩与重试。
- 等整轮历史保存后才扣费：崩溃或保存失败会漏账。
- 以 LangSmith 导出作为账本：观测可关闭或丢弃。
**命门**：短事务原子检查可用额度并预占；模型网络等待在锁外；每次传输重试独立留痕，重复用量帧只取该次发送的最后有效快照。
**展开**：[调用预占与结算](../切片方案-运营后台与账号额度.md#4-调用预占与结算)。

## §5 成本事实与未知值

**决策**：确认成本与待核算占用分别保存。
**否决**：
- 超时或缺失用量记零：请求可能已经产生费用。
- 预估 Token 直接当账单：估计不能证明实际费用。
- 推理 Token 再加到输出：当前 Provider 合同中它是输出子集。
**命门**：保存 Provider 用量、费率快照、估算来源和结算依据；未知发送保留占用并允许人工核算；超出预占的真实费用完整入账，不足时停止下一次发送。
**何时回头**：供应商提供可关联的请求账单接口时，再自动核对待核算记录。
**展开**：[调用预占与结算](../切片方案-运营后台与账号额度.md#4-调用预占与结算)、[已知限制](../切片方案-运营后台与账号额度.md#10-已知限制与上线前运营配置)。

## §6 持续执行与额度停止

**决策**：额度不足结束本轮并保留未完成目标。
**否决**：
- 恢复固定轮数或累计 Token 停机：与 ADR-0150 的进展判断冲突。
- 加额度后自动重跑：可能重复已发生的工具效果。
- 为余额压低下一次输出上限：会改变既有生成策略。
**命门**：额度是多人服务的费用授权边界；保存已完成结果与明确停止原因，补额度后由读者显式继续；普通阅读、笔记与历史访问沿用原授权。
**展开**：[停止与恢复](../切片方案-运营后台与账号额度.md#5-停止恢复与读者体验)、[ADR-0150](0150-resident-unbounded-tool-loop-and-progress-stops.md)。

## §7 持久化与恢复

**决策**：运营与额度事实进入现有服务数据库。
**否决**：
- 只在内存里维护余额：重启丢账。
- 新建通用支付平台或消息队列：当前服务不需要。
- 删除聊天时删除费用记录：已发生费用独立于内容生命周期。
**命门**：沿用 control.sqlite 的版本升级、短事务与备份；管理操作和调用结算按稳定操作身份提交一次；恢复修复账目状态，不重发模型请求。
**展开**：[持久化与接口](../切片方案-运营后台与账号额度.md#6-持久化与接口)、[迁入与验收](../切片方案-运营后台与账号额度.md#9-迁入上线与验收)。

## §8 首轮运营数据

**决策**：后台展示账号、收款、用量与回访事实。
**否决**：
- 用 Token 多寡推断学习效果：两者没有对应关系。
- 从全体聊天正文扫描生成报表：增加内容访问和运行负担。
- 把未核算费用从合计中隐藏：会误导成本判断。
**命门**：报表从运营和运行元数据生成；已结算成本、正在使用的预留、待核算占用分别展示；任务完成采用既有交付事实。
**展开**：[后台与读者界面](../切片方案-运营后台与账号额度.md#7-后台与读者界面)。

## §9 后台前端选型

**决策**：采用 shadcn-admin 建立独立 React 后台。
**否决**：
- 将模板改写为 Vue：失去直接复用页面与组件的收益。
- 将 Reader 整体迁移到 React：扩大到阅读现场与桌面端，超出后台目标。
- 沿用模板模拟身份或另接 Clerk：与现有服务账号和权限分裂。
**命门**：`apps/admin` 挂载 `/admin/`，与 Vue Reader 共用 Cookie、CSRF 和 Rust 管理 API；后台静态资源由现有 Nginx 提供，随同一 release 发布，保留上游 MIT 声明。
**何时回头**：跨前端复用界面或维护两套依赖成为实际成本时，再评估统一框架。
**展开**：[前端与发布合同](../切片方案-运营后台与账号额度.md#7-后台与读者界面)、[shadcn-admin](https://github.com/satnaing/shadcn-admin)。
