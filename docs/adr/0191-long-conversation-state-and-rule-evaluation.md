# ADR-0191 按实际请求和交付验收长对话

2026-11-19 · **已接受。** 三项实验已取得实际请求和运行记录。本机交接、检查点恢复与真实模型配对的结果见[切片实施记录](../切片方案-长对话状态保持与规则遵循.md#实施记录)。首次失败的修法、真实模型复验和窄屏成品见[修复结果](../切片方案-长对话状态保持与规则遵循.md#修复结果)。

读者在第一轮约定讲义的记号，中途改正一个数值，第八轮只说“按之前的约定整理”。如果最后沿用了旧值，可能是 Reader 没有带入纠正、压缩摘要写错，也可能是模型看到了正确要求却没有照做。**以送达模型的请求、工具回执和最终产物定位长对话失败。** Reader 保存的用户原话确定当时的要求，实际写入和交付状态确定发生过的动作，模型摘要作为待核对的语义记录。

本机 ACP 每轮新建会话，验收 Reader 交给外部 Agent 的历史与任务；内置 Resident 管理活动上下文，验收检查点安装前后及进程重开后的请求。两条入口共用读者场景，各自承担其可观察的状态。这样可以先用受控回放定位历史丢失，再把真实模型预算用在规则已送达之后的理解、执行与恢复。[本机 Agent 的职责](0189-local-agent-learning-with-acp-and-mcp.md) · [活动上下文预算](0091-model-aware-agent-request-tool-exposure-and-active-context-budget.md) · [会话日志](0152-resident-linear-jsonl-session-log.md)

模型比较沿同一 Reader 工具路径，按供应商回报的**单次输入**分档；任务累计用量用于核算成本。模型首次是否遵循、门禁是否拦截、收到诊断后是否自行修好，分别保留证据。只看最终成功会漏掉反复违规的成本，只看工具错误又会把成功纠错算成失败。只有相同条件下的独立重复出现长短档差异，才进一步定位退化区间。[无进展与恢复](0150-resident-unbounded-tool-loop-and-progress-stops.md) · [分层评测](0137-stratified-reading-evals-and-diagnostic-improvement.md)
