# ADR-0187 开源本地应用与云端服务双发行

日期：2026-11-17。状态：**已接受，实施中。** Windows／macOS 本地应用与网站云端服务作为两个独立交付产品，共用阅读与教学核心。实施接点、依赖、升级及验收见[切片方案](../切片方案-开源本地应用与云端服务双发行.md)。

**决策：双发行共享学习核心，宿主独立装配。** 公共核心维护阅读、来源、教学、练习、私人学习记录、画板及模型协议的共同语义。本地宿主承接本机数据、用户模型配置与系统集成；云端宿主承接账号、授权、托管模型、服务额度、云存储与运营。共同能力在公共核心修改一次，由两种宿主分别集成与验收。

## 产品与代码归属

开源本地版提供完整的本机阅读和 AI 学习运行时，安装后无需网站账号即可打开已准备材料、配置自己的模型并学习。Windows 与 macOS 使用同一套应用源码和平台资源适配。网站云端版在服务器运行同一学习核心，由平台提供模型、账号下的数据、共享课程与持续服务；可用课程和资源沿各自实际授权提供。

**本地产品与发行以既有正式 Setup 体验为基线。** Windows 复用 Tauri 桌面壳、currentUser NSIS 安装向导、图标、快捷方式、升级与卸载流程，接入公共本地运行时；macOS 提供相应的正式 app/DMG 安装体验。local-debug 仅作为本地 Reader/AI、设置和持久化行为的开发参考与验证入口。普通用户通过安装包和应用图标完成使用，应用负责启动本机服务、定位资源和保存数据。

代码目标组织为**公共仓库与云端扩展仓库**。公共仓库包含公共学习核心、共享阅读界面、本地应用、必要本机辅助资源、预构建插件与 Build Engine；云端专属入口、账号套餐、运营和部署扩展归云端私有仓库。云端固定引用公共核心的明确版本，公共构建不依赖私有仓库或运营配置。现有云端桌面客户端作为云服务的客户端归云端发行线，保持独立应用身份和升级路径。

共同教学实现随本地产品公开。云端产品以托管运行、课程供给、多设备访问和服务运营形成差异；共享核心的修复回到公共仓库，云端通过依赖升级接入。具体仓库路径和包名在拆分切片形成可运行边界后确定；本 ADR 不变更已有许可证，也不代表已执行仓库迁移或公开发布。

## 宿主边界与数据

业务核心依赖已有的运行状态、模型用量和服务接口。宿主提供身份/材料访问范围、存储位置、模型选择、运行准入与系统资源实现。云端授权、额度扣减和结算由云端宿主执行；本地使用用户自有模型时记录实际用量，本地学习不依赖平台余额。协议适配器、教学 prompt、工具注册与引用规则继续共用。

前端按本地和云端入口装配共享阅读/教学组件。文件书库、模型设置与系统菜单归本地入口；登录、套餐与云工作区归云端入口。构建目标具有各自入口与依赖，避免通过遍布业务代码的产品判断承担隔离。

本机记录与云端账号记录分别持有。应用安装、升级或登录不自动上传或合并本机资料与记录；已有显式云端副本操作沿原合同。新本地应用使用独立应用标识和数据目录，旧 Debug 数据通过明确的一次性导入承接；云端拆分通过原数据库升级与发布流程承接在用状态。材料、发布、课程、聊天、运行和学习证据身份沿原事实保留。

预构建继续采用插件和外部 Harness：Harness 管理模型配置与执行器生命周期，Build Engine 管理计划、候选接纳、恢复和发布。阅读器消费已有成果并呈现插件准备入口；平台可沿原维护管线准备云端资料。两种发行形态不新增独立的内置预构建模型循环。

## 与既有决策的关系

- **部分修订 [ADR-0173](0173-cloud-learning-subscriptions-and-exam-sprints.md)**：其账号、套餐、云端数据与现有云服务客户端合同继续有效；“正式产品全部围绕云端、收缩完整本地核心交付”的定位由双发行取代。新本地应用独立于现有云客户端升级。
- **落实 [ADR-0186](0186-multi-protocol-reader-model-providers.md) 的产品归属**：协议与能力解析属于公共核心，本地用户和云端管理员分别管理所属配置；九类协议及云端变体的原覆盖目标继续由模型接入方案维护。
- **承接 [ADR-0068](0068-windows-desktop-reader-and-codex-plugin-distribution.md) 的正式安装形态**：复用用户级 Tauri/NSIS Setup 与桌面生命周期；公共安装资产与本地运行时装配进入开源发行，当前云客户端的登录和远程 Reader 装配仍归云端。插件准备继续沿现行插件合同独立管理。
- **承接 [ADR-0122](0122-linux-reader-host-and-source-deployment.md) 与 [ADR-0138](0138-multi-harness-prebuild-and-deepseek-harness-adapter.md)**：源码单用户阅读仍可复用公共宿主，插件构建与阅读运行时保持独立。多人授权、学习工作区和费用规则继续沿各自原 ADR。

## 取舍

完整复制两套代码会使共同教学和数据语义随修复分叉；采用共享核心和明确依赖版本。一个应用同时装入两套账号、存储与付费状态会增加使用和测试复杂度；首轮提供独立产品入口与发行物。模块先在现有工作树形成可构建边界，再迁移云端扩展，保持每个切片可运行和可验证。

Windows／macOS 安装包与网站独立编号和发布，分别记录使用的公共核心版本及数据格式要求。共同核心升级需要两类宿主的合同与代表性学习路径验证，平台安装包还需在相应操作系统实际验收。出现明确的跨端同步或统一桌面登录需求时，再基于现有身份与数据规则设计相应能力。
