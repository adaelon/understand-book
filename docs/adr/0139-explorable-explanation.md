## 背景

Understand Book 已有富文本制作、HTML/CSS/JavaScript 交互、真实浏览器预览、版本化内容、现场状态和 Python/Matplotlib 静态绘图。EX6 已补充时间定位预览；连续变化目前主要靠候选临时编写，方法指导的增益仍需真实对照确认。

[ED3–ED4 记录](../performance/agent-presentation-ed3-ed4-20260925.md)已有能显现学习率方向差异的交互页面，但制作成本超标，最终文字出现数值错误。新方案以该实际产物为表示基线，分别验证解释方法、连续过渡和制作辅助的新增收益。

3Blue1Brown、Ciechanowski 等提供方法参考。目标是把对象连续性、渐进揭示、动态对照、参数探索、轨迹残影、不变量高亮、视角切换、反例、预测后揭示等能力内化给 Agent，保持 Understand Book 的统一视觉语言。

## §1 能力命名

**决策**：建立 `explorable-explanation` 可探索解释方法能力。

**否决**：`style=3b1b` 或按作者建立互斥 skill；用黑底、彩色公式、动画数量衡量解释质量；按学科建立固定页面模板。

**命门**：Agent 根据当前理解障碍选择解释动作；来源、权限、版本、学习状态和交付资格仍归既有 Runtime/Server/Reader 合同。

## §2 Explanation Moves

方法库按“用户需要看见什么关系”组织。首批 repertoire：

1. `object-continuity`：变化中保持对象身份。
2. `progressive-reveal`：控制同时出现的信息量。
3. `transform`：显示 A 如何变成 B。
4. `compare-in-motion`：暴露静态相似但过程不同。
5. `parameter-sweep`：改变参数观察响应。
6. `trace-ghost`：保留历史轨迹。
7. `invariant-highlight`：突出变化中的不变量。
8. `viewpoint-change`：换坐标、表示或视角显现结构。
9. `counterexample`：用边界/反例打破错误泛化。
10. `prediction-reveal`：先预测，再揭示。
11. `decompose-recompose`：拆解后重组。
12. `concrete-to-abstract`：从具体直觉收敛到符号规则。

方法可组合，不构成固定流程，也不要求把方法名展示给用户。

## §3 最小设计判断

skill 教 Agent 在制作前考虑四件事，沿用现有制作合同：

- **Obstacle**：用户究竟没看见哪个差别、关系或机制？
- **Objects**：哪些对象必须保持身份？
- **Change**：什么变化最能显现目标关系？
- **Interaction**：什么操作最有助于理解；无必要则不加。

这些判断在当前制作过程内完成，不要求独立模型回合、公开输出或强制 `presentation.plan`。普通文字足够时直接回答。

## §4 连续演示运行模型

**决策**：浏览器承载连续演示，Matplotlib 承载静态图。

采用“可定位场景”方向：

`renderAt(transition_progress, semantic_state, parameters, reveal_state?) -> visible scene`

**命门**：算法/数学的 `semantic_state` 与视觉 `transition_progress` 分离。暂停、定位、保存、重开与追问共享可重建的现场；视觉插值保留过渡含义。详细行为见[方案第 1 节](../切片方案-可探索解释方法库与连续视觉演示.md#1-目标链路与时间现场)。

**否决**：视觉插值冒充算法真实状态；先建设通用动画 DSL；让公共 helper 成为时间预览的前置条件。

**何时回头**：真实样板证明重复时间控制与恢复代码造成明显成本时，再从 SVG/Canvas/JavaScript 和现有 `window.presentation` 接口提炼公共 helper。

## §5 观察边界

逐帧视觉变化与需要宿主认证的语义变化分层：

- 高频几何属性、透明度、位置留在页面本地。
- 参数操作完成、阶段切换、暂停/回退和追问形成可捕获状态。
- 新增/改变可见文字、来源引用继续走现有公开内容与来源校验。
- 交付沿用既有门槛。

现有 bridge 会观察正文子树的节点、文字和属性变化；文字与来源未变时通常不新增宿主请求，但本地克隆、扫描仍可能发生。动画基准随 EX1 样板进行，分别测本地观察耗时、帧间隔、宿主请求及保存次数。先确定目标帧率和观察开销预算，超出预算再优化观察粒度，保持语义校验。

## §6 时间预览

**决策**：扩展 preview，使其能有界观察连续过程。

**命门**：时间预览基于真实样板的最小定位约定，可独立于公共 helper 实现。定位先停止推进，在同一稳定场景上采集截图、DOM、layout 和 issues，并绑定候选、环境、动作序号与场景位置。

**否决**：开放任意脚本执行；把持续播放期间分次取得的结果当作同一帧；将关键时间点与全部视口、参数做笛卡尔积。

最小检查包含起点、中间位置、终点、回退和重复定位，检查对象身份、标签遮挡、公式/图形一致性及未来轨迹残留。播放流畅度在真实播放中验收，保存、重开和追问在真实 Reader 验收。

## §7 金样板

先用已有学习率“表示盲区”做金样板，再按新增收益决定公共能力。

给定 `L(w)=(w-2)^2`、`w₀=0`、更新规则 `wₖ₊₁=wₖ−2η(wₖ−2)`，则误差满足 `eₖ₊₁=(1−2η)eₖ`：

- `η=0.2` 与 `η=0.8` 的距离和损失序列相同，分别同侧接近与跨越最优点交替接近。
- `η=1.1` 的误差每步乘以 `−1.2`，交替发散。以上结论限定于该简化模型。
- 图形标签与 readable content 从同一计算结果派生；页面、readable content 和最终交付文字均用独立已知算例核对。

以 ED3 已交付页面为基线；相同信息与算例下比较连续过渡与静态或离散步进表示，确认对象跟踪、跨越过程等具体收益。带符号误差或轨迹的收益单独归因。

该样例可组合 `compare-in-motion -> trace-ghost -> invariant-highlight -> prediction-reveal`，方法顺序随理解障碍选择。

## §8 Skill 与加载

沿用 Resident 的短核心 `presentation-method` 入口，`explorable-explanation` 为能力名称。详细方法参考只有在真实对照证明有必要时才按需拆分，并同时提供 Resident 可用的最小读取或注入路径，以实际模型请求中的参考内容验证接入。

完整方法参考按需加载。`.comparison`、`.card`、`.callout` 为可选布局能力。

## §9 Manim

本节保留 EX9a 阶段的样片决策与工程结论；2026-09-28 起，局部短片段的产品建设按 §14 和 EX11 推进。

Manim 产品渲染支路保持条件性。2026-09-27 用户确认新增并提前开展 EX9a：当前学习率题目的 Manim 连续讲解样片，与已有浏览器动画对照；样片验证不再以 EX7/EX8 为前置。具体范围与顺序见[切片方案 §0.1、§11、§13](../切片方案-可探索解释方法库与连续视觉演示.md)。

依据实际样片的质量与制作成本对照决定是否设计产品渲染支路；选择接入后，按实际需要定义依赖、受限执行、取消、资源格式、预览、版本保存、Reader 媒体/CSP、缓存和跨平台部署。

临时目录和超时不等于代码执行沙箱。

EX9a 于 2026-09-27 完成定向样片与工程对照，见[实际结果](../performance/explorable-explanation-ex9a-manim-comparison-20260927.md)。现阶段保留浏览器主路径，Manim 用于离线讲解样片；跨点停顿、箭头与公式强调属于此次编排收益，不能据此判定引擎独有优势。用户随后明确实时交互需求并确认 EX10；自然请求稳定性未取得，Manim 产品接入仍为条件性。

## §10 PresentationBrief

`PresentationBrief` 沿用 ADR-0133 的条件性结论。未来只有跨轮修改证明设计意图无法从成品恢复时，才在 Brief 实验中保存“为何选择此表示”等信息。方法名只表达制作方法。

## §11 验收

三项分别记录：

1. **工程可用**：可交付、播放稳定、暂停/回退/恢复一致、触控可用、成本可接受。
2. **表示有效**：关键差别可见，连续变化有具体解释收益，画面、公式、说明一致。
3. **学习效果**：记录真实用户接触解释前后的表现，使用未展示的新参数或新例子观察预测及原因解释。

质量目标、运行次数与成本界限由 EX0 在处理组运行前冻结，后续实验引用同批记录。独立答题者用于检查表示；真实用户学习效果单列，未开展时记为“尚未评估”，工程与表示验收可分别完成。

点击、停留、播放完成、页面无错误或 Agent 自评均不能单独证明学习效果。

## §12 页面计算结果回读

**决策**：解释中的具体数值回读页面计算结果。

**否决**：
- 仅补充算术提醒：已出现页面数值正确而最终文字配错步号。
- 截取整页前部文字：结果可能位于截断点之后，压缩会丢失参数关系。

**命门**：`preview(read_selector)` 返回的文字、实时参数、数学步号和观察来源整体保留；容量不足时省略整条读取结果并明确请求缩小范围。
**展开**：[结果读取实现与验证](../performance/explorable-explanation-ex2-result-read-20260927.md)。

## §13 二维交互图形库对照

本节记录 EX10 冻结批次的历史决策；用户后续视觉反馈及新的开发方向见 §14。

**决策**：EX10 对照已于 2026-09-28 完成，采用证据不足，保留原生 SVG，不进入 Konva 产品接入。

**否决**：
- 将视频播放视为交互解释完成：用户需要拖动参数后的实时反馈。
- 直接采用全套图形库：先证明一套二维候选能改善 Agent 制作质量或成本。

**命门**：两组同请求、同体验与共同底座；固定资源随候选保存，库与使用资料的整体收益单独归因。
**何时回头**：同题结果不足以支持采用，或后续跨领域任务出现不同图形需求。
**实施证据**：工程点线场景通过。第一批 C 因实验装配写入模型历史而耗尽上下文；修复后第二批 B 遇 Provider 输出截断，两批按合同停止。现有 SVG 交付原稿和 Konva 诊断原稿也有必要质量错误，未满足采用门槛。装配移至 test-only Author Write 边界，生产 CSP、大小限制和 ed3.v1 不变。

**第三批补证**：用户要求重做后，B/C 均保存交付版本，真实请求历史验证装配修复有效。C 的动态边界解释和圆点拖动较好，但成本及修订更多，且触控、提交、零位移图形不通过，回执标为不完整。仍不足以采用；见[第三批报告](../performance/explorable-explanation-ex10-svg-konva-batch3-20260928.md)。

**展开**：[EX10 合同、停止条件与采用依据](../切片方案-EX10-Agent二维交互图形库对照.md)、[实际结果与下一入口](../performance/explorable-explanation-ex10-svg-konva-20260928.md)。

## §14 通用制作与局部动态演示

**决策**：建设通用 Konva、局部 Manim 与密度指导。

**否决**：
- 只精修学习率样板：无法证明 Agent 能在其他主题复用制作能力。
- 默认长视频与固定卡片布局：局部解释需要按关系组织图文和操作。

**命门**：正式供给、实际模型指导、跨题生成及 Reader 现场共同验收；旧实验失败记录保留。
**何时回头**：真实生成暴露表示选择、媒体成本或状态恢复问题时，修对应路径并另开验证批次。
**展开**：[EX11 详细合同](../切片方案-EX11-Konva通用能力与局部动态演示.md)、[实际网站观察](../performance/ciechanowski-observation-plan-20260928.md)。

## 后果

前期金样板、时间预览、EX9a 和 EX10 的结果保留为能力与问题证据。当前按 EX11 依次建设固定 Konva 供给、通用制作指导、短动画资产、内嵌播放与恢复，独立处理短屏操作及回合收尾，然后进行跨题验证。

用户对 Konva 的视觉反馈支持继续投入；现有工程与内容缺陷作为具体改进项。公共 helper 仍由真实重复劳动触发，学习效果需要另外取得读者证据。
