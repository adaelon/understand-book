# ADR-0181 来源知识树与理解果实

2026-11-05 · 已接受，已于 15:55:12 HKT 上线。承接 [ADR-0179](0179-note-thinking-path-and-current-understanding.md)、[音乐伴听](0175-curated-music-prebuild-and-guided-listening.md)及[设计方案](../设计方案-知识树与理解果实.md)。执行进度与验证见[切片方案](../切片方案-知识树与理解果实.md)，线上证据见发布记录。

## 决策

**程序将既有公共知识投影为树，私人理解按实际表达挂接。** 文字以章、节组织范围，Pass1 概念和论断作为主要枝条，discourse 在“解释、例子与论证”分枝展开，已有 BookStructure 补充主题；视频使用视觉事件、已有图谱和讲解结构；音乐使用曲式、音乐事件、主题与声部关系。生成树不追加全书分析或模型调用。普通段落、公式、图片等 LID 叶子只作为来源定位，不各占可见枝条。同一知识条目在本节多次出现时合并入口并保留各处依据，跨章节保留各自入口。树的父子关系表示浏览归属，已有语义关系保留其类型和来源；未分析范围保留真实导航与覆盖状态。

**理解果实复用 LearningEvidence 和 TeachingTarget。** 知识引用包含材料版本、产物类型与原条目身份，来源位置沿文字、媒体和音乐的既有合同保存。现有理解整理调用同时选择实际涉及的知识候选并提供相应用户原话；宿主核对来源与表达后保存。阅读、播放、选中与 Agent 讲解提供情境，不形成用户理解证据。同段或同一时刻出现只用于提名候选。历史仅有来源范围的记录保留在该范围，不推断细粒度归属。

**树、我的理解与问答双向接续。** 树上分别展示当前阅读／播放位置和真实理解记录。果实保留表达、帮助、修订和时间线，可返回来源、原讨论并继续推敲；接续不要求先有笔记。音乐保留重复演奏身份及确切录音、谱本，视频保留文字、画面、原声的各自依据。Agent 在讲解或指定片段完成后自然提出一问，承接用户的实际表达。

**先给阅读入口，再逐层展开。** 打开树时优先使用明确的知识引用，其次使用正在阅读／播放的内容范围；没有现场位置时恢复上次分枝。首屏显示具体主题及已有章节说明，缺少说明时可引用该范围按原文顺序出现的首条 discourse 摘要，并标作“开篇线索”。有理解时优先接续用户表达；没有理解时使用已有关键内容，或按原文顺序的第一条论断作为起点。音乐范围优先进入按时间顺序的已有音乐事件。起点表示浏览顺序，不推断知识重要性。

同一范围超过 6 个概念、对象、论断或关键内容时，程序增设“要弄清的关系”“会用到的概念”导航分枝，解释与论证保留原分枝。原知识身份、出现位置、来源和理解归属保持连续。叶子直接展示内容与来源；后台刷新固定当前选择，读者主动定位时才跟随新的阅读／播放位置。

## 取舍与影响

只用目录会遗漏具体概念和论断；新增全书语义重组会增加模型成本并产生另一套身份，因此沿用已接纳知识产物。图关系不天然是一棵树，多个出现位置可共享一个知识引用，交叉关系按需展示。界面以局部分枝展开和有界读取控制实际大材料的负载，新增果实不重排整棵树。

同一知识关系与能力的表达沿现有理解归组，跨知识引用分别保留原话归因。新观察追加历史；纠正复用已有修订机制；不同版本和材料不按名称合并。公共成果补齐时增加可浏览内容，私人历史仍指向当时的来源。

同一关系与能力的新表达可能从 discourse 关联到 Pass1 概念。当前判断按稳定关系与能力取最新表达；原枝条保留原话并标为先前记录，不能继续把旧误解显示为当前卡点。原记录的知识引用不因此迁移，新旧表达仍在同一理解时间线中。

连续问答没有新增读源时，后台整理沿原表达之前已交付的帮助恢复同会话、同材料版本的实际来源。普通问答使用原有后台整理；显式修改已保存理解才打开前台修改工作流。两条路径都保留表达之前真实交付的帮助，点击继续或教师讲解本身不新增理解。
