# ADR-0152 Resident 会话顺序日志

状态：已接受，2026-10-01；JL0–JL7 已实现并验证，新日志已接入正式启动与备份恢复；旧对话保持原样，不迁移。本文替代旧方案中 `agent-history.json` 的聊天历史持久化选择，其余领域归属与运行恢复合同沿用。

## §1 会话持久化

**决策**：住户会话按会话保存为追加式 JSONL。

**否决**：
- 整份 AgentHistory 快照反复重写：局部更新的保存成本随该读者全部历史增长。
- 仅将 JSONL 用作导出格式：未改变运行历史的实际保存方式。
- 会话分支树：当前产品需要顺序阅读、追问与恢复，没有分叉编辑需求。

**命门**：一个聊天对应一个追加式 JSONL；按会话序号折叠出消息、回合、目标及压缩检查点。当前状态是派生结果，历史读取不执行工具。
**何时回头**：实际出现需要编辑旧回合后保留多个后续版本的产品需求时，再讨论分支。
**展开**：[实施方案](../切片方案-会话JSONL与阅读回顾.md)、[聊天历史定义](../../CONTEXT.md)。

## §2 增量记录与模型上下文

**决策**：持久事件与模型上下文分别表达。

**否决**：
- 每轮将完整 messages 塞入一个 JSONL 事件：仍按历史长度重复写入。
- 将 SSE 字符流直接落盘：它表示展示进度，不是可恢复的回合事实。

**命门**：冻结输入引用已提交的历史位置；消息、结果和必要状态增量保存，压缩只改变模型输入投影。既有合法协议续接字段可保存，但不进入公开历史、回顾或学习证据；需清理的内部工具内容在追加前处理。当前已有的最终消息修订以显式修订事件表达。
**展开**：[压缩与冻结输入链路](../切片方案-会话JSONL与阅读回顾.md)、[运行归属与恢复](0147-linux-multi-reader-service-without-redis.md)。

## §3 阅读现场与来源

**决策**：提问现场冻结，回答保留来源关联。

**否决**：
- 用打开历史时的当前位置解释旧问题：读者可能已切书或移动现场。
- 将检索命中等同于回答依据：命中、读取、接受为依据是不同事实。

**命门**：回合保留原材料发布、位置、已验证引文，以及发送时的 Presentation 版本和状态引用；回答按实际来源绑定关联原文。已有引用身份继续使用，正文和 Presentation 内容由原存储持有。
**展开**：[材料及现场归属](0147-linux-multi-reader-service-without-redis.md)、[Presentation 共同现场](0144-shared-presentation-conversation-workspace.md)。

## §4 实际成果与用户处置

**决策**：保存实际交付及用户处置回执。

**否决**：
- 以模型声称“已保存”证明成果存在：必须有实际执行结果。
- 仅以前端“已保留／已撤销”标记作为结果：刷新和重启后无法恢复。

**命门**：笔记、标注、导航、布局与 Presentation 分别引用真实对象或操作回执。保留、撤销、忽略由服务器记录实际处理结果及原对象、结果对象身份；历史读取只展示，重新执行须走现有显式命令。外部对象与日志写入分属不同存储，不能承诺跨存储原子提交。
**展开**：[成果回执与失败处理](../切片方案-会话JSONL与阅读回顾.md)。

## §5 聊天任务与教学状态

**决策**：会话关联教学事实，沿用原有归属。

**否决**：
- 把 TutorSession、画像及学习进度整体搬入聊天日志：会改变跨聊天生命周期。
- 以助手解释过、检索过或总结过作为掌握证据：这些只证明活动发生。

**命门**：ResidentGoal 属于当前聊天；TutorSession 与教学事实属于 `learning.db`，稳定画像属于 `memory.json`。回合保留当时的教学引用、修订及可用回执；压缩继续保留任务约束、未完成事项和来源，不负责关闭教学会话或判定掌握。
**展开**：[全局 Tutor 与存储归属](0141-global-tutor-control-and-session-ownership.md)、[教学证据](0143-teaching-trace-assessment-and-learning-evidence.md)、[阅读回顾](0153-session-reading-recap.md)。

## §6 新会话启用与恢复

**决策**：从新聊天启用 JSONL，旧文件原样保留。

**否决**：
- 重放日志时重跑已开始的工具：可能重复产生笔记、导航或其他成果。
- 长期双写 JSON 与 JSONL：会形成两份需要协调的聊天历史。
- 旧聊天导入及旧格式回退转换：没有继续使用旧聊天的产品要求。

**命门**：新聊天直接保存为 JSONL，新界面只列出新日志中的聊天；旧 JSON 文件原样存留。新日志恢复沿用单写者、准入和完整事件规则，仅未认领且输入完整的 queued run 可续行；备份恢复覆盖新日志及选择元数据。书籍、笔记、学习事实和 Presentation 继续由原存储持有。
**展开**：[既有恢复合同](0147-linux-multi-reader-service-without-redis.md)、[新日志启用与分阶段交付](../切片方案-会话JSONL与阅读回顾.md)。
