# ADR-0174 独立教学教练与用户参与活动

2026-10-29 接续：[ADR-0176](0176-main-agent-planned-teaching-and-coach-guidance.md) 保留逐轮教学教练，并明确当前代码已采用“只注入就绪指导，前台不等待”的行为，取代本文早期等待安排。制作前的表达教练另沿其既有同步入口保留；移出同步交付审稿的决定尚待实施。下文其余内容保留原决策与实施记录。

创建：2026-10-21；修订：2026-10-22。状态：已接受；目的入口、系统逐轮调度与下轮自动注入的代码链路已实现，服务端及真实模型联调状态见[实施方案](../实施方案-Tutor教练与用户参与闭环.md#10-验证与会改变实施的失败)。

**决策**：系统逐轮自动调用教练，下轮自动注入指导。

用户通过点击或自由表达确定阶段目的。独立教练负责全局节奏与参与活动安排，主 Resident 负责取证、材料和教具准备、公开交付及现场回应。每个成功交付的教学回合由系统登记后台教练任务，包含讲解、提示和收束；阶段首次开始由系统生成起步指导。主 Agent 无教练调用工具，也不决定是否运行教练。

指导绑定已完成的源回合与实际交付，给出下一步规格和少量条件安排。下一轮输入照常接纳，系统在主模型采样前注入已就绪且适用的指导；任务未完成或失败时明确指导不可用，前台继续处理当前请求。当前用户输入优先，Resident 据真实表达落实或调整，并把实际过程交给回合后的教练。后台不直接接纳 TeachingDesign，也不把未来条件写成理解事实。

**权衡**：逐轮调用保证教练持续参与，增加一次模型成本及可能的下轮等待。后置指导尚未见到下一句用户输入，因此现场适配由 Resident 承担，后置教练持续复盘。采用受管理的 ReaderTask 与窄持久任务记录，独立于已经结算的前台 ReaderRun；不采用 Agent 自选工具触发或每轮额外前置规划。

**既有决策接续**：调整 ADR-0164／0172 中由同一 Resident 负责全部参与规划的职责，教练承担持续规划，Resident 按最新输入落实。TeachingDesign、实际帮助、理解证据和交付审核沿原合同。ADR-0170 的大目标／阶段边界、ADR-0171 的费用归属和 ADR-0173 的云端核心执行继续适用。

**落地**：learning schema 4 保存教练任务和回合依赖，CoachGuided 与 ready 状态同事务提交；网络与本地宿主调度，Runtime 以私有 TurnFrozen 片段自动消费。网络费用使用 ReaderTask，采用及实质调整随实际交付回流。专门的教练重试界面和真人使用观察留在实施范围记录中。

**何时回头**：真实使用中指导未被采用、未改善参与和反馈适配，或后台任务导致明显等待时，依据逐轮轨迹修正指导内容、上下文和执行开销；逐轮自动参与保持为已确认需求。
