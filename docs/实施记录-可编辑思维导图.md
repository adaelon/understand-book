# 可编辑思维导图实施记录

日期：2026-10-28。本文记录当前实现的数据、接口和执行链路；产品约定见[实施方案](实施方案-可编辑思维导图.md)。真实服务、浏览器、Rust 模型回放和规模验收的状态统一见[验收记录](performance/editable-mind-map-20261028/README.md)，布局与图片证据见[布局和导出记录](performance/editable-mind-map-20261028/layout/README.md)。

## 数据与编辑接口

主题沿用 `BoardItem.item_id`、`title` 和来源绑定，目标类型新增 `Topic { children, style, based_on }`。有序 `children` 是父子关系和同级顺序的唯一权威；父节点、分支范围、树边及主题几何从它派生。主题标题不再复制到绘图文字或正文中，长解释继续使用已有回答块、笔记和演示。

`BoardDocument.mind_maps` 保存 `map_id`、`root_item_id`、`layout`、根锚点 `anchor` 和一级分支的 `branch_sides`。布局支持 `balanced` 与 `right`。普通跨主题关系仍是独立的 `BoardLink`；树边使用子主题 ID 定位，在指定修订中解析其父子端点。旧画板缺少导图字段时读取为空集合。

`BoardView` 保存折叠主题 `folded_topic_ids`、多选 `selected_item_ids`、大纲开关 `mind_map_outline`，并复用视口、阅读对象及播放状态。视图变化独立保存，不产生内容修订。结构校验覆盖孩子存在、单一父级、无环和导图归属。

人工与 AI 共用 `BoardEditOperation`：创建导图、插入或修改主题、移动／复制／删除整支、修改布局，以及按身份增删改关系、图文映射和路线。整批先校验后提交，复制生成新 ID 并保留来源，删除同时清理失效目标。

| HTTP 接口 | 作用 |
| --- | --- |
| `POST /boards/edit` | 提交 `board_id`、`board_revision`、`operations`、动作说明 `action`，返回完整新文档 |
| `POST /boards/undo`、`/boards/redo` | 基于 `board_revision` 撤销或重做顶端事务 |
| `POST /boards/view.save` | 保存相机、选择、折叠和大纲等阅读状态 |
| `POST /boards/candidate.preview` | 读取待确认旧图重组候选的文档 |
| `POST /boards/candidate.accept`、`/boards/candidate.dismiss` | 明确接受或放弃该重组候选；接受同时检查当前修订 |

Web 调用层使用 `expected_revision` 参数，再映射为 HTTP 的 `board_revision`；后者由存储层严格比较。

`edit_history` 随画板保存事务记录、`undo_stack` 和 `redo_stack`。事务记录修订、前一修订、人工／AI 作者、动作摘要及撤销／重做关联。撤销以新修订反向恢复本次涉及的内容，重做保留原 ID；交付回执、原聊天和教学事实继续留存。新内容编辑清空重做栈，重新打开仍可读取历史操作。共享笔记正文和投影关系继续归笔记系统所有，画板撤销不回退它们。

## 人工编辑、保存和草稿

`BoardWorkspace` 保留加载、侧栏、讨论、来源与交付刷新；`BoardCanvas` 保留统一视口、自由卡片和原生板书。新增 `MindMapLayer`、`MindMapOutline` 和 `MindMapToolbar`，画布与大纲操作进入同一个 `useMindMapEditor` 控制器。

控制器先投影语义操作以即时显示，再按队列串行提交。每个操作批次记录所依赖字段的原值，收到新文档后只重放尚未提交的操作；失败保留队列和未保存提示，可重试。若相关字段已改变，保留本地修改并停止继续写入。

实际 `boardEdit` 请求飞行期间，外部交付刷新暂存最新文档。收到本次保存确认后，先移除已提交的队列头，再接入暂存文档和剩余操作。这样即使 AI 刷新快照已包含那笔人工插入，也不会重复插入或把自己的已提交结果误判为外部冲突。

正在输入的标题以 `editingId / draftTitle / draftBase` 独立保存，不随交付快照替换。结束编辑时比较当前标题与草稿基线；同主题已被修改时，显示“保留我的文字／查看当前内容”。若主题已删除，独立草稿面板继续展示文字，支持复制、另存为新主题或放弃；另存使用新 ID，不复活已删除主题。导图与大纲切换保留草稿和输入位置。

双击／F2 编辑，非输入状态下 Tab／Enter 新增子主题／同级，方向键移动选择。中文输入法确认与文字编辑器自身的撤销不触发结构命令。拖普通主题修改父级或同级顺序并带走整支，拖根主题移动整图；自由卡片仍使用独立位置。折叠属于视图操作，搜索或讲解定位会展开必要祖先。手机通过工具条、大纲“移动到”和双指缩放完成核心操作。

## AI 候选与交付

选中的 Topic 将编辑范围限定到本主题及后代。“解释这一项／没懂”允许直接回答文字；补例子、展开、简化和重新组织按需要生成语义操作。既有精确选择、最近问答和表达教练继续提供上下文。

执行链为：冻结范围与版本 → `board.author plan` 的表达规划 → `prepare` 准备操作和解释 → 公共编辑器投影 → 共享布局的实际 Reader 预览 → 按既有教学状态执行 Tutor 选择／审核 → 提交已观察的候选。普通改图直接交付并提示变化、提供撤销；同一批 AI 编辑作为一个事务。仍在生成时请求撤销，先停止运行，再撤销已提交事务。

候选记录基线、操作、显式读取依赖和共享笔记修订。并发处理比较这些实际字段，而不把自动布局坐标变化视为语义冲突：

- 只有其他分支改变时，读取或预览阶段在新基线上重放同一操作，沿用节点身份和正文，更新候选修订及候选内新内容引用。旧预览、暂存交付和教学审核授权清空，必须重新实际预览，并满足新的教学审核条件。
- 同一主题、相关父级顺序或明确依赖改变时，候选保留为 `candidate_pending_changes`，展示当前修订、涉及条目和按当前内容重做的入口。当前工具批结束后，宿主直接给出“AI 修改未应用、人工内容和建议已保留”的操作状态，不让模型继续改写冲突候选，也不把未审核的候选作为教学回答交付；自动追加画板内容的收尾路径同时跳过该冲突。已删除目标保持删除。
- 正式提交仍检查当前状态，不在提交入口悄悄承接新基线或复用旧预览。

“按当前内容重新生成”先保存尚未失焦的人工草稿，再携带当前修订和原待处理建议的精确会话、轮次、候选 ID 与候选版本。服务端用原候选基线和当前内容的实际差异，冻结需要保留的字段、身份、父级及已有孩子顺序；原请求中与这些人工修改冲突的改名、样式或移动要求不再生效。候选准备、修改、预览和最终提交都检查这份约束，允许继续增加例子或修改未冲突字段。不能只靠提示词中的“保留人工修改”保护用户内容。

新轮次实际交付成功后，讨论中才消除精确关联的旧待处理卡片；失败、取消或仅回复文字仍保留原建议，再次冲突则显示新的待处理建议。长篇建议默认收起，展开复用已有 Markdown 展示代码和段落。

新主题可以引用本候选预留的新讲解块，但必须逐字使用工具返回的身份与修订。`board.author` 的 `INVALID_BOARD` 与其他已支持的可修正错误共用既有的一次有界纠错机会；模型能够消费准确的引用修法，重复出错仍终止，整体调用预算不重置。

历史中“禁用工具后收尾”的投影可以不含工具声明。下一轮恢复时，若本轮非空声明全部被标成延迟加载，按当前已授权工具重新建立声明序列，保证有立即可调用的入口；正常后续新增仍按原规则延迟加载。当前画板请求若在首个工具前发生模型服务错误、且本轮尚无候选、已接受正文或交付，宿主直接说明此次未改图并保留人工内容及原建议，不再另用模型猜测用户缺少什么材料。已有工具证据和交付的降级路径保持原行为。

旧自由图形保持原样。显式“整理成思维导图”会生成新 Topic 树，完成预览及适用审核后展示确认窗口；只有用户接受才创建导图，原内容和来源保留。候选的接受／放弃独立于聊天结束时间。

## 共享布局与带走成果

`mind-map-layout.ts` 统一主题树索引、真实字体测量、换行、子树尺寸、左右归属、节点位置和树边。Reader、候选预览与 PNG 导出使用同一布局和主题外观规则；字体加载变化后重新测量。服务端实际预览先等待打包画板完成字体、布局和聚焦，再执行原有绘制、几何和控件检查，等待仍受原截止时间和取消机制约束。根锚点保持稳定，既有自由图元不参加树排布。

大纲隐藏画布期间不移动相机，切回导图后才按真实尺寸定位。全图总览按全部内容计算缩放，允许低于普通缩放下限；从总览定位主题恢复可读大小，缩放百分比可直接恢复 100%。

PNG 按完整语义内容展开，可导出整棵导图或所选分支，包含范围内的跨主题关系；不依赖当前视口截图。输出尺寸过大时提示改选分支，避免静默缩成不可读图片。

Markdown 导入处理标题、嵌套有序／无序列表及文字层级，按先父后子的操作创建稳定主题 ID；多个根项置于一个新中心主题下。导出使用缩进列表，保留主题文字、多行标题和层级。格式范围集中如下：Markdown 不包含跨主题关系、来源绑定、讲解路线或演示；PNG 是可阅读图片，不能反向恢复结构。SVG/PDF、Xmind 互通、分享和多人协作未纳入本次实现。
