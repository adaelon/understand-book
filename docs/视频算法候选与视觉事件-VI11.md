# 算法候选与视觉事件（VI11）

## 扫描与任务

`video-visual-scan.ts` 用 FFmpeg 流式解码全片，每秒选一帧并保留源 PTS，将 480×270 灰度图按 32×32 局部块比较。灰度差至少 24 的像素计为变化；任一块的变化比例达到 0.06 就保留前后两帧，每 15 秒补充一帧，首末采样必留。候选没有全局排名淘汰，摄像头运动不会占满名额而挤掉讲解画面。

`content_rect` 指定需要描述的讲解区域，默认整帧。有固定摄像头或字幕栏的视频可明确排除该区域；本片采用 `[0,0,1,0.89]`，排除底部烧录字幕。真实模型仍收到原分辨率整帧，描述范围随输入声明。

同一 VI0a 样本比较 0.5/1/2 秒与 0.01/0.03/0.06 三档阈值。1 秒、0.06 在两次固定代码微改两侧保留相距不超过一秒的观察；2 秒缺少变化前一秒内的帧。1 秒档的渐进样本由 30/20 候选降至 14，重复主体由 42/21 降至 6；596/618/628/648 秒的实际原图分别保留由来、内存与动态范围、精度限制、非零结果。[参数凭据](../evals/video/results/vi11-20261010/calibration.json)。

全片扫描后，可对指定区间渐进执行语义任务。每任务至多四张责任帧，并在图片预算容许时携带相邻前后帧作上下文；每六任务聚合一个不可变发布批次。原片所有采样结果在分析目录 `scan.json`，计划、帧、候选和运行回执在 `.build/video-visual/<analysis_id>/`。同一命令恢复缺失任务；修改采样设置或重新划分事件使用新的分析 ID。

## 候选接纳与复用

`原片扫描 → 原分辨率补取帧 → 四工具 MCP 原生图片 → 模型划分候选 → Engine 接纳 → 阶段原子 writer → VI9 累积发布`。

输出候选为 `{input_ref, task_id, events:[{start_ms,end_ms,frame_ids,screen_text,description,change}]}`。事件必须按顺序完整划分任务区间，全部责任帧恰好出现一次，实际 PTS 位于事件内。上下文帧不能冒充责任帧；错误输入、空帧、重复帧、缺 PNG、越界及间隙在接纳处退出。附近转写由 Engine 根据确切转写版本和时间相交关系关联，不由模型猜段 ID。模型输入和输出沿 VI4 原生图片与候选传输预算。

像素复用直接比较指定区域的原分辨率 RGB，最多保留 32 个不同画面。完全相同才使用同一内容标记；如果一个任务的全部画面已有已接纳描述，Engine 复用画面文字与描述，跳过该任务的模型调用。新的 VU 保留本次实际帧、时间区间、附近转写与 `description_reused_from`。变化线索重新注明本次重复出现，不复用上次的讲解时间或转写。

## 发布与回看

每批保存 `visual_units.json` 和所有代表帧 PNG，记录分析版本、材料身份、采样参数、VU、原片位置和已接纳覆盖。读者只得到完整批次；未完成的其他范围仍显示缺口。VU 身份为分析 ID/任务 ID/事件序号，同源重划分创建新的分析贡献，旧发布及旧贡献保持不可变。历史引用继续使用原 `PublishedBookRef` 和 `MediaLocation` / `FrameLocation`。

发布恢复直接比较材料和批次贡献，批次集合按 ID 排序后比较。Rust 的 BTreeMap 输出顺序与 Core 的完成顺序不同，不能触发重复发布；视觉和中文驱动共同使用该比较。实际依赖仍由原发布门验证。

重复描述自包含于当前贡献，回读本次帧不依赖旧描述文件。VI12 将消费各分析贡献进行视觉检索，并按分析版本处理重划分；检索命中仍只是候选位置，取得证据需再读原片。依据：[ADR-0145](adr/0145-video-media-locations-and-revisable-visual-units.md)、[VI9](视频同源累积发布与接入-VI9.md)。

## 操作入口

```powershell
. .\.worktree-local\environment.ps1
node --import tsx skills/build/video-visual-units.ts prepare <工作区> <分析ID> [设置JSON]
node --import tsx skills/build/video-visual-units.ts run <工作区> <分析ID> <Codex可执行文件> [publish_book可执行文件 独立服务根]
```

设置 JSON 可给出 `options`（`interval_ms/supplement_ms/change_threshold/content_rect`）和 `ranges`（带 video 身份的媒体区间数组）；省略范围表示整讲语义处理，省略配置使用默认参数。准备操作总是全片扫描。原片验收入口 `node --import tsx evals/video/vi11-run.ts [Codex可执行文件]`，固定处理 550–655 秒、1180–1225 秒和独立 6 秒补充夹具。

## 验收与成本

2026-10-10，Core 16、Server 5 个独立定向用例及 Core 类型检查通过。全片扫描 4,642 帧、1,743 候选，耗时 97,416 ms；原片选区 37 张 PNG 共 19,026,212 字节，10 个真实模型任务形成 22 个 VU，两批覆盖 550–655 秒和 1180–1225 秒。补充夹具形成 A→B→A 三个 VU，返回 A 的任务尝试次数为零，保留独立转写上下文。

9 个代表及变化前后帧从正式旧、新发布解码后与候选 PNG 逐像素一致。英文、时间映射与 720 段中文逐字节保持，覆盖缺口正确；完成后重跑不再启动模型或复制媒体。重划分旧产物保持由真实解码集成用例验证。[机器凭据](../evals/video/results/vi11-20261010/verification.json)、[原图内容对照](../evals/video/results/vi11-20261010/semantic-review.json)、[测试](../evals/video/results/vi11-20261010/tests.json)。

实际 Codex CLI `0.162.0-alpha.2`，默认模型、low reasoning。三个外部 Harness 进程累计 820,185 ms，包含网络重试与退出；实际输入 2,193,330 tokens（缓存输入 1,972,736）、输出 26,066，模型名称和金额未返回。原片每次发布物化 225,917,024 字节；正常基线加两批为三份，本轮含排序问题多发一份，共四份、903,668,096 字节。完成态复用已修复并验证。

最终 publication `01a12543-5248-76d0-9d6c-71a133a14357`，Book `19ac880d-a788-43f4-9725-6c56f4980189`。工作区 `evals/video/generated/vi11/workspace`，独立书库 `evals/video/generated/vi11/service`；原 VI3/VI10 工作区保持。`vi11-verify.ts` 可重跑像素、覆盖、上下文及恢复验证。

## 已知限制

- 扫描覆盖全片；本轮语义验收覆盖指定 150 秒及独立夹具。全讲 VU 生产可沿同一入口执行，整讲最终验收属于 VI18。
- 秒级采样表达离散观察，事件边界是采样下的组织边界，不证明帧间没有瞬时变化。高速动作不在当前教学场景范围内。
- 原片字幕、鼠标或压缩噪声可能增加候选或阻止严格像素复用；本轮不采用模糊相似度自动合并代码。
- DSH、读时真模型、Linux 和安装态沿原待办。源代码入口使用 Codex 默认模型、low reasoning；金额若宿主未返回则保留未知。
- 本轮第二批首次发布返回一次 `PUBLICATION_STORAGE_FAILED`，未登记新发布，重跑恢复成功且模型任务未重复。未定位该次存储错误的根因；[原始记录](../evals/video/results/vi11-20261010/initial-run-output.txt)保留，不能将已修复的批次排序问题当作其原因。
