# WB6：以画板为主的学习与讨论

日期：2026-10-26。状态：18:44:57 HKT 发布后发现两个生产部署遗漏，已于 19:27:17 HKT 修正前端模式、20:16:11 HKT 修正预览资源目录；20:27:07 HKT 追加公式显示修复。原公网文件/接口复核不足以证明端到端可用，详见[部署纠正记录](performance/reader-cloud-fix-20261026/README.md)。

## 目标与产品行为

读者在空白画板上即可提出问题。Agent 根据当前学习工作区的材料与真实讨论记录组织讲解，绘制有关系的图解，并在后续讲解中修改图元、添加圈注。画板内保留问题、回答、生成过程和理解变化，切换聊天后仍可继续。

沿用暖白画布、橙色主操作和现有排版。画布为主区域；桌面右侧切换“讲解 / 讨论”，手机切换“画板 / 讲解 / 讨论”。底部始终能提问，并明确当前针对“全画板”还是所选内容。新回答不强制移动读者当前视野。

## 已确认的缺口与修复方向

| 实际问题 | 本次处理 |
| --- | --- |
| 首次画板提问自动创建聊天后，仍拿创建前的空编号校验，误报聊天已切换 | 将本次正常创建视为合法会话建立；真正切换时保留输入，可在画板重试 |
| 本地画板请求没有提交实际聊天头 | 沿现有提交合同发送已观察到的聊天头 |
| 提问、冻结上下文、正式交付都要求选中条目 | 全链路支持可选锚点，空白板无需伪造根条目 |
| 画板只展示最新运行状态，缺少真实讨论 | 从原聊天投影画板相关轮次，包含历史、进行中、失败与草稿，不建立第二份聊天存储 |
| Agent 只能看到选中内容，不能查找整个学习过程 | 复用 workspace.records.read 检索当前学习空间原生历史及显式带入历史；分页读取全文匹配结果 |
| Agent 无法从可加入目录取材并组合到自己的图解 | board.author 接通目录查询、源内容读取与候选导入，保留确切原来源 |
| 原生图元只能追加 | 在同一修订中更新已有原生图元并追加内容，保留原作者与旧修订，已有引文不随改图被改写 |

## 范围决定

材料与私人历史按当前已接受运行的学习空间和成员资料读取。其他学习空间的私人记录沿既有“带入学习记录”选择进入。检索结果保留书籍、会话、轮次和原始时间；用户原话、发生事实、Agent 对理解的判断及其修正分别呈现。没有原始时间的数据不补造时间。

图示使用已有原生文字、路径、矩形、椭圆、连线和讲解路线。圈注使用路径，避免把圈注误当成遮盖内容的实体节点。修改、图文对应、讲解路线共同经过候选预览与正式提交。

## Excalidraw 参照研究

用户视频时长 331.23 秒，1920×1080，30 fps。抽帧见 `tmp/board-book-20261026/video/contact-sheet.jpg`。视频展示预先准备的场景逐步出现，再按 Transformer 讲解顺序切换视野；不能据此推断播放时有 Agent 自主实时编辑。

所给发布仓库指向 Obsidian 插件和 Excalidraw 组件的源码分支。效果由可编辑场景对象、逐笔/逐字揭示、出现顺序、镜头视野与圈注轨迹组成：
