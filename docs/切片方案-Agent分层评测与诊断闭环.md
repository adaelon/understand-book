## 目标与完成标准

评测应回答：哪项阅读要求没有完成、证据在哪个阶段丢失、哪项改动能改善它，以及改善是否损害其他能力。首个交付是三个可追溯案例：来源交付失败、答案正确但旧判分失败、多证据关系解释；随后形成一轮当前版本的假设验证。

本次设计范围为本地 Agent 评测。实现复用生产入口和质量复评，不以更换模型、增加预算或扩大工具面为默认修法。交付验收同时要求：原始运行可回读、判定有答案与原文依据、失败可分类、诊断条件独立标记、新旧结果可配对。具体生产改动在 EV7 根据新证据确定。

领域边界：评测任务合同描述外部验收要求；Resident Goal 描述生产会话中的任务状态；AssessmentContract 判定 Learner 作答。三者不互相替代。生产的 Goal completed 只作为观察事实，不替评委判任务成功。

## 任务合同与层级

EvalTaskSpec 在运行前冻结，最小内容如下；字段属于评测包，不新增生产 Core schema。

```text
身份：case_id、task_revision、family_id、development/holdout/regression
分类：原有题型、ReadingTaskLevel、ReadingInteractionCondition
用户可见输入：问题、必要历史、选区/位置、用户授权的动作要求
初始状态：独立书库引用、材料版本、隔离记忆与聊天状态
验收要求：requirement_id、具体要求、是否必要、适用的内容/引用/动作条件
核验材料：必要事实与关系、允许的替代证据集合、关键错误
执行条件：模型/程序/提示/工具配置、预算、交互脚本、重复编号
```

生产输入只包含真实用户可获得的上下文；标准答案、参考 LID、隐藏证据、层级标签、判分规则及后续脚本信息只给评测端。用户原本选中的位置或明确给出的原文可以进入生产输入。不同来源的上下文必须保留身份。

| 层次 | 必要理解操作 | 示例与边界 |
|---|---|---|
| L1 定位与忠实提取 | 找到直接答案并准确交付 | 定义、直接分类、原句定位；按要求核验来源或跳转 |
| L2 解释与局部推导 | 解释一个机制、条件联系或局部公式推导 | embargo 的做法与原因；公式代入不能只核最终数字而忽略题目要求的解释 |
| L3 多证据整合与关系判断 | 联合互补前提建立关系、区别条件或处理表面矛盾 | 分别回答两章的独立事实仍是组合任务，不自动成为 L3 |
| L4 情境诊断、迁移与论证评价 | 将原则映射到新情境，辨析失效点与证据边界 | 给定实验流程判断哪些结论成立；简单换数字仍可属于 L2 |

按验收必需的理解操作标主层级；混合任务保留分要求判定。层级不随某次失败、工具数或篇幅变化。实际难度另看通过率、稳定性与成本。同页也可有 L3，跨书也不自动成为 L4。

| 交互条件 | 必需能力 |
|---|---|
| single_turn 单轮 | 一次请求内完成，不依赖此前私人状态 |
| multi_turn 多轮 | 承接逐步透露的信息、纠正或追问，调整当前解释/操作 |
| cross_session 跨会话 | 新聊天或重启后从真实持久状态恢复所需材料与目标 |

跨会话题显式区分同聊天重启与新聊天恢复；现有笔记/位置恢复可跨聊天，ADR-0136 的 Goal 首版归同聊天，不能在夹具中伪造跨聊天 Goal 所有权。不要求铺满层级与交互条件的笛卡尔积。引用、可回答性、动作类型和材料模态作为适用条件，均不单独充当最高层级。

首批选择 2–3 个有完整原文依据的主题，每个主题构造 L1–L4，共 8–12 题，再增加两个短多轮变体。候选主题包括防过拟合、因子组合、目标与损失的关系；逐题以实际原文确认可回答性。由同一证据链产生的层级题和改写题归同 family，不分散到开发集和留出集。原有题保留为基础能力与历史回归，新增题集单独版本化。

## 判分合同

每次产品执行保留原生 execution、delivery、persistence、Goal 状态和停止原因。评测从实际用户交付与后置状态判任务，不把这些状态重新压成一个 healthy 布尔值。

```text
RequirementJudgment:
  verdict = met | unmet | unknown | not_applicable
  assessment_status = valid | not_run | invalid | needs_review
  reason_code、简短理由、answer_span_ids、reference_ids、effect_refs

TaskResult = pass | fail | unresolved
QualitySummary = accuracy / completeness / grounding / explanation
PairPreference = A | B | tie | unresolved | not_applicable
```

not_applicable 由任务合同预先确定；所有必要项均满足且必要交付成立才 pass。任一可信必要项 unmet 或已确认关键错误即可 fail；无已确认失败、但存在未判项才 unresolved。有效的 unknown 表示材料不足，不与 JSON/传输错误混同；已确认失败可以与其他项未决并存。运行取消是否失败取决于任务是否要求取消；缺观察不能臆断实际结果。

原子要求尽量二元，部分完成通过已满足的子要求体现；四维质量沿用既有 met/partial/failed/unknown/not_applicable 作为汇总，不平均掉关键错误。内容评价与引用/动作兑现分别记录，完整任务结果再依合同汇合。每个率标明分母；完整任务分母含产品失败与未决，已交付答案质量是另一个明确标注覆盖范围的子集。

确定性程序检查事实值、引用/片段身份、动作后置状态和格式；语义评委判断要求、关系与证据支持，并接受人工校准。公共参考原文用于核验完整性，不能替答案补引用。推断可联合多个前提，不要求结论逐字存在；标注包外的有效来源进入补证复核，不能因未命中唯一 LID 就判错。extra claims 中的实质性错误仍应计入。

答案片段由程序编号，评委引用编号而不重抄答句。评分状态细分 not_run、transport_error、invalid_output、insufficient_evidence、judgment_disagreement，并保留原始错误。两次展示顺序必须都完成才能判断顺序分歧；一次请求失败属于评分无效，不能冒充位置偏差。

绝对合格逐答案判定；A/B 偏好独立运行、交换顺序，仅比较双方实际交付的答案。偏好失败不抹去已有效取得的绝对判定。双方都不合格时，某方偏好获胜仍不计任务成功。评分版本变化后对同一比较的全部系统统一复评，历史记录及旧报告保持原样。

## 实验记录与报告

复用本地实际请求记录和观测事实。诊断针对每项要求连接：参考材料存在 → 取得的原文 → 实际决策请求可见内容 → 最终答案的使用 → 来源交付 → 动作与持久结果。既有 evidence 区间并集表示“曾经看过”，不能表示“终答时仍看得到”；缺字段明确记不可观察，按具体诊断需要补采集。

每批记录程序 revision、相关未提交 diff 和未跟踪源文件副本、固定可执行文件位置、模型及参数、prompt/工具配置、书源及语义资产版本、初始状态、题集、预算、评委协议及校准依据。复用已有版本身份；资料存在本地可回放目录，批次内不替换程序或材料。模型隐藏推理不作为采集内容。

报告分别呈现：产品成功/失败/未决、按层级与交互条件的要求满足情况、配对新增/失去成功、实际交付覆盖、判分故障及分歧、成本与延迟。成本包含失败尝试，Judge 和诊断另账，缺失 usage 保持未知。不得将未决删出分母；可给确认成功下界 S/N 与可能上界 (S+U)/N，并明确这是未决范围而非统计置信区间。

同任务重复运行测产品稳定性；同答案重复判分测评委稳定性。关键案例先用预先固定的三次独立运行作小样本观察，报告每次结果和三次全过的任务数，不挑最好一次。比较以任务/family 为配对或聚类单位，不把重复和同链改写当独立题。小样本优先逐题差异；需要决定细小差异时再设计扩样与不确定性分析。

## EV1 显式任务合同

**实施结果**：`task-spec.mjs` 将旧协议的 24 道问答、4 道来源动作、4 道重启题冻结为独立 `quantification-essence-task-spec-v1`。每题显式给出层级、交互条件、必要内容/来源/动作/持久要求和可替代证据；同证据链使用共同 `family_id`。`agent-run.mjs --task-protocol` 用 `productInput` 投影用户当前可见材料，恢复阶段不预泄漏下一阶段信息。旧入口和旧题保持原样。解释适用性由合同给出，新质量协议不按关键词推断。

**验证结果**：32 题分类与等义措辞、并列跨章事实仍为 L1、重启 L1 跨会话及用户输入投影均有定向测试；`agent-run.mjs --validate --task-protocol` 返回 32 题、8 类。新入口只构造用户问题与原有回答指令，金标准保留在评测端。

**依赖**：EV0。**位置**：`agent-dataset.mjs`、`quality-core.mjs`；新增最小 `task-spec.mjs` 与对应测试。旧 `dataset.mjs` 的冻结题目及旧协议保留；新合同用独立版本与入口选择。

**工作**：给旧题逐题显式标层级、交互条件、解释/来源/动作适用性、必要要求和证据替代关系；移除新协议中通过题面关键词推断 explanation_required 的行为。新增输入投影区分用户材料与评分材料；任务只要求分类时不增加隐藏解释要求。

**验收**：同一问题的等义措辞不改变要求；并列两章事实不自动变 L3；单纯重启不自动升理解层；生产实际请求没有参考答案或隐藏 LID。

**验证目的**：用缺解释关键词但要求原因的题、L1 跨会话题和实际 Provider 输入 fixture 检测误分类/金标准泄漏；失败则修合同及投影。此步不运行大批模型或改生产 prompt。

**验证目的**：先以历史形状建立红测，分别检测误放、误杀、未决删分母及状态混同，再改新评分路径。通过相关 semantic/quality 测试，并用固定历史包生成新旧差异报告；旧协议仍能解释旧分数。此步不修 Agent。

## EV3 按用途校准评委

**实施结果**：`task-calibration.mjs` 按绝对合格与双顺序偏好生成分用途判例；历史三案实际交付与否定反转、引用误导、漏条件、简答和拒绝等构成 13 案。新题校准包覆盖各层级与多轮条件。`task-quality-run.mjs` 提供校准作业、人工规则判定与 family/层级/交互条件精确范围门禁。关键错误误放会阻断绝对评分，即使普通分歧预算尚有余额；偏好失败不抹去独立绝对判定。用户已确认全部正反标签，两份校准分别通过；两个格式无效判例的绝对评分范围保持未批准，偏好范围独立获准。详见[实施记录](performance/agent-eval-ev3-ev4-20260925.md)。

**依赖**：EV2。**位置**：`quality-core.mjs:assessCalibration`、`quality-run.mjs`、`quality.test.mjs`、`QUALITY_EVAL.md`；人工材料保留私有目录。

**工作**：用三案及少量正反判例覆盖否定反转、真实但不支持的引用、漏关键条件、短而充分的答案、合理拒绝与过度拒绝。分别审核绝对合格和 A/B 偏好，记录误放、误杀、unknown 与有效顺序分歧；高分答案也抽检。标签和严重性依据题面与原文，不能由被测 Agent 自评批准。

**校准使用规则**：首批固定的关键错误判例不得出现已知误放；若仍误放，对应任务范围保留人工复核，不授予自动合格裁决。其他允许分歧、所需样本与适用任务族由人工在正式批次前写入校准记录；没有已确认规则时仅输出探索性结果。偏好未通过不阻断已通过范围的绝对评分；不得反复请求直到碰巧一致。

**验收**：校准记录明确能支持的用途、任务族、评委/协议版本与未覆盖范围；机器不能批准空标签；正式批次固定新目录。新 L3/L4 或多轮任务进入正式评分前，补足对应判例，历史 L1/L2 校准不能自动外推。

**验证目的**：检测空白人审被批准、偏好分歧污染绝对评分、严重误放被平均一致率掩盖；出现则修批准逻辑。模型传输/格式失败保留具体原因与费用，协议修订后统一复评各系统。

## EV4 分层题与多轮任务

**实施结果**：`reading-dataset.mjs` 以防过拟合和目标/损失对齐两条真实原文链，各冻结 L1–L4 一题及同 family 的多轮纠正变体。`agent-run.mjs --reading-protocol` 逐轮投影用户输入，保持同一生产聊天；`task-quality.mjs` 将新运行准备为 10 题、18 个系统样本。用户已确认私有 `reading-review` 的题面、合格答案和关键错答。首轮当前版本完整运行后，因一个产品交付失败，形成 31 个评分作业；其中 30 个获准运行，29 个有效，1 个评委输出无效，1 个未获批准。完整分母与逐要求结果见[实施记录](performance/agent-eval-ev3-ev4-20260925.md)。

**依赖**：EV1/EV2；正式结果依 EV3 覆盖新范围。**位置**：独立版本的题集文件（建议 `reading-dataset.mjs`），`agent-run.mjs` 的显式协议选择；多轮执行保持同一生产聊天与隔离记忆，前端动作复用已有 continuous-reading 入口。

**工作**：人工回读候选主题原文，冻结 8–12 题、可接受替代证据及两个多轮脚本。脚本只按已定义的用户行为逐步给出信息，允许合理的澄清/直接解释路径；首版固定脚本即可，不需通用 LLM 用户模拟平台。每个变体注明是否运行真实 UI 或仅 API 状态验证。

**验收**：L3 必须判断材料关系，L4 必须完成情境映射；人工参考完成能满足判据，关键错误答案会失败。相同 family 不跨开发/留出；尚未人审的出题候选不能进入正式集。多轮中纠正的信息被承接，不强制每轮重复所有旧解释，也不把脚本后续内容提前提供给 Agent。

**验证目的**：检测“跨章但只查两值”、隐藏要求、同链泄漏及忽略用户纠正。发现则修改题目/脚本并升版本，不靠放宽评分修复题目。此步保持原有基础题和模型配置。

## EV5 充分证据下的交付诊断

**实施结果**：`diagnostic-run.mjs` 对当前 `target-l2` 来源支持失败提供独立诊断。前两次脚本化模型工具选择只把固定原文短语交给真实 `book.search_text`，再复制其返回 LID 调用真实 `book.text`；660 字符必要原文被接纳并进入第三次模型请求。后续模型正常回答、来源可解析；原始评委判来源满足，但事实槽枚举与其他维度冲突，完整任务经无新调用复核为未决。原始失败尝试、费用和任务分母独立保存，见[实施记录](performance/agent-eval-ev5-ev6-20260925.md)。

**依赖**：EV2/EV3 和已确认充分的原文材料。**位置**：建议 `diagnostic-run.mjs`；复用生产 read-tools、证据接纳与来源编译路径，确有必要的 Runtime 诊断接入单独提交。

**工作**：以正常运行失败为输入，在独立诊断运行中提供人工确认的必要原文，不提供答案。使用合法 book.text 回读/接纳形成可见证据，不绕过来源与权限合同。固定题目、模型、材料和交付要求，记录插入位置、初始化方式及干预前后实际预算；预供材料改变输入条件，不能描述为完全相同的自然运行。

**验收**：真实模型请求包含完整必要原文；伪造来源仍不能通过；诊断只观察后续解释、引用和最终交付。充分证据下仍失败，则进入后半段诊断；成功只支持优先检查取证/证据组织，不直接证明唯一根因。提供证据后仍可正常使用生产工具，其新增行动如实记录。

**验证目的**：检测证据实际未入输入、账本与正文不符及诊断结果混入产品主表；失败则修夹具。先选一类失败做最小真模探针，必要时扩展相关题，不全量重跑。诊断成本独立。

## EV6 实际取证结果的共同回答器诊断

**实施结果**：`diagnostic-core.mjs` 只从两组自然运行的真实模型请求与已接纳工具正文抽取 canonical 原文，按原书顺序合并、统一 6000 UTF-16 字符预算。`target-l2` Chunk / Resident 分别送入 5550 / 1362 字符，均无截断；同一回答器与模型下 Resident 通过，Chunk 因事实槽与维度冲突未决，双顺序偏好平局。该结果只支持检查自然产品后续引用组织，不支持声称某组证据更优。见[实施记录](performance/agent-eval-ev5-ev6-20260925.md)。

**依赖**：EV2/EV3；可使用 EV5 已核对的案例，独立于其干预成绩。**位置**：`diagnostic-run.mjs`、现有 Chunk 回答器/记录器及新报告路径。

**工作**：分别提取正常 RAG/Agent 运行中实际取得并进入模型输入的 canonical 原文，保留来源区间，去除工具指令等包装。用同一排序/去重规则、同一正文预算、同一回答 prompt、模型与来源编号交给共同回答器；规则在看结果前固定，超预算截取及遗漏明确记录，不按金标准挑片段。

**验收**：两组仅有取得的原文内容不同；相同片段输入产生相同请求形状；新引用只绑定提供的原文，不继承原系统未兑现的来源。报告说明这是受共同预算约束的证据集合效用，不代表原 Agent 的终答上下文或某条图边的因果效果。

**验证目的**：检测原文被补造、取证遗漏被金标准填补、格式/预算偏向某组。若证据集合有益而原产品失败，优先验证后续执行损失；若无收益，优先检查追加取证价值。结果保持诊断分账，不替换既有同环消融。

## EV7 完成首个改进闭环

**当前前置状态**：CQ0–CQ8 已完成来源定位及评分工程修正，最终新协议在十个既有人审案例上零分歧；引用覆盖和全书否定仍有行为残留。CQ 阶段性收尾；EV7 优先验证范围表达，冻结当前代码与评分协议，不将“工程完成”记为全部行为合格。

**依赖**：EV3/EV4 及具体失败所需的 EV5/EV6。**位置**：沿用 `eval:agent`、`eval:quality` 与报告入口；添加最小实验清单与工作记录，生产修改文件由当前复现确定。

**工作顺序**：固定当前程序并复现三案相关形状 → 选择一项有证据的假设 → 声明唯一改动、预期收益及否定条件 → 修改并运行目标/相邻回归 → 用固定新旧程序交错配对运行 → 检查同层未见变体及简单题退化。历史缺陷若已修复，记录消失并选择仍存在的失败，不重新制造旧 bug。

**最小实验清单**：问题与 requirement_id；已观察证据；诊断假设；本次变量；固定条件；开发与留出 family；预先选定的重复次数/预算；预期变化；不可接受的退化；实际结论（保留、撤回或证据不足）。准备接受候选版本时运行固定基础回归集与受影响能力族；日常局部修改仅跑能检测该改动具体失败的项目。

**验收**：报告能指出改善发生在哪些要求及阶段，新增/失去成功、未决与实际成本均有完整分母；关键案例按预定重复执行，至少一组未用于调参的 family 参与验证。更快放弃、减少必要引用或移除简单题不能算优化。实验未支持假设也是有效结论，但不得宣称 Harness 已改善。

**验证目的**：检测局部修复损害原能力、只适应开发题、不同评分版本混比或失败成本丢失；出现则撤回/缩小改动或报告证据不足。确定性回归至少覆盖 semantic 与 quality 相关入口；是否运行更广测试由生产触达面决定。

## 已知限制

- 历史单书单次实验和未校准复评不能代表当前版本能力，也不足以支持架构普遍优劣或统计显著性。
- 四层是任务结构，不是均匀难度标尺；8–12 道首批题用于验证协议，不能代表全部阅读需求。
- 语义判定依赖评委和核验材料；人工校准只覆盖已记录的用途与任务族。未决与材料缺口继续可见。
- API 后置状态不等于用户实际 UI 体验；要求页面或交互产物的题需另按真实产物验收，不能只评正文。
- 真人独立应用、延迟保持与长期学习效果属于独立产品验证。模拟用户、解释高分和 Goal completed 都不证明读者学会。
