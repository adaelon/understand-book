# 切片方案：想法笔记与理解路径

日期：2026-11-01。状态：**UP1–UP4 本地实现及相关验收完成，未上线。** 架构决策见 [ADR-0179](adr/0179-note-thinking-path-and-current-understanding.md)。

承接[个人想法演进与教学召回](切片方案-个人想法演进与教学召回.md)、[ADR-0177](adr/0177-personal-notes-evolution-and-teaching-recall.md)、[情境练习与学习脉络](切片方案-情境练习与学习脉络.md)。现有存储、权限、工作区归属、教学与计量合同继续适用。

## 1. 已确认的产品定位

**决策：笔记呈现思考路径，系统解释当前理解。**

笔记的“思考过程”串联用户实际留下的想法、讨论、修订与练习；系统依据真实表达和表现标出当前已经能做什么、卡在哪里、还待确认什么。理解说明自动更新，笔记正文及其修订仍由用户保存或采纳。用户可以查看判断依据、纠正判断，并从具体卡点继续讨论或练习。“我的理解”提供跨笔记导航，同一学习范围内两处读取同一结果。

当前判断按知识关系与能力组织；一条笔记可以涉及多个关系，多条笔记也可以指向同一关系。进展以可说明的表现及其条件表达。历史路径保留分支、回访与反复。

## 2. 首个可用版本的完整场景

示例材料为平均速度，所有引文及作答在验收时使用确定的实际输入。

1. 用户保存“停车的时候没运动，这段时间应该不算吧？”。笔记立即可读，路径出现“留下疑问”；尚无已形成的理解判断时显示“还没有相关理解观察”。
2. 用户点“一起推敲”，讨论冻结该版笔记及本次补充。真实用户表达表明其混淆运动时间与整段行程时间时，系统形成可修正解释，显示相应原话与来源。
3. 用户在讲解后重新表达。路径出现“讲解后的表达”，当前判断可以说明“在已提供解释下，能说清时间范围”。
4. 用户点“练一练”，题目沿既有正式活动产生，采用新的情境。独立完成时显示“本次在新情境中独立判断正确”；看提示后完成时明确显示协助条件。
5. 用户可以将新表达保存为同一笔记的下一版。路径显示具体修改及其明确关联讨论；未修改笔记也能看到较新的理解依据。
6. 用户反馈“刚才我是参考笔记才答出来的”，系统保留补充原话、修订相应解释，两个入口同步显示变化。

完成这条场景需要保存、讨论、判断、练习、纠正、重开和返回依据全部接通。

## 3. 用户界面

### 3.1 笔记中的位置

沿用现有非模态笔记窗口、“当前表述 / 思考过程 / 联系”导航及品牌样式。

- **当前表述**：正文编辑区之外显示紧凑的“相关理解”摘要。无判断时给出自然空态；有多项知识关系时各自列出简短结论。
- **思考过程**：上方是当前理解，下方是一条按实际发生时间排列的路径。修订、讨论、练习和系统解释通过文字与图标区分，重要变化优先展开，其余内容按需展开。
- **每个理解条目**：明确的关系标题、已能做到、当前卡点、还待确认、最近依据，以及“继续推敲 / 练一练 / 查看依据 / 纠正判断”。三个内容部分可以同时存在。
- **每个路径节点**：当时原话或表现摘要、当时帮助、确切版本和返回原讨论入口。明确的“基于这次讨论修改”才画因果连接；仅时间先后按时间排列。
- **我的理解**：按当前学习范围提供卡点与已有表现导航；详情能打开相关笔记及确切版本。

沿用页面的文字密度、焙橙强调色与中性表面。颜色辅助辨认，正文必须直接说明含义；窄窗口改为单列，依据详情就地展开。

### 3.2 交互变化

“继续推敲”携带所选关系、笔记版本、判断依据及当前请求进入原聊天流程。“练一练”携带同一目标进入现有练习入口。新表达保存复用原编辑器及 `based_on_turn`。纠正复用现有证据纠正机制，并使摘要失效后重算。

后台整理期间保留上一份判断，标明新依据正在整理；失败提供重试入口并保留原话及已完成交付。打开笔记直接读已保存依据与投影。

## 4. 记录怎样关联

### 4.1 复用的真实引用

| 记录 | 现有权威 | 联动方式 |
| --- | --- | --- |
| 笔记及版本 | `PersonalNote / NoteRevision / NoteRef` | 保留稳定笔记身份与确切讨论版本 |
| 明确相关讨论 | `NoteDiscussion.turn`、回合中的个人笔记引用 | 定位用户表达、原回复及该回合学习归属 |
| 正文修改来路 | `NoteRevision.based_on_turn / source_refs` | 仅对明确来路显示“由这次讨论产生的修订” |
| 实际活动与帮助 | `InteractionTrace`、`TeachingMove.note_refs`、`PracticeSpec.revisit_note` | 从实际采用或回访的确切笔记版本定位活动 |
| 理解解释与表现 | `LearningEvidence`、`ResponseAssessment.items` | 判断引用真实表达、逐项标准与帮助条件 |

笔记相似度与学习脉络只用于提名相关材料。进入本条思考路径需要明确关联；一次讨论引用多条笔记时，还要定位实际涉及的笔记片段和关系，不能把整轮结论分发给所有笔记。

### 4.2 知识关系身份

已有正式对象时复用对象及版本。现有设计块可在同一设计谱系中承载明确的关系接续。没有正式对象、但已有确切来源的日常讨论与练习，给其 `TeachingTarget` 补充稳定的私人关系引用（拟名 `focus_ref`），使同一关系的不同表现可以汇总。

关系由当前学习范围、准确陈述、成立条件和来源确定；模型只能从实际提供的候选中引用已有关系或提出新关系，由宿主持有身份。同一段原文可以包含多种关系，标题、裸 LID 或笔记 ID 均不能单独充当关系身份。关系含义发生变化时保留新旧对应和原证据归属。

这项引用服务现有 LearningMemory 中的证据归组；学习脉络图继续保持知识结构职责。材料跨版本或工作区跨范围时依既有显式对应与历史引用规则处理。

### 4.3 读取合同

在 `personal_note_api` 增加“思考过程”读取动作（拟名 `thinking`），组合现有权威记录，不生成第二份可编辑历史正文。返回的逻辑内容为：

```text
NoteThinkingView
  note_id / current_revision
  scopes[]                         原学习范围和材料版本
  current_understanding[]          每个关系及能力的当前解释
  timeline[]                      保存、修订、明确讨论、活动、纠正
  next_cursor / update_status

UnderstandingSummary
  scope / focus_ref / capability
  demonstrated[]                  已观察到能做什么及其条件
  difficulties[]                  具体障碍与支持该判断的原话
  unconfirmed[]                   对当前目标有用、但仍未确认的部分
  evidence_refs / note_refs        支持每一项结论的确切引用
  next_step                       与本次目标相关的一项后续动作
  evidence_watermark / interpreter_version
```

字段名称在实现时沿既有类型收敛；判断结果存放在原学习存储内，可由保留的事实与解释重新构建。原有能力计数仍保持表现证据的语义，普通理解假设只参与解释视图。

全局笔记按实际关联的学习范围分别显示理解；当前材料默认定位其所属范围。另一个工作区的表现保持原归属，同一条笔记被复用不构成状态迁移。

## 5. 系统怎样判断和更新

### 5.1 获取与解释信息

复用已有回合后教练观察，输入本轮真实用户表达、表达前已提供的帮助、该关系的相关历史、原文和可用的逐项评分。输出将“能做什么、障碍、待确认”明确分开，每个结论附证据与适用条件。

保存、改字及打开笔记只更新事实或读取视图。讨论和练习产生新的真实表达后自动整理；普通新表达可以构成暂定理解，正式评分负责说明本次表现，二者按各自身份参与解释。

如果不能区分“概念混淆”和“偶然失误”，在当前判断中保留未决，并建议一个能够区分两者的小问题。继续获得讲解仍沿用户原请求处理。

### 5.2 修正多知识点评分归因

扩展原子评分标准与目标关系、能力的对应，使证据派生依据适用的逐项结果；整题状态继续服务本次作答反馈。

例如一项标准判断“总时间包含停车”，另一项判断“比值计算正确”。第一项通过、第二项失败时，只把计算表现记为未达到标准。无法分辨子知识点的封闭题结果保留为综合任务表现，后续用专门的问题定位。

旧记录没有逐项对应时保留原作答与整题结果，不猜补具体薄弱点。

### 5.3 当前判断的变化

- **讲解后复述**：支持在当前帮助下表达关系；保存已获得帮助。
- **首次独立完成**：说明本次任务和情境下的实际表现；结论保持对应范围。
- **在不同情境重复独立完成**：当前说明可概括已经验证的共同适用范围。
- **新表现与旧判断不同**：比较是否同一关系、能力与条件；可比的新表现修订当前解释，不可比的条件分开说明。
- **用户纠正或题目被判存疑**：原依据及纠正留在历史，当前摘要撤回依赖失效依据的部分。
- **长时间没有新表现**：保留最近一次观察的时间；需要时建议复查。

不把每次观测累计成固定通关级别。阶段在界面中是对已发生过程的描述；具体困难、应用表现及未确认范围分别保留。

## 6. 自动更新、已有数据和成本

复用现有回合后任务与计量，优先在同一次观察输出中补齐结构化结论。页面读取基于已有证据的视图；新证据、纠正及题目存疑按原水位触发更新。日常保存和打开笔记新增模型调用数为零。

旧笔记立即能显示已有修订和明确关联讨论；可明确定位的既有理解与活动直接关联。只为缺少关系归属的内容提供“继续推敲”入口，后续新表达逐步补全。不开启全库自动重新判读。

查询从这条笔记的明确讨论、实际活动和关系索引定位，分页读取时间线。复用原笔记验收规模（1000 条 / 3001 修订）观察打开与更新路径；记录实际模型输入量和调用次数，确认自动判断没有进入保存或打开的等待路径。

## 8. 验证与完成标准

工程验证复用原 memory/server/runtime/Web 测试与浏览器流程，每次针对一个会改变实现选择的具体失败。

1. **记了正确笔记却被认定会了**：保存用户正文、AI 摘录与采纳改写，确认只有真实记录，能力判断没有凭保存动作增加。
2. **算错拖累已理解的概念**：一题两项标准，只错计算，确认关系理解保持其实际结果；若失败，修正评分归因。
3. **旧疑问一直盖住后来表现**：先误解、受助表达、后独立变式，重开后当前说明采用相应新证据，旧原话仍能回看。
4. **新笔记版本错误继承旧判断**：修改为另一关系，确认旧结论保持其旧适用范围；若失败，修正关系归属及版本呈现。
5. **判断纠正或坏题未生效**：补充曾看提示、撤回错误解释、标记题目存疑，两个入口同步撤回依赖的结论。
6. **关系错连**：一条笔记含两个知识点、多条笔记讨论同一关系、同名关系位于不同范围；确认汇总与拆分符合实际依据。
7. **交互断路或窄窗口不可读**：实际操作推敲、练习、跳过、保存新版、查看依据、纠正和返回；查看 360px 与桌面布局、长原话与空态。
8. **模型只换了说法却未定位障碍**：用有明确原文与判据的一组短对话，覆盖疑问、正确理由、正确答案错误理由、计算失误、提示后完成和后续修正，以真实模型回放检查归因及下一问。失败样例修正观察输入或解释规则后复验。

验收产物放在本项目既有 `docs/performance/` 下的本次目录：保存能复查的场景、相关测试结果、模型原始输出与实际页面截图。用户真实使用后的纠正继续作为下一次校准依据。

## 9. 已知边界

- 首版实现与验证记录见第 10 节；早期回归失败及其修复结果保留在验收记录。
- “完整路径”是实际保存且能明确关联的过程；未保存的思考、没有明确关联的因果关系保持空缺。
- 无材料的独立讨论能呈现真实表达及其变化。当前教练理解证据要求真实材料上下文；首版对此显示可回读讨论与尚待确认的理解，获得合适材料或判断依据后再接入原判定流程。
- 用户更正自己的观点、用户指出系统误判、用户获得新表现是三类不同变化，历史呈现保留这种区别。
- 工程及真实模型样例通过只证明对应路径和判断场景；真人长期学习效果仍需真实使用观察。
