## 目标与边界

交付可信的原文支持/引用定位判定、稳定的 `source.present` 范围语义，以及与之相符的工具提示。成功标志是：同一批旧答案的失败性质可追溯，已读正文不会因先前搜索而缩水，明确指定的短引文仍保持精确。

## 判定合同

沿用 [CONTEXT](../CONTEXT.md) 的“原文支持”“引用定位”、EvalTaskSpec、任务层级和交互条件。前两项为新增评测定义，其他为既有概念；生产证据账本所有权不变。领域对齐完成。

```text
SourceView = { id, valid, highlighted_quote, context_before, context_after,
               view_status: complete | partial | unavailable }
ClaimAssessment = { answer_span_ids, claim_text,
  support: met | unmet | unknown,
  basis: [{ source_id, part: highlight | before | after, start, end }],
  location: met | unmet | unknown, reason }
Requirement = { requirement_id, evaluator: semantic | exact, required, ... }
```

字段为新协议的设计合同，具体导出沿用现有匿名编号。片段位置采用各 part 内 UTF-16 半开区间；程序验证来源身份、区间与原文，语义评委判断蕴含、必要条件和定位充分性。答案片段可以包含多个论断，`claim_text` 明确本次判定对象。

内容准确性可用公共参考核验；原文支持只用该答案实际交付的有效来源。评委同时检查核心回答与实质性额外论断；缺少必要依据记 `unknown` 或有明确证据的 `unmet`，不能以未收录材料推定全书不存在。引用错绑与原文不支持分别记录。

`sources` 在新任务版本中拆为支持与定位两个必要子要求（原题要求来源时适用）。来源可打开性继续由程序检查。支持成立而定位失败时，完整任务可失败，报告必须显示“内容/支持满足，定位未满足”。可信必要项失败优先于其他未决；没有失败且存在必要未决则任务未决。四维质量仅作汇总，不替代逐要求结果。

## CQ3 稳定来源范围语义

