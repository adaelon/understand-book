# 模型服务配置

阅读、问答、教学反馈和后台任务共用模型配置。资料预构建继续使用插件与外部 Harness 的模型设置。

## 从界面配置

从本地书库右上角打开**桌面设置**，或在阅读器里选择**更多阅读工具 → 打开桌面设置**。设置首先显示 **AI 模型**。本地网页从**更多阅读工具 → 模型设置**进入。云端管理员在**运营后台 → 模型服务**管理共享配置。

1. 直接选择服务商。OpenAI、DeepSeek、Anthropic 和 Google Gemini 会填好服务地址、协议和认证方式，Ollama 默认连接本机。使用中转地址或其他兼容服务时选择**自定义服务**。已有配置显示在左侧的**模型服务**列表，点击**添加服务**可以再接入一家。切换到另一个服务商时单独填写它的密钥。
2. 输入 API Key。在本地版可以点击**从服务获取型号**，然后从返回的清单选取模型。Ollama 显示本机已安装的模型。也可以直接填写服务商给出的**模型 ID**。云部署、特殊协议或没有列出型号的端点直接手填。服务名称和认证方式在**高级连接选项**中，API 协议在**模型能力与预算**中。
3. 根据该型号的实际能力设置工具、图像、结构化输出、流式与推理参数。原生问答需要明确声明工具能力；高级设置可指定上下文窗口和输出上限。
4. 选择默认模型。需要时展开用途设置，为主 Agent、教学反馈或后台任务指定其他模型。
5. **保存并应用**后，新任务采用新选择。保存本身不发生成请求。**测试文本生成**调用已保存模型；有更改时可用**测试草稿文本**验证当前输入，不保存、不更改活动默认。文本通过不代表工具或结构化输出已验证。

密码留空会保留同一服务已保存的凭据；清除凭据使用单独的明确操作。更换服务 ID 不会复制其他服务的密码。保存失败保留原配置与编辑内容。删除被用途引用的模型前，先选择替代模型。

运行开始后固定选择；切换默认模型不影响活动运行。本地应用重启恢复已完成历史与模型配置，未完成回合沿现有行为标为中断。历史中记录模型来源，跨服务或跨协议的新回合保留对话与工具事实，并清除不适用的协议私有续接数据。

## 协议与部署

| 协议 | 服务地址示例 | 认证与配置 |
|---|---|---|
| OpenAI Chat Completions / Responses | `https://api.openai.com/v1` | Bearer Key；两种 API 分别选择 |
| Anthropic Messages | `https://api.anthropic.com` | API Key；使用通用 Messages，不开启 DeepSeek 工具更新扩展 |
| Gemini GenerateContent / Interactions | `https://generativelanguage.googleapis.com` | API Key；两套协议分别选择 |
| Ollama Chat | `http://127.0.0.1:11434` | 通常无需认证；使用原生 `/api/chat` |
| Cohere V2 Chat | `https://api.cohere.com` | Bearer Key；工具调用与结构化结果按接口允许的组合使用 |
| DeepSeek Messages | 现有支持 Messages 扩展的地址 | 保留能力探测；显式选择后不可用会报错 |
| Bedrock Converse | `https://bedrock-runtime.<region>.amazonaws.com` | Bedrock 部署与区域，使用 Bedrock API Key |

云端部署参数在服务高级设置中选择：Azure v1 或 deployment/API version；Vertex 项目、位置及可选配额项目；Bedrock 区域。Azure Entra 支持 Developer Tools、Managed Identity 和 Workload Identity 凭据；Vertex 使用 Google ADC。凭据由后端正式 SDK 获取和刷新，浏览器不接收令牌。Bedrock 当前使用其官方 API Key 路径。

兼容服务按明确的协议配置。保存配置和确定性测试通过，仅证明对应合同；实际服务、部署、型号及能力需要分别验证，源码快照状态见 [EDITION.md](../EDITION.md)。

## 文件与旧配置

桌面继续使用应用数据目录内的 `settings.json`，其中 `model_settings` 是模型配置权威字段。旧的单个 `provider` 会在读取时转换为默认服务与模型；成功保存后采用新字段。原环境变量 `OPENCODE_API_KEY`、`OPENCODE_BASE_URL`、`FLUID_LLM_MODEL` 仍可用于旧入口。

独立本地服务使用其数据目录的 `model-settings.json`。读取 API 只返回脱敏的当前设置。

单独调用或真实模型试验可设置 `UNDERSTAND_BOOK_MODEL_SETTINGS` 为普通模型配置 JSON 文件，`UNDERSTAND_BOOK_MODEL_CONFIG_ID` 为要使用的模型配置 ID。显式文件无效时会报错，不会回退到旧环境的另一模型。普通 JSON 示例：

```json
{
  "revision": 0,
  "services": [{
    "id": "local",
    "name": "本地 Ollama",
    "base_url": "http://127.0.0.1:11434",
    "auth": "none",
    "api_key": "",
    "headers": {},
    "deployment": { "kind": "direct" }
  }],
  "models": [{
    "id": "local-reader",
    "name": "本地阅读模型",
    "service_id": "local",
    "model_id": "替换为已安装且支持工具调用的模型ID",
    "api_protocol": "ollama_chat",
    "mode": "native",
    "context_window_tokens": 32768,
    "output_token_limit": 4096,
    "capabilities": { "native_tools": true, "json_object": true }
  }],
  "bindings": { "default_model": "local-reader" }
}
```

示例的能力与窗口需要按实际安装模型填写。输出上限同时限制主问答和后台调用，不会因调用方请求较大输出而超出配置。Chat 的高级生成参数可选择 `max_tokens` 或 `max_completion_tokens`；未填写温度时新协议不发送温度参数，按实际服务能力填写。

使用推理模型时，应为推理与最终结果共同留足输出空间，并按实际输出及费用预算设置。

## 已知限制

- 真实服务验收按端点、型号、区域逐项记录；缺少凭据或预算的组合保持未验收，不以本地 HTTP 夹具代替。
- Bedrock 尚未实现 AWS access-key / SigV4 凭据链；Azure Responses 使用 v1 路由。
- 模型目录自动发现、厂商托管搜索与执行环境不在当前设置表单中；手填 ID 可直接使用。
