# 跨书补讲与理解接续

2026-10-16。CB0–CB5 已实现并通过自动验收。决策：[ADR-0169](adr/0169-cross-book-reading-and-private-understanding.md)。

## 1. 目标与归属

阅读器 Agent 在当前任务中识别具体知识困难，从用户可访问的其他已发布材料读取相关原文，同时读取该用户已有理解，并将真实交互及新的理解假设保存到同一 LearningMemory。引用和后续追问保留材料身份。

示例：读系统编程书时不理解 Rust 借用，Agent 从 Rust 书取得原文并读到用户之前混淆移动与借用的记录；本次针对这一区别补讲。用户之后的回应关联 Rust 来源保存，未来从原书、Rust 书或另一阅读任务都能取到。

聊天和阅读现场仍归原任务；参考材料使用确切 PublishedBookRef；学习记录归当前用户、关联来源和可用正式对象。普通解释允许补充参考材料，不要求先开启正式测评。

**对齐记录**：用户已确认复用内部多书读取和 LearningMemory，要求同时贯通补讲、理解读写、引用与后续追问，并先落档拆片。已接受的边界变化是单书证据扩展到带材料版本的多书证据；聊天与私人数据所有权不随参考材料改变。

## 2. 内部调用与来源

```text
当前问题与已验证原文
  → library.list：当前用户获授权的材料与可用能力
  → library.read：指定 PublishedBookRef，复用已有检索/结构/原文投影
  → library.learning：读取该材料的已有理解与相关交互
  → 补讲与引用 → 用户反馈 → 带真实依据的理解更新
```

书库目录和内容读取复用 PublishedLibrary 与现有 MCP 纯读取实现，抽出内部账号入口；远程认证、用量扣次和传输保留在远程入口。Runtime 通过现有运行端口取得服务，不能在参数中指定用户身份。

Agent 工具使用独立 library 命名，当前 book 工具保持当前书语义。目录分页、内容分页、不可用能力沿既有返回。检索结果用于定位，实际读到的正文才进入证据账本；位置按材料版本分区。

触发依据是当前请求、具体困难及相关学习记录。已有材料足够时直接解释；需补充时选择相关书和范围。没有相关材料或权限时明确该次缺口，沿当前可用证据继续。

## 3. 学习记录

读取使用 LearningStore 的 current_interpretations、learner_projection 和真实交互记录；返回来源版本、依据与仍未知的部分。普通跨书补讲使用已有 UsageObserved 和 Hypothesis 合同，保留原聊天/回合的引用。Agent 更新时必须提交实际读过的参考来源和原用户表达，服务端核对后写入 LearningMemory。

解释送达记录仅在实际回答提交后成立。理解假设标为未评估，不能由助手答案单独支持；正式表现证据仍由既有活动、作答与评估路径产生。修正沿 supersedes 保留历史。用户进入参考书时，既有理解查询能够按其来源取回这些记录。

## 4. 引用和追问

来源绑定保留 book_id、确切 publication_id、原文范围与可见标签；引用呈现复用当前来源组件。跨书引用预览读取被引用材料，明确书名和位置；完整打开使用已有确切出版来源链接，原聊天保持可接续。

历史加载允许合法的参考材料来源；当前书的无 publication_id 旧来源继续遵守原合同。追问以原问题现场为主，附带上一回答的参考材料身份与已交付内容。只把当前书范围交给当前书导航/正式教学目标；参考来源独立参与解释与理解记录。

## 6. 当前边界

首版参考材料来自现有账号授权的已发布书库；单机未连接该书库的运行没有参考材料入口。公网自动找书、下载新书和跨书正式对象对齐另有需求时再扩展。已存在的单书读取、远程 MCP 和正式能力评估沿各自合同。

工作区在开始时已有发布、自进化、缓存等未提交改动；本线只在所需路径作局部修改，保留其他工作线内容。实施基于 HEAD 402d9be 的当前工作树。
