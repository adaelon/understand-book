## 3. 共用观察与记录合同

### 3.1 不引入检查 API 的数据边界

产品运行继续使用现有 `framework`、`focus`、`working.items` 与 preview 回执。下表只是**测试/评测归档内容**，不是新增 wire schema、数据库表或 Agent 必填输出：

| 应记录的信息 | 用途 |
|---|---|
| case、组别、模型/指导版本、材料摘要、run | 使实验可追溯、可对照 |
| 当前候选或确切已交付版本 | 防止把旧成果的检查算给新候选 |
| 要检查的具体关系与已知风险 | 区分布局问题、内容问题与状态问题 |
| 环境、活动演示、初始参数与动作序列 | 重现本批从新页面开始的状态 |
| 请求逻辑位置、返回逻辑位置、可取得的实际媒体时间 | 防止把目标当作已显示结果 |
| 对应截图、DOM、read_selector 读数及错误 | 将判断绑定到实际观察 |
| 下一次模型请求中的图片绑定、回执及实际加载的新增指导 | 区分观察是否到达、检查指导是否加载、视觉方法指导是否加载 |
| 发现的问题、修改候选、复查结果或未覆盖原因 | 防止“检查过”替代“已修好” |

不得把生成页面中的说明、截图文字或该归档提升为新的系统指令。来源可信度仍由原证据链决定。

### 3.2 四动作预算与 fresh-page 重放

每次 preview 从候选的真实初始页面开始。**一批可达的条件是：重建全部前提所需动作 + 本批目标操作 ≤ 4。** 需要观察第二个演示后段时，可按真实控件组织为：滚动到局部 → 选择活动演示 → 定位到变化前 → 定位到关键位置。下一批检查变化后时，重新建立本批所需的演示选择与参数。

只有各批均满足上述条件时才能拆批。当前 `click` 点击控件中心；`key` 仅支持方向键、Home、End、Enter、Tab；`seek` 设置语义位置。参数能否设到目标值取决于页面的真实控件，跨批不能累计调整次数。源码入口为 `crates/server/src/presentation_preview.rs:Cdp::interact`。

项目已有圆盘页面的 `r2Range` 范围为 1–3、步长 0.01、初始值 2，设为 1.5 需要 50 次方向键调整；该值也在已有数学检查中使用。现有 preview 的中心点击和定位动作不能替代这项参数设置。材料见 `docs/performance/ex11-local-demonstrations/ex11.7/batch12/runs/disk-1/delivered-raw.html` 与 `packages/web/playwright/agent-presentation-ex11-batch12-math.spec.ts`。

现场超出当前动作能力且没有真实快捷控件时，记录目标、所需前提及未覆盖原因。工程验收可通过现有 Reader 操作或定向浏览器测试补证，注明候选/版本和观察方式；运行中的 Agent 保留未覆盖项。此类补证单独归档，不计为 Agent 已自行通过 preview 检查，也不替代当前候选的正式三环境回执。

一批中 `read_selector` 只对应最后动作。需要比较两个位置的精确读数时，分别安排以这两个位置结尾的预览，并保留各自参数、语义步号、单位和截图。前后图片可来自同批，但不能共用一份末态读数作为两者的事实。

### 3.3 最低工程回归与内容检查不同

新验收显式传入 `viewport`。现有实现另保留 legacy `width` 回执路径，本片不改变其兼容行为，但不能用一次 legacy 预览作为三环境通过的证据。该区别来自 `crates/server/src/presentation_author.rs:392–439`。

工程测试覆盖已有非零小数定位、回退和重复定位合同。具体小数位置只出现在测试数据中，不写死到通用指导。被测页面报告状态正确但几何不动时，测试应能发现；对固定夹具可以用已知标记区域、对象位置或图像差异验证，不把此方法扩成任意教学图的自动正确性判断。

内容评审还需要看“变化前—关键变化—变化后”是否表达了目标关系。某一张图没有遮挡，不代表整个过渡合理；实际播放的流畅性和停止行为另验。

### 8.3 隔离的数学核对值

N1 使用：

```text
L(w) = (w - 2)^2
w0 = 0
w(k+1) = w(k) - 2η(w(k) - 2)
e(k+1) = (1 - 2η)e(k),  e(k) = w(k) - 2
```

独立已知值如下。它们来自以上给定模型的直接计算，只用于核对，不自动进入通用指导：

| 学习率 | w1 | w2 | w3 | 解释性质 |
|---|---:|---:|---:|---|
| 0.2 | 0.8 | 1.28 | 1.568 | 同侧接近 |
| 0.8 | 3.2 | 1.28 | 2.432 | 跨越且交替接近 |
| 1.1 | 4.4 | -0.88 | 5.456 | 交替远离 |

η=0.2 与 η=0.8 在相同步号的距离和损失相同，不代表其位置在每一步相同。步号、参数和符号不能在 DOM、图形或最终回答中丢失。该模型的边界不得与 `f(w)=w²/2` 的学习率边界混用。

## 12. 测试执行分层

以下是拟实施测试的运行组织，不是本轮已执行命令。新测试先通过 `--list` 确认真实注册；过滤到零个测试不算成功。

```bash
# 检查现有 Runtime 演示测试及新增 Server 测试注册情况。
cargo test -p runtime presentation -- --list
cargo test -p server ex14_ -- --list

# 确定性单测、假 Provider 的请求装配与负向合同；不得调用付费模型。
cargo test -p runtime presentation -- --nocapture
cargo test -p server ex14_ -- --nocapture

# 拟新增的环境依赖测试应显式 ignored，按名称单独执行。
# 运行前确认当前测试列表、浏览器与 Manim 配置，避免误选付费测试。
cargo test -p server ex14_browser_ -- --ignored --nocapture
cargo test -p server ex14_manim_ -- --ignored --nocapture
```

命名 `ex14_browser_`、`ex14_manim_` 是对新测试的命名要求，当前没有声称这些测试已经存在。真实 Provider 实验应有单独的显式启动入口、费用边界和输出目录，不放进上述普通测试命令，不依靠“本机有 API key”自动运行。

当前 runner 固定 Manim 0.21.0/Cairo、30fps、无音频及既有输出限制。遵循仓库 `docs/Manim-部署.md` 的部署合同；指导不得要求 Agent 在制作时安装依赖。真实测试缺少配置时，保留具体环境诊断。

## 13. 每片完成记录与回滚

每片提交记录：实际修改路径、相关基础版本、测试名称与执行结果、证据位置、已验证路径及仍未覆盖的情况。代码编译、工程接入和自然实验采用分别记录。

若首批结果不能支持采用，交付“未采用”的报告和可重用工程测试即为有效结果，不强迫继续加动画或扩大参考资料。若真实用户学习测量未开展，不能为了完成计划补写学习效果结论。
