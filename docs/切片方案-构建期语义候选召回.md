## 1. 当前代码接点与待补合同

```text
teaching-build.ts
  routeFormalObjectFragments(...)
    → fragment generation tasks
    → accepted FormalObjectFragmentResult[]
    → newObjectAlignment(...)
    → objectAlignmentInput(...)
    → alignment Agent action
    → advanceObjectAlignment(...)
    → acceptFormalObjects(...)
```

起始实现与现有接点：

- whole-source object input 超限后进入 fragment + alignment 路径；完整 candidate ledger 持久化，模型只看到 focus、搜索页、最近 inspected records 和有界原文。
- `search` 对 catalog JSON 做 lowercase substring 匹配，每页 6 条；空 query 浏览整个目录。
- 非 focus 的参与对象须经过 inspect。Core 校验来源归属、引用、覆盖和拆并；SR0a 已增加 resolve/identity 的本次原文读取覆盖 gate。
- 起始实现恢复完整 `ObjectAlignmentWork` 后状态；SR4b 已改为持久化并重放原始 action，当前目录和模型输入分别判断复用。
- `routeTeachingBuildStages` 和 candidate writer 当前均为同步路径。普通 snapshot 路由还被计划准备、剩余工作查询和恢复读取调用。
- `BuildExecutionProfileV1` 描述 Harness transport/session；EmbeddingProvider 由 Core 独立配置。

主要代码：[alignment](../packages/core/src/teaching-object-alignment.ts)、[teaching build](../packages/core/src/teaching-build.ts)、[snapshot / authorized preparation](../packages/core/src/build-orchestrator.ts)、[build driver](../skills/build/automatic-build.ts)。

## 2. 目标数据流与所有权

```text
已确认 BuildPlan：mode / provider / 数据边界 / 预算
              ↓
当前 fragment candidates + previous FormalObjects
              ↓
当前 alignment catalog + focus / 显式 search 请求
              ↓
Core 获授权的异步 preparation
  投影 → 复用向量或调用 provider → hybrid retrieval
              ↓
准备好的候选页 → rendered input / input hash
              ↓
复用或生成 Codex / DSH 的一个模型 action
              ↓
在当前 ledger 上应用 action，校验 inspect / 原文读取覆盖
              ↓
search → 保存请求，下一步准备搜索结果
resolve → 更新目录与下一 focus
identity → 接纳对应并切换下一 focus
finish → 既有正式对象分配与接纳
```

普通 snapshot 读取只消费已准备结果；缺失时返回待准备。Provider 请求、缓存重建和用量写入只在 authorized preparation 内进行。search action 的接纳不调用 provider。

向量缓存位于 `.build/semantic-retrieval/`。已接纳 action、冻结模型输入及其实际候选页沿现有 teaching task/artifact 路径保存；它们服务语义复用，不随向量缓存删除。准备依赖未变时复用已有检索结果，依赖变化时先重新准备再判断模型 action 是否可复用。

**目的**：确认真实召回缺口，并用一个真实 provider 验证后续合同的可行性。

**主要位置**：

**工作**：

2. 记录两个现状缺口：未执行 read 的引用仍可被接纳；未展示对象变化可保持 rendered input 不变。分别由 SR0a、SR4b 修复，不把它们写成已有保证。

## SR1 — 异步 EmbeddingProvider 与确定性 Projection

**进度：已完成。** [实施与验证](performance/semantic-retrieval-sr1-sr3-20261001.md)：异步合同、完整引用一跳投影、实际 tokenizer 门禁；同接口本地 MiniLM 完成固定 28 documents / 8 queries。v1 摘要上限为每条 256 / 整体 1024 Unicode code points，实际 token 仍超 128 时明确拒绝，完整词法字段保持。

**目的**：用 SR0 的真实 provider 约束建立与 Harness 解耦的最小合同。

**主要位置**：新增 `packages/core/src/embedding-provider.ts`、`packages/core/src/semantic-retrieval.ts` 及对应测试。

**Provider 合同**：

```text
EmbeddingProviderIdentity {
  provider_id
  model_id
  model_revision          // 按 provider 可提供的事实记录
  embedding_config        // 实际影响向量的参数，含 document/query 处理方式
  dimensions
}

EmbeddingProvider {
  identity
  limits                  // 已选 adapter 的单条输入及批量上限
  embed_documents(text[], {signal}) -> Promise<{vectors[], usage?}>
  embed_query(text, {signal}) -> Promise<{vector, usage?}>
}
```

身份按显式字段比较；secret 不属于身份。Core 记录调用/记录/query 数与耗时，adapter 回传可获得的真实 usage；未知用量保留未知。同一检索使用同一 identity 的 document/query 向量，返回数量与维度须符合合同。

**Projection 合同**：

```text
SemanticRetrievalRecord {
  key
  lexical_fields          // meaning / aliases / conditions / kind / 角色与组件摘要
  embedding_text
  content_digest          // 仅绑定 embedding_text，供向量缓存使用
}
```

`embedding_text` 排除 key、object_id、candidate_refs、路径、revision、构建状态和 similarity；record 的 key 仅用于目录寻址。当前对象的 participant/component 按 qualified key 解析；previous 对象按 `LearningObjectRef` 解析到其有效 revision。

角色摘要保留“角色 → 对象含义”的配对，组件摘要只展开一跳；读取被引用对象的 kind/meaning/aliases/conditions，不递归展开其关系。字段顺序、摘要上限及 embedding 总输入限制由 `formal_object_retrieval_projection.v1` 固定，并满足所选 provider 的限制；词法字段不因 embedding 文本截短而丢失 exact/alias 匹配。超限处理由显式投影规则决定，不依赖 SDK 静默截断。

**测试**：

- 同内容及引用目标 → 相同投影；只换 key/ref 且维持相同引用内容 → embedding text 不变。
- 实际进入 embedding 文本的 meaning/conditions、角色配对或所引组件摘要变化 → content digest 变化；仅未进入文本的词法字段变化则只重算检索结果。
- 当前候选和 previous 正式对象的等价内容投影一致；相同文本的不同对象仍保留各自 key。
- provider identity、返回数量或维度不匹配时拒绝使用；取消可传到 adapter。
- Fake provider 离线验证调用与投影；SR0 的真实样本验证合同可执行。

**完成判据**：Core 独立于 Codex/DSH 生成稳定 records，并能通过同一异步接口消费 fake 与所选真实 provider；接口不提供身份修改能力。

## SR2 — 可再生向量缓存与 Brute-force Cosine

**进度：已完成。** [实施与验证](performance/semantic-retrieval-sr1-sr3-20261001.md)：按完整投影复用/重算，失败保存已完成批次；fake 与真实本地删除重建排序一致，3k/10k 测量完成。准备记录独立且可序列化，教学状态的持久化接入由 SR4 完成。

**目的**：按完整投影变化更新向量，用单书规模验证简单实现。

**主要位置**：`semantic-retrieval.ts`、cache helper 及对应测试；必要时调整 `.gitignore`。

```text
.build/semantic-retrieval/
  cache.json              // 一次替换：格式/provider/projection/维度 + records 映射 + vectors
```

**缓存与准备结果**：

- 向量 key 为 `provider identity + projection version + content digest`，用于跳过昂贵 embedding。相同文本共享 vector，不合并 catalog records。
- resolve 修改目录后重投影当前目录。只重算完整 embedding 投影发生变化的 vector，包含受参与者、组件变化影响的 relation/composite。
- retrieval policy 的排序、配额变化只重做检索结果；provider/projection 未变的向量继续复用。
- 准备记录沿 teaching 状态保存，包含 provider/projection/policy、focus 或显式 query、实际参与检索的 records 及稳定结果序列。直接比较这些依赖决定是否复用；不增加仅供诊断的 catalog 总摘要。
- query vector 不要求长期持久化。同一准备记录的翻页只切片结果序列，inspect/read 也不重复请求 query embedding。
- cosine 使用 brute-force；同分按 canonical catalog key 排序。模型摘要由当前记录渲染，避免把旧完整对象保存在搜索页中继续使用。

**测试与完成判据**：

- Fake provider 下删除向量缓存并显式重建，得到相同排序；真实 adapter 的重建记录实际结果，变化按 SR4b 处理。
- 独立对象内容变化只重算自身向量；被引用对象变化时，引用方投影随之更新；不变投影不请求 provider。
- provider/model/config 变化导致向量 miss；只换检索排序 policy 不重新 embedding 文档。
- 同一 query 翻页或 inspect/read 不重复请求 provider；维度不匹配的向量不被使用。
- 删除向量缓存保留已接纳 action、冻结输入和已发布正式对象，不撤销 readiness；新的检索准备若需要向量，由获授权步骤补建。
- 3k/10k records 测量投影、cosine 与内存开销。该结果用于判断简单实现能否承担实际单书目录，不预先引入 vector DB。

## SR3 — Hybrid 搜索、空查询与分页

**进度：已完成。** [实施与验证](performance/semantic-retrieval-sr1-sr3-20261001.md)：固定融合规则、空查询全目录、稳定分页、显式准备输入与 search 请求接纳。正式 Core 排序复用真实 Gold 向量，B/C recall@6=12.5%/100%。现有生产 router 仍走旧 substring，待 SR4 接入；Agent prompt policy/generation 已升 v3，action schema 与 alignment 状态保持 v2。

**目的**：在可解释候选页内增加 semantic lane，同时保留完整目录浏览。

**主要位置**：`semantic-retrieval.ts`、`teaching-object-alignment.ts`、`agents/formal-objects-extractor.md` 及对应测试。此切片消费显式传入的准备数据，不在 action writer 中调用 provider。

```text
retrieve(request, current_catalog, prepared_vectors, policy)
  query == "" → 现存目录按 canonical key 排序 → offset/page_size
  否则：
    解析有效 canonical key，过滤 focus 自身与退出目录的旧 key
    按 canonical key 去重
    exact meaning / alias lane
    lexical lane
    semantic cosine 排名
    固定 lane 顺序，按 canonical key 去重并融合 match_reasons
    跳过重复并继续补位，semantic 独立贡献上限 K
    固定结果序列 → offset/page_size
```

**首版 policy**：

- `page_size = 6`，`semantic_top_k = 12`。空 query 浏览完整现存目录，含 focus、current 与 previous records，不调用 embedding。
- 非空查询保留所有 exact/alias 强命中作为融合序列前缀；剩余 lexical/semantic 以一条 lexical、一条 semantic 交替补入，某 lane 耗尽由另一 lane 补位。Semantic 顺排名扫描，遇到已收录 key 只合并 match reasons 并继续补位，最多贡献 12 个新增对象；不预截 12 条后再丢重复项。
- Lexical 在语义字段上保留现有空白分词、lowercase substring 命中规则；同层使用确定性顺序。当前 substring JSON matcher 保留在 benchmark 的旧基线中。
- Top-K 从可补入的有效对象中选取，过滤或跨 lane 去重不能造成有候选却未补位。不同对象不得按投影 digest 去重；redirect 的存活目标及已 resolve 对象仍是有效候选。
- 同一快照/query/policy 的融合序列固定后分页。返回 `next_offset`、实际候选数与 semantic lane 的截断事实；无下一页仅表示当前融合结果耗尽，不表示全目录不存在其他相关对象。

**自动 focus 与显式 search**：

自动召回在新 focus 开始时执行：exact/alias 使用 focus 的 meaning/aliases，semantic query 使用其有界语义投影。Agent 发出 `{kind:"search", query, offset}` 后，该显式请求接管当前搜索页；非空 query 原文作为查询，按 provider 输入限制明确处理超限。inspect/read 保持此请求，翻页复用同一序列；成功 resolve/identity 清除旧请求，准备下一 focus。目录或检索配置变化后重建序列，offset 从当前有效 action 链重放取得，不沿用旧游标。

**候选页**：

```text
{
  key,
  match_reasons: (exact_meaning | alias | lexical | semantic)[]
}
```

模型页保留有限 meaning/kind/conditions 摘要，similarity 只写诊断；完整对象仍经 inspect，实际引用仍受 SR0a 的 read gate 约束。

**完成判据**：exact/alias 强命中保留；self/重复项不挤占 semantic 补位；空查询可以翻遍目录；显式搜索不被自动页覆盖。Fake vectors 验证这些机制；语义收益由 SR0 真实探针及 SR6 对照判定。

## SR4a — BuildPlan 与获授权的异步准备

**进度：已完成。** [实施与验证](performance/semantic-retrieval-sr4a-20261001.md)：BuildPlan 绑定配置/范围/额度，显式异步准备接入普通路由的 preparation_required；逐次调用预留、实际 usage/未知用量、失败/取消与恢复持久化。10 文件 83 项及 Core 类型检查通过。生产 adapter 与 host/driver 注入仍由 SR5 完成，模型 action 重放由 SR4b 完成。

**目的**：将 provider 的执行授权、预算和失败恢复接入现有构建控制边界。

**主要位置**：

- `packages/core/src/build-intent.ts`、`automatic-build-budget.ts`
- `packages/core/src/build-orchestrator.ts` 的 `prepareAutomaticBuildSnapshot` 与普通 snapshot 路径
- `packages/core/src/teaching-build.ts`
- `skills/build/automatic-build.ts` 的准备、计划与预算执行接点

**合同**：

1. BuildPlan 绑定 `retrieval_mode`、provider selection/config identity、local/remote、投影文本的数据边界及执行额度。记录数尚未形成时标注估计/未知，fragments 就绪后展开实际准备工作量。
2. document embedding、query、resolve 引起的投影重算和 adapter 重试均计入实际执行用量及剩余工作估计。沿现有 token/墙钟预算执行；provider 无 token 用量时用明确的 records/query/call 额度限制，未知不记为 0，不伪造精确费用。
3. 复用现有 authorized preparation 控制调用增加异步路径。调用前读取已确认 plan identity、检索配置与预算；配置漂移、额度超出沿现有 needs_user 恢复边界处理。
4. 普通 snapshot 路由只比较当前依赖并消费准备记录。缺失返回 `preparation_required`；计划预览、remaining-work、普通恢复读取不发请求、不重建 cache、不写 provider 用量。
5. `acceptTeachingCandidate` 继续确定性接纳 action；search 只保存 query/offset 请求。下一模型任务在检索准备完成并渲染实际页后创建。
6. preparation 接收当前控制调用的取消信号；请求和有界重试由本次调用拥有，不跨已结束调用保留后台工作。

**模式与失败**：

| 条件 | 行为 |
| --- | --- |
| `lexical_only` | Core 完成本地 exact/lexical 搜索，provider 调用数为 0 |
| `semantic_required` 且已有有效准备结果 | 使用已准备候选页，不因 provider 临时离线重复探测 |
| 普通路由发现缺少准备结果 | 返回待准备，等待获授权的执行调用 |
| 获授权准备中 auth/rate-limit/network 失败或取消 | 保持 incomplete，记录 provider/取消原因；保留已接纳 action |
| provider 恢复 | 补完原请求的准备，再渲染下一任务；不递增语义生成 attempt |

**测试与完成判据**：用计数 fake provider 验证未确认计划、纯状态读取、预算不足与配置漂移均为零调用；正常准备记入用量；失败不变成 `semantic_output_invalid` 或空候选；恢复不要求 Agent 重新生成 search。Codex/DSH 共用同一准备结果，Harness 切换不更换 provider。

## SR4b — Action 复用与当前 Ledger 恢复

**进度：已完成。** [实施与验证](performance/semantic-retrieval-sr4b-20261001.md)：alignment 内部 v3 与 action receipt、当前 ledger 重放、冻结输入/当前 writer 状态分离、finish 依赖比较与关闭时物化；旧 generation 与 receipt 保留。7 文件 83 项与 Core 类型检查通过。

**目的**：满足 ADR-0146 的实际输入重算，同时保留正式身份分配的幂等性。

**主要位置**：`teaching-build.ts` 的任务构造/冻结/接纳/恢复、`teaching-object-alignment.ts`、对应 artifact 类型与集成测试。

**保存与重放**：

- 接纳记录保存模型原始 action 及其现有 input/prompt/semantic-contract 绑定。Core 从当前 accepted fragments 和 previous 构造 ledger，按任务顺序准备实际页、渲染输入，再查找可复用 action。
- 非终态 action 在当前 ledger 上重新应用并执行当前接纳 gate；search 得到请求，不能从旧 post-state 恢复搜索结果。显式 query 和自动 focus 的准备分别使用自身实际依赖。
- 保留的整份 post-state 仅在其对应冻结前状态与本轮 Core 依赖相同时可直接恢复。Core 依赖包含当前 proposal（含引用、来源和覆盖）、previous、source 版本/范围、决策中的 inspected/read 状态及当前检索请求/结果；依赖直接比较，不另加总状态指纹。
- finish 的既有 FormalObjects 只在当前 proposal、previous 和 source 依赖仍一致时恢复，保持既有 operation/身份分配幂等性；依赖变了按原接纳规则重新物化。
- 当前 ledger 或新诊断不回写旧冻结任务。已有 task 保存当时模型实际输入，新的运行状态由 Core 持有；cache 路径和 provider 诊断字段不进入模型复用身份。
- 实际候选 key、match reasons、摘要、query/offset 等模型可见内容进入 rendered input。Provider/config 改变但实际输入相同，可以复用 action；输入改变则使后续模型决策失效。
- 存储中加入 action、读取覆盖及检索请求需要显式更新 alignment 内部版本；新增接纳约束和模型合同按实际语义变更更新绑定，不能把缺失这些记录的旧 artifact 冒充新合同。

**必须覆盖的恢复场景**：

1. 自动 focus 页不变，但同一显式 query 因 provider/policy 变化得到新结果：旧 search action 可复用，下一步使用新结果，原后续模型决策失效。
2. 未展示目录对象变化，bounded input 和候选页均不变：模型 action 可复用，当前目录变化保留，旧完整 proposal 不得覆盖它。
3. resolve 修改参与者含义或组件引用：检索准备失效、相应投影更新；其它不变向量继续命中缓存。
4. provider/config 改变但实际模型输入仍相同：复用 action，不因诊断变化触发旧 frozen task 改写冲突。
5. 缓存删除或 provider 中途失败：已接纳 action、已读范围和正式身份保持；缺少的新准备获授权后补完，同依赖 finish 恢复不分配新 ID。

**完成判据**：以上场景经实际 task/input/artifact 路径验证；既有完整目录、来源、身份和发布 gate 通过。检索 freshness 和模型 freshness 分别判定，代码不会以旧搜索结果证明自身仍 fresh。

## SR5 — 一个真实 Adapter 与配置/确认面

**进度：已完成。** [实施与验证](performance/semantic-retrieval-sr5-20261001.md)：本地 MiniLM adapter、逐次计量的有限重试、获授权后加载/释放、配置草稿与精确确认、Codex/DSH 异步 driver/refill/controller 接入。Core 13 文件 153 项、DSH 前台 10 项与双包类型检查通过；新授权真实本地 9 documents / 3 queries / 5 calls，取消后恢复及配置漂移零调用通过。

**目的**：将 SR0 选定 provider 接入 SR4 的执行边界，完成可使用的配置入口。

**工作**：

1. 只生产化 SR0–SR1 已验证的一个 adapter；落定批处理、取消、有限重试、usage 回传及实际模型/config 身份。核心合同若与实测不符，先修订 SR1 合同再继续。
2. 配置与 BuildPlan 确认面展示 retrieval mode、local/remote、provider/model、待 embedding 文档/query 的估计、发送的投影文本范围、预算上限及可获得的费用类别；授权绑定 SR4a 的实际字段。
3. Secret 沿现有安全配置路径读取，不写书工作区、task artifact 或 cache manifest。配置随构建选择持久化，不由当前 Harness 推断。
4. 将真实 adapter 仅注入 authorized preparation；普通状态读取与 candidate writer 保持零 provider 调用。

**完成判据**：在已确认计划下真实执行准备，覆盖一次失败/取消与恢复；费用/用量记录进入预算判断，配置变化进入既有确认边界。未配置 provider 时可使用 `lexical_only`，不同 Harness 消费相同候选页。SR4a/SR4b/SR5 共同通过后才开放生产 semantic mode。

## SR6 — 三组对照、真实长材料与发布门槛

**进度：验收工具已实现，真实验收未通过。** [实施记录](performance/semantic-retrieval-20260930.md)：三组真实 Agent 入口、固定向量排序、身份指标、调用计量及续跑已实现；读取越界错误增加实际段长反馈，25 项定向测试通过。首轮仅 B 完成；用户批准的统一非思考轮 A/B/C 均因连续三次动作拒绝停止，涉及错误 JSON 包装和整体/部分合并后自包含。两轮累计 345 次生成、29 documents / 4 queries / 9 embedding calls，均在批准额度内。固定向量 B/C recall@6=12.5%/100%；未完成身份质量保持未知。长材料 338 个首批分块任务的草稿尚未确认；默认保持 lexical_only，SR6 未完成。

**目的**：区分词法改进和 embedding 的实际贡献，并验证构建全流程。

**主要位置**：新增 `docs/performance/semantic-retrieval-20260930.md`，扩展 T5A 真实长材料记录与 teaching build/source review 回归。

**对照组**：

| 组 | 候选召回 |
| --- | --- |
| A | 当前 catalog JSON substring 算法 |
| B | SR3 的 exact/alias + lexical，关闭 semantic lane |
| C | 与 B 完全相同的词法实现，加真实 embedding lane |

A/B/C 使用同一 gold、来源/候选目录、query、page size、K、模型/prompt、SR0a 读取 gate 和 alignment 预算；旧版本历史用量只作参考。主比较为 C 对 B，A 用于说明词法改进贡献。质量判断依据 gold 对象对与独立原文审阅，排序分数不充当判断依据。

**记录**：recall/precision@6/12、false merge、false split/missed identity reuse、alignment steps、inspect/read 次数、rendered input tokens、embedding 文档/query/重试用量、批次、latency、cache 命中及整份构建耗时。费用或 token 不可得时明确标注未知。

**真实验收**：

- 至少一份真实长材料，包含跨章节改写、同词异义、条件和关系角色差异；独立 source review 回读原文判断最终 Formal Objects。
- 经过一次 provider failure、cache rebuild、provider/config change 后的 resume/reuse，确认 SR4b 的刷新与稳定身份合同。
- 检查普通阅读、Pass2 enabled/disabled、小材料直接路径与 readiness；它们不需要检索准备时不因 provider 不可用被阻断。

**发布门槛**：

- C 的 gold recall@6 高于 B，且 exact/alias 强命中不丢失；recall@12 与各类样本结果同时报告，不能用总体数掩盖具体退化。
- 明确应分离 gold 对象对 false merge 为 0；总体 false merge 与 missed reuse/false split 不高于 B，新的真实语义错误须修复后再发布。
- 来源读取、coverage、身份与 readiness 合同无回归；实际调用符合确认预算，模型步骤及总耗时变化可解释。
- 若 C 相对 B 的收益不足，生产保持 `lexical_only`；保留验证记录和已有最小合同，不新增 vector DB 或默认必需依赖来维持实验。

## 3. 范围与已知限制

首轮只处理 T5A Formal Object Alignment；`book.concept`、读时检索、跨书身份、私人知识空间和 Pass2 保持既有合同。关系及身份继续由 Agent 比较原文、Core 接纳。

SR0–SR5 已实测本地 MiniLM、128-token 明确拒绝边界、固定 Gold 召回增益，以及获授权调用、取消恢复和配置漂移边界；真实 Agent 身份质量和长材料仍待 SR6。单个决策在现有来源读取或模型预算内无法完成时保持 incomplete。缓存删除不撤销已发布正式资产；新的构建请求仍须按当前依赖准备输入。

## 4. Pass2 后续准入条件

只有 SR6 通过后才开独立切片：将 shared-node、discourse/formula 与 semantic 候选融合，再交付双端原文 evidence packet，经 LLM classification 和确定性 gate 接纳。首轮结果不直接批准 embedding 产生 Pass2 edge。

## 5. 实施顺序

```text
SR0 现状 / gold / 一个真实 provider spike
  ↓
SR0a alignment 原文读取接纳
  ↓
SR1 异步 provider + 确定性 projection
  ↓
SR2 cache + 当前目录更新 + cosine
  ↓
SR3 hybrid 搜索 / 浏览 / 分页
  ↓
SR4a 已确认计划 / 预算 / 异步 preparation
  ↓
SR4b 模型 action 复用 / 当前 ledger 重放
  ↓
SR5 真实 adapter 生产接入 + 配置/确认面
  ↓
SR6 三组对照 + 真实长材料验收
```

每一步按其完成判据独立验证。SR0 无真实缺口或 provider 收益则停止生产 embedding 接入；SR4/SR5 合同未共同完成前，真实 provider 只用于已授权样本探针。
