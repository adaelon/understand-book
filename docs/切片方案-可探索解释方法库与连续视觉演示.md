## 0. FrozenIntent

用户只需表达“哪里没懂”。Resident Agent 识别理解障碍，选择解释动作；需要连续视觉解释时，制作对象身份稳定、可暂停/回退/改参数/追问的内容，并依据真实浏览器观察修订。

## 1. 目标链路与时间现场

```text
问题/选区/证据
 -> 判断是否需要富解释
 -> Obstacle / Objects / Change / Interaction
 -> 选择 0..N explanation moves
 -> 最小原型
      静态图 -> 按需使用 Matplotlib
      实时改参/连续几何 -> SVG/Canvas/JS；EX11 增加固定 Konva
      固定局部过程 -> EX11 Manim 短片段
 -> write
 -> preview（三视口 + 必要关键时间点）
 -> 截图/DOM/layout/issues
 -> revise 或 deliver
 -> Reader 中暂停/回退/改参数/保存/追问
```

scene helper 提供制作辅助；explanation move 表达方法选择。来源与交付权威仍由既有 Runtime/Server/Reader 合同拥有。

连续演示使用可重建的现场，复用现有 `PresentationState` 与页面 state reader/restorer。以下是行为约定，字段名称由样板确定：

```text
现场 = { parameters, semantic_state, transition_progress, reveal_state? }
renderAt(transition_progress, semantic_state, parameters, reveal_state?) -> visible scene
```

金样板中 `semantic_state` 的步数 k 表示已完成的真实迭代；`transition_progress` 描述 k 到 k+1 的视觉过渡。到达终点后归入 k+1，进度归零。图上应区分真实迭代端点与插值运动，数值说明以真实迭代结果为准。`reveal_state` 仅在存在预测后揭示互动时使用，并参与画面重建。

| 操作 | 金样板行为 |
| --- | --- |
| 暂停或定位 | 停止时间推进，保留参数、语义步骤、过渡进度及当前预测项的揭示状态，重建对应画面。 |
| 上一步、下一步 | 定位到当前位置之前或之后相邻的真实迭代端点；轨迹由目标位置重建，回退后不保留未来轨迹。 |
| 改 η | 停止播放，从 `w₀=0` 重算；回到第 0 步、进度 0，清除旧轨迹并将预测项恢复为未揭示。 |
| 保存或追问 | 沿用公开内容校验，在同一同步读取中捕获已渲染的参数、步骤、进度、揭示状态及可见结果；以实际捕获时刻为准，追问绑定保存回执。保存和追问不隐式改变播放状态，高频视觉帧不触发保存。 |
| 同版重开 | 恢复上述现场并保持暂停；从数据重建画面，不重放控件点击或其他副作用。 |

暂停中间位置、回退后重放、改参数和预测后揭示分别保留可复现操作序列。preview 验收定位与画面；真实 Reader 验收保存、重开和追问；真实播放验收流畅度。

## 2. EX0：冻结基线与金样例

实施记录：[EX0 冻结输入与门槛](performance/explorable-explanation-ex0-20260927.md)、[独立答案](performance/explorable-explanation-ex0-answers.md)。本刀已完成。

固定学习率任务的材料为 `L(w)=(w-2)^2`、`w₀=0`、`wₖ₊₁=wₖ−2η(wₖ−2)`，并声明该一维简化模型的适用范围。

| η | 误差乘数 `1−2η` | 独立核对的现象 |
| --- | --- | --- |
| 0.2 | 0.6 | 同侧接近最优点。 |
| 0.8 | −0.6 | 跨越最优点交替接近，与 η=0.2 的距离和损失序列相同。 |
| 1.1 | −1.2 | 两侧交替且距离增大。 |

独立答案可由闭式关系 `wₖ=2−2(1−2η)^k`、`L(wₖ)=4(1−2η)^(2k)` 求得。数值检查覆盖页面、readable content 和最终交付文字。

将 [ED3 已交付页面](performance/ed3-windows/C-position/view.json)及其[原始判定](performance/agent-presentation-ed3-ed4-20260925.md)保存为表示基线。手工样板另以相同信息与算例的静态或离散步进版本对照连续过渡；技能与制作成本对照在本批共同底座上重新取得 B，历史结果只作背景依据。

自然请求集保留学习率困惑、普通短答、非数值机制题，以及一个适合换视角而不需要动画的题。测试材料与独立答案分开保存，设计答案不注入自然请求。

EX0 在 `docs/performance/` 产出本批实验记录：固定请求、材料、模型及采样配置、实际代码/资源状态、各组差异、重复运行次数、失败记账方式，以及具体质量目标、采样/tokens/墙钟上限和可接受退化界限。先冻结这些条件，再运行处理组；后续 EX2、EX3、EX7 引用相应记录。新批次调整门槛须在处理组运行前说明依据。

运行记录包含能力发现、实际加载内容、模型采样数、tokens、墙钟、write/preview 次数、交付结果、三视口、数值正确性和表示收益。成本包含全部必要预览及修订重试，保留全部失败；小样本结论限定在实际覆盖范围内。

**Gate**：可复现输入、独立答案、表示基线和本批具体运行/判定条件已落盘，可供后续切片直接引用。EX0 不改产品。

## 3. EX1：手工金样板

实施记录：[EX1 样板、真实 Reader 验收与 EX5a](performance/explorable-explanation-ex1-20260927.md)。工程与可见表示已验；连续过渡的独立学习增益尚未由读者任务证明，因此不据此抽取公共 helper。

先用现有 HTML + SVG + JavaScript 手工完成参考候选，不抽象框架。

必须具备：

- 同一坐标/数轴比较 `η=0.2` 与 `η=0.8`，并用 `η=1.1` 显现交替发散。
- 对象身份稳定，每一步保留 trace/ghost，同时显示带符号误差与损失。
- 播放、暂停、上一步、下一步、定位和改 η 后重算。
- prediction-reveal 时刻，以及第 1 节约定的现场捕获与恢复。

页面核心计算只写一份，图形标签与 readable content 从同一结果对象派生；用 EX0 的独立答案核对多个 η 和 step，最终交付文字也在核对范围内。

比较已有 ED3 表示基线及同信息量的静态/离散步进版本，记录连续过渡是否改善同一对象的跟踪、跨越最优点过程的辨认等具体问题。若收益仅来自带符号误差或轨迹，归入相应表示方法；连续能力只按已证明的收益继续。

样板一旦可播放即开展 EX5a 测量。实际 Reader 覆盖中间位置暂停后保存、同版重开、追问，以及改参数和揭示状态恢复；preview 覆盖三视口及可执行交互。

**Gate**：三种现象可区分，数值正确，三视口可用，实际 Reader 现场一致；新增表示收益有明确对照记录。连续过渡增益未获证实时，保留有效局部改进，停止以该样板为依据提炼连续演示公共能力。

## 6. EX4：可定位 Scene Helper（条件性）

触发：EX1/EX2 已证明连续解释有效，且重复编写时间控制/恢复代码成为明显成本。EX6 使用样板的最小定位约定，可以在 EX4 未触发时独立实施。

先从金样板提炼最小浏览器 helper，概念接口：

```text
scene.seek({ semantic_state, transition_progress })
scene.play()
scene.pause()
scene.step(delta)
scene.snapshot()
```

实际 API 以最小实现为准，行为遵守第 1 节的时间现场约定。

要求：

- 同一参数、语义状态、过渡进度和揭示状态可确定性重建画面。
- 来源身份与交付资格继续由宿主拥有。
- 页面依赖随版本自包含或由宿主版本化装配，重开时可还原原版本行为。

**Gate**：金样板迁移后重复代码或实际缺陷有可记录的减少，播放、定位和现场恢复行为保持一致。

## 7. EX5：bridge 动画基准与观察分层

主要文件候选：`packages/web/src/presentation-bridge.js`、`packages/web/src/components/AgentPresentation.vue` 和 Playwright bridge/presentation tests。

**EX5a：测量。** 随 EX1 的可播放样板开展，在抽取公共 helper 前完成。测量前将宿主、目标帧率、典型对象/轨迹规模、可接受帧间隔和每帧本地观察耗时上限写入本批记录。

测量包括：

- 目标帧率下 SVG transform/opacity/geometry 更新，以及逐帧数字文字更新的负面对照。
- 本地 observe 次数、克隆/扫描等主线程耗时和实际帧间隔。
- 宿主 observe 请求、现场保存次数、遮罩和布局位移。
- pause/seek 后公开文字与画面的一致性。

现有 bridge 在文字与来源未变时不新增宿主 observe 请求，但属性变化仍可触发整树克隆与扫描。分别记录本地处理和宿主往返，据此判断是否需要修改。

**EX5b：条件性修复。** 仅在 EX5a 显示超出冻结预算、可见停顿或遮罩异常时启动。按实测原因调整观察粒度、局部视觉区域或提交边界，动态文字和 source ref 仍经校验。测量与修复各自形成独立结果，未触发修复时以测量记录收口。

**Gate**：目标场景下本地观察耗时和帧间隔满足预定预算，纯视觉帧不产生逐帧宿主往返或保存；操作期间无可见停顿、遮罩或布局异常；语义提交后能捕获一致现场，来源与非法动态文字回归继续通过。

## 8. EX6：时间预览合同

**状态（2026-09-27）**：已实施并通过工程 Gate；实现、真实浏览器与模型演练结果见 [EX6 报告](performance/explorable-explanation-ex6-20260927.md)。

主要文件：`crates/runtime/src/presentation_preview.rs`、`crates/runtime/src/presentation_author.rs`、`crates/server/src/presentation_preview.rs`、`crates/server/src/presentation_author.rs` 的 `preview_document` 装配，以及 Server/Runtime tests。

基于 EX1 的真实样板定义受限的“定位语义步骤与过渡进度”动作，使用有界位置参数，不开放任意脚本执行。页面与 preview 采用同一最小定位约定；EX4 若已触发则复用其 helper。

定位停止自动推进并重建目标场景；宿主等待实际浏览器渲染后，在场景保持冻结期间采集 DOM、layout、issues 和截图。观察结束后保持暂停，避免自动播放改变后续动作的起点。

需要支持：起点、中间位置、终点、回退，以及再次定位到同一点。沿用 candidate/environment/step 关联，其中 `step` 仍为 preview 动作序号；另记录目标与实际场景位置，区分算法语义步骤和过渡进度。

时间采样选择有解释意义的关键点；三视口继续按既有合同执行，其他视口只补查受布局影响的关键帧。真实 click/key 继续验证控件操作，定位动作只证明定位与画面。

**Gate**：同一点重复定位结果确定，同次观察各部分对应同一场景，回退不残留未来轨迹；实际模型请求获得关键中间帧并能据此修订；既有 click/key 与三视口合同不回归。保存、重开和追问复用 EX1 的真实 Reader 验收，按接口改动补跑相关路径。

使用真实 Resident 入口，不用详细工程 prompt 替代自然请求。

比较旧 skill + 旧 preview 与新 skill + 时间 preview 的实际选定组合。EX3 方法参考、EX4 helper 只在各自通过收益条件后纳入处理组，并记录其差异。

两组共享来源、状态和观察修复等共同底座，采用同一模型、材料、采样配置和总预算。该对照评价所选组合的整体收益；说明、参考和 helper 的单项收益分别引用 EX2、EX3、EX4。运行次数及成本门槛引用 EX0 的本批记录。

指标分三层：

**工程**：交付率、回合/tokens/墙钟、预览次数、三视口、运行错误、触控。

**表示**：相对基线的具体解释收益、方向差异、对象身份稳定性、公式/画面/readable content/最终文字的一致性，以及连续过渡的必要性。独立答题者可用于检查产物是否足以支持正确判断。

**学习效果**：对真实用户记录接触解释前后的表现，使用预先准备、未展示过的新 η 或等价新例，观察预测及原因解释；记录用户已有知识和作答时可获得的帮助。独立答题者已有知识带来的正确回答不计为用户学习收益。

**Gate**：工程与表示验收同时满足正确性、新增表示收益和预冻结成本门槛，报告预定重复运行中的全部结果。学习观察单列结果；尚未开展真实用户任务时标为“尚未评估”，工程与表示结论按各自证据成立。

## 10. EX8：跨领域迁移

覆盖三类任务：

1. 算法：双指针/滑动窗口等状态移动。
2. 生物机制：剪接或调控过程中的对象/状态关系。
3. 系统/论文：数据流、组件关系或实验变量变化。

目的不是统一模板，而是验证 explanation moves 能跨领域迁移。

**Gate**：至少两类非金样板任务通过正确性、表示收益和成本条件，其中至少一类为生物机制或系统/论文任务；能复用方法或已选 helper，无需增加学科专属核心 schema。

## 11. EX9a：Manim 连续讲解样片对照（样片与工程对照已完成）

**实施结果（2026-09-27）**：[对照报告](performance/explorable-explanation-ex9a-manim-comparison-20260927.md)、[播放页](performance/ex9a-manim/index.html)、[正式视频](performance/ex9a-manim/learning-rate-final.mp4)。Manim 0.21.0 / Cairo，五次真实更新与跨点停顿，独立数学及实际坐标 3/3 通过，全片解码与浏览器播放通过。定向样片体现了停顿、箭头及公式强调的编排收益；该收益不等于 Manim 引擎独有收益。用户随后明确要实时交互体验，下一步进入 EX10；学习收益及自然生成稳定性尚未取得。

**目标**：用同一学习率题目制作可播放的 Manim 连续讲解，与已有浏览器连续样板比较实际表达效果及制作成本，形成是否继续接入的结论。

**前置与输入**：沿用 EX0 的 `L(w)=(w−2)^2`、`w₀=0`、递推式和 η=0.2/0.8/1.1；对照 `docs/performance/ex1-learning-rate.html`，独立数值依据见 EX0 answers。EX1 与 EX6 已有工程证据，本切片无需等待 EX2 完整 Gate 或 EX7/EX8。

**范围**：检查本机 Python、Manim、字体/公式渲染条件，选择并记录具体实现；制作一段连续讲解并保存可重跑脚本、可播放媒体和对照记录。样片包含：

- 同一个点从真实迭代端点连续移动，原位置保留淡色标记，更新箭头显示方向和距离。
- 在越过最优点的时刻停顿，将跨越与误差符号翻转联系起来。
- 三种学习率轨迹并排播放，显现同侧接近、交替接近、交替发散。
- 公式中的 `1−2η` 与画面的方向/距离变化同步突出；数字、标签来自程序计算结果，真实迭代端点与视觉插值明确区分。

**交付物（拟建）**：`docs/performance/ex9a-manim/` 保存场景脚本、最小运行说明及播放媒体；`docs/performance/explorable-explanation-ex9a-manim-comparison-20260927.md` 保存对照记录、环境/版本、生成与修订次数、实际耗时及采用建议。实施跨日时报告日期使用实际日期。最终直接展示可播放样片。

**验收**：

1. 媒体能播放，以上连续运动、跨越停顿、并排比较与公式同步均在实际画面中出现；截图不能代替播放验收。
2. 用独立答案核对真实端点、`Δw=−2ηe`、步长 `2η|e|` 和距离比例；查看关键中间帧，出现数值或图文不一致即修订样片。
3. 与已有浏览器连续样板同题观看，记录可见表达差异、制作/修订成本和用户反馈，给出接入、继续补证或保留浏览器方案的具体理由。用户反馈未取得时如实标记。
4. 标明手工/模型生成身份及辅助程度；手工样片不能证明自然请求已稳定成功，不计作 EX2/EX7 通过或学习效果证据。

**范围外**：本切片不改生产方法库、Runtime/Server/Reader 渲染路径，不构建通用动画框架，不扩展到其他题目。

**后续条件**：若对照支持产品接入，再单独定义接入切片，按实际需要确定资源格式、预览、媒体装配、版本保存、执行与取消、跨平台依赖；不将这些工作预塞进 EX9a。

无明确收益则不接。

## 14. 完成定义

本节保留原 EX0–EX8 路线的完成口径；EX11 使用其独立合同，尤其按用户反馈记录成本而不套用旧 EX0 token 门槛，完成也不自动改变原停止批次状态。

工程与表示完成需满足：

- Agent 在自然请求下识别真实理解障碍，所选 explanation moves 相对基线产生具体收益；结论覆盖预定重复运行及全部失败。
- 连续演示可播放、暂停、回退、定位，并按同一时间现场约定在真实 Reader 保存、重开和追问。
- preview 能在冻结场景下检查关键中间状态，真实播放满足 EX5 的观察开销和帧间隔预算。
- 页面、readable content 与最终交付文字正确，来源和动态文字合同保持有效。
- 制作与修订总成本满足本批预冻结门槛。
- 至少两类非金样板任务通过 EX8，其中至少一类为生物机制或系统/论文任务。

学习效果单列“已评估及结果”或“尚未评估”，有真实用户证据后再形成对应结论。EX3、EX4、EX9 分别记录触发与采用情况；未触发的条件性能力不影响已选方案的完成判定。若连续解释未达到收益条件，记录未达成，并交付有独立证据的局部改进。
