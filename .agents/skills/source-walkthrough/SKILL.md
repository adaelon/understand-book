# 源码导读

读者在右侧选择一个步骤，左侧会打开真实文件并高亮对应代码。交付可直接打开的 HTML 和可编辑的导读稿。

## 选取源码

从读者关心的一次操作、输入或函数开始。如果给的是仓库链接，先取得要讲解版本的本地源码。沿实际调用点找到数据、分支与结果，使用带行号的源码确立每一步。在说明中跟踪一个具体输入怎样变化。给有条件的路径保留分支，标题写该步做了什么，符号写实际函数名或对应代码标识。

## 编写导读稿

在目标仓库选取输出位置，写 UTF-8 的 JSON 文件。所有说明是纯文本。以下是一个节点的格式示例，文件与行号在制作时从目标仓库取值。

```json
{
  "project": "项目名",
  "title": "请求在哪里进入队列？",
  "summary": "沿一个请求追踪入队时写入的数据。",
  "steps": [
    {
      "id": "enqueue",
      "title": "请求入队",
      "symbol": "enqueue",
      "file": "src/queue.ts",
      "start": 12,
      "end": 16,
      "explanation": "这几行中哪个值发生了变化，以及调用者接下来能观察到什么。",
      "next": []
    }
  ]
}
```

`file` 从目标仓库根目录起算，`start` 和 `end` 都包含在高亮内，行号从 1 开始。`steps` 按读者逐步阅读的顺序组织，`next` 用节点 ID 表示图上的有向连接，可以分支、汇合或返回。最后一步通常使用空数组。一个文件可以有多个步骤。

## 生成与交付

```text
node "<本技能目录>/scripts/build.mjs" "<目标仓库根目录>" "<导读稿.json>" "<导读页.html>"
```

生成器把本次引用的完整文件随页面一起保存，可离线查上下文。已有导读更新时，重读发生改动的片段并调整行号、说明或连接，再生成。用浏览器从生成的 HTML 点一个跨文件步骤，核对显示的路径、行段和解释，交付页面链接。
